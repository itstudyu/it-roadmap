# 모바일 학습 경험 최종 목업

## 결정

사용자 선택에 따라 다음 두 방향을 하나로 합쳤다.

- **A · Guided Trail**의 `필요 → 핵심 → 흐름 → 오해 → 설명 → 확인` 6단계 학습 구조
- **B · Concept Atlas**의 `Domain → DNS → IP → TCP → HTTP` 연결 경로와 `Cache·TTL` 분기

최종안 이름은 **Mobile Guided Atlas**다. 첫 화면에서 B의 개념 경로를 세로 지그재그 지도로 보여주고,
학습을 시작하면 같은 경로를 한 줄 미니맵으로 줄인다. 경로는 맥락을 주는 레이어이며, 핵심 학습은
A의 직선 코스가 담당한다.

## 콘텐츠 계층

- `대분류 → 주제 묶음 → 상황별 경로 → 단어 상세`의 4단계다.
- 12개 원본 카테고리와 629개 실제 단어를 모두 탐색할 수 있다. 각 카테고리의 `전체 N개` 목록 수는 원본 데이터와 정확히 일치한다.
- 카테고리마다 대표 경로 1개와 보조 경로 2개를 제공한다. 총 36개 경로이며, 모든 노드는 실제 원본 단어 ID로 연결된다.
- `네트워크 → 주소와 이름 → 웹사이트가 열리는 길 → DNS 상세`는 B 경로 지도와 A의 6단계 학습을 끝까지 체험하는 대표 코스다.
- 한 경로는 4~7개 핵심 단어만 연결한다. Cache·TTL처럼 본선이 아닌 개념은 순번 대신 가지 표시(`↳`)를 쓴다.
- 단어마다 별도 대형 지도를 만들지 않는다. 상세 학습에서는 현재 위치를 알려주는 한 줄 미니 경로만 유지한다.
- 단어와 경로는 다대다 관계다. 같은 단어가 여러 실전 경로에 들어가더라도 학습 상태는 하나의 `termId`로 공유한다.
- 현재 데이터 629개는 12개 대분류에 속한다. 전면 개편에서는 대분류 하나를 긴 목록으로만 두지 않고 4~8개 주제 묶음으로 다시 나눈다.
- 모바일 코스 홈에서는 12개 원본 카테고리를 4개 학습 목적(`코드와 웹`, `데이터와 AI`, `연결·배포·운영`, `설계·보안·제품`) 아래 묶어 보여준다. 기존 bookId와 진도 키는 바꾸지 않는다.
- 카테고리 선택은 상단 트리거와 전체 높이의 모바일 시트 두 곳에서 가능하다. 선택하면 추천 경로와 전체 단어 수가 즉시 바뀐다.

### 현재 목업의 데이터 범위

| 항목 | 목업에 반영된 범위 |
|---|---:|
| 하단 메뉴 | 오늘 · 코스 · 찾기 · 복습 · 진도 5개 화면 |
| 원본 카테고리 | 12개 전체 |
| 실제 단어 목록 | 629개 전체 |
| 상황별 경로 | 카테고리당 3개, 총 36개 |
| 완전한 상세 설명 예시 | DNS · Connection Pool · Change Data Capture 3개 |

목업의 목적은 화면 구조와 학습 깊이의 기준을 승인받는 것이다. 따라서 629개 목록과 36개 경로는 실제 데이터로 연결하되,
긴 상세 본문은 위 세 단어를 대표 예시로 완성했다. 나머지 단어의 짧은 시트는 누락이 아니라 목업 범위를 명시하는 상태이며,
전면 개편 때 아래 설명 구조로 629개 전부를 작성·검수한다.

## 사용 맥락

- 지하철에서 iPhone을 한 손으로 들고 5~10분 학습
- iPhone 17/17 Pro의 약 402×874 CSS viewport를 1차 기준으로 사용
- iPhone 17 Pro Max의 약 440×956, 기존 소형 화면 390px과 320px도 함께 확인
- Safari에서 홈 화면에 추가한 `standalone` PWA
- 이동 중 연결이 끊겨도 학습할 수 있는 오프라인 우선 앱

실제 앱은 이미 `viewport-fit=cover`, standalone manifest, portrait orientation, Apple touch icon,
safe-area padding, 서비스 워커 전체 프리캐시를 갖고 있다. 이 목업은 그 기반 위의 학습 화면을 검증한다.

## 정보 구조

각 단계는 같은 네 층으로 구성한다.

1. **핵심 답** — 이 단계에서 반드시 기억할 한 문장
2. **보이는 근거** — 단순 선화나 입력·출력 표로 인과를 확인
3. **선택 심화** — 기록 종류, 재귀 조회처럼 정확한 내부 원리를 구체적 제목으로 펼침
4. **회상** — 화면 없이 설명하거나 정답을 펼치기 전에 먼저 답함

모든 단어 상세는 전면 개편 때 `정의 → 왜 필요한가 → 입력·역할·출력 → 작동 순서 → 예시 → 경계와 오해 → 관련 경로 → 남에게 설명` 순서로 확장한다.
모바일에서는 첫 화면에 핵심만 두고 `정확히 보기`와 `연결된 학습`을 사용자가 펼치는 점진적 공개 방식으로 길이를 제어한다.

DNS 목업에는 다음 내용을 포함한다.

- DNS의 정확한 정의와 필요한 이유
- 입력, 조회, 출력, DNS가 끝나는 경계
- A·AAAA·CNAME·MX·TXT 기록 예시
- 도메인 이름과 URL의 차이
- 재귀 DNS → 루트 → TLD → 권한 서버 조회
- 캐시와 TTL, 주소 변경 직후 답이 엇갈리는 이유
- 대표 오해 세 가지
- 30초 teach-back과 회상 질문

## 일러스트 결정

인물과 질감이 많은 ImageGen 렌더는 정보보다 표현이 앞선다는 사용자 피드백으로 제외했다.
실제 앱의 공용 장면 생성기가 만드는 단순 선화 SVG를 사용하며, 기존 3컷의 빠진 왕복을 보완해
다음 4컷으로 나눴다.

1. 브라우저에 이름 입력
2. DNS에 이름 질문
3. DNS가 IP 주소 응답
4. 브라우저가 그 주소로 서버에 직접 연결

원본은 `scenes/net.json`의 `net--dns`다. `python3 tools/build_scenes.py net`으로
`data/scenes/net.js`를 생성하며, 목업도 이 실제 자산을 직접 읽는다.

## 모바일 규칙

- 본문 16px 이상, 긴 설명 행간 1.72 이상
- 주요 조작 44×44pt 이상; 하단 다음 버튼은 52px 이상
- 일반 탐색과 경로 미리보기에서는 `오늘·코스·찾기·복습·진도` 5탭을 하단에 유지한다.
- DNS처럼 집중해서 진행하는 상세 학습 세션에서만 글로벌 탭을 숨기고 이전·다음 액션을 엄지 영역에 고정한다.
- 단어 상세는 하단 시트로 열며, 스크롤해도 핵심 행동 버튼이 시트 아래에 고정된다.
- `env(safe-area-inset-top/bottom)`으로 Dynamic Island와 홈 인디케이터 회피
- 개념 지도는 축소하지 않고 세로 재배치; 단계 안에서는 미니맵으로 축약
- 일러스트 안 작은 글자만으로 의미를 전달하지 않고 16px HTML 캡션을 병기
- 정답은 먼저 노출하지 않고 사용자가 답한 뒤 펼치게 함

## 합격 기준

1. 본 뒤 `무엇인가 / 왜 필요한가 / 어떻게 되나 / DNS가 끝나는 지점`을 30초 안에 설명한다.
2. 루트·TLD·권한 서버가 같은 답을 주지 않는다는 것을 구분한다.
3. TTL 때문에 옛 주소가 잠시 남는 이유를 설명한다.
4. 그림만 보고 `이름 질문 → IP 응답 → 브라우저 연결`을 순서대로 말한다.
5. 402×874, 440×956, 320×700에서 가로 넘침과 고정 요소 겹침이 없고 핵심 터치 대상이 44px 이상이다.
6. 12개 카테고리의 전체 단어 수와 36개 경로 노드가 원본 데이터에 존재하며, 단어를 누르면 같은 단어 상세로 연결된다.
7. 상세 예시를 본 사용자가 `정의 / 필요성 / 작동 / 예시 / 경계 / 관련 개념`을 순서대로 남에게 설명할 수 있다.
