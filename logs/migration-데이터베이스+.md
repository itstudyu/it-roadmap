# 이행 기록 — 데이터베이스+ (15편)

대상: Connection Pool · DB · Index(인덱스) · NoSQL · ORM · Oracle Exadata · Redis ·
SQL · Snowflake · Transaction · 구조화 데이터 · CSV · JSON · XML · YAML

검사 결과: **15편 실패 0건 · 경고 0건** (`python3 tools/check_template.py` 15편 일괄)

H1 제목 · 파일 이름 · 폴더는 하나도 건드리지 않았다.

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (15편 전부)

15편 모두 화살표가 없었다. 전부 달았고, **화살표를 달기 전에 그 섹션을 열어
답이 실제로 거기 있는지 하나씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고,
끝의 물음표는 본보기(DNS·HTTP)와 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| Connection Pool | 흔한 오해 · 해결하는 문제 · 주의사항 |
| DB | 해결하는 문제 · 작동 원리 · 실제 사례 |
| Index | 흔한 오해 · 주의사항 · 작동 원리 |
| NoSQL | 작동 원리 · 흔한 오해 · 해결하는 문제 |
| ORM | 작동 원리 · 그림 · 흔한 오해 |
| Oracle Exadata | 흔한 오해 · 해결하는 문제 · 주의사항 |
| Redis | 해결하는 문제 · 주의사항 · 흔한 오해 |
| SQL | 해결하는 문제 · 비교 · 흔한 오해 |
| Snowflake | 흔한 오해 · 작동 원리 · 실제 사례 |
| Transaction | 그림 · 작동 원리 · 흔한 오해 |
| 구조화 데이터 | 해결하는 문제 · 흔한 오해 · 작동 원리 |
| CSV | 흔한 오해 · 해결하는 문제 · 비교 |
| JSON | 주의사항 · 해결하는 문제 · 흔한 오해 |
| XML | 해결하는 문제 · 주의사항 · 흔한 오해 |
| YAML | 해결하는 문제 · 작동 원리 · 주의사항 |

### 질문을 바꾼 것 (6건)

여섯 건 다 같은 이유다 — **답이 노트 안에 딱 한 자리에만 있는데, 그 자리를 다른 질문이
이미 겨누고 있었다.** 억지로 같은 칸을 두 번 짚으면 확인이 안 되므로, 답이 따로 있는
질문으로 갈아 끼웠다. 새 질문의 답은 전부 그 노트 안에서 확인했다.

- **Connection Pool** — "풀의 최대 연결 수를 무제한으로 두면 무엇이 문제가 되나"
  답(연결 수에 뚜껑이 없다 · 놀아도 자원을 잡는다)이 해결하는 문제에 있는데 둘째 질문이
  거기를 겨눴다. → **"풀에 담아 둔 연결이 다음 요청 때 이미 못 쓰게 되어 있는 일은 왜 생기나
  → 주의사항"** 으로 바꿨다. 주의사항 첫 줄("서버 쪽에서 유휴 연결을 닫아 버릴 수 있다")이 답이다.
- **Index** — "인덱스가 있는데도 데이터베이스가 전체 훑기를 고르는 경우는 언제인가"
  답이 흔한 오해에만 있고 첫 질문이 이미 흔한 오해였다. → **"인덱스를 걸어뒀는데도 전체 훑기가
  그대로 일어나는 컬럼은 어떤 것인가 → 주의사항"**. 주의사항 두 줄(값 종류가 적은 컬럼,
  앞이 열린 `LIKE '%…%'`)이 그대로 답이다.
- **Oracle Exadata** — "같은 장비에 다른 회사 DB 를 올리면 무엇이 안 되나"
  답이 흔한 오해 셋째 줄에만 있는데 첫 질문이 흔한 오해였다. → **"나중에 다른 DB 로 갈아타려 할 때
  이 장비가 짐이 되는 이유는 → 주의사항"**. 주의사항의 "하드웨어와 소프트웨어에 함께 묶인다"가 답.
- **Snowflake** — "실수로 지운 표를 나중에 되살릴 수 있는 근거는 무엇인가"
  근거(Time Travel)는 작동 원리에 있는데 둘째 질문이 작동 원리였다. → **"조건을 잘못 걸어 지운 표를
  되살릴 때 무엇을 읽어서 복구하나 → 실제 사례"**. 사례의 "한 시간 전 시점의 표를 그대로 읽어
  복구한다"가 답이다.
- **JSON** — "설정 파일에 주석을 달았더니 프로그램이 뜨지 않는다"
  주석 얘기는 흔한 오해에만 있고 셋째 질문(날짜)도 흔한 오해였다. 날짜 쪽이 더 좋은 물음이라
  이쪽을 바꿨다. → **"설정 파일의 키를 작은따옴표로 감쌌더니 프로그램이 뜨지 않는다. 왜 그런가
  → 주의사항"**. 주의사항 첫 줄이 그대로 답이다.
- **XML** — "닫는 태그를 하나 빠뜨리면 어떤 일이 일어나나"
  답이 흔한 오해 셋째 줄에만 있는데 셋째 질문(HTML 과 XML)도 흔한 오해였다. HTML 혼동 쪽이
  더 값진 물음이라 이쪽을 바꿨다. → **"본문에 `<` 를 그대로 적으면 문서가 왜 깨지나 → 주의사항"**.

## 2. 흐름의 `<` 감사 — 5편에서 고쳤다

물음은 하나였다. **누가 누구에게 답을 주는가.**

| 노트 | 있던 줄 | 무엇으로 | 왜 |
|---|---|---|---|
| Connection Pool | `< 반납 :: 끊지 않고 풀에 돌려준다` | `@` (마지막 줄) | 아무도 답을 주지 않는다. 연결이 통으로 돌아가고 **다음 요청이 처음부터 다시** 빌린다. 순환이다 |
| Redis | `< 앱 :: 두 번째 요청은 Redis 에서 끝난다` | `@` (마지막 줄) | "두 번째 요청" 은 응답이 아니라 **처음으로 돌아가 다시 하는 것**이다 |
| Transaction | `< 결과 :: 두 계좌 모두 시작 전 잔액` | 표지 없는 마디 | 롤백은 되돌리는 것이지 누가 답을 보내는 게 아니다. 끝난 상태를 적은 줄이다 |
| CSV | `< 읽는 쪽 :: 줄 바꿈을 만나면 다음 행` | 표지 없는 마디 | 파서가 계속 읽을 뿐 응답이 없다. `@` 도 아니다 — 첫 마디가 헤더 줄이라 되돌아가면 거짓이 된다 |
| JSON | `< 서버 :: 언어가 달라도 같은 글자를 읽는다` | 줄을 없애고 브라우저 마디에 합침 | 응답이 아니라 결론을 한 번 더 적은 줄이었다. 뜻("언어가 달라도")은 `브라우저 :: 언어가 달라도 같은 글자를 객체로 푼다` 로 살렸다 |

`<` 를 그대로 둔 곳: DB · Index · NoSQL · ORM(두 줄 다 되돌아오는 구간) · Oracle Exadata ·
SQL · Snowflake · 구조화 데이터. 전부 **요청을 받은 쪽이 결과를 돌려주는 자리**다.

검사기가 Snowflake 에서 "'다시' 가 있다" 고 경고했는데 오탐이었다(사용자가 결과를 받는
진짜 응답 줄이다). 뜻이 바뀌지 않는 선에서 `곧 다시 멈춘다` → `곧 멈춘다` 로 다듬어
경고만 걷었다.

## 3. 대조 감사 — ✕ 칸 자기검사 (1편)

- **NoSQL** — `관계형 DB || NoSQL` 을 **`|=|`** 로 바꿨다.
  왼쪽 첫 줄이 `스키마 :: 미리 정해둔다` 인데 이건 관계형의 **장점**이다. 결론 줄도
  `정해진 모양을 지켜서 얻던 것을 내주고 유연함과 확장을 산다` 로 스스로 거래라고 말하고 있다.
  `||` 로 두면 그림이 2초 만에 "관계형은 나쁜 것" 을 심는데, 같은 노트의 흔한 오해가
  지우려는 게 바로 그 오해다("NoSQL이 SQL보다 빠르다").

그대로 둔 것 — 전부 **"있고 없고"** 라 왼쪽이 실제로 나쁜 상태다.
DB(파일로 · 지금은 그림 자리) · Connection Pool(풀 없이) · Index(인덱스 없이) ·
Redis(DB 만 쓰면) · Transaction(트랜잭션 없이) · 구조화 데이터(형식 없이) ·
JSON/XML(형식 없이) · SQL(직접 코드로) · ORM(직접 SQL) · Exadata(따로 둘 때) ·
CSV(전용 형식) · Snowflake(전통 DB) · YAML(JSON 으로).
CSV 와 YAML 은 한참 봤다 — 각각 `파일 크기` 행과 `설정을 JSON 으로 적으면` 이라는
제목이 견주는 축을 좁혀 주고 있어서, 왼쪽 칸이 그 축에서는 장점이 아니다.

## 4. 그림 자리 감사 — 2편에서 바꿔 걸었다

판정법은 하나. **그림만 보고 정의 첫 문장을 복원할 수 있는가.**

- **DB** — 그림 자리에 있던 `흐름: 조회 문장 하나를 던지면 DB 는 무엇을 하나` 로는
  "데이터를 구조에 맞춰 맡아두고 **지키는** 시스템" 이 복원되지 않는다. 그 그림이 말하는 건
  "쿼리를 받아 행을 돌려준다" 이고, 결론 줄도 `셋째 마디에서 무엇을 고르느냐로 속도가 갈린다` 라
  속도 이야기였다. 해결하는 문제에 있던 `대조: 데이터를 파일에 그냥 적어두면 어떻게 되나`
  (동시 수정 · 사용자 삭제 · 중간에 실패)를 **그림 자리로 올리고**, 조회 흐름은
  ⚙️ 작동 원리로 내렸다. 인덱스 문단 바로 위라 `계획 :: 인덱스를 탈지 전부 훑을지 정한다` 와도 붙는다.
- **Redis** — 그림 자리의 캐시 흐름으로는 "디스크가 아니라 **메모리**에 두는 저장소" 가
  복원되지 않는다(메모리라는 말이 그림에 없다). 작동 원리에 있던
  `층: 값 하나를 읽을 때 어디까지 가게 되나`(앱 메모리 / Redis = 여러 서버가 같이 보는 메모리 /
  DB = 디스크에 있는 원본)를 **그림 자리로 올리고**, 캐시 흐름은 작동 원리로 내렸다.
  TTL 문단이 그 바로 아래라 `살 시간을 건다` 마디와 이어진다.

두 편 다 도해를 **자리만 맞바꿨다.** 없앤 도해도, 새로 지어낸 도해도 없다.

그대로 둔 것 중 오래 본 것 — **Oracle Exadata**. 정의 첫 문장이 "오라클 DB 만 돌리려고 만든
전용 장비" 라 어느 도해로도 "전용" 이 그려지지 않는다. 바꿔봐야 나아지지 않아서 그대로 뒀다.

## 5. 층 반증 테스트 — 3편에서 고쳤다

**이웃한 두 층을 맞바꿔도 안 틀리면 층이 아니다.**

- **Connection Pool** — `층: 풀의 크기를 정하는 값들은 무엇을 붙드나` 는 손잡이 세 개를
  나열한 것이었다(맞바꿔도 멀쩡하다). 결론 줄도 `이 셋이 정한다` 로 집합어였다.
  **걸리는 범위**라는 진짜 축으로 다시 세웠다 — 최대 연결 수(풀 전체) → 유휴 보관 수
  (그 안에서 놀려 둘 몫) → 최대 수명(연결 한 개). 이제 위아래를 바꾸면 틀린다.
- **SQL** — `층: 데이터에 하는 일은 무엇으로 나뉘나 / SELECT · INSERT · UPDATE · DELETE` 는
  그냥 목록이었다(INSERT 와 UPDATE 를 바꿔도 아무 일도 안 난다). 결론도 `나머지 셋은` 이라는
  집합어로 시작했고, 게다가 INSERT 에는 `WHERE` 가 없어서 "조건을 빠뜨리면" 이 안 맞았다.
  **되돌리기 어려운 정도**로 다시 세웠다 — 읽기만 함 → 넣은 것만 늘어남 → 옛 값이 사라짐 →
  행이 사라짐. 주의사항("조건 없이 실행하면 되돌릴 방법이 없다")과 같은 축이다.
- **YAML** — 그림 자리의 층에서 마지막 마디 `하이픈 :: 목록 표시` 를 뺐다. 앞의 셋은
  들여쓰기 깊이라는 축 위에 있는데 하이픈만 그 축 밖이라, 어디에 놓아도 안 틀렸다.
  하이픈 설명은 작동 원리 본문에 이미 있다("줄 앞에 하이픈을 붙이면 목록의 한 항목이다").

반증을 통과해 그대로 둔 층: Redis(앱 메모리→Redis→DB) · ORM(내 코드→ORM→드라이버→DB) ·
Snowflake(서비스→컴퓨팅→저장소) · Transaction(격리 수준 넷) · 구조화 데이터(구조화→반구조화→비구조화).
전부 이웃을 맞바꾸면 그림이 거짓이 된다.

## 6. 선행 용어 (2편)

- **Index** — 도해 마디 `옵티마이저 :: email 에 인덱스가 있는지 본다` 는 옵티마이저를 모르면
  빈칸이 된다(단어장에 그 노트가 없다). 반 구절로 풀었다 —
  `옵티마이저 :: 어떻게 찾을지 고르는 쪽. 인덱스가 있나 본다`.
  흔한 오해에 또 나오는 "옵티마이저" 도 이 한 줄로 받쳐진다.
- **Connection Pool** — `여러 고루틴이 동시에 써도 안전하고` →
  `여러 고루틴(Go 가 동시에 굴리는 가벼운 실행 단위)이 …`.

## 손대지 않은 것

- 정의 · 비유 · 정리 · 실제 사례 · 흔한 오해 문장은 위에 적은 것 말고는 그대로다.
- 새 사실을 지어내지 않았다. 도해를 다시 세울 때 쓴 말은 전부 같은 노트의 다른 섹션에
  이미 있는 내용이다.
- 도해를 새로 만들거나 없애지 않았다(YAML 의 마디 한 줄과 JSON 의 줄 한 개 제외 — 둘 다
  본문에 같은 말이 남아 있다).
