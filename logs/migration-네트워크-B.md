## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (15편 전부)

15편 모두 화살표가 없었다. 전부 달았고, **화살표 뒤의 섹션을 실제로 열어
거기에 답이 있는지 한 줄씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고,
끝의 물음표는 본보기 두 편(DNS·HTTP)과 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| OSI 7계층 | 해결하는 문제 · 작동 원리 · 실제 사례 |
| Port Forwarding | 해결하는 문제 · 그림 · 흔한 오해 |
| Port | 작동 원리 · 주의사항 · 흔한 오해 |
| Proxy | 그림 · 흔한 오해 · 작동 원리 |
| Public IP vs Private IP | 작동 원리 · 해결하는 문제 · 흔한 오해 |
| Reverse Proxy | 해결하는 문제 · 작동 원리 · 주의사항 |
| SSE | 흔한 오해 · 작동 원리 · 주의사항 |
| Socket | 작동 원리 · 해결하는 문제 · 비교 |
| TCP | 그림 · 작동 원리 · 실제 사례 |

### 답이 노트에 없거나 자리가 겹쳐 질문을 바꾼 것 (4건)

이번 이행의 진짜 수확이다. 억지로 아무 섹션이나 짚지 않았다.

- **Port Forwarding** — "공인 IP가 하나뿐인데 기기 두 대를 밖에 열려면 무엇으로 구분하나"
  답은 해결하는 문제에 있는데 첫 질문이 이미 그 자리를 겨눈다. 셋이 두 자리로 몰리는 걸
  피해 **"요청을 받은 공유기는 목적지의 무엇을 바꿔서 안쪽으로 넘기나 → 그림"** 으로 바꿨다.
  그림의 `공유기 :: 목적지를 안쪽 주소와 포트로 바꾼다` 가 그대로 답이다.
- **Port** — "브라우저 탭 여러 개로 같은 사이트를 열었을 때 응답이 섞이지 않는 이유는"
  답(임시 포트)이 작동 원리에 있는데 첫 질문의 답도 작동 원리다. 답이 따로 있는
  **"웹 서버를 80번에 띄우려는데 권한 오류가 난다면 무엇 때문인가 → 주의사항"** 으로 바꿨다.
  주의사항의 "1023번 이하는 관리자 권한이 있어야 잡을 수 있다" 가 답이다.
- **Public IP vs Private IP** — "집에 둔 서버에 밖에서 접속하려면 왜 설정을 따로 해야 하나"
  **"왜"의 답이 노트 안에 없었다.** 실제 사례는 포트 포워딩을 거는 방법만 적고 이유를 안 적고,
  이유가 적힌 곳은 해결하는 문제인데 둘째 질문이 이미 그 자리다.
  **"사설 IP를 쓰는 집 안 기기를 그것만으로 안전하다고 할 수 없는 이유는 → 흔한 오해"** 로 바꿨다.
- **TCP** — "영상 통화가 TCP를 쓰지 않는 이유는"
  답이 실제 사례에 있는데 셋째 질문(와이파이가 약할 때)의 답도 같은 실제 사례 안에 있다.
  아무 질문도 안 겨누던 작동 원리 쪽으로 돌려
  **"세 번 인사를 두 번으로 줄이면 서버 쪽에 무슨 일이 생기나 → 작동 원리"** 로 바꿨다.
  "서버는 자기 응답이 도착했는지 모른 채 자원을 잡고 기다리게 된다" 가 답이다.

## 2. 흐름의 `<` 감사 — 6편을 고쳤다

물은 것은 하나다. **누가 누구에게 답을 주는가.**
검사기가 경고한 세 자리(Reverse Proxy · VPN · UDP)는 단순 문자열 검사라
둘은 오탐이었고, 정작 경고가 안 뜬 자리 넷에서 거짓 `<` 가 나왔다.

### `<` 를 뗀 것 — 아무것도 안 돌아온다 (4편)

| 노트 | 문제의 줄 | 판단 |
|---|---|---|
| Port | `< 웹 서버 :: 자기 앞으로 온 요청을 받아 처리한다` | 도착이지 응답이 아니다. 브라우저에게 돌아가는 것이 그림 안에 없다 |
| Tunnel | `< 내부 DB :: 서버 안쪽에서 3306 으로 이어진다` | 터널 끝에 닿은 것이다. 되돌아오는 구간이 아니다 |
| UDP | `< 응용 :: 다시 받아야 하면 응용이 직접 챙긴다` | 위층에 넘기는 것이지 보낸 쪽으로 가는 것이 아니다. UDP 는 아무것도 안 돌려준다 |
| WebSocket | `< 어느 쪽 :: 닫자는 프레임을 보내면 거기서 끝난다` | 끝내는 마디다. 답을 주는 사람이 없다 |

넷 다 표지 없는 보통 마디로 되돌렸다. `<` 앞에는 앱이 "여기서부터 돌아오는 길" 을
새기므로, 그대로 뒀으면 네 편의 그림이 각각 없는 귀갓길을 하나씩 그리고 있었을 것이다.

### `@` 로 바꾼 것 (1편)

- **SSE** — `< 브라우저 :: 끊기면 알아서 다시 연결한다` 는 응답이 아니라 **처음으로 돌아가는 길**이다.
  첫 마디가 `브라우저 :: /events 로 연결을 한 번 연다` 이고, 끊기면 바로 그 일을 다시 한다.
  이미 마지막 줄이라 자리는 그대로 두고 표지만
  `@ 브라우저 :: 끊기면 알아서 다시 연결해 이어받는다` 로 바꿨다. 마디 5개라 `@` 를 함께 세도 넉넉하다.

### `<` 를 옮긴 것 (1편)

- **TCP** — `<` 가 마지막 마디(`받는 쪽 :: 순서대로 맞춰서 위층에 올린다`)에 붙어 있었는데
  거기서는 아무도 누구에게 답을 주지 않는다. 답이 오가는 자리는 그 앞이다 —
  받는 쪽이 "3번을 다시 달라" 고 했고 **보내는 쪽이 그 요청에 답한다.**
  그래서 `< 보내는 쪽 :: 3번만 다시 보낸다` 로 한 칸 올렸다. 본보기 HTTP.md 가
  `< 서버 :: 200 OK 와 함께 HTML 본문을 돌려준다` 로 답하는 쪽에 표지를 다는 것과 같은 자리다.

### 경고를 남긴 세 자리 (전부 오탐)

셋 다 `<` 줄에 "다시" 라는 낱말이 들어 있어 걸렸을 뿐, 실제로는 응답이 돌아오는 자리다.

- **Reverse Proxy** — `< 프록시 :: 압축하고 다시 암호화해 돌려준다` — 앱 서버의 응답을 클라이언트에게 돌려준다. "다시 암호화" 는 순환이 아니라 SSL 종료의 되감기다.
- **VPN** — `< VPN 서버 :: 응답을 다시 암호화해 돌려보낸다` — 같은 모양이다. 웹사이트의 응답이 내 기기로 돌아온다.
- **TCP** — `< 보내는 쪽 :: 3번만 다시 보낸다` — 재전송은 "다시" 라는 낱말을 피할 수 없다. 되돌아가는 것이 아니라 요청에 답하는 것이라 `<` 가 맞다.

## 3. 대조 감사 — ✕ 칸 자기검사 (1편)

- **UDP · 해결하는 문제** — `TCP 로 || UDP 로` 였다. 왼쪽 칸이 TCP 인데
  `빠진 조각 :: 다시 요청` 과 `전송 속도 :: 막히면 줄임` 은 **명백한 TCP 의 장점**이다.
  그대로 두면 그림이 2초 만에 "TCP 는 나쁜 것" 이라는 오해를 심는데, 같은 노트의
  흔한 오해가 지우려는 것("UDP가 TCP보다 항상 빠르다") 과 정면으로 어긋난다.
  칸 이름 줄만 **`TCP 로 |=| UDP 로`** 로 바꿨다. `= ` 줄이 이미
  "기다리는 쪽이 손해인 **경우가 있다**" 로 하나를 고르라 말하지 않으니 중립 대조가 맞다.

나머지 14편의 `||` 는 전부 "있고 없고" 다(프록시 없이 · 터널 없이 · 포트가 없으면 · 폴링으로).
왼쪽이 실제로 나쁜 상태라 그대로 뒀다.

- **Tunnel** 만 한 칸을 다듬었다. `내부 서버 :: 밖에서 못 본다 || 안까지 닿는다` 에서
  "밖에서 못 본다" 는 보안상 장점처럼 읽힌다. 이 대조의 시점(닿아야 하는 사람)에 맞춰
  `닿을 길이 없다` 로 고쳤다. 오른쪽 "안까지 닿는다" 와 같은 것을 놓고 견주게 된다.

## 4. 그림 자리 감사 (1편)

판정법은 **그림만 보고 정의 첫 문장을 복원할 수 있는가** 였다.

- **URL** — 그림 자리에 `흐름: 주소창에 URL 을 치면 무슨 순서로 오가나` 가 있었다.
  이건 URL 이 **무엇인지**가 아니라 브라우저가 URL 로 **무슨 일을 하는지**다. 그림만 보면
  DNS 와 접속 절차가 남지 "무엇을 어디서 어떻게 가져올지 적은 주소" 는 복원되지 않는다.
  작동 원리에 있던 `층: URL 한 줄은 무엇으로 나뉘나` 를 **그림 자리로 올렸다** —
  프로토콜(어떻게) · 호스트(어디서) · 경로(무엇을) · 질의(조건) 가 정의 첫 문장 그대로다.
  흐름은 작동 원리로 내려보냈고, 앞 문장을 "쪼개진 한 줄을 브라우저는 이런 순서로 쓴다" 로 이었다.

나머지 14편은 그림만 보고 정의가 복원된다. OSI 7계층의 일곱 마디 흐름은 마디가 일곱이라
층으로는 담기지 않고(층은 3~5개), 내려가며 봉투가 덧씌워지는 것 자체가 개념의 형태라 그대로 뒀다.

## 5. 층 반증 테스트 — 2편이 층이 아니었다

- **UDP · 작동 원리** — `층: UDP 가 하지 않는 일은 무엇인가` (연결 맺기 / 재전송 / 순서 맞추기 / 속도 조절).
  `= ` 줄이 **"이 넷을"** 이라는 집합어로 시작했고, 재전송과 순서 맞추기를 맞바꿔도
  그림이 하나도 안 틀린다. 순서에 뜻이 없으니 층이 아니라 목록이었다.
  **본문 불릿으로 되돌렸다.** 대조로 옮기는 길도 있었지만 이 노트에는 TCP 와의 견줌이
  이미 둘(해결하는 문제의 대조, 📊 비교 표) 있어서 셋째를 만들 이유가 없었다.
- **VPN · 작동 원리** — `층: VPN 은 무엇을 켜켜이 쌓아 만드나` (인증 / 키 교환 / 터널 / 트래픽).
  이웃을 맞바꾸면 틀리긴 하는데, **틀리는 이유가 시간이다.** `= ` 줄이 스스로
  "인증과 키 교환이 **먼저**인 이유다" 라고 말한다. 인증과 키 교환은 연결이 선 뒤에
  패킷마다 겹쳐 있는 층이 아니라 세울 때 한 번 지나가는 단계다. 층으로 그리면
  OSI 처럼 매 통신에 네 겹이 얹힌다고 읽힌다.
  **`흐름: VPN 연결은 어떤 순서로 서나` 로 바꿨다.** 마디 넷, 마디 이름은 그대로 뒀다.

층을 그대로 둔 곳 — OSI 7계층(TCP/IP 4계층 묶음, 계층 번호가 축) · Port(포트 번호 구간) ·
Reverse Proxy(바깥에서 안쪽으로) · Socket(내 프로그램에서 IP 까지) · Tunnel(포장 겹) ·
WebSocket(내 코드에서 TCP 까지) · URL(한 줄의 앞에서 뒤로, 이번에 그림 자리로 승격).
전부 이웃을 맞바꾸면 그림이 틀린다.

## 6. 선행 용어 (2편)

노트 밖에서 배워야 하는 말인데 그냥 놓여 있던 자리를 짚었다.

- **Public IP vs Private IP** — 작동 원리의 "주소를 바꾸는 일은 NAT가 한다" 를
  `[[NAT]]` 로 걸었다. 관련 용어에는 이미 있었지만 본문에서 눌리지 않았다.
- **Tunnel** — 작동 원리의 "SSH 터널은 잇는 방향에 따라" 를 `[[SSH]]` 로 걸었다. 같은 이유다.
- **UDP** — "체크섬" 을 `체크섬(내용이 깨졌는지 보는 검사값)` 으로 반 구절 풀었다.
  바로 다음 문장이 "체크섬이 안 맞으면 그 조각을 조용히 버린다" 라 모르면 그 줄이 통째로 빈칸이 된다.

브로드캐스트·멀티캐스트(UDP), SSL 종료(Reverse Proxy), 캡슐화(OSI 7계층),
101 Switching Protocols(WebSocket) 은 이미 그 자리에서 반 구절로 풀려 있어 그대로 뒀다.

## 손대지 않은 것

- H1 제목 · 파일 이름 · 폴더 — 하나도 건드리지 않았다.
- 정의 · 비유 · 실제 사례 · 흔한 오해 · 정리 — 본문 내용은 새로 짓지 않았다.
  질문을 바꿀 때도 답은 전부 그 노트에 이미 있던 사실에서 가져왔다.
- Proxy · Reverse Proxy · Socket · OSI 7계층 · curl — 확인 질문 화살표 말고는
  고칠 것이 없어서 고치지 않았다.
