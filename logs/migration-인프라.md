# 이행 기록 — 인프라 (13편)

대상: Apache · Bare Metal · CI_CD · Cron Job · DevOps · Elastic Search ·
Hypervisor · Kubernetes · Logging · On-Premises · TTL · VM · VPS

검사 결과: **13편 실패 0건 · 경고 0건** (`--strict` 로도 0건)

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (13편)

13편 모두 화살표가 없었다. 전편에 달았고, **화살표 뒤의 섹션을 실제로 열어
답이 거기 있는지 하나씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고,
끝의 물음표는 본보기 두 편(DNS·HTTP)과 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| Apache | 그림 · 흔한 오해 · 작동 원리 |
| Bare Metal | 해결하는 문제 · 흔한 오해 · 실제 사례 |
| CI_CD | 해결하는 문제 · 작동 원리 · 주의사항 |
| Cron Job | 그림 · 흔한 오해 · 작동 원리 |
| DevOps | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| Elastic Search | 흔한 오해 · 해결하는 문제 · 주의사항 |
| Hypervisor | 그림 · 해결하는 문제 · 작동 원리 |
| Kubernetes | 그림 · 흔한 오해 · 주의사항 |
| Logging | 흔한 오해 · 작동 원리 · 비교 |
| On-Premises | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| TTL | 실제 사례 · 작동 원리 · 흔한 오해 |
| VM | 해결하는 문제 · 작동 원리 · 비교 |
| VPS | 해결하는 문제 · 작동 원리 · 흔한 오해 |

### 답을 못 찾아 질문을 바꾼 것 (2건)

- **Elastic Search** — "주문 데이터를 여기에만 저장하면 무엇이 곤란해지나"
  답(트랜잭션·정합성이 약하다)이 🚫 흔한 오해에 있는데 첫 질문이 이미 그 자리를
  겨누고 있었다. 🚨 주의사항의 "원본과 어긋나는 것을 전제로 만든다" 는 원본이 DB 라는
  전제 아래 쓴 줄이라 이 물음의 답으로 삼기엔 반만 맞는다. 억지로 짚지 않고
  **"이미 수만 건을 색인해둔 뒤에 분석기 설정을 바꾸면 무슨 일이 생기나 → 주의사항"** 으로
  바꿨다. 주의사항 첫 줄 "이미 색인된 문서는 새 분석기로 다시 쪼개지지 않아서 전체를
  다시 넣어야 한다" 가 그대로 답이다.
- **Logging** — "오류가 난 줄만 남겼을 때 원인을 찾기 어려운 이유는"
  답은 흔한 오해 둘째 줄에 있지만 첫 질문의 답도 흔한 오해 첫째 줄이라 셋이 두 자리로
  몰렸다. **"한 요청이 남긴 줄들이 여기저기 흩어졌을 때 다시 묶으려면 무엇이 필요한가
  → 작동 원리"** 로 바꿨다. 작동 원리의 "요청마다 같은 식별자를 넣어두면 흩어진 줄들을
  하나의 요청으로 다시 묶을 수 있다" 가 답이다.

나머지 11편은 원래 질문의 답이 노트 안에 실재해서 화살표만 달았다.

## 2. 흐름의 `<` 감사 — 5편에서 고쳤다

"누가 누구에게 답을 주는가" 를 물었다. 대답이 안 나오면 `<` 가 아니다.
검사기 경고(Kubernetes·TTL)는 참고만 했고 뜻을 보고 판단했다 — 경고가 없던 자리에서도
셋을 고쳤고, 경고가 있던 둘은 실제로 순환이 맞았다.

### `<` → `@` 로 (순환이었다) — 3편

- **Cron Job** `< cron :: 다음 1분을 기다린다`
  → 응답이 아니라 **처음으로 돌아가 다시 시계를 보는 것**이다. cron 의 정체가 곧 이 반복이라
  직선으로 펴 그리면 개념이 사라진다.
  `@ cron :: 1분 뒤 다시 깨어나 처음부터 본다` 로 바꿨다.
- **Kubernetes** `< 상태 :: 다시 3개. 사람이 아무것도 하지 않았다`
  → 아무도 답을 되돌려주지 않는다. `= 원하는 상태와 현재를 계속 비교해 좁힌다` 가 말하는
  그 순환이다. `@ 다시 세기로 :: 3개가 됐다. 사람은 아무것도 안 했다` 로 바꿨다.
  원래 문장의 힘("사람이 아무것도 하지 않았다")은 그대로 두고 마디 이름이 돌아갈 자리를
  가리키게 했다.
- **TTL** `< 저장소 :: 읽어 온 값을 새 TTL 로 다시 넣는다`
  → 새 TTL 을 달아 넣는 순간 첫 마디("저장할 때")로 돌아간다. 한 바퀴다.
  `@ 다시 저장 :: 읽어 온 값에 새 TTL 을 달아 넣는다` 로 바꿨다.

### `<` 를 뗐다 (앞으로 나아가는 걸음이었다) — 2편

- **CI_CD** `< CD :: 확인되면 운영에 순차 배포한다`
  → 테스트 환경 다음이 운영이다. 되돌아오는 게 아니라 파이프라인의 다음 칸이다. 표지를 뗐다.
- **Logging** `< 사람 :: 조건을 걸어 그때 무슨 일이 있었는지 찾는다`
  → 저장소가 사람에게 답을 주긴 하지만, 그 사람은 맨 앞에서 요청한 쪽이 아니다.
  기록을 남긴 건 코드고 찾는 건 사람이다. 돌아오는 길이 아니라 사슬의 끝이다. 표지를 뗐다.

### `<` 를 옮겼다 — 1편

- **VPS** — `<` 가 `고객 :: SSH 로 들어가 원하는 것을 설치한다` 에 붙어 있었다.
  고객이 SSH 로 들어가는 건 새 행동이지 응답이 아니다. 실제로 돌아오는 자리는 그 앞
  `전달 :: IP 와 루트 접속 정보를 고객에게 넘긴다` 다 — 2번 마디에서 주문한 고객에게
  결과가 되돌아가는 지점. `<` 를 전달로 옮기고 고객은 보통 마디로 뒀다.

### 그대로 둔 `<` (응답이 실제로 돌아온다)

Apache(`< Apache :: 찾은 내용을 응답으로 돌려준다`) · Elastic Search(`< 결과 ::
점수 높은 순으로 돌려준다`) · Hypervisor(`< 게스트 OS :: 성공했다는 답만 받는다`).
셋 다 "누가 누구에게" 가 또렷하다.

**DevOps** 는 아래 4번에 함께 적었다 — `<` 였는데 순환이면서 동시에 그림 자리 문제였다.

## 3. 대조 감사 — ✕ 칸 자기검사 (바꾼 것 없음)

`||` 대조 13개를 전부 열어 **왼쪽 칸에 장점이 한 줄이라도 있는지** 봤다. 한 줄도 없었다.

다만 둘은 오래 들여다봤다.

- **Bare Metal** `가상화 위에서 || 베어 메탈에서` — 가상화는 나쁜 상태가 아니다.
  그런데 세 줄(성능·지연·하드웨어 기능)이 전부 성능 축이고, 그 축에서는 가상화가 실제로
  지는 쪽이다. `= 얇게 깎이는 성능이 사고가 되는 자리가 있다` 로 결론이 이미 조건부다.
  같은 노트의 흔한 오해 "성능이 좋으니 무조건 낫다" 가 과잉 적용을 따로 막고 있다. 그대로 뒀다.
- **On-Premises** `클라우드로 || 온프레미스로` — 마찬가지로 클라우드가 나쁜 상태는 아니다.
  하지만 제목이 "데이터를 밖에 둘 수 없을 때는 어떻게 하나" 로 조건을 먼저 걸어두었고,
  그 조건 아래에서는 클라우드가 실제로 못 하는 쪽이다. 📊 비교 표가 클라우드의 장점
  (초기 비용·즉시 확장·유지 인력)을 따로 싣고 있다. 그대로 뒀다.

나머지(Apache · CI_CD · Cron Job · DevOps · Elastic Search · Hypervisor ·
Kubernetes · Logging · TTL · VM · VPS)는 "있고 없고" 거나 왼쪽이 명백히 나쁜 상태다.
`|=|` 를 억지로 넣지 않았다.

## 4. 그림 자리 감사 — 2편에서 손봤다

판정법은 **그림만 보고 정의 첫 문장을 복원할 수 있는가** 였다.

- **DevOps** — 정의는 "개발과 운영을 한 팀이 함께 맡는 방식" 인데, 그림은 커밋에서 배포까지
  일직선으로 흐르고 끝났다. 직선으로 보면 여전히 **넘기는 그림**이라 정의의 핵심(경계가 없다)이
  복원되지 않는다. 마지막 `< 모니터링 :: 로그와 지표를 보고 다음 계획에 반영` 은 응답이
  아니라 다음 커밋으로 돌아가는 자리였다.
  `@ 모니터링 :: 로그와 지표를 보고 다음 커밋에 반영한다` 로 바꿔 한 바퀴로 닫고,
  `=` 를 `개발에서 운영까지 벽 없이 한 바퀴 돈다. 사람 손은 맨 앞 커밋뿐이다` 로 고쳤다.
  이제 그림만 봐도 "개발과 운영이 끊기지 않은 한 줄기" 가 보인다.
  같은 그림의 `배포 :: 스테이징에 먼저` 는 노트가 설명하지 않는 말이라
  `테스트 환경에 먼저` 로 풀었다(6번 참고).
- **Hypervisor** — 정의는 "한 대의 컴퓨터를 여러 대처럼 나눠 쓰게 하는 소프트웨어" 인데,
  그림의 `= 게스트는 가로채였다는 사실을 끝내 모른다` 는 **가로채기만** 말하고 나눔을
  말하지 않았다. 도해를 옮기는 대신 결론 한 줄을
  `= 한 대를 잘라 나눠주면서, 게스트는 가로채였다는 사실도 모른다` 로 고쳤다.
  둘 다 정의 아래 배경 문단에 이미 있는 사실이라 새 정보는 아니다.

나머지 11편은 그림만 보고 정의가 복원됐다. 절차를 그림 자리에 올려둔 노트는 없었다.

## 5. 층 반증 테스트 — 1편에서 뒤집었다

층 도해 9개(Apache · Bare Metal · CI_CD · Hypervisor · Kubernetes · Logging ·
On-Premises · VM · VPS)에 이웃 맞바꾸기를 해봤다.

### 위아래가 거꾸로였다 — On-Premises

```
건물과 전력 :: … 여기부터 우리 몫      ← 맨 위였다
…
서비스 :: 원래 하려던 것. 맨 위 한 겹   ← 맨 아래였다
= 하려던 일은 맨 위 한 겹이고 나머지가 전부 딸려 온다
```

**그림이 자기 글자와 반대로 그려지고 있었다.** 앱은 위에서 아래로 갈수록 배경을 짙게
칠하고 "위가 가깝고 아래가 멀다" 로 읽히는데, 정작 "맨 위 한 겹" 이라고 적힌 서비스가
맨 아래에 있었다. 순서를 뒤집어 `서비스 → 운영체제 → 하드웨어 → 건물과 전력` 으로
세우고, 이제 바닥이 된 줄의 "여기부터 우리 몫" 을 "여기까지 우리 몫" 으로 고쳤다.
`=` 줄은 손대지 않았다 — 이제야 그림과 맞는다.

### 그대로 둔 것

- **Apache**(VirtualHost → Directory → .htaccess) — 넓은 범위에서 좁은 범위로 덮어쓰는
  축. 맞바꾸면 "아래로 갈수록 좁은 범위를 덮어쓴다" 가 거짓이 된다.
- **Bare Metal**(애플리케이션 → 운영체제 → 물리 하드웨어) · **Hypervisor**(게스트 OS →
  하이퍼바이저 → 호스트 OS → 하드웨어) · **VM**(앱 → 게스트 OS → 하이퍼바이저 →
  물리 하드웨어) — 셋 다 실제로 얹혀 있는 순서라 맞바꾸면 틀린다.
- **Kubernetes**(클러스터 → 노드 → 파드 → 컨테이너) — 담고 담기는 관계. 맞바꿀 수 없다.
- **Logging**(DEBUG → INFO → WARN → ERROR → FATAL) — 심각도 축. 맞바꾸면 순서가 깨진다.
- **CI_CD**(빌드 → 단위 테스트 → 통합 테스트 → 배포) — 시간처럼 보여 오래 봤다. 다시 보니
  **위 칸을 통과한 것만 아래로 내려가는 깔때기**다(마지막 마디가 `배포 :: 여기까지
  통과한 것만 올라간다`). 아래로 갈수록 대상이 줄어드는 부분집합 관계라 맞바꾸면 틀린다.
  마디 이름에도
  먼저/다음/N단계가 없다. 층으로 뒀다.
- **VPS**(공유 호스팅 → VPS → 전용 서버) — 나뉘는 깊이가 계정 → OS → 기계로 깊어지는
  축이고, 맞바꾸면 `= 가운데만 OS 가 나뉘어 있다` 가 거짓이 된다. Logging 의 레벨 층과
  같은 종류(겹겹이 아니라 순서 있는 눈금)라 같게 판정했다.

상태 전이를 층으로 그린 노트는 없었다.

## 6. 선행 용어 — 7편에서 반 구절로 풀었다

노트 밖에서 배워야 답을 아는 말들이다. 전부 `[[링크]]` 대신 반 구절을 골랐다 —
관련 용어 칸이 이미 3~5개로 차 있었고, 한 줄 안에서 풀리는 말들이었다.

| 노트 | 어디 | 어떻게 |
|---|---|---|
| CI_CD | 실제 사례 | 린트 → `린트(코드 스타일 자동 점검)` |
| Cron Job | 정의 배경 | 데몬 → `데몬(화면 없이 배경에서 계속 도는 프로그램)` |
| DevOps | 그림 마디 | `스테이징에 먼저` → `테스트 환경에 먼저` (같은 노트 어디에도 스테이징 설명이 없었다) |
| Elastic Search | 흔한 오해 | 트랜잭션 → `트랜잭션(여러 변경을 한 덩어리로 묶어 통째로 되돌리는 장치)` |
| Elastic Search | 해결하는 문제 | 희소성 → `희소성(흔한 단어일수록 점수를 적게 준다)` |
| Kubernetes | 작동 원리 | YAML → `YAML(들여쓰기로 구조를 나타내는 설정 형식)` |
| VM | 흔한 오해 | 커널 → `커널(운영체제에서 하드웨어를 직접 다루는 핵심부)` |
| VPS | 작동 원리 | 스왑 → `스왑(모자란 만큼을 디스크로 밀어내기)` |
| VPS | 비교 표 | `수직만` → `더 큰 장비로만` (수직 확장이라는 말을 노트가 안 가르친다) |

이미 반 구절로 풀려 있던 것들(Hypervisor 의 트랩, VPS 의 오버커밋, DevOps 의 IaC,
Cron Job 의 crontab 표현식)은 손대지 않았다.

## 손대지 않은 것

- H1 제목 · 파일 이름 · 폴더 — 하나도 건드리지 않았다.
- 섹션 구성 — 새 섹션을 만들거나 지우지 않았다. Cron Job · DevOps · On-Premises 는
  접이식 칸이 이미 6개로 꽉 차 있어 더 늘릴 수 없기도 했다.
- 없는 사실을 지어내지 않았다. 채워 넣은 문장은 전부 그 노트의 다른 자리에 이미 있던
  말이다(Hypervisor 의 `=` 는 정의 배경, DevOps 의 `=` 는 정의 배경에서 가져왔다).
