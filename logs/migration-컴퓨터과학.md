### 답이 노트 밖에 있던 질문: 없었다

54개 전부 이 노트 안에 답이 있었다. 답을 채우려고 새로 쓴 문장은 하나도 없다.

### 질문을 바꾼 것 (4건 — 전부 "답이 한 자리로 몰려서")

답이 없어서가 아니라, 셋이 같은 섹션을 두 번 겨누게 되어 확인이 안 되는 자리였다.
같은 데를 두 번 짚는 대신 다른 자리에 답이 있는 질문으로 바꿨다.

- **Cache** — "캐시 만료 시각을 전부 같게 잡으면 무슨 일이 생기나"
  답(주의사항의 "캐시가 동시에 비면 DB가 죽는다")은 있지만 둘째 질문이 이미 주의사항이었다.
  → **"캐시를 붙였는데 첫 요청만 오히려 조금 느려지는 이유는 → 그림"**.
  그림의 `= 두 번째부터 싸진다. 첫 번째는 오히려 조금 느리다` 가 그대로 답이다.
- **Hash** — "충돌이 잦아지면 조회 성능이 어떻게 되나"
  답이 작동 원리인데 둘째 질문(비밀번호 해시)도 작동 원리였다.
  → **"충돌이 생겼다면 해시 함수를 잘못 고른 탓인가 → 흔한 오해"**.
  "충돌은 설계 실수다 — 입력은 무한이고 출력은 유한하므로 반드시 생긴다" 가 답이다.
- **Stack** — "배열 대신 스택을 쓰면 얻는 것은 무엇인가"
  답이 흔한 오해인데 둘째 질문(스택 오버플로)도 흔한 오해였다.
  → **"재귀 깊이를 미리 알 수 없는 코드는 무엇으로 바꾸나 → 주의사항"**.
- **Thread** — "교착 상태를 만드는 잠금 순서 문제는 무엇인가"
  자리는 주의사항으로 맞지만 형태가 정의 되묻기였다. 상황을 주는 물음으로 고쳤다.
  → **"A 다음 B 로 잠그는 스레드와 B 다음 A 로 잠그는 스레드가 만나면 어떻게 되나 → 주의사항"**.

## 2. 흐름의 `<` 감사 — 3편은 `@` 로, 5편은 표지를 뗐다

"누가 누구에게 답을 주는가" 를 물어 판정했다. 검사기 경고는 참고만 했다.

### `@` 로 바꾼 것 (처음으로 돌아가 다시 하는 자리)

- **CPU** `< 반복 :: 전원이 꺼질 때까지 이것만 되풀이한다`
  → 가져오기·해석·실행·저장을 **처음부터 다시** 도는 것이다. 응답이 아니다.
  `@ 다시 처음으로` 로 바꿨다. 되돌아가는 곳이 첫 마디(가져오기)라 화살표도 맞는다.
- **Memory** ⚙️ 작동 원리 `< 다음 번 :: 같은 값을 다시 찾으면 위에서 끝난다`
  → 다음 조회가 다시 레지스터(첫 마디)부터 시작한다는 뜻이다. `@ 다음 번`.
- **Algorithm** 이진 탐색의 반복이 중간 마디(`반복 :: 남은 절반에서 다시 가운데를 본다`)에
  묻혀 있고, 끝의 `< 도착` 은 아무것도 안 돌려주고 있었다. 도착을 보통 마디로 내리고
  반복을 마지막 줄 **`@ 다시 가운데로`** 로 올렸다. 순환이 그림에 보이게 됐다.

### 표지를 뗀 것 (돌아오는 것이 없는 자리)

- **Heap** `< 아래로 :: 더 작은 자식과 바꿔가며 내려간다` — 내려가는 걸음이다.
- **Multi-thread** `< 결과 :: 전체 시간이 가장 느린 하나로 줄어든다` — 결론이지 응답이 아니다.
- **RAM** `< 종료 :: 그 자리를 비워 다른 프로그램에 내준다` — 자리를 비우는 끝 마디다.
- **Thread** `< 결과 :: 60이어야 하는데 70이 남았다` — 어긋난 결과, 응답 아님.
- **자료구조** `< 선택 :: 자주 하는 연산이 가장 빠른 쪽을 고른다` — 마지막 결정이다.

### 두고 온 `<` (실제로 응답이 되돌아온다)

Async-Await(응답 → 멈췄던 함수) · Binary(메모리 → 화면, 약속표를 거꾸로 뒤져 A 로) ·
Cache(캐시 → 앱) · Concurrency(서버들 → 도착 순서대로 처리) · Hash(표 → 프로그램) ·
Parallelism(코어 넷 → 모으기) · Process(프로세스 → OS 가 메모리와 PID 를 되받는다) ·
Stack(합치기 → 계산으로 반환).

## 3. 대조 감사 — 2편을 `|=|` 로 바꿨다

`||` 대조의 왼쪽 칸을 한 줄씩 읽었다.

- **Hash** ⚠️ `목록에서 찾기 || 해시 테이블`
  셋째 줄 `필요한 것 :: 없음 || 여분의 빈 칸` 에서 **왼쪽이 장점**이다. 그대로 두면
  해시가 메모리를 더 쓴다는 **비용**이 초록 ✓ 로 칠해져 미덕처럼 보인다.
  `= 메모리를 조금 더 쓰고 검색 시간을 사는 거래다` 가 이미 거래라고 말하고 있어
  **`|=|`** 로 바꿨다. "목록이 느리다" 는 바로 아래 두 문단이 그대로 말한다.
- **Thread** ⚠️ `프로세스 여러 개 || 스레드 여러 개`
  `하나가 죽으면 :: 나머지는 멀쩡 || 전체가 죽을 수 있다` — 왼쪽이 명백한 장점이고
  오른쪽이 단점인데 색이 거꾸로 붙는다. `= 싸고 편한 대신 하나가 잘못되면 같이 넘어진다`
  가 우열이 아니라 거래라고 말한다. **`|=|`**.

나머지 16편은 전부 "있고 없고" 이거나 왼쪽에 장점이 한 줄도 없어 `||` 그대로 뒀다
(절차 없이 / 콜백으로 / 실행 시간 재기 / 10 단계로 / 한 코어만 / 캐시 없이 / 순차로 /
매번 정렬하면 / 한 종류로 / 한 갈래 / 한 코어로 / 프로세스 없이 / 큐 없이 / 디스크에 두면 /
스택 없이 / 배열에 그냥).

## 4. 그림 자리 감사 — 자료구조를 갈아 끼웠다

"그림만 보고 정의 첫 문장을 복원할 수 있는가" 로 18편을 봤다.

- **자료구조** — 그림 자리가 `흐름: 자료구조 하나를 고를 때 무엇을 따져 보나` 였다.
  이건 규약 문서가 예로 든 바로 그 실패다. **고르는 절차**라서 자료구조가 무엇인지는
  말하지 않는다. → ⚙️ 작동 원리 맨 뒤로 내리고(고르는 절차는 작동 원리 자리다),
  같은 섹션에 있던 `층: 값 하나를 찾는 데 드는 시간은 어떻게 갈리나` 를 그림으로 올렸다.
  해시 테이블 / 이진 탐색 트리 / 배열·연결 리스트가 나란히 서서 "담는 모양에 따라
  걸리는 시간이 다르다" 를 2초에 보여준다 — 정의 첫 문장이 복원된다.
- **Multi-thread** — 같은 이름의 마디(`한 갈래로`)가 둘로 나뉘어 있어 번호가 붙으면
  "한 갈래로 하다가 여러 갈래로 넘어간다" 는 없는 순서가 생겼다. 하나로 묶었다.
- 나머지 16편은 그대로 뒀다. 전부 개념의 형태이고 절차가 올라온 편은 없었다.

## 5. 층 반증 테스트 — 4편에서 층이 아니었다

이웃한 둘을 맞바꿔 보고 그림이 안 틀리면 층이 아니라고 봤다.

- **Concurrency** ⚙️ `층: 하나의 흐름 안에서 작업은 어떤 상태를 오가나`
  (실행 중 / 준비됨 / 대기 중) — 제목부터 "**오가나**" 다. 상태 전이는 층이 아니라
  흐름이라고 규약에 적혀 있다. 준비됨과 대기 중을 맞바꿔도 그림이 안 틀린다.
  → **`@` 를 쓴 흐름으로 다시 세웠다**(실행 중 → 대기 중 → 준비됨 → 실행 중 → 다시 대기로).
  움직이는 것이 움직이는 것으로 보이게 됐다.
- **Parallelism** ⚙️ `층: 코어를 8배로 늘려도 8배가 안 되는 이유는 무엇인가`
  (프로세스 / 데이터 복사 / 결과 수집 / 못 나눌 곳) — 이건 **시간 순서**다. 바로 위
  문단이 "일을 쪼개고, 코어마다 돌리고, 결과를 합친다" 라고 이미 순서로 말하고 있었다.
  → **흐름으로 바꿨다**(나누기 → 프로세스 → 데이터 복사 → 계산 → 결과 수집).
  가운데 한 마디만 여덟 코어가 도는 것이 그림에 보인다.
- **Queue** ⚙️ `층: 큐를 어떻게 만드나`
  (연결 리스트 / 원형 배열 / 단순 배열) — 앞의 둘을 맞바꿔도 아무것도 안 틀린다.
  축이 없는 **구현 나열**이었다. 실제 정체는 "당기느냐 안 당기느냐" 두 갈래다.
  → **`||` 대조로 다시 세웠다**(단순 배열로 ‖ 당기지 않게 — 꺼낼 때 / 비용 / 항목이 늘면).
  연결 리스트와 원형 배열이라는 이름은 바로 아래 문단으로 옮겨 살렸다.
- **Thread** 🖼️ `층: 프로세스와 스레드는 무엇을 나눠 갖나`
  스레드 A 와 스레드 B 가 나란히 층으로 서 있었다. 형제를 위아래로 놓은 것이라
  맞바꿔도 아무 일이 안 일어나고, 없는 순서까지 생긴다.
  → **바깥에서 안으로의 축으로 다시 세웠다**(프로세스 → 공유하는 것 → 스레드마다).
  공유 영역과 전용 영역을 맞바꾸면 틀리므로 이제는 층이다.

### 살아남은 층 (맞바꾸면 틀린다)

- **Algorithm**·**Big O 표기법**·**자료구조**: 증가율/조회 비용 축. O(1) 과 O(n²) 을 맞바꿀 수 없다.
- **Binary**: 비트 → 바이트 → 문자 → 파일. 담김의 축이라 맞바꾸면 포함 관계가 깨진다.
- **Cache**·**CPU**·**Memory**·**RAM**: CPU 에서 멀어지는 거리 축. 단조롭게 느려진다.
- **Heap**·**Process**: 프로그램 메모리 영역. `= ` 줄이 "위쪽은 시작할 때 정해지고
  아래쪽은 도는 동안 늘었다 줄었다 한다" 로 축을 대놓고 말한다. 스택과 힙을 맞바꾸면 틀린다.

## 남긴 경고 1건 (왜 남겼나)

**Binary.md** — `응답 줄에 '다시' 가 있다 — < 화면 :: 다시 읽어 약속표를 거꾸로 뒤져 A 로 그린다`

문자열 검사의 **오탐이다.** 여기서 "다시" 는 처음으로 돌아가 같은 일을 되풀이한다는
뜻이 아니라, 메모리에 넣어둔 비트를 **되읽어 원래 글자로 되돌린다**는 뜻이다.
글자 A 로 시작해 비트로 내려갔다가 다시 A 로 올라오는 왕복이고, 그림의 결론
`컴퓨터 안에 글자 A 는 없다. 65 번이라는 약속이 있을 뿐이다` 가 그 왕복에 기대고 있다.
`@` 로 바꾸면 "저장을 계속 되풀이한다" 는 거짓말이 된다. 뜻을 보고 `<` 를 남겼다.
