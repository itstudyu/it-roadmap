# 이행 기록 — AI_ML-A (14편)

`docs/TERM-TEMPLATE.md` 전면 개정판 기준. 배정 14편 전부 `python3 tools/check_template.py --strict` 실패 0건 · 경고 0건.

---

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (14편 전편)

42개 질문 전부에 화살표를 달았다. 다는 것으로 끝내지 않고 **가리킨 섹션을 열어 답이 실재하는지 확인**했다.
질문 셋이 같은 섹션을 겨누게 된 경우가 5편에서 나왔고, 그때는 답이 실제로 있는 다른 섹션으로 질문을 옮기거나 질문 자체를 바꿨다.

### 답이 노트 안에 없어서 질문을 바꾼 것 — 이번 이행의 수확

| 노트 | 원래 질문 | 무엇이 문제였나 | 어떻게 했나 |
|---|---|---|---|
| CNN | 고양이가 사진 왼쪽에 있든 오른쪽에 있든 같게 보이게 만드는 단계는? | 큰 위치 이동을 견디는 건 **필터 공유**(해결하는 문제)이고 풀링은 몇 픽셀 수준이다. 질문이 두 섹션에 걸쳐 답이 한 군데로 안 모였다 | 질문을 버리고 **"필터에 넣을 숫자는 누가 정하고, 사람이 정하는 것은 무엇인가 → 흔한 오해"** 로 교체. 흔한 오해에 "사람이 정하는 건 필터의 크기와 개수다" 가 그대로 있다 |
| Guardrail | 규칙을 너무 세게 잡으면 어떤 일이 생기나? | 답이 흔한 오해 한 군데에만 있는데, 1번 질문("프롬프트에 써두면 된다")도 같은 자리를 가리켜 셋 중 둘이 겹쳤다 | **"규칙에 걸려 막혔는데 이유를 안 알려주면 사용자는 무엇을 하나 → 작동 원리"** 로 교체. 작동 원리에 "시스템이 고장 났다고 여기고 같은 요청을 되풀이한다" 가 있다 |
| Fallback | 폴백을 다섯 단계로 늘리면 사용자 쪽에서는 무엇이 나빠지나? | 답이 흔한 오해에만 있어 2번 질문과 겹쳤다 | **"폴백 순서를 아래까지 내려가서 받은 답은 무엇이 약한가 → 주의사항"** 으로 교체. 주의사항의 "아래로 내려갈수록 답의 근거가 약해진다" 가 답이다 |
| Chunking | 조항 번호가 붙은 사규를 자를 때 어떤 기준이 가장 잘 맞나? | 답이 작동 원리에 있어 2번 질문과 겹쳤다. 실제 사례에 더 구체적인 답(조항 번호 + 출처 저장)이 있었다 | 질문을 **"무엇을 기준으로 자르고 무엇을 함께 저장하나 → 실제 사례"** 로 넓혀 실제 사례를 겨누게 했다 |

내용을 새로 채워 넣은 자리는 없다. 네 건 모두 **이미 노트에 있는 사실 쪽으로 질문을 옮기는** 방향으로 풀었다.

## 2. 흐름의 `<` 감사

"누가 누구에게 답을 주는가" 를 물어 판정했다. 검사기 경고는 문자열 검사라 참고만 하고 뜻으로 판단했다.

### `<` → `@` (처음으로 돌아가 다시 하는 순환)

- **AI Agent** `< 에이전트 :: 없으면 답하고 끝, 있으면 다시 판단으로` → `@ 다시 판단으로 :: 없으면 답하고 끝, 있으면 한 바퀴 더`
  판단으로 되돌아가는 것이지 응답이 오는 게 아니다. 이 노트의 `=` 줄이 "목표에 닿을 때까지 돈다" 인데 직선으로 펴 그려서 순환이 사라져 있었다.
- **Few-shot & Zero-shot** `< 비용 :: 예시만큼의 토큰을 매번 같이 보낸다` → `@ 다음 요청 :: 예시를 또 붙여야 한다. 토큰도 매번`
  "비용" 은 응답이 아니다. 이 노트의 흔한 오해 1번("Few-shot은 모델을 학습시키는 것이다 — 다음 요청에는 다시 붙여야 한다")이 지우려는 오해가 바로 이 순환이라, `@` 로 그리니 그림이 오해를 먼저 막는다.

### `<` → 표지 없는 보통 마디 (아무것도 안 돌아온다)

- **CNN** `< 출력 :: 고양이 90%, 개 10%` — 파이프라인의 끝일 뿐 되돌아오는 것이 없다.
- **Chunking** `< LLM :: 고른 조각만 읽고 답을 만든다` — 검색→생성은 계속 앞으로 가는 방향이다.
- **Cosine Similarity** `< 상위 몇 개 :: 점수 높은 순으로 골라 넘긴다` — 넘기는 것이지 돌려주는 것이 아니다.
- **Embedding** `< 결과 :: 각도가 가장 작은 문서가 뜻이 가장 가깝다` — 계산의 결론이지 응답이 아니다.
- **Fine-tuning** `< 사용 :: 긴 지시문 없이 질문만 보내도 그 말투로 답한다` — 학습이 끝난 뒤의 다음 단계다.

### `<` 는 맞지만 되돌아가는 대상이 틀려서 고친 것

- **Context Window** `< 모델 :: 창 안에 남은 것만 보고 답한다` → `< 사용자 :: 창 안에 남은 것만 보고 만든 답을 받는다`
  답을 받는 쪽은 사용자다. 여기에 `@ 다음 질문 :: 지난 대화가 또 통째로 붙어 온다` 를 마지막 줄로 더했다 — `=` 줄이 "매번 통째로 다시 읽는 것이다" 라고 주장하는데 그림에는 그 순환이 없었다.
- **Intent 분류** `< 담당 :: 정해진 쪽이 실제 답을 만든다` → `< 담당 :: 정해진 쪽이 답을 만들어 돌려준다`
  "만든다" 로 끝나면 되돌아오는 길이 아니다. 돌려준다는 사실을 마디에 적어 표지와 뜻을 맞췄다.

### 새로 `@` 를 더한 것

- **Fine-tuning** `@ 내용이 바뀌면 :: 예시를 고쳐 처음부터 다시 돌린다`
  이 노트가 세 군데(해결하는 문제 · 비교 표 · 흔한 오해 3번)에서 반복해 말하는 단 하나의 함정인데 그림에는 없었다.

### 손대지 않은 `<` — 실제로 응답이 돌아온다

Agent(`< 사용자 :: 완성된 보고서를 받는다`) · Escalation(`< 담당자 :: 사람이 이어받아 답한다`) · Guardrail(`< 사용자 :: 네 자리를 다 통과한 답만 보인다`) · Hallucination(`< 사용자 :: 존재하지 않는 논문을 받는다`). 넷 다 물은 쪽이 답을 받는다.

### 마디 구조를 다시 짠 것

- **Fallback** — `< 최종 :: 전부 실패하면 정해둔 문구를 돌려준다` 가 응답 마디 뒤에 붙어 있어, 최종 문구가 "돌아오는 길" 로 그려지고 있었다.
  `최종 :: 여기까지도 못 찾으면 정해둔 문구` 를 보통 마디로 제자리에 놓고, 되돌아오는 자리는 `< 사용자 :: 어느 순서에서 나왔든 답을 하나 받는다` 로 새로 세웠다.

## 3. 대조 감사 — ✕ 칸 자기검사

14편의 `||` 대조를 전부 훑었다. **왼쪽 칸에 장점이 든 대조는 없었다.** `|=|` 로 바꾼 것도 없다.
Embedding 의 `"환불 불가" 문서 :: 찾는다 || 찾는다` 는 무승부 줄이라 장점이 아니다 — 키워드 검색이 아무 데도 못 쓰는 것처럼 보이지 않게 막아주는 좋은 줄이라 그대로 뒀다.
Chunking · Context Window · Escalation · Fallback · Guardrail · Hallucination · Intent 분류는 "있고 없고" 대조라 `||` 가 맞다.

한 칸만 고쳤다.

- **AI Agent** `단계 :: 한 번에 끝 || 목표까지 반복` → `단계 :: 한 번 답하고 끝 || 목표까지 반복`
  "한 번에 끝" 은 ✕ 칸에 놓였는데도 "빠르다" 는 장점으로 읽힐 수 있었다. 한 걸음에서 멈춘다는 한계임을 분명히 했다.

## 5. 층 반증 테스트

`층` 도해가 있는 노트는 다섯이다. 이웃한 둘을 맞바꿔 그림이 틀리는지 봤다.

### 층이 아니었던 것

- **Agent** `층: Agent 는 무엇으로 이루어져 있나` (LLM · 도구 · 기억 · 멈춤 조건)
  도구와 기억을 맞바꿔도 그림이 안 틀린다. `=` 줄도 "도구가 없으면… 기억이 없으면…" 하고 **열거로 시작**한다. 축이 없는 목록이었고, 멈춤 조건은 애초에 공간 축 위에 놓일 물건이 아니다.
  → **본문 불릿으로 되돌렸다.** 내용은 한 줄도 안 버렸다.
- **Embedding** `층: 무엇을 임베딩할 수 있나` (단어 · 문장 · 문단 · 이미지)
  앞의 셋은 크기 축인데 이미지가 그 축 밖에 있어 축이 도중에 끊긴다. `=` 줄("같은 공간에 넣으면…")도 순서와 무관하다.
  → **본문 불릿으로 되돌렸다.**
- **AI Agent** `층: 에이전트는 무엇으로 이루어져 있나` (LLM · 계획 · 기억 · 도구)
  계획과 기억을 맞바꿔도 안 틀린다. 다만 이 노트에는 **진짜 축**이 있었다 — 흔한 오해 1번과 정리가 똑같이 "모델은 같은 것을 쓴다, 달라지는 건 바깥 구조다" 라고 말한다.
  → 그 축으로 **다시 세웠다.** `층: 어디까지가 모델이고 어디부터 붙인 것인가` (LLM 자체 / 계획·기억 / 도구). 이제 셋 중 어느 둘을 바꿔도 안→밖 읽기가 깨진다. `=` 줄도 순서에 기대는 문장으로 바꿨다("그 위에 얹은 두 겹이다").

### 진짜 층이라 그대로 둔 것

- **CNN** (1층→2층→3층→4층): 모서리가 곡선보다 먼저 와야 한다. 맞바꾸면 틀린다.
  다만 마디 이름 `마지막` 이 시간으로 읽혀 검사기 경고가 떴다. 실제로는 깊이지 시간이 아니므로 **`4층` 으로 이름만 고쳐** 나머지와 표기를 맞췄다.
- **Cosine Similarity** (0.9 이상 → 0.3 미만): 눈금이라 순서가 곧 뜻이다.
- **Hallucination** (최신 정보 → 일반 상식): `=` 줄이 "아래로 갈수록 안전하다" 라고 순서에 기대고 있다.

## 6. 선행 용어

노트 밖에서 배워야 하는 말이 도해 마디나 본문에서 맨몸으로 나오는 자리를 반 구절로 풀었다.

- **Chunking** 도해 `청크 :: 조각마다 벡터로 바꿔 저장한다` → `벡터(뜻의 좌표)로 바꿔 저장한다`.
  이어지는 `질문 :: 들어온 질문도 벡터로 바꾼다` 는 `같은 방식으로 바꾼다` 로 고쳐 같은 말을 두 번 안 쓰게 했다.
- **Cosine Similarity** 정의 배경 문단 `벡터의 크기는 버리고` → `벡터(뜻을 담은 숫자 목록)의 크기는 버리고`.
  표제어가 "두 벡터를 견주는 값" 인데 벡터를 한 번도 안 풀어주고 있었다.
- **Embedding** 작동 원리 첫 문장에 `임베딩이 만들어낸 숫자 목록을 벡터라고 부른다.` 를 앞세웠다. 정의는 "숫자 목록" 이라 부르고 작동 원리는 갑자기 "벡터" 라고 불러 이름이 갈라져 있었다.
