# 보안-B 이행 기록 (17편)

`python3 tools/check_template.py` 로 배정 17편 전부 **실패 0건 · 경고 0건**.
H1 제목 · 파일명 · 폴더는 하나도 건드리지 않았다.

## 1. 확인 질문 — 51개 전부에 `→ 답이 있는 자리` 를 달았다

모든 편에서 화살표 뒤 섹션을 직접 열어 답이 실재하는지 확인했다.
세 질문이 서로 다른 섹션을 겨누게 맞췄다.

### 답이 노트 안에 없어서 질문을 바꾼 것 — 이번 이행의 수확

| 노트 | 원래 질문 | 무엇이 문제였나 | 어떻게 했나 |
|---|---|---|---|
| RBAC | 권한 규칙 하나가 바뀌었을 때 역할을 쓰면 100명 중 몇 군데를 고치게 되나 | 답이 "퇴사자" 질문과 **같은 섹션**(해결하는 문제)에만 있어 확인이 겹쳤다 | 질문을 갈아 그림을 겨누게 했다 — "글 삭제 요청이 왔을 때 서버가 대조하는 것은 사람인가 역할의 권한인가 → 그림" |
| SSL_TLS | 인증서를 갱신하지 않으면 접속이 아예 막히는 이유는 | "왜"에 해당하는 답이 작동 원리에만 있는데 그 자리를 세 번째 질문이 이미 쓰고 있었다 | "암호화만 해두면 가짜 서버가 중간에 앉는 것을 왜 못 막나 → 해결하는 문제" 로 교체. 답은 해결하는 문제 본문에 그대로 있다 |
| SSO | 여러 서비스에 같은 비밀번호를 쓰는 것과 SSO는 어떻게 다른가 | 답을 흔한 오해에서 찾으면 세 질문 중 둘이 흔한 오해로 몰렸다 | 같은 답이 해결하는 문제 본문·대조에도 있어 그쪽으로 겨눴다 |
| Zero Trust | 방화벽 안쪽이라는 사실이 왜 더 이상 신뢰의 근거가 못 되나 | 두 번째 질문과 같은 섹션(해결하는 문제)을 겨눴다 | "사내망 안에서 접속했다는 사실은 접근 판단에서 어떻게 쓰이나 → 그림" 으로 바꿨다. 그림의 `=` 줄이 곧 답이다 |
| QueryPie | 개발자가 개인정보 컬럼을 조회했는데 원본이 안 보인다면 어느 단계에서 가려진 것인가 | 답은 있으나("마스킹은 결과가 나갈 때 걸린다") 물음이 단계 이름을 되묻는 꼴이었다 | "조회 결과에서 주민번호가 가려졌다면 원본 데이터는 어떻게 된 것인가 → 작동 원리" 로 다듬었다 |

나머지 12편은 원래 질문의 답이 노트 안에 실재해서 화살표만 달았다.

## 2. 흐름의 `<` 감사 — 7편에서 고쳤다

`<` 앞에는 앱이 "여기서부터 돌아오는 길" 을 새긴다. **누가 누구에게 답을 주는가**로 물었다.

| 노트 | 원래 | 판정 | 고친 것 |
|---|---|---|---|
| Refresh Token | `< 클라이언트 :: 원래 요청을 새 토큰으로 다시 보낸다` | 클라이언트가 **나가는** 줄이다. 돌아오는 게 없다 | `@ 다시 처음으로 :: 새 토큰으로 원래 요청을 보낸다` 로 옮기고, 진짜 응답인 `< 인증 서버 :: 확인하고 새 액세스 토큰을 내준다` 에 `<` 를 달았다 |
| Step-up Auth | `< 서버 :: Level 2 로 다시 온 송금 요청을 처리한다` | 승격된 토큰으로 **송금을 처음부터 다시** 한다 | `@ 다시 송금으로 :: 이번에는 Level 2 라 그대로 처리된다` |
| Zero Trust | `< 접근 허용 :: 넷 다 통과했을 때만. 다음 요청에 또 확인한다` | 한 줄에 허용과 순환이 뭉쳐 있었다. 제로 트러스트의 핵심이 곧 순환인데 직선으로 펴져 있었다 | `허용 :: 넷 다 통과했을 때만 열어준다` + `@ 다음 요청에 :: 넷을 처음부터 또 확인한다` |
| QueryPie | `< 기록 :: 누가 언제 무엇을 돌렸는지 남긴다` | 기록은 누구에게도 답을 주지 않는다 | 기록을 보통 마디로 내리고, 실제로 돌아오는 `< 개발자 :: 개인정보 컬럼을 가린 결과를 받는다` 를 마지막에 뒀다 (마스킹이 결과가 나갈 때 걸린다는 본문과도 맞다) |
| SSL_TLS | `< 이후 :: 그 열쇠로 내용을 가려서 주고받는다` | 핸드셰이크가 끝난 뒤의 통신이지 응답이 아니다 | 표지 없는 보통 마디 |
| 인증서 | `< 둘 다 :: 그 열쇠로 암호화해서 주고받는다` | 위와 같다 | 표지 없는 보통 마디 |
| Session | `< 서버 :: abc123 으로 저장소를 뒤져 누구인지 알아본다` | 브라우저가 보낸 쿠키를 서버가 **받는** 줄이다 | 표지 없는 보통 마디 |
| 암호화 | `< 평문 :: 원래 내용이 그대로 나온다` | 값이 원래 모습으로 돌아오는 것이지 누가 답을 주는 게 아니다 | 표지 없는 보통 마디 |

**검사기 경고를 그대로 따르지 않은 자리** — 경고가 없던 5편(Zero Trust · QueryPie · SSL_TLS · 인증서 · Session)에서도 뜻을 보고 고쳤다.
반대로 `<` 를 그대로 둔 자리: RBAC(403 응답) · SAML(보증서가 SP 로 돌아온다) · SQL Injection(로그인 결과가 공격자에게) · SSH(서버가 문을 연다) · SSO(증표가 위키로) · Token 인증(데이터 또는 401) · XSS(쿠키가 공격자 서버로) · 인바운드 아웃바운드(결과를 사용자에게).

## 3. 대조 감사 — ✕ 칸 자기검사

왼쪽 칸에 장점이 있는 `||` 는 **없었다.** 배정 17편의 `||` 대조는 전부
"있고 없고"(암호화 없이 / 규칙 없이 / SSO 없이 / Telnet 으로) 라 왼쪽이 실제로 나쁜 상태다.
억지로 `|=|` 로 바꾸지 않았다.

한 곳만 새로 `|=|` 를 썼다.

- **암호화** — 대칭키와 비대칭키는 우열이 없다. 대칭키는 "빠르다", 비대칭키는 "알려줘도 된다"가
  각각 명백한 장점이라 `||` 로 두면 그림이 2초 만에 거짓말을 한다. `대칭키 |=| 비대칭키` 로 세웠다.

**판단하고 남긴 것 — Token 인증의 `세션으로 || 토큰으로`.**
같은 노트의 흔한 오해가 "토큰이 세션보다 무조건 안전하다" 를 지우려 하므로 위험한 자리다.
그래도 `||` 로 뒀다. 세 줄(로그인 정보 · 다른 서버로 · 공용 저장소)이 전부 **서버를 늘리는 축** 하나에
매여 있고 그 축에서 세션 쪽 장점은 한 줄도 없다. 도해 제목도 "서버를 여러 대로 늘리면 무엇이
달라지나" 로 축을 못 박아 두었다. 축을 넓히는 순간 `|=|` 로 가야 한다.

## 4. 그림 자리 감사 — 1편에서 바꿨다

판정법: **그림만 보고 정의 첫 문장을 복원할 수 있는가.**

- **SSH** — 정의 첫 문장은 "멀리 있는 컴퓨터에 **암호화된 통로**로 접속하는 규약"인데,
  그림 자리에 있던 흐름은 공개키 인증만 보여줘서 암호화가 복원되지 않았다.
  작동 원리에 있던 층("SSH 통로 하나로 무엇까지 할 수 있나")은 층이 아니었고(→ 5번),
  그 자리를 진짜 층으로 다시 세워 그림 자리로 올렸다.
  - 🖼️ 그림 = `층: SSH 연결 하나는 무엇 위에 무엇을 쌓나` (셸과 전송 / 인증 / 암호 통로 / TCP 22)
  - ⚙️ 작동 원리 = 공개키 인증 흐름 (원래 그림 자리에 있던 것). "어떻게 작동하나" 에 제자리다.

나머지 16편은 통과했다. 특히 RBAC 의 권한 확인 흐름은 "절차"처럼 보이지만
`= 묻는 것은 "누구냐" 가 아니라 "그 역할에 이 권한이 있나" 다` 가 정의를 그대로 복원해서 남겼다.

## 5. 층 반증 테스트 — 4편에서 층이 아니었다

**이웃한 두 층을 맞바꿔도 그림이 안 틀리면 층이 아니다.**

| 노트 | 원래 층 | 왜 층이 아닌가 | 어디로 보냈나 |
|---|---|---|---|
| Zero Trust | `층: 요청마다 무엇을 근거로 판단하나` (신원/기기/권한/맥락) | `= 넷을 종합해` — 집합어로 시작한다. 넷은 나란히 보는 값이라 신원과 기기를 맞바꿔도 안 틀린다 | **본문 불릿**으로 되돌렸다. 그림 자리 흐름이 이미 같은 넷을 확인 마디로 보여준다 |
| 인바운드 아웃바운드 | `층: 방화벽 규칙 하나는 무엇으로 이루어지나` (방향/상대/포트/허용) | `= 이 넷이 다 맞아야` — 규칙 한 줄의 **구성 요소**지 겹겹이 아니다 | **본문 한 문단**으로 되돌렸다 |
| SSH | `층: SSH 통로 하나로 무엇까지 할 수 있나` (원격 셸/파일 전송/포트 포워딩) | `= 여러 가지를 얹을 수 있다` — 셋은 나란한 쓰임새다. 맞바꿔도 안 틀린다 | **진짜 축(프로토콜 스택)으로 다시 세워** 그림 자리로 승격 (→ 4번). 셋의 쓰임새는 맨 위 층과 흔한 오해에 남아 있다 |
| 암호화 | `층: 암호화는 어떤 갈래로 나뉘나` (대칭키/비대칭키/해시) | 갈래 나열이다. 대칭키와 비대칭키를 맞바꿔도 안 틀린다 | **대조 `|=|`** 로 바꿨다 (→ 3번). 해시는 작동 원리 본문 한 문단으로 옮겨 `[[Hash]]` 를 걸었다 |
| SAML | `층: SAML 에서 각자는 무엇까지 아나` (사용자/IdP/SP) | 참여자 나열이다. 사용자와 IdP 를 맞바꿔도 안 틀린다 | **진짜 축(정보가 얼마나 남나)으로 다시 세웠다** — `층: 비밀번호는 어디까지 가고 어디서 멈추나` (IdP 원본 → 보증서 발췌 → SP 수신). 이제 맞바꾸면 거짓이 된다 |

**층으로 남긴 것과 그 근거** — 맞바꾸면 실제로 틀어지는 것들이다.
RBAC(사용자–역할–권한: 가운데를 빼면 개념 자체가 사라진다) ·
Refresh Token(둘 자리를 안전한 순서로) · SQL Injection(막는 확실성 순서, `=` 줄이 위아래를 못 박는다) ·
SSO(신뢰의 원천 → 전달물 → 수신자) · Session(가까운 저장소 → 먼 저장소) ·
Step-up Auth(Level 0/1/2 사다리) · Token 인증(Header·Payload·Signature 는 서명이 위 둘을 덮는 순서) ·
방화벽 규칙(위쪽 규칙 → 아래쪽 규칙 → 기본 정책: 이름 자체가 위치다) ·
인증서(루트 CA → 중간 CA → 사이트 인증서 신뢰 사슬) · SSH 새 층(TCP → 암호 통로 → 인증 → 응용).

## 6. 선행 용어

노트 밖에서 배워야 하는 말을 반 구절로 풀거나 `[[링크]]` 를 걸었다.

- **SAML** — `IdP` · `SP` 가 그림 도해 마디에 설명 없이 나왔다. 정의 배경 문단에
  "인증을 맡는 쪽을 IdP, 서비스를 내주는 쪽을 SP 라고 부른다" 를 넣어 그림보다 앞에 두었다.
- **SQL Injection** — `ORM(객체와 테이블을 짝지어 질의문을 대신 써주는 도구)`
- **XSS** — `DOM 기반(브라우저 안에서 화면을 고치는 코드가 원인인 것)`
- **Step-up Auth** — 비교표의 `OTP(일회용 코드)`
- **방화벽 규칙** — 주의사항의 `0.0.0.0/0(모든 주소)`
- **암호화** — `무결성 확인` → `내용이 그대로인지 보는 무결성 검사`
- **Refresh Token** — 층과 주의사항이 XSS 를 전제한다. 주의사항에 `[[XSS]]` 를 걸고
  관련 용어에 한 줄 올렸다(4개 → 5개).
- **Token 인증** — 작동 원리 첫 줄의 `JWT` 를 `[[JWT]]` 로. 이미 관련 용어에 있던 이름이다.
- **SSO** — `[[SAML]]` 본문 링크, `OIDC 는 [[OAuth]] 위에 **신원 확인을** 얹은 방식`
- **인증서** — `최상위 발급 기관([[CA]])의 인증서`

## 남겨둔 판단

- **Step-up Auth 대조의 `잔액 조회 :: 그냥 된다 || 그냥 된다`** — 양쪽이 같다. ✕ 칸에 장점은 없으니
  자기검사는 통과하고, "가벼운 일은 이 방식이 건드리지 않는다"를 보여주는 줄이라 그대로 뒀다.
- **방화벽 규칙**은 그림(패킷이 목록을 내려간다)과 층(위쪽/아래쪽/기본 정책)이 겹쳐 보이지만,
  층 이름이 곧 위치라 맞바꾸면 즉시 거짓이 된다. 둘 다 남겼다.
- **SAML 관련 용어의 `[[Certificate]]`** — 이 저장소의 파일은 `content/보안/인증서.md` 다.
  링크 해석 규칙을 확인하지 못해 손대지 않았다. 통합 담당이 한 번 봐주면 좋겠다.
