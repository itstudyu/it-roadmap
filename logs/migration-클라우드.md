# 이행 기록 — 클라우드 (13편)

대상: AWS · Availability Zone · Azure · Cloud · EC2 · IaaS_PaaS_SaaS · Lambda ·
Region · S3 · Serverless · Subnet · Tenant · VPC

검사 결과: **13편 실패 0건 · 경고 0건** (`--strict` 로도 0건)

---

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (13편 전부)

13편 모두 화살표가 없었다. 전부 달았고 **화살표가 가리키는 섹션을 열어
거기에 답이 정말 있는지 한 줄씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고,
끝의 물음표는 본보기(DNS·HTTP)와 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| AWS | 해결하는 문제 · 흔한 오해 · 작동 원리 |
| Availability Zone | 흔한 오해 · 작동 원리 · 비교 |
| Azure | 작동 원리 · 흔한 오해 · 비교 |
| Cloud | 해결하는 문제 · 작동 원리 · 그림 |
| EC2 | 작동 원리 · 주의사항 · 흔한 오해 |
| IaaS_PaaS_SaaS | 비교 · 실제 사례 · 흔한 오해 |
| Lambda | 작동 원리 · 흔한 오해 · 주의사항 |
| Region | 흔한 오해 · 비교 · 작동 원리 |
| S3 | 해결하는 문제 · 작동 원리 · 비교 |
| Serverless | 흔한 오해 · 작동 원리 · 주의사항 |
| Subnet | 작동 원리 · 해결하는 문제 · 실제 사례 |
| Tenant | 그림 · 흔한 오해 · 작동 원리 |
| VPC | 해결하는 문제 · 작동 원리 · 흔한 오해 |

### 답이 겹쳐서 질문을 바꾼 것 (1건)

- **EC2** — "인스턴스를 정지시켰는데 요금이 조금씩 나온다면 무엇 때문인가"
  답은 흔한 오해의 "인스턴스를 껐으니 요금이 안 나간다" 한 곳뿐인데,
  셋째 질문("EC2 가 스스로 대수를 늘리지 않는 이유")의 답도 같은 섹션이었다.
  이 노트의 주의사항은 키 파일과 포트 이야기뿐이라 옮겨 짚을 자리가 없다.
  억지로 같은 데를 두 번 짚지 않고
  **"인스턴스를 멈췄다 다시 켜도 안에 있던 파일이 그대로인 이유는 → 작동 원리"** 로 바꿨다.
  작동 원리의 "디스크는 인스턴스와 별개로 붙는다. 그래서 인스턴스를 멈췄다 켜도
  디스크 내용은 남고" 가 그대로 답이고, 정리가 못 박는 "정지와 종료가 서로 다른 일" 을
  같은 축에서 묻는다.

**답이 아예 노트에 없어서 내용을 채운 편은 없었다.** 나머지 38개 질문은 전부
노트 안에 답이 있었고, 겨누는 섹션만 정해 주면 되는 자리였다.

## 2. 흐름의 `<` 감사 — 4편에서 뗐고 1편에서 옮겼다

"누가 누구에게 답을 주는가" 를 물었다. `<` 앞에는 앱이 "여기서부터 돌아오는 길" 을
새기므로, 대답이 안 나오는 자리에 두면 그림이 거짓말을 한다.

### 뗀 것 (4편)

- **AWS** `< 사용자 :: 붙인 도메인으로 들어와 화면을 받는다`
  이 흐름의 시작은 "리전을 고른다" 이고 그 임자는 **만드는 사람**이다.
  마지막 마디의 사용자는 나중에 찾아온 방문자라 시작한 쪽으로 돌아오는 것이 없다.
- **Azure** `< 사용자 :: 만들어진 주소로 들어온다` — AWS 와 같은 모양. 뗐다.
- **Lambda** `< Lambda :: 함수가 끝나면 과금을 멈춘다`
  사건을 알린 S3 에게 아무것도 돌아가지 않는다. 뒷정리지 응답이 아니다.
- **S3** `< 브라우저 :: 주소로 사진을 받아 화면에 띄운다`
  이 흐름의 시작은 "앱이 사진을 올린다" 다. 브라우저는 앞에서 묻지 않았으므로
  받아 가는 것이지 돌려받는 것이 아니다. 올림 → 저장 → 가공 → 캐시 → 내보냄의
  한 방향 관이다.
- **IaaS_PaaS_SaaS** `< 운영 :: 감시하고 고치고 늘렸다 줄인다`
  응답이 아니다. 그렇다고 "서버 마련" 으로 돌아가는 것도 아니라 `@` 도 아니다.
  (`@` 는 화면에서 **첫 마디**를 가리키며 되돌아온다.) 표지 없는 보통 마디로 뒀다.

### 옮긴 것 (1편)

- **Serverless** `< 클라우드 :: 잠시 살려뒀다가 요청이 없으면 지운다` →
  `< 함수 :: 코드가 실행되고 결과를 돌려준다`
  응답이 실제로 되돌아가는 자리는 함수가 결과를 돌려주는 줄이다. 뒷정리 줄에 붙어 있던
  표지를 한 줄 위로 옮겼다. 첫 마디가 "사용자 :: 요청을 보낸다" 라 돌아갈 임자도 맞다.

### 두고 온 `<` (뜻을 보고 남긴 것)

- **Availability Zone**(사용자 → 로드밸런서 → … → 사용자): 처음 들어온 사용자가
  같은 화면을 받는다. 실제 왕복이다.
- **EC2**(사양을 고른 사람 → AWS → 그 사람이 SSH 로 들어감): DNS 본보기의
  `< 브라우저 :: 받은 IP 로 접속` 과 같은 모양이다. 시작한 임자가 결과를 받아 쓴다.
- **Region**(사용자 → DNS → 리전 → 사용자), **Subnet**(요청 → 웹 서버 → `< DB` 가
  웹 서버에게 답한다), **Tenant**(요청 → 식별 → 조회 → `< 응답`): 전부 응답이 돌아온다.

검사기가 걸어준 "다시/반복/매번" 경고는 이번 13편에 한 건도 없었다. 위 판정은
문자열이 아니라 **첫 마디의 임자와 마지막 마디의 임자가 같은가**로 갈랐다.

## 3. 대조 감사 — 바꾼 것 없음

13편의 `||` 대조를 왼쪽 칸부터 읽었다. 전부 "있고 없고" 꼴이고 왼쪽에 장점이 한 줄도 없다.

직접 장만 / 서버실 직접 / 직접 사면(Cloud·EC2) / 한 곳에만 / 한 리전만 /
서버 디스크에 / 서버에 두면 / 서버 상시 운영 / 한 덩어리로 / 고객마다 따로 / VPC 없이 —
왼쪽은 전부 실제로 나쁜 상태다. 규약이 그대로 두라고 한 자리라 `|=|` 로 바꾸지 않았다.

**Tenant 만 한 번 더 봤다.** 싱글 테넌시에는 "보안 설계가 단순하다 · 맞춤 변경이 쉽다" 는
장점이 있는데, 그 둘은 대조가 아니라 📊 비교 표에 들어가 있다. 대조가 겨눈 것은
"고객사가 천 곳으로 늘면" 이라는 조건이고 그 조건 아래 왼쪽은 세 줄 다 나쁘다.
`||` 가 맞다.

## 4. 그림 자리 감사 — 2편을 바꿔 끼웠다

13편 모두 "그림만 보고 정의 첫 문장을 복원할 수 있는가" 를 물었다.

- **Availability Zone** — 그림 자리에 `흐름: 가용 영역 하나가 죽으면 무슨 일이 일어나나`
  가 있었다. 장애가 났을 때의 **거동**이지 개념의 형태가 아니다. 그림만 봐서는
  정의 첫 문장("한 리전 안에서 전원과 망이 따로 도는 데이터센터 묶음")의
  "한 리전 안에서" 도 "데이터센터 묶음" 도 복원되지 않는다.
  → 작동 원리에 있던 `층: 리전과 가용 영역은 어떻게 겹쳐 있나`(리전 → 가용 영역 →
  데이터센터 → 랙과 서버)를 그림 자리로 올리고, 장애 흐름을 작동 원리로 내렸다.
  작동 원리의 두 문단이 로드밸런서 헬스 체크와 복제본 승격을 설명하고 있어서
  내려간 흐름과 바로 맞물린다.
- **IaaS_PaaS_SaaS** — 그림 자리에 `흐름: 서비스를 하나 올리려면 무엇을 해야 하나`
  가 있었다. **올리는 절차**지 개념이 아니고, 그림 안에 IaaS·PaaS·SaaS 라는 말이
  한 번도 안 나온다. 정의 첫 문장을 복원할 길이 없다.
  → 작동 원리의 `층: 어디까지를 제공사가 맡나`(SaaS → PaaS → IaaS → 온프레미스)를
  그림 자리로 올렸다. 이 층은 정의 첫 문장 그 자체다. 절차 흐름은 작동 원리로 내렸고,
  뒤따르는 세 문단이 IaaS·PaaS·SaaS 를 하나씩 풀어서 자리가 맞는다.

### 그대로 둔 것

- **AWS**(리전·EC2·RDS·S3 를 하나씩 빌려 끼우는 흐름) — "필요한 조각만 빌린다" 가
  정의 첫 문장이라 복원된다.
- **Azure**(구독 → 리소스 그룹 → VM · Blob · SQL DB) — 무엇을 빌려 쓰는지가 보인다.
  해결하는 문제의 대조를 끌어올리면 그 자리가 비어버리기도 한다(해결하는 문제는
  대조 도해 하나가 규약이다).
- **Cloud**(SaaS → PaaS → IaaS → 직접 운영) · **VPC**(VPC → 퍼블릭 → 프라이빗 →
  보안 그룹) — 원래 층이고 형태다.
- **EC2 · Lambda · Region · S3 · Serverless · Subnet · Tenant** — 흐름이지만
  "고르는 절차" 가 아니라 그 개념이 하는 일 자체라 정의가 복원된다.

## 5. 층 반증 테스트 — 2편에서 층이 아니었다

- **Lambda** ⚙️ 작동 원리 `층: 같은 함수를 두 번째로 부르면 왜 더 빠른가`
  (첫 호출 / 이어지는 호출 / 한동안 뜸하면)
  마디 이름이 전부 **시간**이다. 셋은 겹겹이 쌓여 동시에 있는 것이 아니라 차례로
  지나가는 상태고, 셋째 줄이 이미 "다음엔 다시 첫 호출" 이라고 적어 순환이라고
  말하고 있었다. 규약이 "상태 전이는 층이 아니라 `@` 흐름" 이라고 못 박은 자리다.
  → **`@` 를 쓴 흐름으로 다시 세웠다.** 마지막 줄 `@ 다시 첫 호출로 :: 치워진 뒤에
  부르면 또 100~1000ms` 가 첫 마디를 가리키며 되돌아간다. 없어진 내용은 없고
  "다음엔 다시 첫 호출" 이 표지로 바뀌었을 뿐이다. 확인 질문 1번의 답도 그대로다.
- **Serverless** ⚙️ 작동 원리 `층: 무엇을 어디에 둬야 하나`
  (함수 코드 / 상태와 데이터 / 파일 업로드)
  둘째와 셋째를 맞바꿔도 그림이 안 틀린다. 둘 다 "밖에 둔다" 라 위아래에 뜻이 없고,
  `= ` 줄("함수는 매번 처음 켜진 것처럼 굴어야 안전하다")도 축이 아니라 총평이다.
  축이 없으니 층이 아니라 **나열**이었다.
  → 본문 한 문단으로 되돌렸다. 세 마디의 내용과 `= ` 줄을 문장으로 그대로 옮겼고
  버린 사실은 없다. 확인 질문 2번의 답(바로 위 문단의 "다음 호출에서 없다")도 그대로다.

### 살아남은 층

- **AWS**(Route 53 → CloudFront → EC2 → RDS): 바깥에서 안으로의 깊이 축.
  맞바꾸면 "요청이 DB 를 거쳐 CDN 으로 간다" 가 되어 틀린다.
- **Availability Zone**(리전 → 가용 영역 → 데이터센터 → 랙): 담김의 축. 맞바꾸면 틀린다.
- **Cloud**(SaaS → PaaS → IaaS → 직접 운영) · **IaaS_PaaS_SaaS**(SaaS → PaaS → IaaS →
  온프레미스): 맡기는 범위 축. 단조롭게 줄어든다.
- **Region**(규제 → 지연 → 서비스 → 비용): 판단 순서 축. `= ` 줄이
  "위에서 걸리면 아래는 볼 필요가 없다" 라고 축을 붙들고 있다. 규제를 지연 밑으로
  내리면 그 문장이 거짓이 된다.
- **S3**(버킷 → 키 → 객체): 담김의 축. **Subnet**(네트워크 → 가용 영역 → 서브넷 →
  자원): 같은 축. **Tenant**(DB 분리 → 스키마 분리 → 행 수준): 갈라짐의 세기 축.
  **VPC**(VPC → 퍼블릭 → 프라이빗 → 보안 그룹): 바깥에서 안으로의 노출 축.

## 6. 선행 용어 — 2곳에 `[[링크]]` 를 붙였다

- **Region** 그림 마디의 `DNS :: 접속 지역을 보고 리전을 고른다`
  → 🔗 관련 용어에 `[[DNS]] — 요청을 어느 리전으로 보낼지 정해주는 자리` 를 넣었다.
  마디 이름이 통째로 노트 밖 용어인데 이 노트는 DNS 가 무엇인지 한 번도 말하지 않는다.
- **EC2** 그림 마디의 `네트워크 :: 어느 VPC 와 서브넷에 놓을지 정한다`
  → `[[VPC]]` 는 이미 걸려 있고 서브넷만 없었다. `[[Subnet]] — 그 VPC 안에서
  인스턴스가 실제로 자리 잡는 구획` 을 넣었다.

나머지는 반 구절이 이미 붙어 있어 그대로 뒀다 — AWS·Azure 의 제품 이름(Route 53,
CloudFront, Blob, RDS 등)은 마디마다 하는 일이 한국어로 적혀 있고, Subnet 의 CIDR
(`/24` 는 앞의 24비트가 고정), S3 의 11 nines, Lambda·Serverless 의 콜드 스타트,
Tenant 의 시끄러운 이웃 문제, VPC 의 NAT 게이트웨이(한 방향 통로)가 그렇다.

## 손대지 않은 것

- H1 제목 · 파일 이름 · 폴더: 그대로. 새로 만들거나 지운 노트 없음.
- 배정 밖 파일, `tools/` · `js/` · `css/` · `docs/`: 읽기만 했다.
- git 명령은 하나도 돌리지 않았다.
