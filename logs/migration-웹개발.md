# 이행 기록 — 웹개발 (13편)

대상: Backend · CORS · CSR · Frontend · Full Stack · GraphQL ·
HTTP Status Code · Middleware · REST · SPA · SSR · Webhook · gRPC

검사 결과: **13편 실패 0건 · 경고 3건** (경고 셋은 아래 5절에 남긴 이유대로 일부러 남겼다)

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (13편)

13편 모두 화살표가 없었다. 전편에 달았고, **화살표 뒤의 섹션을 실제로 열어
답이 거기 있는지 하나씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고,
끝의 물음표는 본보기 두 편(DNS·HTTP)과 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| Backend | 해결하는 문제 · 작동 원리 · 그림 |
| CORS | 흔한 오해 · 작동 원리 · 해결하는 문제 |
| CSR | 그림 · 해결하는 문제 · 장단점 |
| Frontend | 그림 · 흔한 오해 · 해결하는 문제 |
| Full Stack | 그림 · 해결하는 문제 · 흔한 오해 |
| GraphQL | 해결하는 문제 · 흔한 오해 · 주의사항 |
| HTTP Status Code | 흔한 오해 · 비교 · 주의사항 |
| Middleware | 그림 · 흔한 오해 · 작동 원리 |
| REST | 비교 · 흔한 오해 · 해결하는 문제 |
| SPA | 그림 · 작동 원리 · 장단점 |
| SSR | 해결하는 문제 · 흔한 오해 · 작동 원리 |
| Webhook | 해결하는 문제 · 흔한 오해 · 작동 원리 |
| gRPC | 실제 사례 · 해결하는 문제 · 흔한 오해 |

### 답이 노트에 없어 질문을 바꾼 것 (4건)

- **HTTP Status Code** — "로그인을 했는데도 403 이 온다면 **무엇을 해야 하나**"
  노트는 "403 은 로그인해도 안 풀린다" 까지만 말하고 그다음에 무엇을 해야 하는지
  (권한을 받아야 한다)는 어디에도 없다. 없는 답을 짚지 않고
  **"401 은 로그인하면 풀리는데 403 은 왜 로그인해도 안 풀리나 → 흔한 오해"** 로 바꿨다.
  흔한 오해 둘째 줄이 그대로 답이다.
- **REST** — "`/createUser` 라는 주소가 REST 답지 않은 이유는"
  답은 🚫 흔한 오해 둘째 줄에 있는데, 둘째 질문(무상태와 로그인)의 답도 흔한 오해라
  셋이 두 자리로 몰렸다. **"처음 보는 API 인데도 목록 조회와 삭제쯤은 짐작할 수 있는
  이유는 → 해결하는 문제"** 로 바꿨다. 해결하는 문제 마지막 문단이 그대로 답이다.
- **CORS** — "쿠키를 함께 보내는 요청에서 허용 출처를 전체로 열 수 없는 이유는"
  답이 작동 원리와 흔한 오해 양쪽에 있어 앞의 두 질문과 자리가 겹쳤다.
  **"브라우저가 다른 출처의 응답을 그냥 읽게 두면 로그인한 사용자에게 무슨 일이 생기나
  → 해결하는 문제"** 로 바꿨다. 해결하는 문제 첫 문단(남의 사이트 스크립트가 내 쿠키로
  은행 API 를 부르고 응답까지 읽는다)이 답이다.
- **Frontend** — "버튼을 눌러도 화면이 안 바뀌는데 서버 로그에는 요청이 남았다. **어디를 보나**"
  "어디를 보나" 에 대한 답(프론트 코드를 보라)을 노트가 말해주지 않는다. 그림 도해는
  단계를 보여줄 뿐이다. 물음을 그림이 실제로 답할 수 있는 형태
  **"…서버 로그에 요청이 남았다면 어느 단계에서 멈춘 것인가 → 그림"** 으로 다듬었다.
  그림의 마지막 마디("받아온 값으로 그 부분만 다시 그린다")가 답이다.

나머지 9편은 원래 질문의 답이 노트 안에 실재해서 화살표만 달았다.

## 2. 흐름의 `<` 감사 — 고친 것 2건

**CSR · 🖼️ 그림** — `< 브라우저 :: 이후 화면 이동은 서버 없이 처리한다`
누가 누구에게 답을 주는지 물었더니 대답이 안 나온다. 아무것도 되돌아오지 않고,
그저 "그 뒤로는 이렇다" 는 후속 상태다. 되돌아가는 것도 아니라서 `@` 도 아니다
(첫 마디가 "서버가 빈 HTML 을 내려준다" 인데 그건 다시 일어나지 않는다).
**표지 없는 보통 마디로 바꿨다.** 이제 이 흐름에는 `<` 가 없는데, 첫 마디부터가
이미 서버의 응답이라 돌아오는 구간을 따로 그을 자리가 없는 것이 맞다.

**CORS · 🖼️ 그림** — `<` 를 마지막 줄에서 셋째 줄로 올렸다.
앱은 처음 나오는 `<` 앞에 "여기서부터 돌아오는 길" 을 새긴다. 마지막 줄에 있으면
"브라우저 :: 적힌 출처가 내 출처와 맞는지 본다" 가 가는 길로 보이는데, 그 줄은 이미
응답을 받은 뒤 브라우저 안에서 벌어지는 일이다. 실제로 되돌아오기 시작하는 자리는
`서버 :: 응답에 허용 출처를 적어 보낸다` 다. 거기로 옮겼다.

**Webhook · 🖼️ 그림** — `< 응답 :: 200 을 돌려준다. 못 받으면 다시 온다`
`<` 자체는 맞다(받는 쪽이 보낸 쪽에게 200 을 돌려준다). 다만 뒤에 붙은 재시도가
이번에 작동 원리로 옮겨가 `@` 흐름이 됐으므로(4절), 대표 그림에서는 덜어내
**`< 응답 :: 잘 받았다는 뜻으로 200 을 돌려준다`** 로 줄였다.

나머지 10편의 `<` 는 전부 "요청을 받은 쪽이 응답을 되돌려준다" 가 맞아 그대로 뒀다.

## 3. 대조 감사 — ✕ 칸 자기검사 (고친 것 없음)

13편의 `||` 대조를 전부 열어 왼쪽 칸을 한 줄씩 봤다. **장점이 든 왼쪽 칸은 없었다.**
`|=|` 로 바꾼 것도 없다.

판단이 갈릴 만한 자리 넷을 따로 봤고, 넷 다 유지로 결론냈다.

- **SSR** `브라우저가 조립 || 서버가 조립` 과 **CSR** `서버가 매번 그림 || CSR 로`
  두 노트가 서로를 ✕ 로 세우는 모양이 된다. 그래도 각 대조가 놓인 자리는 ⚠️ 해결하는
  문제 — "이게 없으면 무슨 일이 벌어지나" 를 보이는 자리이고, 두 대조 모두 왼쪽 칸이
  전부 단점이다. 균형은 각 노트의 🚫 흔한 오해 첫 줄이 잡는다
  ("CSR이 SSR보다 빠르다" / "SSR이 CSR보다 빠르다").
- **GraphQL** `주소별 API 로 || GraphQL 로` — REST 의 캐시 장점은 📊 비교 표가 맡고 있고
  대조 왼쪽에는 장점이 없다. 흔한 오해 셋째 줄("REST를 대체한다 — 골라 쓰는 것이다")이
  과잉 적용을 겨눈다.
- **Full Stack** `나눠 맡으면 || 한 사람이 맡으면` — 왼쪽 세 줄이 전부 절차 낭비다.
  "각 층의 깊은 곳까지 다 아는 것은 아니다" 는 흔한 오해 첫 줄이 맡는다.

## 4. 그림 자리 감사 (고친 것 없음) · 층 반증 테스트 (고친 것 3건)

### 그림 자리

13편의 🖼️ 도해를 "그림만 보고 정의 첫 문장을 복원할 수 있는가" 로 하나씩 재봤다.
**13편 모두 복원됐다.** 개념을 고르는 절차가 그림 자리에 올라앉은 노트는 없었다.
(예: gRPC 의 `= 부르는 쪽 코드에는 네트워크가 안 보인다. 그냥 함수 호출이다` 가
정의 "먼 서버의 함수를 내 함수처럼 부르게 해주는 방식" 을 그대로 되돌려준다.)

### 층 반증 테스트 — 이웃을 맞바꿔봤다

층 도해가 있는 노트는 여섯이다. **셋이 반증에 걸렸다.**

**Webhook · ⚙️ 작동 원리** — `층: 웹훅 한 번에 무엇이 들어 있나`
`= ` 줄이 **"이 넷이"** 로 시작한다. 주소와 페이로드를 맞바꿔도, 페이로드와 서명을
맞바꿔도 그림이 안 틀린다. 순서에 뜻이 없으니 층이 아니라 목록이었다.

그런데 이 노트의 작동 원리 본문에는 진짜 순환이 하나 들어 있었다 — **재시도**다.
"응답이 없거나 오류가 오면 보낸 쪽이 다시 보낸다. 간격을 늘려가며 재시도한다."
그 순환을 `@` 흐름으로 세웠다.

```
흐름: 보낸 알림이 도착하지 않으면 어떻게 되나
전송 :: 등록된 주소로 알림을 POST 한다
받는 쪽 :: 서명을 먼저 확인하고 내용을 처리한다
응답 :: 잘 받았으면 200 을 돌려준다
보낸 쪽 :: 200 이 없으면 실패로 본다
@ 다시 보내기 :: 간격을 늘려가며 될 때까지 되풀이한다
= 그래서 같은 알림이 두 번 도착할 수 있다
```

`@` 가 첫 마디("전송")를 가리키는 것이 뜻과 정확히 맞는다 — 재시도는 전송을 다시
하는 것이다. 네 요소(주소·페이로드·서명·응답)는 바로 아래 문단으로 내렸고
"이 넷이 갖춰져야 가짜 알림과 유실을 둘 다 막는다" 는 문장도 거기 살렸다.

**SPA · ⚙️ 작동 원리** — `층: SPA 를 이루는 것은 무엇인가`
제목부터 나열을 부른다. 라우터와 API 를 맞바꿔도 그림이 안 틀리고,
`= 서버가 화면을 만들지 않고 데이터만 내주는 구조로 갈린다` 는 순서를 전혀 설명하지
않는다(층의 `= ` 줄은 왜 그 순서인지를 말해야 한다). **본문 불릿으로 되돌렸다.**
작동 원리의 진짜 알맹이(주소는 바뀌는데 서버엔 안 간다, 라우터가 짝을 찾는다)는
원래 문단이 이미 잘 말하고 있어서 흐름 도해를 새로 만들지 않았다 —
만들면 🖼️ 그림 자리의 흐름과 겹친다.

**gRPC · ⚙️ 작동 원리** — `층: gRPC 는 어떤 모양의 통신을 지원하나`
서버 스트리밍과 클라이언트 스트리밍을 맞바꿔도 그림이 안 틀린다. 둘은 같은 층위다.
게다가 `= REST 는 맨 위 하나만 되고, 아래는 다른 기술을 붙여야 한다` 가 말하는
진짜 축은 "REST 로 되나 안 되나" 두 갈래뿐이라 네 칸을 세울 축이 아니었다.
**본문 불릿으로 되돌렸고**, `= ` 줄의 뜻은 불릿 앞 문장으로 살렸다.

**Frontend · ⚙️ 작동 원리** — `층: 프론트엔드는 무엇으로 이루어져 있나` (다시 세움)
HTML 과 CSS 를 맞바꿔도 `= 아래로 갈수록 편해지지만, 위 세 층을 모르면…` 이 그대로
성립한다. 게다가 "위 세 층" 이라는 말 자체가 셋을 한 덩어리로 묶어 프레임워크와
대비시키고 있어서, 실제 축은 넷이 아니라 둘이었다. 그리고 방향도 거꾸로였다 —
프레임워크는 HTML·CSS·JS 를 **감싸는** 쪽인데 맨 아래에 놓여 있었다.

**얹힘을 축으로 세 층으로 다시 세웠다.**

```
층: 프론트엔드 코드는 무엇 위에 얹혀 도나
프레임워크 :: React, Vue, Angular. 아래를 묶어 다루는 도구
HTML·CSS·JS :: 구조와 모양과 동작. 브라우저가 아는 말
브라우저 :: 이것들을 읽어 실제 화면으로 만든다
= 위를 걷어내도 아래는 돌지만, 아래를 모르면 고장 난 자리를 못 짚는다
```

이제 어느 이웃을 맞바꿔도 그림이 틀린다. HTML·CSS·JS 가 각각 무엇을 맡는지는
🖼️ 그림 자리의 흐름 도해와 📝 정리가 이미 말하고 있어서 잃은 것이 없다.

### 통과한 층 셋

- **Backend** `요청 하나가 백엔드 안에서 어디를 지나나` — 인증과 로직을 맞바꾸면
  그림이 틀린다. `= 위에서 걸러진 요청은 아래까지 내려가지 않는다` 가 순서를 설명한다.
- **Full Stack** `풀스택이 말하는 스택은 무엇으로…` — `= 아래로 갈수록 사용자에게서
  멀어지고 고장이 나면 영향은 커진다` 라는 축이 있고, 화면·서버·데이터·배포 어느
  이웃을 맞바꿔도 그 축이 깨진다.
- (Frontend 는 위에서 다시 세운 것)

## 5. 선행 용어 (고친 것 없음) · 일부러 남긴 경고 3건

### 선행 용어

도해 마디 이름이 노트 밖 용어를 전제하는 자리를 훑었다. 걸릴 만한 곳은
GraphQL 의 `스키마 검사` · `리졸버`, gRPC 의 `직렬화`, Webhook 의 `서명` 인데
**넷 다 마디의 `하는 일` 쪽이 이미 뜻을 풀고 있다**
(`리졸버 :: 필드마다 담당 함수가 값을 가져온다`). 반 구절 규칙을 지킨 상태라 그대로 뒀다.
`[[링크]]` 를 새로 건 곳은 없다.

### 남긴 경고 3건 — 전부 `REPEATING` 문자열 오탐

검사기가 `<` 줄에서 "다시" 를 찾아 경고하지만, 셋 다 순환이 아니라 부사다.
뜻을 보고 판단해 `<` 를 유지했다.

| 노트 | 줄 | 왜 `<` 인가 |
|---|---|---|
| CORS · 작동 원리 | `< 서버 :: 본 응답에도 허용 출처를 다시 적는다` | 서버가 본 요청에 응답한다. "다시" 는 "사전 응답에 이어 본 응답에도" 라는 뜻이지 되돌아감이 아니다 |
| Frontend · 그림 | `< 화면 :: 받아온 값으로 그 부분만 다시 그린다` | API 응답이 돌아와 화면이 갱신된다. "다시 그린다" 는 re-render 다 |
| gRPC · 그림 | `< 응답 :: 결과를 다시 바이너리로 담아 돌려준다` | 서버가 결과를 돌려준다. "다시" 는 "인자를 그랬듯 결과도" 라는 뜻이다 |

셋 모두 `@` 로 바꾸면 첫 마디로 되돌아가는 난간이 그려지는데, 그 첫 마디는
각각 "브라우저가 OPTIONS 를 보낸다" · "서버에서 HTML 을 받아온다" · "proto 를 적는다" 라
되돌아갈 자리가 아니다.

## 손대지 않은 것

- H1 제목 · 파일 이름 · 폴더 — 전부 그대로다.
- 섹션 구성 · 접이식 칸 수 — 어느 편도 늘리거나 줄이지 않았다.
