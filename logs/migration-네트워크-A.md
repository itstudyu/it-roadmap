Intranet · Load Balancer · Localhost · MCP · Multi-tenancy · NAT · Nginx

검사 결과: **15편 실패 0건 · 경고 1건**(Domain, 아래에 남긴 이유 적음)

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (13편)

DNS·HTTP 는 본보기라 이미 달려 있었다. 나머지 13편에 화살표를 달았고,
**답이 실제로 그 섹션에 있는지 하나씩 열어 확인했다.** 질문 셋이 서로 다른 섹션을
겨누게 맞췄고, 끝의 물음표는 본보기 두 편과 같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| CDN | 흔한 오해 · 주의사항 · 그림 |
| Domain | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| Firewall | 흔한 오해 · 주의사항 · 작동 원리 |
| Gateway | 해결하는 문제 · 비교 · 흔한 오해 |
| HTTPS | 흔한 오해 · 주의사항 · 해결하는 문제 |
| IP Address | 작동 원리 · 그림 · 흔한 오해 |
| Intranet | 실제 사례 · 해결하는 문제 · 흔한 오해 |
| Load Balancer | 흔한 오해 · 주의사항 · 작동 원리 |
| Localhost | 작동 원리 · 주의사항 · 실제 사례 |
| MCP | 그림 · 해결하는 문제 · 작동 원리 |
| Multi-tenancy | 해결하는 문제 · 주의사항 · 작동 원리 |
| NAT | 작동 원리 · 흔한 오해 · 주의사항 |
| Nginx | 실제 사례 · 흔한 오해 · 해결하는 문제 |

### 답을 못 찾아 질문을 바꾼 것 (3건)

- **CDN** — "CDN을 붙였는데 원본 서버 부하가 그대로라면 어디를 봐야 하나"
  답이 노트에 없었다. 흔한 오해의 "사용자마다 다른 내용은 캐시할 게 없다" 가 가장
  가깝지만 그건 첫 질문이 이미 겨눈 자리다. 억지로 같은 데를 두 번 짚지 않고
  **"같은 이미지를 두 번째로 요청한 사람은 왜 미국까지 안 가도 되나 → 그림"** 으로 바꿨다.
  그림의 `= 첫 사람만 미국까지 가고, 그다음 사람들은 서울에서 끝난다` 가 그대로 답이다.
- **IP Address** — "노트북 IP가 어제와 오늘 다르다면 무엇 때문인가"
  답(DHCP)은 작동 원리에 있는데, 첫 질문의 답도 작동 원리에 있어 셋이 두 자리로 몰렸다.
  **"노트북을 집에서 회사로 들고 가면 IP 주소는 어떻게 되나 → 흔한 오해"** 로 바꿨다.
  흔한 오해 첫 줄 "기기가 아니라 자리에 붙는다" 가 답이다.
- **Load Balancer** — "포트만 확인하는 헬스체크가 왜 위험한가"
  답이 주의사항에 있는데 두 번째 질문도 주의사항이었다.
  **"서버 한 대가 죽었는데도 사용자가 오류를 안 보는 이유는 → 작동 원리"** 로 바꿨다.
  작동 원리의 "답이 없으면 목록에서 뺀다. 그래서 서버가 죽어도 사용자는 오류를 보지 않는다" 가 답이다.

## 2. 흐름의 `<` 감사 — 3편에서 뗐다

"누가 누구에게 답을 주는가" 를 물었을 때 대답이 안 나오는 자리다.
`<` 앞에는 앱이 "여기서부터 돌아오는 길" 을 새기므로 그대로 두면 그림이 거짓말을 한다.

- **Firewall** `< 전달 :: 통과한 것만 목적지로 간다`
  → 패킷이 목적지로 **계속 나아가는** 마지막 걸음이지 돌아오는 응답이 아니다. 표지를 뗐다.
- **HTTPS** `< 서버 :: 같은 열쇠를 나눠 갖는다`
  → 브라우저가 만든 열쇠를 서버가 받는 자리다. 방향이 앞으로다. 표지를 뗐다.
- **IP Address** `< 받는 쪽 :: 자기 주소면 위층으로 올린다`
  → 목적지에 닿은 것이지 보낸 쪽에 답이 간 것이 아니다. 표지를 뗐다.

### 두고 온 `<` (뜻을 보고 남긴 것)

CDN(원본 → 거점) · DNS(권한 서버 → 브라우저) · Gateway(서비스 → 게이트웨이 → 클라이언트) ·
HTTP(서버 → 브라우저) · Intranet(내부 서버 → PC) · Load Balancer(서버 → 사용자) ·
MCP(MCP 서버 → AI) · Multi-tenancy(DB → 화면) · NAT(인터넷 서버 → 공유기 → PC) ·
Nginx(앱 서버 → Nginx → 브라우저) — 전부 실제로 응답이 되돌아온다.

**Localhost 는 남겼다.** 겉모습은 Firewall·IP Address 와 같은 "도착" 마디지만,
이 단어는 정의부터가 "요청이 컴퓨터 안에서 **되돌아온다**" 이고 그림의 결론도
"밖으로 한 번도 나가지 않는다" 다. 되돌아오는 길이 곧 이 개념이라 표지를 뜻대로 남겼다.

## 3. 대조 감사 — 바꾼 것 없음, `|=|` 하나 새로 씀

13편의 `||` 대조를 왼쪽 칸부터 읽었다. 전부 "있고 없고" 꼴이고 왼쪽에 장점이 한 줄도 없다
(CDN 없이 / DNS 없이 / HTTP 없이 / 방화벽 없이 / 게이트웨이 없이 / 공개망에 두면 /
분산기 없이 / localhost 없이 / MCP 없이 / 고객마다 따로 / NAT 없이 / 앞단 없이 / IP 주소만).
그대로 뒀다.

`|=|` 는 NAT 에서 새로 생긴 대조 한 곳에만 썼다(아래 5번). SNAT 와 DNAT 는 우열이 없다.

## 4. 그림 자리 감사 — 바꾼 것 없음

15편 모두 그림 도해만 보고 정의 첫 문장을 복원할 수 있는지 봤다. 전부 통과했고
"개념을 고르는 절차" 가 그림 자리에 올라온 편은 없었다.

**Domain 만 판단이 갈렸다.** 그림 자리의 층은 도메인 이름의 짜임(루트 / 최상위 /
2단계 / 서브도메인)이고, 정의 첫 문장("숫자 IP 주소에 붙인 사람이 읽는 이름")보다는
"점으로 나뉜 이름 계층" 쪽을 복원한다. 그래도 절차가 아니라 **개념의 형태**이고,
해결하는 문제의 대조를 그림으로 끌어올리면 그 자리가 비어버린다(해결하는 문제는
대조 도해 하나가 규약이다). 형태를 담은 도해가 그림 자리에 있다는 점에서 그대로 뒀다.

## 5. 층 반증 테스트 — 2편에서 층이 아니었다

- **NAT** ⚙️ 작동 원리 `층: NAT 는 무엇을 바꾸나` (SNAT / DNAT / NAT 테이블)
  SNAT 와 DNAT 는 **위아래가 아니라 좌우**다. 둘을 맞바꿔도 그림이 안 틀리고,
  셋째 줄(NAT 테이블)은 아예 다른 종류의 것이라 축이 없었다.
  → **`|=|` 대조로 다시 세웠다.** "SNAT 와 DNAT 는 어느 쪽을 바꾸나" — 바꾸는 자리 /
  방향 / 쓰이는 곳. 사실은 전부 바로 아래 두 문단에 있던 것이고, 층이 갖고 있던
  "표에 적힌 연결만 되돌아온다" 는 같은 섹션 마지막 문단과 흔한 오해에 이미 있어
  없어진 내용이 없다. 확인 질문 1번의 답도 그 문단이 그대로 받는다.
- **Nginx** ⚙️ 작동 원리 `층: Nginx 는 어떤 일을 대신 맡아주나`
  (정적 파일 / TLS 종료 / 로드 밸런싱 / 접근 제어)
  `= ` 줄이 **"하나같이"** 로 시작했고, 이웃한 둘을 어떻게 맞바꿔도 그림이 안 틀린다.
  순서에 뜻이 없으니 층이 아니라 **나열**이었다. → 본문 불릿 넷으로 되돌렸다.

### 살아남은 층

- **CDN**(브라우저 캐시 → 거점 → 상위 → 원본): 거리 축. 맞바꾸면 틀린다.
- **DNS**(브라우저 → OS → 로컬 DNS → 권한 서버): 같은 축.
- **Domain**(루트 → 최상위 → 2단계 → 서브도메인): 이름의 소속 축.
- **HTTPS**(루트 CA → 중간 CA → 서버 인증서): 보증의 사슬. 맞바꾸면 사슬이 끊긴다.
- **Intranet**(인터넷 → 방화벽 → VPN → 내부망): 바깥에서 안으로의 깊이 축.
  VPN 을 방화벽 위로 올리면 "통로가 벽 밖에 있다" 가 되어 틀린다.
- **MCP**(도구 호출 → JSON-RPC → 전송): 프로토콜 층. 맞바꾸면 틀린다.
- **Multi-tenancy**(행 → 스키마 → DB): 갈라짐의 세기 축. 단조롭게 짙어진다.

## 6. 선행 용어 — 4곳을 풀었다

- **Gateway** 그림 마디의 `401` `429`
  → "없으면 돌려보낸다" · "너무 잦으면 막는다" 로 바꿨다. 상태 코드는 이 노트가
  설명하지 않는 말이고, 그림에만 있던 사실이라 그림을 못 읽는 사람은 영영 모르는 자리였다.
  작동 원리 본문이 이미 같은 말을 한국어로 하고 있다.
- **NAT** 실제 사례의 `STUN` `TURN`
  → "공인 주소를 알려주거나 대신 중계해주는 서버(STUN, TURN)" 로 반 구절 풀이를 붙였다.
- **NAT** 비교 표의 `P2P 통신` → `기기끼리 직접 연결`.
- **NAT** 실제 사례의 `ISP` → `인터넷 회선 업체(ISP)`.
- **Nginx** 실제 사례의 `SPA` → "화면 전환을 브라우저가 맡는 앱(SPA)".

## 남긴 경고 1건 (왜 남겼나)

**Domain.md** — `층 이름이 순서를 가리킨다 — 2단계`

검사기의 `^\d+\s*단계` 가 걸었지만 **오탐이다.** 여기서 "2단계" 는 시간의 2단계가 아니라
`google.com` 의 `google` 자리를 부르는 이름(second-level domain)이다. 같은 도해의
이웃이 루트 · 최상위 · 서브도메인이라 읽는 사람이 시간으로 오해할 자리도 아니다.
층 자체는 반증 테스트를 통과한다 — 최상위와 2단계를 맞바꾸면 `com.google` 이 되어 틀린다.
표준 용어를 검사기 문자열에 맞춰 바꾸는 것이 손해라 보고 그대로 뒀다.
