# 이행 기록 — 프로그래밍 (15편)

대상: Array · Build · Class · Compile vs Interpret · Compile · Component ·
Dictionary · Framework vs Library · Function · Loop · Object · Package ·
Recursion · Regex · Variable

검사 결과: **15편 실패 0건 · 경고 0건**(`--strict` 로도 0건)

이행 전 상태는 15편 전부 "확인 질문 3개에 → 답이 있는 자리가 없다" 경고,
거기에 Framework vs Library 와 Loop 의 `<` 응답 줄 경고 둘이 더 있었다(총 17건).

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (15편 전부)

화살표를 달기 전에 **그 섹션을 열어 답이 실제로 있는지 하나씩 확인했다.**
질문 셋이 서로 다른 섹션을 겨누게 맞췄고, 끝의 물음표는 본보기 두 편(DNS·HTTP)과
같게 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| Array | 그림 · 흔한 오해 · 비교 |
| Build | 흔한 오해 · 주의사항 · 작동 원리 |
| Class | 그림 · 작동 원리 · 흔한 오해 |
| Compile vs Interpret | 비교 · 작동 원리 · 흔한 오해 |
| Compile | 해결하는 문제 · 흔한 오해 · 그림 |
| Component | 해결하는 문제 · 그림 · 작동 원리 |
| Dictionary | 그림 · 흔한 오해 · 작동 원리 |
| Framework vs Library | 작동 원리 · 해결하는 문제 · 실제 사례 |
| Function | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| Loop | 그림 · 흔한 오해 · 주의사항 |
| Object | 작동 원리 · 흔한 오해 · 주의사항 |
| Package | 해결하는 문제 · 작동 원리 · 그림 |
| Recursion | 그림 · 해결하는 문제 · 흔한 오해 |
| Regex | 흔한 오해 · 작동 원리 · 주의사항 |
| Variable | 흔한 오해 · 작동 원리 · 해결하는 문제 |

### 답이 노트에 없어 질문을 바꾼 것 (5건)

이번 이행의 진짜 수확이다. 전부 **답이 이미 다른 질문이 겨눈 자리에만 있어서**
셋이 두 자리로 몰리던 경우다. 억지로 같은 데를 두 번 짚지 않고 질문을 바꿨다.

- **Compile** — "윈도우에서 만든 실행 파일이 맥에서 안 도는 이유는"
  답이 ⚠️ 해결하는 문제 문단에만 있는데 첫 질문이 이미 그 자리를 겨눴다.
  **"라이브러리를 못 찾겠다는 오류는 네 단계 중 어디에서 나나 → 그림"** 으로 바꿨다.
  그림의 `링킹 :: 조각들과 라이브러리를 하나로 붙인다` 와
  `= 오류는 대개 둘째와 넷째에서 난다. 문법이 틀렸거나 붙일 게 없거나다` 가 그대로 답이다.

- **Framework vs Library** — "\"우리한테 전화하지 마, 우리가 전화할게\"는 어느 쪽을 가리키나"
  답이 ⚙️ 작동 원리에만 있는데 첫 질문이 이미 그 자리다.
  **"프레임워크를 쓰기로 했으면 라이브러리는 안 쓰는 것인가 → 실제 사례"** 로 바꿨다.
  실제 사례 첫 줄 "함께 쓰기 — 프레임워크로 구조를 잡고 그 안에서 라이브러리를 불러 쓴다" 가 답이고,
  둘을 배타로 아는 초보자의 오해를 정면으로 겨눈다.

- **Object** — "좌표가 똑같은 두 점 객체를 비교했는데 다르다고 나오는 이유는"
  답이 🚫 흔한 오해 셋째 줄에만 있는데 둘째 질문이 이미 흔한 오해를 겨눴다.
  **"두 객체가 서로를 가리키게 두면 어떤 문제가 생기나 → 주의사항"** 으로 바꿨다.
  주의사항의 "두 객체가 서로를 붙잡고 있으면 정리 시점이 늦어지거나 순회 코드가 무한히 돈다" 가 답이다.

- **Regex** — "짧은 입력에서 빠르던 패턴이 긴 입력에서 느려지는 이유는"
  답(백트래킹)이 ⚙️ 작동 원리에만 있는데 둘째 질문이 이미 그 자리다.
  🚨 주의사항은 현상만 적고 이유는 안 적는다.
  **"글에서 마침표만 찾으려고 `.` 를 썼더니 모든 글자가 잡혔다. 왜 그런가 → 주의사항"** 으로 바꿨다.
  주의사항의 "점은 아무 글자 하나를 뜻하므로 진짜 점을 찾으려면 `\.` 로 적는다" 가 답이다.

- **Function** — "리스트를 넘긴 함수가 원본까지 바꿔놓는 이유는"
  자리는 🚫 흔한 오해가 맞는데, 거기에는 **현상**만 있고 "이유"(참조를 넘긴다)는 이 노트 어디에도 없다.
  참조 설명은 [[Variable]]·[[Object]] 쪽 일이라 이 노트에 끌어오지 않았다.
  대신 **질문을 노트가 실제로 답하는 형태로 바꿨다** —
  **"리스트를 넘긴 함수는 원본까지 바꿔놓는다. 숫자를 넘길 때와 무엇이 다른가 → 흔한 오해"**.
  "숫자나 문자열과 달리 리스트는 함수 안에서 고치면 밖의 것도 같이 바뀐다" 가 그대로 답이 된다.

### 자리를 옮겨 겹침을 푼 것 (2건)

- **Dictionary** — "리스트를 키로 쓰면 언어가 막는 이유를 저장 방식으로 설명하면"
  작동 원리를 겨누면 셋째 질문(대괄호)과 겹친다. 흔한 오해에도 같은 답이
  ("넣어둔 자리를 다시 찾지 못해서 대개 언어가 막는다") 있어서 그쪽으로 돌렸고,
  질문 끝의 "저장 방식으로 설명하면" 은 뺐다. 흔한 오해 쪽 문장이 그 요구를 이미 담는다.
- **Package** — 4번(그림 자리 감사)에서 도해 둘을 맞바꾼 결과 질문 둘의 자리도 따라 바뀌었다.
  import 질문 → 그림에서 **작동 원리**로, `mypackage.utils.hello` 질문 → 작동 원리에서 **그림**으로.

## 2. 흐름의 `<` 감사 — 고친 곳 4, 지킨 곳 5

`<` 앞에는 앱이 "여기서부터 돌아오는 길" 을 새긴다. 그래서 줄마다
**누가 누구에게 답을 주는가**를 물었다.

### `<` 를 뗀 곳 — 아무도 답을 주지 않는다 (3편)

| 노트 | 줄 | 왜 아닌가 |
|---|---|---|
| Build | `< 산출물 :: 배포할 수 있는 덩어리가 남는다` | 파이프라인 끝에 남는 결과물이다. 누구에게도 되돌아가지 않는다 |
| Compile | `< 실행 파일 :: 이제 CPU 가 바로 읽을 수 있다` | 같다. 링킹의 산출물이지 응답이 아니다 |
| Variable | `< 사라짐 :: 쓰이는 범위를 벗어나면 그 칸이 회수된다` | 변수 생애의 마지막이다. 소멸은 응답이 아니다 |

셋 다 표기 없는 보통 마디로 돌렸다. 마디 수는 그대로라 4~7 범위를 벗어나지 않는다.

### `<` 를 `@` 로 바꾼 곳 (1편) — 아래 3절과 함께

Loop 의 `< 다음 줄 :: 반복문 아래로 이어진다` 는 "조건을 만족해 빠져나온다" 쪽이라
`<` 가 아니었고, 같은 도해에 **진짜 순환이 표기 없이 묻혀 있었다**. 4절에 적었다.

### `<` 를 지킨 곳 (5편) — 실제로 응답이 돌아온다

- **Array** `< 읽기` — 요청한 자리로 값이 돌아온다.
- **Function** `< 호출한 곳 :: 그 자리에 결과값이 놓인다` — 함수가 호출자에게 준다. 교과서적인 `<`.
- **Object** `< 변수 car :: 그 자리를 가리키게 된다` — `Car("Tesla")` 의 결과가 대입되는 쪽으로 돌아온다.
- **Package** `< 내 코드 :: requests.get 처럼 점을 찍어 꺼내 쓴다` — import 를 건 쪽이 이름 공간을 돌려받는다.
- **Recursion** `< 호출 2` · `< 호출 1` — 호출 3이 2에게, 2가 1에게 값을 준다. 재귀의 반환 그 자체다.
- **Regex** `< 결과 :: 통과로 돌려준다` — 엔진이 부른 쪽에 판정을 준다.

### 검사기 경고를 따르지 않은 자리는 없다

검사기가 잡은 두 건은 둘 다 실제로 고칠 자리였다.

- Framework vs Library `< 내 코드 :: 자기 몫만 하고 다시 넘긴다` — "다시" 때문에 걸린 오탐이었고,
  뜻으로는 제어를 프레임워크에 되돌려주는 **올바른 `<`** 였다. 다만 도해 자체를 대조로
  바꾸면서(4절) 이 줄은 사라졌다.
- Loop `< 다음 줄 :: 반복문 아래로 이어진다` — "반복" 때문에 걸렸는데, 경고가 짚은 이유와는
  다른 이유로 실제로 틀린 줄이었다.

## 3. 대조 감사 — ✕ 칸 자기검사

`||` 대조 15개를 전부 훑어 **왼쪽 칸에 장점이 한 줄이라도 있는지** 봤다.
**고칠 것이 없었다.** 15개 모두 "있고 없고" 대조이고 왼쪽이 실제로 나쁜 상태다
(변수 100개로 두기 · 손으로 컴파일 · 값과 기능이 흩어짐 · 붙여넣기 · 한 파일에 다 넣기 …).

한 자리만 따로 짚어둔다. **Recursion** 의
`반복문으로 || 재귀로` 는 📊 비교 표가 "반복이 더 빠르고 메모리도 덜 쓴다" 고 말하는 것과
반대로 보일 수 있다. 그러나 이 대조의 제목이 `폴더 안에 폴더가 몇 겹인지 모를 때` 라는
상황을 못박고 있고, 그 상황에서 왼쪽은 실제로 나쁘다. 왼쪽 칸에 장점은 한 줄도 없다.
그대로 뒀다.

새로 `|=|` 를 쓴 자리는 전부 아래 4·5절에서 도해 모양을 바꾸며 생겼다(3곳).

## 4. 그림 자리 감사 — 4편을 고쳤다

판정법은 **그림만 보고 정의 첫 문장을 복원할 수 있는가** 하나였다.

### Compile vs Interpret — 흐름이 없는 순서를 만들고 있었다

```
소스 코드 → 컴파일러 → 실행 파일 → 인터프리터 → < 실행
```

컴파일 경로와 인터프리트 경로는 **서로 다른 갈래**인데 한 줄로 이어 붙였다.
앱이 1~5 번호를 붙이면 "인터프리터는 실행 파일 다음에 온다" 는 없는 순서가 생긴다.
`< 실행` 도 두 갈래가 합류하는 자리지 응답이 아니었다.

제목에 vs 가 들어간 노트다. **대조 + `|=|`** 로 바꿨다.

```도해
대조: 번역을 미리 해두는 것과 돌리면서 하는 것은 무엇이 다른가
컴파일 |=| 인터프리트
번역 시점 :: 실행 전에 한 번 || 한 줄씩 그때그때
남는 것 :: 실행 파일 || 없다
오류가 나는 때 :: 빌드할 때 || 그 줄에 닿을 때
다른 OS 로 :: 다시 빌드한다 || 그대로 쓴다
= 미리 옮기면 실행이 빠르고, 돌리면서 옮기면 고쳐서 바로 본다
```

네 줄 전부 📊 비교 표에 이미 있는 사실이다(그림에 새 정보를 넣지 않았다).
`|=|` 를 쓴 이유는 정의가 "두 방식" 이라고만 하고 우열을 매기지 않기 때문이다.
`||` 로 뒀다면 그림이 2초 만에 "인터프리트는 나쁜 것" 이라는 오해를 심는다.

`=` 줄은 처음에 ⚠️ 해결하는 문제 도해의 결론과 거의 같게 썼다가
(둘 다 "번역을 언제 하느냐만 다르다"), 📝 정리에 있는 사실로 바꿔 겹침을 풀었다.

### Framework vs Library — 같은 병이다

```
내 코드 → 라이브러리 → 내 코드 → 프레임워크 → 프레임워크 → < 내 코드
```

두 시나리오를 한 줄로 이어 붙였다. `반대로 여기서는` 이라는 말로 갈래 전환을
알리기는 하는데, 번호가 이어 붙는 이상 그림의 **형태**는 여전히 거짓말을 한다.

```도해
대조: 내 코드와 그쪽 코드 중 누가 누구를 부르나
Library |=| Framework
먼저 시작 :: 내 코드가 || 그쪽이
부르는 쪽 :: 내가 부른다 || 내가 불린다
구조 :: 내가 정한다 || 이미 정해져 있다
갈아끼우기 :: 쉽다 || 대부분 다시 짠다
= 부르는 방향이 어디냐가 둘을 가르는 유일한 기준이다
```

여기서 `|=|` 는 특히 중요하다. 이 노트의 🚫 흔한 오해 첫 줄이
"프레임워크가 라이브러리보다 좋은 것이다 — 등급이 아니라 방향의 차이다" 인데,
그림을 `||` 로 두면 접히지 않는 그림이 접힌 오해 정정문과 정면으로 싸운다.

`=` 줄은 원래 것을 그대로 살렸다.

### Package — 승격이었다. 도해 둘을 맞바꿨다

정의 첫 문장이 "Module은 코드 파일 하나고, **Package는 그 파일들을 묶은 폴더**다" 인데
그림 자리의 import 흐름은 **패키지를 한 번도 보여주지 않는다.** 복원 실패다.
반대로 ⚙️ 작동 원리에 있던 층 도해가 정의를 그대로 그린다.

- 🖼️ 그림으로 보기 ← `층: 파이썬에서 부르는 이름은 어떻게 겹겹이 붙나`
  (myproject → mypackage → utils.py → hello. 폴더 안에 폴더, 그 안에 파일)
- ⚙️ 작동 원리 ← `흐름: import 한 줄을 쓰면 무슨 일이 벌어지나` (절차다. 여기가 제자리다)

층 도해는 반증 테스트도 통과한다 — 이웃 둘을 맞바꾸면 포함 관계가 뒤집혀 그림이 틀린다.

### Loop · Class · Component — 그림 자리는 그대로, 표기만 고쳤다

셋 다 판정법은 통과했다. 5절에 적었다.

### 손대지 않은 그림 (11편)

Array · Build · Class · Component · Compile · Dictionary · Function · Loop ·
Object · Recursion · Regex · Variable 의 그림은 전부 정의 첫 문장을 복원한다.
절차를 그림 자리에 올려둔 노트는 Package 하나뿐이었다.

## 5. 층 반증 테스트 — 2개가 층이 아니었다

`층` 도해 5개를 이웃끼리 맞바꿔봤다.

### 층이 맞은 것 (3개, 그대로 뒀다)

| 노트 | 축 | 맞바꾸면 |
|---|---|---|
| Class `상속을 쓰면 코드가 어떻게 겹치나` | 공통 → 구체 | Dog 가 Animal 위에 오면 물려받는 방향이 뒤집힌다 |
| Variable `같은 이름이 여러 곳에 있으면 어느 것을 쓰나` | 찾는 순서(안 → 밖) | `= 안쪽부터 찾아 나가므로` 가 축을 못박는다. 뒤집으면 틀린다 |
| Package `부르는 이름은 어떻게 겹겹이 붙나` | 바깥 폴더 → 안쪽 이름 | 포함 관계가 뒤집힌다 |

Function 의 `함수 안에서 만든 값은 어디까지 살아 있나` 도 지역 → 반환값 → 전역이
좁은 데서 넓은 데로 가는 축이라 통과시켰다.

### 층이 아니었던 것 (2개)

**Loop `층: for 와 while 은 무엇이 다른가`** — for / while / break / continue 넷.
for 와 while 을 맞바꿔도, break 와 continue 를 맞바꿔도 **그림이 안 틀린다.**
순서에 뜻이 없으니 층이 아니다. 게다가 제목은 둘을 묻는데 마디는 넷이라 제목과도 안 맞았다.

정체는 **두 갈래 비교**였다. 대조로 다시 세웠고, for 와 while 에 우열이 없으니 `|=|` 다.

```도해
대조: for 와 while 은 무엇이 다른가
for |=| while
돌 대상 :: 목록이나 범위 || 정해두지 않는다
멈추는 때 :: 다 돌면 끝난다 || 조건이 거짓일 때
종료 챙기기 :: 안 해도 된다 || 직접 바꿔야 한다
= for 는 몇 번 도는지 알고 시작하고, while 은 돌아봐야 안다
```

밀려난 break / continue 는 **본문 불릿으로 되돌렸다.** 도해에 있던 말을 그대로 옮겼다.
`break` 는 본문에 이미 설명이 있었고 `continue` 는 없어서 한 줄이 늘었다.

**Regex `층: 패턴은 무엇으로 이루어져 있나`** — 문자 클래스 / 수량자 / 경계 / 그룹.
어느 이웃을 맞바꿔도 그림이 안 틀린다. 넷은 위아래가 아니라 나란한 갈래다.
`= 어떤 글자가 몇 번 어디에 나오는지를 조합해` 라는 결론 자체가 "각각" 을 열거하고 있었다.

진짜 축도 없고 두 갈래도 아니라 **본문 불릿으로 되돌렸다.**
"문법은 네 갈래로 나뉜다. 넷 사이에 위아래는 없고, 하나씩 골라 이어 붙이면 그것이 패턴이다" 라고
앞에 한 줄을 두어, 왜 이걸 그림으로 안 그렸는지가 본문에서 읽히게 했다.

### 상태 전이·순환을 층으로 그린 노트는 없었다

## 6. `@` 를 새로 쓴 곳 (3편)

셋 다 원래 `<` 였고, 셋 다 **아무것도 되돌아오지 않는 자리**였다.

- **Loop** `< 다음 줄 :: 반복문 아래로 이어진다` → 뗐다. 그리고 같은 도해 안에
  `다시 위로 :: 조건을 또 확인한다` 라는 **표기 없는 순환**이 묻혀 있었다.
  둘을 합쳐 마지막 줄을 `@ 다시 조건으로 :: 나오지 않았으면 한 바퀴 더` 로 만들었다.
  반복문은 순환의 원형이다. 직선으로 펴 그리면 그게 순환이라는 사실이 사라진다.
  마디는 6개에서 5개로 줄었다.

- **Class** `< 사용 :: user.greet() 은 자기 값으로 동작한다` 는 응답이 아니었고,
  바로 위의 `객체 :: 다시 부르면 값이 다른 것이 또 생긴다` 가 순환이었다.
  `사용` 을 보통 마디로 내리고 마지막을 `@ 다시 호출로 :: 또 부르면 값이 다른 것이 또 생긴다` 로 했다.
  틀 하나로 몇 개든 찍어낸다는 것이 클래스의 요점이고, 그게 곧 순환이다.

- **Component** `< 수정 :: 정의 한 곳을 고치면 쓴 곳이 다 바뀐다` 는 응답이 아니라
  **첫 마디(정의)로 되돌아가는 길**이었다. `@ 다시 정의로 :: 한 곳을 고치면 쓴 곳이 다 바뀐다`.
  화면에서 난간이 첫 마디를 가리키며 되돌아오는 것이 "고칠 곳이 한 곳" 이라는 말과 정확히 겹친다.

세 곳 모두 `@` 를 마디 수에 넣고 세어 4~7 범위를 지켰다.

## 7. 선행 용어

**새로 푼 것도, 새로 건 링크도 없다.** 훑어보니 이 15편은 도해 마디마다
반 구절 설명이 이미 붙어 있었다.

- Class `생성자 :: 넘겨받은 값을 자기 속성에 채운다` — 하는 일이 곧 뜻이다
- Dictionary `해시 계산 :: 그 글자를 숫자로 바꾼다` — 같다. [[Hash]] 는 🔗 관련 용어에 있다
- Package `mypackage :: __init__.py 를 둔 폴더. 패키지가 된다` — 그림 자리로 올라왔지만
  마디 안에서 뜻이 닫힌다
- Framework vs Library 본문의 "제어의 역전" — 바로 다음 문장이 풀어 쓴다
- Regex 본문의 "백트래킹" — "이렇게 되돌아가는 것을" 이라고 앞에서 풀고 이름을 뒤에 붙인다

Array 의 📝 정리에 "자료구조" 가 링크 없이 나오는데(Dictionary·Recursion 은 [[자료구조]] 를
관련 용어에 뒀다), 문맥에서 뜻이 닫히고 관련 용어 4개가 이미 제 몫을 해서 건드리지 않았다.

## 남긴 판단

- **Recursion 의 `||` 대조를 `|=|` 로 바꾸지 않았다.** 3절에 이유를 적었다.
  제목이 상황을 못박고 있고 왼쪽 칸에 장점이 없다. "있고 없고" 는 `||` 다.
- **Compile vs Interpret 과 Framework vs Library 는 그림·해결하는 문제가 둘 다 대조가 됐다.**
  두 대조가 서로 다른 물음에 답한다(형태가 무엇인가 / 없으면 무슨 일이 벌어지나)
  — 규약이 그림 자리에 세 모양을 다 허용하므로 그대로 뒀다.
- **Package 의 ⚙️ 작동 원리 첫 문단**("부를 때 쓰는 이름은 폴더 이름과 파일 이름을 이어 붙인 것이다")은
  이제 그림 자리로 올라간 층 도해의 결론을 되짚는 문장이 됐다. 지우지 않았다 —
  그림을 접지 않으니 바로 위에서 본 것을 이어받는 자리가 되고, 뒤따르는 import 흐름의 전제이기도 하다.
- **H1 제목 · 파일명 · 폴더는 하나도 건드리지 않았다.** 파일을 새로 만들거나 지우지도 않았다.
