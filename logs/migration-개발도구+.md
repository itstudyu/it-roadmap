# 이행 기록 — 개발도구+ (13편)

대상: CLI · Container · Docker · Environment Variable · Git · IDE · Package Manager ·
SDK · Terminal · CRM · Linux · OS · Windows

검사 결과: **13편 실패 0건 · 경고 0건** (`python3 tools/check_template.py` 13편 일괄)

H1 제목 · 파일 이름 · 폴더는 하나도 건드리지 않았다. 파일을 새로 만들거나 지우지 않았다.
배정 밖의 파일은 열지 않았다(tools/ · docs/ 는 읽기만).

## 1. 확인 질문에 "→ 답이 있는 자리" 달기 (13편 전부)

13편 모두 화살표가 없었다. 전부 달았다. **화살표를 달기 전에 그 섹션을 열어 답이 실제로
거기 있는지 하나씩 확인했다.** 질문 셋이 서로 다른 섹션을 겨누게 맞췄고, 끝의 물음표는
본보기(DNS·HTTP)와 이미 이행된 492줄의 관례대로 뗐다.

| 노트 | 겨눈 자리 셋 |
|---|---|
| CLI | 해결하는 문제 · 흔한 오해 · 작동 원리 |
| Container | 그림 · 주의사항 · 흔한 오해 |
| Docker | 해결하는 문제 · 주의사항 · 작동 원리 |
| Environment Variable | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| Git | 흔한 오해 · 작동 원리 · 주의사항 |
| IDE | 그림 · 작동 원리 · 흔한 오해 |
| Package Manager | 실제 사례 · 해결하는 문제 · 흔한 오해 |
| SDK | 그림 · 해결하는 문제 · 흔한 오해 |
| Terminal | 그림 · 비교 · 해결하는 문제 |
| CRM | 해결하는 문제 · 작동 원리 · 흔한 오해 |
| Linux | 그림 · 작동 원리 · 해결하는 문제 |
| OS | 작동 원리 · 그림 · 실제 사례 |
| Windows | 해결하는 문제 · 작동 원리 · 흔한 오해 |

### 답이 노트에 없거나 자리가 겹쳐서 질문을 바꾼 것 (3건)

**답이 없어서 죽은 단추가 될 뻔한 자리다. 이번 이행의 진짜 수확이다.**
셋 다 새 질문의 답을 그 노트 안에서 확인한 뒤에 갈아 끼웠다. 내용을 새로 지어내지 않았다.

- **CRM** — "담당자가 바뀌어도 고객 이력이 이어지려면 무엇이 남아 있어야 하나"
  답("담당자 교체 :: 이력이 사라짐 || 기록이 남는다")이 **해결하는 문제에만** 있는데
  첫 질문이 이미 거기를 겨눴다. 셋째가 같은 칸을 두 번 짚게 된다.
  → **"이름과 전화번호만 채워 둔 CRM 이 안 넣은 것과 같아지는 이유는 → 흔한 오해"**.
  흔한 오해 첫 줄("이름과 번호만 들어 있으면 안 넣은 것과 같다. 언제 무슨 말이 오갔고
  지금 어느 단계인지가 있어야 판단에 쓰인다")이 그대로 답이다.

- **Package Manager** — "테스트 라이브러리를 dependencies 가 아니라 devDependencies 에
  두는 이유는" 답이 **실제 사례에만** 있는데 첫 질문이 이미 실제 사례였다.
  → **"라이브러리 하나만 적었는데 폴더에 수십 개가 깔리는 까닭은 → 해결하는 문제"**.
  해결하는 문제의 "라이브러리 하나를 쓰려면 그 라이브러리가 기대는 다른 라이브러리도
  있어야 한다" + 대조의 "딸린 것 :: 직접 쫓아다닌다 || 같이 받아 온다" 가 답이다.

- **IDE** — "IDE의 이름 바꾸기가 문자열 찾아 바꾸기와 다른 점은" 과
  "IDE만 쓰다가 서버에 접속했을 때 막히는 이유는" 이 **둘 다 흔한 오해**를 겨눴다.
  앞엣것의 답이 작동 원리에도 온전히 있다("이름 바꾸기가 안전한 것도 같은 이유다.
  글자가 같아도 다른 변수면 건드리지 않는다"). 질문은 그대로 두고 겨눈 자리만 갈랐다.

### 물음 자체를 다듬은 것 (1건)

- **CLI** — "`cat app.log | grep ERROR | wc -l` 에서 각 프로그램은 서로를 **어떻게 아나**"
  는 서로 안다는 것을 전제로 깔았는데, 작동 원리의 답은 정반대다("세 프로그램은 서로를
  모르고 각자 글자를 받아 글자를 내놓을 뿐"). 전제를 답과 맞춰
  **"…세 프로그램이 서로를 모르는데도 이어 붙는 까닭은 → 작동 원리"** 로 고쳤다.

## 2. 흐름의 `<` 감사 — 6곳에서 뗐고, 1곳은 `@` 가 됐다

`<` 앞에는 앱이 "여기서부터 돌아오는 길" 을 새긴다. **누가 누구에게 답을 주는가**를
한 줄씩 물어봤다. 대답이 안 나오는 자리 여섯을 표지 없는 보통 마디로 내렸다.

| 노트 | 문제의 줄 | 왜 `<` 가 아닌가 | 어떻게 |
|---|---|---|---|
| Git | `< push :: 원격 저장소로 올려…` | push 는 **바깥으로 나가는 길**이다. 되돌아오는 게 아니라 정반대 방향인데 난간이 여기서 꺾여 그려지고 있었다 | 보통 마디 |
| Docker | `< 결과 :: 내 컴퓨터와 같은 환경이…` | 아무도 누구에게 답을 주지 않는다. 실행의 결말이지 응답이 아니다 | 보통 마디 |
| Environment Variable | `< 앱 :: 그 값으로 접속하고…` | 값을 받아 쓰는 다음 동작이다. 되돌려주는 것이 없다 | 보통 마디 |
| Package Manager | `< 내 코드 :: import 한 줄로…` | 설치가 끝난 뒤의 사용이다. 응답이 아니다 | 보통 마디 |
| CRM | `< 결과 :: 성사와 실패를 남겨…` | 파이프라인의 종착이다. "다음 판단에 쓴다" 가 되돌아가는 화살처럼 읽히지만 첫 마디(접점)로 돌아가는 게 아니라 기록으로 쌓이는 것이다 | 보통 마디 |
| Windows | `< 작업 관리자 :: 목록에 프로세스가…` | 작업 관리자는 **구경하는 자리**다. 아무에게도 답을 주지 않는다 | 보통 마디 |

### `@` 로 올라간 것 (1건)

- **IDE** — `< 편집기 :: 고치고 다시 돌린다. 창을 바꾼 적이 없다`
  → **`@ 편집기 :: …`**. 마지막 마디가 **첫 마디(편집기)로 되돌아가 처음부터 다시 하는**
  자리다. 검사기가 "'다시' 가 있다" 고 경고한 자리와 같지만, 문자열이 아니라 뜻으로 봐도
  순환이 맞다 — 고치면 다시 빨간 줄부터 시작한다. 이미 마지막 줄이라 옮길 필요는 없었고,
  마디는 `@` 포함 6개로 4~7 안에 그대로 든다.

### 그대로 둔 `<` (5건, 전부 진짜 응답이다)

CLI(운영체제→셸→터미널) · SDK(카메라→운영체제→내 앱) · Terminal(프로그램→터미널) ·
Linux(하드웨어→커널→셸) · OS(디스크→운영체제→프로그램). 다섯 다 "누가 누구에게" 에
이름이 또렷하게 나온다.

## 3. 대조 감사 — ✕ 칸 자기검사

11편의 `||` 대조를 왼쪽 칸부터 한 줄씩 읽었다. **왼쪽에 장점이 실린 줄은 없었다.**
전부 "있고 없고"(격리 없이 / 코드에 적으면 / 손으로 / OS 없이 / CRM 없이 …)라
`||` 가 맞아서 **하나도 바꾸지 않았다.**

한 곳만 오래 봤다 — **Linux** 의 `고치기 :: 만든 곳에 요청 || 직접 고친다` 다.
같은 노트 흔한 오해가 "직접 해결해야 한다" 를 **비용**으로 적어두고 있어서 ✓ 가 거슬렸다.
그래도 왼쪽 칸("만든 곳에 요청")은 만든 곳에 매인 상태이지 장점이 아니고, ✅ 장단점으로
옮기려면 접이식이 7칸이 되어 한 칸이 잘린다. 자기검사 기준대로 `||` 를 유지했다.

`|=|` 를 새로 쓴 곳은 4번에서 만든 Container 그림 하나뿐이다. 억지로 넣지 않았다.

## 4. 그림 자리 감사 — 2편을 바꿨다

판정법은 **그림만 보고 정의 첫 문장을 복원할 수 있는가** 다.

### Linux — 흐름과 층을 맞바꿨다 (승격)

그림 자리에 있던 `흐름: 터미널에 명령을 치면 무슨 일이 일어나나` 는
**리눅스에 대해 아무것도 말하지 않는다.** 사용자→셸→커널→하드웨어는 CLI·Terminal·OS
어느 노트에 놓아도 똑같이 맞는 그림이고, 정의("누구나 뜯어보고 고칠 수 있는 운영체제")를
복원할 수 없다. 게다가 CLI.md·Terminal.md의 그림과 사실상 같은 그림이다.

작동 원리에 있던 `층: 배포판마다 무엇이 다른가` 를 그림 자리로 올렸다. 이쪽은
**커널 하나에 포장이 여럿**이라는 이 노트의 뼈대를 그대로 보여주고, 정리("리눅스는 소스가
공개된 커널이고, 그 위에 도구를 얹어 묶은 것이 배포판이다")와 흔한 오해 첫 줄
("정확히는 커널 이름이다")이 겨누는 바로 그 형태다.

흐름은 작동 원리로 내려보내면서 배포판 문단 뒤에 "포장이 달라도 안쪽에서 벌어지는 일은
같다" 한 줄을 놓아 이었다. 뒤따르는 명령어 목록("배포판이 달라도 대체로 통한다")과
자연스럽게 붙는다. 확인 질문 둘의 겨눈 자리도 따라 옮겼다(배포판→그림, `ls`→작동 원리).

### Container — 층을 대조로 다시 세웠다

5번(층 반증)에서 걸렸다. 아래에 같이 적는다.

### 그대로 둔 것

Docker · Git · CLI · Terminal · Package Manager · Environment Variable · CRM · SDK ·
OS · Windows · IDE — 전부 개념의 형태이고 정의 첫 문장이 복원된다. 고르는 절차를
그림 자리에 둔 노트는 없었다.

SDK 와 OS 는 한 번 더 봤다. SDK 의 흐름은 "꾸러미" 라는 말까지는 못 그리지만 "플랫폼
속사정을 함수 뒤로 감춘다" 는 정의의 작동부를 `=` 줄이 그대로 말하고, OS 의 흐름은
"프로그램과 하드웨어 사이에 선다" 를 복원한다. 둘 다 절차가 아니라 개념의 작동이라 뒀다.

## 5. 층 반증 테스트 — 3편에서 걸렸다

**이웃한 두 층을 맞바꿔도 그림이 안 틀리면 층이 아니다.**

### Container — 층 → `|=|` 대조 (그림 자리)

```
하드웨어 / 호스트 OS / 컨테이너 / 가상 머신
```
**컨테이너와 가상 머신을 맞바꿔도 아무것도 안 틀린다.** 둘은 위아래로 쌓인 게 아니라
나란히 선 두 갈래인데 층으로 그려서 없는 상하가 생겼다. 게다가 하드웨어가 맨 위라
"위가 가깝고 아래가 멀다" 는 층의 방향과도 거꾸로였다.

두 갈래 비교이므로 **대조**로 다시 세웠다. 칸 이름 줄은 `|=|` 를 썼다 — 같은 노트
흔한 오해가 "격리 수준이 가상 머신보다 낮다" 를 적어두고 관련 용어가 VM 을 "더 강한
격리" 라고 부르는데, `||` 로 두면 그림이 2초 만에 "가상 머신은 나쁜 것" 이라는 오해를
심는다. "있고 없고" 가 아니라 우열이 갈리지 않는 두 선택지다.
줄은 노트에 이미 있는 사실(운영체제 공유 / 하드웨어 흉내 대 프로세스 가리기 / 무게)로만
채웠고 `=` 줄은 그대로 뒀다.

### IDE — 층 → 진짜 축으로 다시 세움

```
편집기 / 분석기 / 디버거 / 연동
```
**디버거와 연동을 맞바꿔도 안 틀린다.** "IDE 안에는 무엇이 겹쳐 있나" 라고 물었지만
답은 네 부품의 나열이었고, `= ` 줄도 편집기·분석기 한 쌍만 설명하고 있었다.

축을 **"내 코드를 어디까지 들여다보나"** 로 다시 세웠다 —
글자 그대로(편집기) → 이름이 무엇을 가리키는지(분석기) → 실행 중의 값(디버거).
아래로 갈수록 **더 많이 본다.** 이웃을 맞바꾸면 전부 틀린다(분석기는 편집기보다 더 보고,
디버거는 정적 분석이 알 수 없는 실행 시점 값까지 본다). `= ` 줄은 확인 질문 둘째가
겨누는 이름 바꾸기 이야기로 맞췄다.

빠진 "연동(터미널과 Git 을 같은 창에)" 은 해결하는 문제 본문과 실제 사례에 이미 같은
말이 있어서 사라진 정보가 없다.

### Windows — 층 → 본문 불릿

```
탐색기 / 작업 관리자 / CMD, PowerShell
```
**탐색기와 작업 관리자를 맞바꿔도 안 틀린다.** 축이 없는 도구 셋 나열이고,
`= ` 줄("화면으로 하는 일은 대부분 명령줄로도 할 수 있다")은 층이 아니라 **대조**의 결론이다.

그런데 이 노트가 가진 사실만으로는 대조 줄 3개를 못 채운다(화면 대 글자로 견줄 항목이
탐색기·작업 관리자 둘뿐이다). 없는 줄을 지어내지 않기로 하고 **본문 불릿으로 되돌렸다.**
확인 질문 둘째가 겨누는 자리라 답이 사라지지 않게 세 줄과 결론을 그대로 옮겨 적었다.

### Package Manager — 층 → 본문 문단

```
선언 / 해석 / 내려받기 / 설치 자리
```
이웃을 맞바꾸면 틀리기는 하는데 **틀리는 이유가 시간 순서**다. 마디 이름이 그대로 단계
이름이고, 같은 순서를 그림 자리의 흐름(`npm install 한 줄이 무슨 일을 하나`)이 이미
그리고 있었다. 층으로 그릴 것도 흐름으로 그릴 것도 아니라 **본문 문단으로 되돌렸다.**
도해에만 있던 "레지스트리" 는 반 구절로 풀어(6번) 문단에 살렸다.

### 그대로 둔 층 (5건)

- **CLI** (터미널/셸/프로그램/커널) — 사람↔하드웨어 축. 이웃 교환 전부 틀린다.
- **Terminal** (터미널/Shell/운영체제) — 같은 축. `=` 줄이 "터미널을 바꿔도 Shell 은
  그대로" 라는 구조 주장이라 시간이 아니다.
- **Docker** (Dockerfile/이미지/컨테이너) — 설명서→굳힌 것→실행 상태의 파생 관계.
  `=` 줄이 "이미지 하나로 컨테이너 여럿" 이라 시간이 아니라 포함이다.
- **Environment Variable** (직접 넘긴 값/.env/코드 기본값) — 우선순위 축. 교환하면 틀린다.
- **CRM** (행동/판단/고객 정보/접점 데이터) — 의존 축. 위가 아래 없이는 못 선다.
- **OS** (응용/시스템 호출/커널/드라이버/하드웨어) — 교과서적인 깊이 축.
- **SDK** (내 앱/SDK 라이브러리/플랫폼 API/드라이버) — 같은 깊이 축.
- **Linux** (기본 구성/패키지 관리/기본 도구/커널) — **갈리는 정도** 축.
  가장 많이 갈림 → 대체로 비슷 → 어느 배포판이든 같음. 이웃을 맞바꾸면 `= ` 줄이 틀린다.

`= ` 줄이 "이 넷이 / 하나같이 / 각각" 으로 시작하는 층은 배정 안에 없었다.

## 6. 선행 용어 — 반 구절로 푼 것 (4건)

`[[링크]]` 를 걸 만한 노트가 없는 말들이라(Shell·Kernel·Driver·Volume·Linter 노트는
`content/` 에 없다) 전부 반 구절로 풀었다. 관련 용어 칸이 이미 꽉 찬 노트도 있었다.

- **Docker** — 볼륨 → `볼륨(호스트 디스크의 한 칸을 컨테이너 안에 붙여주는 것)`
- **IDE** — 린터 → `린터(돌려보지 않고 코드의 문제를 짚어주는 검사기)`
- **SDK** — 에뮬레이터 → `에뮬레이터(실제 기기를 흉내 내 컴퓨터에서 돌려보게 하는 프로그램)`
- **Windows** — 드라이버 → `드라이버(장비마다 다른 다루는 법을 운영체제에 알려주는 프로그램)`
- **Package Manager** — 도해 마디의 `semver 규칙에 맞는 버전을 고른다` 는 마디 이름 안에서
  풀 자리가 없어 **`적어 둔 범위에 맞는 것을 고른다`** 로 갈았다. "범위로 적는다" 는
  흔한 오해 둘째 줄이 이미 설명한다. 없어진 "레지스트리" 는 본문에서
  `레지스트리(패키지들이 올라가 있는 공개 저장소)` 로 풀어 살렸다.
