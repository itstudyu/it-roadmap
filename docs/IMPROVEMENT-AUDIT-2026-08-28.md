# IT 단어 학습 앱 개선 감사

작성일: 2026-08-28

## 결론

이 프로젝트의 약점은 콘텐츠 양이나 기본 시각 품질이 아니다. 이미 12개 단어장, 629개 용어,
629개 장면 SVG, 용어별 정의·비유·사례·오해·열 살 설명·확인 질문을 갖춘 강한 학습 콘텐츠다.

가장 큰 개선 기회는 다음 세 가지다.

1. **사전 색인을 학습 경로로 바꾸기** — 알파벳순 목록은 찾기에는 좋지만 배우는 순서가 아니다.
2. **읽기→회상→확인의 직선 루프 복원** — 현재 정상 CTA는 회상 단계를 건너뛸 수 있다.
3. **그림 문법 검사와 의미 이해 검사를 분리** — 3컷 형식을 통과해도 핵심 원리가 빠질 수 있다.

전면 리스킨보다 이 세 가지를 먼저 바꾸는 편이 사용자 목표인 “남에게 설명 가능한 이해”에 직접 닿는다.

## 현재 구조

- Vanilla HTML/CSS/JS 정적 PWA. 빌드 프레임워크, 로그인, 서버 DB가 없다.
- 해시 라우터와 `localStorage`로 읽기·회상·퀴즈·간격 복습을 제공한다.
- 실제 데이터는 12권 629편이다. `data/index.js`와 권별 `data/terms/*.js`를 쓴다.
- 원본은 `content/` Markdown이며 생성 데이터를 직접 고치면 안 된다.
- 장면 원본은 `scenes/*.json`; 생성기와 공용 부품으로 `data/scenes/*.js` SVG를 만든다.
- 디자인은 따뜻한 종이, 잉크, Pretendard와 Source Serif 중심이다. 현재 기반은 보존 가치가 높다.

## 잘된 점

- 첫 문장 60자 원칙과 쉬운 한국어.
- 이름 풀기, 비유, 실제 예, 직접 해보기, 흔한 오해, 열 살 설명, 상황형 확인 질문.
- 본문 속 낯선 용어를 그 자리에서 푸는 점선 용어 풀이.
- 장면에서 변한 것 하나만 파란색으로 추적하는 일관된 시각 문법.
- 정답/오답을 비난하지 않는 피드백과 색+모양+문구를 함께 쓰는 상태 표현.
- 모바일, 다크 모드, 오프라인, 모션 감소 설정을 이미 고려한 기반.

## 우선순위 문제

### P1 · 초보자용 학습 순서가 없다

권 안은 제목 기준으로 모여 냉시작 추천이 `Async/Await`, 네트워크 첫 항목이 `ALPN`이다.
전역 검색도 없어서 DNS가 어느 권인지 모르는 사용자는 먼저 분야를 알아야 찾을 수 있다.

추천 개선:

- 홈에서 `웹이 열리는 원리`, `앱 만들고 배포하기`, `데이터·AI 이해하기`처럼 4개 이하 목표 경로를 제시.
- 경로에 `7개 · 약 20분 · 기초`를 표시.
- 예시 경로: `URL → DNS → IP Address → TCP → HTTP → HTTPS → Load Balancer`.
- “학습 경로”와 알파벳순 “주제별 사전”을 별도 모드로 둔다.

### P1 · 회상 단계가 정상 루프에서 우회된다

상세의 주 CTA는 바로 학습 완료 상태로 올리지만, 떠올리기 후보는 읽는 중/복습 상태다.
따라서 README의 `읽기 → 떠올리기 → 퀴즈`와 실제 정상 흐름이 어긋난다.

추천 개선:

- 상세 CTA를 `그림 없이 설명해 보기`로 바꾼다.
- 단어 하나 회상 → `떠올랐다` → 학습 완료 → 오늘의 1~3문제 순으로 직선 연결한다.

### P1 · 퀴즈 규모가 완료 의지를 꺾는다

권별 범위가 실제로 수백 문제까지 표시된다. 사용자는 “언제든 그만둘 수 있음”보다 큰 숫자를 먼저 본다.

추천 개선:

- 기본 CTA는 `오늘의 5문제 · 약 3분` 하나.
- 끝난 뒤 `5개 더`를 선택하게 한다.
- 권 전체 수백 문제는 “문제은행” 또는 진단 모드로 분리한다.

### P1 · 핵심 재설명 단계가 긴 상세 맨 아래에 있다

DNS 상세는 접힌 심화를 열지 않아도 약 4.8개 모바일 화면 길이다. “열 살에게”와 자기 확인은 거의 끝에 온다.

추천 개선:

- `무엇인가 → 왜 필요한가 → 어떻게 되나 → 흔한 오해 → 내 말로 설명 → 확인`으로 한 단계씩 제시.
- 사전식 전체 글은 `전체 글로 보기`로 남겨 빠르게 훑는 사용자를 막지 않는다.

### P1 · 그림의 형식 통과가 의미 완전성을 보장하지 않는다

장면 629편은 문법 lint를 통과하지만 609편이 3컷이다. 확률·권한·동시성·상태처럼 복잡한 개념도
같은 actor-flow 3컷에 압축되면 핵심 분기나 왕복이 빠질 수 있다.

즉시 검토할 대표:

- DNS: 이름 질문 → 번호 응답 → 받은 번호로 직접 접속을 분명히 분리.
- Bloom Filter: `확실히 없음`과 `있을 수도 있음 → 원본 확인` 두 갈래.
- OAuth: 앱 이동 → 서비스에서만 로그인 → 범위가 제한된 토큰 반환까지 신뢰 경계를 표시.

개념에 맞는 그림 유형:

- 흐름: DNS, HTTP, CI/CD — 3~5컷 이야기.
- 알고리즘·확률: Bloom Filter, B-Tree — 값 추적과 분기 도해.
- 권한·보안: OAuth, XSS — 신뢰 경계와 노출 데이터.
- 동시성·상태: Race Condition, Transaction — 타임라인/상태 머신.
- 계층·포함: Kubernetes, OSI — 중첩 구조.
- 대조·트레이드오프: TCP/UDP, VM/Container — 같은 입력의 두 결과.

## 새 프로토타입

`mockups/learning-experience-prototype.html?variant=a|b|c`

- A · Guided Trail: 설명 가능한 6단계 코스. 제품 구조 추천.
- B · Concept Atlas: 선행·후속 개념을 보는 탐색 지도. 별도 탐색 모드 후보.
- C · Illustrated Handbook: 큰 그림과 글의 절이 함께 움직이는 편집형 사전.

추천 조합은 **A의 단계형 학습 구조 + C의 큰 일러스트 연출**이다.

## “100% 이해”를 제품 기준으로 바꾸기

절대 이해를 선언할 수는 없으므로 통과 기준으로 측정한다.

1. 제목을 가리고 그림만 보여 5명 중 4명 이상이 `문제 → 핵심 동작 → 결과`를 말한다.
2. 제목과 정의까지 본 5명 모두 상황형 3문항 중 2개 이상 답한다.
3. 흔한 오해 하나를 제시했을 때 이유와 함께 반박한다.
4. IT 용어를 최소화한 두 문장 teach-back에 성공한다.

실패하면 문구를 더 붙이기 전에 학습 순서와 그림 구조를 먼저 고친다.
