# 전면 개편 계획 — Mobile Guided Atlas 이식

작성 2026-08-30. `mockups/learning-experience-prototype.*` 를 실물 앱으로 옮기는 계획이다.
목표는 하나뿐이다: **이 앱을 본 사람이 다른 열 살 아이에게 그 단어를 설명할 수 있게 만든다.**

## 확정된 결정

| # | 결정 |
|---|---|
| 1 | 진짜 전면 교체 — 퀴즈·회상 화면도 목업 언어로 새로 쓴다 |
| 2 | 608편을 4컷으로 다시 굽는다 |

## 검수에서 확인한 것

목업을 실제 데이터와 대조해 확인한 사실이다. 추정이 아니라 측정값이다.

### 멀쩡한 것

- 36개 경로 · 218개 노드 이름 → **218/218 실제 단어 id 로 해석된다. 실패 0.**
- 12개 카테고리 count → **12/12 실제 인덱스와 일치.** 합계 629 = 실제 629.
- 9개 씬 토큰 이름 → 라이트 테마 기준 전부 정의돼 있다.
- 상세 없는 단어의 폴백 → 깨지지 않는다. "전면 개편에서 보강" 안내로 정직하게 내려앉는다.
- 5개 노드가 다른 책으로 넘어간다 (`cloud` 경로 → `tool--dockerfile`, `infra--deployment`,
  `infra--service`, `tool--docker-image`, `net--load-balancer`). 의미상 의도된 참조로 보인다.
  다만 `pathsContainingTerm` 이 이 단어들을 cloud 소속으로 표시하므로 라벨은 손봐야 한다.

### 목업에 아예 없는 것

목업은 **화면 시안**이지 동작하는 앱이 아니다. 이걸 전제로 일정을 잡아야 한다.

1. **저장이 없다.** `localStorage` 검색 0건. 진도는 전부 하드코딩이다 —
   `learnedByCategory = {net:6, cs:3, web:2, …}`, `PROGRESS_GROUPS` 의 `learned: 7/2/6/3`.
   단어 상태는 `termStatus(index)` 가 **배열 순번으로** 정한다(0번=학습 중, 1·4번=설명 가능,
   2번=복습 필요). 어느 카테고리를 열든 같은 자리에 같은 뱃지가 붙는다.
2. **라우팅이 없다.** `location.hash` · `pushState` · `popstate` 전부 0건.
   뒤로가기를 누르면 앱을 나간다. 딥링크도 안 된다. 지금 앱은 라우트가 10개다.
3. **다크 테마가 없다.** `prefers-color-scheme` 0건. 실제 앱은 `css/tokens.css:166` 부터
   다크 팔레트가 다 있다. 다크 모드 폰에서 목업은 흰 화면만 나온다.
4. **퀴즈가 통째로 없다.** 목업에서 "퀴즈"는 버튼 라벨 4곳뿐.
   실제 앱은 `js/quiz.js` 44KB + `js/quiz-screens.js` 24KB.
   복습도 `reviewTotal = 3` 고정이라 `REVIEW_QUEUE` 5개 중 4·5번은 도달 불가다.
5. **코스는 DNS 한 편만 돈다.** `isDnsRoute = category.id === "net" && state.routeIndex === 0`
   이 6단계 워크스페이스 전체를 막는다. 나머지 35개 경로에서 `workspace` 는 빈 문자열이다.
   `dnsSceneSvg()` 는 항상 `net--dns` 만 반환하고, `STORY` 4컷 캡션도 DNS 하드코딩이다.

### 가장 비싼 것 — 컷 수 불일치

```css
.storyboard__masks { grid-template-rows: repeat(4, 1fr); }
```

629편 각본의 실제 컷 수:

```
3컷: 608편   (96.7%)
4컷:  21편   ( 3.3%)
```

단계 공개 마스크는 4컷 전용이다. viewBox 는 4컷일 때 `0 0 400 512` 이고 컷 pitch 가 130 인데,
3컷은 높이가 382 라 마스크 4행(95.5씩)이 컷 경계와 전부 어긋난다.
목업 노트의 "나머지는 글만 더 쓰면 된다" 가 성립하지 않는 지점이다. 글이 아니라 그림 작업이다.

### 뒤집힌 것 — "3/629" 는 집필 격차가 아니다

목업 노트는 상세 설명이 3편뿐이라고 적었다. 실제 `content/*.md` 를 세어 보면:

| 절 | 커버리지 |
|---|---|
| 📝 정의 | 629 / 629 |
| ⚠️ 해결하는 문제 | 629 / 629 |
| 🚫 흔한 오해 | 629 / 629 |
| 🧒 열 살에게 | 629 / 629 |
| 💡 실제 사례 | 629 / 629 |
| ⚙️ 작동 원리 | **547 / 629** |

목업의 `TERM_DETAILS` 6필드가 기존 절에 그대로 매핑된다:

| 목업 필드 | 기존 절 | 상태 |
|---|---|---|
| `definition` | 📝 정의 | 629편 있음 |
| `why` | ⚠️ 해결하는 문제 | 629편 있음 |
| `steps` | ⚙️ 작동 원리 | 547편 있음 · **82편 부족** |
| `traps` | 🚫 흔한 오해 | 629편 있음 |
| `teach` | 🧒 열 살에게 | 629편 있음 |
| `paths` | — | `pathsContainingTerm` 이 자동 계산 |

목업이 3편만 가진 이유는 목업이라 JS 리터럴로 박아 둔 것뿐이다.
**진짜 집필은 작동 원리 82편이 전부다.** 나머지는 배선 작업이다.

그리고 `INPUT / ROLE / OUTPUT / 경계` 4칸 띠(`visualByTerm`)는
Phase 1 에서 각본을 `입력 → 일 → 출력 → 경계` 4컷으로 다시 구우면 캡션에서 그대로 나온다.
컷 4개와 띠 4칸이 같은 것이다. 두 작업을 하나로 묶는다.

### Phase 1 — 각본 4컷화 (608편) · 트랙 A

Phase 2 와 **파일이 겹치지 않는다.** 진짜로 병렬로 돌릴 수 있다.

**컷 문법 확정:**

| 컷 | 뜻 | DNS 예시 |
|---|---|---|
| 1 | 입력 — 무엇이 들어오나 | 이름을 입력한다 |
| 2 | 일 — 이 단어가 하는 일 | DNS에 묻는다 |
| 3 | 출력 — 무엇이 나오나 | IP 주소를 받는다 |
| 4 | **경계** — 여기서 끝나고 다음은 누구 일인가 | 그 주소로 연결한다 |

4컷째가 경계인 이유: 열 살에게 설명할 때 가장 많이 틀리는 지점이
"이 단어가 어디까지 하는가" 다. DNS 를 "웹사이트를 열어 주는 것" 이라고
말하는 오해가 정확히 여기서 생긴다.

작업:

1. `tools/scenes/lint_scenes.py` 에 규칙 추가 — 컷은 정확히 4개, 4컷째는 경계 컷.
   기존 3~6컷 허용 규칙을 4컷 고정으로 좁힌다.
2. 각 각본의 🚫 흔한 오해 절을 근거로 4컷째를 쓴다. 629편 전부 이 절을 갖고 있으므로
   경계 문장의 원천이 이미 있다.
3. 캡션 ≤10자 · 말풍선 ≤8자 · 이름표 ≤12자 규칙 유지.
4. 파란색 = 옮겨지는 것, 컷당 1개(체크 달린 컷은 2개) 규칙 유지.
5. 접힌 선 규칙은 4컷 고정이 되면 자동으로 만족된다 (체크가 첫 4컷 안).
6. `tools/build_scenes.py` 로 12권 전부 재생성.
7. **덤으로 나오는 것**: 4컷 캡션이 곧 `INPUT / ROLE / OUTPUT / 경계` 띠 데이터다.
   `data/scenes/*.js` 에 캡션 배열을 SVG 와 같이 굽는다.

**통과 조건** — 629/629 편이 4컷이고 lint 통과. 12권 재생성 완료.
표본 20편을 실제로 렌더해 눈으로 확인한다. 지표만 보고 판단하지 않는다
(예전에 뼈대 충돌·그림 낱말 지표 두 개가 렌더해 보니 둘 다 헛경보였다).

### Phase 2 — 앱 뼈대 교체 · 트랙 B

**2-1 토큰과 CSS**
목업 CSS 7098줄(123KB)에서 실제로 쓰이는 규칙만 추린다. `:root` 를 다시 써서
`css/tokens.css` 의 라이트·다크 팔레트를 상속받게 한다.
**9개 씬 토큰 이름은 절대 바꾸지 않는다** — 이름이 바뀌면 629편이 전부 검게 렌더된다.
값은 바꿔도 된다.

**2-2 라우터**
5탭 IA 를 라우트로 매핑한다. 뒤로가기와 딥링크를 복구한다.

```
/today                 오늘
/course                코스 목록
/course/:categoryId    카테고리 허브
/course/:categoryId/:pathIndex   경로 · 6단계 학습
/terms/:categoryId     카테고리 전체 단어
/term/:termId          단어 상세
/search                찾기
/review                복습 (회상 + 퀴즈)
/review/run
/review/result
/progress              진도
```

기존 라우트(`/home /books /books/:bookId /term/:termId /quiz /quiz/run
/quiz/result /progress /recall/run /recall/done`)에서 오는 링크는
새 라우트로 리다이렉트한다. `/term/:termId` 는 그대로라 기존 북마크가 산다.

**2-3 화면**
`js/screens.js` 를 목업 템플릿 함수 기준으로 다시 쓴다:
`hubShell` · `todayTemplate` · `courseCatalogTemplate` · `categoryHubTemplate` ·
`categoryTermsTemplate` · `searchTemplate` · `reviewTemplate` · `progressTemplate` ·
`guidedTemplate` · `termSheet` · `categorySheet`.

**2-4 가짜 데이터를 진짜로 교체** — 이게 이식의 핵심이다

| 목업 (가짜) | 실물 (진짜) |
|---|---|
| `termStatus(index)` 순번 기반 | `store.statusOf(term.id)` |
| `learnedByCategory` 하드코딩 12개 | `store.counts()` 를 책별 집계 |
| `PROGRESS_GROUPS[].learned` 하드코딩 | 4개 학습 목적 그룹별 집계 |
| `REVIEW_QUEUE` 하드코딩 5개 | `store.dueTerms()` |
| `reviewTotal = 3` 고정 | 실제 due 개수 |
| `TERM_DETAILS` JS 리터럴 3편 | `data/terms/<book>.js` 의 절 |
| `STORY` DNS 하드코딩 4컷 | 각 단어 각본의 캡션 배열 |
| `dnsSceneSvg()` | `VOCAB_SCENES[book][termId]` |
| `visualByTerm` 3편 | 각본 4컷 캡션 |
| `isDnsRoute` 게이트 | 삭제 — 36개 경로 전부 6단계를 돈다 |

**2-5 저장**
`KEY = "it-vocab-mockup:v1"` 그대로. 모양도 그대로.
`{terms: {id: {status, readAt, passedAt, wrong, box, dueAt}}, history, studyDays,
lastSeenAt, read: {hintSeen, gloss, walked}}`.
Leitner 박스 `[1,3,7,16,35]` 유지. 단어 id `{book}--{titleSlug}` 유지.
**새 필드를 추가하지 않는다.** 마이그레이션 코드가 없으면 되돌리기도 공짜다.

**2-6 스토리보드 마스크**
Phase 1 이 끝나면 `repeat(4, 1fr)` 이 맞다. 다만 Phase 1 진행 중에는
3컷과 4컷이 섞이므로, 각본의 컷 수를 CSS 변수로 넘겨 방어한다:
`grid-template-rows: repeat(var(--cuts, 4), 1fr)`.
Phase 1 완료 후에도 이 방어는 남겨 둔다 — 공짜고, 나중에 컷 수가 바뀌어도 안 깨진다.

**2-7 씬 로딩과 오프라인**
씬은 12권 5.3MB 다. 목업은 `net.js` 하나(670KB)만 불러온다.
지금 앱처럼 책 단위 lazy load 를 유지하고, `sw.js` 는 12권 전부 프리캐시한다.
오프라인에서 어느 단어를 펼칠지 미리 알 수 없기 때문이다.
첫 로드 예산을 잰다 — 지금 114KB gzip 이고, `related[].note` 가 인덱스의 26% 다.
이식하면서 이걸 인덱스에서 빼 `data/terms/` 로 옮길지 판단한다.
(`js/quiz.js:585` 가 `answer.note` 를 전체 풀에서 쓰고 `js/screens.js:748` 이 렌더한다.
빼려면 이 둘을 같이 고쳐야 한다.)

**통과 조건** — 5탭 전부 진짜 진도로 그려진다. 뒤로가기가 동작한다.
다크 모드에서 그림이 검게 안 나온다. 기존 진도가 그대로 보인다.

### Phase 3 — 퀴즈·회상 재작성 (복습 탭 통합)

복습 탭 하나가 두 가지를 맡는다. 둘 다 "기억을 꺼내는 일" 이라 사용자 머릿속에서 한 개다.

- **떠올리기** — 화면을 가리고 말한 뒤 모범 설명과 대조. 자기 채점 (다시 · 어려움 · 알겠음).
- **고르기** — 객관식. 자동 채점.

**가정을 명시한다**: 화면은 전부 새로 쓰되, **출제·채점 로직은 유지한다.**
`js/quiz.js` 의 오답 후보 생성과 Leitner 승급 규칙은 디자인이 아니라 데이터 계층이고,
이미 검증됐다. 교체 대상은 `js/quiz-screens.js` (24KB) 와 `js/recall.js` (16KB) 의 화면이다.
로직까지 새로 쓰길 원하면 알려 달라 — 그러면 Phase 3 이 두 배가 된다.

`REVIEW_QUEUE` 의 `cue` (예: "이름 · 주소 · 끝나는 지점")는 목업이 손으로 쓴 것이다.
629편으로 늘리려면 4컷 캡션의 앞 3개를 이어 붙이면 된다 — Phase 1 결과물이 여기서도 쓰인다.

**통과 조건** — 복습 탭에서 두 방식이 다 돌고, 진도가 저장되고,
Leitner 박스가 기존 규칙대로 오른다.

### Phase 4 — 1차 배포

**실측 검증.** 헤드리스 크롬의 `--window-size` 는 예전에 뷰포트를 속였다
(390 · 430 · 500 에서 내용이 재배치되지 않고 절대 좌표가 동일했다).
**진짜 iframe 안에** 목표 너비로 렌더해서 잰다.

| 뷰포트 | 기기 |
|---|---|
| 402 × 874 | iPhone 17 / 17 Pro (기준) |
| 440 × 956 | iPhone 17 Pro Max |
| 390 × 844 | iPhone 14/15 급 |
| 320 × 700 | 최소폭 |

각 뷰포트 · 라이트/다크 양쪽에서:
- 가로 넘침 0
- 고정 요소(하단 탭 · 하단 CTA · 시트)와 본문 충돌 0
- 터치 대상 ≥ 44 × 44pt
- 하단 CTA ≥ 52px
- `env(safe-area-inset-*)` 반영
- 본문 ≥ 16px, 줄간 ≥ 1.72

그림 검증:
- 629편 전부 라이트·다크에서 검게 안 나오는지 (9개 토큰 계약)
- 그림 속 작은 글자만으로 뜻이 전달되는 편이 없는지 (16px HTML 캡션이 옆에 있어야 한다)

접근성:
- `#prototype-main` 건너뛰기 링크 대상이 JS 렌더라 초기 HTML 에 없다 — 실물에서는 정적으로 둔다
- 보이는 포커스 · aria · 동적 타입 · `prefers-reduced-motion`

오프라인:
- 비행기 모드에서 설치된 앱이 그대로 열리는지
- `sw.js` `CACHE_VERSION` 을 `data/` 재생성과 같은 커밋에 올렸는지
  (안 올리면 설치된 앱에는 영원히 안 보인다)

배포:
- main 에 병합 후 배포. 되돌리기는 이전 커밋 재배포.
- 추가된 줄만 비밀값 스캔을 다시 돌린다.
