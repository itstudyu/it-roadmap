# 단어 노트 템플릿

새 단어를 vault 에 추가할 때 AI 가 따르는 형식이다.
기존 노트 246편에서 실제로 반복되는 구조를 추린 것이고, 여기에 **그림 한 장**을 새로 넣었다.

> **기존 노트는 이 템플릿에 맞춰 고치지 않는다.**
> 이 문서는 앞으로 쓸 단어에만 적용된다. 이미 있는 노트를 일괄 변환할지는 별도로 결정한다.

---

## 왜 그림을 넣었나

노트는 잘 쓰여 있는데 **읽어야만 알 수 있다.** 모바일에서 개념 하나를 이해하려면
문단 서너 개를 스크롤해야 하고, 그러다 보면 결국 안 읽는다.

그림 한 장이 하는 일은 요약이 아니라 **형태 인식**이다.
"DNS 는 다섯 군데를 거쳐 갔다가 돌아오는 길"이라는 걸 글로 읽으면 20초, 그림으로 보면 2초다.
그 2초가 나머지를 읽을지 말지를 정한다.

그래서 그림은 **접지 않는다.** 표제어 바로 아래, 정의 다음에 펼친 채로 둔다.

---

## 골격

```
# 단어 (원어)                        ← 필수

## 📝 정의                            ← 필수
  (첫 문단 = 한 줄 요약. 굵은 글씨로 화면 맨 위에 올라간다)
  (둘째 문단 = 배경. 없으면 생략)
  ### 비유                            ← 필수

## 🖼️ 그림으로 보기                   ← 필수 · 접히지 않는다
  ```도해 ... ```

## ⚠️ 해결하는 문제                    ← 필수
## ⚙️ 작동 원리                        ← 선택
## 📊 비교                             ← 선택
## ✅ 장단점                           ← 선택
## 💡 실제 사례                        ← 필수
## 🚫 흔한 오해                        ← 필수
## 🚨 주의사항                         ← 선택
## 📝 정리                             ← 필수
## ❓ 이해했는지                        ← 필수 · 접히지 않는다
## 🔗 관련 용어                        ← 필수
```

제목의 이모지까지 **글자 그대로** 쓴다. 앱이 이 문자열로 섹션을 찾는다.
`## 🖼️ 그림으로 보기` 를 `## 🖼 그림` 으로 바꾸면 그림 자리를 못 찾는다.

콜론을 붙여 부제를 다는 건 된다 — `## 📊 비교: DNS vs 유사 기술`.
무엇을 비교하는지 제목에서 알려주는 편이 낫다. 콜론 **앞부분**만 정확하면 된다.

필수 8개는 어떤 단어에도 쓸 수 있는 것들만 골랐다.
선택 4개는 그 단어에 정말 할 말이 있을 때만 쓴다. **빈 섹션을 만들지 않는다.**

### 펼쳐두는 자리는 셋

앱은 나머지를 전부 접는다. 펼친 채로 두는 건 **정의 · 그림 · 이해했는지** 셋뿐이다.
그림으로 들어와서 확인 질문으로 나간다. 그 사이가 설명이다.

### 필수 섹션이 각각 막는 구멍

| 섹션 | 안 쓰면 생기는 일 |
|---|---|
| 📝 정의 | 무슨 말인지 모른다 |
| 🖼️ 그림 | 읽어야만 알 수 있다 — 대개 안 읽는다 |
| ⚠️ 해결하는 문제 | 왜 있는지 모르니 기억에 안 남는다 |
| 💡 실제 사례 | 아는 것과 쓰는 것이 안 이어진다 |
| 🚫 흔한 오해 | **틀린 그림을 그대로 갖고 나간다** |
| 📝 정리 | 읽고 나서 손에 남는 게 없다 |
| ❓ 이해했는지 | 이해한 줄 알고 넘어간다 |
| 🔗 관련 용어 | 단어가 섬으로 남는다 |

## 섹션별로 지킬 것

### 📝 정의

첫 문단은 **한 문장, 60자 이내**. 화면에서 표제어 바로 밑에 큰 글씨로 올라가는 자리라
길면 그대로 벽이 된다. 형태는 `X 는 ~하는 Y 다`.

핵심어 하나만 `**굵게**` 한다. 굵은 게 셋이면 아무것도 안 굵은 것과 같다.

둘째 문단은 배경이나 유래. 정말 도움이 될 때만 쓰고 아니면 생략한다.

### ### 비유

**한 문장.** 일상 사물 하나에 빗댄다. IT 용어로 IT 용어를 설명하지 않는다.

```
✓ 전화번호부. 친구 이름을 대면 번호를 알려주고, 번호가 바뀌어도 이름은 그대로다.
✗ 서비스 디스커버리와 유사한 이름 해석 계층이다.
```

### 🖼️ 그림으로 보기

도해 블록 하나. 아래 문법 절을 따른다. **글은 쓰지 않는다** — 그림만 둔다.

### ⚠️ 해결하는 문제

`대조` 도해 하나 + 문단 1~2개.
"이게 없으면 무슨 일이 벌어지나"를 먼저 쓰고, 그다음에 이 단어가 그걸 어떻게 없애는지 쓴다.

### 💡 실제 사례

목록 3개. 각 항목은 `**상황** — 무슨 일이 일어나는지` 한 줄.
회사 이름을 지어내지 않는다. 일반적인 상황으로 쓴다.

### 🚫 흔한 오해

**여기가 이 템플릿에서 가장 어려운 자리다.** 그리고 가장 중요한 자리다.

반쯤 이해한 사람이 막히는 건 정보가 없어서가 아니라 **틀린 그림을 갖고 있어서**다.
맞는 말을 열 번 더 해도 그 그림은 안 지워진다. 틀렸다고 **이름을 불러줘야** 지워진다.

목록 2~3개. 형식은 `- **틀리게 아는 말** — 실제로는 이렇다`.

```
✓ - **DNS 가 사이트에 연결해준다** — 아니다. IP 주소를 알려주고 거기서 끝난다.
✗ - **DNS 는 중요하다** — 맞다. 인터넷의 핵심 인프라다.
```

- 앞부분은 **사람이 실제로 하는 말** 그대로 쓴다. 교과서 문장이 아니라 입말로.
- 초보자가 진짜 헷갈리는 것을 쓴다. 전문가끼리 다투는 미묘한 구분이 아니라.
- **순서를 뒤집지 않는다.** 맞는 말을 먼저 하면, 읽는 사람은 자기가 뭘 잘못 알고 있었는지
  모르고 지나간다.

어떻게 찾나 — 이 단어를 처음 듣는 사람이 이름만 보고 **넘겨짚을 만한 것**을 쓴다.
"DNS(Domain **Name** System)" 라는 이름만 보면 이름을 다루는 것까지는 맞히지만,
거기서 연결까지 해준다고 넘겨짚기 쉽다. 그 지점이 오해다.

### 📝 정리

**3문장 이내.** 앞에서 한 말을 줄이는 게 아니라, 이 단어의 정체를 한 번 더 못 박는다.

### ❓ 이해했는지

질문 3개. 화면 맨 아래에 펼쳐진 채로 놓이고, "학습 완료" 버튼 바로 위에 온다.

**철칙: 답이 반드시 이 노트 안에 있어야 한다.** 밖에서 찾아야 하는 질문은 시험이지 확인이 아니다.
쓰고 나서 각 질문의 답이 몇 번째 섹션에 있는지 짚어보고, 못 짚으면 질문을 바꾸거나 그 내용을 노트에 넣는다.

셋을 서로 다른 데서 가져온다. 한 문단만 읽어도 셋 다 맞힐 수 있으면 확인이 안 된다.

```
1. google.com 을 두 번째로 열면 왜 더 빠른가?          → 층 도해
2. 서버 IP 를 바꿨는데 30분간 옛 서버로 가는 사람이 있다. 왜? → 주의사항
3. DNS 가 IP 를 돌려준 다음에는 무슨 일이 일어나나?      → 흐름 도해 마지막 마디
```

- "DNS 란 무엇인가?" 같은 정의 되묻기는 쓰지 않는다. 외웠는지만 확인될 뿐이다.
- **상황을 주고 묻는다.** 이해한 사람만 답할 수 있는 건 대개 "왜 이런 일이 벌어지나" 다.

### 🔗 관련 용어

3~5개. `- [[단어]] — 이 단어와 무슨 관계인지` 형식.
관계를 반드시 쓴다. 이름만 나열하면 왜 걸려 있는지 알 수 없다.

## 도해 문법

` ```도해 ` 로 시작하는 블록. Obsidian 에서는 평문으로 보이고, 앱에서는 그림이 된다.

**모양은 셋뿐이다.** 넷째가 필요해 보이면 그건 대개 글로 써야 할 내용이다.

| 모양 | 언제 | 들어갈 섹션 |
|---|---|---|
| `흐름` | 순서대로 일어나는 일 | 🖼️ 그림으로 보기, ⚙️ 작동 원리 |
| `대조` | 있고 없고의 차이, A 와 B | ⚠️ 해결하는 문제, 📊 비교 |
| `층` | 시간 순서가 아닌 겹겹의 구조 | ⚙️ 작동 원리 |

### 표기는 다섯 개

```
모양: 이 그림이 답하는 질문       ← 첫 줄. 반드시 물음이어야 한다
이름 :: 하는 일                   ← 마디 하나
< 이름 :: 하는 일                 ← 돌아오는 구간 (흐름에서만)
이름 :: 왼쪽 || 오른쪽            ← 두 칸 (대조에서만)
= 한 줄로 남길 말                 ← 그림의 결론 (선택이지만 되도록 쓴다)
```

### 흐름

```도해
흐름: 주소창에 google.com 을 치면 무슨 일이 일어나나
브라우저 :: 캐시에 있나? 있으면 여기서 끝난다
로컬 DNS :: 없으면 ISP 나 `8.8.8.8` 에 묻는다
루트 서버 :: ".com 담당은 저쪽이야"
.com 서버 :: "google.com 담당은 저쪽이야"
권한 서버 :: "142.250.196.78 이야"
< 브라우저 :: 받은 IP 로 접속. TTL 동안 캐시에 둔다
= 다섯 번을 물어 찾아가는 길이지만, 열에 아홉은 첫 줄에서 끝난다
```

- 마디 **4~7개**. 여덟을 넘으면 한눈에 안 들어온다. 넘치면 묶어라.
- `이름` 은 **8자 이내**. 누가/어디가 하는 일인지.
- `하는 일` 은 **한 줄, 30자 안팎**. 두 줄까지는 괜찮고 세 줄이면 길다.
- `<` 는 응답이 돌아오는 구간에만. 처음 나오는 `<` 앞에 "여기서부터 돌아오는 길" 표시가 자동으로 들어간다.

### 대조

```도해
대조: DNS 가 없으면 인터넷은 어떻게 되나
DNS 없이 || DNS 로
주소 :: 숫자 12자리를 왼다 || 이름만 기억한다
서버 이전 :: 접속 경로가 끊긴다 || 레코드만 고치면 된다
장애 :: 그 서버가 죽으면 끝 || 다른 IP 로 즉시 돌린다
= 사람은 이름을, 기계는 숫자를 쓴다. DNS 는 그 사이의 번역기다
```

- **둘째 줄은 칸 이름**이다. `::` 없이 `||` 만 쓴다. 왼쪽이 ✕, 오른쪽이 ✓ 로 나온다.
- 줄은 **3~4개**. 왼쪽과 오른쪽은 반드시 **같은 것을 놓고** 비교한다.
- 한 칸은 **14자 이내**. 390px 화면에서 두 칸이 나란히 서기 때문에 길면 세로로 무너진다.
- 나쁜 쪽을 왼쪽에 둔다. 좌우가 뒤집히면 색과 기호가 거꾸로 붙는다.

### 층

```도해
층: 같은 주소를 두 번째로 열면 왜 빠른가
브라우저 :: 탭을 닫기 전까지. 수십 초
운영체제 :: hosts 파일과 OS 캐시. 수 분
로컬 DNS :: TTL 이 정한 만큼. 보통 5분에서 1시간
권한 서버 :: 원본. 여기까지 오는 요청은 드물다
= 위에서 끝날수록 빠르다. TTL 은 "얼마나 위에 머물까"를 정하는 값이다
```

- 층은 **3~5개**. 위에서 아래로 갈수록 배경이 짙어진다 — 위가 가깝고 아래가 멀다.
- 순서에 뜻이 있어야 한다. 그냥 목록이면 그건 그림이 아니라 불릿이다.

### 도해에서 하지 말 것

- **mermaid 를 쓰지 않는다.** 지금 vault 노트 248편 중 183편이 mermaid 를 쓰고 있는데,
  `graph` 는 가로로 넓어져서 390px 화면에서는 읽을 수 없고, 앱은 그걸 코드블록으로밖에 못 보여준다.
  도해는 세로 한 폭에서 끝나도록 설계했다.
- **ASCII 아트를 그리지 않는다.** `┌──┐` 같은 선은 고정폭 폰트가 아니면 어긋난다.
  한글은 고정폭 글리프가 없어서 반드시 어긋난다.
- **그림에 새 정보를 넣지 않는다.** 그림은 본문에 있는 것을 형태로 보여주는 것이다.
  그림에만 있는 사실이 생기면 그림을 못 읽는 사람은 그걸 영영 모른다.
- **이모지를 뜻으로 쓰지 않는다.** ✕ / ✓ 는 앱이 붙인다. 원문에 🔴🟢 를 넣으면 두 번 말하게 된다.

- [ ] 필수 섹션 8개가 다 있다 — 정의 / 그림 / 해결하는 문제 / 실제 사례 / 흔한 오해 / 정리 / 이해했는지 / 관련 용어
- [ ] 정의 안에 `### 비유` 가 있다

- [ ] 도해 마디가 7개를 넘지 않는다
- [ ] 대조의 한 칸이 14자를 넘지 않는다
- [ ] 관련 용어에 관계 설명이 붙어 있다
- [ ] 빈 섹션이 없다

## 앱에 반영하려면 (승인 후)

이 템플릿은 아직 앱에 연결되어 있지 않다. 목업에서만 동작한다. 붙이려면:

1. `tools/obsidian_adapter.py` 의 `SECTION_MAP` 에 세 줄 추가
   — `("figure", ["🖼️ 그림으로 보기"])`, `("myth", ["🚫 흔한 오해"])`, `("check", ["❓ 이해했는지"])`
2. 같은 파일에서 `figure` 와 `check` 는 `DISCLOSURE_ORDER` 에 **넣지 않는다** — 접히면 안 되는 자리다.
   `myth` 는 넣는다 (`example` 다음, `caution` 앞)
3. `MAX_SECTIONS = 5` 를 다시 본다. 흔한 오해가 들어오면서 접이식이 하나 늘었다
4. `mockups/dohae.js` 를 `js/ui.js` 의 `takeFence()` 안으로 옮긴다 (`lang === "도해"` 분기)
5. `mockups/dohae.css` 와 `mockups/mockup.css` 의 `.analogy` / `.figure-slot` /
   `.myth` / `.selfcheck` 를 `css/app.css` 로 옮긴다
6. 확인 질문을 `js/recall.js` 의 회상 단계에 연결한다 — 지금 회상은 단어만 보여주는데,
   저자가 쓴 질문이 있으면 그걸 물어보는 게 낫다
