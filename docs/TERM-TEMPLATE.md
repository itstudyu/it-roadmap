# 단어 노트 템플릿

새 단어를 `content/` 에 추가할 때 AI 가 따르는 형식이다.
vault 에서 들여온 노트에서 실제로 반복되는 구조를 추린 것이고, 여기에
**읽고 나서도 남는 구멍**을 막는 자리를 넣었다 — 그림, 흔한 오해, 이해 확인.

> ## 이 템플릿이 재는 것 하나
>
> **읽고 나면 IT 를 전혀 모르는 사람(열 살 아이)에게 제 입으로 설명할 수 있어야 한다.**
>
> 이해의 기준이 "알아본다" 가 아니라 "가르칠 수 있다" 다. 아래 모든 규칙이 이
> 문장에서 나온다. 새 자리를 더할지 말지도 "이게 재설명 능력을 올리나" 로 정한다.
> `## 🧒 열 살에게` 의 모범 답이 IT 낱말 0개인 것이 그 기준을 기계로 잰 것이다.

> **`content/` 의 단어 327개가 모두 이 형식을 지킨다.**
> `python3 tools/check_template.py content/` 가 전부를 통과시킨다. 새로 쓰는 단어도
> 같은 형식을 따르고, 어기면 검사기가 어디가 틀렸는지 말해준다.
> 검사기는 두 단계로 말한다 — **실패(✕)** 는 고쳐야 하고, **경고(△)** 는 판단을 묻는다.
> `--strict` 를 붙이면 경고도 실패로 센다. 전수 점검할 때 쓴다.

## 왜 그림을 넣었나

노트는 잘 쓰여 있는데 **읽어야만 알 수 있다.** 모바일에서 개념 하나를 이해하려면
문단 서너 개를 스크롤해야 하고, 그러다 보면 결국 안 읽는다.

그림 한 장이 하는 일은 요약이 아니라 **형태 인식**이다.
"DNS 는 다섯 군데를 거쳐 갔다가 돌아오는 길"이라는 걸 글로 읽으면 20초, 그림으로 보면 2초다.
그 2초가 나머지를 읽을지 말지를 정한다.

그래서 그림은 **접지 않는다.** 표제어 바로 아래, 정의 다음에 펼친 채로 둔다.

그림은 두 가지다. **장면 컷 만화**는 한 줄 뜻 바로 밑에서 그 단어가 하는 *일*을
세 컷으로 말하고, **도해**는 그 아래에서 개념의 *형태*를 말한다. 앞의 것은 원문
밖 그림 서랍(`scenes/`)에 살고, 뒤의 것은 원문 안 ` ```도해 ` 블록에 산다.

## 골격

```
# 단어 (원어)                        ← 필수

## 📝 정의                            ← 필수
  (첫 문단 = 한 줄 요약. 굵은 글씨로 화면 맨 위에 올라간다)
  (둘째 문단 = 배경. 없으면 생략)
  ### 이름                            ← H1 괄호에 영어 이름이 있으면 필수
  ### 비유                            ← 필수
  ### 예                              ← 필수
  ### 직접                            ← 선택

## 🖼️ 그림으로 보기                   ← 필수 · 접히지 않는다
  ```도해 ... ```

## ⚠️ 해결하는 문제                    ← 필수 · 접히지 않는다
## 🧱 구성                            ← 선택 · 접히지 않는다
## ⚙️ 작동 원리                        ← 선택
## 📊 비교                             ← 선택
## ✅ 장단점                           ← 선택
## 💡 실제 사례                        ← 필수
## 🚫 흔한 오해                        ← 필수
## 🚨 주의사항                         ← 선택
## 📝 정리                             ← 필수 · 접히지 않는다
## 🧒 열 살에게                        ← 필수 · 접히지 않는다
## ❓ 이해했는지                        ← 필수 · 접히지 않는다
## 🔗 관련 용어                        ← 필수
```

제목의 이모지까지 **글자 그대로** 쓴다. 앱이 이 문자열로 섹션을 찾는다.
`## 🖼️ 그림으로 보기` 를 `## 🖼 그림` 으로 바꾸면 그림 자리를 못 찾는다.

콜론을 붙여 부제를 다는 건 된다 — `## 📊 비교: DNS vs 유사 기술`.
무엇을 비교하는지 제목에서 알려주는 편이 낫다. 콜론 **앞부분**만 정확하면 된다.

필수 8개는 어떤 단어에도 쓸 수 있는 것들만 골랐다.
선택 5개는 그 단어에 정말 할 말이 있을 때만 쓴다. **빈 섹션을 만들지 않는다.**

### 이해의 네 기둥은 접지 않는다

읽는 사람이 단어 하나에 던지는 물음은 넷이다. 넷 다 첫 화면에 답이 있어야 한다.

| 물음 | 답하는 자리 |
|---|---|
| 무엇인가 | 📝 정의 (한 줄 뜻 · 비유 · 예) |
| 어떻게 되나 | 🖼️ 그림으로 보기 |
| 왜 필요한가 | ⚠️ 해결하는 문제 |
| 무엇으로 되어 있나 | 🧱 구성 (부품이 있는 단어만) |

넷은 접히지 않고 이 순서로 그려진다. **접힌 것은 대체로 안 열린다 —
열어야 보이는 기둥은 없는 기둥이다.** 2026-08-18 이전에는 해결하는 문제와
구성이 접이식 안에 있었고, 그래서 첫 화면에 기둥이 절반만 서 있었다.

접이식에 남는 것은 전부 심화다 — 작동 원리 · 비교 · 장단점 · 사례 · 오해 · 주의.
그래서 이제 접이식은 **전부 닫힌 채로 시작한다.** 하나만 열어두면 그 칸이
특별해 보이는데, 실은 다 대등한 심화다.

### 화면에 그려지는 순서

원문의 절 순서와 화면 순서는 다르다. 화면은 **물음의 순서**를 따라간다.

```
한 줄 뜻 → 장면 컷 만화 → 이름 → 비유 → 예 → 직접 → 배경 문단
        → 그림(도해) → 왜 필요한가 → 무엇으로 되어 있나
        → [접힌 심화 칸들] → 이 말을 만나면 → 이해했는지 → 열 살에게
```

정의 · 그림 · 해결하는 문제 · 구성 · 정리 · 이해했는지 · 열 살에게가 펼쳐진다.
장면으로 들어와서 열 살에게로 나간다. 그 사이가 설명이다.

정리가 여기 있는 이유는 한 번 데었기 때문이다. 접이식은 여섯 칸이 상한인데
정리는 순서상 맨 뒤라, 229편 중 199편에서 통째로 잘려 나가고 있었다.
필수라고 적어놓은 항목이 화면에 아예 닿지 못한 것이다. 정리는 카드가 아니라
마무리 문단 하나이고, 되짚고 나서 스스로 물어보는 순서로 확인 질문과 짝을 이룬다.
접이식에 두고 자리를 다투게 할 것이 아니었다.

### 접이식은 여섯 칸까지다

펼쳐두는 여섯 자리와 관련 용어를 뺀 나머지가 접이식으로 간다.
일곱 번째부터는 **화면에 닿지 못하고 그대로 사라진다.** 검사기가 실패로 잡고,
`build.py` 도 무엇이 잘렸는지 stderr 로 말해준다.

접이식 후보는 여섯이다 — 작동 원리 · 비교 · 장단점 · 실제 사례 · 흔한 오해 ·
주의사항. 다 써도 딱 맞지만, **선택 섹션을 다 쓰지 마라.** 여섯 칸이 꽉 찬
화면은 자기만의 제목을 쓴 절이 하나만 생겨도 넘친다. 이 단어에 정말 할 말이
있는 둘셋만 고른다.

### 필수 섹션이 각각 막는 구멍

| 섹션 | 안 쓰면 생기는 일 |
|---|---|
| 📝 정의 | 무슨 말인지 모른다 |
| 🖼️ 그림 | 읽어야만 알 수 있다 — 대개 안 읽는다 |
| ⚠️ 해결하는 문제 | 왜 있는지 모르니 기억에 안 남는다 |
| 💡 실제 사례 | 아는 것과 쓰는 것이 안 이어진다 |
| 🚫 흔한 오해 | **틀린 그림을 그대로 갖고 나간다** |
| 📝 정리 | 읽고 나서 손에 남는 게 없다 |
| 🧒 열 살에게 | 알아본 것을 아는 것으로 착각한다 |
| ❓ 이해했는지 | 이해한 줄 알고 넘어간다 |
| 🔗 관련 용어 | 단어가 섬으로 남는다 |

## 섹션별로 지킬 것

### 📝 정의

첫 문단은 **한 문장, 60자 이내**. 화면에서 표제어 바로 밑에 큰 글씨로 올라가는 자리라
길면 그대로 벽이 된다. 형태는 `X 는 ~하는 Y 다`.

핵심어 하나만 `**굵게**` 한다. 굵은 게 셋이면 아무것도 안 굵은 것과 같다.

둘째 문단은 배경이나 유래. 정말 도움이 될 때만 쓰고 아니면 생략한다.

이름을 푸는 일은 아래 `### 이름` 이 맡는다. 배경 문단에서 또 풀지 않는다.

### ### 이름

**H1 괄호 안에 영어 이름이 있으면 필수.** 없으면 생략한다(표제어가 영어이고
풀면 배울 게 있으면 넣어도 된다).

영어 이름을 낱말로 쪼개 뜻을 달고, 도로 이어 붙인다. 이어 붙인 문장이 그대로
정의가 되는 단어가 많다 — 이름을 풀면 외울 것이 하나 줄어든다.

```
### 이름
Dynamic :: 그때그때
Host :: 망에 붙은 기기
Configuration :: 설정
Protocol :: 약속
= 붙여 읽으면 "기기 설정을 그때그때 잡아 주는 약속". 이름이 곧 하는 일이다
```

- `낱말 :: 뜻` 여러 줄 + `= …` **정확히 한 줄**. 그 밖의 줄은 넣지 않는다.
- 뜻은 **14자 이내**, 사전 뜻이 아니라 **이 문맥에서의 뜻**을 쓴다.
- 한 낱말 이름(Docker · Kafka)은 `::` 없이 `= 유래 한 줄` 만도 된다.
- 화면에서는 낱말마다 칩이 되어 가로로 늘어서고, `=` 줄이 그 밑에 붙는다.

```
✓ Transmission :: 보내기 / Control :: 통제 / Protocol :: 약속
  = 붙여 읽으면 "보내는 일을 통제하는 약속"
✗ Application :: 응용 프로그램 / Programming :: 프로그래밍 / Interface :: 인터페이스
  ← 풀어 써도 아무것도 안 알려준다. 이런 이름은 쪼개지 말고 `=` 한 줄로 유래만 쓴다.
```

### ### 비유

**한 문장.** 일상 사물 하나에 빗댄다. IT 용어로 IT 용어를 설명하지 않는다.

```
✓ 전화번호부. 친구 이름을 대면 번호를 알려주고, 번호가 바뀌어도 이름은 그대로다.
✗ 서비스 디스커버리와 유사한 이름 해석 계층이다.
```

### ### 예

**한두 문장, 90자 안쪽.** 비유 바로 다음에 온다.

비유가 "무엇과 닮았나"(가상의 사물)를 주면, 예는 "어디서 봤나"(이미 겪은
장면)를 준다. **둘이 같은 일을 하면 예가 있을 이유가 없다.**

읽는 사람이 화면에서 본 것, 손으로 한 것, 겪어서 짜증났던 것 하나를 든다.
정의를 되풀이하지 않는다.

```
✓ 주소창의 자물쇠가 곧 HTTPS다. 오늘 여는 사이트 열에 아홉이 이걸로 연결된다.
✓ 결제 창이 한참 돌다가 "잠시 후 다시 시도해 주세요" 로 끝나는 그 순간이다.
✗ 많은 기업에서 널리 쓰인다.                    ← 장면이 없다
✗ HTTPS는 HTTP에 보안을 더한 것이다.            ← 정의 되풀이
✗ 카카오톡도 Kubernetes 를 쓴다.                ← 확인 못 하는 사실 주장
```

💡 실제 사례와 다른 자리다. 저건 접힌 칸의 사례 셋이고, 이건 첫 30초에
"아, 그거" 가 나오게 하는 한 줄이다. 사례 셋 중 가장 흔한 하나를 줄여 써도 된다.

굵게·링크·코드·목록을 쓰지 않는다. 평문 문장만.

비유는 화면에서 **정의 바로 다음, 배경 문단보다 앞에** 놓인다.
한 문장·일상 사물 규칙을 지키면 배경을 안 읽어도 통한다.

### ### 직접

**선택.** 지금 이 폰이나 컴퓨터로 **실제로 해 볼 수 있는 것**이 있을 때만.
한두 문장, 120자 이내. 예 절 바로 다음에 온다.

비유가 "무엇과 닮았나", 예가 "어디서 봤나" 를 주면 직접은 "지금 어떻게 보나" 를
준다. 직접 눈으로 본 것은 장면이 되어 남는다.

```
✓ 주소창의 자물쇠를 눌러 보라. 지금 이 연결이 어떤 증명서로 잠겨 있는지 볼 수 있다.
✓ 폰의 와이파이 상세 설정에 적힌 "DNS" 주소를 한번 보라.
✗ 서버에 접속해 nslookup 을 실행한다.        ← 준비가 필요하다
✗ 계정을 만들고 결제 정보를 넣는다.           ← 시켜서는 안 되는 일이다
```

**없으면 넣지 않는다.** 억지로 만든 "직접" 은 없느니만 못하다.

### 🖼️ 그림으로 보기

도해 블록 하나. 아래 문법 절을 따른다. **글은 쓰지 않는다** — 그림만 둔다.

**세 모양을 다 쓸 수 있다.** 흐름이 기본값이 아니다.
이 자리에는 **개념의 형태**를 담는다. 개념을 고르거나 확인하는 **절차**는 개념이 아니다 —
그건 ⚙️ 작동 원리로 보낸다.

> **판정법: 그림만 보고 정의 첫 문장을 복원할 수 있는가.**
> 못 하면 그 그림은 대표 그림이 아니다.

```
✗ 흐름: 어떤 자료구조를 골라야 하나        ← 고르는 절차다. 자료구조가 뭔지는 안 말한다
✓ 대조: 배열과 연결 리스트는 무엇이 다른가  ← 형태가 보인다
```

### ⚠️ 해결하는 문제

`대조` 도해 하나 + 문단 1~2개.
"이게 없으면 무슨 일이 벌어지나"를 먼저 쓰고, 그다음에 이 단어가 그걸 어떻게 없애는지 쓴다.

접히지 않는다. 정의·그림과 함께 첫 화면에 그려진다.

### 🧱 구성

**선택이다. 부품이 있는 단어에만 쓴다.** 접히지 않으므로 여기 쓴 것은
반드시 읽히고, 그래서 채울 것이 없으면 그 자리를 만들지 않는 편이 낫다.

`층` 도해 하나. 다른 것을 넣지 않는다.

넣는 조건 셋을 **모두** 만족해야 한다.

1. 그 단어가 여러 부품으로 이루어져 있고, 부품을 세는 것이 이해에 실제로 도움이 된다
2. 부품이 3~5개로 깔끔하게 떨어진다
3. 그 목록이 `🖼️ 그림으로 보기` 의 도해와 다르다 — 같은 그림을 두 번 그리지 않는다

**애매하면 쓰지 않는다.** 개념·원칙·현상·행위를 가리키는 단어(확장성, 기술 부채,
정규화, 애자일…)는 대체로 해당 없다. 프로토콜·시스템·형식·구조·도구처럼
**부품이 있는 것**만 해당한다. 327편 중 이 자리를 쓰는 편은 소수다.

```도해
층: HTTPS 는 무엇을 무엇으로 감싼 것인가
HTTP :: 주고받는 내용. 요청과 응답의 양식
TLS :: 그 내용을 암호화하는 보안 계층
TCP :: 암호문을 실어 나르는 연결
IP :: 목적지 컴퓨터까지 찾아가는 주소 체계
= HTTPS 라는 새 프로토콜이 따로 있는 게 아니다. HTTP 와 TCP 사이에 TLS 가 한 겹 낀 것이다
```

**층 도해가 이미 `⚙️ 작동 원리` 안에 있고 그것이 "무엇으로 되어 있나" 에
답한다면, 여기로 옮겨라.** 작동 원리는 접히는 칸이라 거기 있는 그림은
대개 안 읽힌다. 옮길 때 도해의 글자는 그대로 두고, 옮긴 뒤 작동 원리에
산문이 한 문단은 남아야 한다(빈 칸이 되면 확인 질문의 `→ 작동 원리` 가
아무 데도 못 간다).

아래 "층 반증 테스트" 를 그대로 적용한다. 시간 순서는 층이 아니다.

### 💡 실제 사례

목록 3개. 각 항목은 **`- **상황** — 무슨 일이 일어나는지`** 한 줄.
`— ` 를 빠뜨리지 마라. 라벨과 설명이 붙어버리면 화면에서 한 덩어리로 읽힌다.

```
✓ - **무중단 배포** — 새 서버를 띄우고 DNS 레코드만 바꿔 끼운다.
✗ - **무중단 배포** 새 서버를 띄우고 DNS 레코드만 바꿔 끼운다.
```

회사 이름을 지어내지 않는다. 일반적인 상황으로 쓴다.

### 🚫 흔한 오해

**여기가 이 템플릿에서 가장 어려운 자리다.** 그리고 가장 중요한 자리다.

반쯤 이해한 사람이 막히는 건 정보가 없어서가 아니라 **틀린 그림을 갖고 있어서**다.
맞는 말을 열 번 더 해도 그 그림은 안 지워진다. 틀렸다고 **이름을 불러줘야** 지워진다.

목록 2~3개. 형식은 `- **틀리게 아는 말** — 실제로는 이렇다`.

```
✓ - **DNS 가 사이트에 연결해준다** — 아니다. IP 주소를 알려주고 거기서 끝난다.
✗ - **DNS 는 중요하다** — 맞다. 인터넷의 핵심 인프라다.
```

- 앞부분은 **사람이 실제로 하는 말** 그대로 쓴다. 교과서 문장이 아니라 입말로.
- 초보자가 진짜 헷갈리는 것을 쓴다. 전문가끼리 다투는 미묘한 구분이 아니라.
- **순서를 뒤집지 않는다.** 맞는 말을 먼저 하면, 읽는 사람은 자기가 뭘 잘못 알고 있었는지
  모르고 지나간다.

어떻게 찾나 — 이 단어를 처음 듣는 사람이 이름만 보고 **넘겨짚을 만한 것**을 쓴다.
"DNS(Domain **Name** System)" 라는 이름만 보면 이름을 다루는 것까지는 맞히지만,
거기서 연결까지 해준다고 넘겨짚기 쉽다. 그 지점이 오해다.

**대안이 있는 기술이면 오해 하나는 "과잉 적용"을 겨눈다.**
`X 가 항상 낫다` 꼴이다. 새 기술을 배운 사람이 가장 먼저 갖는 틀린 그림이고,
✅ 장단점을 아무리 정직하게 써도 그 칸은 접혀 있다.

```
✓ - **MSA 가 모놀리스보다 낫다** — 팀이 하나면 배포만 열 배 어려워진다.
```

접힌 상태에서는 **틀린 문장 앞부분만** ✕ 표와 함께 미리 보인다.
정정문은 열어야 나온다. 그래서 틀린 말 쪽을 짧고 또렷하게 써야 한다.

### 📝 정리

**3문장 이내.** 화면에서는 제목이 **"이 말을 만나면"** 이다. 요약이 아니라
**다음에 이 말을 만났을 때 할 생각**을 준다.

첫 문장은 반드시 이 꼴이다:

```
**"주소를 기한 걸어 빌려주는 그 약속"** 이라고 읽으면 된다.
```

- 받침이 있으면 `이라고`, 없으면 `라고`.
- 큰따옴표 안은 **머릿속에 떠올릴 한 마디**다. 정의의 압축이 아니라 "아, 그 ~구나".
- 뒤 문장들은 기억할 것 한둘을 못 박는다. 절 전체가 3문장을 넘지 않는다.

### 🧒 열 살에게

**전편 필수.** 정리 바로 뒤, 확인 질문 바로 앞.

이 템플릿이 재는 것 하나가 여기 있다 — 읽고 나면 IT 를 모르는 사람에게 제
입으로 설명할 수 있어야 한다. 화면에서는 모범 답을 바로 보여주지 않는다.
**"해 봤다"** 를 누른 뒤에 열린다. 남을 가르칠 준비가 배움을 가장 깊게 만들고,
답을 보기 전에 스스로 만들어 보는 인출이 기억을 굳히기 때문이다.

```
## 🧒 열 살에게

카페에 가면 직원이 빈자리를 골라서 앉혀 주지? 와이파이도 똑같아. 새 폰이
들어오면 빈 번호표를 하나 빌려주고, 그 폰이 나가면 번호표를 걷어서 다음 폰한테 줘.
```

- **1~3문장, 30자 이상.** 목록이 아니라 이어지는 문장으로.
- 아이에게 말 걸듯. `~지?` `~해` `~야`.
- **IT 낱말 0개.** 검사기가 금지어 목록과 영문 두 글자 이상을 잡는다
  (`tools/check_template.py` 의 `KID_BANNED`). 표제어 자체도 쓰지 않는다.
- **그 편의 `### 비유` 세계를 그대로 쓴다.** 새 비유를 발명하지 않는다.
- **정의를 쉬운 말로 옮겨 적은 것은 실패다.** 그 개념 때문에 **일어나는 일**을 말한다.

```
✓ 친구 이름은 외워도 전화번호는 잘 안 외우지? 그래서 이름을 대면 번호를 찾아
  주는 커다란 번호부가 있어. 네가 이름을 치면 그 번호부가 먼저 번호를 찾아 줘.
✗ DNS 는 도메인 이름을 IP 주소로 바꿔 주는 시스템이야.   ← 낱말도 그대로, 정의 옮겨 적기
✗ 이름을 주소로 바꿔 주는 거야.                          ← 일어나는 일이 없다
```

### ❓ 이해했는지

질문 3개. 화면 맨 아래에 펼쳐진 채로 놓이고, "학습 완료" 버튼 바로 위에 온다.

형식은 **`- 질문 → 답이 있는 자리`** 다. 화살표 뒤가 필수다.

```
- google.com 을 두 번째로 열면 왜 더 빠른가 → 작동 원리
- 서버 IP 를 바꿨는데 30분간 옛 서버로 가는 사람이 있다. 왜 → 주의사항
- DNS 가 IP 를 돌려준 다음에는 무슨 일이 일어나나 → 그림
```

화살표 뒤에는 **이 노트에 실제로 있는 섹션 이름**을 쓴다. 이모지는 빼도 되고 붙여도 된다.
그림 도해를 가리킬 때는 `그림` 이라고 쓴다. 검사기가 대상이 실재하는지 확인한다.

화면에서는 질문마다 **"답이 있는 자리 →"** 단추가 붙는다. 누르면 그 칸이 열리고
제목이 잠깐 물들면서 거기로 데려간다.

> **철칙: 답이 반드시 이 노트 안에 있어야 한다.**
> 화살표를 못 달겠으면 답이 노트에 없다는 뜻이다. 질문을 바꾸거나 그 내용을 노트에 넣는다.
> 밖에서 찾아야 하는 질문은 시험이지 확인이 아니다.

- 셋을 서로 다른 데서 가져온다. 한 문단만 읽어도 셋 다 맞힐 수 있으면 확인이 안 된다.
- "DNS 란 무엇인가?" 같은 정의 되묻기는 쓰지 않는다. 외웠는지만 확인될 뿐이다.
- **상황을 주고 묻는다.** 이해한 사람만 답할 수 있는 건 대개 "왜 이런 일이 벌어지나" 다.

### 🔗 관련 용어

3~5개. `- [[단어]] — 이 단어와 무슨 관계인지` 형식.
관계를 반드시 쓴다. 이름만 나열하면 왜 걸려 있는지 알 수 없다.

### 노트 밖 용어를 처음 쓸 때

독자가 이 노트 밖에서 배워야 하는 말이 나오면 둘 중 하나를 한다.

1. **반 구절로 푼다** — `벡터(뜻을 담은 숫자 목록)로 바꿔 저장한다`
2. **`[[링크]]` 를 걸고 🔗 관련 용어에 올린다**

본문의 `[[링크]]` 는 화면에서 **누를 수 있는 단추**가 된다(↗ 표가 붙는다).
단어장에 없는 이름이면 눌러도 안내만 나오고 페이지는 그대로다.

도해 마디 이름은 특히 조심한다. `옵티마이저 :: 실행 계획을 고른다` 에서
옵티마이저를 모르면 그 마디는 빈칸이다. 검사기가 다른 노트 제목과 겹치는데
관련 용어에 없으면 경고한다.

## 장면 컷 만화 — 그림 서랍

한 줄 뜻 바로 밑에 서는 **세로 컷 만화**다. 도해가 개념의 *형태*를 그린다면
장면은 그 단어가 하는 *일*을 그린다. 글을 읽기 전에 그림만 보고도 "아, 이런
일을 하는 거구나" 가 되는 것이 목표다.

**장면은 원문 Markdown 밖에 산다.** `content/*.md` 는 그림 때문에 한 글자도
바뀌지 않는다 — 단어 id 로만 이어져 있다.

```
scenes/<권id>.json      각본(사람이 쓴다).  단어id -> 컷 목록
        ↓ tools/build_scenes.py
data/scenes/<권id>.js   그림(조립기가 굽는다). 단어id -> SVG
```

각본만 쓰고 SVG 는 그리지 않는다. 조립은 `tools/scenes/render.py` 가 부품
라이브러리(`tools/scenes/parts.py`)로 한다. **자유 드로잉이 없어야 327편이 같은
세계에 산다.**

### 컷 문법

딥리서치(Cohn 의 시각 서사 문법, McCloud 의 컷 사이 닫힘, 글 없는 조립
설명서 연구, Mayer 의 신호 원리, わわわ·학습만화·IKEA 사례)로 뽑아
블라인드 테스트 두 번으로 다듬었다. 한 순간 프레임은 인과를 전달하지 못한다.

1. **세로로 쌓은 컷. 문제 → 동작 → 결과 세 컷.** 왕복이 본질인 것만 네 컷.
2. **같은 배우는 매 컷 같은 자리.** 자리가 흔들리면 같은 배우로 안 읽힌다.
3. **화살표는 전부 회색 점선.** 파랑은 이동이 아니라 **옮겨지는 사물**의 색이다.
4. **파랑은 컷당 한 군데.** 파랑만 눈으로 따라가도 이야기가 되어야 한다.
   마지막 컷만 사물과 마침 체크 둘을 허용한다.
5. **얼굴은 그 컷에서 행동하는 쪽에만.** 표정이 상태를 말한다. 구경꾼은 일자 입.
6. **글자는 아껴 쓴다.** 캡션 10자 · 말풍선 8자 · 이름표 12자 · 한 편 48자.
7. **정의에 없는 것은 그리지 않는다.** 배경 소품도 없다.

### 각본 한 편

```json
{
  "net--dhcp": {
    "alt": "세 컷 — 주소가 없던 폰이 공유기에게 주소를 빌려 그 주소로 통신하게 되는 이야기",
    "cuts": [
      {"caption": "주소가 없다",
       "actors": [{"part": "폰", "slot": "left", "face": "sad",
                   "tag": {"text": "?", "tone": "blue-dash"}},
                  {"part": "공유기", "slot": "right", "face": "flat"}]},
      {"caption": "공유기가 빌려준다",
       "actors": [{"part": "폰", "slot": "left", "face": "flat"},
                  {"part": "공유기", "slot": "right", "face": "happy"}],
       "move": {"from": "right", "to": "left",
                "payload": {"text": "192.168.0.7", "tone": "blue"}},
       "bubble": {"slot": "right", "text": "이거 써!"}},
      {"caption": "그 주소로 통신한다",
       "actors": [{"part": "폰", "slot": "left", "face": "happy",
                   "tag": {"text": "…0.7", "tone": "plain"}},
                  {"part": "공유기", "slot": "right", "face": "flat"}]}
    ]
  }
}
```

자리는 `left` · `mid` · `right` 셋. 얼굴은 `happy` · `sad` · `flat` · `none`.
색조는 `blue`(이야기의 사물) · `blue-dash`(아직 없는 것) · `plain`(이미 있는 것).
부품은 폰 · 공유기 · 컴퓨터 · 서버 · 사람 · 구름 · 저장통 · 자물쇠 · 열쇠 ·
문서 · 벽 · 문 · 지구 · 시계 · 돋보기 · 표지판 · 장부 · 소포.
**부품이 모자라면 만들지 말고 늘려 달라고 한다** — 부품은 한 손이 그린다.

### 검사

```bash
python3 tools/scenes/lint_scenes.py       # 컷 수 · 글자 수 · 파랑 개수 · 배우 자리
python3 tools/build_scenes.py             # 각본 -> SVG
```

### 각본을 쓰지 않아도 되는 때

억지로 그린 그림은 없느니만 못하다. 옮겨지는 것이 없는 성질·기준뿐인 개념,
세 컷으로 자르면 정의가 틀려지는 개념은 **건너뛰고 사유를 남긴다.**
건너뛰는 것은 실패가 아니라 판단이다.

## 도해 문법

` ```도해 ` 로 시작하는 블록. Obsidian 에서는 평문으로 보이고, 앱에서는 그림이 된다.

**모양은 셋뿐이다.** 넷째가 필요해 보이면 그건 대개 글로 써야 할 내용이다.

| 모양 | 언제 | 주로 들어갈 섹션 |
|---|---|---|
| `흐름` | 순서대로 일어나는 일, 한 바퀴 도는 일 | 🖼️ 그림으로 보기, ⚙️ 작동 원리 |
| `대조` | 있고 없고의 차이, A 와 B | ⚠️ 해결하는 문제, 📊 비교, 🖼️ 그림으로 보기 |
| `층` | 시간 순서가 **아닌** 겹겹의 구조 | 🧱 구성, 🖼️ 그림으로 보기, ⚙️ 작동 원리 |

섹션은 권고다. 그림 자리에는 세 모양 모두 올 수 있다(위 🖼️ 절 참고).

### 표기는 일곱 개

```
모양: 이 그림이 답하는 질문       ← 첫 줄. 반드시 물음이어야 한다
이름 :: 하는 일                   ← 마디 하나
< 이름 :: 하는 일                 ← 돌아오는 구간 (흐름에서만)
@ 이름 :: 하는 일                 ← 다시 처음으로 (흐름의 마지막 줄에서만)
이름 :: 왼쪽 || 오른쪽            ← 두 칸, 왼쪽이 ✕ (대조에서만)
왼쪽 이름 |=| 오른쪽 이름         ← 두 칸, 우열 없음 (대조의 칸 이름 줄에서만)
= 한 줄로 남길 말                 ← 그림의 결론 (필수. 검사기가 없으면 잡는다)
```

**제목이 물음이 아닌 채로 끝나는 실수가 가장 많다.** 이 노트들을 쓰면서 스무 번 넘게 걸렸다.
`~할 때`, `~하면`, `~하기까지`, `~하는 길`, `~하는 방법` 으로 끝나면 그건 물음이 아니라
상황 설명이다. 뒤에 한 마디를 붙이면 물음이 된다.

```
✗ 대조: 서버를 여러 대로 늘릴 때
✓ 대조: 서버를 여러 대로 늘리면 무엇이 달라지나

✗ 흐름: 커밋 하나가 서버에 올라가기까지
✓ 흐름: 커밋 하나가 서버에 올라가기까지 무엇을 거치나
```

제목이 물음이어야 하는 이유는 **접기 버튼의 미리보기로 이 제목이 그대로 쓰이기 때문**이다.
"컨테이너가 수십 개일 때" 는 열어보기 전에 아무것도 알려주지 않는다.

### 흐름

```도해
흐름: 주소창에 google.com 을 치면 무슨 일이 일어나나
브라우저 :: 캐시에 있나? 있으면 여기서 끝난다
로컬 DNS :: 없으면 ISP 나 `8.8.8.8` 에 묻는다
루트 서버 :: ".com 담당은 저쪽이야"
.com 서버 :: "google.com 담당은 저쪽이야"
권한 서버 :: "142.250.196.78 이야"
< 브라우저 :: 받은 IP 로 접속. TTL 동안 캐시에 둔다
= 다섯 번을 물어 찾아가는 길이지만, 열에 아홉은 첫 줄에서 끝난다
```

- 마디 **4~7개**. 여덟을 넘으면 한눈에 안 들어온다. 넘치면 묶어라.
- `이름` 은 **8자 이내**. 누가/어디가 하는 일인지.
- `하는 일` 은 **한 줄, 30자 안팎**. 두 줄까지는 괜찮고 세 줄이면 길다.

#### `<` 는 오직 "응답이 돌아온다" 일 때만

처음 나오는 `<` 앞에 **"여기서부터 돌아오는 길"** 이라는 문장이 자동으로 새겨진다.
그러니 아무것도 안 돌아오는 자리에 쓰면 그림이 거짓말을 한다.

`<` 를 쓰기 전에 물어라 — **누가 누구에게 답을 주는가.** 대답이 안 나오면 `<` 가 아니다.

| 실제로 벌어지는 일 | 무엇을 쓰나 |
|---|---|
| 요청을 받은 쪽이 응답을 되돌려준다 | `<` |
| 처음으로 돌아가 다시 한다 | `@` |
| 조건을 만족해서 반복을 빠져나온다 | 표기 없는 보통 마디 |
| 여럿이 동시에 받는다 | 마디 **하나로 묶는다** |

병렬은 표기를 만들지 않았다. 마디를 나누면 없는 순서가 생긴다.

```
✗ 구독자A :: 재고를 줄인다
  구독자B :: 배송을 잡는다
  구독자C :: 알림을 보낸다      ← 1·2·3 번호가 붙어 순서가 있는 것처럼 보인다
✓ 구독자들 :: 재고·배송·알림이 같은 소식을 저마다 받는다. 순서도 없고 서로 모른다
```

#### `@` — 한 바퀴 도는 일

IT 개념의 큰 갈래 하나가 "돌고 또 돈다" 인데(이벤트 루프, 에이전트 루프,
Circuit Breaker, Scrum) 직선으로 펴 그리면 그게 순환이라는 사실이 사라진다.

`@` 는 **흐름의 마지막 줄**에만 쓴다. 중간에서 되돌아가는 그림은 세로 한 폭에 안 담긴다.
`@` 줄도 화면에서 한 줄을 차지하므로 **마디 4~7개 안에 함께 센다.** 마디가 일곱이면 `@` 를 못 붙인다.

```도해
흐름: LLM 에이전트는 어떻게 스스로 일을 끝내나
사용자 :: 목표를 말한다
에이전트 :: 무엇을 할지 정한다
도구 :: 검색·계산·파일 읽기를 실제로 한다
에이전트 :: 결과를 보고 목표에 닿았는지 본다
@ 다시 판단으로 :: 닿았으면 답하고, 아니면 한 바퀴 더
= 한 번에 푸는 게 아니라, 될 때까지 도는 것이다
```

화면에서는 마지막 마디에서 왼쪽으로 난간이 내려갔다가 **첫 마디를 가리키며** 되돌아온다.
번호는 붙지 않는다 — 그건 새 단계가 아니라 앞으로 되돌아가는 길이다.

**상태 전이는 층이 아니라 흐름이다.** `닫힘 → 열림 → 반열림 → 닫힘` 을 층으로 그리면
움직이는 것이 정지한 구조로 보인다. `@` 를 쓴 흐름으로 그려라.

### 대조

```도해
대조: DNS 가 없으면 인터넷은 어떻게 되나
DNS 없이 || DNS 로
주소 :: 숫자 12자리를 왼다 || 이름만 기억한다
서버 이전 :: 접속 경로가 끊긴다 || 레코드만 고치면 된다
장애 :: 그 서버가 죽으면 끝 || 다른 IP 로 즉시 돌린다
= 사람은 이름을, 기계는 숫자를 쓴다. DNS 는 그 사이의 번역기다
```

- **둘째 줄은 칸 이름**이다. `::` 없이 `||` 만 쓴다. 왼쪽이 ✕, 오른쪽이 ✓ 로 나온다.
- 줄은 **3~4개**. 왼쪽과 오른쪽은 반드시 **같은 것을 놓고** 비교한다.
- 한 칸은 **14자 이내**. 390px 화면에서 두 칸이 나란히 서기 때문에 길면 세로로 무너진다.
- 나쁜 쪽을 왼쪽에 둔다. 좌우가 뒤집히면 색과 기호가 거꾸로 붙는다.

#### `|=|` — 우열을 안 매기는 대조

```도해
대조: 세션과 JWT 중 무엇을 골라야 하나
세션 방식 |=| JWT 방식
저장 위치 :: 서버가 들고 있다 || 토큰 안에 들어 있다
즉시 로그아웃 :: 지우면 끝난다 || 만료까지 유효하다
서버 늘리기 :: 저장소를 공유해야 || 아무 서버나 받는다
= 로그아웃이 급하면 세션, 서버를 늘릴 참이면 JWT 다
```

칸 이름 줄만 `||` 대신 `|=|` 로 쓴다. 그러면 ✕/✓ 와 빨강·초록이 빠지고
양쪽이 같은 색 ◆ 로 선다.

> **✕ 칸 자기검사.** 왼쪽 칸에 **장점이 한 줄이라도 있으면** 그건 `||` 대조가 아니다.
> `|=|` 로 바꾸거나, 그 줄을 ✅ 장단점으로 옮겨라.

위 예에서 "지우면 끝난다" 는 세션 쪽의 명백한 장점이다. `||` 로 뒀다면
그림이 2초 만에 "세션은 나쁜 것" 이라는 오해를 심는다 — 같은 노트의
🚫 흔한 오해가 지우려는 바로 그 오해를.

`|=|` 를 남용하지도 마라. **"있고 없고" 는 `||` 다.** 캐시 없이 vs 캐시로,
DNS 없이 vs DNS 로 — 여기서 왼쪽은 실제로 나쁜 상태다.

### 층

```도해
층: 같은 주소를 두 번째로 열면 왜 빠른가
브라우저 :: 탭을 닫기 전까지. 수십 초
운영체제 :: hosts 파일과 OS 캐시. 수 분
로컬 DNS :: TTL 이 정한 만큼. 보통 5분에서 1시간
권한 서버 :: 원본. 여기까지 오는 요청은 드물다
= 위에서 끝날수록 빠르다. TTL 은 "얼마나 위에 머물까"를 정하는 값이다
```

- 층은 **3~5개**. 위에서 아래로 갈수록 배경이 짙어진다 — 위가 가깝고 아래가 멀다.
- 순서에 뜻이 있어야 한다. 그냥 목록이면 그건 그림이 아니라 불릿이다.

#### 층 반증 테스트

> **이웃한 두 층을 맞바꿔도 그림이 안 틀리면, 그건 층이 아니다.**

바꿔도 멀쩡하면 순서에 뜻이 없다는 뜻이고, 순서에 뜻이 없으면 층이 아니라 목록이다.
`= ` 줄이 **"이 넷이", "하나같이", "각각"** 같은 집합어로 시작하면 특히 의심하라.

층이 아닌 것으로 판명되면 셋 중 하나로 간다.

| 실제 정체 | 어디로 |
|---|---|
| 진짜 축이 따로 있다 | 그 축으로 다시 세운 층 |
| 두 갈래 비교다 | `대조` |
| 그냥 나열이다 | 본문 불릿으로 되돌린다 |

마디 이름이 `먼저 / 다음 / 그다음 / 이후 / 마지막 / 1단계` 라면 그건 시간이다.
층이 아니라 흐름으로 그려라. 검사기가 경고한다.

### 도해에서 하지 말 것

- **mermaid 를 쓰지 않는다.** 들여오기 전 노트 244편 중 181편이 mermaid 를 쓰고 있었다.
  `graph` 는 가로로 넓어져서 390px 화면에서는 읽을 수 없다. 이전할 때 옮길 수 있는 132개만
  도해로 바꾸고 나머지는 버렸다.
  도해는 세로 한 폭에서 끝나도록 설계했다.
- **ASCII 아트를 그리지 않는다.** `┌──┐` 같은 선은 고정폭 폰트가 아니면 어긋난다.
  한글은 고정폭 글리프가 없어서 반드시 어긋난다.
- **그림에 새 정보를 넣지 않는다.** 그림은 본문에 있는 것을 형태로 보여주는 것이다.
  그림에만 있는 사실이 생기면 그림을 못 읽는 사람은 그걸 영영 모른다.
- **이모지를 뜻으로 쓰지 않는다.** ✕ / ✓ / ◆ 는 앱이 붙인다. 원문에 🔴🟢 를 넣으면 두 번 말하게 된다.

## 숫자 하나를 준다

"빠르다 / 느리다 / 크다" 가 이 단어의 핵심 주장이면, **어림수 앵커 하나**를 넣는다.
정확할 필요는 없다. 자릿수만 맞으면 된다.

```
✓ 캐시에서 읽으면 디스크보다 100배쯤 빠르다.
✓ 128K 토큰이면 책 한 권 분량이다.
✗ 매우 빠른 응답 속도를 제공한다.
```

**절대치보다 비율을 쓴다.** "3ms" 는 하드웨어가 바뀌면 틀려지지만 "100배" 는 오래 간다.
모델 이름이나 제품 버전에 앵커를 걸지 마라 — 가장 먼저 낡는다.

## 쓰고 나서 확인할 것

아래는 눈으로 볼 목록이고, 같은 내용을 검사기가 돌려준다.

```bash
python3 tools/check_template.py content/네트워크/DNS.md
python3 tools/check_template.py --strict content/네트워크/DNS.md   # 경고까지 실패로
```

읽기만 하는 도구다. 노트를 고치지 않는다.

**형식**

- [ ] 필수 섹션 8개가 다 있다 — 정의 / 그림 / 해결하는 문제 / 실제 사례 / 흔한 오해 / 정리 / 이해했는지 / 관련 용어
- [ ] 정의 안에 `### 비유` 와 `### 예` 가 있다
- [ ] `### 예` 가 비유와 다른 일을 한다 — 비유는 닮은 것, 예는 겪은 장면
- [ ] `## 🧱 구성` 을 썼다면 그 안이 `층` 도해이고, 그림 자리의 도해와 다르다
- [ ] 제목 이모지가 위 골격과 **글자 그대로** 같다
- [ ] 접이식으로 갈 섹션이 **여섯 개 이하**다
- [ ] 정의 첫 문단이 한 문장이고 60자 이내다
- [ ] 실제 사례가 `- **상황** — 설명` 이다 (`— ` 를 빠뜨리지 않았다)
- [ ] 관련 용어에 관계 설명이 붙어 있다
- [ ] 빈 섹션이 없다

**도해**

- [ ] 첫 줄이 **물음**이다 ("DNS 구조" 가 아니라 "DNS 는 어떻게 주소를 찾나")
- [ ] 흐름 마디가 7개를 넘지 않는다
- [ ] 대조의 한 칸이 14자를 넘지 않는다
- [ ] `<` 를 쓴 자리에서 **실제로 응답이 돌아온다**
- [ ] 순환이면 `@` 를 마지막 줄에 썼다
- [ ] `||` 대조의 **왼쪽 칸에 장점이 없다** (있으면 `|=|`)
- [ ] 층의 이웃 둘을 맞바꾸면 그림이 틀린다
- [ ] 그림 자리의 도해만 보고 **정의 첫 문장이 복원**된다

**내용**

- [ ] 확인 질문 3개에 `→ 답이 있는 자리` 가 달렸고, 그 답이 **전부 이 노트 안에** 있다
- [ ] 확인 질문이 서로 다른 섹션을 겨눈다
- [ ] 흔한 오해가 **사람이 실제로 하는 말**이다 (교과서 문장이 아니라)
- [ ] 대안이 있는 기술이면 오해 하나가 **과잉 적용**을 겨눈다
- [ ] 노트 밖 용어를 반 구절로 풀었거나 `[[링크]]` + 관련 용어에 올렸다
- [ ] 빠르다/크다가 핵심 주장이면 **어림수 앵커**가 하나 있다
- [ ] 이름이 곧 구조인 단어면 이름을 쪼갰다

## 앱에 연결되어 있다

`content/` 에 이 형식으로 쓰고 `python3 tools/build.py` 를 돌리면 그대로 화면에 나온다.
확인은 목업이 아니라 실제 앱에서 한다.

```bash
python3 tools/check_template.py content/네트워크/DNS.md
python3 tools/build.py
# http://localhost:8000/#/term/net--dns
```

`mockups/term.html` 은 "이 글자들이 저 화면이 된다"를 나란히 보는 용도로 남겨뒀다.
도해 렌더러와 스타일은 앱 것(`js/ui.js`, `css/app.css`)을 그대로 쓴다 — 사본을 두면 갈라진다.

### 파일 이름은 바꾸지 않는다

단어 id 가 `{권}--{제목slug}` 이고, 그게 그 사람의 학습 기록이 저장된 열쇠다.
**H1 제목·파일명·폴더를 바꾸면 그 단어의 진도가 사라진다.** 내용은 고쳐도 이름은 그대로 둔다.
