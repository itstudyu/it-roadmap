# 웹 서비스 전환 + 자동 단어 수집 루틴 설계

작성일: 2026-08-16 · 상태: 승인 대기

목업으로 만든 IT 단어 학습 앱을 (A) 어디서든 열리는 웹앱으로 만들고,
(B) 수백 개 규모를 견디는 데이터 구조로 바꾸고,
(C) 주 3회 스스로 단어를 늘리는 클라우드 루틴을 붙인다.

---

## 배경

현재 상태:

- 순수 정적 사이트. 빌드 스텝도 프레임워크도 없다 (`index.html` + `css/` + `js/` + `data/`)
- 진실의 원천은 Mac 로컬의 Obsidian vault. `tools/obsidian_adapter.py` 가 `data/vocabulary.js` 를 생성한다
- 학습 진도는 `localStorage` 에만 있다
- 저장소는 `itstudyu/it-roadmap` (public), `index.html` 이 저장소 루트에 있다

이번 작업으로 프레임워크를 바꾸지 않는다. React/Angular 전환은 이 목표들 중 어느 것도
해결하지 못하면서 재작성 비용만 발생시킨다.

---

## 확정된 결정

브레인스토밍과 그릴링에서 사용자가 확정한 사항이다. 구현 중 임의로 뒤집지 않는다.

| 항목 | 결정 |

| 호스팅 | Vercel (계정 보유) |
| 오프라인 | 필수. 지하철·기내에서 동작해야 함 |

| 단어 원본 위치 | 저장소 안 (vault 의존은 **별도 세션에서 제거 예정**) |
| 원본 파일 형식 | **미정** — vault 제거 세션에서 결정 |

| 실패 통보 | 저장소에 실행 기록 커밋 |

## Part A — 어디서든 열리는 웹앱

### 목표

URL 하나로 어느 기기에서든 열리고, iPhone 홈 화면에 설치되며, 오프라인에서 동작한다.

### 구조

```
Obsidian vault (당분간)          ─┐
                                  ├─→ data/  ──git push──▶  Vercel
저장소 안 단어 원본 (이후)        ─┘                          │
                                                             ▼
                                            iPhone Safari → 홈 화면에 추가
                                                             ▼
                                          독립 아이콘 · 전체화면 · 오프라인
```

### 산출물

| 파일 | 역할 |
|---|---|
| `manifest.webmanifest` | 앱 이름·아이콘·테마색, `display: standalone`, 상대 경로 `start_url` |
| `sw.js` | 앱 셸 + 데이터 precache. 오프라인 동작 |
| `icons/` | 180px (iOS 홈 화면), 192·512px, maskable |
| `fonts/` | Pretendard 한글 서브셋, Source Serif 4 라틴 서브셋 |
| `vercel.json` | `sw.js` 에 `Cache-Control: no-cache`, `.webmanifest` MIME 지정 |
| `index.html` (수정) | manifest 링크, iOS 메타태그, SW 등록 (`file://` 에서는 조용히 건너뜀) |
| `README.md` (수정) | 배포·갱신 절차 |

### 설계 결정

**캐시 전략 — 통째로 받고 네트워크를 끊는다**

전체가 약 350KB 라 설치 시점에 전부 받아둔다. 이후 네트워크를 타지 않는다.
갱신은 `sw.js` 안의 `CACHE_VERSION` 문자열 하나로 제어한다. 값이 바뀌면 다음 실행에서
새 캐시로 교체된다. 반쪽짜리 갱신 상태가 생기지 않고, 문제가 생기면 값만 되돌리면 된다.

> **중요**: 서비스 워커는 **파일 바이트가 바뀌어야** 재설치된다. 데이터만 갱신하고
> `sw.js` 를 그대로 두면 설치된 앱에 새 단어가 영원히 안 보인다.
> Part C 의 루틴은 커밋할 때마다 반드시 이 값을 갱신해야 한다.

**폰트 — 셀프호스팅하되 최소한만**

현재 jsdelivr·Google Fonts 에서 받는다. 오프라인이면 가져올 수 없다.
폴백(`-apple-system`, `Iowan Old Style`)이 애플 기기에서 훌륭해 깨지지는 않지만,
온라인일 때와 오프라인일 때 **글꼴이 달라지는** 일관성 문제가 남는다.
서브셋 2개만 저장소에 넣고 precache 한다. 제목용 Serif 는 라틴 글자만 쓰이므로 가볍다.

**진도는 `localStorage` 그대로**

서버도 로그인도 없다. 홈 화면 앱으로 설치하면 Safari 의 7일 저장소 삭제(ITP) 대상에서
빠지므로 지금보다 오히려 안전해진다.

알려진 동작: iOS 는 홈 화면 웹앱과 Safari 탭의 저장 공간을 분리한다. 설치 직후 진도가
비어 보인다. 진도 이전이 불필요하다고 확정했으므로 문제되지 않으나, 설치 후에는
홈 화면 앱만 쓰는 편이 좋다.

### 범위에서 뺀 것

Supabase·로그인·진도 동기화 (불필요 확정) / 진도 내보내기·불러오기 (같은 이유) /
React·Angular 전환 (얻는 것 없음) / iPad 전용 레이아웃 (`css/app.css:190` 에서
48rem 이상일 때 40rem 중앙 컬럼으로 이미 대응) / 푸시 알림 (요청 없음)

### 확인 방법

- 로컬: `python3 -m http.server 8000` → DevTools Application 탭에서 manifest·SW 확인 →
  Network 를 Offline 으로 두고 새로고침
- 실기기: 배포 URL 을 iPhone 에서 열기 → 홈 화면에 추가 → **기내 모드 전환 후 실행**

## Part B — 수백 개를 견디는 데이터 구조

### 왜 필요한가

주 6개씩 쌓이면 데이터가 이렇게 늘어난다. 현재 단어당 약 5.7KB 기준이다.

| 시점 | 단어 수 | `vocabulary.js` |
|---|---|---|
| 지금 | 36 | 204 KB |
| 6개월 | ~190 | ~1.1 MB |
| 1년 | ~340 | ~1.9 MB |
| 2년 | ~650 | ~3.7 MB |

현재 코드에서 실제로 깨지는 두 지점:

1. **시작할 때 전부 파싱한다.** `window.VOCABULARY_DATA` 단일 배열에 모든 단어의 본문까지
   들어있다. 목록 화면은 `term`·`summary` 만 필요한데 본문 전체를 지고 시작한다.
2. **`allTerms()` 가 호출될 때마다 전체를 재구축한다.** `js/store.js:168` 이 전 단어를
   순회해 새 배열을 만드는데, `js/store.js:222-228` 에서 연속 4회 호출되고 탭바는 화면이
   바뀔 때마다 `reviewQueue()` 를 부른다 (`js/app.js`). 650개면 렌더마다 수천 번 순회한다.

### 해법

**인덱스와 본문을 분리한다.**

```
data/index.js          단어장 메타 + 단어별 경량 필드(id, term, reading, summary, book, level)
                       650개 기준 약 100~150KB. 항상 로드.
data/terms/<book>.js   해당 단어장 단어들의 본문(sections, related).
                       단어 상세를 처음 열 때만 로드하고 캐시.
```

- 홈·목록·검색·퀴즈 선택은 인덱스만으로 동작한다 (`summary` 가 인덱스에 있으므로 검색도 됨)
- 상세 화면 진입 시 해당 단어장 청크를 읽는다. 오프라인 요건상 청크도 전부 precache 하되,
  **시작 시 파싱하지 않는 것**이 이 변경의 핵심 이득이다
- `Store.allTerms()` 는 인덱스 기반으로 한 번만 만들어 재사용한다 (현재는 매번 재구축)

**단어장 구조 — 카테고리 고정, 안에서 단계로 나눈다**

각 단어에 `level`(기초/중급/심화)을 부여하고 단어장 안에서 단계별로 접어 보여준다.

이유는 세 가지다.

1. **끝낼 수 있는 덩어리가 생긴다.** "네트워크 83개 중 15개"는 막막하지만
   "네트워크 · 기초 18개 중 15개"는 오늘 끝낼 수 있는 목표다. 간격 반복 앱의 지속률은
   대부분 여기서 갈린다.
2. **단계가 학습 순서를 내포한다.** 단어장을 늘리는 방식은 분류만 정확해질 뿐 순서
   정보를 주지 않는다. 로드맵 기반 수집 전략과도 맞는다.
3. **AI 가 분류 체계를 건드리지 못하게 잠근다.** 루틴에 새 단어장 생성 권한을 주면
   2년 뒤 "클라우드"·"인프라"·"DevOps"가 따로 생겨 겹친다. 되돌리려면 수백 개를 손으로
   재분류해야 한다. 루틴에는 "기존 카테고리 중 하나를 고르고 단계만 부여하라"는
   좁은 권한만 준다.

**선행 작업 — 카테고리 체계 한 번 확정**

현재 6권(네트워크·아키텍처·AI/LLM·보안·인프라·CS기초)으로는 **데이터베이스·운영체제·
프론트엔드**가 갈 곳이 없다. 루틴을 켜기 전에 카테고리를 한 번 신중히 확장하고
(6 → 8~9권) 그 뒤로 고정한다. 한 번의 신중한 확장이 2년간의 자동 표류보다 낫다.

### 다른 세션과의 관계

vault 의존 제거는 **별도 세션에서 진행**된다. Part B 는 그 작업과 같은 파일을 건드리므로
순서를 지켜야 한다. 원본 파일 형식(Markdown vs JSON)은 그 세션에서 정해지며, 이 계획은
"저장소 안의 단어 원본 디렉터리"라는 추상 계약만 전제한다.

## Part C — 자동 단어 수집 루틴 3종

### 실행 환경 (확인 완료)

- Anthropic 클라우드에서 격리 세션으로 실행된다. **로컬 컴퓨터가 꺼져 있어도 동작한다**
- `itstudyu/it-roadmap` 자체 체크아웃을 가지므로 커밋·푸시가 가능하다
- cron 은 **UTC 고정**. 최소 간격 1시간
- 루틴 삭제는 도구로 불가 — https://claude.ai/code/routines 에서 수동
- Context7 커넥터가 연결되어 있다. 공식 라이브러리 문서 조회용으로 붙인다

### 일정

00:00 KST = 전날 15:00 UTC.

| 루틴 | 전략 | 시각 | cron (UTC) |
|---|---|---|---|
| `vocab-roadmap` | 표준 로드맵의 빈칸 채우기 | 월 00:00 KST | `0 15 * * 0` |
| `vocab-trend` | 최신 실무 용어 추적 | 수 00:00 KST | `0 15 * * 2` |
| `vocab-related` | 기존 단어의 관련 용어 따라가기 | 금 00:00 KST | `0 15 * * 4` |

루틴을 3개로 분리하는 이유: 프롬프트가 각각 한 가지 일만 하게 되어 단순해지고,
하나가 실패해도 나머지가 영향받지 않으며, 순환 상태를 저장소에 기록할 장치가 필요 없다.

### 각 루틴의 동작

회당 **2개**를 추가한다. 모든 루틴이 같은 6단계를 따르며 3단계만 다르다.

1. **현황 파악** — 저장소의 단어 인덱스를 읽어 이미 있는 단어 목록을 확보한다
2. **후보 선정** — 전략에 따라 다음 2개를 고른다 (아래 참조)
3. **중복 배제** — 표기 정규화 후 대조한다. 대소문자·공백·한영 표기(로드 밸런서 /
   Load Balancer)·약어 확장(CDN / Content Delivery Network)을 같은 것으로 본다
4. **집필** — 1차 출처를 조회해 기존 단어와 **동일한 형식**으로 작성한다.
   각 단어에 출처 URL 을 기록한다
5. **검증** — 아래 별도 절
6. **커밋** — 통과분만 커밋. `sw.js` 의 `CACHE_VERSION` 갱신. 실행 기록 커밋. main 에 push

**전략별 2단계**

- `vocab-roadmap`: roadmap.sh 등 확립된 개발자 커리큘럼을 기준으로, 기존 카테고리에서
  아직 없는 핵심 개념을 **기초 → 중급 → 심화 순서로** 채운다
- `vocab-trend`: 최근 실무에 등장한 용어를 다룬다. **공식 스펙이나 공식 발표 문서가
  존재하는 것만** 대상으로 한다. 없으면 추가하지 않는다 (유행어 방지)
- `vocab-related`: 기존 단어의 `관련 용어` 에 등장하지만 아직 설명이 없는 단어를 채운다

### 출처 기준 — 1차 출처만

허용 목록을 `tools/sources.allowlist.md` 에 두고 루틴과 검증자가 함께 읽는다.
저장소 파일이므로 루틴을 건드리지 않고 언제든 고칠 수 있다.

허용: RFC/IETF, W3C, MDN, OWASP, 프로젝트 공식 문서(kubernetes.io, react.dev, docker docs 등),
AWS·GCP·Azure 공식 문서, 언어·런타임 공식 스펙.

제외: 블로그, 튜토리얼 사이트, 백과사전, 강의 자료, AI 생성 요약 사이트.

각 단어는 **최소 2개의 독립 출처**를 인용한다. 요구를 못 채우면 그 단어는 버린다.

### 검증 — 유일한 관문

main 에 자동 push 하므로 검증이 마지막 방어선이다. 느슨하게 두지 않는다.

- **집필자와 검증자를 분리한다.** 검증자는 새 컨텍스트에서 시작하며 집필 과정을 보지 않는다
- **검증자는 떨어뜨릴 권한을 갖는다.** 통과가 기본값이 아니다
- 검증 항목: (a) 인용 URL 이 허용 목록에 있는가 (b) URL 을 실제로 열어 본문이 주장하는
  내용을 담고 있는가 (c) 정의가 출처와 모순되지 않는가 (d) 기존 단어와 중복이 아닌가
  (e) 앱이 파싱할 수 있는 형식인가
- **판단이 서지 않으면 탈락시킨다.** 애매한 것을 통과시키는 것보다 놓치는 편이 낫다
- 탈락분은 커밋하지 않고 실행 기록에만 사유를 남긴다

안전망: 잘못 들어가도 `git revert` 한 번으로 되돌아간다.

### 실행 기록

매 실행마다 `logs/routine-YYYY-MM-DD-<전략>.md` 를 커밋한다. 내용은
후보 목록, 통과·탈락 결과와 사유, 인용 출처, 최종 커밋 SHA.

추가 인프라가 0이고, GitHub 커밋 목록만 훑어도 루틴이 돌았는지 알 수 있다.
다만 루틴이 아예 안 떴으면 커밋도 없으므로, "조용한 사망"은 직접 봐야 알 수 있다.
이 한계를 알고 선택했다.

### 프롬프트

클라우드 에이전트는 **컨텍스트 0에서 시작한다.** 프롬프트가 자기완결적이어야 한다.
각 루틴 프롬프트에 반드시 포함할 것:

- 저장소 구조와 단어 원본 디렉터리 경로
- 기존 단어 형식의 실제 예시 (섹션 슬롯 포함)
- 고정된 카테고리 목록과 `level` 값의 정의
- 허용 출처 목록 파일 경로와 "1차 출처만" 규칙
- 회당 2개라는 상한
- 검증 절차와 탈락 기준
- `CACHE_VERSION` 갱신 지시
- 실행 기록 파일 형식
- 커밋 메시지 규칙

### 미확인 사항

`allowed_tools` 예시에 `WebSearch` 가 없다. 클라우드 루틴에서 웹 검색이 가능한지는
**등록 후 수동 1회 실행으로 확인**한다. 안 되면 Context7 커넥터를 주 조회 수단으로
전환하고, 대상을 Context7 이 다루는 공식 문서 범위로 좁힌다.

git push 권한도 같은 수동 실행에서 함께 확인한다.

## 구현 순서

의존 관계 때문에 순서가 중요하다.

| 순서 | 작업 | 선행 조건 |
|---|---|---|
| 1 | **Part A** — Vercel 배포 + PWA | 없음. 즉시 가능 |
| 2 | 카테고리 체계 확장 후 고정 (6 → 8~9권) | 없음 |
| 3 | vault 의존 제거 + 원본 형식 확정 | **별도 세션** |
| 4 | **Part B** — 인덱스/본문 분리, `allTerms()` 캐싱 | 3 |
| 5 | 허용 출처 목록 작성 (`tools/sources.allowlist.md`) | 없음 |
| 6 | 루틴 1개(`vocab-roadmap`) 등록 후 **수동 실행으로 검증** | 4, 5 |
| 7 | 나머지 2개 루틴 등록 | 6 통과 |

Part A 는 나머지와 독립이므로 지금 바로 시작할 수 있다.
Part C 는 4번이 끝나기 전에는 켜지 않는다 — 형식이 확정되지 않은 상태에서 루틴을 돌리면
앱이 못 읽는 파일이 쌓인다.

## 위험과 완화

| 위험 | 완화 |
|---|---|
| AI 가 틀린 정보를 main 에 올림 | 집필자·검증자 분리, 1차 출처 2개 요구, 애매하면 탈락. 사후 `git revert` |
| 루틴이 조용히 안 돎 | 실행 기록 커밋으로 확인. 한계는 인지하고 수용 |
| 데이터 갱신이 설치된 앱에 안 보임 | 루틴이 커밋마다 `CACHE_VERSION` 갱신 (누락 시 영구히 안 보임 — 검증 항목에 포함) |
| 단어가 배우는 속도보다 빨리 쌓임 | 회당 2개로 시작. 밀리면 루틴을 비활성화하면 됨 |
| AI 가 카테고리를 임의 생성 | 카테고리 고정, 루틴에는 `level` 부여 권한만 |
| 3번(vault 제거) 결과와 형식 불일치 | Part C 는 4번 완료 전 미가동. 추상 계약으로만 기술 |
| 저장소가 public 이라 단어가 공개됨 | 이미 public. 학습용 IT 용어라 민감정보 아님 |
