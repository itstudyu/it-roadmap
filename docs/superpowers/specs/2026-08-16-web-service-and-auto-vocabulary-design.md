## Part A — 어디서든 열리는 웹앱

### 산출물

| 파일 | 역할 |
|---|---|
| `manifest.webmanifest` | 앱 이름·아이콘·테마색, `display: standalone`, 상대 경로 `start_url` |
| `sw.js` | 앱 셸 + 데이터 precache. 오프라인 동작 |
| `icons/` | 180px (iOS 홈 화면), 192·512px, maskable |
| `fonts/` | Pretendard 한글 서브셋, Source Serif 4 라틴 서브셋 |
| `vercel.json` | `sw.js` 에 `Cache-Control: no-cache`, `.webmanifest` MIME |
| `index.html` (수정) | manifest 링크, iOS 메타태그, SW 등록 (`file://` 에서는 건너뜀) |

### 설계 결정

**캐시 전략 — 통째로 받고 네트워크를 끊는다**

갱신은 `sw.js` 안의 `CACHE_VERSION` 문자열 하나로 제어한다.

> **중요**: 서비스 워커는 **파일 바이트가 바뀌어야** 재설치된다. 데이터만 갱신하고
> `sw.js` 를 그대로 두면 설치된 앱에 새 단어가 영원히 안 보인다.
> Part C 의 루틴은 커밋할 때마다 반드시 이 값을 갱신해야 한다.

**폰트 — 셀프호스팅하되 최소한만**

현재 jsdelivr·Google Fonts 에서 받는다 (`index.html:13-18`, 확인됨). 오프라인이면
가져올 수 없다. 폴백이 애플 기기에서 훌륭해 깨지지는 않지만 온라인일 때와 글꼴이
달라지는 일관성 문제가 남는다. 서브셋 2개만 저장소에 넣고 precache 한다.

**진도는 `localStorage` 그대로**

홈 화면 앱으로 설치하면 Safari 의 7일 저장소 삭제(ITP) 대상에서 빠지므로 지금보다
오히려 안전해진다. iOS 는 홈 화면 웹앱과 Safari 탭의 저장 공간을 분리하므로 설치
직후 진도가 비어 보인다 — 진도 이전이 불필요하다고 확정했으므로 문제되지 않는다.

## Part B-3 — 단어장 구조 검수 (신규)

사용자 요청: "단어장이 12권으로 늘었는데 어떻게 할지, 단어가 계속 늘어날 것도 고려해서."

### 결론: 현상 유지. 단, 발동 임계치를 **한 권 40단어**로 확정한다

**먼저 깨지지 않는 곳부터** — 실측 결과 화면 3개는 성장에 안전하다.

- **홈**: 상수 크기다. 다음 행동 1개 + 진행 중 상위 2권(`slice(0,2)`) + 최근 3개
  (`js/screens.js:132-151, 191-230`). 단어가 몇 개든 안 늘어난다.
- **단어장 목록**: 12권 평면 나열 ≈ 2화면 (`js/screens.js:264-282`). **카테고리 고정
  정책 덕에 앞으로도 안 늘어난다.**
- **퀴즈 범위 선택**: 스코프 2 + 권 12행 ≈ 1.5화면. 같은 이유로 고정.

**먼저 깨지는 곳은 권 내부다.**

1. **권 내 정렬에 교육적 순서가 없다.** 파일명 가나다순이라 `cs` 첫 3개가
   async-await, big-o, binary 다 (`tools/build.py:532`). 루틴이 넣는 신규 단어가
   알파벳 위치에 따라 **사용자 진행 위치 앞에 삽입**되어, 홈의 "다음 단어"가
   방금 들어온 단어로 뒤로 점프한다 (`js/store.js:221-235`). 주 6개 유입이면 상시화된다.
2. **권 스코프 퀴즈가 8문제 고정 샘플**이다 (`js/quiz-screens.js:39`). `sec` 34개 기준
   커버리지 24%, 80개면 10%로 희석된다.
3. **권 내 목록은 검색 + 상태 필터 5종**으로 방어된다 (`js/screens.js:288-310`).
   50~60개까지는 버틴다. Anki 의 표준 권고(다단 하위덱 지양, 단일 덱 + 필터)와 같은 패턴이다.

### 후보 검토

| 후보 | 판정 |
|---|---|
| 분야 묶음 (4분야 아래 12권) | **불필요.** 권 목록이 카테고리 고정으로 안 늘어난다 |
| **임계치 분권** (40개 넘으면 권 쪼개기) | **금지.** id 가 `{bookId}--{slug}` 라 권을 쪼개면 이동한 단어의 진도가 전부 고아가 된다 |
| **권내 단계** (`level`: 기초/중급/심화) | **채택 (조건부).** 순서 문제 · 퀴즈 희석 · 완주 단위를 동시에 푼다 |
| 현상 유지 | **지금은 이것.** 최대 권이 34로 40 미만 |

### 실행 규칙

1. **발동 조건** — 한 권이 **40단어를 넘으면** 그 권부터 `level` 도입.
   권 수 임계는 불필요 (정책상 12 고정).
2. **대응 방식** — 반드시 **권내 단계**. **분권은 진도 키를 파괴하므로 영구 금지.**
3. **도달 시점** — 1차판의 "1년 뒤"는 **과대 추정이었다.** 주 +6이 12권에 균등
   분산돼도 `sec` 는 주 +0.5로 34→40에 **12주(약 3개월)**. `vocab-trend`·`vocab-related`
   가 링크 밀도 높은 큰 권(`sec`·`net`·`ai`)에 편중되면 더 빠르다.
4. **선제 조치** — Part C 실행 기록(`logs/`)에 **권별 단어 수 스냅샷**을 넣어 40 초과를
   루틴 로그에서 자동 감지한다. 루틴에는 "대상 권이 40개 이상이면 추가 금지, 사유 기록".

선례: Duolingo 2022 학습 경로 개편(자유 선택 트리 → 섹션 > 유닛 소단위 선형 경로)이
"끝낼 수 있는 덩어리 + 내포된 순서"의 효과를 보여준다.

| `vocab-related` | 관련 용어 따라가기 | 금 00:00 KST | `0 15 * * 4` |

### 동작 (회당 2개)

1. **현황 파악** — `content/` 를 훑어 기존 단어·폴더 확보
2. **후보 선정** — 전략별 (아래)
3. **중복 배제 — 3축 전부 대조.** 파일명만으로는 부족하다:
   `239037a` 에서 중복 판정 기준이 **파일명 → H1 제목(`title_of`)**으로 바뀌었다.
   **파일명 · H1 제목 · 괄호 안 원어(reading)** 를 정규화해 대조한다.
   대소문자·공백·한영 표기(로드 밸런서 / Load Balancer)·약어 확장(CDN / Content
   Delivery Network)을 같은 것으로 본다
4. **집필** — 1차 출처 조회 후 `content/<기존 폴더>/<Term>.md` 작성
5. **검증** — 3층 (아래)
6. **커밋** — `git pull --rebase` → `build.py` 재실행 → `CACHE_VERSION` 갱신 →
   실행 기록 → main push

**전략별 2단계**

- `vocab-roadmap`: roadmap.sh 등 확립된 커리큘럼 기준 빈칸 채우기.
  **검증된 빈칸**: `db`(Primary/Foreign Key, 정규화, 복제), `tool`(패키지 매니저, 린터,
  디버거). ⚠️ 후보를 추정으로 적지 말 것 — 1차 분석이 "빈칸"이라 한 WebSocket·샤딩은
  검증 결과 `content/네트워크/WebSocket.md`·`content/아키텍처/Sharding.md` 로 **이미 존재**했다.
  권 이름만 보고 판단하면 다른 권에 있는 단어를 놓친다. **반드시 `content/` 전체를 훑어
  확인**한다. **후보가 동급이면 단어 수가 가장 적은 권 우선.**
  `content/IT_Expert_로드맵.md` 에 백로그가 있으나 일부는 이미 구현됐다(gRPC·REST·GraphQL 실존).
- `vocab-trend`: 최근 실무 용어. **공식 스펙·공식 발표 문서가 있는 것만.** 없으면 추가 안 함
- `vocab-related`: 기존 단어의 `🔗 관련 용어` 중 파일이 없는 것.
  ⚠️ **가동 시점에 후보 풀이 비어 있다** — 현재 related 1,008항목이 **전부** 기존 단어의
  alias 로 해소된다(미해결 0건, 실측). 풀은 roadmap·trend 가 신규 단어를 넣어야 생긴다.
  **후보 0개면 아무것도 만들지 말고 "후보 없음"만 기록한다. 즉흥 후보 생성 금지.**

### 분류 배정 규칙

"기존 폴더에만 쓴다"는 필요조건일 뿐 배정을 결정하지 못한다. 저장소에는 반직관적
정착 사례가 있다:

```
MCP → 네트워크        gRPC → 웹개발       Cookie·Session → 보안
Container·Docker → 개발도구               Kubernetes·CI_CD → 인프라
```

**원칙: 오배정이어도 이동하지 않는다.** 파일을 옮기면 book id 가 바뀌어 id 가 바뀌고
진도가 고아가 된다. 루틴에는 **"추가만 하고 절대 수정·이동·삭제하지 않는다"** 를
안전 불변식으로 명시한다. 이 불변식을 지키는 한 신규 단어 id 는 기존 어떤 id 와도
충돌하지 않고 기존 진도가 구조적으로 안전하다.

### 출처 기준 — 1차 출처만

`tools/sources.allowlist.md` 를 루틴과 검증자가 함께 읽는다. **작성 완료.**
각 단어는 서로 다른 도메인의 출처를 **최소 2개** 인용한다. 못 채우면 탈락.
루틴은 이 파일을 수정하지 않는다.

### 검증 — 3층

| 층 | 방법 | 판정 |
|---|---|---|
| 1 | `python3 tools/check_template.py <파일>` | 기계 (결정론적) |
| 2 | AI 검증 (별도 컨텍스트, 집필자와 분리) | 사실 정확성, 출처 실재·일치, 의미 중복 |
| 3 | `python3 tools/build.py --dry-run` | 앱이 파싱 가능함 |

**⚠️ 3층 판정을 "exit 0"으로 하면 안 된다.** `FOLDER_TO_BOOK` 미등록 폴더의 단어는
`dropped` 에 기록되지만 **stderr 에만 찍히고 `main()` 은 0을 반환한다**
(`tools/build.py:535-538, 582-609`). 새 폴더를 만들면 1·2·3층을 전부 통과하고도
**앱에서 조용히 사라진다.**

→ 3층 판정 기준: **`--dry-run` stderr 에 제외 0건 AND 단어 총수가 정확히 +2.**

**1층은 표를 복제하지 말고 위임한다.** 이번 범위에서 검사기가 5건 강화됐고
(대조 줄 3~4 신설, 정의 첫 문단 정확히 한 문장, 되묻기 검출 확대, `💻 코드 구현` 섹션
금지, H2 제목 중복 금지), 원래부터 표에 없던 검사도 10여 건이다 (흐름 마디 이름 8자,
층 3~5, 도해 첫 줄 `모양: 질문` 형식, H1 필수, 정의 안 `### 비유` 필수, 그림 섹션은
도해 정확히 1개, mermaid 금지, 도해 `= 한 줄 결론` 필수).
→ 프롬프트에는 **"`docs/TERM-TEMPLATE.md` 를 읽고 `check_template.py` 판정을 따르라"**
로 위임한다. 표를 복제하면 검사기가 강화될 때마다 프롬프트가 낡는다.

**2층 운영 원칙**: 검증자는 새 컨텍스트에서 시작하며 집필 과정을 보지 않는다.
떨어뜨릴 권한을 갖는다. 통과가 기본값이 아니다. **판단이 서지 않으면 탈락시킨다.**

**추가 탈락 규칙**: 신규 단어의 slug 가 대상 권의 기존 slug 와 충돌하면 탈락.
충돌 시 `-2` 접미가 제목 정렬 순서에 의존해 **기존 단어의 id 를 빼앗을 수 있다**
(`tools/build.py:532, 562-567`).

안전망: 잘못 들어가도 `git revert` 한 번으로 되돌아간다.

### 도해 작성 부담

`🖼️ 그림으로 보기` 가 필수 섹션이다. 세 종류:

```
흐름:  단계 순서 (마디 4~7개, 마디 이름 8자 이내)
대조:  두 상태 나란히 (데이터 줄 3~4개, 칸 14자 이내)
층:    쌓인 구조 (3~5층)
= 한 줄 결론  ← 필수
```

첫 줄은 `모양: 질문` 형식이고 제목은 물음이어야 한다.
본보기: `content/네트워크/DNS.md` (세 유형 전부 사용), `content/네트워크/HTTP.md`.

### 실행 기록

`logs/routine-YYYY-MM-DD-<전략>.md` 를 커밋한다. 내용: 후보 목록, 3층 각각의
통과·탈락과 사유, 인용 출처, **권별 단어 수 스냅샷**(40 초과 감지용), 최종 커밋 SHA.

### 프롬프트 요건

클라우드 에이전트는 컨텍스트 0에서 시작한다. 자기완결적이어야 한다.

- 저장소 구조와 **폴더명 15개 목록** (단어장 12권 ≠ 폴더 12개 — 폴더명을 직접 나열)
- **루트에 파일을 만들지 말 것. 반드시 폴더 안에.** 새 폴더 생성 금지
- `docs/TERM-TEMPLATE.md` 를 읽고 `content/네트워크/DNS.md` 를 본보기로 삼을 것
- `tools/sources.allowlist.md` 의 1차 출처만, 최소 2개
- 회당 2개 상한. 대상 권이 40개 이상이면 추가 금지
- 3층 검증 절차와 "애매하면 탈락"
- **안전 불변식: 추가만 한다. 수정·이동·삭제·개명 금지. BOOKS 수정 금지**
- `git pull --rebase` → `build.py` → `CACHE_VERSION` 갱신 → 실행 기록 → push
- 코드 예시를 쓸 일이 생기면 반드시 언어 태그를 붙일 것 (태그 없는 펜스는 도해
  휴리스틱 분류에 맡겨진다). 단 템플릿상 코드 섹션이 제거됐으므로 기본은 안 쓰는 것

### 미확인 사항

`allowed_tools` 예시에 `WebSearch` 가 없다. **등록 후 수동 1회 실행으로 확인**한다.
안 되면 Context7 을 주 조회 수단으로 전환하고 대상을 공식 문서 범위로 좁힌다.
git push 권한도 같은 실행에서 확인한다.
