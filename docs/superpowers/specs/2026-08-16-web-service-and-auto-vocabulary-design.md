## Part A — 어디서든 열리는 웹앱

### 목표

URL 하나로 어느 기기에서든 열리고, iPhone 홈 화면에 설치되며, 오프라인에서 동작한다.

### 구조

```
content/*.md  ──build.py──▶  data/  ──git push──▶  Vercel
                                                      │
                                     iPhone Safari → 홈 화면에 추가
                                                      ▼
                                    독립 아이콘 · 전체화면 · 오프라인
```

### 산출물

| 파일 | 역할 |
|---|---|
| `manifest.webmanifest` | 앱 이름·아이콘·테마색, `display: standalone`, 상대 경로 `start_url` |
| `sw.js` | 앱 셸 + 데이터 precache. 오프라인 동작 |
| `icons/` | 180px (iOS 홈 화면), 192·512px, maskable |
| `fonts/` | Pretendard 한글 서브셋, Source Serif 4 라틴 서브셋 |
| `vercel.json` | `sw.js` 에 `Cache-Control: no-cache`, `.webmanifest` MIME 지정 |
| `index.html` (수정) | manifest 링크, iOS 메타태그, SW 등록 (`file://` 에서는 조용히 건너뜀) |
| `README.md` (수정) | 배포·갱신 절차 |

### 설계 결정

**캐시 전략 — 통째로 받고 네트워크를 끊는다**

설치 시점에 전부 받아두고 이후 네트워크를 타지 않는다.
갱신은 `sw.js` 안의 `CACHE_VERSION` 문자열 하나로 제어한다. 값이 바뀌면 다음 실행에서
새 캐시로 교체된다. 반쪽짜리 갱신 상태가 생기지 않고, 문제가 생기면 값만 되돌리면 된다.

> **중요**: 서비스 워커는 **파일 바이트가 바뀌어야** 재설치된다. 데이터만 갱신하고
> `sw.js` 를 그대로 두면 설치된 앱에 새 단어가 영원히 안 보인다.
> Part C 의 루틴은 커밋할 때마다 반드시 이 값을 갱신해야 한다.

**폰트 — 셀프호스팅하되 최소한만**

현재 jsdelivr·Google Fonts 에서 받는다 (`index.html:13-18`). 오프라인이면 가져올 수 없다.
폴백(`-apple-system`, `Iowan Old Style`)이 애플 기기에서 훌륭해 깨지지는 않지만,
온라인일 때와 오프라인일 때 **글꼴이 달라지는** 일관성 문제가 남는다.
서브셋 2개만 저장소에 넣고 precache 한다. 제목용 Serif 는 라틴 글자만 쓰이므로 가볍다.

**진도는 `localStorage` 그대로**

서버도 로그인도 없다. 홈 화면 앱으로 설치하면 Safari 의 7일 저장소 삭제(ITP) 대상에서
빠지므로 지금보다 오히려 안전해진다.

알려진 동작: iOS 는 홈 화면 웹앱과 Safari 탭의 저장 공간을 분리한다. 설치 직후 진도가
비어 보인다. 진도 이전이 불필요하다고 확정했으므로 문제되지 않으나, 설치 후에는
홈 화면 앱만 쓰는 편이 좋다.

### 범위에서 뺀 것

Supabase·로그인·진도 동기화 (불필요 확정) / 진도 내보내기·불러오기 (같은 이유) /
React·Angular 전환 (얻는 것 없음) / iPad 전용 레이아웃 (`css/app.css:190` 에서
48rem 이상일 때 40rem 중앙 컬럼으로 이미 대응) / 푸시 알림 (요청 없음)

### 확인 방법

- 로컬: `python3 -m http.server 8000` → DevTools Application 탭에서 manifest·SW 확인 →
  Network 를 Offline 으로 두고 새로고침
- 실기기: 배포 URL 을 iPhone 에서 열기 → 홈 화면에 추가 → **기내 모드 전환 후 실행**

## Part B — 데이터 구조

> **갱신**: 초판에서 "1년 뒤 ~1.9MB" 로 예측했던 지점에 **이미 도달했다.**
> 미래 대비가 아니라 지금 고쳐야 하는 문제로 승격한다.

### 지금 아픈 것

```
data/vocabulary.js = 1.3 MB · 단어 229개 · 단어장 12권
```

실제로 깨지는 세 지점:

1. **동기 로드다.** `index.html:30` 이 `<script src="data/vocabulary.js"></script>` 로
   `defer` 도 `async` 도 없이 받는다. 1.3MB 파싱이 끝날 때까지 첫 화면이 안 그려진다.
2. **목록에 필요 없는 것까지 지고 시작한다.** 목록 화면은 `term`·`summary` 만 쓰는데
   본문·도해·관련용어가 전부 같은 파일에 있다.
3. **`allTerms()` 가 호출될 때마다 전체를 재구축한다.** `js/store.js:168` 이 전 단어를
   순회해 새 배열을 만드는데, `js/store.js:222-228` 에서 연속 4회 호출되고 탭바는 화면이
   바뀔 때마다 `reviewQueue()` 를 부른다 (`js/app.js`).

주 6개씩 계속 쌓이면:

| 시점 | 단어 수 | 예상 크기 |
|---|---|---|
| 지금 | 229 | 1.3 MB |
| 6개월 | ~380 | ~2.2 MB |
| 1년 | ~540 | ~3.1 MB |
| 2년 | ~850 | ~4.8 MB |

### 해법

**(1) 즉시 가능한 것 — 생성 파일 최소화**

`tools/build.py:521` 이 `json.dumps(..., indent=2)` 로 굽는다. 생성물이라 사람이 읽을
일이 없으므로 들여쓰기를 뺀다. 코드 한 줄로 눈에 띄는 크기 감소를 얻는다.

**(2) 인덱스와 본문을 분리한다**

`build.py` 의 출력부만 고치면 된다. 소비 측(`js/store.js`, `js/screens.js`)이 따라온다.

```
data/index.js          단어장 메타 + 단어별 경량 필드
                       (id, term, reading, summary, book) — 항상 로드
data/terms/<book>.js   해당 단어장 단어들의 본문(definition, sections, figure, related)
                       단어 상세를 처음 열 때만 로드하고 캐시
```

- 홈·목록·검색·퀴즈 선택은 인덱스만으로 동작한다 (`summary` 가 인덱스에 있어 검색도 됨)
- 오프라인 요건상 청크도 전부 precache 하되, **시작할 때 파싱하지 않는 것**이 핵심 이득이다
- `index.js` 에도 `defer` 를 붙인다

**(3) `Store.allTerms()` 를 한 번만 만들어 재사용한다**

인덱스 기반으로 최초 1회 구축하고 캐시한다. 진도가 바뀔 때만 무효화한다.

### 단어장 안 단계 나누기 — 지금은 보류

> **갱신**: 초판에서는 단어장 6권 × 80개를 전제로 `level`(기초/중급/심화) 도입을 권했다.
> 카테고리가 **12권으로 늘어나면서 권당 평균 19개**가 되었다. 가장 큰 `sec` 도 34개다.
> 지금 계층을 하나 더 넣는 것은 이르다.

구조적 논거 자체는 유효하다 — 끝낼 수 있는 덩어리가 있어야 지속되고, 단계는 학습 순서를
내포한다. 다만 **한 단어장이 40개를 넘을 때** 다시 꺼내는 것으로 미룬다. 주 6개 속도라면
`sec` 기준 대략 1년 뒤다.

그때까지 루틴에는 **새 단어장을 만들 권한을 주지 않는다.** 2년간 AI 가 자유롭게 카테고리를
만들면 "클라우드"·"인프라"·"DevOps"가 따로 생겨 겹치고, 되돌리려면 수백 개를 손으로
재분류해야 한다. 루틴은 `build.py` 의 `FOLDER_TO_BOOK` 에 이미 있는 폴더에만 쓴다.

## Part B-2 — 템플릿 미통과 83개 (다른 세션에서 진행 중)

> **갱신**: 초판에는 없던 항목이다. 템플릿 규약이 새로 생기면서 드러났다.
> **변환 작업은 이미 다른 세션에서 진행 중이다.** 이 계획서는 현황만 기록하고,
> 루틴 가동 시점의 선행 조건으로만 참조한다.

`docs/TERM-TEMPLATE.md` 를 기준으로 `tools/check_template.py` 를 242개 전부에 돌린 결과:

```
통과 159 / 미통과 83
```

미통과 예: `Windows.md`, `Process.md`, `Parallelism.md`, `자료구조.md`, `Variable.md`,
`Regex.md`, `Recursion.md`, `VPN.md`, `Reverse Proxy.md`, `MCP.md`, `UDP.md`,
`WebSocket.md`, `Socket.md`, `curl.md` …

**이 83개는 앱에서 빠지지 않는다.** `build.py:425` 의 `is_converted()` 는 동명 노트가
여러 폴더에 있을 때 우선순위를 가리는 데만 쓰이고, 미변환이라고 버리지 않는다.
따라서 그림·흔한 오해·이해 확인이 없는 단어가 앱에 섞여 있다.

**현재 다른 세션에서 변환 작업이 진행 중이다.** 따라서 네 번째 "변환 루틴"은 만들지 않는다.

이 계획에 남기는 것은 두 가지뿐이다.

- **루틴 가동 전 확인.** 루틴을 켜기 전에 `check_template.py` 를 전수로 돌려 통과 수를
  확인한다. 변환이 끝나지 않았어도 루틴 가동을 막지는 않는다 — 신규 단어는 어차피
  1층 검증에서 템플릿을 강제받으므로, 미변환분과 독립이다.
- **충돌 회피.** 변환 세션은 기존 파일을 고치고 루틴은 새 파일만 만든다. 대상이 겹치지
  않으므로 동시 진행이 가능하다. 다만 둘 다 `data/vocabulary.js` 를 다시 구우므로,
  루틴은 커밋 직전에 `git pull --rebase` 를 먼저 한다.

진행 상황 확인 명령 (읽기 전용):

```bash
python3 - <<'PY'
import subprocess, pathlib
files = [p for p in pathlib.Path("content").rglob("*.md")
         if p.name not in ("INDEX.md", "IT_Expert_로드맵.md")]
ok = sum(subprocess.run(["python3","tools/check_template.py",str(p)],
                        capture_output=True).returncode == 0 for p in files)
print(f"{ok}/{len(files)} 통과")
PY
```

## Part C — 자동 단어 수집 루틴 3종

### 실행 환경 (확인 완료)

- Anthropic 클라우드에서 격리 세션으로 실행된다. **로컬 컴퓨터가 꺼져 있어도 동작한다**
- `itstudyu/it-roadmap` 자체 체크아웃을 가지므로 커밋·푸시가 가능하다
- cron 은 **UTC 고정**. 최소 간격 1시간
- 루틴 삭제는 도구로 불가 — https://claude.ai/code/routines 에서 수동
- Context7 커넥터가 연결되어 있다. 공식 라이브러리 문서 조회용으로 붙인다

### 일정

00:00 KST = 전날 15:00 UTC.

| 루틴 | 전략 | 시각 | cron (UTC) |
|---|---|---|---|
| `vocab-roadmap` | 표준 로드맵의 빈칸 채우기 | 월 00:00 KST | `0 15 * * 0` |
| `vocab-trend` | 최신 실무 용어 추적 | 수 00:00 KST | `0 15 * * 2` |
| `vocab-related` | 기존 단어의 관련 용어 따라가기 | 금 00:00 KST | `0 15 * * 4` |

루틴을 3개로 분리하는 이유: 프롬프트가 각각 한 가지 일만 하게 되어 단순해지고,
하나가 실패해도 나머지가 영향받지 않으며, 순환 상태를 저장소에 기록할 장치가 필요 없다.

### 각 루틴의 동작

회당 **2개**를 추가한다. 모든 루틴이 같은 6단계를 따르며 2단계만 다르다.

1. **현황 파악** — `content/` 를 훑어 기존 단어 목록과 카테고리를 확보한다
2. **후보 선정** — 전략에 따라 다음 2개를 고른다 (아래 참조)
3. **중복 배제** — 표기 정규화 후 대조한다. 대소문자·공백·한영 표기(로드 밸런서 /
   Load Balancer)·약어 확장(CDN / Content Delivery Network)을 같은 것으로 본다.
   `content/` 는 파일명이 곧 단어이므로 목록 확보가 값싸다
4. **집필** — 1차 출처를 조회해 `docs/TERM-TEMPLATE.md` 를 지켜 작성한다.
   `content/<기존 카테고리>/<Term>.md` 에 쓴다. 출처 URL 을 함께 기록한다
5. **검증** — 3층 (아래 별도 절)
6. **커밋** — 통과분만. `python3 tools/build.py` 재실행, `sw.js` 의 `CACHE_VERSION` 갱신,
   실행 기록 커밋, main 에 push

**전략별 2단계**

- `vocab-roadmap`: roadmap.sh 등 확립된 개발자 커리큘럼을 기준으로, 기존 12개 카테고리에서
  아직 없는 핵심 개념을 기초부터 채운다
- `vocab-trend`: 최근 실무에 등장한 용어를 다룬다. **공식 스펙이나 공식 발표 문서가
  존재하는 것만** 대상으로 한다. 없으면 추가하지 않는다 (유행어 방지)
- `vocab-related`: 기존 단어의 `🔗 관련 용어` 에 등장하지만 아직 파일이 없는 단어를 채운다.
  템플릿이 관련 용어 3~5개를 요구하므로 후보가 자연히 쌓인다

### 출처 기준 — 1차 출처만

허용 목록을 `tools/sources.allowlist.md` 에 두고 루틴과 검증자가 함께 읽는다.
저장소 파일이므로 루틴을 건드리지 않고 언제든 고칠 수 있다.

허용: RFC/IETF, W3C, MDN, OWASP, 프로젝트 공식 문서(kubernetes.io, react.dev, docker docs 등),
AWS·GCP·Azure 공식 문서, 언어·런타임 공식 스펙.

제외: 블로그, 튜토리얼 사이트, 백과사전, 강의 자료, AI 생성 요약 사이트.

각 단어는 **최소 2개의 독립 출처**를 인용한다. 요구를 못 채우면 그 단어는 버린다.

### 검증 — 3층

> **갱신**: 초판은 "집필자와 검증자를 분리한 AI 검증" 1층이었다. `check_template.py` 와
> `build.py` 가 생기면서 **기계가 판정하는 두 층**이 앞뒤로 붙는다. main 자동 push 의
> 위험이 실질적으로 줄어든다.

| 층 | 방법 | 판정 주체 | 무엇을 잡나 |
|---|---|---|---|
| 1 | `python3 tools/check_template.py <파일>` | 기계 (결정론적) | 필수 섹션 8종, 흔한 오해 2~3개, 이해 확인 3개(각 12자 이상), 흐름 마디 4~7개, 대조 칸 14자 이내, 관련 용어 3~5개, 정리 3문장 이내, 정의 첫 문단 60자 이내 |
| 2 | AI 검증 (별도 컨텍스트) | AI | 사실 정확성, 인용 출처 실재 여부와 내용 일치, 기존 단어와 의미 중복 |
| 3 | `python3 tools/build.py` 성공 | 기계 | 앱이 실제로 파싱하고 굽을 수 있음. `report()` 출력의 단어 수 증가 확인 |

2층 운영 원칙:

- **집필자와 검증자를 분리한다.** 검증자는 새 컨텍스트에서 시작하며 집필 과정을 보지 않는다
- **검증자는 떨어뜨릴 권한을 갖는다.** 통과가 기본값이 아니다
- **판단이 서지 않으면 탈락시킨다.** 애매한 것을 통과시키는 것보다 놓치는 편이 낫다
- 탈락분은 커밋하지 않고 실행 기록에만 사유를 남긴다

안전망: 잘못 들어가도 `git revert` 한 번으로 되돌아간다.

### 도해 작성 부담 (신규)

> **갱신**: 초판에는 없던 제약이다.

`🖼️ 그림으로 보기` 가 필수 섹션이고, 본문에도 `도해` 블록이 쓰인다. 세 종류가 있다.

```
흐름:  단계를 순서대로 (마디 4~7개)
대조:  두 상태를 나란히 (칸 14자 이내)
층:    쌓인 구조를 위에서 아래로 (3~5층)
```

새 단어마다 이걸 그려야 한다. 루틴 프롬프트에 **실제 예시를 충분히 넣어야 한다** —
`content/네트워크/DNS.md` 가 세 종류를 모두 쓰는 좋은 본보기다.
1층 기계 검증이 형식을 잡아주므로 실패는 조용하지 않고 드러난다.

### 실행 기록

매 실행마다 `logs/routine-YYYY-MM-DD-<전략>.md` 를 커밋한다. 내용은
후보 목록, 3층 각각의 통과·탈락 결과와 사유, 인용 출처, 최종 커밋 SHA.

추가 인프라가 0이고, GitHub 커밋 목록만 훑어도 루틴이 돌았는지 알 수 있다.
다만 루틴이 아예 안 떴으면 커밋도 없으므로, "조용한 사망"은 직접 봐야 알 수 있다.
이 한계를 알고 선택했다.

### 프롬프트

클라우드 에이전트는 **컨텍스트 0에서 시작한다.** 프롬프트가 자기완결적이어야 한다.
각 루틴 프롬프트에 반드시 포함할 것:

- 저장소 구조와 `content/<카테고리>/` 경로, `build.py` 의 `FOLDER_TO_BOOK` 에 있는 폴더만 쓸 것
- `docs/TERM-TEMPLATE.md` 를 읽으라는 지시와 `content/네트워크/DNS.md` 를 본보기로 삼으라는 지시
- 고정된 12개 카테고리 목록. **새 카테고리를 만들지 말 것**
- 허용 출처 목록 파일 경로와 "1차 출처만, 최소 2개" 규칙
- 회당 2개라는 상한
- 3층 검증 절차와 "애매하면 탈락" 원칙
- `build.py` 재실행과 `CACHE_VERSION` 갱신 지시
- 실행 기록 파일 형식과 커밋 메시지 규칙

### 미확인 사항

`allowed_tools` 예시에 `WebSearch` 가 없다. 클라우드 루틴에서 웹 검색이 가능한지는
**등록 후 수동 1회 실행으로 확인**한다. 안 되면 Context7 커넥터를 주 조회 수단으로
전환하고, 대상을 Context7 이 다루는 공식 문서 범위로 좁힌다.

git push 권한도 같은 수동 실행에서 함께 확인한다.

## 구현 순서

> **갱신**: 초판의 2번(카테고리 확장)과 3번(vault 제거)은 완료되어 삭제했다.
> Part B 를 앞으로 당기고, 배포와 PWA 를 분리했다.

| 순서 | 작업 | 선행 조건 | 비고 |
|---|---|---|---|
| 1 | **Vercel 배포** (PWA 없이) | 없음 | 10분. 재작업 위험 0. "어디서든 보기" 즉시 충족 |
| 2 | **Part B** — `indent` 제거, 인덱스/본문 분리, `allTerms()` 캐싱 | 없음 | 지금 아픈 문제 |
| 3 | **PWA** — manifest, sw.js, 아이콘, 폰트 | 2 | 순서를 바꾸면 precache 목록을 두 번 짜게 됨 |
| 4 | 허용 출처 목록 작성 (`tools/sources.allowlist.md`) | 없음 | |
| 5 | 루틴 1개(`vocab-roadmap`) 등록 후 **수동 실행으로 검증** | 2, 4 | 웹 검색·push 가능 여부 확인 |
| 6 | 나머지 2개 루틴 등록 | 5 통과 | |

(Part B-2 의 템플릿 변환은 다른 세션에서 병행된다. 이 순서에 포함하지 않는다.)

1번은 나머지와 독립이므로 지금 바로 시작할 수 있다.
5번은 2번이 끝나기 전에 켜지 않는다 — 데이터 구조가 바뀌는 중에 루틴이 커밋하면
충돌이 나거나 앱이 못 읽는 산출물이 쌓인다.

## 위험과 완화

| 위험 | 완화 |
|---|---|
| AI 가 틀린 정보를 main 에 올림 | 3층 검증(기계·AI·빌드), 1차 출처 2개 요구, 애매하면 탈락. 사후 `git revert` |
| 루틴이 조용히 안 돎 | 실행 기록 커밋으로 확인. 한계는 인지하고 수용 |
| 데이터 갱신이 설치된 앱에 안 보임 | 루틴이 커밋마다 `CACHE_VERSION` 갱신 (누락 시 영구히 안 보임 — 검증 항목에 포함) |
| 단어가 배우는 속도보다 빨리 쌓임 | 회당 2개로 시작. 밀리면 루틴을 비활성화하면 됨 |
| AI 가 카테고리를 임의 생성 | 카테고리 고정. `FOLDER_TO_BOOK` 에 있는 폴더에만 쓰도록 프롬프트에 명시 |
| 도해를 못 그려서 품질이 떨어짐 | 1층 기계 검증이 형식을 잡음. 프롬프트에 DNS.md 본보기 포함 |
| 루틴 커밋과 변환 세션이 충돌 | 변환 세션은 기존 파일, 루틴은 신규 파일 — 대상이 안 겹침. 둘 다 `data/vocabulary.js` 를 구우므로 루틴은 커밋 직전 `git pull --rebase` |
| 미통과 83개로 앱 품질이 들쭉날쭉 | 다른 세션에서 변환 진행 중. 신규 단어는 1층 검증이 템플릿을 강제하므로 독립 |
| 저장소가 public 이라 단어가 공개됨 | 이미 public. 학습용 IT 용어라 민감정보 아님 |
