## Part A — 어디서든 열리는 웹앱 ✅ 완료 (`3a65951`)

### 산출물

| 파일 | 실제 |
|---|---|
| `manifest.webmanifest` | `display: standalone`, 상대 경로 `start_url`, 아이콘 3종 |
| `sw.js` | 자산 30개 precache. 오프라인 동작 |
| `icons/` | 180 (iOS 홈 화면) · 192 · 512 · maskable-512. '단' 한 글자, 잉크 바탕 |
| `fonts/` | Pretendard 서브셋 861KB + Source Serif 4 라틴 122KB |
| `vercel.json` | `sw.js` no-cache, `.webmanifest` MIME, 폰트 immutable |
| `index.html` | manifest·iOS 메타태그·SW 등록, 폰트 preload, CDN 링크 제거 |

### 설계 결정

**캐시 전략 — 통째로 받고 네트워크를 끊는다**

`addAll` 은 하나라도 실패하면 통째로 실패하는데 그게 맞다. 반쯤 받은 캐시로 오프라인에
들어가면 어떤 단어는 열리고 어떤 단어는 빈 화면이 된다.

**`CACHE_VERSION` 을 사람에게 맡기지 않는다** ⚠️ 계획 변경

> 원래 계획은 "루틴이 커밋할 때마다 이 값을 갱신한다"였다. 구현하면서 그게 가장 약한
> 고리임이 분명해졌다 — 이 값을 안 올리면 설치된 앱에 새 단어가 **영원히** 안 보이는데,
> 앞으로 이걸 굽는 주체가 주 3회 도는 루틴이면 언젠가 반드시 잊는다.
>
> `tools/build.py` 의 `bump_cache_version()` 이 인덱스 내용의 sha1 로 자동으로 맞춘다.
> 내용 해시라서 단어가 안 바뀌면 값도 안 바뀌고, 의미 없는 커밋이 안 생긴다.

**폰트 — 서브셋으로 셀프호스팅**

통짜 Pretendard 가변 폰트가 2MB 라 그대로 넣을 수 없었다. 현재 콘텐츠에 나오는 글자
전부 + 상용 한글 음절을 합쳐 **5,401자로 잘라 861KB**. 실제 사용분은 1,016자지만
루틴이 새 단어를 넣을 것이므로 넉넉하게 잡았다 — 글자가 빠지면 한 단어 안에서 글꼴이
섞여 보인다. Source Serif 4 는 라틴만 받는다(제목에 한글이 오면 Pretendard 가 맡는다).

**검증**: 로컬 서버를 **죽인 상태**에서 앱이 열리고, 단어 상세가 도해·대조표까지 그대로
그려지며, 폰트 둘 다 캐시에서 로드된다. 캐시 항목 30/30. 배포본에서도 SW 등록 확인.

**진도는 `localStorage` 그대로**

홈 화면 앱으로 설치하면 Safari 의 7일 저장소 삭제(ITP) 대상에서 빠지므로 지금보다
오히려 안전해진다. iOS 는 홈 화면 웹앱과 Safari 탭의 저장 공간을 분리하므로 설치
직후 진도가 비어 보인다 — 진도 이전이 불필요하다고 확정했으므로 문제되지 않는다.

## Part B — 데이터 구조 (실측 확정)

### 지금 아픈 것

세 지점 모두 이번 커밋 4개에서 **손대지 않았음이 확인됐다.**

1. **동기 로드.** `index.html:30` 이 `defer`·`async` 없이 1.33MB 를 받는다.
   파싱이 끝날 때까지 첫 화면이 안 그려진다.
2. **목록에 필요 없는 것까지 지고 시작한다.** 아래 실측 참조.
3. **`allTerms()` 가 호출마다 전체 재구축.** `js/store.js:168`.
   `js/store.js:222·225·228` 3회 + `231`의 `reviewQueue()` 내부 1회 = **연속 4회**.
   탭바는 화면 전환마다 `reviewQueue()` 를 부른다 (`js/app.js:111`).

### 실측 — 무엇이 1.33MB 를 차지하나

| 필드 | 바이트 | 비중 | 어디서 쓰나 |
|---|---|---|---|
| `sections` | 751,746 | 62.9% | 상세 화면 접이식 |
| `figure` | 108,831 | 9.1% | 상세 화면 도해 |
| `related` | 92,659 | 7.8% | 상세 화면 + **퀴즈** |
| `recap` | 61,718 | 5.2% | 상세 화면 |

**상위 6개 필드가 94%다. 전부 상세 화면에서만 쓰인다.**

### 해법 — ✅ 구현·배포 완료 (`74c4d5d`)

**(1) 생성 파일 최소화** — `json.dumps` 의 들여쓰기를 뺐다. 생성물이라 사람이 읽을
일이 없는데 13%가 공백이었다.

**(2) 인덱스와 본문을 분리했다**

```
data/index.js          단어장 메타 + 단어별 경량 필드          143 KB  ← 항상 로드
data/terms/<book>.js   본문                                  37~164 KB/권  ← 지연 로드
```

**시작 시 파싱량 1.33MB → 143KB (89% 감소).** 실측 DOMContentLoaded 22ms.

**필드 배치 — 여기가 함정이었다.** 소비처를 전수 조사해 확정했다.

| 인덱스 (`data/index.js`) | 본문 (`data/terms/<book>.js`) |
|---|---|
| `id`, `term`, `reading`, `summary`, `category` | `definition`, `analogy`, `sections` |
| **`aliases`** — `js/screens.js:518-519` 가 관련용어 링크를 풀 때 **전 단어**의 aliases 를 뒤진다. 본문에만 두면 다른 권 청크를 로드하기 전엔 링크가 전부 끊긴다 | `figure`, `recap`, `check` |
| **`related` 전체** ⚠️ 계획 변경 | — |

> **계획에서 바뀐 것**: 원래는 `related` 의 단어명만 인덱스에 남겨 92KB → 11KB 로
> 줄이려 했다. 구현 중에 `js/quiz.js:208,234` 가 `r.term` 과 `r.note` 를 **객체로**
> 쓰는 것을 발견했다. 이름 문자열 배열로 바꿨으면 관련용어 퀴즈의 해설이
> `undefined` 가 됐을 것이다. 81KB 를 더 쓰고 동작을 보존했다 — 그래도 89% 감소다.

**(3) `allTerms()` 를 한 번만 만들어 재사용한다** — 인덱스 기반으로 최초 1회 구축하고
캐시한다. `termById` 는 별도 해시맵을 쓴다.

**(4) 본문은 `<script>` 주입으로 받는다** — `fetch` 는 `file://` 에서 CORS 에 막힌다.
이 앱은 `index.html` 더블클릭으로 여는 것도 지원한다.

**(5) 라우터가 동기 렌더라 상세 화면은 스켈레톤 → 재렌더** — 청크가 없으면 제목과 한 줄
뜻을 먼저 보여주고 도착하면 `App.render()` 로 다시 그린다. 단어장 목록에 들어가면 그 권을
미리 받아두므로 실제로는 이 화면을 거의 안 본다. `markOpened` 는 본문을 실제로 보여줄
때만 부른다 — 로딩 화면을 스쳐도 "읽는 중"이 되면 안 된다.

**검증**: 홈·목록·검색·상세·퀴즈·진도 전부 헤드리스로 통과, 콘솔 오류 0건.
퀴즈는 본문 청크 0개 상태로 8문제를 끝까지 진행한다.

**소비자 전수** — `js/screens.js`, `js/quiz.js`, `js/quiz-screens.js`, `js/recall.js`,
`js/app.js`. `recall.js` 는 `summary` 만 쓰므로 인덱스로 충분하다.

## Part B-3 — 단어장 구조 검수 (신규)

사용자 요청: "단어장이 12권으로 늘었는데 어떻게 할지, 단어가 계속 늘어날 것도 고려해서."

### 결론: 현상 유지. 단, 발동 임계치를 **한 권 40단어**로 확정한다

**먼저 깨지지 않는 곳부터** — 실측 결과 화면 3개는 성장에 안전하다.

- **홈**: 상수 크기다. 다음 행동 1개 + 진행 중 상위 2권(`slice(0,2)`) + 최근 3개
  (`js/screens.js:132-151, 191-230`). 단어가 몇 개든 안 늘어난다.
- **단어장 목록**: 12권 평면 나열 ≈ 2화면 (`js/screens.js:264-282`). **카테고리 고정
  정책 덕에 앞으로도 안 늘어난다.**
- **퀴즈 범위 선택**: 스코프 2 + 권 12행 ≈ 1.5화면. 같은 이유로 고정.

**먼저 깨지는 곳은 권 내부다.**

1. **권 내 정렬에 교육적 순서가 없다.** 파일명 가나다순이라 `cs` 첫 3개가
   async-await, big-o, binary 다 (`tools/build.py:532`). 루틴이 넣는 신규 단어가
   알파벳 위치에 따라 **사용자 진행 위치 앞에 삽입**되어, 홈의 "다음 단어"가
   방금 들어온 단어로 뒤로 점프한다 (`js/store.js:221-235`). 주 6개 유입이면 상시화된다.
2. **권 스코프 퀴즈가 8문제 고정 샘플**이다 (`js/quiz-screens.js:39`). `sec` 34개 기준
   커버리지 24%, 80개면 10%로 희석된다.
3. **권 내 목록은 검색 + 상태 필터 5종**으로 방어된다 (`js/screens.js:288-310`).
   50~60개까지는 버틴다. Anki 의 표준 권고(다단 하위덱 지양, 단일 덱 + 필터)와 같은 패턴이다.

### 후보 검토

| 후보 | 판정 |
|---|---|
| 분야 묶음 (4분야 아래 12권) | **불필요.** 권 목록이 카테고리 고정으로 안 늘어난다 |
| **임계치 분권** (40개 넘으면 권 쪼개기) | **금지.** id 가 `{bookId}--{slug}` 라 권을 쪼개면 이동한 단어의 진도가 전부 고아가 된다 |
| **권내 단계** (`level`: 기초/중급/심화) | **채택 (조건부).** 순서 문제 · 퀴즈 희석 · 완주 단위를 동시에 푼다 |
| 현상 유지 | **지금은 이것.** 최대 권이 34로 40 미만 |

### 실행 규칙

1. **발동 조건** — 한 권이 **40단어를 넘으면** 그 권부터 `level` 도입.
   권 수 임계는 불필요 (정책상 12 고정).
2. **대응 방식** — 반드시 **권내 단계**. **분권은 진도 키를 파괴하므로 영구 금지.**
3. **도달 시점** — 1차판의 "1년 뒤"는 **과대 추정이었다.** 주 +6이 12권에 균등
   분산돼도 `sec` 는 주 +0.5로 34→40에 **12주(약 3개월)**. `vocab-trend`·`vocab-related`
   가 링크 밀도 높은 큰 권(`sec`·`net`·`ai`)에 편중되면 더 빠르다.
4. **선제 조치** — Part C 실행 기록(`logs/`)에 **권별 단어 수 스냅샷**을 넣어 40 초과를
   루틴 로그에서 자동 감지한다. 루틴에는 "대상 권이 40개 이상이면 추가 금지, 사유 기록".

선례: Duolingo 2022 학습 경로 개편(자유 선택 트리 → 섹션 > 유닛 소단위 선형 경로)이
"끝낼 수 있는 덩어리 + 내포된 순서"의 효과를 보여준다.

### 분류 배정 규칙

"기존 폴더에만 쓴다"는 필요조건일 뿐 배정을 결정하지 못한다. 저장소에는 반직관적
정착 사례가 있다:

```
MCP → 네트워크        gRPC → 웹개발       Cookie·Session → 보안
Container·Docker → 개발도구               Kubernetes·CI_CD → 인프라
```

**원칙: 오배정이어도 이동하지 않는다.** 파일을 옮기면 book id 가 바뀌어 id 가 바뀌고
진도가 고아가 된다. 루틴에는 **"추가만 하고 절대 수정·이동·삭제하지 않는다"** 를
안전 불변식으로 명시한다. 이 불변식을 지키는 한 신규 단어 id 는 기존 어떤 id 와도
충돌하지 않고 기존 진도가 구조적으로 안전하다.

### 출처 기준 — 1차 출처만

`tools/sources.allowlist.md` 를 루틴과 검증자가 함께 읽는다. **작성 완료.**
각 단어는 서로 다른 도메인의 출처를 **최소 2개** 인용한다. 못 채우면 탈락.
루틴은 이 파일을 수정하지 않는다.

### 검증 — 3층 ✅ 구현됨 (`tools/verify_new_terms.py`)

기계 판정 두 층을 **한 스크립트로 묶었다.** 루틴은 이것만 부르면 된다.

```bash
python3 tools/build.py
python3 tools/verify_new_terms.py --expect 2
```

| 층 | 무엇을 보나 | 판정 |
|---|---|---|
| 1 | `check_template.py` 를 새 파일마다 | 기계 (결정론적) |
| 2 | AI 자기 재검증 — 인용 URL 을 다시 열어 문장 대조 | 사실 정확성 |
| 3 | 빌드 제외 0건 **AND** 단어 수 정확히 +N | 기계 |

**⚠️ 3층을 "exit 0"으로 판정하면 안 된다.** `FOLDER_TO_BOOK` 미등록 폴더의 단어는
`dropped` 에 기록되지만 **stderr 에만 찍히고 `main()` 은 0을 반환한다.** 새 폴더를
만들면 1·2·3층을 전부 통과하고도 **앱에서 조용히 사라진다.**

`verify_new_terms.py` 가 `--dry-run` 의 stderr 를 파싱해 이걸 잡는다. 가짜 폴더에
단어를 만들어 **실제로 재현해 검증했다**:

```
FAIL  빌드가 단어를 버렸다. 제외 1건 — TestGhost: 단어장이 없는 폴더 데브옵스
      FOLDER_TO_BOOK 에 없는 폴더에 파일을 만들었을 가능성이 높다.
```

단어 수 검사는 **기존 단어를 밀어내는 경우도 함께 잡는다** — 제목이 겹치면 `pick_one`
이 한쪽을 조용히 버리는데, 그러면 +2 가 아니라 +1 이 되어 실패한다.

**1층은 표를 복제하지 말고 위임한다.** 이번 범위에서 검사기가 5건 강화됐고
(대조 줄 3~4 신설, 정의 첫 문단 정확히 한 문장, 되묻기 검출 확대, `💻 코드 구현` 섹션
금지, H2 제목 중복 금지), 원래부터 표에 없던 검사도 10여 건이다 (흐름 마디 이름 8자,
층 3~5, 도해 첫 줄 `모양: 질문` 형식, H1 필수, 정의 안 `### 비유` 필수, 그림 섹션은
도해 정확히 1개, mermaid 금지, 도해 `= 한 줄 결론` 필수).
→ 프롬프트에는 **"`docs/TERM-TEMPLATE.md` 를 읽고 `check_template.py` 판정을 따르라"**
로 위임한다. 표를 복제하면 검사기가 강화될 때마다 프롬프트가 낡는다.

**2층 운영 원칙**: 검증자는 새 컨텍스트에서 시작하며 집필 과정을 보지 않는다.
떨어뜨릴 권한을 갖는다. 통과가 기본값이 아니다. **판단이 서지 않으면 탈락시킨다.**

**추가 탈락 규칙**: 신규 단어의 slug 가 대상 권의 기존 slug 와 충돌하면 탈락.
충돌 시 `-2` 접미가 제목 정렬 순서에 의존해 **기존 단어의 id 를 빼앗을 수 있다**
(`tools/build.py:532, 562-567`).

안전망: 잘못 들어가도 `git revert` 한 번으로 되돌아간다.

### 도해 작성 부담

`🖼️ 그림으로 보기` 가 필수 섹션이다. 세 종류:

```
흐름:  단계 순서 (마디 4~7개, 마디 이름 8자 이내)
대조:  두 상태 나란히 (데이터 줄 3~4개, 칸 14자 이내)
층:    쌓인 구조 (3~5층)
= 한 줄 결론  ← 필수
```

첫 줄은 `모양: 질문` 형식이고 제목은 물음이어야 한다.
본보기: `content/네트워크/DNS.md` (세 유형 전부 사용), `content/네트워크/HTTP.md`.

### 실행 기록

`logs/routine-YYYY-MM-DD-<전략>.md` 를 커밋한다. 내용: 후보 목록, 3층 각각의
통과·탈락과 사유, 인용 출처, **권별 단어 수 스냅샷**(40 초과 감지용), 최종 커밋 SHA.

### 프롬프트 요건

클라우드 에이전트는 컨텍스트 0에서 시작한다. 자기완결적이어야 한다.

- 저장소 구조와 **폴더명 15개 목록** (단어장 12권 ≠ 폴더 12개 — 폴더명을 직접 나열)
- **루트에 파일을 만들지 말 것. 반드시 폴더 안에.** 새 폴더 생성 금지
- `docs/TERM-TEMPLATE.md` 를 읽고 `content/네트워크/DNS.md` 를 본보기로 삼을 것
- `tools/sources.allowlist.md` 의 1차 출처만, 최소 2개
- 회당 2개 상한. 대상 권이 40개 이상이면 추가 금지
- 3층 검증 절차와 "애매하면 탈락"
- **안전 불변식: 추가만 한다. 수정·이동·삭제·개명 금지. BOOKS 수정 금지**
- `git pull --rebase` → `build.py` → `CACHE_VERSION` 갱신 → 실행 기록 → push
- 코드 예시를 쓸 일이 생기면 반드시 언어 태그를 붙일 것 (태그 없는 펜스는 도해
  휴리스틱 분류에 맡겨진다). 단 템플릿상 코드 섹션이 제거됐으므로 기본은 안 쓰는 것
