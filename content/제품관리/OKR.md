# OKR (Objectives and Key Results)

## 📝 정의

OKR은 **목표 하나에 달성 여부를 잴 숫자를 붙이는 틀**이다.

Objective 는 어디로 갈지를 말로 적고, Key Results 는 거기 닿았는지를 숫자로 적는다. 앞은 정성적이고 뒤는 정량적이라 역할이 겹치지 않는다.

### 비유
등산 계획. 정상까지 간다는 게 목표고, 몇 번째 대피소를 언제 지났는지가 지금 어디쯤인지 말해주는 숫자다.

## 🖼️ 그림으로 보기

```도해
흐름: 한 분기의 OKR 은 어떤 순서로 굴러가나
분기 시작 :: 어디로 갈지를 한 문장으로 적는다
KR 붙이기 :: 닿았는지 잴 숫자를 두셋 정한다
매주 :: 그 숫자가 어디까지 왔는지만 본다
분기 말 :: KR 마다 달성률을 매긴다
< 다음 분기 :: 왜 못 갔는지 보고 목표를 다시 적는다
= 목표는 말로 적고 진행은 숫자로만 본다
```

## ⚠️ 해결하는 문제

```도해
대조: 목표를 말로만 적으면 무엇이 달라지나
숫자 없이 || KR 을 붙이면
달성 판단 :: 사람마다 다르다 || 숫자 하나로
중간 점검 :: 느낌으로 한다 || 진척률로 본다
목표 수준 :: 쉬운 걸 고른다 || 크게 잡는다
= 다 했다는 말이 사람마다 다르게 들리는 걸 막는다
```

"최고의 사용자 경험 제공" 같은 목표는 분기가 끝나도 됐는지 안 됐는지 다투게 된다. 누구는 됐다고 하고 누구는 아직이라고 한다. 다툼이 싫으면 애초에 재기 쉬운 목표를 고르게 되고, 그러면 목표가 작아진다.

KR 은 그 자리에 숫자를 놓는다. NPS 70점, 앱 크래시율 1% 이하, 페이지 로딩 시간 2초 이하처럼 분기 말에 한 번 재면 판정이 끝나는 것들이다. 판정을 숫자에 맡겼기 때문에 목표 쪽은 도리어 크게 잡을 수 있다.

## ⚙️ 작동 원리

Objective 는 한 문장이고 숫자가 들어가지 않는다. 그 아래 KR 은 둘에서 셋이고 전부 숫자다. 숫자에는 기한이 붙는데, 대개 그 분기의 마지막 날이다.

```도해
층: 같은 분기에 OKR 은 어디까지 적히나
회사 :: 최고의 사용자 경험 제공
팀 :: 회사 KR 하나를 받아 자기 목표로 삼는다
개인 :: 팀 KR 에 닿을 자기 숫자를 적는다
= 위층의 KR 이 아래층의 Objective 가 된다
```

달성률은 100%를 기준으로 보지 않는다. 전부 채웠다는 건 대개 목표를 안전하게 잡았다는 뜻이라, 70% 근처를 정상으로 놓고 읽는다.

## 📊 비교: OKR vs KPI

| | OKR | KPI |
|---|---|---|
| 무엇을 하나 | 도전적 목표를 민다 | 현상을 지키고 잰다 |
| 주기 | 분기별 | 지속적 |
| 달성률 | 70% 를 정상으로 본다 | 100% 를 지켜야 한다 |

## 💡 실제 사례

- **회사 분기 목표** — "최고의 사용자 경험 제공"에 NPS 70점, 크래시율 1% 이하, 로딩 2초 이하를 붙인다.
- **개인 성장 계획** — "AI 전문가 되기"에 LLM 프로젝트 3개, 논문 10편, 기술 블로그 12편을 붙인다.
- **주간 점검** — 목표를 다시 읽는 게 아니라 KR 숫자가 지난주보다 얼마나 움직였는지만 확인한다.

## 🚫 흔한 오해

- **KR 을 다 채우는 게 잘한 것이다** — 전부 채웠으면 목표를 쉽게 잡았다고 본다. OKR 은 70% 근처를 정상으로 놓는다.
- **OKR 은 할 일 목록이다** — 할 일이 아니라 결과다. "블로그를 쓴다"가 아니라 "블로그 12편"처럼 끝났을 때 잴 수 있는 것으로 적는다.
- **Objective 도 숫자로 적어야 한다** — 숫자는 KR 이 맡는 자리다. 목표까지 숫자로 적으면 어디로 가는지가 지표 하나로 쪼그라든다.

## 📝 정리

OKR은 목표를 말로 적고 그 옆에 달성 여부를 잴 숫자를 붙이는 틀이다. 판정을 숫자에 맡겼기 때문에 목표 자체는 크게 잡을 수 있고, 다 못 채우는 쪽을 정상으로 본다. Objective 는 어디로 갈지를 맡고 Key Results 는 거기 닿았는지를 맡는다.
