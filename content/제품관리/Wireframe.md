# Wireframe (와이어프레임)

## 📝 정의

Wireframe은 **색과 꾸밈을 뺀 화면 설계도**다.

무엇이 어디에 놓이고 무엇을 하는지만 회색 상자와 글자로 표시한다. 이미지도 색도 글꼴도 정하지 않기 때문에 몇 분 만에 그리고 그만큼 쉽게 버릴 수 있다.

### 비유
건축 도면. 벽과 문의 위치만 그려져 있고 벽지 색이나 가구는 없다. 벽을 옮기자는 이야기는 도면 위에서 해야 싸다.

## 🖼️ 그림으로 보기

```도해
흐름: 와이어프레임 한 장은 어떤 순서로 만들어지나
요소 모으기 :: 이 화면에 무엇이 들어가야 하는지 적는다
자리 잡기 :: 회색 상자로 크기와 위치만 배치한다
주석 달기 :: 누르면 어디로 가는지 옆에 적어둔다
보여주기 :: 팀에 돌려 빠진 것과 어색한 곳을 듣는다
@ 고치기 :: 지우고 다시 그린다. 몇 분이면 된다
= 되돌리는 값이 쌀 때 어긋난 곳을 찾아내는 것이 목적이다
```

## ⚠️ 해결하는 문제

```도해
대조: 버튼 위치를 바꾸자는 말이 언제 나오면 싼가
디자인부터 하면 || 먼저 그려보면
고치는 비용 :: 며칠이 날아감 || 몇 분이면 끝
팀의 그림 :: 각자 다르다 || 같은 것을 본다
빠진 화면 :: 개발 중에 발견 || 미리 보인다
= 어긋난 곳은 되돌리기 싼 단계에서 찾아야 한다
```

디자인을 3주 걸려 마친 뒤에야 버튼 위치가 이상하다는 말이 나오면 그 3주가 다시 든다. 같은 지적이 종이 스케치 단계에서 나왔다면 지우고 다시 그리는 데 몇 분이면 된다.

말로만 정하면 각자 다른 그림을 상상하는 것도 문제다. "여기에 검색 기능"이라는 한마디를 두고 기획은 왼쪽 위를, 개발은 오른쪽 아래를 떠올린다. 화면을 한 장 그려 놓고 이야기하면 그 차이가 그 자리에서 드러나고, 전체 화면을 늘어놓으면 아예 빠뜨린 화면도 눈에 띈다.

## ⚙️ 작동 원리

```도해
층: 와이어프레임은 어느 정도까지 그리나
저해상도 :: 종이에 손으로. 몇 분이면 그린다
중해상도 :: 도구로 실제 크기에 맞춰. 한 시간쯤
고해상도 :: 눌러서 넘어가는 프로토타입까지. 하루쯤
= 아래로 갈수록 정확해지고 그만큼 고치기 아까워진다
```

그리는 규칙이 몇 가지 있다. 이미지 자리는 회색 상자로만 두고 색과 글꼴은 손대지 않는다. 대신 문구는 실제로 쓸 것을 넣는다. 그래야 제목이 두 줄로 넘어가거나 버튼 안에 글자가 안 들어가는 문제가 그 자리에서 보인다.

동작도 적어둔다. 그림만 있으면 같은 화면을 보고도 누른 뒤에 무슨 일이 일어나는지를 각자 다르게 상상한다. 검색창 옆에 세 글자부터 제안이 뜬다고 적어두는 식으로 옆에 짧게 붙인다. 화면 크기가 여럿이면 좁은 화면 것도 같이 그린다.

## 💡 실제 사례

- **회의 전 종이 스케치** — 논의할 화면을 몇 분 만에 그려 놓고 그 위에서 이야기를 시작한다.
- **화면 목록에서 빠진 것 찾기** — 전체 화면을 늘어놓으면 로그인이나 오류 화면처럼 빠뜨린 것이 드러난다.
- **개발자에게 넘기는 주석** — 요소 옆에 언제 무엇이 일어나는지 적어 넘기면 다시 물어볼 일이 준다.

## 🚫 흔한 오해

- **와이어프레임이 나오면 그대로 만들면 된다** — 뼈대까지만 정한 것이다. 그대로 개발로 넘기면 디자인 단계가 통째로 빠진 채 화면이 나온다.
- **와이어프레임은 디자이너가 그려서 넘겨주는 것이다** — 혼자 완성해 넘기면 볼 사람의 의견이 빠진다. 기획과 디자인과 개발이 같이 그릴 때 빠진 화면과 만들기 어려운 동작이 미리 나온다.
- **글자는 아무거나 채워 넣어도 된다** — 의미 없는 채움 글로 채우면 실제 문구의 길이를 못 본다. 제목이 몇 줄이 되는지, 목록 한 줄에 몇 글자가 들어가는지가 레이아웃을 바꾼다.

## 🚨 주의사항

- **색과 글꼴을 정하기 시작하면 멈춘다.** 회색만 쓰는 이유는 구조 이야기가 색 이야기에 밀리지 않게 하려는 것이다.
- **누른 뒤에 무슨 일이 일어나는지 반드시 적는다.** 이게 없으면 화면은 같아 보여도 동작을 각자 다르게 만든다.

## 📝 정리

Wireframe은 색과 꾸밈을 빼고 구조와 동작만 남긴 화면 설계도다. 빨리 그리고 쉽게 버릴 수 있어서 되돌리는 값이 쌀 때 어긋난 곳을 찾아내는 데 쓴다. 디자인을 대신하지 않으며 여기서 합의한 구조 위에 디자인이 올라간다.
