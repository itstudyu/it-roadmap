# Wireframe (와이어프레임)

## 📝 정의

Wireframe은 **웹사이트나 앱의 골격을 보여주는 저해상도 설계도**입니다. 디자인이나 색상 없이 구조, 레이아웃, 기능만 표현합니다.

### 핵심 개념

- **무엇인가?**: UI/UX의 청사진
- **왜 필요한가?**: 빠른 아이디어 검증, 의사소통
- **특징**: 흑백, 단순, 빠르게 제작

### Wireframe이 해결하는 문제

**문제 상황**:
```
😱 시나리오 1: 비싼 수정
디자이너: 3주 작업해서 완성!
PM: "아, 버튼 위치가 이상한데..."
→ 3주 다시! 😱

😱 시나리오 2: 의사소통 실패
PM: "여기에 검색 기능"
디자이너: (왼쪽 상단 상상)
개발자: (오른쪽 하단 상상)
→ 각자 다른 그림! 😱

😱 시나리오 3: 기능 누락
개발 완료 후
PM: "로그인 화면은요?"
→ 깜빡! 😱
```

**Wireframe의 해결**:
```
✅ 시나리오 1: 빠른 검증
종이에 스케치 (30분)
→ 피드백 받고 수정 (10분)
→ 합의 후 디자인 시작! ✅
→ 시간/비용 절약!

✅ 시나리오 2: 명확한 소통
와이어프레임 공유
"여기 검색창, 여기 필터"
→ 모두가 같은 그림 봄! ✅

✅ 시나리오 3: 전체 흐름 파악
모든 화면 와이어프레임
→ 누락 없음
→ 사전 발견! ✅
```

## 📝 정리

**Wireframe의 핵심**:
```
Wireframe = UI의 청사진
→ 구조만 표현 (디자인 ❌)
→ 빠른 검증
→ 의사소통 도구
```

**종류**:
```
Low: 종이 스케치 (5분)
Mid: 디지털 와이어프레임 (1시간)
High: 상세 프로토타입 (1일)
```

**작성 순서**:
```
1. 정보 구조 정리
2. 레이아웃 스케치
3. 주석 추가
4. 피드백 받기
5. 수정 반복
```

**원칙**:
```
✅ 단순하게 (회색톤)
✅ 실제 콘텐츠
✅ 인터랙션 표시
✅ 협업하며 작성
```

**비유로 기억하기**:
```
Wireframe = 건축 도면
→ 방 배치만 (인테리어 ❌)
→ 벽 위치, 문 위치
→ 빠르게 그리고 수정
→ 모두가 같은 그림 보고 논의

"디자인 전에 구조부터"
```
