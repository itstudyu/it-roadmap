# A/B Testing (A/B 테스트)

## 📝 정의

A/B Testing은 **두 버전을 동시에 내보내 어느 쪽이 나은지 재는 실험**이다.

같은 화면을 두고 의견이 갈릴 때 말로는 끝나지 않는다. 사용자를 무작위로 나눠 한쪽에는 A를, 다른 쪽에는 B를 보여주고 같은 기간의 숫자를 비교한다.

### 비유
같은 국을 두 냄비에 나눠 끓이면서 한쪽만 간을 다르게 해보는 것과 같다.

## 🖼️ 그림으로 보기

```도해
흐름: 버튼 색을 바꾸면 정말 나아지는지 어떻게 아나
가설 :: 초록 버튼이 클릭을 늘린다고 적어둔다
분배 :: 사용자를 무작위로 절반씩 나눈다
수집 :: 그룹별 노출 수와 전환 수를 센다
검정 :: 이 정도 차이가 우연일 확률을 계산한다
< 판단 :: 우연이 아니면 이긴 쪽을 전체에 적용한다
= 이긴 안을 고르는 절차가 아니라, 차이가 우연인지 가르는 절차다
```

## ⚠️ 해결하는 문제

```도해
대조: 실험 없이 정하면 무엇이 달라지나
실험 없이 || A/B 테스트로
결정 근거 :: 직급 높은 사람 || 전환율 숫자
실패 비용 :: 전원이 겪는다 || 절반만 겪는다
되돌리기 :: 이미 늦다 || 바로 되돌린다
= 누가 옳은지 다투던 자리를 무엇이 옳은지 재는 자리로 바꾼다
```

새 디자인을 전체 사용자에게 한 번에 적용하면, 그게 나쁜 선택이었다는 걸 지표가 떨어진 다음에야 알게 된다. 이미 모두가 겪은 뒤라 되돌려도 손해는 남는다.

절반에게만 보여주면 나머지 절반이 비교 기준이 된다. 같은 기간, 같은 트래픽에서 잰 숫자이기 때문에 계절이나 광고 때문에 오른 것과 버튼 때문에 오른 것을 구분할 수 있다.

## ⚙️ 작동 원리

두 그룹의 전환율은 어차피 다르게 나온다. 같은 화면을 보여줘도 사람이 달라서 숫자는 늘 흔들린다. 그래서 실험이 묻는 것은 "차이가 있나"가 아니라 "이 정도 차이가 흔들림만으로 나올 수 있나"다.

이 확률을 p-value라고 한다. 기준을 0.05로 잡으면, 실제로는 아무 차이가 없는데 이만큼 벌어질 확률이 5% 미만일 때만 이겼다고 본다.

표본이 적으면 흔들림이 커서 웬만한 차이는 우연으로 설명된다. 그래서 시작 전에 그룹당 몇 명이 필요한지 계산해두고, 그 수를 채우기 전에는 결과를 보고 멈추지 않는다. 기간도 최소 한 주는 잡는다. 요일마다 오는 사람이 다르기 때문이다.

## 📊 비교: A/B 테스트와 비슷한 방식들

| | A/B 테스트 | 다변량 테스트 | 밴딧 |
|---|---|---|---|
| 나누는 것 | 한 요소, 두 안 | 여러 요소의 조합 | 여러 안 |
| 트래픽 배분 | 끝까지 고정 | 끝까지 고정 | 잘 되는 쪽으로 옮김 |
| 필요한 인원 | 적다 | 많다 | 중간 |
| 쓸 때 | 결론을 남기고 싶을 때 | 요소끼리의 영향을 볼 때 | 빨리 최적화하고 싶을 때 |

## 💡 실제 사례

- **버튼과 문구** 색이나 문장 한 줄만 바꾸고 클릭률을 비교한다. 바꾼 게 하나라서 원인을 지목할 수 있다.
- **위험한 배포** 새 결제 흐름을 절반에게만 열어두고, 지표가 떨어지면 그 절반만 되돌린다.
- **AA 테스트** 똑같은 화면을 A와 B로 나눠 돌려본다. 여기서 차이가 나오면 실험 장치 자체가 고장 난 것이다.

## 🚫 흔한 오해

- **유의미한 차이가 보이면 바로 끝내도 된다** — 초반 숫자는 크게 흔들린다. 정해둔 표본 수와 기간을 채우기 전에 멈추면 우연을 실력으로 착각하게 된다.
- **이긴 쪽이 더 좋은 안이다** — 정해둔 지표 하나가 이긴 것이다. 클릭은 늘었는데 구매가 줄었다면, 무엇을 기준으로 삼을지 먼저 정했어야 한다.
- **A/B 테스트니까 두 개만 비교하는 것이다** — 셋 이상으로도 나눌 수 있다. 다만 그룹이 늘어난 만큼 각 그룹에 필요한 인원도 같이 늘어난다.

## 🚨 주의사항

- **지표를 여러 개 걸어두고 하나라도 이기면 성공으로 치지 않는다.** 지표가 많을수록 그중 하나가 우연히 이길 확률도 같이 올라간다.
- **결과가 나온 다음에 세그먼트를 뒤지지 않는다.** "iOS에서는 이겼다"는 대개 나중에 찾아낸 것이라 다음 실험에서 재현되지 않는다.

## 📝 정리

A/B Testing은 사용자를 무작위로 나눠 두 안을 같은 조건에서 비교하는 실험이다. 이기는 안을 뽑아주는 도구라기보다, 눈에 보이는 차이가 우연인지 아닌지를 가르는 도구다. 표본 수와 기간과 판단 지표를 시작 전에 정해두지 않으면 숫자는 나와도 결론은 나오지 않는다.

## ❓ 이해했는지

- 시작한 지 하루 만에 B가 앞섰는데 여기서 멈추면 안 되는 이유는?
- 클릭률은 올랐는데 구매가 줄었다면 B가 이겼다고 할 수 있나?
- 똑같은 화면을 A와 B로 나눠 돌렸는데 차이가 나왔다면 무엇을 의심해야 하나?
