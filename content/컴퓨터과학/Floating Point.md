# Floating Point (부동소수점)

## 📝 정의

부동소수점은 **소수를 2진 근삿값으로 담는 수 형식**이다.

'부동(浮動)' 은 소수점이 떠서 움직인다는 뜻이다. 소수점 자리를 고정하지 않고 값 안에 함께 적어 두는 덕에, 같은 64비트로 10의 308제곱쯤까지 담는다. 이 형식의 규격은 IEEE 754 — '부동소수점 산술 표준' 이 정한다.

### 비유
2배씩만 반으로 나뉜 자로 길이를 재는 일 — 반이나 반의 반은 딱 맞지만 10분의 1 은 눈금 사이에 걸린다.

### 예
엑셀에서 금액을 쭉 더했더니 합계가 1원 어긋나 있던 일이 이것 때문이다.

## 🖼️ 그림으로 보기

```도해
흐름: 0.1 을 저장하면 무엇이 남나
0.1 :: 사람이 10진법으로 적은 값
2진 변환 :: `0.000110011001100…` 으로 끝없이 이어진다
자리 자름 :: 2진 53자리에서 끊고 가장 가까운 값으로 맞춘다
저장값 :: 0.1 보다 아주 조금 큰 값이 담긴다
더하기 :: 어긋난 값끼리 더하니 `0.1 + 0.2` 가 `0.3` 이 아니다
= 계산이 틀린 게 아니라, 처음부터 0.1 이 아닌 값을 더한 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 같은 64비트로 큰 수와 작은 수를 어떻게 다 담나
소수점을 고정하면 || 소수점을 띄우면
담는 범위 :: 한 폭에 갇힌다 || 10의 308제곱까지
큰 수 :: 넘쳐서 못 담는다 || 지수만 키운다
작은 수 :: 0 으로 사라진다 || 지수를 내린다
= 소수점 자리를 값 안에 함께 적어 두면, 같은 비트로 훨씬 넓은 범위를 덮는다
```

소수점 자리를 고정해 두면 담을 수 있는 범위가 그 폭에 갇힌다. 원자 크기와 별 사이 거리를 같은 형식으로 다뤄야 하는 계산에서는 한쪽이 넘치고 다른 쪽이 0 으로 사라진다.

부동소수점은 **소수점 위치를 값 안에 같이 적어서** 그 폭을 벗어난다. 지수(2의 몇 제곱인지)를 올리고 내리는 것만으로 아주 큰 수와 아주 작은 수를 한 형식에 담는다. 대신 자리 수가 유한하니 **정확함을 조금 내주는** 거래가 붙는다.

## 🧱 구성

```도해
층: 하나의 값 안에 무엇이 나뉘어 들어가나
부호 :: 양수인가 음수인가
지수 :: 2의 몇 제곱만큼 자리를 옮길지. 범위를 정한다
유효숫자 :: 2진수 53자리. 정확도를 정한다
= 지수가 범위를 넓히고 유효숫자가 정확도를 정한다. 모자란 자리는 가장 가까운 값으로 반올림된다
```

## ⚙️ 작동 원리

유효숫자가 2진 53자리라는 것은 **10진수로 믿고 쓸 수 있는 자리가 열다섯 자리쯤**이라는 뜻이다. 파이썬은 이 값을 `sys.float_info` 로 그대로 보여준다 — `radix=2`, `mant_dig=53`, `dig=15`.

10진 소수를 2진법으로 옮기면 대개 끝나지 않는 소수가 된다. 그래서 컴퓨터는 53자리 안에서 가장 가까운 값을 골라 담는다. `0.1` 을 넣으면 실제로 담기는 값은 `0.1000000000000000055511151231257827021181583404541015625` 이고, 이것은 `3602879701896397 / 2**55` 과 같은 값이다. 화면에 `0.1` 로 보이는 것은 같은 값을 가리키는 여러 10진 표기 중 가장 짧은 것을 골라 보여주기 때문이다.

## 💡 실제 사례

- **`0.30000000000000004` 가 화면에 뜬다** — `0.1 + 0.2` 를 있는 자리까지 다 보여준 값이다. 계산이 틀린 게 아니라 담긴 값이 그렇다.
- **원 단위로 어긋나는 정산** — 금액을 부동소수점으로 세면 건마다 아주 조금씩 어긋나고, 수십만 건이 쌓이면 합계가 맞지 않는다. 회계 계산에는 10진 소수 형식을 쓴다.
- **`==` 로 물어서 실패하는 검사** — 계산 경로가 다르면 마지막 자리가 갈려 같은 값이 아니게 된다. 파이썬 문서는 이럴 때 `math.isclose()` 로 견주라고 안내한다.

## 🚫 흔한 오해

- **컴퓨터가 계산을 틀리는 것이다** — 더하기는 정확하다. 애초에 `0.1` 이라고 적은 값이 0.1 이 아니어서 결과가 어긋난다.
- **미리 반올림해 두면 해결된다** — 안 된다. 0.1 은 반올림해도 1/10 에 더 가까워지지 않아서, 미리 반올림한 값끼리 더해 견줘도 여전히 같지 않다.
- **넓은 범위를 담으니 돈도 부동소수점으로 두면 된다** — 돈에 필요한 것은 넓이가 아니라 정확함이다. 10진 소수 형식이나 최소 단위 정수로 센다.

## 🚨 주의사항

- **돈에는 쓰지 않는다.** 정확한 10진 계산이 필요한 자리에는 회계용으로 만들어진 10진 소수 형식(파이썬의 `decimal` 같은)을 쓴다.
- **`==` 로 같은지 묻지 않는다.** 차이가 충분히 작은지로 묻는다. 파이썬은 그 용도로 `math.isclose()` 를 둔다.
- **1/3 같은 분수도 마찬가지다.** 2진법이든 10진법이든 끝나지 않는 소수라서, 정확히 다루려면 분수 그대로 다루는 형식이 필요하다.

## 📝 정리

부동소수점은 소수를 2진 근삿값으로 담는 형식이다. 소수점 자리를 값 안에 함께 적어 아주 넓은 범위를 덮고, 그 대가로 10진 소수 대부분을 정확히 담지 못한다. 넓이가 필요한 계산에는 이 거래가 남고, 정확한 10진 값이 필요한 돈 계산에는 다른 형식을 쓴다.

## ❓ 이해했는지

- 0.1 을 넣었는데 그와 다른 값이 담기는 과정은 → 그림
- 미리 반올림해 둬도 0.1 + 0.2 가 0.3 이 안 되는 이유는 → 흔한 오해
- 같은 64비트로 아주 큰 수까지 담을 수 있는 이유는 → 구성
