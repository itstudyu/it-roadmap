# Memory (메모리)

## 📝 정의

메모리는 **지금 쓰는 데이터를 잠시 올려두는 자리**다.

저장 장치는 크지만 느리고, CPU 옆의 자리는 빠르지만 작고 비싸다. 그래서 컴퓨터는 한 종류만 쓰지 않고 빠른 층부터 느린 층까지 여러 겹으로 나눠 쓴다.

### 비유
책상. 지금 보는 책은 책상 위에, 가끔 보는 건 서랍에, 안 보는 건 창고에 둔다.

## 🖼️ 그림으로 보기

```도해
층: 같은 값을 꺼내는데 왜 어디서 꺼내느냐가 문제가 되나
레지스터 :: CPU 안. 지금 계산 중인 값 몇 개
캐시 :: CPU 옆. 자주 쓰는 값. 나노초
RAM :: 실행 중인 프로그램 전체. 마이크로초
SSD, HDD :: 전원이 꺼져도 남는 곳. 밀리초
= 위로 갈수록 빠르고 작고 비싸다. 아래로 갈수록 그 반대다
```

## ⚠️ 해결하는 문제

```도해
대조: 저장 장치를 한 종류만 쓰면 어떻게 되나
한 종류로 || 층을 나눠서
빠른 것만 :: 값이 감당 안 됨 || 조금만 산다
느린 것만 :: CPU 가 논다 || 위층이 받아냄
전체 비용 :: 둘 중 하나 포기 || 둘 다 얻는다
= 자주 쓰는 것만 위에 올려두면 비싼 것을 조금만 사도 된다
```

CPU는 나노초 단위로 움직이는데 디스크는 밀리초가 걸린다. 값 하나를 디스크에서 꺼낼 때마다 CPU는 그동안 아무것도 못 하고 서 있다.

빠른 저장 장치를 많이 두면 되지만 값을 감당할 수 없다. 그래서 자주 쓰는 것만 위층에 올려두고 나머지는 아래에 둔다. 프로그램이 방금 쓴 값을 곧 다시 쓰는 경향이 있어서 이 방식이 실제로 통한다.

## ⚙️ 작동 원리

```도해
흐름: CPU 가 값 하나를 찾을 때 어디까지 내려가나
레지스터 :: 여기 있으면 그대로 쓴다
캐시 :: 없으면 옆 캐시를 본다
RAM :: 캐시에도 없으면 여기서 꺼낸다
복사 :: 꺼내면서 위층에도 같이 올려둔다
< 다음 번 :: 같은 값을 다시 찾으면 위에서 끝난다
= 아래로 내려갈수록 느려지고, 한 번 다녀오면 다음은 빨라진다
```

RAM이 모자라면 운영체제는 한동안 안 쓴 부분을 디스크로 밀어낸다. 이걸 스왑이라고 하는데, 밀려난 부분을 다시 쓰려 하면 디스크까지 다녀와야 해서 갑자기 느려진다. 프로그램이 멈춘 것처럼 느려지고 디스크가 계속 도는 상황이 대개 이 경우다.

## 📊 비교

| | 캐시 | RAM | SSD |
|---|---|---|---|
| 속도 | 나노초 | 마이크로초 | 밀리초 |
| 용량 | KB~MB | GB 단위 | GB~TB |
| 전원이 꺼지면 | 사라진다 | 사라진다 | 남는다 |
| 관리 | CPU가 알아서 | 운영체제 | 파일 시스템 |
| 담는 것 | 자주 쓰는 값 | 실행 중인 프로그램 | 오래 두는 파일 |

## 💡 실제 사례

- **브라우저 탭** 탭을 열 때마다 RAM을 더 쓰고, 모자라면 운영체제가 한동안 안 본 탭을 디스크로 밀어낸다.
- **게임 로딩 화면** 디스크에 있던 자원을 RAM으로 올리는 시간이고, 올라간 뒤에는 화면이 부드럽게 돈다.
- **두 번째가 빠를 때** 첫 번째에 꺼낸 값이 위층에 남아 있어서 아래층까지 다시 내려가지 않는다.

## 🚫 흔한 오해

- **메모리와 저장 공간은 같은 말이다** — 다르다. 메모리는 지금 돌고 있는 것을 올려두는 자리고, 저장 공간은 전원이 꺼져도 남는 곳이다.
- **RAM을 늘리면 컴퓨터가 빨라진다** — 모자라던 경우에만 그렇다. 이미 남고 있으면 늘려도 달라지는 게 없다.
- **캐시는 개발자가 넣고 빼는 것이다** — CPU 캐시는 알아서 채워지고 밀려난다. 개발자가 하는 일은 값을 가까이 모아 두어 적중률을 올리는 쪽이다.

## 📝 정리

메모리는 지금 쓰는 데이터를 올려두는 자리이고, 속도와 용량이 반대로 가기 때문에 여러 층으로 나뉘어 있다. 자주 쓰는 것만 위층에 두는 방식으로 비싼 것을 조금만 사고도 빠르게 쓴다. 위층에서 못 찾는 횟수가 곧 체감 속도다.

## ❓ 이해했는지

- 같은 계산을 두 번째로 돌리면 더 빠른 이유는?
- 프로그램이 갑자기 느려지고 디스크가 계속 돈다면 무엇이 벌어진 것인가?
