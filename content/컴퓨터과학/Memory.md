# Memory

## 📝 정의

메모리는 컴퓨터가 현재 사용 중인 데이터와 명령어를 임시로 저장하는 공간입니다. 메모리는 CPU와 가까울수록 빠르지만 용량이 작고, CPU에서 멀어질수록 느리지만 용량이 큰 계층 구조를 이룹니다. 최상위 계층의 레지스터(Registers)에서 시작하여 캐시(Cache), RAM(Random Access Memory), SSD, HDD 순서로 구성되어 있으며, 각 계층은 자신의 역할을 수행합니다. 메모리 계층 구조의 핵심은 속도와 용량의 트레이드오프(Trade-off)로, CPU의 빠른 처리 속도와 저장 장치의 큰 용량을 동시에 활용하기 위한 설계입니다.

> **한 줄 요약**: 메모리는 CPU가 빠르게 접근하는 상위 계층에서 느리지만 용량이 큰 하위 계층까지 계층화된 데이터 저장소입니다.

### 비유
- 🔵 **사무실 수납 체계**: 자주 사용하는 물건은 책상 위(레지스터)에, 가끔 쓰는 것은 서랍(RAM)에, 거의 안 쓰는 것은 창고(HDD)에 보관하는 것처럼, 메모리도 사용 빈도에 따라 저장 위치를 나눕니다.
- 🟡 **가게의 진열 방식**: 인기 상품은 계산대 앞(캐시)에, 일반 상품은 선반(RAM)에, 창고 상품은 물류센터(HDD)에 둡니다.

## 🎯 핵심 개념

### 1. 메모리 계층 구조와 속도 트레이드오프
메모리는 CPU에 가까울수록 접근 속도가 빠릅니다. 레지스터는 나노초(ns) 단위로 접근 가능하지만 수KB 규모입니다. L1 캐시는 몇 나노초, L2/L3 캐시는 더 느리지만 용량은 증가합니다. RAM은 마이크로초(μs) 단위로 접근하며 수GB 규모입니다. SSD와 HDD는 밀리초(ms) 단위로 접근하지만 용량은 테라바이트(TB) 규모입니다. 이 계층화는 CPU의 초고속 처리와 대용량 데이터 저장이라는 상충하는 요구사항을 동시에 만족시키기 위한 설계입니다. CPU의 속도에 맞춰 빠른 메모리를 많이 두면 비용이 너무 높아지고, 느린 메모리만 두면 CPU가 대기하는 시간이 늘어납니다.

### 2. 휘발성과 비휘발성 메모리
메모리는 전원이 꺼지면 데이터가 지워지는지 여부로 분류됩니다. 레지스터, 캐시, RAM은 휘발성 메모리로, 전원이 끊어지면 모든 데이터가 손실됩니다. 대신 접근 속도가 빠릅니다. SSD와 HDD는 비휘발성 메모리로, 전원이 꺼져도 데이터가 영구적으로 보관됩니다. 비휘발성이지만 접근 속도는 훨씬 느립니다. 운영체제와 애플리케이션은 이 특성을 활용하여 자주 사용하는 데이터는 RAM에, 장기 보관이 필요한 데이터는 SSD/HDD에 저장합니다.

### 3. CPU의 메모리 접근 과정
CPU가 데이터를 필요로 할 때, 먼저 가장 가까운 레지스터를 확인합니다. 없으면 L1 캐시, 그 다음 L2, L3 캐시 순서로 확인합니다. 캐시에 없으면 RAM에서 찾고, RAM에도 없으면 SSD/HDD에서 로드합니다. 메모리에서 찾은 데이터는 더 빠른 계층으로 복사되어, 다음에 같은 데이터를 접근할 때는 더 빠르게 얻을 수 있습니다. 이 과정에서 캐시 히트(찾음)와 캐시 미스(못 찾음)의 빈도가 성능에 큰 영향을 미칩니다.

## ⚠️ 해결하는 문제

### 문제 1: CPU와 저장 장치의 속도 불균형
CPU는 수 GHz 속도로 계산하지만, HDD는 밀리초 단위로 데이터를 읽습니다. 이 엄청난 속도 차이로 인해 CPU가 계속 대기하는 상황이 발생합니다. 메모리 계층 구조는 자주 사용되는 데이터를 빠른 메모리에 두어 이 속도 격차를 완충합니다. 캐시와 RAM이 없다면 모든 데이터를 HDD에서 찾아야 하므로 컴퓨터는 사용 불가능할 정도로 느려질 것입니다.

### 문제 2: 비용 효율성
고속 메모리는 매우 비쌉니다. 레지스터와 캐시는 CPU 칩 위에 직접 구성되므로 극도로 비싸고, RAM도 상당한 가격입니다. 모든 데이터를 최고속 메모리에 저장할 수 없으므로, 계층 구조를 통해 필요한 용량의 비싼 메모리와 큰 용량의 저렴한 메모리를 조합합니다. 이렇게 하면 합리적인 가격으로 빠른 성능을 제공할 수 있습니다.

### 문제 3: 데이터 무결성과 영구성
프로그램 실행 중 발생한 모든 데이터를 유지해야 할까요? 프로그램 종료 후에도 필요한 데이터는 영구적으로 보관되어야 합니다. 휘발성 메모리는 이 목적에 맞지 않으므로, 최종 결과는 비휘발성 저장소에 저장합니다. 메모리 계층은 이런 용도의 차이를 반영하고 있습니다.

## ⚙️ 작동 원리

컴퓨터가 프로그램을 실행할 때, 운영체제는 프로그램과 데이터를 HDD에서 RAM으로 로드합니다. CPU가 어떤 데이터를 필요로 하면, 먼저 자신이 가진 레지스터에서 찾습니다. 없으면 점점 더 큰 캐시를 확인하고, 캐시에도 없으면 RAM으로 요청을 보냅니다. RAM에서 데이터를 받으면 동시에 캐시에도 복사합니다. 이렇게 하면 다음에 같은 데이터가 필요할 때는 더 빠른 캐시에서 얻을 수 있습니다. 데이터가 RAM에도 없으면 SSD에서 로드하는데, 이 과정은 상당한 시간이 걸립니다. 프로그램이 새로운 데이터를 생성하면 먼저 RAM에 저장되고, 프로그램을 종료할 때 중요한 데이터는 SSD로 저장됩니다. 캐시는 자동으로 관리되므로 개발자가 신경 쓸 필요가 없지만, 메모리 접근 패턴을 고려한 효율적인 코드를 작성하면 캐시 히트를 증가시켜 성능을 크게 개선할 수 있습니다.

## ✅ 장단점

### 장점
- **최적의 성능**: 속도와 용량의 균형으로 실질적인 고성능을 제공합니다.
- **비용 효율성**: 비싼 메모리를 적게 사용하면서도 빠른 성능을 얻습니다.
- **자동 관리**: 캐시는 운영체제와 CPU가 자동으로 관리하므로 개발자가 신경 쓸 필요가 없습니다.
- **데이터 영구성**: 비휘발성 저장소로 프로그램 종료 후에도 데이터를 보관할 수 있습니다.
- **확장성**: 더 많은 메모리가 필요하면 RAM을 추가하거나 저장소를 확장할 수 있습니다.

### 단점
- **복잡성**: 메모리 관리가 복잡하여 개발자가 메모리 누수 같은 문제를 야기할 수 있습니다.
- **캐시 미스 성능 저하**: 캐시에 자주 미스가 발생하면 성능이 크게 하락합니다.
- **전원 의존성**: 휘발성 메모리의 데이터는 전원 차단 시 손실됩니다.
- **용량 제한**: 실제 필요한 데이터보다 RAM이 작으면 스왑 영역을 사용하여 성능이 저하됩니다.
- **비용**: 큰 용량의 RAM과 고속 SSD는 여전히 비싼 편입니다.

## 💡 실제 사례

### 프로그램 실행 시 메모리 사용
사용자가 웹 브라우저를 실행하면, 먼저 브라우저 프로그램이 HDD의 설치 폴더에서 실행 파일을 읽어 RAM으로 로드합니다. 브라우저가 웹 페이지를 표시할 때, HTML과 CSS는 RAM에 로드되고, 자주 접근하는 DOM 요소는 L3 캐시에 의해 캐싱됩니다. JavaScript 실행 중 변수와 객체는 레지스터와 L1/L2 캐시를 활용하여 빠르게 처리됩니다. 사용자가 새 탭을 열면 또 다른 메모리 공간이 할당되고, RAM이 부족하면 운영체제는 가장 최근에 사용하지 않은 메모리를 SSD의 스왑 영역으로 옮겨 RAM을 확보합니다.

### 게임 로딩 시 메모리 계층 활용
게임을 실행할 때 그래픽, 음성, 스크립트 데이터가 모두 HDD에서 RAM으로 로드됩니다. 이 과정이 게임의 '로딩 화면'입니다. 로드되면 게임 진행 중 현재 필요한 캐릭터 위치, 객체 상태 등의 데이터는 RAM에 있고, CPU가 초당 60회 이상 접근하는 매우 핫한 데이터(예: 플레이어 위치, 카메라 행렬)는 자동으로 L3 캐시에 올라갑니다. 캐시 히트 비율이 높을수록 게임이 부드럽게 실행됩니다. 게임 저장 데이터는 게임 종료 시 SSD에 저장되므로 다음 실행 시 이전 진행 상황을 복구할 수 있습니다.

## 🔗 관련 용어

- **캐시 (Cache)**: CPU와 메인 메모리 사이에 위치하여 자주 사용되는 데이터를 저장하는 매우 빠른 메모리입니다.
- **RAM (Random Access Memory)**: 프로그램 실행과 데이터 처리를 위한 주 메모리로, 모든 위치에 같은 속도로 접근할 수 있습니다.
- **SSD (Solid State Drive)**: HDD보다 빠른 비휘발성 저장 장치로, 플래시 메모리 기술을 사용합니다.
- **HDD (Hard Disk Drive)**: 회전 자기 디스크를 사용하는 느리지만 대용량의 저장 장치입니다.
- **스왑 (Swap)**: 메인 메모리가 부족할 때 저장 장치의 일부를 메모리처럼 사용하는 기법입니다.
