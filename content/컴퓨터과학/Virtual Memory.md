# Virtual Memory (가상 메모리)

## 📝 정의

Virtual Memory는 **프로그램마다 메모리를 혼자 통째로 쓰는 것처럼 보여주는 장치**다.

프로그램이 쓰는 주소는 실제 [[RAM]] 칸 번호가 아니다. CPU는 명령어에 적힌 주소를 만날 때마다 페이지 표라는 장부를 짚어 실제 자리로 옮겨 읽는다. 그래서 프로그램은 저마다 같은 번호로 시작하는 자기만의 주소 범위를 받고, 남의 범위는 장부에 없으니 아예 볼 수 없다.

### 비유
아파트 동호수 — 어느 동에나 101호가 있어서 사는 사람은 "101호"만 알면 되고, 그 번호가 실제 어느 우편함인지는 관리실 장부가 안다.

### 예
작업 관리자에서 프로그램이 쓰는 메모리가 꽂아둔 RAM 보다 크게 잡혀 있는 것을 본 적이 있을 것이다.

## 🖼️ 그림으로 보기

```도해
대조: 프로그램이 실제 주소를 직접 쓰면 무엇이 달라지나
실주소로 || 가상 주소로
주소 :: 남과 안 겹치게 || 저마다 0번부터
남의 메모리 :: 그냥 읽힌다 || 장부에 없어 못 본다
자리 옮기기 :: 주소가 어긋난다 || 장부만 고친다
= 프로그램은 저마다 통째로 혼자 쓴다고 믿고, 장부가 실제 자리로 옮겨 준다
```

## ⚠️ 해결하는 문제

```도해
대조: 올려야 할 것이 RAM 보다 많으면 어떻게 되나
RAM 만으로 || 가상 메모리로
쓸 수 있는 양 :: RAM 크기가 끝 || 디스크까지 합쳐서
안 쓰는 부분 :: 계속 자리를 차지 || 디스크로 내린다
큰 프로그램 :: 다 안 들어가면 못 돎 || 쓰는 데만 올린다
= 지금 쓰는 쪽만 RAM 에 두고 나머지는 디스크에 미뤄 둔다
```

주소가 곧 실제 자리라면 한 프로그램이 쓸 수 있는 양은 꽂힌 RAM에서 멈춘다. 게다가 여러 프로그램이 서로 겹치지 않게 자리를 나눠 써야 하고, 한쪽의 잘못된 접근이 다른 쪽 값을 그대로 망친다.

가상 메모리는 주소와 실제 자리 사이에 장부 한 겹을 넣어 이걸 없앤다. [[Process]] 에 주어지는 주소 범위의 총량은 꽂힌 RAM과 디스크의 페이징 파일 여유를 합친 만큼이고, 지금 손대는 부분만 RAM에 올려 둔다. 실제로 쓰려는 양이 RAM보다 커지면 시스템이 일부를 디스크로 내려 자리를 만든다.

## ⚙️ 작동 원리

주소는 **페이지**라는 덩어리 단위로 다룬다. x86에서 한 페이지는 4KB다.

| 무엇 | 하는 일 |
|---|---|
| 가상 주소 | 프로그램이 아는 유일한 주소 |
| 페이지 표 | 그 주소가 실제 어느 페이지인지 적어 둔 장부. 프로세스마다 하나 |
| 작업 집합 | 그중 지금 RAM에 올라와 있는 부분 |
| 페이징 파일 | RAM에서 밀려난 페이지가 내려가 있는 디스크 자리 |

장부는 한 겹이 아니라 여러 겹으로 쌓여 있고, 맨 위 표가 어디 있는지는 레지스터가 들고 있다. 메모리에 손댈 때마다 그 표를 짚어 내려가며 실제 주소를 구한다.

RAM에 자리가 필요해지면 시스템은 가장 오래 안 쓴 페이지를 골라 페이징 파일로 내린다. 페이지가 실제로 옮겨져도 프로그램이 아는 주소는 그대로다 — 시스템이 해당 프로세스의 장부만 고쳐 놓기 때문에, 프로그램은 자기 페이지가 옮겨진 것을 끝까지 모른다.

## 💡 실제 사례

- **RAM보다 큰 데이터 다루기** — 프로그램에 주어진 주소 범위는 꽂힌 RAM 크기와 별개라, 지금 보는 부분만 RAM에 올려 두고 나머지는 디스크에 남겨 둔 채로 다룰 수 있다.
- **프로그램 격리** — 한 프로그램의 잘못된 접근이 다른 프로그램의 값을 건드리지 못한다. 주소 공간이 서로 사유라서, 남의 페이지는 내 장부에 아예 없다.
- **같은 것을 함께 보기** — 반대로 나눠 쓰기로 정해 둔 자리는 여러 프로세스의 장부가 같은 물리 페이지를 가리키게 해서, 한 벌만 올려 두고 함께 본다.

## 🚫 흔한 오해

- **가상 메모리는 RAM이 모자랄 때 쓰는 디스크 공간이다** — 그건 그중 한 부분인 페이징 파일이다. 가상 메모리는 RAM이 넉넉해도 항상 켜져 있는 주소 변환 장치다.
- **RAM을 넉넉히 꽂으면 가상 메모리는 안 쓴다** — 주소는 여전히 전부 가상이고 손댈 때마다 변환된다. 늘어난 RAM은 페이지가 디스크로 내려가는 일을 줄여 줄 뿐이다.
- **주소 범위가 크니 원하는 만큼 잡아도 된다** — 잡을 수 있는 총량은 RAM과 페이징 파일 여유를 합친 만큼이고, 실제로 손대는 양이 RAM을 넘으면 디스크를 오가느라 느려진다.

## 🚨 주의사항

- **잡아 둔 양과 실제로 쓰는 양은 다르다.** RAM에 올라와 있는 부분만 작업 집합이고, 성능을 좌우하는 것은 잡아 둔 총량이 아니라 이쪽이다.
- **32비트에서는 주소 범위 자체가 좁다.** 32비트 윈도우의 주소 범위는 4GB이고, 그중 프로세스가 쓰는 몫은 기본 2GB다. RAM을 더 꽂아도 이 한계는 그대로다.
- **디스크로 내려가는 일이 잦아지면 급격히 느려진다.** 손대는 페이지가 RAM에 안 들어가면 내렸다 올리는 일이 되풀이된다.

## 📝 정리

Virtual Memory는 프로그램마다 자기만의 주소 범위를 통째로 내주고, 그 주소를 실제 자리로 옮겨 주는 장치다. 이 한 겹 덕분에 프로그램은 서로의 메모리를 볼 수 없고 RAM보다 넓은 주소를 쓸 수 있으며, 페이지가 옮겨 다녀도 프로그램은 아무것도 안 고친다. 대신 실제로 손대는 양이 RAM을 넘어서면 디스크를 오가는 값을 치른다.

## 🔗 관련 용어

- [[RAM]] — 가상 주소가 실제로 놓이는 자리. 여기 올라와 있는 몫이 작업 집합이다
- [[Memory]] — 빠른 층부터 느린 층까지 겹쳐 쓰는 구조. 가상 메모리가 그 층을 감춰 준다
