# Parallelism (병렬성)

## 📝 정의

Parallelism은 **여러 코어가 같은 시간에 각자 일하는 것**이다.

CPU에 코어가 넷 있어도 프로그램이 하나로만 돌면 셋은 놀고 있다. 병렬 처리는 일을 쪼개 각 코어에 하나씩 얹어서 실제로 같은 순간에 진행시킨다.

### 비유
요리사 넷이 한 주방에서 각자 다른 요리를 맡는 것. 한 사람이 냄비 여러 개를 오가며 보는 것과는 다르다.

## 🖼️ 그림으로 보기

```도해
흐름: 이미지 1000장을 네 코어로 처리하면 어떻게 도나
나누기 :: 1000장을 250장씩 네 묶음으로 쪼갠다
뿌리기 :: 묶음 하나씩 각 코어에 넘긴다
코어 넷 :: 같은 시간에 각자 250장을 처리한다
< 모으기 :: 끝난 결과를 모아 순서를 맞춘다
= 한 코어로 1000초 걸리던 일이 250초로 줄어든다
```

## ⚠️ 해결하는 문제

```도해
대조: 코어가 넷인데 하나만 쓰면 어떻게 되나
한 코어로 || 네 코어로
1000장 처리 :: 1000초 || 250초
CPU 사용률 :: 25% || 100%
남는 코어 :: 셋은 논다 || 전부 일한다
= 코어는 이미 있다. 안 나눠주면 놀고 있을 뿐이다
```

이미지 한 장을 처리하는 데 1초가 걸린다면 1000장은 1000초다. 이 시간은 CPU가 느려서 생긴 것이 아니라 네 개 중 하나만 쓰고 있어서 생긴 것이다. 4K 영상 인코딩이 다섯 시간 걸리는 동안 CPU 사용률이 25%에 머무는 것도 같은 이유다.

병렬 처리는 일을 코어 수만큼 나눠 동시에 돌린다. 계산 자체가 빨라지는 게 아니라 놀던 코어가 일하기 시작하는 것이다.

## ⚙️ 작동 원리

일을 쪼개고, 코어마다 돌리고, 결과를 합친다. 이 셋 중 가운데만 병렬로 돌고 앞뒤는 그렇지 않다.

```도해
흐름: 코어를 8배로 늘려도 8배가 안 되는 이유는 무엇인가
나누기 :: 일을 코어 수만큼 쪼갠다. 여기는 한 갈래
프로세스 :: 코어마다 실행 단위를 새로 띄운다
데이터 복사 :: 메모리를 안 나누므로 값을 복사해 보낸다
계산 :: 이 구간만 여덟 코어가 같이 돈다
결과 수집 :: 흩어진 결과를 모아 순서를 맞춘다. 여기도 한 갈래
= 8코어에서 잰 값이 6.81배, 효율 85.1% 였던 것도 이 때문이다
```

프로세스는 스레드와 달리 메모리를 나눠 쓰지 않는다. 그래서 넘기는 데이터는 복사되고, 데이터가 크면 이 복사가 계산보다 오래 걸리기도 한다.

## 💡 실제 사례

- **이미지 일괄 처리** — 1000장을 250장씩 네 묶음으로 나눠 네 코어에 맡기면 1000초짜리가 250초가 된다.
- **비디오 인코딩** — 영상을 구간으로 잘라 코어마다 다른 구간을 맡기면 다섯 시간이 한 시간 반으로 줄어든다.
- **시뮬레이션 계산** — 계산을 코어 수만큼 쪼개 돌리고 마지막에 결과를 합친다.

## 🚫 흔한 오해

- **스레드를 여러 개 만들면 병렬로 돈다** — 파이썬에서는 GIL 때문에 한 번에 한 스레드만 파이썬 코드를 실행한다. 계산을 실제로 나누려면 `multiprocessing`으로 프로세스를 띄워야 한다.
- **코어를 두 배로 늘리면 두 배 빨라진다** — 나누고 복사하고 합치는 시간이 붙는다. 8코어에서 재보면 6.81배, 효율은 85.1%였다.
- **느린 코드는 병렬로 돌리면 빨라진다** — 기다리는 시간이 원인이면 그대로다. 네트워크 응답이나 디스크를 기다리는 동안 코어는 이미 놀고 있어서, 노는 코어를 더 붙여도 달라질 게 없다.

## 📊 비교

| | 병렬성 | 동시성 |
|---|---|---|
| 도는 방식 | 실제로 같은 시간에 | 번갈아 가며 |
| 필요한 것 | 코어가 여러 개 | 한 개로도 된다 |
| 맞는 일 | 계산이 무거운 일 | 기다림이 긴 일 |
| 파이썬에서 | `multiprocessing` | `asyncio` |

## 🚨 주의사항

- **작은 작업을 병렬로 돌리지 않는다.** 프로세스를 띄우고 값을 주고받는 시간이 실제 계산보다 커진다.
- **큰 데이터를 통째로 넘기지 않는다.** 프로세스끼리 메모리를 나눠 쓰지 않으므로 넘긴 만큼 복사된다.

## 📝 정리

Parallelism은 일을 쪼개 여러 코어에서 같은 시간에 돌리는 것이다. 계산이 무거운 일에만 효과가 있고, 나누고 복사하고 합치는 값이 붙기 때문에 코어 수만큼 빨라지지는 않는다.

## ❓ 이해했는지

- 코어가 넷인데 CPU 사용률이 25%에서 멈춰 있다면 지금 무엇을 안 하고 있는 것인가 → 해결하는 문제
- 파이썬에서 스레드를 여덟 개 띄웠는데 계산 시간이 그대로인 이유는 → 흔한 오해
- 코어를 8배로 늘렸는데 6.81배까지만 빨라진 이유는 → 작동 원리
