# Mutex vs Semaphore (뮤텍스와 세마포어)

## 📝 정의

뮤텍스는 한 명만 들이고, 세마포어는 **정한 수만큼** 들인다.

Mutex 는 mutual exclusion(상호 배제)을 줄인 말이다 — 이름이 곧 하는 일이다. 세마포어는 컴퓨터 과학에서 가장 오래된 동기화 수단 중 하나로, Python 문서는 이것을 만든 사람이 Edsger W. Dijkstra 이고 그가 `acquire()`·`release()` 대신 `P()`·`V()` 라는 이름을 썼다고 적어 뒀다.

### 비유
뮤텍스는 열쇠가 하나뿐인 화장실 문이고, 세마포어는 남은 자리를 세는 주차장 입구다.

### 예
티켓 예매 사이트에서 접속자가 많다며 대기 번호를 받고 기다린 적이 있을 것이다.

## 🖼️ 그림으로 보기

```도해
대조: 뮤텍스와 세마포어는 무엇이 다른가
뮤텍스 |=| 세마포어
동시 입장 :: 한 번에 한 명 || 정한 수만큼
안의 상태 :: 잠김·풀림 둘 || 0 이상의 숫자
과다 반납 :: 바로 오류다 || 상한을 둬야 안다
= 하나만 들이는 문이 뮤텍스, 자리 수를 세는 문이 세마포어다
```

## ⚠️ 해결하는 문제

```도해
대조: 동시에 몇까지 들일지 정해두지 않으면 무엇이 어긋나나
정하지 않으면 || 잠금으로 세면
동시 진입 :: 몰리는 대로 다 || 정한 수까지만
연결 다섯 개 :: 여섯째도 들어간다 || 여섯째는 기다린다
과다 반납 :: 알 길이 없다 || 상한 두면 잡힌다
= 잠금은 "동시에 몇까지" 를 숫자로 정해 지키게 하는 장치다
```

한쪽 문제는 **한 명만 들여야 하는 자리**다. 여러 흐름이 같은 값을 고치는데 순서를 아무도 정해주지 않으면 결과가 어긋난다. Go 문서가 `Mutex` 를 "상호 배제 잠금" 이라는 한 줄로 정의하고, Python 문서가 `Lock` 을 잠김과 풀림 두 상태만 갖는 가장 낮은 수준의 동기화 수단으로 설명하는 이유가 여기 있다.

다른 쪽 문제는 **자리가 정해진 자원**이다. Python 문서는 세마포어가 대개 용량이 한정된 자원을 지키는 데 쓰인다고 적고, 최대 연결 다섯 개인 풀을 상한 5 의 세마포어로 감싼 예를 든다. 한 명만이 아니라 다섯까지 허용해야 하는 자리에는 뮤텍스가 맞지 않는다.

## ⚙️ 작동 원리

세마포어가 세는 것은 숫자 하나다. `acquire()` 가 1 줄이고 `release()` 가 1 늘린다. 숫자는 0 아래로 내려가지 않고, 0 일 때 들어온 쪽은 누군가 반납할 때까지 그 자리에서 멈춘다. 초기값의 기본은 1 이다 — 그래서 값이 1 인 세마포어는 뮤텍스처럼 굴게 된다.

뮤텍스가 세는 것은 두 상태뿐이다. Python 의 `Lock` 은 풀린 상태로 만들어지고, 잠긴 동안 들어온 `acquire()` 는 풀릴 때까지 막힌다. Go 의 `Mutex` 는 아무것도 안 한 기본값이 곧 풀린 뮤텍스다.

**둘 다 주인을 따지지 않는다.** Python 문서는 `Lock` 이 잠긴 동안 특정 스레드의 것이 아니며 잠근 스레드가 아닌 쪽도 풀 수 있다고 적었고, Go 문서도 잠긴 `Mutex` 는 특정 고루틴과 묶이지 않으며 한 고루틴이 잠근 것을 다른 고루틴이 풀도록 짜도 된다고 말한다. 주인과 중첩 횟수를 따지는 것은 `RLock` 쪽이고, 거기서는 잠근 횟수만큼 풀어야 한다.

차이는 **실수를 잡아주는 자리**에서 갈린다. 잠기지 않은 뮤텍스를 풀려 하면 Python 은 `RuntimeError` 를 내고, Go 는 그것을 런타임 오류로 다룬다. 세마포어는 그냥 숫자가 올라간다 — 너무 많이 반납한 것은 버그라는 신호이므로, 그것까지 잡으려면 초기값을 넘기면 예외를 내는 `BoundedSemaphore` 를 써야 한다.

## 💡 실제 사례

- **연결 풀 다섯 개** — 상한을 5 로 둔 세마포어를 쥐고 연결을 꺼내면, 여섯째 요청은 누가 반납할 때까지 기다린다. Python 문서가 예로 드는 모양 그대로다.
- **공유하는 값 하나** — 여러 흐름이 같은 값을 고쳐야 하면 뮤텍스로 한 번에 한 명만 들인다. 자리가 하나뿐이니 숫자를 셀 이유가 없다.
- **무게를 붙인 제한** — Go 의 `semaphore.Weighted` 는 최대 합계 무게를 정해두고 호출하는 쪽이 무게를 붙여 요청한다. 무거운 작업 하나가 가벼운 작업 여러 개만큼의 자리를 차지하게 만들 수 있다.

## 🚫 흔한 오해

- **뮤텍스는 잠근 쪽만 풀 수 있다** — Python 의 `Lock` 도 Go 의 `Mutex` 도 잠긴 동안 특정 흐름의 것이 아니다. 한쪽이 잠그고 다른 쪽이 풀게 짜도 된다. 주인을 따지는 것은 `RLock` 이다.
- **세마포어가 있으면 뮤텍스는 필요 없다** — 값이 1 이면 비슷하게 굴지만, 세마포어는 너무 많이 반납해도 숫자만 조용히 올라간다. 뮤텍스는 그 실수를 처음부터 오류로 막는다.
- **세마포어 숫자가 0 아래로 내려가 밀린 만큼을 기억한다** — 0 아래로는 안 내려간다. 0 일 때 들어온 쪽은 숫자가 올라갈 때까지 그 자리에 멈춰 선다.

## 🚨 주의사항

- **`RLock` 은 잠근 횟수만큼 풀어야 한다** — 같은 흐름이 여러 번 잠글 수 있는 대신, 잠근 만큼 풀지 않으면 교착으로 이어진다고 Python 문서가 못 박는다.
- **`TryLock` 을 자주 쓰게 되면 설계를 의심해라** — Go 문서는 올바른 사용이 있긴 하지만 드물고, `TryLock` 을 쓰는 것 자체가 그 뮤텍스 사용에 더 깊은 문제가 있다는 신호일 때가 많다고 적었다.
- **뮤텍스를 복사하지 마라** — Go 문서는 `Mutex` 를 한 번 쓴 뒤에 복사하지 말라고 한다. 구조체를 값으로 넘기면 그 안에 든 잠금까지 함께 복사된다.

## 📝 정리

뮤텍스와 세마포어는 둘 다 잠금이지만 세는 것이 다르다. 뮤텍스는 잠김과 풀림 두 상태를 지키고, 세마포어는 0 이상의 숫자를 지킨다. 한 명만 들일 자리에는 뮤텍스, 자리 수를 정해 나눠 쓸 자리에는 세마포어다.
