# Interrupt (인터럽트)

## 📝 정의

인터럽트는 **일이 생겼을 때 장치가 CPU 를 불러 세우는 신호**다.

이름이 곧 하는 일이다 — interrupt, 끼어들기. 리눅스 커널 문서는 이것을 "장치가 보내는 인터럽트 요청(IRQ)" 이라고 적는다. 신호는 핀을 타고 오기도 하고 패킷으로 오기도 한다.

### 이름
Inter :: 사이에
Rupt :: 끊다
= 붙여 읽으면 "하던 일 사이를 끊다". 끊고 들어오는 것이 이름 그대로다

### 비유
선생이 한 명씩 돌며 "질문 있니" 묻는 대신, 질문이 생긴 학생이 손을 드는 교실.

### 예
휴대폰을 주머니에 넣어두어도 문자가 오면 진동이 온다. 새 문자가 왔나 계속 열어 보는 사람은 없다.

## 🖼️ 그림으로 보기

```도해
흐름: 키보드를 누른 걸 CPU 는 어떻게 알게 되나
키보드 :: 눌렸다고 신호선을 올린다
컨트롤러 :: 여러 장치의 신호를 모아 CPU 에 전한다
CPU :: 하던 일을 그 자리에 저장하고 멈춘다
핸들러 :: 신호를 끄고 챙길 것만 챙긴다
CPU :: 저장해 둔 자리로 돌아가 하던 일을 잇는다
= 물어봐서 아는 게 아니라, 불려 가서 알게 되는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 되묻는 것밖에 없으면 CPU 는 어떻게 되나
되묻기만 || 인터럽트로
확인 :: CPU 가 계속 되묻는다 || 장치가 알려준다
빈 시간 :: 확인에 그냥 쓴다 || 다른 일에 쓴다
알아채기 :: 다음 확인 차례에 || 신호가 오는 즉시
= 기다리다 아는 대신 불려 가서 알기로 하면, 기다린 시간이 그대로 남는다
```

CPU 가 장치 상태를 직접 되묻는 방식을 폴링이라 한다. 리눅스 네트워크 문서는 이 둘을 나란히 적어 둔다 — 기본 동작은 "장치가 인터럽트로 새 사건을 알린다" 이고, 필요하면 "인터럽트를 받지 않고 장치를 되물을 수도 있다".

되묻기만 있으면 확인하는 그 시간이 통째로 사라진다. 키를 몇 분에 한 번 누르는 키보드도 쉬지 않고 되물어야 하고, 확인과 확인 사이에 눌린 것은 다음 차례까지 아무도 모른다. 인터럽트는 **알림의 방향을 뒤집어서** 그 시간을 되돌려준다.

## ⚙️ 작동 원리

```도해
층: 인터럽트 처리는 왜 두 토막으로 갈리나
하드 핸들러 :: 같은 급 신호를 막은 채 돈다. 신호를 끄고 상태만 챙긴다
미룬 일 :: 우선순위가 내려간 뒤에 불린다. 실제 처리를 여기서 한다
보통 코드 :: 어떤 신호든 받는 자리. 응용 프로그램이 도는 곳
= 위는 짧아야 하고, 길어질 일은 아래로 내린다
```

핸들러가 도는 동안에는 같은 급 이하의 인터럽트가 막혀 있다. 그래서 윈도우 드라이버 문서는 핸들러가 "장치의 신호를 끄고 상태를 저장하는 데 꼭 필요한 일만" 하고, 나머지는 우선순위가 내려간 뒤에 처리할 일(DPC)로 넘기라고 못 박는다. 리눅스도 핸들러를 하드 인터럽트 문맥에서 도는 부분과 스레드에서 도는 부분으로 나눠 둔다.

## 💡 실제 사례

- **키보드·마우스 입력** — 눌릴 때만 신호가 올라오니, 아무 입력이 없는 동안 CPU 는 그 장치를 잊고 다른 일을 한다.
- **디스크 읽기 완료** — 읽어달라고만 걸어두고 다른 일로 넘어갔다가, 다 됐다는 신호를 받고 이어서 처리한다.
- **초당 수만 건이 몰리는 네트워크 카드** — 매 건마다 불리면 부르는 일에 CPU 가 묶인다. 리눅스 네트워크 계층은 한 번 불린 뒤에는 되묻기로 바꿔 여러 건을 몰아 처리한다.

## 🚫 흔한 오해

- **인터럽트는 뭔가 잘못됐을 때 걸리는 것이다** — 정상 동작이다. 시스템은 그 인터럽트를 받을 때마다 등록된 핸들러를 부른다. 키를 누를 때마다, 디스크를 다 읽을 때마다 걸린다.
- **인터럽트가 폴링보다 항상 낫다** — 부르는 값이 공짜가 아니다. 초당 수만 건이 몰리는 자리에서는 신호 처리에만 CPU 가 묶여서, 리눅스 네트워크 계층은 그때 되묻기로 바꿔 여러 건을 한 번에 처리한다.
- **핸들러 안에서 다 처리하면 된다** — 그 안은 다른 신호를 막고 있는 자리다. 오래 붙들면 그 기계의 모든 장치가 같이 느려진다.

## 🚨 주의사항

- **핸들러는 가능한 한 짧게.** 높은 우선순위로 도는 동안 같은 급 이하의 인터럽트가 전부 막히기 때문에, 짧게 끝내는 것이 기계 전체의 입출력 처리량을 올린다.
- **핸들러도 끼어들기를 당한다.** 더 높은 급의 장치나 시스템 인터럽트가 언제든 그 위에 끼어들 수 있다.
- **한 신호선을 여러 장치가 나눠 쓴다.** 그래서 핸들러는 먼저 "내 장치가 부른 게 맞나" 를 확인하고, 아니면 즉시 손을 떼어 다음 핸들러가 곧바로 불리게 해야 한다.

## 📝 정리

**"손 든 쪽을 돌아보는 그 끼어들기"** 라고 읽으면 된다. 장치가 신호를 올리면 CPU 는 하던 자리를 저장해 두고 잠깐 그쪽을 챙긴 뒤 돌아오니, 되묻느라 쓰던 시간이 통째로 남는다. 대신 불리는 값이 공짜가 아니라서, 너무 자주 불릴 자리에서는 되묻기로 되돌아간다.

## 🧒 열 살에게

선생님이 한 명 한 명한테 다가가서 "질문 있니" 하고 계속 물으러 다니면 수업이 안 되지? 그래서 궁금한 사람이 손을 들어. 컴퓨터도 똑같아서, 키보드가 눌리면 키보드가 스스로 손을 들고 그때만 컴퓨터가 하던 걸 잠깐 멈추고 돌아봐.

## ❓ 이해했는지

- 아무 입력이 없는 동안 CPU 가 키보드를 잊고 있을 수 있는 이유는 → 해결하는 문제
- 초당 수만 건이 몰리는 자리에서 오히려 되묻기로 바꾸는 이유는 → 흔한 오해
- 핸들러에서 할 일을 다 끝내지 않고 뒤로 미루는 이유는 → 작동 원리
