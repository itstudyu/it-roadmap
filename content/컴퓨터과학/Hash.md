# Hash (해시)

## 📝 정의

Hash는 **아무 길이의 값을 정해진 길이의 숫자로 바꾸는 계산**이다.

한 글자짜리든 1기가짜리 파일이든 결과 길이가 같다. 같은 입력은 항상 같은 결과를 내고, 그 결과에서 원래 값을 되돌릴 수는 없다.

### 비유
지문. 사람마다 다르고 같은 사람은 항상 같은 지문이 나오지만, 지문만 보고 얼굴을 그릴 수는 없다. 짧지만 그 사람을 특정한다.

## 🖼️ 그림으로 보기

```도해
흐름: 해시 테이블에서 값을 찾을 때 무슨 계산을 하나
프로그램 :: "email" 이라는 열쇠로 값을 찾는다
해시 함수 :: 그 글자를 숫자로 바꾼다
계산 :: 숫자를 칸 개수로 나눈 나머지를 본다
결과 :: 7번 칸이다. 거기로 바로 간다
< 값 :: 찾았다. 앞의 칸들을 훑지 않았다
= 어디 있는지 계산으로 알기 때문에 개수가 늘어도 시간이 그대로다
```

## ⚠️ 해결하는 문제

```도해
대조: 백만 개 중에서 하나를 찾을 때 어떻게 되나
목록에서 찾기 || 해시 테이블
비교 횟수 :: 평균 50만 번 || 한 번
데이터 100배 :: 시간도 100배 || 그대로
필요한 것 :: 없음 || 여분의 빈 칸
= 메모리를 조금 더 쓰고 검색 시간을 사는 거래다
```

목록에서 값을 찾으려면 앞에서부터 하나씩 비교해야 한다. 백만 개면 평균 오십만 번이다. 데이터가 늘면 그만큼 느려진다.

해시는 비교를 없앤다. 열쇠를 계산해서 어느 칸인지 바로 구하므로 개수와 상관없이 한 번에 간다. 대신 칸을 넉넉히 잡아둬야 해서 메모리를 더 쓴다.

## ⚙️ 작동 원리

다른 입력이 같은 칸으로 계산되는 일이 반드시 생긴다. 이걸 충돌이라고 하고, 칸 수가 유한하므로 피할 수 없다.

```도해
층: 충돌을 어떻게 처리하나
체이닝 :: 같은 칸에 목록으로 이어 붙인다
개방 주소법 :: 다음 빈 칸을 찾아 들어간다
재해싱 :: 칸이 너무 차면 전체를 더 큰 표로 옮긴다
= 충돌이 잦아지면 조회가 O(1) 에서 O(n) 으로 무너진다
```

용도에 따라 요구가 다르다. 자료구조에 쓰는 해시는 빠른 것이 중요하고, 비밀번호에 쓰는 해시는 **의도적으로 느린 것**이 중요하다. 빠르면 공격자가 초당 수억 번 대입할 수 있기 때문이다.

## 💡 실제 사례

- **딕셔너리** 대부분 언어의 map과 dict가 해시 테이블이다.
- **파일 검증** 내려받은 파일의 해시를 원본과 비교해 손상이나 변조를 확인한다.
- **비밀번호 저장** 원문 대신 해시를 저장한다. DB가 털려도 비밀번호 자체는 나가지 않는다.

## 🚫 흔한 오해

- **해시는 암호화다** — 암호화는 되돌릴 수 있지만 해시는 되돌릴 수 없다. 되돌릴 필요가 없는 곳에만 쓴다.
- **해시하면 비밀번호가 안전하다** — 빠른 해시(MD5, SHA-256)를 그냥 쓰면 대입 공격에 뚫린다. bcrypt처럼 느리게 설계된 것에 소금값을 섞어 써야 한다.
- **충돌은 설계 실수다** — 입력은 무한이고 출력은 유한하므로 반드시 생긴다. 처리 방법이 있느냐가 문제다.

## 🚨 주의사항

- **비밀번호에 SHA-256을 쓰지 않는다.** 너무 빠르다. bcrypt, scrypt, argon2 중에서 고르고 소금값을 반드시 붙인다.
- **해시 테이블의 열쇠를 도중에 바꾸지 않는다.** 열쇠가 바뀌면 계산 결과가 달라져서 넣어둔 값을 영영 못 찾는다.

## 📝 정리

Hash는 아무 길이의 값을 고정 길이 숫자로 바꾸는 계산이다. 계산으로 위치를 알아내 조회를 O(1)로 만들고, 되돌릴 수 없다는 성질 덕에 검증과 비밀번호 저장에도 쓰인다.
