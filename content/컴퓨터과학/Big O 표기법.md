# Big O 표기법 (Big O Notation)

## 📝 정의

Big O 표기법은 알고리즘의 시간 복잡도와 공간 복잡도를 나타내는 수학적 표기법입니다. 입력 데이터의 크기(n)가 증가할 때 알고리즘이 얼마나 빠르게 성능이 저하되는지를 분석합니다. 단순히 실행 시간을 측정하는 것이 아니라, 입력 크기에 따른 알고리즘의 상대적 성능 변화를 파악하는 것이 핵심입니다.

Big O 표기법은 '최악의 경우(Worst Case)'를 기준으로 합니다. 즉, 가장 오래 걸리는 경우의 시간 복잡도를 나타냅니다. 이를 통해 알고리즘의 성능 상한을 명확히 할 수 있으며, 대규모 데이터셋에서의 예측 가능한 성능을 파악할 수 있습니다. 개발자는 Big O 표기법을 통해 서로 다른 알고리즘을 객관적으로 비교하고, 실제 상황에 맞는 최적의 알고리즘을 선택할 수 있습니다.

> Big O 표기법 = 입력 크기에 따른 알고리즘 성능의 상대적 변화를 수학적으로 나타낸 표기법

**비유 1**: Big O는 마치 자동차의 가속도 같습니다. 처음 1km 달리는 데 10초가 걸렸다고 해서 10km를 예측할 수 없습니다. 입력이 10배 늘어났을 때 시간이 10배, 100배, 또는 1000배 늘어나는지 파악하는 것이 Big O입니다.

**비유 2**: Big O는 병원 대기시간과 같습니다. 환자 1명일 때 5분, 10명일 때 50분이면 O(n)이고, 10명일 때 100분이면 O(n²)입니다. 시스템이 얼마나 효율적으로 확장하는가를 나타냅니다.

## 🎯 핵심 개념

### 1. 주요 시간 복잡도 계층
Big O 표기법은 가장 빠른 O(1)부터 가장 느린 O(n!)까지 여러 단계로 나뉩니다. 각 단계는 입력 크기가 증가할 때 성능 저하의 정도를 나타내며, 알고리즘 선택의 중요한 기준이 됩니다.

### 2. 상수항과 계수 무시
Big O 표기법에서는 O(2n)과 O(n)을 같은 O(n)으로 표현합니다. 상수 계수와 낮은 차수 항은 무시하고, 가장 영향력 있는 항만 고려합니다. 이는 n이 충분히 커질 때 상수의 영향이 미미해지기 때문입니다.

### 3. 최악의 경우 분석
Big O는 항상 '최악의 경우'를 기준으로 합니다. 평균적인 경우(Theta)나 최선의 경우(Omega)와는 다르며, 알고리즘이 보장할 수 있는 최대 성능 저하를 나타냅니다.

## ⚠️ 해결하는 문제

### 문제 1: 알고리즘 성능 예측 불가능
프로그래머가 단순히 '몇 초가 걸린다'는 경험적 정보만으로는 데이터가 10배, 100배 증가했을 때의 성능을 예측할 수 없습니다. Big O를 통해 입력 크기 증가에 따른 성능 변화를 수학적으로 예측할 수 있습니다.

### 문제 2: 알고리즘 비교의 객관성 부족
서로 다른 두 알고리즘 중 어느 것이 더 효율적인지 판단할 때, 단순 실행 시간 비교는 하드웨어, 환경, 데이터 크기에 따라 결과가 달라집니다. Big O는 이론적, 객관적 기준을 제공합니다.

### 문제 3: 프로젝트 규모 결정의 어려움
초기 개발 시 몇 백 개 데이터로는 문제없던 알고리즘도, 데이터가 백만 개로 증가하면 치명적으로 느려질 수 있습니다. Big O를 미리 분석하면 이러한 스케일링 문제를 사전에 파악할 수 있습니다.

## ⚙️ 작동 원리

Big O 표기법의 계산 방법은 다음과 같습니다:

**1단계: 기본 연산 식별**
알고리즘의 모든 연산을 나열하고, 각 연산이 입력 크기 n에 따라 몇 번 실행되는지 파악합니다. 예를 들어, `for i in range(n):`이면 n번 실행됩니다.

**2단계: 총 연산 횟수 계산**
중첩된 루프나 조건문을 고려하여 총 연산 횟수를 식으로 표현합니다. 이중 루프라면 n × n = n² 번입니다.

**3단계: 지배항(Dominant Term) 추출**
3n² + 2n + 5 같은 식에서 가장 큰 영향을 미치는 항 3n²를 선택합니다.

**4단계: 계수 제거**
3n²에서 상수 계수 3을 제거하여 O(n²)로 표현합니다. n이 무한대에 가까워질수록 상수의 영향은 미미해지기 때문입니다.

**예시: 이중 루프 분석**
```
for i in range(n):
    for j in range(n):
        print(i, j)
```
외부 루프: n번, 내부 루프: n번 → 총 n × n = n² → **O(n²)**

## ✅ 장단점

**장점:**
- 알고리즘의 성능을 객관적으로 비교할 수 있습니다.
- 데이터 크기 증가에 따른 성능 변화를 수학적으로 예측합니다.
- 개발 초기 단계에서 병목 지점을 파악하고 최적화할 수 있습니다.
- 프로그래밍 언어나 하드웨어와 무관하게 통용되는 표준입니다.
- 면접에서 알고리즘 이해도를 평가하는 중요한 기준입니다.

**단점:**
- 상수 계수를 무시하므로, 실제 성능은 다를 수 있습니다. (예: O(100n)과 O(n)은 같지만 실제로는 100배 차이)
- 최악의 경우만 고려하므로, 평균 성능이 훨씬 좋을 수 있습니다.
- 공간 복잡도까지 완전히 설명하지 못합니다.
- 아주 작은 데이터셋에서는 Big O 분석이 의미가 없을 수 있습니다.

## 💡 실제 사례

**사례 1: 배열 탐색**
```
// 선형 탐색 - O(n)
function linearSearch(arr, target) {
    for (let i = 0; i < arr.length; i++) {
        if (arr[i] === target) return i;
    }
    return -1;
}

// 해시맵 탐색 - O(1)
const map = new Map();
// 전처리: O(n)
arr.forEach(item => map.set(item, true));
// 조회: O(1)
map.has(target);
```
데이터가 100개일 때는 선형 탐색(100회)과 해시맵(1회) 모두 충분하지만, 1,000만 개 데이터에서는 선형 탐색(1,000만 회)은 불가능하고 해시맵(1회)은 순식간에 결과를 반환합니다.

**사례 2: 정렬 알고리즘 선택**
초기에 1,000개 데이터는 버블 정렬 O(n²) = 1,000,000 연산으로도 충분하지만, 데이터가 100,000개로 증가하면 버블 정렬은 10,000,000,000 연산이 필요합니다. 반면 병합 정렬 O(n log n) = 1,600,000 연산으로 훨씬 빠릅니다.

**사례 3: 데이터베이스 인덱스**
인덱스 없이 100만 건의 레코드를 탐색하면 O(n)으로 평균 500,000번 조회가 필요합니다. B-tree 인덱스를 사용하면 O(log n)으로 약 20번의 조회만 필요합니다.

## 🔗 관련 용어

- **Omega(Ω)**: 최선의 경우 시간 복잡도
- **Theta(Θ)**: 평균 시간 복잡도
- **시간 복잡도(Time Complexity)**: 알고리즘이 소비하는 시간
- **공간 복잡도(Space Complexity)**: 알고리즘이 소비하는 메모리
- **병합 정렬(Merge Sort)**: O(n log n) 대표 알고리즘
- **퀵 정렬(Quick Sort)**: 평균 O(n log n), 최악 O(n²)
- **이진 탐색(Binary Search)**: O(log n) 효율적인 알고리즘
- **해시 테이블(Hash Table)**: 평균 O(1) 조회
