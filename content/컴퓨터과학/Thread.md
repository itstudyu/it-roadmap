# Thread (스레드)

## 📝 정의

Thread는 **한 프로그램 안에서 따로 도는 실행 흐름**이다.

프로세스가 집이라면 스레드는 그 안의 사람이다. 여러 명이 같은 집에 살면서 같은 냉장고를 함께 쓴다. 각자 하던 일을 동시에 진행하지만 물건은 공유한다.

### 비유
주방의 요리사 여러 명. 같은 재료와 도구를 함께 쓰면서 각자 다른 요리를 만든다. 빠르지만, 두 사람이 같은 칼을 동시에 잡으려 하면 사고가 난다.

### 예
게임을 하는 동안에도 배경 음악이 끊기지 않고 이어지는 것이 한 프로그램 안에서 갈라져 돈 결과다.

## 🖼️ 그림으로 보기

```도해
층: 스레드는 프로세스 안에서 무엇을 나눠 갖나
프로세스 :: 독립된 메모리 공간. 다른 프로세스는 못 본다
공유하는 것 :: 그 안의 변수. 스레드 여럿이 같이 본다
스레드마다 :: 스택과 지역 변수는 따로. 여기서 각자 돈다
= 공유하기 때문에 빠르고, 공유하기 때문에 위험하다
```

## ⚠️ 해결하는 문제

```도해
대조: 여러 일을 동시에 하려면 무엇을 쓰나
프로세스 여러 개 |=| 스레드 여러 개
생성 비용 :: 무겁다 || 가볍다
데이터 공유 :: 별도 통로 필요 || 변수를 그냥 공유
하나가 죽으면 :: 나머지는 멀쩡 || 전체가 죽을 수 있다
= 싸고 편한 대신, 하나가 잘못되면 같이 넘어진다
```

프로세스를 여러 개 띄워도 동시 처리는 된다. 다만 무겁다. 메모리 공간을 새로 잡아야 하고, 데이터를 주고받으려면 별도의 통로를 만들어야 한다.

스레드는 같은 프로세스 안에서 나뉘므로 만드는 비용이 훨씬 싸고 변수를 그냥 함께 쓴다. 그 편함이 곧 위험이기도 하다. 두 스레드가 같은 변수를 동시에 고치면 결과가 어긋난다.

## ⚙️ 작동 원리

두 스레드가 같은 값을 동시에 고칠 때 생기는 문제를 경쟁 상태라고 한다.

```도해
흐름: 잔액 100원을 두 스레드가 동시에 줄이면 어떻게 되나
스레드 A :: 잔액을 읽는다. 100
스레드 B :: 잔액을 읽는다. 아직 100
스레드 A :: 30을 빼고 70을 쓴다
스레드 B :: 자기가 읽은 100에서 30을 빼고 70을 쓴다
결과 :: 60이어야 하는데 70이 남았다
= 읽고 고치고 쓰는 사이에 남이 끼어들면 하나가 사라진다
```

이걸 막으려면 한 번에 한 스레드만 그 구간에 들어가게 잠근다. 대신 잠금을 잘못 걸면 서로가 서로를 기다리다 멈추는 교착 상태가 된다.

## 💡 실제 사례

- **웹 서버** — 요청마다 스레드를 하나씩 배정해 동시에 처리한다.
- **화면 응답 유지** — 무거운 계산을 다른 스레드로 넘겨 화면이 멈추지 않게 한다.
- **병렬 계산** — CPU 코어 수만큼 스레드를 띄워 큰 작업을 나눈다.

## 🚫 흔한 오해

- **스레드를 늘리면 늘린 만큼 빨라진다** — 코어 수를 넘으면 번갈아 쓰느라 전환 비용만 늘어난다. 오히려 느려지는 지점이 있다.
- **읽기만 하면 안전하다** — 읽는 동안 남이 고치면 중간 상태를 읽는다. 읽기도 보호가 필요한 경우가 있다.
- **잠금을 많이 걸면 안전하다** — 잠금이 많아질수록 교착 상태 위험이 커지고 동시 처리 이득도 사라진다.

## 🚨 주의사항

- **공유 상태를 최소로 만든다.** 가장 확실한 동시성 대책은 잠금을 잘 거는 게 아니라 공유할 것을 줄이는 것이다.
- **잠그는 순서를 통일한다.** A 다음 B로 잠그는 스레드와 B 다음 A로 잠그는 스레드가 만나면 교착 상태가 된다.

## 📝 정리

Thread는 한 프로세스 안에서 메모리를 공유하며 따로 도는 실행 흐름이다. 가볍고 데이터를 그냥 나눠 쓰지만, 같은 값을 동시에 고칠 때 결과가 어긋나는 문제를 직접 다뤄야 한다.

## ❓ 이해했는지

- 잔액에서 두 번 빠져야 할 금액이 한 번만 빠지는 일이 왜 생기나 → 작동 원리
- 스레드를 코어 수보다 훨씬 많이 띄우면 무엇이 일어나나 → 흔한 오해
- A 다음 B 로 잠그는 스레드와 B 다음 A 로 잠그는 스레드가 만나면 어떻게 되나 → 주의사항
