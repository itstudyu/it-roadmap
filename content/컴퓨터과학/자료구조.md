# 자료구조 (Data Structure)

## 📝 정의

자료구조(Data Structure)는 데이터를 효율적으로 저장, 관리, 접근하기 위한 조직화된 형식과 구조입니다. 자료구조는 단순히 데이터를 보관하는 것을 넘어, 특정 목적에 맞게 데이터를 조직화하여 접근, 삽입, 삭제, 탐색 등의 연산을 효율적으로 수행하도록 설계됩니다. 올바른 자료구조의 선택은 알고리즘만큼이나 프로그램의 성능을 결정하는 중요한 요소입니다. 같은 데이터라도 배열로 저장하느냐 트리로 저장하느냐에 따라 접근 시간이 크게 달라집니다.

자료구조는 컴퓨터 과학의 역사와 함께 발전해왔으며, 1960년대부터 체계적으로 연구되기 시작했습니다. 오늘날 프로그래밍에서 자료구조는 언어 라이브러리(Java의 Collection Framework, Python의 built-in types 등)로 제공되지만, 각 자료구조의 내부 동작 원리를 이해하는 것이 중요합니다. 잘못된 자료구조 선택은 "느린 프로그램"을 만들고, 정확한 선택은 "빠른 프로그램"을 만듭니다.

> **한 줄 요약**: 자료구조는 데이터를 효율적으로 저장하고 관리하기 위한 체계적인 조직화 방식으로, 선택한 자료구조가 프로그램의 성능과 확장성을 결정합니다.

**비유 1**: 자료구조는 서점의 책 배치 시스템과 같습니다. 책을 무더기로 쌓으면(배열) 원하는 책을 찾기 어렵지만, 카테고리별로 정렬하고(트리), 각 카테고리 내에서 알파벳순으로 배치(정렬)하면 빠르게 찾을 수 있습니다. 어떤 조직 방식을 선택하느냐가 검색 효율을 결정합니다.

**비유 2**: 자료구조는 여행 가방 정리와 같습니다. 모든 물품을 그냥 가방에 집어넣으면(배열) 찾기 어렵지만, 포장 순서대로 꺼낼 수 있게 정리(스택), 먼저 들어온 것부터 꺼내게(큐), 중요도별로 정렬(힙)하면 효율적입니다. 각 상황에 맞는 정리 방식이 있습니다.

## 🎯 핵심 개념

### 1. 자료구조의 분류

자료구조는 데이터를 조직화하는 방식에 따라 크게 두 가지로 분류됩니다:

**선형 자료구조 (Linear)**: 데이터가 일렬로 순서대로 연결된 구조입니다.
- **배열 (Array)**: 연속된 메모리에 같은 크기의 데이터를 저장. 인덱스로 빠른 접근(O(1)), 삽입/삭제는 느림(O(n))
- **연결 리스트 (Linked List)**: 노드와 포인터로 연결된 구조. 삽입/삭제 빠름(O(1)), 접근은 느림(O(n))
- **스택 (Stack)**: LIFO(Last In First Out). 뒤로가기, 함수 호출 스택 등에 사용
- **큐 (Queue)**: FIFO(First In First Out). 프린터 대기열, 작업 스케줄링 등에 사용

**비선형 자료구조 (Non-linear)**: 데이터가 계층적이거나 네트워크 형태로 연결된 구조입니다.
- **트리 (Tree)**: 계층적 구조로 부모-자식 관계 표현. 파일시스템, 인덱싱 등에 사용
- **그래프 (Graph)**: 노드와 간선의 일반적인 연결. SNS의 친구 관계, 지도 등에 사용
- **힙 (Heap)**: 우선순위를 기반으로 정렬된 완전 이진 트리. 우선순위 큐, 힙 정렬에 사용

**해시 기반 자료구조**:
- **해시 테이블 (Hash Table)**: 키-값 쌍을 빠르게 저장/검색. 평균 O(1) 접근

### 2. 각 자료구조의 주요 특징

**배열**: 가장 기본적인 자료구조로, 메모리상 연속된 위치에 데이터를 저장합니다. 인덱스를 통한 접근이 매우 빠르지만(O(1)), 데이터 삽입이나 삭제 시 나머지 원소들을 모두 이동시켜야 합니다(O(n)). 크기가 고정되어 있어 동적 조정이 어렵습니다.

**연결 리스트**: 각 노드가 다음 노드의 주소를 가리키는 구조입니다. 삽입과 삭제가 효율적(O(1))이지만, 특정 위치의 원소에 접근하려면 처음부터 순차적으로 탐색해야 합니다(O(n)). 동적으로 크기를 조절할 수 있습니다.

**스택과 큐**: 삽입과 삭제 위치가 정해진 특수한 리스트입니다. 스택은 LIFO(마지막에 들어온 것이 먼저 나감), 큐는 FIFO(처음 들어온 것이 먼저 나감)의 원칙을 따릅니다. 웹 브라우저의 뒤로가기(스택), 프린터 작업 대기열(큐)에 사용됩니다.

**트리**: 노드와 간선으로 계층을 표현합니다. 이진 탐색 트리(BST)는 정렬된 데이터를 빠르게 검색할 수 있습니다(O(log n)). 파일시스템, HTML DOM, 데이터베이스 인덱싱 등에 사용됩니다.

**그래프**: 트리의 일반화로, 사이클이 가능하고 한 노드가 여러 부모를 가질 수 있습니다. 소셜 네트워크의 친구 관계, 지도 네비게이션, 추천 시스템 등에 사용됩니다.

**힙**: 완전 이진 트리로 부모가 자식보다 항상 크거나 작은 구조입니다. 최댓값 또는 최솟값을 O(log n)에 추출할 수 있어, 우선순위 큐와 힙 정렬에 사용됩니다.

**해시 테이블**: 해시 함수를 사용하여 키를 인덱스로 변환합니다. 평균적으로 O(1)의 빠른 조회가 가능하지만, 충돌 처리가 필요합니다. 딕셔너리, 캐시, 데이터베이스 인덱싱 등에 사용됩니다.

### 3. 자료구조 선택의 기준

자료구조 선택은 주로 수행해야 하는 연산에 따라 결정됩니다:

**빠른 검색이 필요한 경우**: 정렬된 데이터라면 이진 탐색 트리나 해시 테이블 사용
**빠른 삽입/삭제가 필요한 경우**: 연결 리스트 사용
**접근 순서가 중요한 경우**: 스택(LIFO) 또는 큐(FIFO) 사용
**계층적 데이터**: 트리 사용
**네트워크 형태 데이터**: 그래프 사용
**우선순위 처리**: 힙 사용
**메모리가 제한적**: 배열 사용 (연속 메모리)

## ⚠️ 해결하는 문제

### 문제 1: 데이터 관리의 비효율성

**문제**: 자료구조 없이 단순히 배열에 모든 데이터를 저장하면, 특정 작업(검색, 삽입, 삭제)이 비효율적입니다. 예를 들어, 정렬되지 않은 백만 개 데이터에서 특정 값을 찾으려면 평균 50만 번의 비교가 필요합니다.

**해결 방법**: 이진 탐색 트리를 사용하면 같은 데이터에서 20번의 비교만 필요합니다. 또는 해시 테이블을 사용하면 평균 1번의 비교로 찾을 수 있습니다. 적절한 자료구조 선택으로 수행 시간을 수백 배 단축할 수 있습니다.

### 문제 2: 메모리 낭비

**문제**: 크기가 고정된 큰 배열을 미리 할당하면, 실제 사용하지 않는 메모리가 낭비됩니다. 반대로 배열이 부족하면 더 큰 배열을 만들고 복사해야 합니다.

**해결 방법**: 동적으로 크기가 조절되는 연결 리스트나 동적 배열(ArrayList, Vector)을 사용하면 필요한 만큼만 메모리를 사용할 수 있습니다. 이를 통해 메모리 효율성을 크게 높입니다.

### 문제 3: 복잡한 데이터 관계 표현 불가

**문제**: 선형 자료구조로는 계층적이거나 네트워크 형태의 데이터를 표현할 수 없습니다. 파일시스템의 폴더 구조, SNS의 친구 관계 등을 배열만으로는 표현하기 어렵습니다.

**해결 방법**: 트리로 계층을 표현하고, 그래프로 네트워크 관계를 표현합니다. 이를 통해 복잡한 실세계 데이터를 정확하게 모델링하고 효율적으로 처리할 수 있습니다.

## ⚙️ 작동 원리

### 1단계: 데이터 특성 분석
저장할 데이터의 크기, 형태(정렬, 중복, 계층 등), 접근 패턴(빈도, 순서)을 분석합니다.

### 2단계: 연산 요구 분석
자주 수행되는 연산(검색, 삽입, 삭제)이 무엇인지 파악합니다. 검색이 빈번하면 탐색 속도가 빠른 자료구조를, 삽입/삭제가 빈번하면 동적 구조를 선택합니다.

### 3단계: 자료구조 선택
분석 결과에 따라 최적의 자료구조를 선택합니다. 여러 자료구조의 시간 복잡도를 비교하여 결정합니다.

### 4단계: 구현
선택한 자료구조를 프로그래밍 언어로 구현합니다. 대부분의 언어는 표준 라이브러리로 제공합니다.

### 5단계: 최적화
실제 데이터로 성능을 측정하고, 필요하면 자료구조를 변경하거나 조정합니다.

### 6단계: 유지보수
코드가 유지보수 가능하도록 명확한 네이밍과 주석을 작성합니다.

## ✅ 장단점

### 장점

1. **성능 최적화**: 올바른 자료구조 선택으로 연산 시간을 수십 배 단축할 수 있습니다.

2. **메모리 효율성**: 데이터 특성에 맞는 자료구조를 사용하면 메모리 낭비를 줄입니다.

3. **확장성**: 동적 자료구조(연결 리스트, 해시 테이블)는 데이터가 증가해도 유연하게 대응합니다.

4. **명확한 의도**: 적절한 자료구조를 사용하면 코드가 더 읽기 쉽고 유지보수하기 좋아집니다.

5. **문제 해결 용이**: 많은 알고리즘은 특정 자료구조를 기반으로 하므로, 자료구조를 이해하면 알고리즘도 쉬워집니다.

6. **표준 라이브러리**: 대부분의 언어가 기본 자료구조를 라이브러리로 제공하므로 직접 구현할 필요가 없습니다.

### 단점

1. **선택의 복잡성**: 상황에 맞는 자료구조를 선택하려면 경험이 필요합니다.

2. **오버헤드**: 자료구조가 복잡할수록 구현과 유지보수가 복잡해집니다.

3. **학습 곡선**: 각 자료구조의 내부 동작을 이해하려면 시간이 필요합니다.

4. **트레이드오프**: 한 연산이 빠르면 다른 연산이 느려지는 트레이드오프 관계가 있습니다(예: 배열은 접근 빠르지만 삭제 느림).

5. **메모리 오버헤드**: 일부 자료구조(연결 리스트, 트리)는 포인터로 인한 추가 메모리가 필요합니다.

6. **초기 설계의 중요성**: 초기에 잘못된 자료구조를 선택하면, 나중에 변경하는 것이 매우 비용이 많이 들 수 있습니다.

## 💡 실제 사례

### 사례 1: 웹 브라우저의 뒤로가기 기능

브라우저는 방문 페이지를 스택 자료구조로 관리합니다:
```
스택 상태:
[Google] ← top
[YouTube]
[Facebook]
[GitHub]

뒤로가기 클릭 → pop() → Google 제거, YouTube 활성화
```

스택의 LIFO 특성으로 가장 최근에 방문한 페이지부터 역순으로 돌아갑니다.

### 사례 2: 프린터 작업 대기열

여러 컴퓨터에서 프린터로 인쇄 요청이 들어올 때, 큐 자료구조를 사용합니다:
```
큐 상태:
[작업A] ← front (처음 들어옴)
[작업B]
[작업C]
[작업D] ← rear (마지막 들어옴)

프린팅 완료 → dequeue() → 작업A 제거, 작업B 처리
```

큐의 FIFO 특성으로 공정하게 순서대로 처리합니다.

### 사례 3: 파일 시스템의 디렉토리 구조

운영 체제의 파일시스템은 트리 자료구조로 구현됩니다:
```
루트 (/)
├── home/
│   ├── user1/
│   │   ├── Documents/
│   │   ├── Downloads/
│   └── user2/
├── usr/
│   ├── bin/
│   └── lib/
└── var/
```

트리 구조로 계층적 관계를 효율적으로 표현하고, 경로 탐색을 O(h)에 완료합니다(h = 깊이).

### 사례 4: SNS의 친구 관계

소셜 미디어는 그래프 자료구조로 사용자 간 관계를 표현합니다:
```
사용자: A, B, C, D, E
친구 관계 (간선):
A -- B
A -- C
B -- D
C -- D
D -- E

네트워크 분석:
- A와 E의 최단 거리: A-B-D-E (3단계)
- 공통 친구: A, B, C는 모두 D와 연결됨
- 커뮤니티 감지: {A,B,C,D}, {E} 등
```

그래프로 복잡한 관계를 모델링하고, DFS/BFS로 효율적으로 분석합니다.

### 사례 5: 데이터베이스 인덱싱

데이터베이스는 B-트리 같은 균형 트리를 인덱싱에 사용합니다:
```
원본 데이터 (선형 탐색): O(n) = 1,000,000번 비교
B-트리 인덱싱: O(log n) = 약 20번 비교

결과: 쿼리 응답 시간이 50,000배 단축됨
```

효율적인 자료구조로 대규모 데이터도 빠르게 처리합니다.

- **알고리즘**: 자료구조와 함께 성능을 결정하는 핵심 요소

- **트리 (Tree)**: 계층적 비선형 자료구조
- **그래프 (Graph)**: 네트워크 형태 비선형 자료구조
- **힙 (Heap)**: 우선순위 기반 자료구조
- **해시 테이블 (Hash Table)**: 빠른 검색 자료구조
- **시간 복잡도**: 자료구조 선택의 기준
- **공간 복잡도**: 메모리 효율성 평가 기준
- **Big O 표기법**: 자료구조 성능 분석 방식
