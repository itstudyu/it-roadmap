# 자료구조 (Data Structure)

## 📝 정의

자료구조는 **데이터를 어떤 모양으로 담아둘지 정해 놓은 방식**이다.

같은 데이터라도 담는 모양에 따라 찾고 넣고 지우는 속도가 달라진다. 그래서 무엇을 자주 할지 먼저 정하고 거기에 맞는 모양을 고른다.

### 비유
여행 가방 정리. 다 쑤셔 넣으면 찾을 때 통째로 뒤집어야 하고, 쓸 순서대로 넣어두면 꺼낼 때 손이 덜 간다.

### 예
연락처는 이름을 치면 곧바로 뜨는데, 사진첩에서 오래된 사진까지 내려가려면 한참 긁어야 한다.

## 🖼️ 그림으로 보기

```도해
층: 값 하나를 찾는 데 드는 시간은 어떻게 갈리나
O(1) :: 해시 테이블. 계산 한 번으로 자리를 안다
O(log n) :: 이진 탐색 트리. 볼 범위를 반씩 줄인다
O(n) :: 배열과 연결 리스트. 앞에서부터 훑는다
= 위로 갈수록 빠르지만 그만큼 붙는 조건도 많다
```

## ⚠️ 해결하는 문제

```도해
대조: 백만 개를 배열에 넣고 하나를 찾으면 어떻게 되나
배열에 그냥 || 맞는 모양으로
찾기 :: 평균 50만 번 || 트리는 20번쯤
넣고 빼기 :: 뒤를 다 민다 || 리스트는 한 번
관계 표현 :: 한 줄로만 || 계층과 망까지
= 담는 모양을 바꾸는 것만으로 같은 일이 몇 백 배 빨라진다
```

정렬되지 않은 배열 백만 개에서 값 하나를 찾으려면 앞에서부터 비교해야 하고 평균 오십만 번이 든다. 같은 데이터를 이진 탐색 트리에 담으면 스무 번쯤에 끝나고, 해시 테이블이면 평균 한 번이다.

모양이 아예 못 하는 일도 있다. 폴더 안의 폴더 같은 계층이나 친구의 친구 같은 망은 한 줄로 늘어놓은 구조로 표현되지 않는다. 계층은 트리로, 망은 그래프로 담는다.

## ⚙️ 작동 원리

크게 셋으로 나뉜다. 한 줄로 늘어놓는 선형에 배열과 연결 리스트와 스택과 큐가 있고, 계층이나 망을 이루는 비선형에 트리와 그래프와 힙이 있다. 열쇠를 계산해 자리를 정하는 해시 테이블은 따로 놓는다.

스택과 큐는 같은 줄인데 꺼내는 자리만 다르다. 스택은 마지막에 넣은 것을 먼저 꺼내고, 큐는 처음 넣은 것을 먼저 꺼낸다.

빠른 쪽에는 대가가 있다. 해시 테이블은 여분의 빈 칸을 들고 있어야 하고, 이진 탐색 트리는 정렬 기준이 있어야 하며 한쪽으로 치우치면 느려진다. 배열은 아무 조건이 없는 대신 앞에서부터 훑는다.

```도해
흐름: 자료구조 하나를 고를 때 무엇을 따져 보나
데이터 :: 몇 개나 되고 순서나 계층이 있나
연산 :: 자주 하는 게 찾기인가 넣고 빼기인가
후보 :: 그 연산이 빠른 모양을 몇 개 추린다
비교 :: 후보들의 시간 복잡도를 나란히 본다
선택 :: 자주 하는 연산이 가장 빠른 쪽을 고른다
= 무엇이 빠른 모양이냐가 아니라 무엇을 자주 하냐가 기준이다
```

## 📊 비교: 어느 연산이 빠른가

| | 접근 | 찾기 | 넣고 빼기 | 잘 맞는 자리 |
|---|---|---|---|---|
| 배열 | O(1) | O(n) | O(n) | 인덱스로 바로 꺼낼 때 |
| 연결 리스트 | O(n) | O(n) | O(1) | 중간에 자주 넣고 뺄 때 |
| 이진 탐색 트리 | O(log n) | O(log n) | O(log n) | 정렬된 채로 다룰 때 |
| 해시 테이블 | O(1) | O(1) | O(1) | 열쇠로 찾을 때 |
| 힙 | O(1) | O(n) | O(log n) | 가장 큰 것만 꺼낼 때 |

## 💡 실제 사례

- **브라우저 뒤로가기** — 방문한 페이지를 스택에 쌓아 두고 마지막 것부터 꺼낸다.
- **프린터 대기열** — 들어온 순서대로 큐에서 꺼내 처리한다.
- **파일 시스템** — 폴더 안의 폴더를 트리로 담아 경로를 따라 내려간다.

## 🚫 흔한 오해

- **좋은 자료구조와 나쁜 자료구조가 따로 있다** — 자주 하는 연산이 무엇이냐로 갈릴 뿐이다. 배열은 찾기가 느린 대신 인덱스로 꺼내는 건 가장 빠르다.
- **해시 테이블이 모든 면에서 제일 빠르다** — 열쇠로 콕 집어 찾을 때만 그렇다. 순서대로 훑거나 범위로 뽑아내는 일에는 쓸 수 없다.
- **라이브러리가 다 해주니 몰라도 된다** — 무엇을 쓸지 고르는 건 여전히 사람이다. 안에서 무슨 일이 일어나는지 모르면 느린 쪽을 고르고도 이유를 모른다.

## 🚨 주의사항

- **한쪽을 빠르게 하면 다른 쪽이 느려진다.** 전부 빠른 모양은 없고 무엇을 포기할지 정하는 일이다.
- **나중에 바꾸기가 어렵다.** 코드 여러 곳이 그 모양을 전제로 쓰이기 때문에 처음 고를 때의 값이 크다.

## 📝 정리

자료구조는 데이터를 어떤 모양으로 담아둘지 정해 놓은 방식이다. 무엇이 빠른 모양이냐가 아니라 내가 무엇을 자주 하느냐가 고르는 기준이 된다. 한쪽을 빠르게 하면 다른 쪽이 느려지므로 무엇을 포기할지 정하는 일에 가깝다.

## ❓ 이해했는지

- 백만 개에서 값 하나를 찾을 때 배열과 해시 테이블은 비교 횟수가 얼마나 차이 나나 → 해결하는 문제
- 브라우저 뒤로가기에 큐가 아니라 스택을 쓰는 이유는 → 작동 원리
- 해시 테이블이 가장 빠른데도 모든 자리에 쓰지 못하는 이유는 → 흔한 오해
