# Sorting (정렬)

## 📝 정의

Sorting 은 값을 정해진 순서대로 **줄 세우는** 일이다.

정렬은 그 자체가 목적인 일이 거의 없다. 뒤에 올 찾기·고르기·묶기를 싸게 만들려고 미리 치르는 값이고, 그래서 자료구조를 고르는 일과 늘 붙어 다닌다.

### 이름
= 본래 "종류별로 가르다" 는 말이었다. 지금은 종류가 아니라 정해진 순서로 가른다

### 비유
책장 정리. 제목 순으로 꽂아두면 찾을 책이 어느 칸쯤인지 손이 먼저 안다.

### 예
쇼핑몰에서 낮은 가격순 버튼을 누르는 그 순간 벌어지는 일이다.

### 직접
폰의 파일 앱이나 사진첩에서 정렬 기준을 이름순과 날짜순으로 번갈아 바꿔 보라. 같은 목록인데 손이 찾아가는 자리가 달라진다.

## 🖼️ 그림으로 보기

```도해
대조: 값을 줄 세워 두면 목록의 무엇이 달라지나
흐트러진 채 || 줄 세워 두면
어디에 있나 :: 봐야 안다 || 자리가 정해진다
가장 큰 값 :: 전부 봐야 안다 || 맨 끝에 있다
같은 값끼리 :: 흩어져 있다 || 나란히 붙는다
= 정해진 순서대로 줄을 세우면 무엇이 어디에 있는지가 정해진다
```

## ⚠️ 해결하는 문제

```도해
대조: 같은 목록에 여러 번 물어볼 때 무엇이 달라지나
물을 때마다 훑기 || 한 번 줄 세우기
100만 개에서 찾기 :: 100만 번 본다 || 스무 번 본다
값을 치르는 때 :: 물을 때마다 || 한 번만
상위 열 개 :: 전부 견준다 || 앞에서 열 개
= 줄 세우는 값을 한 번 치르면 뒤에 오는 물음이 전부 싸진다
```

흐트러진 목록에는 물을 수 있는 것이 별로 없다. 하나를 찾으려면 끝까지 훑어야 하고, 가장 큰 값을 알려면 전부 한 번은 봐야 하고, 같은 값이 몇 개인지도 다 세어봐야 안다. 물을 때마다 그 값을 다시 치른다.

정렬은 그 값을 **한 번에 몰아서** 치르는 것이다. 줄이 서 있으면 이진 탐색으로 절반씩 버려가며 찾을 수 있어서 100만 개짜리도 스무 번에 좁혀지고, 가장 큰 값은 맨 끝이라 볼 필요조차 없고, 같은 값끼리는 붙어 있어서 묶는 데 견줄 것이 없다. 정렬이 다른 모든 것을 빠르게 한다는 말은 이 뜻이다.

## ⚙️ 작동 원리

정렬 도구가 값에 요구하는 것은 놀랄 만큼 적다. Python 문서는 정렬 루틴이 두 값을 견줄 때 오직 `<` 만 쓴다고 적어 뒀고, Go 도 "이것이 저것보다 먼저 와야 하나" 한 가지만 답하게 한다. 그 하나만 정해주면 무엇이든 줄을 세울 수 있다.

값을 그대로 견주지 않고 **열쇠를 뽑아 견주는** 방식이 흔하다. 나이로 세울지 이름으로 세울지를 열쇠 함수 하나로 정한다. Python 문서는 이 방식이 빠른 이유를 열쇠 함수가 항목마다 정확히 한 번만 불리기 때문이라고 밝힌다.

Go 문서는 정렬 한 번에 견주는 횟수를 O(n log n) 으로 적어 뒀다. 100만 개면 견주는 횟수가 2천만 번 자릿수라, 앞에서 말한 "한 번에 몰아서 치르는 값" 이 공짜는 아니다. 다 줄 세울 필요가 없을 때 쓰라고 Python 이 부분 정렬 도구를 따로 두는 이유이기도 하다 — 가장 큰 값 하나는 한 번 훑으면 나오고, 상위 n 개는 n 개만 손에 들고 한 번 훑으면 나온다.

## 📊 비교: 안정 정렬과 그냥 정렬

```도해
대조: 같은 값이 여럿일 때 무엇이 갈리나
안정 정렬 |=| 그냥 정렬
같은 값끼리 :: 원래 순서 그대로 || 뒤바뀔 수 있다
두 번 나눠 세우면 :: 앞 결과가 남는다 || 앞 결과가 지워짐
치르는 값 :: 옮기는 일이 늘어난다 || 더 적게 옮긴다
= 같은 값끼리의 순서에 뜻이 있으면 안정 정렬을 골라야 한다
```

**안정 정렬은 열쇠가 같은 항목들의 원래 순서를 지키는 정렬이다.** Python 은 정렬이 안정하다고 문서에서 보장한다. Go 문서는 그 반대를 못 박아 뒀다 — 그냥 정렬은 값이 같은 것들을 어떤 순서로든 놓을 수 있고, 원래 순서를 지키는 쪽은 안정 정렬이라고. 그래서 함수가 둘로 나뉘어 있다.

치르는 값이 다른 것도 문서에 적혀 있다. Go 의 안정 정렬은 견주는 횟수는 같은데 자리를 옮기는 횟수가 더 많다.

## 💡 실제 사례

- **여러 기준으로 줄 세우기** — 성적 내림차순 다음 나이 오름차순으로 세우려면 나이로 먼저 세우고 성적으로 다시 세운다. 안정 정렬이라 뒤 정렬이 앞 결과를 지우지 않는다. Python 문서가 그대로 드는 예다.
- **대소문자 무시하고 줄 세우기** — 값을 그대로 견주는 대신 소문자로 바꾼 것을 열쇠로 삼는다. 열쇠 함수는 항목마다 한 번만 불리므로 매번 다시 바꾸지 않는다.
- **상위 몇 개만 뽑기** — 전부 줄 세우지 않고 n 개만 손에 들고 한 번 훑는 도구를 쓴다. n 이 전체에 비해 작으면 견주는 횟수가 온전한 정렬보다 훨씬 적다.

## 🚫 흔한 오해

- **정렬은 보기 좋게 하려고 하는 것이다** — 보기는 곁따라 오는 것이고, 본래 값은 뒤에 오는 물음이 싸진다는 데 있다. 이진 탐색은 정렬돼 있지 않으면 아예 쓸 수 없다.
- **같은 값끼리는 순서가 어차피 상관없다** — 정렬을 두 번 나눠 걸 때 앞 정렬의 결과가 바로 그 순서에 실려 있다. 그것이 지워지면 두 기준으로 세우는 방법이 사라진다.
- **정렬해 두면 무엇이든 빨라진다** — 값 하나를 정확히 집는 일이라면 딕셔너리가 더 빠르고, 가장 큰 값 하나나 상위 열 개만 필요한데 전부 줄 세우는 것은 낭비다.

## 📝 정리

**"찾기를 싸게 만들려고 미리 세우는 줄"** 이라고 읽으면 된다. 줄이 서 있으면 반씩 버려 찾을 수 있고 가장 큰 값이 끝에 있고 같은 값끼리 붙어 있어서, 뒤에 오는 물음이 전부 싸진다. 같은 값끼리의 원래 순서까지 지키는 것이 안정 정렬이고, 여러 기준으로 나눠 세울 때 그 성질이 없으면 앞 결과가 지워진다.

## 🧒 열 살에게

책을 아무렇게나 쌓아 두면 한 권 찾을 때마다 전부 뒤져야 하지? 제목 순서대로 한 번만 꽂아 두면, 다음부터는 가운데를 펼쳐 보고 앞쪽이냐 뒤쪽이냐만 고르면 돼. 맨 끝에 뭐가 있는지도 한 권만 보면 알고.

## ❓ 이해했는지

- 성적과 나이 두 기준으로 세울 때 나이부터 정렬하는 이유는 → 실제 사례
- 같은 값끼리의 순서를 지키는 정렬이 더 비싼 이유는 → 비교
- 줄 세워 두면 가장 큰 값을 찾는 일이 왜 볼 필요조차 없어지나 → 그림
