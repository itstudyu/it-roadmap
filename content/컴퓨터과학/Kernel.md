# Kernel (커널)

## 📝 정의

Kernel은 **하드웨어에 직접 닿는 운영체제의 가장 안쪽 층**이다.

[[OS]] 가 사람이 쓸 수 있게 묶어 놓은 전체라면, 커널은 그 안에서 CPU·메모리·장치를 실제로 쥐고 있는 부분이다. 리눅스 문서는 자기 자신을 "유닉스의 클론" 이라고 소개하면서, 진짜 멀티태스킹과 가상 메모리, 요구 시 적재, 제대로 된 메모리 관리를 갖췄다고 열거한다.

### 이름
Kernel :: 견과의 속 알맹이
= 껍질을 다 벗겨내도 남는 그 안쪽. 운영체제에서 덜어낼 수 없는 심이 이 자리다

### 비유
배의 기관실. 승객은 갑판에서만 지내고, 엔진에 손을 넣는 것은 기관실 사람뿐이다.

### 예
화면이 파랗게 변하며 컴퓨터가 저 혼자 다시 켜지던 순간이 있다. 앱 하나가 죽는 것과는 다른 일이다.

### 직접
작업 관리자(맥은 활성 상태 보기)를 열고 CPU 칸을 보라. "커널" 또는 "시스템" 으로 따로 적힌 몫이 커널이 쓴 시간이다.

## 🖼️ 그림으로 보기

```도해
층: 커널은 어디에 서 있나
응용 프로그램 :: 브라우저와 앱. 제 몫의 주소 공간 안에만 산다
시스템 호출 :: 커널로 넘어가는 경계. 여기서 모드가 바뀐다
커널 :: 프로세스·메모리·파일을 쥐고 장치를 부린다
하드웨어 :: CPU, 메모리, 디스크. 커널을 통해서만 닿는다
= 맨 아래에 손을 넣는 층은 커널이고, 위는 부탁만 한다
```

## ⚠️ 해결하는 문제

```도해
대조: 모드를 나누지 않으면 무엇이 위험한가
경계 없이 || 커널 모드로
주소 공간 :: 남의 자리를 봄 || 각자 격리된다
앱이 죽으면 :: 전체가 멈춘다 || 그 앱만 죽는다
장치 :: 아무나 직접 잡음 || 커널이 대신 한다
= 선을 그어야 앱 하나가 죽어도 컴퓨터는 산다
```

경계가 없으면 프로그램 하나의 실수가 전부의 실수가 된다. 남의 메모리에 쓸 수 있으니 자료가 조용히 망가지고, 장치를 직접 잡을 수 있으니 둘이 같은 장치를 동시에 물면 어느 쪽도 제대로 못 쓴다.

그래서 프로세서가 모드를 둘 갖는다. 윈도우 문서의 설명대로, 사용자 모드 앱은 각자 제 몫의 주소 공간을 받아 남의 자료를 못 고치고 운영체제가 예약해 둔 주소에는 아예 닿지 못한다. 그 선 너머에서 도는 코드가 커널이고, 프로그램은 [[System Call]] 로만 선을 넘는다.

## ⚙️ 작동 원리

커널이 늘 쥐고 있는 것은 넷이다.

| 쥔 것 | 하는 일 |
|---|---|
| **CPU** | 지금 어느 프로세스가 돌지 정하고 아주 짧게 번갈아 준다 |
| **메모리** | 가상 주소를 실제 주소에 잇고, 쓰이는 부분만 올린다 |
| **파일 시스템** | 디스크의 블록을 이름과 폴더로 보여준다 |
| **장치** | 드라이버를 통해 기종마다 다른 말을 하나로 맞춘다 |

넷을 한 층에 모아 둔 대가가 있다. 커널 모드에서 도는 코드는 전부 **하나의 가상 주소 공간을 나눠 쓴다.** 윈도우 문서의 표현대로 커널 모드 드라이버는 다른 드라이버나 운영체제로부터 격리되지 않고, 엉뚱한 주소에 쓰면 남의 자료를 망친다. 위쪽 앱이 서로를 못 건드리는 것과 정반대다.

## 💡 실제 사례

- **한 앱이 죽어도 나머지가 산다** — 앱마다 주소 공간이 따로라서, 브라우저가 죽어도 편집기와 운영체제는 그대로 돈다.
- **가상 메모리** — 프로그램이 보는 주소는 실제 주소가 아니다. 커널이 그 사이를 잇고, 실제로 쓰이는 부분만 올려 준다.
- **사용자 모드 드라이버** — 모든 드라이버가 커널 안에 있지는 않다. 일부는 사용자 모드에서 돌아서, 죽어도 운영체제까지 끌고 내려가지 않는다.

## 🚫 흔한 오해

- **커널이 곧 운영체제다** — 커널은 자원을 쥔 안쪽 부분이다. 셸과 창 관리자, 기본 앱은 그 위 사용자 모드에서 도는 별개의 코드다.
- **하드웨어를 다루는 코드는 다 커널 안에 있다** — 대부분은 그렇다. 다만 윈도우 문서는 드라이버 가운데 일부가 사용자 모드에서 동작한다고 적어 둔다.
- **커널 모드에 넣으면 빨라지니 넣을수록 좋다** — 커널 모드에는 격리가 없다. 앱이 죽으면 그 앱만 죽지만, 커널 모드 코드가 죽으면 운영체제 전체가 함께 멈춘다.

## 🚨 주의사항

- **커널 모드에는 격리가 없다** — 커널 코드는 모두 하나의 가상 주소 공간을 함께 쓴다. 드라이버가 주소를 잘못 짚으면 운영체제의 자료를 덮어쓴다.
- **드라이버 하나가 컴퓨터를 멈춘다** — 윈도우 문서는 커널 모드 드라이버가 죽으면 운영체제 전체가 죽는다고 그대로 적어 둔다. 블루스크린과 커널 패닉이 그 장면이다.
- **커널이 밖에 내놓은 약속은 못 되돌린다** — 시스템 콜은 커널 API 의 일부라, 커널 문서는 한번 내보내면 무한히 지원해야 한다고 못 박는다.

## 📝 정리

**"하드웨어에 직접 손을 넣는 그 안쪽 층"** 이라고 읽으면 된다. 사용자 모드 프로그램은 각자 격리돼 있지만 커널 모드 코드는 주소 공간 하나를 함께 쓴다. 그래서 앱이 죽으면 그 앱만 죽고, 커널이 죽으면 컴퓨터가 멈춘다.

## 🧒 열 살에게

큰 배에서 손님은 갑판에서만 놀고, 엔진에 손을 넣는 건 기관실 사람뿐이지? 컴퓨터 안에도 그런 기관실이 있어서 앱들은 거기다 부탁만 하고 직접 들어가지는 못해. 그래서 앱 하나가 망가져도 배는 계속 가지만, 기관실이 멈추면 배가 통째로 서.
