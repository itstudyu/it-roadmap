# RAM (Random Access Memory)

## 📝 정의

RAM은 **실행 중인 것만 올려두는 작업 공간**이다.

디스크는 파일을 오래 보관하는 곳이고 RAM은 지금 쓰는 것을 펼쳐두는 곳이다. 전원이 꺼지면 RAM의 내용은 사라진다. 대신 디스크보다 훨씬 빨라서 CPU가 곧바로 꺼내 쓸 수 있다.

### 비유
책상. 서랍에 아무리 많이 넣어둬도 지금 보는 서류는 책상 위에 펼쳐야 한다. 책상이 좁으면 자꾸 넣었다 뺐다 해야 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 프로그램을 실행하면 무엇이 어디로 옮겨지나
디스크 :: 프로그램 파일이 저장되어 있다
실행 :: 필요한 부분을 RAM 으로 읽어 올린다
RAM :: 코드와 데이터가 펼쳐진 채로 놓인다
CPU :: RAM 에서 바로 꺼내 계산한다
< 종료 :: 그 자리를 비워 다른 프로그램에 내준다
= 디스크는 보관, RAM 은 펼쳐놓는 자리다
```

## ⚠️ 해결하는 문제

```도해
대조: 작업 데이터를 어디에 두나
디스크에 두면 || RAM 에 두면
접근 시간 :: 밀리초 단위 || 나노초 단위
CPU :: 기다리며 논다 || 바로 이어서 쓴다
프로그램 :: 눈에 띄게 느리다 || 제 속도가 난다
= 속도 차이가 워낙 커서 중간 자리가 반드시 필요하다
```

CPU가 값 하나를 계산하는 시간과 디스크에서 값을 읽어 오는 시간은 자릿수가 크게 다르다. 디스크에서 매번 꺼내 쓰면 CPU가 대부분의 시간을 기다리며 보낸다.

RAM은 그 사이를 메운다. 지금 쓰는 것만 여기 올려두면 CPU가 기다리는 시간이 줄어든다. 대신 전원이 끊기면 사라지므로 오래 남길 것은 디스크로 내려보내야 한다.

## ⚙️ 작동 원리

메모리는 여러 층으로 겹쳐 있고 위로 갈수록 빠르고 작다.

```도해
층: 데이터는 어디에서 찾아 오나
레지스터 :: CPU 안. 지금 계산하는 값 몇 개
캐시 :: CPU 옆. 자주 쓰는 것 수 MB
RAM :: 실행 중인 프로그램 전부. 수 GB
디스크 :: 껐다 켜도 남는 것 전부. 수 TB
= 위에서 찾으면 빠르고 아래로 내려갈수록 기다리는 시간이 길어진다
```

RAM이 모자라면 운영체제는 당장 안 쓰는 부분을 디스크로 밀어낸다. 이걸 스왑이라고 한다. 프로그램은 계속 돌지만 밀려난 부분을 다시 쓸 때마다 디스크를 거치게 되어 체감 속도가 크게 떨어진다.

프로그램이 쓰고 나서 반납하지 않은 메모리가 쌓이면 남은 자리가 계속 줄어든다. 이 상태가 이어지면 스왑이 늘고 결국 실행이 멈춘다.

## 💡 실제 사례

- **탭을 많이 열었을 때** — 브라우저 탭마다 RAM을 쓰고, 자리가 모자라면 오래된 탭이 디스크로 밀려 다시 열 때 느려진다.
- **큰 파일 처리** — 파일을 통째로 읽으면 그만큼 RAM을 차지한다. 조각으로 나눠 읽으면 쓰는 양을 일정하게 유지할 수 있다.
- **계산 결과 재사용** — 한 번 계산한 값을 RAM에 두면 다음 요청 때 계산을 건너뛴다.

## 🚫 흔한 오해

- **저장 공간이 크면 RAM은 적어도 된다** — 별개다. 디스크는 보관하는 곳이고 RAM은 펼쳐놓는 곳이라, 디스크가 아무리 커도 RAM이 모자라면 스왑이 일어나 느려진다.
- **RAM을 늘리면 컴퓨터가 빨라진다** — 모자랄 때만 그렇다. 이미 남아돌면 더 꽂아도 계산 속도는 그대로다.
- **RAM 사용률이 높으면 나쁜 상태다** — 운영체제는 남는 자리를 캐시로 채워 쓴다. 봐야 할 것은 사용률보다 스왑이 일어나고 있는지다.

## 🚨 주의사항

- **스왑이 돌고 있으면 이미 늦었다.** 사용률보다 스왑 지표를 먼저 본다.
- **쓴 자리를 반납하지 않으면 서서히 무너진다.** 잠깐 쓰는 큰 데이터를 계속 붙잡아 두는 코드가 흔한 원인이다.

## 📝 정리

RAM은 실행 중인 것만 올려두는 빠른 작업 공간이고 전원이 꺼지면 비워진다. 디스크 용량과는 다른 자원이라, 모자라면 스왑이 일어나 프로그램 전체가 느려진다.
