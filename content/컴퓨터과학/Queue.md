# Queue (큐)

## 📝 정의

Queue는 **먼저 넣은 것을 먼저 꺼내는 자료구조**다.

넣는 곳과 꺼내는 곳이 반대편이다. 들어온 순서가 그대로 처리 순서가 되므로 아무도 새치기당하지 않는다.

### 비유
매표소 줄. 먼저 온 사람이 먼저 표를 산다. 뒤에 온 사람이 앞으로 갈 방법이 없고, 그래서 기다리는 시간을 예상할 수 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 작업 요청이 어떤 순서로 처리되나
요청 A :: 큐 뒤쪽에 들어간다
요청 B :: A 뒤에 붙는다
요청 C :: B 뒤에 붙는다
처리기 :: 앞쪽에서 A 를 꺼내 처리한다
처리기 :: 다음은 B. 그다음은 C
= 넣는 쪽과 꺼내는 쪽이 달라서 순서가 뒤집히지 않는다
```

## ⚠️ 해결하는 문제

```도해
대조: 요청이 처리 속도보다 빨리 들어오면 어떻게 되나
큐 없이 || 큐로
넘치는 요청 :: 버려진다 || 줄에 쌓인다
처리 순서 :: 뒤죽박죽 || 들어온 순서대로
대기 시간 :: 알 수 없다 || 줄 길이로 계산
= 들어오는 속도와 처리하는 속도를 따로 둘 수 있게 만든다
```

요청이 오는 속도와 처리하는 속도는 다르다. 몰릴 때는 처리기가 감당 못 하고, 한가할 때는 처리기가 논다. 큐가 없으면 몰리는 순간의 요청은 그냥 버려진다.

큐는 그 사이에 완충 지대를 둔다. 몰리면 줄이 길어질 뿐이고 처리기는 자기 속도로 계속 꺼낸다. 줄 길이를 보면 얼마나 밀렸는지도 바로 안다.

## ⚙️ 작동 원리

넣기와 꺼내기 모두 O(1)이어야 한다. 배열로 순진하게 만들면 앞에서 꺼낼 때마다 나머지를 한 칸씩 당겨야 해서 O(n)이 된다.

```도해
대조: 앞에서 꺼내는 구조를 어떻게 만드나
단순 배열로 || 당기지 않게
꺼낼 때 :: 전부 한 칸 당긴다 || 앞 위치만 옮긴다
비용 :: O(n) || O(1)
항목이 늘면 :: 급격히 느려진다 || 그대로다
= 앞에서 꺼내는 구조라서 "당기지 않는 방법" 이 구현의 핵심이다
```

당기지 않는 방법은 둘이다. 연결 리스트는 앞뒤 포인터만 옮기면 되고, 원형 배열은 앞뒤 위치를 옮겨 가며 자리를 돌려 쓴다.

변형이 몇 가지 있다. 양쪽에서 넣고 꺼내는 덱, 우선순위가 높은 것이 먼저 나오는 우선순위 큐가 대표적이다.

## 💡 실제 사례

- **작업 대기열** — 메일 발송이나 이미지 변환을 순서대로 처리한다.
- **프린터** — 인쇄 요청이 들어온 순서대로 출력된다.
- **너비 우선 탐색** — 그래프를 가까운 곳부터 훑을 때 다음에 볼 노드를 큐에 담는다.

## 🚫 흔한 오해

- **큐는 무한히 쌓을 수 있다** — 메모리에는 끝이 있다. 처리보다 들어오는 게 계속 빠르면 결국 넘친다. 상한을 정하고 넘칠 때 무엇을 할지 정해야 한다.
- **큐를 쓰면 처리가 빨라진다** — 처리 속도는 그대로다. 달라지는 건 순서가 보장되고 몰려도 안 잃는다는 점이다.
- **[[Message Queue]]와 같은 것이다** — 개념은 같지만 다른 층이다. 이쪽은 프로그램 안의 자료구조이고, 저쪽은 서버 사이에 두는 시스템이다.

## 🚨 주의사항

- **줄 길이를 지켜본다.** 길이가 계속 늘면 처리기가 부족하다는 신호다. 이 숫자가 가장 빠른 경보다.
- **배열로 직접 만들지 않는다.** 앞에서 꺼낼 때마다 당기는 구현은 항목이 늘수록 급격히 느려진다.

## 📝 정리

Queue는 먼저 넣은 것을 먼저 꺼내는 구조다. 들어오는 속도와 처리 속도를 분리해주며, 줄 길이가 곧 밀린 정도를 알려준다.

## ❓ 이해했는지

- 큐를 붙였는데 처리 속도가 그대로인 것이 정상인가 → 흔한 오해
- 배열 앞에서 꺼내는 구현이 왜 느려지나 → 작동 원리
- 큐 길이가 계속 늘고 있다면 무엇을 뜻하나 → 주의사항
