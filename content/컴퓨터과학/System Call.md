# System Call (시스템 콜)

## 📝 정의

System Call은 **프로그램이 커널에 일을 시키는 유일한 창구**다.

프로그램은 디스크에도 네트워크 카드에도 직접 손을 못 댄다. 파일을 읽는 것도 화면에 한 줄 찍는 것도 `read`·`write` 처럼 [[Kernel]] 이 미리 정해 둔 이름을 불러 부탁하는 일이고, 커널 문서는 이 지점을 사용자 공간과 커널이 맞닿는 자리라고 부른다.

### 비유
은행 창구. 금고에 직접 들어갈 수는 없고, 창구에 부탁하면 직원이 대신 꺼내 온다.

### 예
앱을 처음 켤 때 사진과 위치에 접근해도 되겠냐고 묻는 창이 뜬다. 그 부탁이 지나가는 자리가 여기다.

## 🖼️ 그림으로 보기

```도해
흐름: 파일 한 줄을 읽으면 커널까지 무엇이 오가나
프로그램 :: `read` 로 파일 번호와 담을 자리를 넘긴다
라이브러리 :: 커널이 정한 규약대로 인자를 놓는다
경계 :: CPU 가 사용자 모드에서 커널 모드로 바뀐다
커널 :: 표에서 그 번호의 함수를 찾아 실행한다
< 프로그램 :: 읽은 바이트 수를 돌려받고 사용자 모드로 돌아온다
= 프로그램은 부탁만 하고, 실제 일은 경계 너머에서 벌어진다
```

## ⚠️ 해결하는 문제

```도해
대조: 프로그램이 디스크를 직접 만지면 무엇이 문제인가
창구 없이 || 시스템 콜로
권한 :: 아무나 다 읽음 || 커널이 먼저 확인
장치 :: 기종마다 다시 씀 || 이름만 대면 된다
사고 :: 남의 자리를 덮음 || 커널 안에서 막힌다
= 부탁으로 바꾸는 순간, 확인할 자리가 하나 생긴다
```

프로그램이 저장 장치를 스스로 다루면 권한을 물어볼 곳이 없다. 남의 파일을 읽어도 막을 자리가 없고, 장치가 바뀌면 프로그램을 다시 써야 하고, 두 프로그램이 같은 자리를 동시에 건드리면 어느 쪽 자료가 남는지 알 수 없다.

시스템 콜은 그 일을 **부탁**으로 바꾼다. 커널만 실제로 장치를 다루니 확인은 한 군데서 하면 되고, 부탁하는 이름이 같으면 아래에 어떤 장치가 붙어 있든 프로그램은 그대로 돈다. 대신 그 이름을 지나지 않는 길이 없어져서, 프로그램이 컴퓨터에 무슨 일을 할 수 있는지가 이 목록 하나로 정해진다.

## ⚙️ 작동 원리

부탁은 이름이 아니라 **번호**로 간다. 아키텍처마다 시스템 콜 표가 따로 있고, 그 표의 한 줄이 번호와 이름과 실제로 실행될 함수를 묶는다. 커널은 넘어온 번호로 그 줄을 찾아 함수를 부른다. 커널 문서는 이 함수들을 "사용자 공간에서 시스템 콜 표를 통해서만 부르고, 커널 안 다른 곳에서는 부르지 말 것" 이라고 못 박아 둔다.

보통은 표준 라이브러리가 같은 이름의 함수로 감싸 준다. 감싼 함수가 없는 시스템 콜은 `syscall()` 로 번호를 직접 넘겨야 한다. 파이썬에서는 이 층이 그대로 드러난다 — 내장 `open()` 은 버퍼를 낀 파일 객체를 주고, `os.open()` 은 커널이 준 파일 서술자(열린 파일을 가리키는 작은 정수)를 그대로 준다.

## 💡 실제 사례

- **허용 목록으로 좁히기** — 허용할 시스템 콜만 미리 정해 두면 그 밖의 부탁은 커널이 실행하지 않고 오류로 되돌린다. 프로그램이 커널에 닿을 수 있는 면적이 줄어든다.
- **파이썬의 두 가지 파일 열기** — 내장 `open()` 은 버퍼를 낀 객체를, `os.open()` 은 파일 서술자를 준다. 뒤쪽이 커널에 붙은 쪽이다.
- **표준 입출력의 정체** — 0·1·2 라는 작은 정수가 각각 입력·출력·오류다. 시스템 콜은 파일을 이름이 아니라 이 번호로 가리킨다.

## 🚫 흔한 오해

- **파일을 읽는 건 프로그래밍 언어가 해준다** — 언어가 주는 건 포장이다. 파이썬 문서는 `os.open()` 을 낮은 층 전용이라 하고, 파일 서술자를 파일 객체로 감싸려면 `fdopen()` 을 쓰라고 안내한다.
- **시스템 콜은 그냥 함수 호출이다** — 이름만 함수다. 프로세서가 사용자 모드에서 커널 모드로 넘어가고, 커널은 그 함수를 시스템 콜 표를 통해서만 부른다.
- **시스템 콜을 직접 부르는 쪽이 항상 낫다** — 라이브러리를 건너뛰면 버퍼도 함께 사라진다. 파이썬 문서는 `os.read`·`os.write` 를 낮은 층 전용으로 두고, 보통은 내장 `open()` 을 쓰라고 말한다.

## 🚨 주의사항

- **번호가 어디서나 같지는 않다** — 시스템 콜 표가 아키텍처마다 따로 있다. 같은 이름이 같은 번호라는 보장이 없어서, 번호를 손으로 적어 둔 코드는 CPU 를 바꾸면 깨진다.
- **한번 낸 창구는 못 닫는다** — 커널 문서는 시스템 콜이 커널 API 의 일부이고 무한히 지원해야 한다고 적어 둔다. 인자를 잘못 잡으면 그 실수가 그대로 남는다.
- **버퍼와 섞어 쓰지 마라** — 파이썬 문서는 버퍼를 낀 파일 객체를 디스크까지 내려보내려면 `flush()` 를 먼저 부르고 나서 `os.fsync()` 를 부르라고 한다. 두 층을 같이 쓰면 순서가 어긋난다.

## 📝 정리

시스템 콜은 사용자 공간과 커널이 맞닿는 지점이고, 프로그램이 커널에 일을 시킬 수 있는 유일한 통로다. 언어와 라이브러리가 무엇을 주든 파일·네트워크·프로세스는 결국 이 창구를 지난다. 그래서 허용할 시스템 콜만 골라 두면 그 프로그램이 커널에 시킬 수 있는 일 자체가 줄어든다.
