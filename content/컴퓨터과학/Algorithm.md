# 알고리즘 (Algorithm)

## 📝 정의

알고리즘은 **문제를 푸는 절차를 단계로 적어둔 것**이다.

같은 문제를 풀어도 절차에 따라 걸리는 시간이 달라진다. 정렬되지 않은 100만 개에서 값 하나를 찾을 때 앞에서부터 훑으면 평균 50만 번 비교하지만, 정렬해두고 반씩 좁히면 20번이면 끝난다.

### 비유
요리 레시피. 같은 음식이라도 어떤 레시피를 따르느냐에 따라 걸리는 시간과 쓰는 재료가 달라진다.

## 🖼️ 그림으로 보기

```도해
흐름: 100만 개에서 값 하나를 어떻게 20번 만에 찾나
정렬 :: 값을 크기 순으로 미리 줄 세운다
가운데 :: 한가운데 값과 찾는 값을 비교한다
버리기 :: 크면 왼쪽 절반, 작으면 오른쪽 절반을 버린다
반복 :: 남은 절반에서 다시 가운데를 본다
< 도착 :: 남은 것이 하나가 되면 끝난다
= 한 번 비교할 때마다 후보가 절반으로 준다. 100만이 스무 번이면 하나가 된다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터가 1000배 늘면 무슨 일이 벌어지나
절차 없이 || 절차를 골라서
탐색 :: 앞에서부터 전부 || 반씩 좁힌다
1000배 늘면 :: 1000배 느려짐 || 열 번 더 비교
서버 :: 계속 늘려야 함 || 그대로 버틴다
= 데이터가 늘 때 시간이 어떻게 늘어나는지가 절차마다 다르다
```

작은 데이터에서는 어떻게 짜도 티가 안 난다. 문제는 데이터가 늘어날 때 드러난다. 앞에서부터 훑는 방식은 데이터가 1000배가 되면 시간도 1000배가 되고, 목록을 두 번 겹쳐 도는 방식은 100만 배가 된다.

절차를 고르는 일은 지금 몇 초 걸리느냐가 아니라 데이터가 늘어날 때 시간이 어떤 모양으로 늘어나는지를 고르는 일이다. 그 모양이 나쁘면 서버를 아무리 키워도 따라잡지 못한다.

## ⚙️ 작동 원리

```도해
층: 같은 일을 하는 절차인데 왜 어떤 건 못 쓰나
O(1) :: 데이터가 늘어도 시간이 그대로다
O(log n) :: 100만이 스무 번. 반씩 줄이는 방식
O(n) :: 데이터가 열 배면 시간도 열 배
O(n²) :: 열 배면 100배. 여기서부터 못 버틴다
= 지금 빠른지가 아니라, 데이터가 늘 때 어떻게 늘어나는지를 본다
```

이 표기는 걸리는 시간이 아니라 시간이 늘어나는 모양을 적은 것이다. 그래서 데이터가 열 개뿐이면 O(n²)가 O(n log n)보다 빠른 일이 흔하다. 나누고 합치는 준비 비용이 본 계산보다 크기 때문이다.

메모리도 같은 방식으로 잰다. 결과를 기억해두고 다시 쓰는 방식은 시간을 줄이는 대신 메모리를 더 쓴다. 둘 중 무엇을 내줄지가 대부분의 선택이다.

## 📊 비교

| 절차 | 평균 시간 | 최악 | 언제 쓰나 |
|---|---|---|---|
| 선형 탐색 | O(n) | O(n) | 정렬이 안 되어 있을 때 |
| 이진 탐색 | O(log n) | O(log n) | 정렬해둔 큰 데이터 |
| 삽입 정렬 | O(n²) | O(n²) | 거의 정렬된 작은 데이터 |
| 병합 정렬 | O(n log n) | O(n log n) | 최악의 경우까지 보장이 필요할 때 |
| 퀵 정렬 | O(n log n) | O(n²) | 평균이 중요한 일반적인 경우 |

## 💡 실제 사례

- **길찾기** — 가능한 모든 경로를 다 그려보는 대신 가까운 곳부터 넓혀가며 최단 경로를 찾는다.
- **자동 완성** — 입력할 때마다 전체 단어 목록을 훑지 않고, 앞글자로 갈래를 나눈 구조에서 해당 가지만 본다.
- **중복 제거** — 목록을 두 번 겹쳐 도는 대신 이미 본 값을 기록해두고 한 번만 돈다.

## 🚫 흔한 오해

- **알고리즘은 코딩 테스트에서나 쓴다** — 실무에서 매일 고르고 있다. 목록을 두 번 겹쳐 돌지, 본 값을 기록해두고 한 번만 돌지가 이미 그 선택이다.
- **더 빠른 알고리즘이 항상 낫다** — 데이터가 열 개면 O(n²)가 O(n log n)보다 빠를 때가 많다. 나누고 합치는 준비 비용이 본 계산보다 크기 때문이다.
- **O(n)은 걸리는 시간이다** — 시간이 아니라 데이터가 늘 때 시간이 늘어나는 모양이다. 그래서 O(n)이 O(n²)보다 늘 빠른 것도 아니다.

## 📝 정리

알고리즘은 문제를 푸는 절차이고, 같은 문제에도 절차는 여러 가지다. 무엇을 고를지는 데이터가 늘어날 때 시간이 어떻게 늘어나는지를 보고 정한다. 지금 빠른 것보다 나중에도 버티는 것을 고르는 일이다.

## ❓ 이해했는지

- 100만 개 중에서 값 하나를 스무 번 만에 찾으려면 그 전에 무엇이 되어 있어야 하나?
- 데이터가 열 개뿐인데 정렬 방식을 바꿨더니 오히려 느려졌다. 왜 그런가?
- 데이터가 열 배 늘었는데 시간이 100배 늘었다면 어느 복잡도인가?
