# Async/Await (비동기 문법)

## 📝 정의

Async/Await는 **비동기 코드를 위에서 아래로 읽히게 쓰는 문법**이다.

네트워크 응답을 기다리는 코드는 원래 "끝나면 이걸 해줘"라는 함수를 넘겨주는 식으로 썼다. 그걸 네 번 이어 붙이면 코드가 오른쪽으로 계속 밀려난다. `await`는 같은 일을 한 줄씩 내려가는 모양으로 쓰게 해준다.

### 비유
음식점 번호표. 주문하고 자리에 앉아 기다리는 동안 주방은 다른 손님 것도 만든다. 내 번호가 불리면 하던 자리에서 이어서 받는다.

### 예
앱에서 목록을 아래로 당겨 새로고침하면 위에서 동그라미가 도는데, 이미 떠 있는 글은 그대로 읽힌다.

## 🖼️ 그림으로 보기

```도해
흐름: await 를 만나면 함수는 무엇을 하나
함수 :: 사용자 정보를 요청하고 await 를 만난다
함수 :: 그 자리에서 멈추고 자리를 비켜준다
바깥 :: 그 사이 다른 코드가 돌아간다
응답 :: 사용자 정보가 도착한다
< 함수 :: 멈췄던 다음 줄부터 이어서 실행한다
= 멈추는 것은 그 함수 하나이고 프로그램 전체가 아니다
```

## ⚠️ 해결하는 문제

```도해
대조: 비동기 작업 네 개를 이어 붙이면 어떻게 되나
콜백으로 || await 로
코드 모양 :: 오른쪽으로 밀림 || 위에서 아래로
중간 값 :: 안쪽에서만 보임 || 전부 그대로
에러 처리 :: 단계마다 따로 || try-catch 하나
= 순서대로 일어나는 일을 순서대로 읽게 만드는 문법이다
```

콜백을 겹쳐 쓰면 사용자 정보에서 주문으로, 주문에서 결제로 넘어가는 흐름이 계단 모양으로 안쪽에 파묻힌다. 두 단계 앞에서 받은 값을 마지막 단계에서 쓰려면 그 값을 안쪽까지 들고 내려가야 한다.

`await`를 쓰면 그 값들이 전부 같은 자리에 남는다. 오류도 마찬가지다. 단계마다 오류 처리를 붙이는 대신 `try-catch` 하나로 묶을 수 있고, 어느 줄에서 났는지도 그대로 보인다.

## ⚙️ 작동 원리

`async`를 붙인 함수는 값을 반환하는 대신 "나중에 이 값이 될 것"을 반환한다. `await`는 그 값이 정해질 때까지 그 함수만 멈춰두고, 나머지 코드에는 자리를 내준다.

여기서 실수가 갈린다. `await`를 줄줄이 세우면 하나 끝나야 다음이 시작된다.

```javascript
// 순차. 1초 + 1초 + 1초 = 3초
const a = await fetchA();
const b = await fetchB();

// 동시. 셋을 한꺼번에 보내고 가장 느린 것만 기다린다
const [a, b, c] = await Promise.all([fetchA(), fetchB(), fetchC()]);
```

서로 결과를 참조하지 않는 요청이라면 묶어서 보내는 쪽이 맞다.

## 💡 실제 사례

- **화면 하나에 API 세 개** — 프로필, 알림, 설정을 각각 `await`로 부르면 세 번 기다리고, 묶어 보내면 한 번 기다린다.
- **재시도** — 실패하면 잠시 쉬었다 다시 부르는 코드를 반복문 안에 그냥 `await`로 쓸 수 있다.
- **파일 여러 개 내려받기** — 각 다운로드가 응답을 기다리는 동안 다른 다운로드가 진행되어 전체 시간이 가장 느린 하나에 가까워진다.

## 🚫 흔한 오해

- **await 를 쓰면 프로그램 전체가 멈춘다** — 멈추는 건 그 함수 하나다. 기다리는 동안 화면 조작이나 다른 요청은 계속 처리된다.
- **async 를 붙이면 코드가 빨라진다** — 빨라지지 않는다. `await`를 나란히 세우면 오히려 하나씩 순서대로 기다리게 되고, 동시에 보내려면 따로 묶어줘야 한다.
- **async/await 는 스레드를 새로 만든다** — 만들지 않는다. 한 흐름 안에서 순서를 바꿔 가며 도는 것이라 무거운 계산을 넣으면 그대로 막힌다.

## 🚨 주의사항

- **`await`는 `async` 함수 안에서만 쓴다.** 일반 함수에 넣으면 문법 오류가 난다.
- **반복문 안의 `await`는 순차 실행이다.** 항목마다 하나씩 기다리게 되므로, 서로 무관한 작업이면 묶어서 한꺼번에 보낸다.

## 📝 정리

Async/Await는 기다리는 코드를 순서대로 읽히게 만드는 문법이다. 기다리는 동안 그 함수만 비켜주고 다른 코드는 계속 돌지만, 새 스레드가 생기지도 않고 코드가 저절로 빨라지지도 않는다.

## ❓ 이해했는지

- 서로 무관한 API 세 개를 각각 `await`로 부르면 왜 가장 느린 하나보다 오래 걸리나 → 작동 원리
- 무거운 계산을 `async` 함수에 넣었는데도 화면이 멈추는 이유는 → 흔한 오해
- `await`를 만난 함수가 멈춰 있는 동안 프로그램은 무엇을 하고 있나 → 그림
