# Process (프로세스)

## 📝 정의

Process는 **실행 중인 프로그램**이다.

디스크에 놓인 실행 파일은 아직 프로세스가 아니다. 그 파일을 메모리에 올리고 운영체제가 번호와 자원을 붙여주는 순간부터 프로세스가 된다.

### 비유
레시피와 요리. 레시피는 종이에 적혀 있는 것이고, 요리는 지금 불 위에서 벌어지고 있는 일이다. 같은 레시피로 두 냄비를 동시에 올릴 수도 있다.

### 예
실행 파일을 더블클릭하기 전에는 작업 관리자에 없던 이름이 켜는 순간 목록에 나타난다.

## 🖼️ 그림으로 보기

```도해
흐름: 프로그램을 더블클릭하면 무엇이 프로세스가 되나
디스크 :: 실행 파일이 그냥 파일로 놓여 있다
OS :: 파일을 메모리에 올리고 PID 를 붙인다
OS :: 코드, 데이터, 힙, 스택 자리를 잡아준다
준비 :: CPU 를 받을 차례를 기다린다
실행 :: 차례가 오면 CPU 위에서 돈다
< OS :: 끝나면 메모리와 PID 를 회수한다
= 파일은 레시피고 프로세스는 지금 하고 있는 요리다
```

## ⚠️ 해결하는 문제

```도해
대조: 프로그램 하나가 멈추면 컴퓨터는 어떻게 되나
프로세스 없이 || 프로세스로
동시 실행 :: 한 번에 하나 || 여러 개 같이
메모리 :: 같은 주소 충돌 || 각자 따로 본다
하나가 멈추면 :: 전체가 먹통 || 그것만 끝낸다
= 격리해두면 하나가 무너져도 옆이 같이 무너지지 않는다
```

실행 단위를 나누지 않으면 프로그램 둘이 같은 메모리 주소에 값을 써서 서로를 덮어쓴다. 하나가 무한 루프에 빠지면 CPU를 놓지 않아 컴퓨터 전체가 멈추고 다시 켜는 것 말고는 방법이 없다.

운영체제는 프로그램마다 번호를 붙이고 자기만의 메모리 공간과 CPU 차례를 준다. 그래서 한쪽이 잘못돼도 그 프로세스만 끝내면 되고, 브라우저를 켜둔 채 다른 프로그램을 시작할 수 있다.

## 🧱 구성

```도해
층: 프로세스 하나는 메모리를 어떻게 나눠 쓰나
코드 :: 실행할 명령이 들어간다. 읽기 전용
데이터 :: 전역 변수와 정적 변수. 시작할 때 잡힌다
힙 :: 실행 중에 필요할 때 받아 쓰는 자리
스택 :: 함수 호출과 지역 변수. 끝나면 저절로 빠진다
= 위쪽은 시작할 때 정해지고 아래쪽은 도는 동안 늘었다 줄었다 한다
```

## ⚙️ 작동 원리

프로세스는 만들어진 뒤 계속 CPU를 쥐고 있지 않는다. 차례를 기다리는 준비 상태, CPU 위에서 도는 실행 상태, 파일 읽기나 네트워크 응답을 기다리는 대기 상태를 오간다. 입출력을 기다리는 동안 CPU를 내려놓기 때문에 그 시간에 다른 프로세스가 돈다.

메모리를 따로 쓰는 대가도 있다. 프로세스끼리는 변수를 그냥 공유할 수 없어서, 값을 주고받으려면 큐나 파이프 같은 IPC 수단을 거쳐야 한다.

## 📊 비교: Process 와 Thread

| | Process | Thread |
|---|---|---|
| 메모리 | 각자 따로 | 같이 쓴다 |
| 만드는 비용 | 크다 | 작다 |
| 값 주고받기 | IPC가 필요 | 변수로 바로 |
| 하나가 죽으면 | 나머지는 무사 | 같이 위험하다 |

## 💡 실제 사례

- **응답 없는 프로그램 끄기** — 작업 관리자에서 그 프로세스만 골라 끝내면 나머지는 그대로 돈다.
- **CPU를 많이 쓰는 계산** — 파이썬에서 무거운 계산을 나눌 때 스레드 대신 프로세스를 여러 개 띄운다. 프로세스마다 인터프리터가 따로라 GIL에 걸리지 않는다.
- **프로세스 사이 데이터 전달** — 생산자와 소비자를 따로 띄우고 큐를 통해 값을 넘긴다.

## 🚫 흔한 오해

- **프로그램과 프로세스는 같은 말이다** — 프로그램은 디스크에 있는 파일이고 프로세스는 그것을 메모리에 올려 돌리고 있는 상태다. 같은 프로그램을 두 번 실행하면 프로세스는 둘이다.
- **두 프로세스가 같은 주소를 쓰면 값이 섞인다** — 프로그램이 보는 주소는 가상 주소다. 운영체제가 각각을 다른 물리 메모리에 연결해두기 때문에 같은 숫자여도 다른 자리다.
- **프로세스를 많이 만들수록 빨라진다** — 만들고 전환하는 데 비용이 든다. CPU 코어 수를 크게 넘겨 만들면 오히려 느려진다.

## 📝 정리

Process는 디스크에 있던 프로그램을 메모리에 올려 돌리고 있는 상태다. 운영체제가 프로세스마다 독립된 메모리 공간과 실행 차례를 나눠주기 때문에 여러 프로그램이 서로를 건드리지 않고 같이 돈다. 대신 격리된 만큼 만드는 비용이 크고 값을 주고받으려면 따로 통로가 필요하다.

## ❓ 이해했는지

- 더블클릭한 실행 파일이 프로세스가 되기까지 운영체제는 무엇을 해주나 → 그림
- 두 프로세스가 같은 메모리 주소를 써도 값이 섞이지 않는 이유는 → 흔한 오해
- 무거운 계산을 나눌 때 스레드가 아니라 프로세스를 쓰는 이유는 → 실제 사례
