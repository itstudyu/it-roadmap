# File System (파일 시스템)

## 📝 정의

File System은 **저장 장치의 칸들을 파일과 폴더로 보이게 하는 규칙**이다.

디스크가 실제로 주는 것은 번호 붙은 칸의 나열뿐이다. 윈도우 문서는 파일 시스템을 응용 프로그램이 저장 장치에 파일을 넣고 꺼낼 수 있게 하는 것이라고 짧게 적고, 이름 짓는 규칙과 경로를 적는 형식까지 파일 시스템이 정한다고 덧붙인다.

### 비유
창고와 장부. 물건은 빈 칸에 아무렇게나 넣고, 어디에 무엇을 넣었는지는 장부가 따로 적어 둔다.

### 예
새로 산 외장 하드를 처음 꽂으면 포맷부터 하라는 말이 뜬다. 그 규칙을 아직 정해두지 않아서다.

## 🖼️ 그림으로 보기

```도해
흐름: 파일 이름 하나가 어떻게 실제 바이트가 되나
경로 :: `/` 부터 한 칸씩 이름을 따라 내려간다
폴더 :: 폴더도 파일이다. 이름을 번호로 바꿔 준다
inode :: 그 번호의 표. 크기·권한·블록 위치가 적혀 있다
블록 :: 저장 장치의 4KiB 칸들. 흩어져 있어도 된다
< 프로그램 :: 이어 붙인 바이트만 건네받는다
= 이름은 폴더가, 내용의 위치는 표가 따로 들고 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 파일 시스템이 없으면 디스크는 어떻게 쓰이나
규칙 없이 || 파일 시스템으로
찾기 :: 몇 번 칸인지 왼다 || 이름으로 찾는다
크기 변경 :: 뒤를 밀어야 한다 || 빈 칸을 이어 붙인다
프로그램 :: 장치마다 다시 씀 || 같은 호출로 읽는다
= 장치는 번호 붙은 칸뿐이고, 이름과 계층은 규칙이 만든다
```

파일 시스템이 없으면 프로그램이 장부를 스스로 들어야 한다. "내 자료는 4000번 칸부터 12칸" 을 적어 두고 기억해야 하고, 자료가 커지면 뒤 칸을 쓰던 다른 프로그램과 부딪히고, 장치가 바뀌면 그 계산을 다시 해야 한다.

파일 시스템은 그 장부를 대신 든다. 이름과 계층, 경로를 적는 형식, 어떤 칸이 비었는지를 규칙으로 정해 두고 프로그램에서는 이름만 받는다. 그래서 프로그램은 자기 자료가 몇 번 칸에 있는지 끝내 모른 채로 파일을 읽는다.

## 🧱 구성

```도해
층: 종류가 여럿인데 왜 같은 방법으로 읽히나
프로그램 :: `open` `read` `write` 만 부른다
VFS :: 커널 안의 공통 창구. 종류 차이를 흡수한다
ext4·NTFS :: 이름과 위치를 실제로 어떻게 적을지 정한다
블록 장치 :: 디스크·SSD·메모리카드. 번호 붙은 칸을 준다
= 위에서 하나로 보이게 만드는 층이 VFS 다
```

## ⚙️ 작동 원리

커널 문서는 VFS 를 사용자 프로그램에 파일 시스템 인터페이스를 제공하는 커널 안의 소프트웨어 층이라고 정의하고, 서로 다른 파일 시스템 구현이 함께 존재할 수 있게 하는 추상화라고 덧붙인다. 마운트한 파일 시스템 하나는 커널 안에서 superblock 객체 하나로 표현되고, 폴더에 붙이는 순간 그 파일 시스템의 방식이 그 아래에 적용된다.

경로를 매번 디스크까지 뒤지면 느리다. 그래서 커널은 경로 조각(dentry)을 따로 캐시로 들고 있는데, 커널 문서는 이것이 RAM 에만 살고 디스크에는 절대 저장되지 않으며 순전히 속도를 위해 존재한다고 적어 둔다.

## 💡 실제 사례

- **USB 를 꽂으면 폴더가 생긴다** — 그 파일 시스템을 폴더 하나에 붙이는 것이 마운트다. 커널은 그것을 superblock 하나로 잡는다.
- **이름만 바꾸는 것은 즉시 끝난다** — 폴더가 든 이름표만 고치면 된다. 내용이 든 블록은 한 칸도 움직이지 않는다.
- **작은 파일도 칸 하나를 쓴다** — ext4 의 기본 블록이 4KiB 다. 한 글자만 담은 파일도 대개 그 칸 하나를 차지한다.

## 🚫 흔한 오해

- **파일은 폴더 안에 들어 있다** — 폴더는 이름과 번호를 적어 둔 목록일 뿐이다. 커널 문서도 폴더를 이름을 inode 번호에 대응시키는 파일이라고 설명한다.
- **파일 이름은 그 파일에 붙어 있다** — 이름은 폴더 쪽에 적혀 있다. 크기·권한·시간·블록 위치는 inode 에 있지만 이름은 거기 없다.
- **파일 시스템은 종류가 달라도 결국 같은 것이다** — 위에서 부르는 호출만 같다. 자료를 어떤 형식으로 적고 무슨 기능을 주는지는 종류마다 따로 정하고, 그 차이를 커널의 VFS 가 가려 준다.

## 🚨 주의사항

- **이름 규칙은 파일 시스템이 정한다** — 어떤 문자를 쓸 수 있고 경로를 어떻게 적는지가 종류마다 다르다. 다른 파일 시스템으로 옮겨 담을 때 이름이 깨지는 이유다.
- **블록 크기가 곧 최소 단위다** — 기본 4KiB 라서, 아주 작은 파일이 많으면 자료를 다 더한 것보다 장치를 더 먹는다.
- **쓴 것이 아직 디스크에 없을 수 있다** — 파이썬 문서는 버퍼를 낀 파일 객체의 내용을 디스크까지 내려보내려면 `flush()` 를 먼저 부르고 나서 `os.fsync()` 를 부르라고 한다.

## 📝 정리

파일 시스템은 번호 붙은 칸뿐인 저장 장치 위에 이름과 계층을 세우는 규칙이다. 이름은 폴더가 들고, 크기와 블록 위치는 그 번호의 표인 inode 가 든다. 종류가 여럿인데도 프로그램이 같은 호출로 읽는 것은 커널의 VFS 가 그 차이를 흡수하기 때문이다.

## ❓ 이해했는지

- 파일 이름만 바꾸는 것이 내용을 옮기는 것보다 훨씬 빠른 이유는 → 실제 사례
- ext4 와 NTFS 를 같은 `read` 로 읽을 수 있는 이유는 → 작동 원리
- 한 글자만 담은 파일이 장치에서 4KiB 를 차지하는 이유는 → 주의사항
