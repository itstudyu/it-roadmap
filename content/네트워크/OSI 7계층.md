# OSI 7계층 (OSI 7-Layer Model)

## 📝 정의

OSI 7계층은 국제표준화기구(ISO)에서 정의한 네트워크 통신 표준으로, 컴퓨터 간의 통신 과정을 7개의 계층으로 나누어 설명하는 참조 모델입니다. 각 계층은 정의된 기능을 수행하며, 하위 계층의 기능을 바탕으로 상위 계층의 기능이 구현됩니다. 이러한 계층 구조를 통해 복잡한 네트워크 통신을 이해하기 쉽고, 각 계층을 독립적으로 개선할 수 있습니다.

OSI 7계층은 하위부터 물리(Physical), 데이터링크(Data Link), 네트워크(Network), 전송(Transport), 세션(Session), 표현(Presentation), 응용(Application) 계층으로 구성됩니다. 데이터는 송신자에서 최상위 계층부터 최하위 계층까지 내려가면서 각 계층의 헤더가 붙는 캡슐화 과정을 거칩니다. 수신자에서는 최하위 계층부터 최상위 계층까지 올라가면서 각 계층의 헤더를 제거하는 역캡슐화 과정을 거칩니다.

> **한 줄 요약**: 네트워크 통신의 복잡한 과정을 7개의 계층으로 나누어 표준화한 참조 모델

> **비유**: 🔵우편 배송 시스템 - 편지가 우체국(1계층) → 배송 센터(2계층) → 지역 배송소(3계층) → 배송 담당자(4계층) → 수령인(7계층)을 거치는 것처럼, 데이터도 각 계층을 순서대로 거침 / 🟡건물 건설 - 기초(1계층) → 벽(2계층) → 골조(3계층) → 배관(4계층) → 인테리어(6-7계층)처럼 각 단계가 하위 계층 위에 구성됨

## 🎯 핵심 개념

### 1. 계층 간의 독립성
OSI 모델의 가장 중요한 특징은 각 계층이 독립적으로 작동한다는 것입니다. 한 계층의 변경이 다른 계층에 영향을 주지 않으므로, 예를 들어 와이파이에서 이더넷으로 물리적 매체를 바꿔도 상위 계층의 애플리케이션은 영향을 받지 않습니다. 이러한 모듈화 설계는 네트워크 기술의 발전을 빠르게 하고, 각 계층의 전문가가 독립적으로 개선할 수 있게 합니다.

### 2. 캡슐화와 역캡슐화
데이터가 송신자에서 수신자로 이동할 때, 각 계층을 거치면서 해당 계층의 헤더(또는 트레일러)가 붙습니다. 이를 캡슐화라고 합니다. 예를 들어 애플리케이션 데이터는 전송 계층의 TCP/UDP 헤더를 붙여 세그먼트가 되고, 네트워크 계층의 IP 헤더를 붙여 패킷이 되고, 데이터링크 계층의 프레임 헤더를 붙여 프레임이 됩니다. 수신자에서는 이 과정이 역순으로 진행되어 각 계층의 헤더가 제거됩니다.

### 3. 계층별 PDU (Protocol Data Unit)
각 계층에서 다루는 데이터의 단위를 PDU라고 합니다. 7계층 응용 계층의 PDU는 데이터이고, 4계층 전송 계층의 PDU는 세그먼트(또는 데이터그램)이고, 3계층 네트워크 계층의 PDU는 패킷이고, 2계층 데이터링크 계층의 PDU는 프레임입니다. 각 계층은 상위 계층으로부터 받은 PDU를 자신의 단위로 변환하여 처리합니다.

### 4. 계층 간의 통신 방식
각 계층은 인접한 계층과만 통신합니다. 상위 계층은 하위 계층에 서비스를 요청하고, 하위 계층은 상위 계층에 서비스를 제공합니다. 이를 SAP(Service Access Point)를 통해 구현됩니다. 계층 간의 통신 인터페이스가 명확하게 정의되어 있으므로, 각 계층의 내부 구현이 바뀌어도 인터페이스가 같으면 다른 계층에 영향을 주지 않습니다.

### 5. 각 계층의 역할
물리 계층은 전기 신호를 전송하고, 데이터링크 계층은 같은 네트워크 내에서 주소 기반 통신(MAC 주소)을 담당합니다. 네트워크 계층은 다른 네트워크 간의 라우팅(IP 주소)을 담당하고, 전송 계층은 프로세스 간의 통신(포트)을 담당합니다. 세션 계층은 통신의 시작과 종료를 관리하고, 표현 계층은 데이터 형식 변환을 담당하고, 응용 계층은 사용자와 직접 상호작용하는 서비스를 제공합니다.

## ⚠️ 해결하는 문제

### 문제 1: 네트워크 통신의 복잡성
네트워크 통신은 매우 복잡한 과정으로, 물리적 매체를 통한 신호 전송부터 애플리케이션의 데이터 처리까지 다양한 기술이 필요합니다. OSI 7계층 모델은 이 복잡한 과정을 7개의 단계로 나누어 각 단계를 이해하기 쉽게 합니다. 네트워크 문제가 발생할 때도 어느 계층에서 문제가 발생했는지를 체계적으로 파악할 수 있습니다.

### 문제 2: 기술 개선의 어려움
만약 네트워크 통신을 일체의 하나로 봤다면, 한 부분을 개선하려면 전체 시스템을 재설계해야 합니다. OSI 모델은 계층을 분리함으로써 각 계층을 독립적으로 개선할 수 있게 합니다. 예를 들어 더 빠른 물리 매체가 개발되어도 상위 계층은 변경할 필요가 없습니다.

### 문제 3: 상호운용성의 부족
다양한 제조사의 네트워크 장비들이 통신하려면 공통의 표준이 필요합니다. OSI 7계층 모델은 국제 표준으로서 모든 네트워크 장비 제조사가 따르는 기준을 제공합니다. 이를 통해 다른 제조사의 라우터, 스위치, 호스트 등이 함께 작동할 수 있습니다.

### 문제 4: 각 계층의 역할 모호성
계층이 없다면 각 프로토콜과 기술이 어느 단계에서 필요한지, 어떤 책임을 가지는지 불명확합니다. OSI 모델은 TCP, IP, 이더넷, HTTP 등 다양한 프로토콜을 특정 계층에 배치하여 각 기술의 역할을 명확히 합니다. 이를 통해 네트워크 아키텍처를 이해하기 쉬워집니다.

## ⚙️ 작동 원리

송신자의 애플리케이션에서 사용자가 작성한 데이터(예: HTTP 요청)는 7계층 응용 계층으로 전달됩니다. 응용 계층은 HTTP, SMTP, FTP 등의 애플리케이션 프로토콜을 사용하여 데이터를 처리하고 6계층으로 전달합니다.

6계층 표현 계층은 데이터의 형식을 변환합니다. 문자 인코딩(UTF-8, ASCII), 암호화, 압축 등을 수행하여 7계층으로부터 받은 데이터를 표준 형식으로 변환합니다. 변환된 데이터는 5계층으로 전달됩니다.

5계층 세션 계층은 통신의 시작, 유지, 종료를 관리합니다. 양쪽 호스트 간의 대화를 세션으로 정의하고, 동기화를 수행하며, 데이터 흐름을 조절합니다. 예를 들어 TCP 연결의 3-way handshake는 세션 계층의 역할입니다.

4계층 전송 계층은 종단 간(end-to-end) 통신을 담당합니다. TCP 또는 UDP를 선택하여 프로세스 간의 통신을 제공합니다. TCP/UDP 헤더에 출발지 포트와 목적지 포트를 추가하고, 신뢰성 보장(TCP의 경우)이나 속도 최적화(UDP의 경우)를 수행합니다.

3계층 네트워크 계층은 다른 네트워크와의 통신을 담당합니다. IP 주소 기반의 라우팅을 수행하여 패킷이 최종 목적지에 도달하도록 합니다. 라우터는 주로 이 계층에서 작동합니다.

2계층 데이터링크 계층은 같은 물리 네트워크 내에서의 통신을 담당합니다. MAC 주소(물리 주소)를 사용하여 인접한 호스트 간의 통신을 수행합니다. 스위치는 주로 이 계층에서 작동하며, 이더넷 프로토콜이 이 계층에서 정의됩니다.

1계층 물리 계층은 실제 전송 매체를 통해 전기 신호를 보냅니다. 전압, 주파수, 케이블 사양 등을 정의하고, 비트를 전기 신호로 변환하여 전송합니다. 수신자에서는 이 과정이 역순으로 진행되어 각 계층이 헤더를 제거하고 데이터를 상위 계층으로 전달합니다.

## ✅ 장단점

### 장점
- **명확한 구조**: 네트워크 통신을 7개의 계층으로 나누어 각 부분을 이해하기 쉽습니다.
- **독립성과 모듈화**: 각 계층이 독립적으로 작동하므로 한 계층의 변경이 다른 계층에 영향을 주지 않습니다.
- **표준화**: 국제 표준으로서 모든 네트워크 기기 제조사가 따르는 공통의 기준을 제공합니다.
- **문제 해결 용이**: 네트워크 문제가 발생할 때 어느 계층에서 문제가 발생했는지를 체계적으로 파악할 수 있습니다.
- **기술 발전의 용이성**: 각 계층을 독립적으로 개선할 수 있으므로 새로운 기술 도입이 쉽습니다.

### 단점
- **실제 구현과의 불일치**: 실제 네트워크는 OSI 모델과 완벽하게 일치하지 않습니다(예: TCP/IP 4계층 모델).
- **세션, 표현 계층의 모호함**: 5계층과 6계층의 역할이 실제 구현에서 명확하지 않은 경우가 많습니다.
- **복잡한 구조**: 7개의 계층을 모두 이해하려면 학습량이 많고, 초보자에게는 복잡할 수 있습니다.
- **성능 오버헤드**: 각 계층에서 헤더를 추가하고 처리하는 과정으로 인해 성능이 저하될 수 있습니다.
- **실무에서의 제한된 사용**: 실제로는 TCP/IP 4계층 모델이 더 널리 사용되므로 OSI 모델은 교육 및 이론적 이해에 주로 사용됩니다.

## 💡 실제 사례

웹 요청이 OSI 7계층을 통해 전달되는 과정을 보면, 사용자가 브라우저에 URL을 입력하면 7계층 응용 계층의 HTTP 프로토콜이 요청을 생성합니다. 6계층 표현 계층에서는 데이터를 인코딩하고 필요하면 암호화(HTTPS의 경우 SSL/TLS)를 수행합니다. 5계층 세션 계층에서는 웹 서버와의 세션을 관리합니다.

4계층 전송 계층에서는 TCP를 사용하여 신뢰성 있는 전송을 보장합니다. 3계층 네트워크 계층에서는 목적지 서버의 IP 주소를 기반으로 패킷을 라우팅합니다. 2계층 데이터링크 계층에서는 로컬 네트워크 내에서 다음 홉(hop)의 MAC 주소를 사용하여 프레임을 전달합니다. 1계층 물리 계층에서는 이더넷 케이블을 통해 전기 신호로 변환되어 전송됩니다.

Wireshark 같은 패킷 분석 도구를 사용할 때도 OSI 모델을 이해하면 매우 유용합니다. 패킷을 캡처하면 각 계층의 헤더를 분리된 섹션으로 볼 수 있습니다. 맨 아래의 프레임 정보는 2계층, 그 위의 IP 정보는 3계층, TCP/UDP 정보는 4계층, HTTP 정보는 7계층을 나타냅니다. 이를 통해 데이터가 어느 계층에서 손상되었는지 파악할 수 있습니다.

네트워크 문제 해결에도 계층 개념이 유용합니다. 예를 들어 컴퓨터가 인터넷에 연결되지 않으면, 먼저 1계층(케이블이 연결되었는가?), 2계층(IP 주소를 받았는가?), 3계층(라우터에 도달할 수 있는가?), 4계층(특정 포트가 열려있는가?), 7계층(웹 서버가 응답하는가?) 순서대로 확인할 수 있습니다.

## 🔗 관련 용어

- **TCP/IP 4계층**: OSI 7계층을 4개로 단순화한 실무 모델
- **캡슐화(Encapsulation)**: 각 계층이 상위 계층의 데이터에 헤더를 추가하는 과정
- **역캡슐화(Decapsulation)**: 각 계층이 헤더를 제거하는 과정
- **PDU(Protocol Data Unit)**: 각 계층에서 다루는 데이터의 단위
- **SAP(Service Access Point)**: 계층 간의 통신을 위한 인터페이스
- **라우터**: 3계층 네트워크 계층에서 작동하는 네트워크 장비
- **스위치**: 2계층 데이터링크 계층에서 작동하는 네트워크 장비
