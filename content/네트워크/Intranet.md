# Intranet (인트라넷)

## 📝 정의

인트라넷(Intranet)은 인터넷 기술(TCP/IP, 웹 브라우저, HTTP 등)을 활용하지만 **특정 조직(기업, 학교, 정부기관)의 내부에서만 접근 가능한 사설 네트워크**입니다. 외부 인터넷과는 방화벽으로 분리되어 있으며, 조직 구성원만이 내부 시스템, 문서, 애플리케이션에 접근할 수 있습니다.

인터넷(Internet)의 "inter-(사이)"와 달리, 인트라넷의 "intra-(내부)"는 조직 내부를 의미합니다. 인터넷이 발전하기 전에는 조직 내 정보 공유를 위해 전용 소프트웨어가 필요했지만, 인트라넷은 기존 웹 기술을 그대로 사용하여 내부 네트워크를 구축합니다. 사원 포털, 인사 시스템(HR), 내부 문서 관리, ERP 시스템 등이 인트라넷에서 운영됩니다.

> **한 줄 요약**: "인터넷 기술로 만든 회사 전용 내부 네트워크 — 외부에서는 접근 불가"

**비유**:
- **사내 방송망 비유**: 회사 내부 방송(인트라넷)은 회사 건물 내에서만 수신되고, 외부에서는 들을 수 없습니다. 같은 방송 기술을 쓰지만 전파 범위가 내부로 제한됩니다.
- **군 내부망 비유**: 군대의 국방망처럼, 외부 인터넷과 물리적으로 분리된 내부망에서 군사 정보를 안전하게 공유합니다.

## 🎯 핵심 개념

### 1. 인트라넷 vs 인터넷 vs 엑스트라넷
- **인터넷(Internet)**: 전 세계 누구나 접근 가능한 공개 네트워크
- **인트라넷(Intranet)**: 조직 내부 구성원만 접근 가능한 사설 네트워크
- **엑스트라넷(Extranet)**: 인트라넷의 일부를 협력업체, 파트너 등 외부 특정 대상에게만 제한적으로 공개한 네트워크

### 2. 인트라넷의 핵심 구성요소
- **내부 웹 서버**: 조직 포털, 공지사항, 프로세스 문서 호스팅
- **내부 DNS**: 내부 도메인 이름(예: hr.company.internal) 해석
- **방화벽**: 외부 인터넷과 인트라넷을 분리하고 접근을 제어
- **VPN**: 재택근무자나 출장 직원이 외부에서 인트라넷에 접근하는 경로
- **LDAP/Active Directory**: 내부 사용자 인증 및 권한 관리

### 3. 온프레미스 vs 클라우드 인트라넷
- **온프레미스 인트라넷**: 자체 데이터센터에서 운영. 높은 보안, 높은 비용
- **클라우드 기반 인트라넷**: AWS Private Cloud, Microsoft 365 SharePoint 등. 유연성 높음
- **하이브리드**: 핵심 시스템은 온프레미스, 협업 도구는 클라우드

### 4. 주요 인트라넷 서비스
- **사원 포털**: 회사 공지, 복리후생, 조직도
- **그룹웨어**: 이메일, 일정, 문서 공유
- **ERP/HR 시스템**: 인사, 급여, 재무 관리
- **내부 Wiki/문서**: 지식 관리, 프로세스 문서
- **DevOps 도구**: 내부 Git 서버(GitLab), CI/CD, 모니터링

## ⚠️ 해결하는 문제

### 문제 1: 내부 정보의 외부 노출 위험
인사 정보, 재무 데이터, 영업 기밀 등 민감한 정보를 인터넷에 공개하면 보안 위협이 됩니다. 인트라넷은 이러한 정보를 조직 내부에서만 접근 가능하도록 격리합니다.

### 문제 2: 분산된 조직 내 정보 공유
지점이 여러 곳에 있거나 원격 근무자가 많은 조직에서, 모든 직원이 동일한 정보와 도구에 접근해야 합니다. 인트라넷은 물리적 위치에 관계없이(VPN을 통해) 통합된 내부 환경을 제공합니다.

### 문제 3: 외부 인터넷 의존성 없는 업무
인터넷이 불안정해도 내부 업무 시스템은 계속 운영되어야 합니다. 인트라넷은 외부 인터넷과 독립적으로 운영되어, 인터넷 장애가 내부 업무에 미치는 영향을 최소화합니다.

## ⚙️ 작동 원리

### 1단계: 내부 네트워크 구성
조직의 서버들을 사설 IP 대역(예: 10.0.0.0/8)으로 구성합니다. 내부 DNS 서버를 설정하여 `portal.company.internal` 같은 내부 도메인을 사용합니다. 방화벽으로 외부 인터넷과 분리합니다.

### 2단계: 직원 인증
내부 접속 시 Active Directory나 LDAP 기반 인증을 사용합니다. 직원들은 회사 계정(아이디/비밀번호)으로 한 번 로그인하면(SSO) 모든 내부 시스템에 접근할 수 있습니다.

### 3단계: 서비스 접근
사무실 내에서는 내부 IP나 내부 도메인으로 각 서비스에 접근합니다. 웹 브라우저에서 `http://portal.company.internal`을 입력하면 인사 포털에 접근됩니다.

### 4단계: 원격 접근 (VPN)
사무실 외부에서는 VPN 클라이언트를 연결하여 마치 사내에 있는 것처럼 인트라넷에 접근합니다. VPN 연결 후에는 `portal.company.internal` 같은 내부 주소에 접근 가능합니다.

| **접근 범위** | 내부 구성원만 | 승인된 외부 파트너 | 누구나 | 계정 보유자 |
| **보안 수준** | 매우 높음 | 높음 | 낮음 | 중간 |
| **인증 방식** | AD/LDAP/SSO | VPN + 계정 | 없음/선택 | 계정 인증 |
| **구축 비용** | 높음 | 높음 | - | 낮음 (구독) |
| **유지 관리** | 직접 관리 | 직접 관리 | ISP | 벤더 관리 |

| **가용성** | 내부 인프라 의존 | 내부 인프라 의존 | ISP 의존 | 벤더 의존 |
| **적합 규모** | 중대형 기업 | 협력사 많은 기업 | - | 소규모~대형 |

## ✅ 장단점

**장점**:
- 민감한 내부 데이터와 시스템을 외부로부터 완전히 격리하여 보안 강화
- 인터넷 연결 없이도 내부 업무 시스템 운영 가능 (외부 의존성 최소화)
- 표준 웹 기술 사용으로 사용자가 별도 교육 없이 사용 가능
- 조직 전체의 정보 공유와 협업 효율 향상
- 컴플라이언스 요건(금융, 의료, 정부)을 충족하는 데이터 보호 가능

**단점**:
- 서버, 네트워크 장비, IT 인력 등 초기 구축 및 유지 비용 높음
- 외부에서 접근하려면 VPN 설정이 필요하여 번거로움
- SaaS 도구(Slack, Notion 등)에 비해 사용자 경험이 떨어질 수 있음
- 클라우드 서비스 확산으로 인트라넷의 역할이 점차 클라우드로 이전되는 추세
- 재해복구(DR) 계획 및 백업 관리를 직접 해야 함

## 💡 실제 사례

### 1. 대기업 사원 포털
삼성, LG 같은 대기업은 `https://portal.company.com` 같은 내부 포털을 운영합니다. 이 포털에서 급여 명세서 확인, 휴가 신청, 출장 정산, 교육 신청 등 모든 인사/행정 업무를 처리합니다. 외부에서는 VPN 연결 후에만 접근 가능합니다.

### 2. 병원 내부 의료 정보 시스템 (EMR)
병원은 환자 의료 기록을 인트라넷 기반의 EMR(Electronic Medical Records) 시스템에서 관리합니다. 환자 개인 정보 보호를 위해 인터넷과 완전히 분리된 내부망에서만 접근 가능하며, 의료진은 병원 내부나 VPN을 통해서만 EMR에 접근합니다.

### 3. 공공기관 국가망
정부기관은 행정망(인트라넷)을 인터넷과 물리적으로 분리하여 운영합니다. 공무원들은 행정 업무를 외부 인터넷이 아닌 행정망에서 처리하며, 민감한 국가 정보는 외부에서 접근 불가능합니다.

## 🔗 관련 용어

- **VPN (Virtual Private Network)**: 원격에서 인트라넷에 안전하게 접속하는 기술
- **방화벽 (Firewall)**: 인트라넷과 인터넷 사이의 트래픽을 제어하는 보안 장치
- **DMZ**: 인트라넷과 인터넷 사이의 완충 영역. 공개 서버를 배치
- **Active Directory/LDAP**: 인트라넷 사용자 인증 및 접근 권한 관리 시스템
- **SSO (Single Sign-On)**: 인트라넷 내 여러 시스템을 하나의 로그인으로 접근하는 기술
- **엑스트라넷 (Extranet)**: 인트라넷의 일부를 외부 파트너에게 제한적으로 공개한 네트워크
- **Private Subnet**: 클라우드 환경에서 인트라넷과 유사하게 외부 접근을 차단한 서브넷
- **On-Premises**: 자체 데이터센터에서 인트라넷 서버를 직접 운영하는 방식
