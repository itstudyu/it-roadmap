# Nginx (엔진엑스)

## 📝 정의

Nginx 는 **요청을 먼저 받아 파일을 주거나 뒤 서버로 넘기는 프로그램**이다.

이벤트 기반으로 만들어져서, 연결마다 프로세스를 띄우지 않고 적은 수의 워커가 많은 연결을 나눠 맡는다. 그래서 동시 접속이 몰릴 때 메모리가 덜 든다.

### 비유
건물 1층 안내 데스크. 가벼운 일은 그 자리에서 처리하고, 나머지는 담당 부서로 올려 보낸다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청이 들어오면 Nginx 는 무엇부터 보나
요청 :: 브라우저가 80 또는 443 으로 들어온다
Nginx :: 주소가 어느 location 에 맞는지 고른다
정적 파일 :: 이미지나 CSS 면 그 자리에서 돌려준다
프록시 :: 아니면 뒤에 있는 앱 서버로 넘긴다
앱 서버 :: 처리해서 결과를 돌려준다
< Nginx :: 압축해서 브라우저에 전달한다
= 앱 서버가 안 해도 되는 일을 앞에서 걷어내는 것이 이 자리의 일이다
```

## ⚠️ 해결하는 문제

```도해
대조: 앱 서버가 요청을 직접 다 받으면 어떻게 되나
앞단 없이 || Nginx 를 두면
정적 파일 :: 앱이 직접 읽는다 || 앞에서 끝낸다
동시 접속 :: 프로세스가 는다 || 적은 수로 받는다
서버 늘리기 :: 주소가 바뀐다 || 뒤에서만 바뀐다
= 앞에 한 겹을 두면 뒤를 바꿔도 밖에서는 같은 주소로 보인다
```

앱 서버가 이미지와 CSS 까지 직접 읽어 내보내면, 로직을 돌려야 할 일꾼이 파일 읽기에 붙잡힌다. 동시 접속이 늘 때 연결마다 프로세스나 스레드가 붙는 구조라면 메모리부터 바닥난다.

Nginx 를 앞에 두면 정적 파일은 거기서 끝나고, 앱 서버로는 정말 로직이 필요한 요청만 간다. 서버를 여러 대로 늘리거나 교체해도 밖에서 보는 주소는 그대로다.

## ⚙️ 작동 원리

```도해
층: Nginx 는 어떤 일을 대신 맡아주나
정적 파일 :: 이미지, CSS, JS 를 직접 돌려준다
TLS 종료 :: 인증서를 여기서 처리하고 뒤로는 평문
로드 밸런싱 :: 뒤에 붙은 서버들에 요청을 나눈다
접근 제어 :: IP 제한, 호출 횟수 제한, 기본 인증
= 하나같이 앱 코드가 안 해도 되는 일이라, 앞으로 뺄수록 뒤가 단순해진다
```

설정은 `server` 블록 안에 `location` 을 두고, 주소가 어디에 맞는지에 따라 다르게 처리하는 구조다. 뒤로 넘길 때는 `proxy_pass` 를 쓰고, 원래 요청자의 IP 와 프로토콜을 헤더에 실어 보내야 앱 쪽에서 알 수 있다.

로드 밸런싱은 `upstream` 에 서버 목록을 적어두면 된다. 기본은 차례로 돌리는 방식이고, 연결이 적은 쪽으로 보내거나 같은 IP 를 같은 서버로 붙이는 방식도 고를 수 있다.

## 📊 비교

| | Nginx | Apache |
|---|---|---|
| 처리 방식 | 이벤트 기반 | 연결마다 프로세스 |
| 동시 연결 | 수만 개 | 수천 개 |
| 메모리 | 적게 쓴다 | 많이 쓴다 |
| 동적 처리 | 뒤로 넘긴다 | 직접 처리 |

## 💡 실제 사례

- **앱 서버 앞단** 앱은 로컬 포트에서만 돌게 두고, 바깥 요청은 Nginx 가 받아 넘긴다.
- **SPA 서비스** 빌드된 파일을 직접 주고, 없는 경로는 `index.html` 로 보내 라우팅을 화면 쪽에 맡긴다.
- **무중단 설정 반영** 문법을 확인한 뒤 reload 를 걸어 연결을 끊지 않고 새 설정을 적용한다.

## 🚫 흔한 오해

- **Nginx 가 웹 애플리케이션을 실행한다** — 직접 돌리지 않는다. 파일을 주거나 뒤에 있는 앱으로 넘길 뿐이다.
- **설정 파일을 고치면 바로 적용된다** — 다시 읽어들여야 한다. 문법을 확인하고 reload 를 해야 새 설정이 산다.
- **로드 밸런싱을 켜면 로그인이 알아서 유지된다** — 요청마다 다른 서버로 갈 수 있다. 세션을 서버 메모리에 두면 로그인이 풀린다.

## 🚨 주의사항

- **설정을 바꾸면 먼저 문법을 검사한다.** 틀린 설정으로 재시작하면 그 순간 서비스가 내려간다.
- **프록시 헤더를 빠뜨리지 않는다.** 원래 요청자의 IP 를 넘기지 않으면 앱 로그에 Nginx 의 주소만 남는다.

## 📝 정리

Nginx 는 요청을 가장 먼저 받아 파일을 돌려주거나 뒤 서버로 넘기는 앞단이다. 정적 파일, 인증서 처리, 요청 분배, 접근 제어를 앱 코드 밖으로 빼준다. 앱을 직접 실행하는 물건은 아니다.

## ❓ 이해했는지

- 설정 파일을 고쳤는데 화면이 그대로다. 무엇을 빠뜨렸나?
- 서버를 여러 대로 늘린 뒤부터 새로고침할 때마다 로그아웃된다. 어디를 보나?
- 이미지 요청 때문에 앱 서버가 바쁘다. 어디서 끊나?
