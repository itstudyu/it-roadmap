# VLAN (가상 랜)

## 📝 정의

VLAN 은 **같은 선을 쓰면서도 서로 닿지 못하게 갈라 둔 망**이다.

가르는 방법은 선을 새로 까는 것이 아니라 프레임에 번호표를 하나 끼우는 것이다. IEEE 802.1Q 가 그 번호표의 모양과, 번호를 아는 스위치가 어떻게 동작하는지를 정한 표준이다.

### 이름
Virtual :: 실물이 아닌
Local :: 한 군데의
Area :: 구역
Network :: 이어진 망
= 붙여 읽으면 "선을 새로 깔지 않고 만든 한 구역의 망". 같은 선인데 다른 방인 셈이다

### 비유
사무실 하나를 파티션으로 나눈 것과 같다. 바닥도 천장도 그대로인데 옆 칸 사람과는 문을 통해서만 만난다.

### 예
회사에서 업무용 와이파이와 손님용 와이파이가 따로 있는데 벽 속의 선은 같은 한 가닥인 경우다.

### 직접
집 공유기 설정에서 "게스트 와이파이" 를 켜 보라. 기계도 선도 하나인데 그쪽에 붙은 폰에서는 내 컴퓨터가 안 보인다.

## 🖼️ 그림으로 보기

```도해
층: 왜 같은 선을 흐르는데 서로 안 섞이나
이더넷 머리 :: 어디서 어디로 — 14바이트
VLAN 태그 :: 4바이트. 이 안의 번호가 칸을 가른다
IP 조각 :: 실제로 나르는 내용
꼬리 검사값 :: 오다가 망가졌는지 보는 4바이트
= 프레임 가운데 끼운 4바이트짜리 번호표, 그것이 망을 가르는 전부다
```

## ⚠️ 해결하는 문제

```도해
대조: 선 하나에 두 조직을 태우면 어떻게 되나
번호표 없이 || 번호표를 붙여
같은 선 :: 서로 다 보인다 || 번호 다르면 못 봄
갈라놓으려면 :: 선을 따로 깐다 || 번호만 다르게 준다
자리 옮길 때 :: 배선을 다시 한다 || 포트 설정만 바꾼다
= 물리적으로 한 선인 것을 번호 하나가 두 개의 망으로 만든다
```

선을 물리적으로 나누면 확실하지만, 조직이 바뀔 때마다 배선을 다시 해야 하고 층마다 스위치를 따로 사야 한다. 개발팀이 3층으로 옮기면 3층까지 개발팀 전용 선을 끌고 가야 한다는 뜻이다.

번호표는 그 셈을 뒤집는다. 선과 스위치는 하나로 두고, **어느 포트가 몇 번인지만 설정으로 바꾼다.** AWS Direct Connect 가 전용선 한 가닥 위에서 가상 인터페이스마다 VLAN 번호를 하나씩 요구하고, Google Cloud 의 VLAN 어태치먼트가 전용 인터커넥트 한 가닥 위에 802.1Q VLAN 하나를 할당해 VPC 에 잇는 것이 같은 셈법이다.

## ⚙️ 작동 원리

```도해
흐름: 번호표는 어디서 붙고 어디서 떨어지나
접속 포트 :: 번호표 없는 프레임이 들어온다
들어온 곳 :: 그 포트에 정해진 번호를 붙인다
트렁크 :: 여러 번호가 한 선을 함께 탄다
나가는 곳 :: 같은 번호의 포트로만 내보낸다
끝단 기기 :: 번호표가 떨어진 프레임을 받는다
= 번호표는 스위치 사이 구간에만 산다. 끝에 붙은 기기는 갈린 줄도 모른다
```

번호는 12비트라 **1부터 4094 까지**만 쓸 수 있다. AWS 도 가상 인터페이스를 만들 때 "1 과 4094 사이여야 하고 이더넷 802.1Q 표준을 따라야 한다" 고 같은 범위를 요구한다. 태그가 4바이트 붙기 때문에 프레임은 1518 대신 1522바이트가 되고, AWS 문서가 프레임 크기를 `14 + 4 + IP 조각 + 4` 로 적는 그 `4` 가 이 태그다.

리눅스에서 직접 만들어 보면 구조가 그대로 보인다.

- `ip link add link eth0 name eth0.10 type vlan id 10` — eth0 위에 10번 칸을 하나 만든다
- `ip -d link show eth0.10` — `vlan protocol 802.1Q id 10` 이 찍힌다
- `tcpdump -e -i eth0 vlan` — 실제로 흐르는 프레임에 `vlan 10,` 이 붙어 있는지 본다
- `bridge vlan show` — 어느 포트가 어떤 번호를 태그 채로/떼고 내보내는지

다른 번호끼리 통신하려면 반드시 3계층 장비를 거쳐야 한다. 그 지점이 유일한 통로이므로, 조직 간 규칙은 거기에 건다.

## 📊 비교: 접속 포트와 트렁크 포트는 무엇이 다른가

```도해
대조: 두 종류의 포트는 무엇이 다른가
접속 포트 |=| 트렁크 포트
나르는 번호 :: 하나뿐이다 || 여럿을 함께 나른다
번호표 :: 떼고 내보낸다 || 붙인 채로 흐른다
붙는 것 :: 컴퓨터·프린터 || 스위치·라우터
= 끝단은 갈린 줄 모르고, 중간 구간만 번호를 알고 있다
```

## 💡 실제 사례

- **손님용 와이파이** — 같은 공유기, 같은 선인데 손님 쪽에서는 사내 프린터가 안 보인다. 번호가 다를 뿐이다.
- **전용선 한 가닥에 여러 계정** — AWS Direct Connect 는 가상 인터페이스마다 1~4094 중 겹치지 않는 번호를 요구한다. 광케이블은 한 가닥이고 그 위를 여러 조직이 나눠 쓴다.
- **자리 이동** — 개발팀이 3층으로 옮겨도 그 자리 포트의 번호만 바꾸면 같은 망에 그대로 남는다. 배선은 손대지 않는다.

## 🚫 흔한 오해

- **번호를 나누면 절대 못 만난다** — 스위치만으로는 그렇지만 라우터나 3계층 스위치를 거치면 만난다. 그 통로에 규칙을 걸지 않으면 나눈 의미가 없다.
- **VLAN 이 방화벽을 대신한다** — 갈라 두기는 하지만 트렁크 설정 하나가 어긋나면 옆 칸이 통째로 보인다. 갈라진 칸 사이의 통로에서 실제로 막는 것은 방화벽이다.
- **번호는 아무거나 줘도 된다** — 1부터 4094 안이어야 하고, 링크 양쪽 장비가 같은 번호로 합의해야 한다. 한쪽만 바꾸면 그 구간은 조용히 죽는다.

## 🚨 주의사항

- **트렁크에 필요한 번호만 허용해라.** 기본이 "전부 허용" 인 장비가 많고, 그러면 갈라 놓은 값을 못 한다.
- **태그 4바이트를 계산에 넣어라.** MTU 1500 을 유지하려면 링크가 1522바이트 프레임을 받아야 한다.
- **기본 번호를 그대로 쓰지 마라.** 아무 설정도 안 한 포트가 다 같은 칸에 들어가면, 나눴다고 믿는 동안 실제로는 한 칸이다.

## 📝 정리

**"선은 하나인데 방은 여럿으로 쓰게 해 주는 번호표"** 라고 읽으면 된다. 갈라진 칸 사이는 3계층을 거쳐야만 통하므로, 규칙을 걸 자리는 언제나 그 통로 하나다.

## 🧒 열 살에게

교실 하나를 가운데 칸막이로 나누면 바닥도 천장도 그대로인데 옆 칸 아이들과는 안 섞이지? 칸막이조차 세우기 싫으면, 주고받는 쪽지마다 몇 번 칸 것인지 번호를 적어 두고 같은 번호끼리만 건네주면 돼. 그러면 바로 옆자리에 앉아 있어도 번호가 다른 아이한테는 쪽지가 영영 안 가.
