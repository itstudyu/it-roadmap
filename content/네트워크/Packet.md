# Packet (패킷)

## 📝 정의

패킷은 **보낼 데이터를 잘라 주소를 붙인 한 조각**이다.

인터넷은 파일을 통째로 옮기지 않는다. 1981년 IP 규격(RFC 791)이 정한 방식은 데이터를 조각으로 나눠 조각마다 주소를 붙여 보내고, 받는 쪽에서 다시 맞추는 것이다. 조각 하나에는 실어 보낼 내용(payload)과 그걸 어디로 보낼지 적은 머리표(header)가 함께 들어간다.

### 비유
번호 붙인 이삿짐 상자 여러 개로 나눠 보내면 받는 집에서 번호대로 다시 쌓는다.

## 🖼️ 그림으로 보기

```도해
흐름: 파일 하나를 보낼 때 선을 타고 가는 것은 무엇인가
보낼 것 :: 파일 하나. 선에 그대로 얹지 못한다
자르기 :: 지나갈 망이 받아주는 크기로 조각을 낸다
주소 붙임 :: 조각마다 보낸 곳·받을 곳·몇 번째인지 적는다
가는 길 :: 조각들이 저마다 길을 골라 따로 간다
받는 쪽 :: 번호대로 다시 붙여 원래 파일을 만든다
= 선을 타고 가는 것은 파일이 아니라, 주소 붙은 조각들이다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터를 통째로 보내면 무엇이 문제인가
통째로 || 패킷으로
좁은 망 :: 못 지나간다 || 조각내 지나간다
경로 :: 한 길에 묶인다 || 조각마다 고른다
손상 :: 전부 헛일 된다 || 그 조각만 버린다
= 잘라 두면 좁은 길도 지나가고, 하나 망가져도 그 하나만 잃는다
```

통째로 보내려면 중간에 있는 모든 망이 그 크기를 받아줘야 한다. RFC 791 은 이걸 조각내기(fragmentation)로 푼다 — 큰 패킷을 허용하는 망에서 출발한 데이터가 작은 패킷만 허용하는 망을 지나야 할 때, 중간의 게이트웨이가 조각을 내고 목적지 호스트가 다시 맞춘다.

머리표에 식별 번호와 조각 위치가 적혀 있어서, 흩어져 도착한 조각도 원래 자리에 다시 놓을 수 있다. IP 는 조각 하나하나를 **다른 조각과 무관한 독립된 것**으로 다루고 연결이라는 개념 자체를 두지 않는다. 그래서 조각들은 저마다 다른 길로 갈 수 있고, 그 대가로 순서가 뒤바뀔 수 있다.

## ⚙️ 작동 원리

머리표에는 조각을 옮기고 되맞추는 데 필요한 것만 적는다.

| 머리표에 적히는 것 | 무엇에 쓰나 |
|---|---|
| 보낸 곳 · 받을 곳 주소 | 어느 길로 보낼지 고른다 |
| 식별 번호 | 어느 데이터의 조각인지 가른다 |
| 조각 위치 | 원래 데이터의 몇 번째 자리인지 |
| 남은 조각 표시 | 이게 마지막 조각인지 |
| 살아 있는 시간 | 0 이 되면 버린다. 영원히 떠돌지 못하게 |
| 머리표 검사합 | 틀리면 발견한 자리에서 곧바로 버린다 |

RFC 791 은 한 조각의 전체 길이를 최대 65,535 옥텟까지 적을 수 있게 해놓고, **모든 호스트가 반드시 받아줘야 하는 크기는 576 옥텟**으로 정했다. 100배가 넘는 차이라서, 그보다 큰 조각을 보내려면 상대가 받을 수 있다는 확인이 먼저다.

IP 가 하지 않는 일도 분명하다. 확인 응답도, 재전송도, 흐름 제어도 없고 본문에 대한 오류 검사도 없다. 순서를 맞추고 잃은 것을 되찾는 일은 위층에 있다 — [[TCP]] 는 조각에 붙은 번호로 그걸 해내고, [[UDP]] 는 아예 하지 않는다고 규격에 못 박아 두었다.

## 💡 실제 사례

- **영상 통화가 잠깐 깨진다** — 조각 몇 개가 늦거나 사라진 것이다. UDP 는 전달도 중복 방지도 보장하지 않으니 그 자리가 빈 채로 지나간다.
- **파일을 받는 중에 한 경로가 끊겨도 이어진다** — IP 는 조각마다 길을 따로 고른다. 앞 조각이 간 길이 막혀도 뒤 조각은 다른 길로 간다.
- **깨진 조각은 그 자리에서 사라진다** — 머리표 검사합이 틀리면 발견한 쪽이 곧바로 버린다. 본문은 검사하지 않으니 내용이 맞는지는 위층이 따로 본다.

## 🚫 흔한 오해

- **보낸 순서대로 도착한다** — 조각들은 저마다 다른 길로 가서 뒤바뀌어 도착할 수 있다. 순서를 세워주는 것은 IP 가 아니라 그 위의 TCP 다.
- **조각이 사라지면 오류가 뜬다** — IP 에는 확인 응답도 재전송도 없다. 사라진 걸 알아채는 것부터가 위층의 일이고, UDP 를 쓰면 그마저 없다.
- **조각을 잘게 나눌수록 빠르다** — 조각을 낼 때 머리표를 복사해 새 조각마다 붙인다. 잘게 나눌수록 같은 데이터에 머리표가 여러 벌 실려서 보낼 양이 늘어난다.

## 🚨 주의사항

- **576 옥텟이 안전선이다.** 그보다 큰 조각을 보내려면 상대가 받을 수 있다는 확인이 있어야 한다고 RFC 791 이 권한다.
- **"조각내지 마라" 표시는 버림표다.** 그 표시가 붙은 조각은 지나갈 망이 작으면 조각나는 대신 그냥 버려진다.
- **본문은 아무도 봐주지 않는다.** IP 의 검사합은 머리표만 본다. 본문이 깨졌는지는 위층이 따로 확인해야 한다.

## 📝 정리

패킷은 보낼 데이터를 잘라 주소를 붙인 조각이다. 조각마다 길을 따로 고르니 좁은 망도 지나가고 한 곳이 막혀도 돌아갈 수 있지만, 그 대가로 순서가 뒤바뀌거나 조각이 없어지는 일이 생긴다. TCP 와 UDP 의 갈림길은 그 대가를 누가 감당하느냐다.

## 🔗 관련 용어

- [[IP Address]] — 조각의 머리표에 적히는 보낸 곳·받을 곳 주소
- [[TCP]] — 뒤바뀌고 사라지는 조각을 순서대로 세워 주는 위층
- [[UDP]] — 그 보정을 포기하고 조각을 그대로 넘기는 위층
- [[OSI 7계층]] — 이 조각이 층마다 어떤 이름으로 불리는지 정리한 지도
- [[TTL]] — 조각이 살아 있을 시간을 미리 정해두는 것도 같은 발상이다
