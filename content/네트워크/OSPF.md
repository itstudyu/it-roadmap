# OSPF (최단 경로 우선)

## 📝 정의

OSPF는 **조직 안에서 최단 경로를 각자 계산하는 길 찾기**다.

이웃이 알려준 결과를 받아쓰는 방식이 아니다. 모든 라우터가 **똑같은 지도 한 장**을 나눠 갖고, 그 지도로 각자 계산한다. RFC 2328 은 이것을 "각 라우터가 조직의 지형을 적은 데이터베이스를 유지하며, 참여하는 모든 라우터가 동일한 데이터베이스를 갖는다" 고 적는다. 규격이 공개되어 있어 제조사가 달라도 같은 조직 안에서 섞어 쓸 수 있다.

### 이름
Open :: 규격이 공개됨
Shortest :: 가장 짧은
Path :: 길
First :: 먼저 고른다
= 붙여 읽으면 "가장 짧은 길을 먼저 고르는 공개 규격". 이름이 곧 하는 일이다

### 비유
반 아이들에게 "어디로 가라" 고 알려주는 대신 학교 지도를 똑같이 한 장씩 나눠 주고, 각자 그 지도로 제일 짧은 길을 스스로 그리게 하는 것과 같다.

### 예
사무실 스위치 한 대의 전원을 뽑았는데 몇 초 만에 통신이 되살아나던 그 순간이다.

### 직접
회사 와이파이에서 `traceroute` 를 쳐 보라. 앞쪽에 사내 주소만 나오는 몇 줄이 있는데, 그 순서를 정한 것이 대개 이 계산이다.

## 🖼️ 그림으로 보기

```도해
흐름: 라우터들은 어떻게 똑같은 지도를 갖게 되나
Hello :: 랜에서는 10초마다 인사해 이웃이 사는지 본다
LSA :: "나는 이 이웃들과 이 비용으로 붙어 있다" 를 적는다
플러딩 :: 그 쪽지를 영역 안 모두에게 퍼뜨린다
지도 :: 쪽지를 모으면 모두가 같은 지도 한 장을 갖는다
계산 :: 각자 자기를 뿌리로 최단 경로 나무를 친다
= 길을 나눠 받는 게 아니라 지도를 나눠 갖는다. 계산은 각자 따로 한다
```

## ⚠️ 해결하는 문제

```도해
대조: 이웃이 말한 거리만 믿으면 무엇이 잘못되나
거리만 믿으면 || 지도를 가지면
사고 뒤 :: 소문이 천천히 돈다 || 몇 초 안에 다시 푼다
헛길 :: 없는 길을 믿는다 || 지도로 걸러 낸다
회선 종류 :: 홉 수로만 센다 || 대역폭을 비용으로
= 남이 계산한 결과를 받는 것과, 원본 지도를 받아 내가 계산하는 것의 차이다
```

옛 방식(거리 벡터)은 이웃이 "저기까지 세 걸음" 이라고 말해 주면 그걸 믿고 자기는 네 걸음이라고 옆에 전했다. 문제는 사고가 났을 때다. 끊겼다는 소식이 한 다리씩 건너 퍼지는 동안, 아직 소식을 못 들은 라우터가 옛 정보를 되돌려 주면서 이미 없는 길이 살아 있는 것처럼 한동안 떠돈다. 규모가 커질수록 그 시간이 길어진다.

OSPF 는 결과 대신 재료를 퍼뜨린다. 각 라우터는 "내가 누구와 얼마의 비용으로 붙어 있다" 는 쪽지(LSA) 하나만 만들고, 그 쪽지가 영역 안 전체에 퍼진다. 쪽지를 다 모으면 조직의 지형도가 완성되고, 각자 다익스트라 계산으로 자기를 뿌리로 한 최단 경로 나무를 친다. 회선 하나가 죽으면 그 쪽지 하나만 갈아 끼워 다시 계산하면 끝이라, 수렴이 소문이 아니라 계산 속도로 결정된다.

## 🧱 구성

```도해
층: 영역을 나누면 무엇이 어디까지만 보이나
백본 영역 0 :: 모든 영역이 여기에 붙는다. 끊기면 조직이 갈라진다
영역 경계 라우터 :: 두 영역에 걸쳐 서서 요약한 길만 넘긴다
일반 영역 :: 안쪽 지도는 이 안에서만 돈다. 밖에서는 안 보인다
= 지도를 통째로 나눠 가지면 커질수록 무거워진다. 영역은 그 지도를 잘라 둔 칸이다
```

## ⚙️ 작동 원리

주고받는 것은 다섯 가지 패킷뿐이다. IANA 등록부에 Hello(1) · Database Description(2) · Link State Request(3) · Link State Update(4) · Link State Ack(5) 로 올라 있고, 다섯 다 RFC 2328 이 정의한다. 쪽지 자체도 종류가 나뉜다 — Router-LSA(1) 는 라우터가 제 이웃을 적은 것, Network-LSA(2) 는 한 구간에 여럿이 붙었을 때 그 구간을 적은 것, Summary-LSA(3·4) 는 영역 밖으로 요약해 넘기는 것, AS-external-LSA(5) 는 조직 밖에서 배워 온 길이다.

같은 이더넷 구간에 라우터가 다섯 대 붙어 있으면 서로 짝을 다 맺을 때 열 쌍이 된다. 그래서 RFC 2328 은 그런 구간에서 대표 라우터(Designated Router) 를 뽑아 모두가 대표하고만 짝을 맺게 한다. 맺을 짝이 열에서 넷으로 줄고, 쪽지도 대표를 거쳐 한 번만 퍼진다.

비용은 회선마다 나가는 쪽 인터페이스에 붙는다. 홉 수가 아니라 관리자가 매긴 값이라, 느린 회선에 큰 값을 주면 그 길은 자동으로 뒤로 밀린다.

IPv6 용은 OSPFv3 로 따로 있다. RFC 5340 은 "IPv4 의 서브넷 단위가 아니라 링크 단위로 동작한다" 고 적고, 주소 정보를 라우터 쪽지에서 아예 빼 버렸다. 이웃을 가리킬 때는 `fe80::` 로 시작하는 링크 로컬 주소를 쓰고, 인증은 프로토콜 안에서 없애고 IPsec 에 맡긴다. 다만 라우터 ID 와 영역 ID 는 그대로 32비트다.

## 📊 비교: OSPF 와 BGP

| | OSPF | BGP |
|---|---|---|
| **어디를 맡나** | 한 조직 안 | 조직과 조직 사이 |
| **주고받는 것** | 지형 쪽지(LSA) | 주소 묶음과 거쳐 온 조직 번호 |
| **길을 고르는 값** | 회선마다 매긴 비용의 합 | 사람이 매긴 선호도, 조직 수 |
| **누가 계산하나** | 라우터마다 각자 전부 | 받은 후보 중에서 고른다 |
| **바뀌면** | 몇 초 안에 전부 다시 계산 | 바뀐 것만 옆으로 흘린다 |

## 💡 실제 사례

- **사내 회선 이중화** — 주 회선과 예비 회선의 비용을 다르게 매겨 둔다. 주 회선이 죽으면 쪽지가 갱신되고 몇 초 만에 예비로 넘어간다.
- **제조사 섞어 쓰기** — 규격이 RFC 2328 로 공개되어 있어 다른 회사 장비끼리도 같은 영역 안에서 이웃을 맺는다. 값만 맞으면 짝이 성립한다.
- **큰 캠퍼스 쪼개기** — 건물마다 영역을 나누고 백본에 붙인다. 한 건물 안 회선이 흔들려도 다른 건물은 다시 계산하지 않는다.

## 🚫 흔한 오해

- **최단 경로니까 제일 빠른 길이다** — 아니다. 실제 지연을 재지 않는다. 관리자가 회선마다 매겨 둔 비용의 합이 가장 작은 길일 뿐이라, 비용을 잘못 매기면 느린 회선이 최단 경로가 된다.
- **OSPF 하나면 인터넷까지 다 된다** — 조직 안까지다. 밖으로 나가는 길은 [[BGP]] 가 배워 오고, OSPF 는 그걸 AS-external-LSA 로 받아 안쪽에 뿌릴 뿐이다.
- **영역을 나누면 언제나 좋다** — 라우터가 몇 대뿐인 곳에서 영역을 쪼개면 얻는 것 없이 요약 설정과 백본 유지 부담만 는다. 영역은 지도가 무거워졌을 때 꺼내는 칼이다.

## 🚨 주의사항

- **백본이 끊기면 조직이 갈라진다.** 모든 영역은 영역 0 에 붙어야 하고, 백본 자체가 두 조각이 나면 서로 반대편 영역끼리 길이 사라진다.
- **비용을 손으로 매겼는지 확인하라.** 자동 계산은 기준 대역폭에 맞춰 도는데, 요즘 회선 속도가 그 기준을 넘어서면 서로 다른 속도의 회선이 같은 비용으로 잡힌다.
- **이웃이 안 맺히면 값부터 맞춰 봐라.** 인사 주기·대기 시간·영역 번호·인증이 양쪽에서 하나라도 다르면 짝이 성립하지 않고, 그 구간은 조용히 없는 길이 된다.

## 📝 정리

**"길을 나눠 받는 대신 지도를 나눠 갖는 그 방식"** 이라고 읽으면 된다. 각 라우터가 제 이웃을 적은 쪽지를 퍼뜨리고, 그것들을 모아 만든 같은 지도로 저마다 최단 경로를 계산하므로, 회선 하나가 죽어도 소문을 기다리지 않고 몇 초 안에 다시 푼다. 지도가 무거워지면 영역으로 잘라 두되, 모든 영역은 백본에 붙어 있어야 한다.

## 🧒 열 살에게

친구들한테 "어디로 가" 하고 일일이 알려 주는 대신 학교 지도를 똑같이 한 장씩 나눠 준다고 해 봐. 계단 하나가 막혀도 누가 알려 주기를 기다릴 필요 없이 각자 지도를 보고 곧바로 돌아갈 길을 그릴 수 있어. 대신 학교가 너무 커지면 지도가 무거워져서 층별로 잘라 나눠 줘야 해.

## ❓ 이해했는지

- 회선 하나가 죽었을 때 소문이 도는 방식보다 지도를 갖는 쪽이 왜 빠른가 → 해결하는 문제
- 한 이더넷 구간에 라우터가 다섯 대인데 짝을 열 쌍이나 맺지 않는 이유는 무엇인가 → 작동 원리
- 라우터가 네 대뿐인 사무실에서 영역을 쪼개면 무엇이 손해인가 → 흔한 오해

**출처**

- [RFC 2328 — OSPF Version 2](https://www.rfc-editor.org/rfc/rfc2328.html) — 모든 라우터가 동일한 링크 상태 데이터베이스를 갖는다는 규정, 자기를 뿌리로 한 최단 경로 나무, 영역과 백본 영역 0, Hello 프로토콜과 인접 관계, 대표 라우터로 인접 수를 줄이는 이유, 인터페이스 나가는 쪽에 붙는 비용, 16.1 절의 다익스트라 계산, 부록 C.3 이 랜의 예시값으로 든 인사 주기 10초를 확인
- [IANA Open Shortest Path First (OSPF) Parameters](https://www.iana.org/assignments/ospfv2-parameters/ospfv2-parameters.xhtml) — 패킷 다섯 종류(Hello 1 ~ Link State Ack 5) 와 LSA 종류(Router 1 · Network 2 · Summary 3·4 · AS-external 5) 의 실제 등록 값을 확인
- [RFC 5340 — OSPF for IPv6](https://datatracker.ietf.org/doc/html/rfc5340) — 서브넷 단위가 아닌 링크 단위 동작, 라우터·네트워크 쪽지에서 주소 정보를 뺀 점, 링크 로컬 주소 사용, 인증을 IPsec 에 넘긴 점, 라우터 ID 는 32비트 유지를 확인
