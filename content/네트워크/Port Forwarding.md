# Port Forwarding (포트 포워딩)

## 📝 정의

Port Forwarding(포트 포워딩)은 공유기나 방화벽의 특정 포트로 들어오는 외부 트래픽을 내부 사설 네트워크의 특정 기기(IP:포트)로 전달하는 기술입니다. 사설 IP를 사용하는 내부 서버나 서비스를 외부 인터넷에서 접근할 수 있도록 "문(포트)"을 열어주는 역할을 합니다.

사설 IP를 사용하는 기기는 기본적으로 인터넷에서 직접 접근할 수 없습니다. 공유기나 라우터가 NAT를 통해 내부 기기를 숨기기 때문입니다. 하지만 가정에서 게임 서버, NAS, 웹 서버를 운영하거나, 기업에서 특정 내부 서비스를 외부에 공개할 때 Port Forwarding을 사용합니다. 공유기/방화벽이 "이 포트로 오는 요청은 이 내부 서버로 보내라"는 규칙을 설정하는 것입니다.

> **한 줄 요약**: "공유기에게 '이 번호(포트)로 오는 방문자는 안쪽 방(내부 서버)으로 안내해줘'라고 지시하는 것"

**비유**:
- **아파트 경비원 비유**: 건물 경비원(공유기)에게 "302호 방문자입니다"라는 사람이 오면 자동으로 302호로 안내하도록 규칙을 설정합니다. 외부에서는 건물 주소만 알면 됩니다.
- **회사 대표번호 비유**: 회사 대표번호(공인 IP)로 전화하면 "1번은 영업부, 2번은 기술지원"처럼 내선번호(포트)별로 연결됩니다.

## 🎯 핵심 개념

### 1. 포트(Port)의 역할
포트는 하나의 IP 주소에서 여러 서비스를 구분하는 번호입니다. 같은 서버에서도 포트 80은 웹 서버, 포트 22는 SSH, 포트 3306은 MySQL이 각각 담당합니다. Port Forwarding은 "외부의 특정 포트 번호를 내부의 특정 IP:포트로 연결"합니다.

### 2. 포트 포워딩 규칙 구성요소
- **외부 포트**: 공인 IP에서 열어둘 포트 (예: 8080)
- **내부 IP**: 전달받을 내부 기기의 사설 IP (예: 192.168.1.100)
- **내부 포트**: 내부 서비스가 사용하는 포트 (예: 80)
- 예시: 외부 `8080` → 내부 `192.168.1.100:80`

### 3. 포트 번호 범위
- **Well-known ports (0~1023)**: HTTP(80), HTTPS(443), SSH(22), FTP(21) 등 표준 서비스
- **Registered ports (1024~49151)**: MySQL(3306), PostgreSQL(5432), Redis(6379) 등
- **Dynamic/Private ports (49152~65535)**: 일반 애플리케이션이 임시로 사용

### 4. 포트 포워딩 vs 포트 트리거링
- **포트 포워딩**: 항상 동일한 내부 IP로 전달하는 정적 규칙
- **포트 트리거링**: 내부 기기가 특정 포트로 요청을 보낼 때만 임시로 외부 포트를 여는 동적 방식

## ⚠️ 해결하는 문제

### 문제 1: 사설 IP 기기에 외부 접근 불가
NAT 환경에서는 외부에서 192.168.x.x 같은 사설 IP에 직접 접근할 수 없습니다. Port Forwarding을 통해 공인 IP의 특정 포트로 들어오는 트래픽을 내부 기기로 전달할 수 있습니다.

### 문제 2: 하나의 공인 IP로 여러 서비스 운영
서버 1대(웹 서버)와 서버 2대(게임 서버)를 동시에 운영하고 싶을 때, 두 서버 모두 공인 IP가 없어도 됩니다. 포트 80은 웹 서버로, 포트 25565는 게임 서버로 포워딩하면 하나의 공인 IP로 여러 서비스를 제공할 수 있습니다.

### 문제 3: 원격 접근 및 모니터링
집에 있는 NAS나 CCTV에 외부에서 접근할 때, 공유기에 Port Forwarding을 설정하여 집 밖에서도 해당 기기에 접근할 수 있습니다.

## ⚙️ 작동 원리

### 1단계: 포트 포워딩 규칙 설정
공유기 관리 페이지(보통 192.168.1.1)에서 포트 포워딩 규칙을 설정합니다. "외부 포트 8080으로 들어오는 TCP 트래픽을 192.168.1.100의 포트 80으로 전달"하는 규칙을 등록합니다.

### 2단계: 외부 요청 수신
외부 사용자가 203.0.113.5:8080으로 HTTP 요청을 보냅니다. 공유기가 이 요청을 수신합니다.

### 3단계: 포워딩 규칙 매칭
공유기가 목적지 포트(8080)를 확인하고, 포트 포워딩 규칙 테이블에서 해당 포트에 매칭되는 규칙을 찾습니다. "8080 → 192.168.1.100:80" 규칙을 발견합니다.

### 4단계: 내부 서버로 전달
공유기가 패킷의 목적지 IP를 공인 IP에서 내부 IP(192.168.1.100)로, 포트를 8080에서 80으로 변경하여 내부 서버에 전달합니다.

### 5단계: 응답 반환
내부 서버의 응답이 공유기를 통해 원래 외부 요청자에게 전달됩니다.

## 📊 비교

| 항목 | Port Forwarding | Reverse Proxy | VPN | DMZ |
|------|----------------|--------------|-----|-----|
| **설정 위치** | 공유기/방화벽 | 서버 소프트웨어 | 서버 소프트웨어 | 네트워크 아키텍처 |
| **복잡도** | 낮음 | 중간 | 높음 | 높음 |
| **보안성** | 낮음 (직접 노출) | 중간 | 높음 | 높음 |
| **여러 서버** | 포트별로 분산 | 도메인/경로별 분산 | 전체 내부망 | 격리 영역 |
| **SSL/TLS 처리** | 불가 (서버에서 처리) | 가능 (중앙 처리) | 자동 암호화 | 별도 설정 |
| **접근 제어** | 없음 (IP 필터 가능) | 가능 | IAM/인증서 | 방화벽 규칙 |
| **주요 용도** | 가정/소규모 서버 | 웹 서버 분산 | 원격 근무 | 기업 네트워크 |
| **비용** | 없음 | 서버 비용 | 서버+관리 비용 | 높음 |

## ✅ 장단점

**장점**:
- 설정이 간단하고, 별도 소프트웨어 없이 공유기 설정만으로 가능
- 공인 IP 하나로 여러 내부 서비스를 외부에 노출 가능
- 특별한 지식 없이도 공유기 관리 페이지에서 설정 가능

**단점**:
- 내부 서비스가 인터넷에 직접 노출되므로 보안 취약점이 공격 대상이 됨
- 공인 IP가 변경(동적 IP)되면 외부에서 접근 불가능 (DDNS로 해결 가능)
- 정교한 접근 제어(인증, 속도 제한)가 불가능하므로 프로덕션 서버에는 부적합
- 한 포트에 하나의 내부 서버만 연결 가능

## 💡 실제 사례

### 1. 가정용 게임 서버 운영
마인크래프트 서버(포트 25565)를 집에서 운영할 때:
1. 내부 PC에서 서버 실행 (192.168.1.100:25565)
2. 공유기에서 포트 포워딩: 외부 25565 → 192.168.1.100:25565
3. 친구들이 집 공인 IP:25565로 접속

### 2. NAS 원격 접근
Synology NAS(192.168.1.50)에 외부에서 접근:
- 포트 5000(HTTP) → 192.168.1.50:5000
- 포트 5001(HTTPS) → 192.168.1.50:5001
외출 시에도 스마트폰으로 집 NAS 파일에 접근 가능

### 3. 개발 서버 임시 공개 (ngrok 대안)
로컬에서 개발 중인 웹 서버(localhost:3000)를 클라이언트에게 임시로 공개할 때 포트 포워딩을 사용합니다. 단, 보안을 위해 테스트 후 즉시 규칙을 삭제하는 것이 중요합니다.

## 🔗 관련 용어

- **NAT (Network Address Translation)**: 사설 IP와 공인 IP를 변환하는 기술. Port Forwarding의 기반
- **Public IP vs Private IP**: 공인/사설 IP 개념. Port Forwarding이 필요한 이유
- **Reverse Proxy**: Port Forwarding의 고급 대안. Nginx, Traefik 등으로 구현
- **방화벽 규칙**: 포트 포워딩과 함께 인바운드 허용 규칙을 방화벽에도 설정해야 함
- **DDNS (Dynamic DNS)**: 동적 IP가 변경될 때 도메인이 자동으로 새 IP를 가리키도록 하는 서비스
- **DMZ**: 네트워크 수준의 격리. Port Forwarding보다 고급 보안 구성
- **SSH 터널링**: SSH를 통해 특정 포트를 안전하게 포워딩하는 기법
- **ngrok**: 로컬 서버를 임시로 인터넷에 공개하는 도구. Port Forwarding 없이도 사용 가능
