# Port Forwarding (포트 포워딩)

## 📝 정의

Port Forwarding은 **바깥 포트로 온 요청을 안쪽 기기로 넘기는 규칙**이다.

공유기 안쪽 기기들은 밖에서 직접 부를 수 없다. 공유기에 "이 번호로 오는 것은 저 기기에게" 하고 적어두면 그 통로 하나가 열린다.

### 이름
Port :: 들어오는 문 번호
Forwarding :: 온 것을 딴 데로 넘김
= 붙여 읽으면 "그 번호로 온 것을 딴 데로 넘기기". 문을 하나 여는 일이지 지키는 일이 아니다

### 비유
회사 대표번호와 내선. 밖에서는 대표번호만 알면 되고 교환기가 내선번호를 보고 해당 자리로 돌려준다.

### 예
집에 둔 CCTV 를 밖에서 보려고 공유기 설정에 번호 하나를 적어 넣는 그 작업이다.

### 직접
폰의 와이파이를 끄고 데이터로만 집 안 기기의 `192.168.` 주소를 열어 보라. 아무것도 안 뜬다 — 규칙을 적어두기 전에는 밖에서 닿지 않는다.

## 🖼️ 그림으로 보기

```도해
흐름: 밖에서 보낸 요청이 어떻게 안쪽 서버까지 가나
외부 사용자 :: 공인 IP 의 8080 포트로 접속한다
공유기 :: 8080 으로 온 것을 어디로 보낼지 찾는다
공유기 :: 목적지를 안쪽 주소와 포트로 바꾼다
내부 서버 :: 자기 앞으로 온 요청처럼 받아 처리한다
< 공유기 :: 응답을 받아 원래 요청자에게 돌려준다
= 밖에서는 공유기 주소만 알고 안쪽 주소는 드러나지 않는다
```

## ⚠️ 해결하는 문제

```도해
대조: 사설 IP 를 쓰는 기기는 밖에서 어떻게 부르나
포워딩 없이 || 포워딩으로
외부 접근 :: 닿지 않는다 || 지정 포트로
공인 IP :: 기기마다 필요 || 하나로 나눔
설정 위치 :: 방법이 없다 || 공유기 한 곳
= 포트 번호로 안쪽 기기를 갈라 쓰는 것이 포워딩이다
```

집이나 사무실 안 기기들은 `192.168.` 로 시작하는 사설 주소를 쓴다. 이 주소는 인터넷에서 통하지 않아서, 밖에 있는 사람이 그 주소로 보내면 어디에도 닿지 않는다.

공인 IP는 보통 하나뿐이다. 그 하나로 여러 기기를 열려면 구분할 표시가 필요한데 포트 번호가 그 역할을 한다. 8080으로 오면 웹 서버로, 다른 번호로 오면 다른 기기로 보내는 규칙을 공유기에 적어두면 된다.

## ⚙️ 작동 원리

규칙 하나는 세 가지로 이뤄진다. 밖에서 열어둘 포트, 넘길 안쪽 기기의 주소, 그 기기가 듣고 있는 포트다. 예를 들어 바깥 8080을 `192.168.1.100` 의 80으로 보내라고 적는다.

요청이 오면 공유기가 목적지 주소와 포트를 바꿔 안쪽으로 넘긴다. 응답이 나갈 때는 반대로 되돌려 놓기 때문에, 밖에 있는 사람은 안쪽 주소를 끝까지 모른다.

안쪽 기기 주소가 바뀌면 규칙이 깨진다. 그래서 포워딩 대상이 되는 기기에는 주소를 고정해두는 편이 낫다.

## 💡 실제 사례

- **집에 둔 저장 장치 접근** — 밖에서 스마트폰으로 집 안 저장 장치의 파일을 연다.
- **개인 게임 서버** — 친구들이 집 공인 IP와 정해진 포트로 접속하게 한다.
- **작업 중인 화면 잠깐 공개** — 만들던 서버를 잠시 열어 보여주고 확인이 끝나면 규칙을 지운다.

## 📊 비교

| | Port Forwarding | Reverse Proxy | VPN |
|---|---|---|---|
| 설정하는 곳 | 공유기 | 서버 소프트웨어 | 서버 소프트웨어 |
| 나누는 기준 | 포트 번호 | 도메인과 경로 | 접속자 인증 |
| 접근 제어 | 거의 없다 | 붙일 수 있다 | 인증이 전제다 |
| 맞는 자리 | 집이나 소규모 | 웹 서비스 앞단 | 내부망 원격 접속 |

## 🚫 흔한 오해

- **포워딩을 열면 그 기기 전체가 열린다** — 적어둔 포트 하나만 통한다. 다만 그 포트에 붙은 서비스에 구멍이 있으면 거기로 들어온다.
- **포워딩이 보안 기능이다** — 반대로 안쪽 기기를 인터넷에 직접 내놓는 일이다. 인증이나 속도 제한 같은 것은 전혀 붙지 않는다.
- **한 번 설정하면 계속 된다** — 회선의 공인 IP가 바뀌거나 안쪽 기기 주소가 바뀌면 끊긴다. 양쪽 다 고정해둬야 한다.

## 🚨 주의사항

- **관리용 포트를 열지 않는다.** 원격 접속이나 데이터베이스 포트를 그대로 열면 자동화된 공격이 바로 붙는다.
- **필요 없어지면 규칙을 지운다.** 잠깐 열어둔 규칙이 그대로 남아 있는 것이 흔한 사고 경로다.

## 📝 정리

**"밖에서 부를 번호 하나를 안쪽 자리에 이어 둔 그 규칙"** 이라고 읽으면 된다. 공인 IP 하나로 여러 기기를 열 수 있지만 그만큼 안쪽 서비스가 인터넷에 직접 노출된다.

## 🧒 열 살에게

회사에 전화하면 "내선 번호를 눌러 주세요" 하고 나오지? 그 번호를 눌러야 원하는 자리로 이어지고, 안 누르면 어느 자리에도 못 가. 대신 그렇게 이어 둔 번호는 아무나 누를 수 있으니까, 안 쓰게 되면 지워 두는 게 좋아.
