# UDP (User Datagram Protocol)

## 📝 정의

UDP는 **확인하지 않고 그냥 보내는 전송 규칙**이다.

연결을 맺는 절차가 없고 도착했는지 확인하지도 않는다. 사라진 조각을 다시 보내지 않고 순서도 맞춰주지 않는 대신, 그 일에 드는 시간을 쓰지 않는다.

### 비유
확성기 방송. 듣는 사람이 준비됐는지 묻지 않고 그냥 말한다. 한두 마디를 놓친 사람이 있어도 방송은 계속 나간다.

## 🖼️ 그림으로 보기

```도해
흐름: 조각 하나가 사라지면 UDP 는 무엇을 하나
보내는 쪽 :: 연결 절차 없이 첫 조각부터 보낸다
네트워크 :: 라우터가 붐벼서 하나를 버린다
받는 쪽 :: 도착한 것만 위층에 올린다
받는 쪽 :: 빠진 게 있다고 알려주지 않는다
보내는 쪽 :: 사라진 줄 모르고 다음 것을 보낸다
< 응용 :: 다시 받아야 하면 응용이 직접 챙긴다
= UDP 는 아무것도 챙기지 않는다. 챙길 일이 있으면 위층 몫이다
```

## ⚠️ 해결하는 문제

```도해
대조: 늦게 도착한 화면 한 장을 어떻게 다루나
TCP 로 || UDP 로
빠진 조각 :: 다시 요청 || 그냥 버린다
그동안 화면 :: 멈춰 있다 || 계속 넘어간다
전송 속도 :: 막히면 줄임 || 일정하게 유지
= 늦게 온 화면은 이미 쓸모가 없다. 기다리는 쪽이 손해인 경우가 있다
```

TCP는 빠진 조각을 다시 요청하고 그동안 뒤에 온 것을 들고 기다린다. 파일을 받을 때는 그게 맞다. 그런데 영상 통화에서는 늦게 도착한 화면 한 장이 이미 지나간 장면이다. 그 한 장을 기다리느라 대화가 끊긴다.

UDP는 기다리지 않는다. 사라진 것은 사라진 대로 두고 다음 것을 보낸다. 확인 신호를 주고받지 않으므로 연결을 맺는 절차도 없고, 헤더도 8바이트로 짧다. TCP 헤더는 20에서 60바이트다.

## ⚙️ 작동 원리

```도해
층: UDP 가 하지 않는 일은 무엇인가
연결 맺기 :: 인사 없이 첫 조각부터 보낸다
재전송 :: 사라진 것을 다시 보내지 않는다
순서 맞추기 :: 도착한 차례 그대로 올린다
속도 조절 :: 길이 막혀도 줄이지 않는다
= 이 넷을 안 하기 때문에 빠르고, 필요하면 응용이 대신 해야 한다
```

UDP가 붙이는 것은 출발지 포트, 목적지 포트, 길이, 체크섬 넷뿐이다. 받는 쪽은 포트 번호를 보고 어느 프로그램에 넘길지 정하고, 체크섬이 안 맞으면 그 조각을 조용히 버린다. 버렸다는 사실을 보낸 쪽에 알리지 않는다.

받는 쪽이 하나가 아니어도 된다는 점도 다르다. 한 번 보낸 것을 같은 네트워크의 모든 기기에 뿌리거나(브로드캐스트) 특정 그룹에만 보낼 수 있다(멀티캐스트). TCP는 일대일 연결만 된다.

확인이 필요하면 응용이 직접 만든다. DNS 클라이언트는 일정 시간 안에 응답이 없으면 요청을 다시 보내는데, 이건 UDP가 해주는 것이 아니라 DNS가 스스로 하는 일이다.

## 📊 비교: UDP vs TCP

| | UDP | TCP |
|---|---|---|
| 연결 | 없이 바로 보낸다 | 세 번 인사하고 시작 |
| 빠진 조각 | 그대로 잃음 | 다시 요청 |
| 순서 | 도착한 대로 | 맞춰 준다 |
| 속도 조절 | 없음 | 막히면 줄인다 |
| 헤더 크기 | 8바이트 | 20에서 60바이트 |
| 일대다 | 브로드캐스트, 멀티캐스트 | 일대일만 |
| 어디에 쓰나 | 게임, 스트리밍, DNS, VoIP | HTTP, 메일, FTP, SSH |

## 💡 실제 사례

- **영상 통화** — 화면 몇 장이 빠져도 대화가 이어지는 편이 낫다. 낮은 지연이 화질보다 앞선다.
- **온라인 게임** — 위치 정보가 하나 빠져도 다음 갱신이 곧 온다. 다시 받느라 늦어지는 쪽이 손해다.
- **DNS 조회** — 묻고 답하는 한 번이 전부라 연결을 맺을 이유가 없다. 답이 안 오면 클라이언트가 다시 묻는다.

## 🚫 흔한 오해

- **UDP는 데이터를 잃어버리는 규칙이다** — 잃어버리는 건 네트워크가 하는 일이고, UDP는 잃은 것을 챙기지 않을 뿐이다. 길이 한가하면 아무것도 안 잃는다.
- **UDP를 쓰면 안정성을 포기해야 한다** — 응용이 직접 챙기면 된다. DNS는 응답이 없으면 다시 묻고, 게임은 중요한 값만 따로 확인한다.
- **UDP가 TCP보다 항상 빠르다** — 조각 하나가 오가는 시간 자체는 같다. 인사와 재전송을 기다리지 않아서 늦게 도착하는 것이 안 생길 뿐이다.

## 🚨 주의사항

- **속도를 조절해주는 것이 없다.** 길이 막혀도 같은 속도로 계속 보내므로 응용이 스스로 줄여야 한다.
- **문제를 재현하기 어렵다.** 조각이 간헐적으로 사라지는데 아무도 알려주지 않아서, 로그만 봐서는 어디서 빠졌는지 알 수 없다.

## 📝 정리

UDP는 연결도 확인도 없이 조각을 그냥 보내는 전송 규칙이다. 사라진 것을 다시 보내지 않고 순서도 맞추지 않는 대신, 기다림이 없어서 늦게 도착하는 것이 생기지 않는다. 확인이 필요하면 그 일은 위층 응용이 직접 한다.

## ❓ 이해했는지

- 네트워크가 막혔을 때 UDP로 보내는 쪽은 무엇을 해야 하나?
