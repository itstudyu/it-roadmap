# Gateway (게이트웨이)

## 📝 정의

Gateway는 **서로 다른 네트워크가 만나는 지점에 서는 중개자**다.

두 네트워크가 같은 방식으로 말하지 않으면 그대로는 이어지지 않는다. 게이트웨이는 그 경계에 서서 오가는 것을 상대 쪽 형식으로 바꿔주고, 어디로 보낼지도 정한다.

### 비유
공항의 입국 심사대. 나라 밖에서 온 사람은 여기서 확인을 받고 절차를 거친 다음에야 안으로 들어간다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청 하나가 게이트웨이를 어떻게 지나가나
클라이언트 :: /api/users 로 요청을 보낸다
게이트웨이 :: 토큰을 확인한다. 없으면 401
게이트웨이 :: 요청 횟수를 본다. 넘치면 429
게이트웨이 :: 경로를 보고 담당 서비스를 고른다
사용자서비스 :: 처리해서 결과를 돌려준다
< 게이트웨이 :: 기록을 남기고 응답을 넘긴다
= 클라이언트가 아는 주소는 하나뿐이고, 뒤가 몇 개인지는 모른다
```

## ⚠️ 해결하는 문제

```도해
대조: 클라이언트가 서비스마다 직접 붙으면 어떻게 되나
게이트웨이 없이 || 게이트웨이로
아는 주소 :: 서비스 수만큼 || 하나
서비스 이동 :: 앱을 고쳐야 함 || 설정만 바꿈
인증 처리 :: 서비스마다 구현 || 한 곳에서
= 뒤가 몇 개로 쪼개지든 앞에서 보이는 문은 하나로 유지한다
```

서비스를 여러 개로 쪼개면 클라이언트가 알아야 할 주소도 같이 늘어난다. 서비스 하나가 옮겨 가거나 이름이 바뀔 때마다 앱을 새로 배포해야 하고, 인증이나 요청 제한 같은 공통 처리는 서비스마다 다시 구현된다.

게이트웨이는 그 앞에 문 하나를 세운다. 클라이언트는 게이트웨이 주소만 알고, 뒤에서 무엇이 어떻게 바뀌든 그 안에서 흡수된다. 공통으로 해야 하는 검사도 여기서 한 번만 하면 된다.

## ⚙️ 작동 원리

들어온 요청은 순서대로 몇 가지 관문을 지난다. 먼저 인증 토큰이 유효한지 보고, 다음으로 이 사용자가 짧은 시간에 너무 많이 부르지 않았는지 센다. 여기까지 통과하면 경로를 보고 어느 서비스가 담당인지 고른다.

형식이 다르면 바꾼다. 바깥에서는 익숙한 방식으로 받고 안쪽 서비스가 쓰는 방식으로 옮겨 보내는 식이다. 응답도 같은 자리에서 되돌려 바꾼다.

모든 요청이 한 지점을 지나기 때문에 기록도 여기 모인다. 어떤 요청이 얼마나 걸렸고 어디서 실패했는지가 한 곳에 남는다는 것이 장점이고, 동시에 이 지점이 멈추면 전부 멈춘다는 뜻이기도 하다.

## 📊 비교: 비슷한 자리에 서는 것들

| | 게이트웨이 | 로드 밸런서 | 리버스 프록시 |
|---|---|---|---|
| 주로 하는 일 | 경로 선택과 형식 변환 | 같은 서비스에 요청 분산 | 뒤의 서버를 가리고 대신 받음 |
| 형식 변환 | 한다 | 안 한다 | 대체로 안 한다 |
| 인증 처리 | 한다 | 안 한다 | 붙이기 나름 |
| 나누는 기준 | 요청 경로 | 서버 부하 | 설정한 규칙 |

## 💡 실제 사례

- **여러 서비스를 하나의 주소로** — 앱은 게이트웨이 한 곳만 부르고, 게이트웨이가 사용자, 주문, 결제 서비스로 나눠 보낸다.
- **오래된 시스템을 옮기는 중** — 일부 경로는 예전 시스템으로, 나머지는 새 시스템으로 보내면서 조금씩 옮긴다.
- **집 밖과 안의 경계** — 사무실 네트워크에서 인터넷으로 나갈 때 그 경계에 있는 장비가 게이트웨이 역할을 한다.

## 🚫 흔한 오해

- **게이트웨이는 로드 밸런서의 다른 이름이다** — 로드 밸런서는 같은 서비스의 여러 대에 요청을 나눠준다. 게이트웨이는 요청이 무엇을 원하는지 보고 서로 다른 서비스로 보낸다.
- **게이트웨이를 두면 빨라진다** — 관문이 하나 늘어난 것이라 그 자체로는 조금 느려진다. 얻는 것은 속도가 아니라 앞뒤를 끊어놓는 구조다.
- **게이트웨이가 있으면 뒤는 안 지켜도 된다** — 앞문만 잠근 셈이다. 안쪽에서 서로 부를 때는 그 검사를 지나지 않으므로, 뒤에서도 확인이 필요하다.

## 🚨 주의사항

- **모든 요청이 지나는 지점이라 여기가 멈추면 전부 멈춘다.** 여분을 두지 않으면 서비스를 쪼갠 의미가 사라진다.
- **여기에 업무 로직을 넣기 시작하면 아무도 못 건드리는 덩어리가 된다.** 경계에서 할 일과 서비스가 할 일을 갈라둬야 한다.

## 📝 정리

Gateway는 서로 다른 네트워크나 서비스가 만나는 경계에 서서, 오가는 것을 옮기고 어디로 보낼지 정하는 중개자다. 앞에서 보이는 문을 하나로 유지해주는 대신 그 문이 병목이자 단일 장애점이 된다. 인증과 제한과 기록처럼 모두에게 필요한 일을 여기 모아 처리한다.

## ❓ 이해했는지

- 뒤쪽 서비스의 주소가 바뀌었는데 앱을 새로 배포하지 않아도 되는 이유는?
- 게이트웨이가 요청을 나누는 기준은 로드 밸런서와 어떻게 다른가?
- 게이트웨이에서 인증을 처리하는데도 각 서비스에 확인이 남아 있어야 하는 이유는?
