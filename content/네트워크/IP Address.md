# IP Address (IP 주소)

## 📝 정의

IP 주소는 **네트워크에서 어디로 보낼지 가리키는 번호**다.

IPv4는 `192.168.0.10` 처럼 점으로 나눈 숫자 넷으로 쓰고, 자리가 모자라서 나온 IPv6는 훨씬 긴 형식을 쓴다.

### 비유
우편 주소. 이름만 알아서는 편지를 못 부치고, 어디로 갈지 적혀 있어야 배달이 시작된다.

## 🖼️ 그림으로 보기

```도해
흐름: 주소만 보고 데이터가 어떻게 상대에게 가나
보내는 쪽 :: 목적지 주소를 앞에 붙여 내보낸다
공유기 :: 내 망 안의 주소인가 밖인가를 본다
라우터 :: 앞부분만 보고 다음 라우터로 넘긴다
라우터 :: 같은 판단을 여러 번 되풀이한다
< 받는 쪽 :: 자기 주소면 위층으로 올린다
= 아무도 전체 길을 모른다. 각자 다음 한 칸만 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 주소가 없으면 데이터는 어디로 가나
주소 없이 || IP 주소로
목적지 :: 정할 수 없다 || 하나로 정해짐
중간 경로 :: 판단 근거 없음 || 앞부분으로 판단
기기 여럿 :: 구분 못 함 || 각각 구분됨
= 주소가 있어야 중간에서 어디로 넘길지를 정할 수 있다
```

인터넷에는 전체 길을 아는 중앙이 없다. 중간의 장비들은 주소의 앞부분만 보고 다음으로 넘길 곳을 정한다. 주소가 없으면 이 판단 자체가 성립하지 않는다.

주소는 앞부분과 뒷부분으로 나뉜다. 앞부분은 어느 망인지, 뒷부분은 그 망 안의 몇 번째 기기인지를 가리킨다. 어디까지가 앞부분인지는 `192.168.1.0/24` 처럼 뒤에 붙는 숫자가 정한다.

## ⚙️ 작동 원리

인터넷에서 통하는 주소와 집이나 회사 안에서만 통하는 주소가 나뉘어 있다. `10.` `172.16~31.` `192.168.` 로 시작하는 대역은 바깥으로 라우팅되지 않는 사설 주소라, 전 세계 어느 집에서든 같은 주소를 다시 쓴다.

주소를 사람이 하나씩 적어 넣을 수도 있고, 기기가 켜질 때 받아 갈 수도 있다. 뒤쪽을 맡는 것이 DHCP다. 노트북의 IP가 어제와 오늘 다른 것은 이 때문이다.

몇 개는 뜻이 정해져 있다. `127.0.0.1` 은 자기 자신이고, `0.0.0.0` 은 서버가 어느 자리로 들어오는 요청이든 받겠다는 뜻이며, `169.254.` 로 시작하면 주소를 못 받은 상태다.

## 💡 실제 사례

- **집 공유기** 기기마다 `192.168.0.x` 를 나눠 주고, 바깥으로 나갈 때는 공유기가 받은 주소 하나로 바꿔 내보낸다.
- **서버 바인딩** 개발 중에는 `127.0.0.1` 에 묶어 자기 컴퓨터에서만 열리게 하고, 배포할 때 `0.0.0.0` 으로 바꾼다.
- **연결이 안 될 때** 주소가 `169.254.` 로 시작하면 DHCP에서 주소를 못 받았다는 뜻이라 공유기부터 본다.

## 🚫 흔한 오해

- **IP 주소는 그 컴퓨터에 붙어 있는 고유 번호다** — 기기가 아니라 자리에 붙는다. 노트북을 집에서 회사로 옮기면 주소가 바뀌고, 원래 자리는 다른 기기가 받는다.
- **IP를 알면 그 사람 집을 알 수 있다** — 대개 통신사 장비까지만 좁혀진다. 집 안의 기기들은 공유기 뒤에 사설 주소로 숨어 있다.
- **주소가 같으면 같은 기기다** — 사설 주소는 집집마다 겹친다. `192.168.0.10` 은 세상에 수없이 많다.

## 📝 정리

IP 주소는 데이터가 어디로 가야 하는지를 적어두는 번호다. 앞부분은 어느 망인지, 뒷부분은 그 망 안의 어느 기기인지를 가리키고, 중간 장비들은 앞부분만 보고 다음 칸을 정한다. 인터넷에 나가는 공인 주소와 안에서만 쓰는 사설 주소가 따로 있다.

- 노트북 IP가 어제와 오늘 다르다면 무엇 때문인가?
