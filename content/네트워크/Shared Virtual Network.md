# Shared Virtual Network (공유 가상 망)

## 📝 정의

Shared Virtual Network는 **여러 살림이 망 하나를 같이 쓰는 방식**이다.

계정이나 프로젝트를 팀마다 쪼개면 값과 권한은 깔끔하게 갈리는데, 망까지 함께 쪼개지는 것이 문제다. 망이 쪼개지면 주소 대역이 겹치고, 팀이 늘 때마다 잇는 일이 늘어난다. 공유 망은 값과 권한만 쪼개고 망은 한 벌로 두는 답이다.

### 이름
Shared :: 같이 쓰는
Virtual :: 실물이 아닌
Network :: 이어 놓은 망
= 붙여 읽으면 "여럿이 같이 쓰는 하나의 가상 망"

### 비유
한 건물을 층별로 나눠 쓰는 사무실 — 전기와 소방은 건물주가 한 벌로 관리하고, 각 층은 제 살림만 챙긴다.

### 예
팀마다 계정을 따로 파 줬더니 팀 수만큼 망이 생기고 주소 대역이 겹쳐 이을 수가 없던 그 상황이다.

## 🖼️ 그림으로 보기

```도해
층: 망 하나를 놓고 누가 무엇을 쥐나
망 주인 :: 대역·칸 나눔·길·방화벽 규칙을 쥔다
빌려주기 :: 어느 살림이 어느 칸을 쓸지 정해 준다
빌려 쓰는 살림 :: 허락받은 칸 위에 제 기계를 띄운다
띄운 기계 :: 사설 주소로 서로 곧장 통한다
= 망은 한 벌, 살림은 여럿. 쥐는 쪽과 쓰는 쪽이 갈린다
```

## ⚠️ 해결하는 문제

```도해
대조: 살림마다 망을 따로 파면 무엇이 어려워지나
살림마다 따로 || 하나를 같이
서로 통하기 :: 짝을 계속 맺는다 || 처음부터 통한다
주소 대역 :: 겹쳐서 못 잇는다 || 한 곳이 나눠 준다
망 규칙 :: 살림마다 제각각 || 한 곳에서 건다
= 망은 한 곳이 쥐고, 살림은 값과 권한을 가르는 데만 쓴다
```

계정을 쪼개는 이유는 값을 갈라 받고 권한을 좁히기 위해서다. 그런데 계정마다 망이 딸려 오면 부작용이 따라온다 — 팀이 열이면 망이 열이고, 서로 통하게 하려면 짝을 계속 맺어야 하고, 각자 알아서 정한 주소 대역이 겹치면 그때는 잇는 것 자체가 막힌다.

공유 망은 이 둘을 떼어 놓는다. Google 문서는 이것을 "여러 프로젝트의 자원을 하나의 공용 망에 붙여 사설 주소로 안전하고 효율적으로 통하게 하는 것" 이라고 적고, AWS 는 "주인이 칸을 나눠 주면 참여자가 그 칸 안에 제 자원을 만드는" 구조라고 적는다. 망을 쥐는 사람과 기계를 띄우는 사람이 갈리므로, 권한을 최소로 좁히면서도 망은 한 벌로 유지된다.

## ⚙️ 작동 원리

역할이 둘로 갈린다. 한쪽은 망을 가진 쪽(Google 의 호스트 프로젝트, AWS 의 소유 계정)이고, 다른 쪽은 그 망의 칸을 빌려 쓰는 쪽(서비스 프로젝트, 참여 계정)이다. 망 쪽은 대역·칸·길·방화벽 규칙을 쥐고, 빌려 쓰는 쪽은 허락받은 칸에 기계를 띄운다. AWS 는 이 나눠 주기를 자원 공유 장치로 하고, 두 쪽이 같은 조직에 속해 있어야 한다는 조건을 건다.

경계는 꽤 단단하다. AWS 문서는 참여자가 "다른 참여자나 주인의 자원은 보거나 고치거나 지울 수 없다" 고 적는다. 같은 칸 안에 기계를 나란히 띄워도 서로의 살림에는 손이 안 닿는다. 값은 자원이 놓인 계정에 붙어서, 망은 공유돼도 계산서는 갈린다.

Google 은 여기에 제약을 하나 더 둔다 — 서비스 프로젝트는 호스트 프로젝트 하나에만 붙을 수 있고, 이미 만들어 둔 자원을 나중에 공유 망으로 옮겨 붙일 수는 없다. 그래서 이 선택은 대개 처음 짤 때 정해야 한다.

## 📊 비교: 여러 살림을 잇는 세 가지 짜임

| | 공유 망 | 짝짓기 | 바퀴통 구조 |
|---|---|---|---|
| **망 개수** | 하나 | 살림 수만큼 | 통 하나 + 살 여럿 |
| **대역 겹침** | 한 곳이 막는다 | 겹치면 못 잇는다 | 겹치면 못 잇는다 |
| **서로 통하기** | 처음부터 통한다 | 짝을 맺은 쌍만 | 통을 거쳐야 |
| **규칙 거는 자리** | 망 주인 한 곳 | 살림마다 | 통 한가운데 |
| **어울리는 때** | 신뢰 경계가 같을 때 | 몇 쌍만 이을 때 | 살림끼리 갈라 둘 때 |

## 💡 실제 사례

- **팀은 여럿, 망은 하나** — 망 담당이 대역과 방화벽을 쥐고, 각 팀은 배정받은 칸에 기계만 띄운다.
- **값은 따로 계산** — 망은 같이 쓰지만 기계 값은 그 기계를 띄운 살림에 붙어서, 팀별 값 관리는 그대로 남는다.
- **대역 충돌 막기** — 대역을 한 곳에서 나눠 주므로 나중에 온프레미스와 이을 때 겹쳐서 못 잇는 사고가 안 난다.

## 🚫 흔한 오해

- **망을 같이 쓰면 남의 기계도 다 보인다** — 아니다. 참여자는 같은 칸에 있어도 다른 참여자나 주인의 자원을 보거나 고치거나 지울 수 없다고 문서가 명시한다.
- **망 주인이 값을 다 낸다** — 자원 값은 그 자원이 놓인 살림에 붙는다. 망은 공유되고 계산서는 갈린다.
- **망은 무조건 하나로 합치는 게 낫다** — 같은 망 안에서는 서로 바로 닿는다는 성질이 신뢰 경계가 다를 때는 그대로 위험이 된다. 오갈 일이 거의 없는 살림은 망을 따로 두고 필요한 곳만 여는 편이 낫다.

## 📝 정리

**"망은 한 벌, 살림은 여럿"** 이라고 읽으면 된다. 망을 쥐는 쪽과 기계를 띄우는 쪽을 갈라 놓아 권한은 좁히고 대역 충돌은 없애면서, 값과 접근 권한은 살림별로 그대로 갈라 받는다. 대신 같은 망 안이라 서로 바로 닿으므로, 신뢰 경계가 다른 살림까지 억지로 넣지 않는다.

## 🧒 열 살에게

한 건물에 여러 학원이 세 들어 있으면 전기랑 소방은 건물 주인이 한 번에 다 챙기지? 학원들은 각자 제 교실만 꾸미면 되고 옆 교실 물건은 못 건드려. 대신 쓴 만큼의 돈은 각자 따로 내.
