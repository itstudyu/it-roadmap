# Firewall

## 📝 정의

방화벽(Firewall)은 네트워크 트래픽을 모니터링하고, 사전에 정의된 보안 규칙에 따라 허용하거나 차단하는 보안 장치 또는 소프트웨어입니다. 마치 국경의 검문소처럼, 모든 네트워크 데이터가 들어오거나 나갈 때 검사하여, 허가받지 않은 것은 통과시키지 않습니다. 방화벽은 포트, IP 주소, 프로토콜, 콘텐츠 유형 등 다양한 기준으로 트래픽을 필터링할 수 있습니다.

방화벽이 필요해진 이유는 인터넷이 보편화되면서 악의적인 해킹 공격이 늘어났기 때문입니다. 외부 해커들이 조직의 네트워크 시스템에 접근하거나, 내부 직원이 무단으로 기밀 정보를 외부로 유출하려는 시도를 차단해야 합니다. 방화벽은 이러한 보안 위협으로부터 네트워크를 보호하는 첫 번째 방어선입니다.

### 한 줄 요약
> 정해진 규칙에 따라 허가받지 않은 네트워크 트래픽을 차단하는 보안 담장

### 비유
- 🔵 **비유 1**: 건물의 정문에서 방문객의 신분증을 확인하고 출입을 허가하거나 거절하는 경비원처럼, 방화벽은 네트워크의 모든 통신을 검사합니다. 등록되지 않은 사람은 출입이 거절됩니다.
- 🟡 **비유 2**: 편지를 검열하는 우체국 직원처럼, 방화벽은 모든 네트워크 패킷을 검사합니다. 금지된 내용이 있거나, 보내는 주소가 의심스러우면 편지를 반송합니다.

## 🎯 핵심 개념

### 1. 패킷 필터링 (Packet Filtering)
가장 기본적인 방화벽 기능입니다. 네트워크 패킷의 헤더 정보(출발지 IP, 목적지 IP, 포트 번호, 프로토콜)를 검사하여, 정의된 규칙과 비교합니다. 규칙에 맞으면 패킷을 통과시키고, 안 맞으면 차단합니다. 예를 들어 "출발지가 192.168.1.0/24이고 목적지 포트가 80(HTTP)이면 허용, 나머지는 차단"과 같은 규칙을 설정할 수 있습니다. 이는 계층 3~4 레벨에서 동작하며, 처리 속도가 빠르지만 헤더 정보만으로 판단하므로 정교함이 부족합니다.

### 2. 상태 기반 검사 (Stateful Inspection)
단순 패킷 필터링의 한계를 극복한 기술입니다. 방화벽이 현재 진행 중인 모든 연결 상태를 추적합니다. 예를 들어, 클라이언트가 외부 서버에 HTTP 요청을 보내면, 방화벽은 이 연결을 "활성"으로 표시하고, 서버의 응답은 같은 연결로 돌아오는 것이므로 자동으로 허용합니다. 반대로 외부에서 먼저 연결을 시도하면 이를 신규 연결로 판단하여, 정책에 따라 허용이나 거절을 결정합니다.

### 3. 애플리케이션 계층 필터링 (Application Layer Filtering, WAF)
HTTP, HTTPS, FTP 등 특정 애플리케이션 프로토콜의 내용을 검사합니다. 웹 애플리케이션 방화벽(WAF: Web Application Firewall)이 대표적입니다. 패킷 필터링이나 상태 기반 검사는 포트 80(HTTP)으로 들어오는 모든 트래픽을 허용하지만, WAF는 HTTP 요청의 내용을 검사합니다. SQL Injection, XSS(크로스 사이트 스크립팅), CSRF(크로스 사이트 요청 위조) 같은 웹 공격을 탐지하고 차단합니다.

### 4. 나가는 트래픽 제어 (Egress Control)
많은 조직은 방화벽으로 들어오는 공격만 차단하는데, 나가는 트래픽도 제어해야 합니다. 예를 들어, 직원이 회사의 기밀 데이터를 개인 클라우드 서비스에 업로드하거나, 악성 소프트웨어가 외부 명령 서버에 접속하려는 것을 차단할 수 있습니다. 이를 위해 들어오는 트래픽뿐만 아니라 나가는 트래픽도 필터링해야 합니다.

## ⚠️ 해결하는 문제

### 문제 1: 외부로부터의 악의적인 접근
인터넷에는 조직의 컴퓨터에 접근하여 데이터를 탈취하거나, 시스템을 마비시키려는 악의적인 해커들이 많습니다. 특히 알려진 보안 취약점이 있는 포트나 서비스는 자동화된 공격 도구의 표적이 됩니다. 예를 들어 포트 22(SSH), 포트 3306(MySQL), 포트 3389(RDP) 등으로 끊임없이 침투 시도가 들어옵니다. 방화벽이 없으면 이 모든 시도를 대응해야 하고, 실수로 취약점이 노출될 수 있습니다. 방화벽을 사용하면 필요한 포트만 열고 나머지는 모두 차단하여, 공격 표면을 크게 줄일 수 있습니다.

### 문제 2: 내부 정보 유출
악의적이든 부주의든, 직원이 회사의 기밀 정보를 외부로 유출할 수 있습니다. 또한 직원의 컴퓨터에 감염된 악성 소프트웨어는 사용자 몰래 중요한 데이터를 외부로 전송할 수 있습니다. 방화벽의 나가는 트래픽 제어(Egress Control) 기능을 사용하면, 승인되지 않은 외부 서비스로의 데이터 전송을 차단할 수 있습니다. 예를 들어, 개인용 클라우드 스토리지(Dropbox, Google Drive 등)로의 접속을 차단하거나, 특정 키워드가 포함된 파일의 전송을 차단할 수 있습니다.

### 문제 3: 성능 저하 공격 (DDoS)
분산 서비스 거부 공격(DDoS: Distributed Denial of Service)은 수많은 봇이 동시에 서버에 요청을 보내서 서버를 마비시키는 공격입니다. 이러한 공격 트래픽이 들어오면, 정상 사용자의 요청도 처리되지 않습니다. 방화벽의 고급 기능(Rate Limiting, 지역별 IP 차단, 패턴 분석)을 사용하면, 비정상적인 트래픽 패턴을 감지하고 자동으로 차단할 수 있습니다. 또한 많은 요청을 보내는 특정 IP나 국가의 트래픽을 사전에 차단할 수도 있습니다.

## ⚙️ 작동 원리

### 단계별 과정

1. **트래픽 수신**: 패킷이 네트워크에 들어오거나 나갑니다. 방화벽은 모든 패킷을 캡처합니다.

2. **패킷 검사**: 패킷의 헤더를 분석합니다. 출발지 IP, 목적지 IP, 포트, 프로토콜 등을 확인합니다.

3. **상태 테이블 확인**: 상태 기반 방화벽은 현재 진행 중인 연결 목록을 확인합니다. 이 패킷이 기존 연결의 일부인지 확인합니다.

4. **규칙 매칭**: 패킷 정보와 설정된 방화벽 규칙을 비교합니다. 규칙은 위에서 아래로 순차적으로 확인되며, 첫 번째로 일치하는 규칙이 적용됩니다.

5. **결정**: 규칙에 따라 "허용(Allow)", "차단(Deny)", "거부(Reject)" 등의 결정을 합니다.
   - 허용: 패킷이 통과합니다.
   - 차단: 패킷이 버려지고, 응답을 보내지 않습니다.
   - 거부: 패킷이 버려지고, 거부 응답을 보냅니다.

6. **로깅**: 대부분의 방화벽은 모든 결정을 로그 파일에 기록합니다. 이는 나중에 보안 감사와 문제 해결에 사용됩니다.

7. **응답 처리**: 허용된 패킷은 목적지로 전달됩니다. 응답 패킷도 같은 절차를 거칩니다.

```도해
흐름: Firewall, 무슨 순서로 오가나
방화벽 :: 기존 연결 확인 (없음)
방화벽 :: 규칙 매칭 Port 80: Inbound허용?
규칙베이스 :: YES
방화벽 :: 상태 추가 Active Connection
방화벽 :: 기존 연결 확인 (있음)
```

## ✅ 장점과 단점

### 장점

- **보안 위협 차단**: 악의적인 접근과 공격을 사전에 차단하여, 내부 네트워크를 보호합니다.
- **접근 제어**: 세밀한 규칙 설정으로 누가, 어디서, 언제 어떤 리소스에 접근할 수 있는지 통제합니다.
- **DDoS 공격 완화**: Rate Limiting, IP 차단, 패턴 분석 등으로 대규모 공격을 완화합니다.
- **내부 정보 유출 방지**: 나가는 트래픽 제어로 기밀 정보의 외부 유출을 방지합니다.
- **규정 준수**: 많은 산업 표준(PCI-DSS, HIPAA, GDPR 등)에서 방화벽 사용을 요구합니다.
- **중앙 집중식 관리**: 모든 네트워크 트래픽을 한 곳에서 모니터링하고 제어할 수 있습니다.
- **로깅 및 감시**: 모든 트래픽의 로그를 남겨서, 보안 사건 조사에 활용할 수 있습니다.

### 단점

- **성능 저하**: 모든 패킷을 검사하므로 네트워크 지연이 발생합니다. 특히 고급 검사(DPI, WAF)는 CPU 사용량이 높습니다.
- **관리 복잡성**: 규칙 설정이 복잡하고, 잘못된 규칙 설정으로 정상 트래픽이 차단될 수 있습니다.
- **단일 장애점**: 방화벽이 다운되면 네트워크가 완전히 마비됩니다. (고가용성 구성이 필요)
- **암호화된 트래픽의 한계**: HTTPS, VPN 같은 암호화된 트래픽은 내용을 검사할 수 없습니다.
- **정확성 문제**: 정당한 트래픽을 차단(False Positive)하거나, 악성 트래픽을 허용(False Negative)할 수 있습니다.
- **비용**: 엔터프라이즈급 방화벽의 구입 및 유지보수 비용이 많이 듭니다.
- **VPN 우회**: 기술에 능한 사용자는 VPN을 사용해 방화벽을 우회할 수 있습니다.

## 💡 실제 사용 사례

**기업 네트워크 보안**: 금융회사, 의료기관, 정부기관 등은 방화벽을 필수로 운영합니다. 직원들의 업무용 컴퓨터가 회사 네트워크에 접근할 때, 승인되지 않은 웹사이트나 포트로 접속하려 하면 즉시 차단됩니다. 또한 외부 해커들의 무차별적인 침투 시도를 모두 차단합니다.

**웹 애플리케이션 보호**: 웹사이트를 운영하는 회사는 WAF(Web Application Firewall)를 앞단에 배치합니다. SQL Injection, XSS, DDoS 공격 등을 자동으로 탐지하고 차단합니다. 특히 전자상거래 사이트는 고객의 신용카드 정보를 보호하기 위해 WAF 사용이 필수입니다.

**클라우드 서비스 보안**: AWS, Google Cloud 같은 클라우드 제공자는 고객의 인스턴스 앞에 방화벽(Security Groups, Cloud Firewall)을 제공합니다. 사용자는 이를 통해 자신의 서버로 들어올 수 있는 트래픽의 종류를 명시적으로 지정할 수 있습니다.

**원격 근무 보안**: 코로나 팬데믹 이후 원격 근무가 증가하면서, VPN 방화벽의 중요성이 높아졌습니다. 회사는 방화벽을 통해 VPN 접속자의 트래픽을 모니터링하고, 업무와 무관한 외부 접속을 차단합니다.

## 🔗 관련 용어

- **[[Proxy]]**: 클라이언트의 요청을 필터링하는 기술로, 방화벽과 유사한 역할을 합니다.
- **[[Reverse Proxy]]**: 서버를 보호하는 기술로, 방화벽과 함께 사용됩니다.
- **[[Load Balancer]]**: 트래픽을 분산하는 기술로, 방화벽 뒤에 위치합니다.
- **[[Gateway]]**: 네트워크 경계를 관리하는 기술로, 방화벽을 포함합니다.
- **[[VPN]]**: 암호화된 터널을 제공하는 기술로, 방화벽과 함께 사용됩니다.
- **WAF (Web Application Firewall)**: 애플리케이션 계층에서 공격을 탐지하는 특화된 방화벽입니다.
- **IDS/IPS**: 침입 탐지/방지 시스템으로, 방화벽과 함께 사용되는 보안 장비입니다.
- **DDoS 공격**: 많은 봇에서 동시에 요청을 보내는 공격으로, 방화벽으로 완화할 수 있습니다.
