# Multi-tenancy (멀티 테넌시)

## 📝 정의

Multi-tenancy는 **한 시스템을 여러 고객이 나눠 쓰는 구조**다.

고객마다 서버와 데이터베이스를 따로 두면 고객이 늘어난 만큼 관리할 시스템도 늘어난다. 하나를 같이 쓰면서 데이터만 갈라두면, 새 고객을 받는 일이 설정 한 줄이 된다.

### 비유
아파트. 건물과 배관은 한 채를 같이 쓰지만 현관문은 세대마다 따로 있고 옆집에 들어갈 수는 없다.

## 🖼️ 그림으로 보기

```도해
흐름: A 회사 직원이 접속하면 무엇을 보고 데이터를 가르나
사용자 :: a.example.com 으로 접속한다
서버 :: 주소나 토큰에서 A 회사임을 알아낸다
요청 :: 이 요청의 소속을 A 로 정해둔다
데이터베이스 :: 모든 조회에 소속 조건이 자동으로 붙는다
< 화면 :: A 회사 데이터만 담긴 결과가 그려진다
= 같은 코드, 같은 테이블인데 보이는 것만 갈린다
```

## ⚠️ 해결하는 문제

```도해
대조: 고객이 백 곳으로 늘면 어떻게 되나
고객마다 따로 || 한 시스템을 나눠
서버 :: 백 벌을 띄운다 || 한 벌을 키운다
배포 :: 백 번 올린다 || 한 번 올린다
새 고객 :: 환경을 새로 짠다 || 설정만 추가
= 관리 대상 수를 고객 수에서 떼어놓는 것이다
```

고객마다 환경을 따로 두면 고칠 것이 생길 때마다 그 수만큼 작업이 늘어난다. 보안 패치 하나를 백 군데에 올려야 하고, 어느 곳이 어느 버전인지도 갈라진다.

한 시스템을 같이 쓰면 배포와 점검이 한 번으로 끝난다. 대신 갈라두는 일을 코드가 책임진다. 조회 한 줄에 소속 조건이 빠지면 남의 데이터가 그대로 나간다.

## ⚙️ 작동 원리

가르는 방식은 몇 가지가 있고 무엇을 얼마나 나눌지가 다르다.

```도해
층: 데이터를 어디서 가르나
행으로 :: 한 테이블에 소속 컬럼을 두고 조건으로 거른다
스키마로 :: 고객마다 테이블 묶음을 따로 둔다
DB 로 :: 고객마다 데이터베이스를 따로 둔다
= 아래로 갈수록 갈라짐은 확실해지고 관리할 것은 늘어난다
```

어느 방식이든 요청이 들어온 시점에 소속을 정하는 일이 먼저다. 주소의 앞부분으로 알아내거나 로그인 토큰에 담아둔다. 그다음 모든 조회가 그 값을 자동으로 붙이게 만든다. 개발자가 매번 손으로 붙이는 구조면 언젠가 한 군데를 빠뜨린다.

한 고객이 시스템을 독차지하는 것도 막아야 한다. 요청 수 제한을 고객별로 걸어두지 않으면, 한 곳의 대량 작업이 나머지 전부의 응답을 느리게 만든다.

## 💡 실제 사례

- **업무용 SaaS** — 회사마다 다른 주소로 들어오지만 뒤에서는 같은 서비스가 돈다.
- **요금제별 제한** — 같은 코드를 쓰면서 저장 용량이나 사용자 수만 고객 설정으로 나눈다.
- **큰 고객만 분리** — 보안 요구가 엄한 고객은 데이터베이스를 따로 두고 나머지는 공유 환경에 남긴다.

## 🚫 흔한 오해

- **멀티 테넌시는 서버를 한 대만 쓴다는 뜻이다** — 대수와는 관계없다. 서버가 수십 대여도 한 벌의 시스템을 여러 고객이 나눠 쓰면 멀티 테넌시다.
- **한 테이블에 섞여 있으니 보안이 약하다** — 나눠 담는 것보다 검증 자리가 좁아진다는 게 문제지 구조 자체가 약한 게 아니다. 조회에 소속 조건을 강제하면 갈라진다.
- **고객마다 기능을 자유롭게 바꿔줄 수 있다** — 같은 코드를 쓰기 때문에 오히려 어렵다. 고객별 요구를 다 받으면 분기가 쌓여서 공유하는 이점이 사라진다.

## 🚨 주의사항

- **소속 조건을 코드가 아니라 틀에서 강제한다.** 조회마다 손으로 붙이면 언젠가 한 군데가 빠지고, 그 한 번이 사고가 된다.
- **고객별 사용량 제한을 건다.** 한 고객의 대량 작업이 나머지 고객의 응답 시간을 그대로 끌어내린다.

## 📝 정리

Multi-tenancy는 한 벌의 시스템을 여러 고객이 나눠 쓰면서 데이터만 갈라두는 구조다. 관리 대상을 고객 수에서 떼어놓는 대신, 갈라두는 책임과 사용량 조절을 코드가 떠안는다.

## ❓ 이해했는지

- 고객이 백 곳인데 보안 패치를 한 번만 올려도 되는 이유는?
- 조회 한 줄에서 소속 조건이 빠지면 무슨 일이 일어나나?
- 한 고객이 대량 작업을 돌렸는데 다른 고객까지 느려진다면 무엇이 빠진 것인가?
