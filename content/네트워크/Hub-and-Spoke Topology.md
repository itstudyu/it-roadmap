# Hub-and-Spoke Topology (바퀴통과 바퀴살 구조)

## 📝 정의

Hub-and-Spoke Topology는 **가운데 한 곳에 공용 장비를 모으는 망 구조**다.

클라우드에서 망을 여러 개로 쪼개면 곧바로 같은 물음이 온다 — 방화벽과 온프레미스로 나가는 문을 망마다 하나씩 둘 것인가. 이 구조는 "아니오" 쪽의 답이고, Azure 의 클라우드 도입 프레임워크가 권하는 기본 짜임이다.

### 이름
Hub :: 바퀴통
Spoke :: 바퀴살
Topology :: 이어 놓은 모양
= 붙여 읽으면 "가운데 통에 살이 꽂힌 모양". 살끼리는 안 닿는다

### 비유
자전거 바퀴 — 살은 저마다 바깥으로 뻗지만 전부 가운데 통 하나에 꽂혀 있다.

### 예
부서마다 망을 따로 파 줬더니 방화벽과 사내 이름 장부를 부서 수만큼 사서 관리하고 있던 그 상황이다.

## 🖼️ 그림으로 보기

```도해
흐름: 한 살에서 나간 것이 바깥으로 어떻게 빠져나가나
살 망 :: 부서 하나의 기계들이 여기 산다
짝짓기 :: 살은 통하고만 짝을 맺는다
바퀴통 :: 검사 장비와 바깥으로 나가는 문이 여기 있다
바깥 :: 인터넷이나 본사 쪽으로 나간다
< 되돌이 :: 답도 같은 통을 거쳐 그 살로 돌아온다
= 살은 저마다 떨어져 있고, 오가는 것은 전부 통을 지난다
```

## ⚠️ 해결하는 문제

```도해
대조: 망마다 따로 갖추면 무엇이 힘들어지나
저마다 갖추면 || 통에 모으면
검사 장비 :: 망 수만큼 산다 || 한 벌만 산다
규칙 손보기 :: 스무 곳을 고친다 || 한 곳만 고친다
나가는 문 :: 사방에 열린다 || 한 곳으로 모인다
= 다 같이 쓸 것만 통에 모으고, 일감은 살마다 따로 둔다
```

망을 부서별·환경별로 쪼개는 것 자체는 좋은 일이다. 문제는 쪼갤 때마다 방화벽, 온프레미스로 나가는 게이트웨이, 사내 이름 장부, 기계에 들어가는 통로가 딸려 온다는 것이다. 스무 개로 쪼개면 이것들도 스무 벌이 되고, 규칙 한 줄을 고치려면 스무 곳을 돌아야 한다.

바퀴통 구조는 **여럿이 같이 쓸 것만** 가운데로 모은다. Azure 문서는 통을 "공용 장비를 두는 곳이자 온프레미스로 나가는 중심 지점" 이라고 적고, 살은 "일감을 저마다 떼어 두는 곳" 이라고 적는다. 값도 여기서 갈린다 — 검사 장비 한 벌을 여럿이 나눠 쓰면 살마다 두는 것보다 훨씬 싸진다.

## ⚙️ 작동 원리

가장 자주 데는 자리는 **짝짓기가 이어 타지 않는다**는 성질이다. 살 A 가 통과 짝을 맺고 통이 살 B 와 짝을 맺어도, 그것만으로 A 와 B 가 통하지는 않는다. Azure 문서는 이를 "비전이 관계" 라고 적는다. A 와 B 를 통하게 하려면 길을 손으로 적어 통 안의 방화벽으로 보내거나, 두 살을 직접 짝지어야 한다.

AWS 는 이 문제를 아예 전용 장치로 푼다. Transit Gateway 는 스스로를 "여러 가상 망과 온프레미스를 잇는 통과 허브" 라고 부르고, 각 망·VPN·전용 회선 게이트웨이를 붙임으로 달면 그 붙임들이 기본으로 같은 길표 하나에 묶인다. 망이 n 개일 때 짝을 일일이 맺으면 연결이 n 제곱으로 늘지만, 허브에 달면 n 개로 끝난다.

통을 거치면 한 걸음이 늘고, 그 걸음은 지연과 값으로 돌아온다. 그래서 오가는 양이 크고 지연에 예민한 두 살은 통을 거치지 않고 직접 짝짓는 편이 낫다고 문서가 권한다. 그리고 통은 리전 자원이다 — 일이 여러 리전에 있으면 리전마다 통을 하나씩 두고 통끼리 잇는다.

## 💡 실제 사례

- **환경 가르기** — 개발·시험·운영을 살 셋으로 떼어 두고, 이름 장부·시각 맞추기 같은 공용은 통에 한 벌만 둔다. Azure 가 대표 쓰임으로 먼저 꼽는 배치다.
- **나가는 길 한 곳으로** — 통에 둔 Azure Firewall 로만 바깥에 나가면 나가는 주소가 그 방화벽 것으로 모여서, 상대 쪽에 알려 줄 주소 목록도 한 벌로 끝난다.
- **기계 접속 통로** — 살마다 공개 주소를 열지 않고, 통에 둔 Azure Bastion 하나를 거쳐 모든 살의 기계에 들어간다.

## 🚫 흔한 오해

- **살끼리는 통에 꽂혀 있으니 서로 통한다** — 짝짓기는 이어 타지 않는다. 길을 따로 적어 통 안 장비로 보내거나 두 살을 직접 짝지어야 비로소 통한다.
- **망은 무조건 이 모양으로 짜는 게 낫다** — 통을 거치는 한 걸음이 그대로 지연과 처리 값이 된다. 오가는 양이 크고 지연에 예민한 두 살이라면 직접 잇는 편이 낫다고 문서가 먼저 말한다.
- **통은 하나면 된다** — 통은 리전 자원이다. 여러 리전에 일이 있으면 리전마다 통을 두어야 한 리전의 사고가 다른 리전의 길을 끊지 않는다.

## 📝 정리

**"가운데 통에 공용을 모은 바퀴 모양"** 이라고 읽으면 된다. 통에 모으는 것은 방화벽·나가는 문·이름 장부처럼 여럿이 같이 쓸 것뿐이고, 일감은 살마다 떨어져 있어야 이 짜임이 값을 한다. 살끼리는 저절로 통하지 않는다는 것 하나만 기억하면 절반은 안 헤맨다.

## 🧒 열 살에게

자전거 바퀴를 보면 살들은 서로 안 붙어 있고 전부 가운데 통에 꽂혀 있지? 어디로 가든 가운데를 지나야 하니까 지켜보는 사람도 문지기도 가운데에 한 명만 두면 돼. 살마다 문지기를 세우면 스무 명이 필요하잖아.

## ❓ 이해했는지

- 통에 나란히 꽂힌 살 둘이 서로 안 통하는 일은 왜 생기나 → 흔한 오해
- 부서 망을 스무 개로 쪼갰는데 검사 장비는 왜 한 벌이면 되나 → 해결하는 문제
- 오가는 양이 많은 두 부서를 굳이 직접 이어 주는 이유는 무엇인가 → 작동 원리
