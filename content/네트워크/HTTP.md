# HTTP (HyperText Transfer Protocol)

## 📝 정의

HTTP는 **웹에서 요청과 응답을 주고받는 규칙**이다.

브라우저가 "이 파일 주세요"라고 보내면 서버가 "여기 있습니다"라고 답한다. 그 편지의 양식을 정해둔 것이 HTTP다. 1991년에 나왔고 지금도 웹에서 오가는 거의 모든 것이 이 양식을 쓴다.

### 비유
식당의 주문서. 정해진 칸에 적어서 넘기면 주방이 그 칸을 보고 만들어 온다. 양식이 같으니 어느 식당에 가도 주문할 수 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 주소창에 주소를 치면 브라우저와 서버가 뭘 주고받나
브라우저 :: `GET /index.html` 을 보낸다
요청 헤더 :: 어떤 브라우저인지, 쿠키는 뭔지 같이 붙인다
서버 :: 그 경로에 파일이 있는지 찾는다
< 서버 :: `200 OK` 와 함께 HTML 본문을 돌려준다
< 브라우저 :: HTML 을 읽다가 이미지와 CSS 를 또 요청한다
= 한 번 묻고 한 번 답하면 끝난다. 페이지 하나에 이 왕복이 수십 번 일어난다
```

## ⚠️ 해결하는 문제

```도해
대조: 공통 규칙이 없으면 웹은 어떻게 되나
HTTP 없이 || HTTP 로
접속 방식 :: 사이트마다 다르다 || 어디든 똑같다
브라우저 :: 사이트별로 만든다 || 하나로 다 본다
새 사이트 :: 지원될 때까지 못 봄 || 만들면 바로 열림
= 웹이 퍼진 건 기술이 뛰어나서가 아니라 규칙이 하나였기 때문이다
```

초기 인터넷에는 파일을 주고받는 방법이 여럿 있었다. FTP, Gopher, 회사마다 만든 자체 방식. 브라우저를 만들려면 그걸 전부 지원해야 했고, 새로 생긴 방식은 지원이 붙을 때까지 아무도 못 봤다.

HTTP는 양식 하나로 그 문제를 없앴다. 서버가 무엇으로 만들어졌든 HTTP로 답하기만 하면 세상의 모든 브라우저가 읽는다.

## ⚙️ 작동 원리

요청은 **메서드**로 무엇을 할지 말한다.

| 메서드 | 하는 일 | 여러 번 보내면 |
|---|---|---|
| `GET` | 가져오기 | 같은 결과 |
| `POST` | 새로 만들기 | 여러 개 생긴다 |
| `PUT` | 통째로 바꾸기 | 같은 결과 |
| `PATCH` | 일부만 바꾸기 | 같은 결과 |
| `DELETE` | 지우기 | 같은 결과 |

`POST`만 여러 번 보내면 여러 개가 생긴다. 결제 버튼을 두 번 눌렀을 때 두 번 결제되는 사고가 여기서 나온다.

응답은 **상태 코드** 세 자리로 결과를 말한다. 앞자리만 봐도 누구 잘못인지 알 수 있다.

```도해
층: 상태 코드 앞자리는 무엇을 말하나
2xx :: 됐다. `200 OK`, `201 Created`
3xx :: 다른 데로 가라. `301`, `302`
4xx :: 네가 잘못 보냈다. `400`, `401`, `404`
5xx :: 내가 잘못했다. `500`, `503`
= 4로 시작하면 요청을 고쳐야 하고, 5로 시작하면 서버 로그를 봐야 한다
```

## 💡 실제 사례

- **로그인 유지** 서버는 매 요청을 처음 보는 것으로 취급한다. 브라우저가 쿠키를 자동으로 붙여 보내기 때문에 로그인이 이어지는 것처럼 보인다.
- **이미지 캐싱** 응답 헤더에 `Cache-Control`을 넣어두면 브라우저가 같은 이미지를 다시 받지 않는다.
- **API 서버** 화면 대신 JSON을 돌려주는 것 말고는 웹페이지를 주는 것과 똑같이 동작한다.

## 🚫 흔한 오해

- **HTTP가 로그인 상태를 기억한다** — 요청 하나하나는 서로를 모른다. 로그인이 유지되는 건 브라우저가 매번 쿠키를 같이 보내기 때문이다.
- **404는 서버가 죽었다는 뜻이다** — 서버는 멀쩡하다. 멀쩡하니까 "그런 경로 없다"고 답할 수 있다. 진짜로 죽으면 아무 답도 오지 않는다.
- **HTTPS는 HTTP와 다른 프로토콜이다** — 같은 HTTP다. 오가는 내용을 TLS로 감싼 것뿐이라 메서드도 상태 코드도 그대로다.

## 📊 비교

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
|---|---|---|---|
| 요청 처리 | 하나씩 줄 서서 | 한 연결에 여러 개 동시에 | HTTP/2와 같음 |
| 헤더 | 매번 통째로 | 압축해서 | 압축해서 |
| 바탕 | TCP | TCP | UDP 기반 QUIC |

## 📝 정리

HTTP는 요청과 응답의 양식을 정한 규칙이다. 매번 처음 보는 사이처럼 구는 덕에 서버를 늘리기 쉽고, 대신 로그인 같은 것은 쿠키나 토큰으로 따로 챙겨야 한다.
