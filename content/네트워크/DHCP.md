# DHCP (Dynamic Host Configuration Protocol)

## 📝 정의

DHCP 는 네트워크에 들어온 기기에 IP 주소를 **빌려주는** 규약이다.

이름 가운데의 Configuration 이 중요하다 — 주소만 주는 게 아니라 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소 같은 설정을 함께 내려준다. RFC 2131 과 2132 가 정한 IETF 표준이고, 그전에 쓰던 BOOTP 를 바탕으로 만들어져 메시지 형식도 거기서 물려받았다.

### 비유
도서관 대출증 — 책을 주는 게 아니라 기한을 정해 빌려주고, 기한이 되면 연장하거나 돌려줘야 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 새 기기는 IP 주소를 어디서 받아 오나
새 기기 :: "주소 줄 사람?" 을 같은 망에 방송한다
DHCP 서버 :: 남는 주소 하나를 골라 제안한다
새 기기 :: "그걸 쓰겠습니다" 를 다시 방송한다
< DHCP 서버 :: 장부에 적고 기한과 함께 확정해 돌려준다
= 네 번 주고받으면 주소가 생긴다. 다만 산 게 아니라 빌린 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 주소를 손으로 적어 넣으면 무엇이 문제인가
손으로 적으면 || DHCP 로
새 기기 :: 관리자가 직접 넣는다 || 켜면 알아서 받는다
같은 주소 두 대 :: 충돌이 난다 || 장부가 막는다
떠난 기기 :: 주소가 묶여 있다 || 기한이 끝나 회수
= 사람이 적어 넣던 일을 서버가 기한을 걸어 대신한다
```

네트워크를 쓰려면 기기마다 겹치지 않는 주소가 하나씩 있어야 한다. DHCP 가 없으면 새로 들어온 기기, 다른 서브넷으로 옮긴 기기의 주소를 사람이 직접 넣어야 하고, 빠져나간 기기의 주소도 사람이 직접 회수해야 한다. 오타 하나나 같은 주소를 두 대에 준 실수 하나가 그대로 장애가 된다.

DHCP 는 이 일을 서버 한 곳으로 모은다. 서버가 주소 풀과 설정값을 장부처럼 들고 있다가 기기가 켜질 때 하나를 **기한을 걸어** 빌려주고, 안 쓰게 된 주소는 기한이 끝나 저절로 풀로 돌아온다. 주소·서브넷 마스크·게이트웨이·DNS 를 한자리에서 함께 내려주는 것도 같은 이유다.

## ⚙️ 작동 원리

```도해
흐름: 빌린 주소는 어떻게 계속 쓰게 되나
임대 시작 :: 서버가 정한 기한과 함께 주소를 받는다
절반 지날 때 :: 빌려준 서버에 대고 갱신을 요청한다
< 서버 :: 연장해 주면 기한이 새로 시작된다
7/8 지날 때 :: 답이 없으면 아무 서버에나 방송해 본다
@ 기한 끝 :: 그래도 못 받으면 그 주소를 버리고 처음부터
= 임대는 저절로 늘어나지만, 늘어난 것에도 기한이 붙어 있다
```

시각은 임대 기간에서 계산한다. 절반이 지난 시점이 T1, 8분의 7이 지난 시점이 T2 다. T1 에는 빌려준 그 서버에게 직접 갱신을 청하고, T2 까지 답이 없으면 자기가 어느 망에 있는지에 대한 가정을 버리고 아무 서버에나 방송한다. 기한이 끝날 때까지 아무도 답하지 않으면 기기는 그 주소를 **즉시** 쓰지 못한다.

기기가 스스로 반납할 수도 있다. 다 썼다고 알리는 메시지를 서버에 보내면 그 주소는 기한 전에 풀로 돌아간다.

## 💡 실제 사례

- **처음 붙는 네트워크** — 집이든 사무실이든, 망에 붙는 순간 그 망의 DHCP 서버가 주소·게이트웨이·DNS 를 한 번에 내려준다. 사용자는 아무것도 입력하지 않는다.
- **노트북을 다른 층으로** — 다른 서브넷으로 옮기면 쓰던 주소는 그 자리에서 통하지 않는다. DHCP 는 새 자리에 맞는 주소를 다시 빌려준다.
- **프린터에 늘 같은 주소** — 특정 기기를 지정해 예약해 두면 그 기기에는 언제나 같은 주소가 간다. 자동으로 받으면서도 주소는 고정된다.

## 🚫 흔한 오해

- **DHCP 가 주소를 준다** — 빌려주는 것이다. 기한이 붙어 있고, 절반이 지나면 기기가 알아서 연장을 청한다. 연장에 실패하면 기한이 끝나는 순간 그 주소를 못 쓴다.
- **DHCP 는 IP 주소만 준다** — 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소도 같이 내려준다. 랜선을 꽂자마자 이름 해석이 되는 건 이것 때문이다.
- **전부 DHCP 로 자동으로 두면 된다** — 남이 찾아와야 하는 서버·프린터는 주소가 바뀌면 곤란하다. 그런 자리에는 예약을 걸거나 주소를 고정한다.

## 🚨 주의사항

- **서버가 멈춰도 당장은 조용하다.** 이미 빌린 기기는 기한이 남은 동안 그대로 쓴다. 새로 들어온 기기부터 주소를 못 받아서, 장애가 몇 시간 뒤에야 드러난다.
- **임대 기간을 자리에 맞춘다.** 기기가 자주 드나드는 게스트 망에서 기한을 길게 잡으면 떠난 기기의 주소가 계속 묶여 있다.
- **아무나 세운 DHCP 서버가 위험하다.** 승인받지 않은 서버가 끼어들면 기기들이 엉뚱한 주소와 설정을 받아 간다. Windows 서버가 Active Directory 에 승인된 DHCP 서버만 주소를 내주게 막는 이유다.

## 📝 정리

DHCP 는 주소를 나눠 주는 게 아니라 기한을 걸어 빌려주는 규약이다. 기기는 켜질 때 네 번의 주고받기로 주소와 함께 서브넷 마스크·게이트웨이·DNS 를 받고, 임대의 절반이 지나면 스스로 갱신을 청한다. 그래서 안 쓰는 주소는 사람이 손대지 않아도 풀로 돌아온다.
