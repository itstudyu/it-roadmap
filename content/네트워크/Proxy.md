# Proxy (Forward Proxy)

## 📝 정의

Proxy는 **클라이언트를 대신해 밖으로 요청을 보내는 서버**다.

요청을 받아 자기 이름으로 목적지에 보내고, 받은 응답을 원래 요청자에게 돌려준다. 그 사이에서 어디로 가는 요청인지 검사하고, 자주 오가는 응답은 저장해뒀다가 다시 쓴다.

### 비유
학교 관리실. 학생은 바깥으로 직접 편지를 보내지 못하고 관리실을 거친다. 관리실은 보낼 편지를 가려내고 발신인을 학교 이름으로 바꿔 부친다.

## 🖼️ 그림으로 보기

```도해
흐름: 사내 PC 가 google.com 을 열면 무슨 순서로 오가나
PC :: 프록시에게 google.com 을 달라고 한다
프록시 :: 차단 목록에 있는 주소인지 본다
프록시 :: 저장해둔 응답이 있으면 여기서 끝난다
프록시 :: 없으면 자기 IP 로 구글에 요청한다
구글 :: 프록시에게 응답을 보낸다
< 프록시 :: 응답을 저장해두고 PC 에 넘긴다
= 구글은 PC 가 아니라 프록시와 이야기했다고 알고 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 사내 PC 가 인터넷에 바로 나가면 무엇이 달라지나
프록시 없이 || 프록시로
밖에 보이는 것 :: PC 주소 그대로 || 프록시 주소만
사이트 차단 :: PC 마다 설정 || 한 곳에서
같은 응답 :: 매번 새로 받음 || 저장해둔 것
= 나가는 길을 한 곳으로 모으면 거기서 보고 막고 아낄 수 있다
```

PC들이 각자 인터넷에 나가면 밖에서 보이는 것은 각 PC의 주소다. 조직 안에 기기가 몇 대 있고 어떻게 배치돼 있는지가 조금씩 드러난다. 차단하고 싶은 사이트가 생기면 PC마다 설정을 심어야 하고, 사용자가 지워버리면 그만이다.

프록시는 나가는 길을 한 곳으로 모은다. 밖에서는 프록시 하나만 보이고, 정책은 프록시에만 넣으면 모든 PC에 적용된다. 같은 페이지를 여러 사람이 열 때는 처음 한 번만 밖에서 받아오고 나머지는 저장해둔 것을 준다.

## ⚙️ 작동 원리

저장해둔 응답에는 쓸 수 있는 시간이 붙어 있다. 그 시간이 지나면 버리고 원본 서버에 다시 물어본다. 오래 잡아두면 바뀐 내용을 늦게 보고, 짧게 잡으면 아낄 것이 없어진다.

HTTPS로 오가는 요청은 프록시도 안을 못 읽는다. 어느 주소로 가는 연결인지까지만 알고 그 안에서 무엇이 오갔는지는 모른다. 그래서 주소 단위로 막는 것은 되지만 내용을 검사하는 것은 되지 않는다.

## 📊 비교: Proxy vs Reverse Proxy vs VPN

| | Proxy | Reverse Proxy | VPN |
|---|---|---|---|
| 서 있는 자리 | 클라이언트 앞 | 서버 앞 | 두 지점 사이 |
| 감추는 것 | 클라이언트 IP | 서버 IP | 연결 전체 |
| 주로 하는 일 | 접근 제어, 캐싱 | 부하 분산, SSL 종료 | 원격 접속, 암호화 |
| 암호화 | 선택 | 선택 | 필수 |

## 💡 실제 사례

- **학교 네트워크** 수업 시간에 게임 사이트 접속을 프록시에서 막는다. PC마다 설정을 심을 필요가 없다.
- **회사 네트워크** 업무와 무관한 사이트를 차단하고, 직원들이 자주 여는 사이트는 저장해둔 응답으로 돌려준다.
- **ISP 캐시** 인기 있는 사이트의 응답을 미리 받아두고 가입자에게 대신 준다. 대역폭이 좁은 지역일수록 차이가 크다.

## 🚫 흔한 오해

- **프록시를 쓰면 익명이 된다** — 목적지 서버는 못 보지만 프록시 운영자는 전부 본다. 감춘 것이 아니라 보는 사람을 프록시 쪽으로 옮긴 것이다.
- **프록시와 VPN은 같은 것이다** — 프록시는 정해진 요청만 대신 보내고 암호화는 하지 않는다. VPN은 연결 자체를 감싸고 암호화한다.
- **프록시가 있으면 오가는 내용을 다 볼 수 있다** — HTTPS 안쪽은 프록시도 못 읽는다. 어느 주소로 가는지까지가 한계다.

## 🚨 주의사항

- **프록시가 멈추면 전부 멈춘다.** 나가는 길을 한 곳으로 모았으니 그 한 곳이 병목이자 고장 지점이 된다.
- **믿을 수 있는 프록시만 쓴다.** 오가는 것을 전부 보는 자리라, 출처를 모르는 공개 프록시로 회사 계정에 접속하면 안 된다.

## 📝 정리

Proxy는 클라이언트를 대신해 밖으로 요청을 보내는 중개 서버다. 나가는 길을 한 곳으로 모아 접근을 통제하고 응답을 저장해 다시 쓴다. 그 대신 한 곳이 병목이 되고, 오가는 것을 전부 보는 자리라 누가 운영하는지가 중요해진다.
