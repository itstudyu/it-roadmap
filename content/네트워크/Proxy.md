# Proxy (Forward Proxy)

## 📝 정의

프록시(Proxy)는 클라이언트를 대신해서 인터넷에 요청을 보내는 중개 서버입니다. 클라이언트의 요청을 받아서 자신의 이름으로 실제 서버에 전달하고, 응답을 다시 클라이언트에게 돌려줍니다. 이 과정에서 클라이언트의 실제 IP 주소를 감출 수 있으며, 요청과 응답을 캐싱하거나 접근을 제어할 수 있습니다.

프록시가 필요해진 이유는 기업이나 학교 같은 폐쇄된 네트워크 환경에서 외부 인터넷 접근을 통제하고, 보안을 유지하면서도 필요한 사용자들에게만 인터넷 접근을 허용하기 위함입니다. 또한 반복되는 요청의 응답을 캐싱하여 네트워크 트래픽을 줄이고 응답 속도를 높이는 역할도 합니다.

### 한 줄 요약
> 클라이언트가 인터넷에 접근할 때 중간에 서서 요청을 가로채고 대신 전달하는 중개인

### 비유
- 🔵 **비유 1**: 학교의 학생들(클라이언트)이 바깥세상(인터넷)과 직접 연락하지 못하고, 학교의 관리실(프록시)을 통해서만 편지를 보낼 수 있는 상황. 관리실에서는 어떤 편지는 받아주고 어떤 편지는 받지 않으며, 편지가 학교에서 오는 것처럼 위장해서 보냅니다.
- 🟡 **비유 2**: 미성년자가 술을 살 수 없으므로 성인 친구(프록시)에게 대신 사달라고 부탁하는 것. 가게 입장에서는 성인 친구와 거래하는 것처럼 보이지만, 실제로는 미성년자를 위한 것입니다.

## 🎯 핵심 개념

### 1. 클라이언트-대면 중개자
프록시는 클라이언트 쪽에 위치해서 모든 나가는 트래픽을 처리합니다. 실제 목적지 서버는 클라이언트와 직접 통신하지 않으며, 프록시를 통해서만 요청을 받습니다. 이를 통해 클라이언트는 자신의 실제 IP를 숨길 수 있고, 목적지 서버도 실제 클라이언트가 누구인지 알 수 없게 됩니다. 이것이 프라이버시를 제공하는 핵심 메커니즘입니다.

### 2. 접근 제어 및 필터링
프록시는 클라이언트가 어떤 사이트에 접근할 수 있는지 결정할 수 있습니다. 관리자는 특정 웹사이트를 차단하거나, 특정 시간대에만 접근을 허용하거나, 특정 사용자 그룹에게만 특정 리소스 접근을 허용하는 규칙을 설정할 수 있습니다. 이는 회사나 학교에서 직원이나 학생의 인터넷 사용을 관리하는데 매우 유용합니다.

### 3. 캐싱 기능
프록시는 이전에 받은 응답을 저장해두었다가, 같은 요청이 다시 들어오면 원본 서버에 다시 요청하지 않고 저장된 응답을 바로 돌려줄 수 있습니다. 이는 특히 많은 사용자가 같은 컨텐츠에 접근하는 환경에서 네트워크 대역폭을 크게 절약하고, 응답 시간을 단축시킵니다.

### 4. 보안과 익명성
클라이언트의 실제 IP를 숨기므로, 외부인이 회사 내부 네트워크 구조를 파악하기 어렵습니다. 또한 프록시에서 악성 코드가 포함된 응답을 필터링할 수도 있습니다. 다만 프록시 서버 관리자는 모든 네트워크 트래픽을 볼 수 있으므로, 신뢰할 수 있는 프록시를 사용하는 것이 중요합니다.

## ⚠️ 해결하는 문제

### 문제 1: 직접 연결의 보안 위험
일반적으로 클라이언트가 외부 서버에 직접 연결하면 클라이언트의 IP 주소가 노출되고, 외부 해킹 그룹이 이를 악용할 수 있습니다. 특히 기업 네트워크의 경우, 내부 IT 인프라 구조가 밖으로 노출되면 표적이 될 가능성이 높아집니다. 프록시는 클라이언트를 대신해서 요청을 보내므로, 실제 클라이언트의 IP가 외부에 노출되지 않습니다. 이를 통해 회사의 내부 네트워크를 보호하고, 해킹 공격의 대상이 되는 것을 방지합니다.

### 문제 2: 네트워크 트래픽의 비효율성
같은 웹사이트를 여러 사용자가 접근할 때마다 매번 원본 서버에서 전체 데이터를 받아와야 합니다. 이는 네트워크 대역폭을 낭비하고, 응답 시간을 길게 만듭니다. 특히 학교나 기업처럼 많은 사용자가 공유 네트워크를 사용하는 환경에서는 동일한 요청이 반복되는 경우가 많습니다. 프록시의 캐싱 기능을 사용하면 이미 받은 응답을 저장해두었다가 재사용할 수 있습니다. 결과적으로 네트워크 대역폭 사용량이 크게 줄어들고, 사용자가 체감하는 응답 속도가 빨라집니다.

### 문제 3: 부적절한 웹사이트 접근
조직 내에서 업무와 무관한 웹사이트나 보안 위험이 있는 사이트에 직원이나 학생이 접근하면 생산성 저하와 보안 침해가 발생할 수 있습니다. 기존에는 각 클라이언트 컴퓨터에 필터링 소프트웨어를 설치해야 하는데, 이는 관리 비용이 크고 우회하기 쉽습니다. 프록시에서 중앙집중식으로 접근 제어를 하면, 모든 사용자가 동일한 정책에 따라 관리되며, 개별 우회가 어렵습니다.

## ⚙️ 작동 원리

### 단계별 과정

1. **요청 수신**: 클라이언트가 프록시에 HTTP 요청을 보냅니다. 예를 들어, 학생이 Google.com에 접속하고 싶으면, 학교의 프록시 서버(192.168.1.100)로 요청을 보냅니다.

2. **정책 확인**: 프록시는 요청한 URL, 사용자, 시간 등을 확인하여 접근 정책을 적용합니다. 차단 목록에 있는 사이트면 바로 차단하고, 허용 목록에 있으면 계속 진행합니다.

3. **캐시 검색**: 프록시는 자신의 캐시 메모리에 이 요청에 대한 응답이 이미 저장되어 있는지 확인합니다. 캐시 유효 시간 내에 동일한 요청이 있으면, 원본 서버에 요청하지 않고 저장된 응답을 사용합니다.

4. **원본 서버로 전달**: 캐시에 없거나 캐시가 만료된 경우, 프록시는 자신의 IP를 출발지로 하여 목적지 서버에 요청을 보냅니다. 목적지 서버는 요청이 실제 클라이언트에서 온 것이 아니라 프록시에서 온 것으로 봅니다.

5. **응답 수신**: 목적지 서버가 프록시에게 응답을 보냅니다. 프록시는 이 응답을 캐시에 저장합니다.

6. **클라이언트에 반환**: 프록시는 응답을 원래 요청한 클라이언트에게 돌려줍니다.

```도해
흐름: Proxy, 무슨 순서로 오가나
클라이언트 :: google.com 요청 (GET /)
< Proxy :: 응답 전송 (빠름)
< Proxy :: 응답 전송
```

## ✅ 장점과 단점

### 장점

- **보안 강화**: 클라이언트의 실제 IP를 외부에서 볼 수 없으므로, 해킹 공격의 표적이 될 확률이 줄어듭니다.
- **접근 제어**: 관리자가 조직 내 모든 사용자의 인터넷 접근을 중앙에서 통제할 수 있습니다.
- **성능 향상**: 캐싱을 통해 반복되는 요청의 응답 시간이 크게 줄어들고, 네트워크 대역폭 사용량이 감소합니다.
- **악성 콘텐츠 필터링**: 프록시에서 악성 코드나 피싱 사이트를 사전에 차단할 수 있습니다.
- **관리 효율성**: 개별 클라이언트마다 설정할 필요 없이 프록시 서버 하나만 관리하면 됩니다.
- **대역폭 압축**: 일부 프록시는 이미지나 동영상을 압축하여 전송하기도 합니다.

### 단점

- **성능 병목**: 모든 트래픽이 프록시를 지나가므로, 프록시 서버에 과부하가 발생하면 모든 사용자가 영향을 받습니다.
- **관리 복잡성**: 프록시 서버의 설정과 유지보수에 전문 인력이 필요합니다.
- **신뢰성 문제**: 프록시 관리자는 모든 네트워크 트래픽을 볼 수 있으므로, 신뢰할 수 있는 프록시를 사용해야 합니다.
- **호환성 문제**: 일부 프로토콜이나 애플리케이션은 프록시를 지원하지 않을 수 있습니다.
- **암호화 우회 불가**: HTTPS 연결은 프록시도 내용을 볼 수 없으므로(중간자 공격 없는 한), 완전한 감시가 불가능합니다.
- **지연 시간**: 추가적인 중간 단계를 거치므로 약간의 지연이 발생합니다.

## 💡 실제 사용 사례

**학교 및 교육 기관**: 학교는 프록시를 사용해 학생들이 수업 시간에 게임 사이트나 소셜 미디어에 접근하는 것을 차단합니다. 또한 성인 콘텐츠나 보안 위험이 있는 사이트도 자동으로 필터링합니다. 이를 통해 교육 환경을 보호하고, 네트워크 대역폭을 절약합니다.

**기업 네트워크**: 대기업은 직원의 인터넷 사용을 감시하고 제한하기 위해 프록시를 도입합니다. 업무 관련이 없는 사이트 접근을 차단하고, 기밀 정보가 담긴 파일이 외부로 나가는 것을 감시할 수 있습니다. 동시에 자주 방문하는 사이트의 응답을 캐싱하여 직원들의 업무 속도를 개선합니다.

**ISP (인터넷 서비스 제공업체)**: ISP는 자신들의 프록시 서버를 운영하여 고객들의 인터넷 접속 속도를 높입니다. 인기 있는 웹사이트들의 응답을 캐싱해두었다가, 고객이 요청하면 빠르게 제공합니다. 이는 특히 시골 지역이나 대역폭이 제한된 환경에서 매우 유용합니다.

**우회 및 개인정보 보호**: 일부 사용자는 프록시를 사용해 자신의 실제 위치나 IP를 숨기고 인터넷을 사용합니다. 이는 개인정보 보호나 지역 제한을 우회하는 데 사용될 수 있지만, 악용될 여지도 있으므로 법적, 윤리적 문제가 될 수 있습니다.

## 🔗 관련 용어

- **[[Reverse Proxy]]**: 서버를 보호하는 프록시로, 클라이언트 앞이 아닌 서버 앞에 위치합니다.
- **[[Load Balancer]]**: 여러 서버에 트래픽을 분산하는 기술로, Reverse Proxy와 함께 사용됩니다.
- **[[VPN]]**: 암호화된 터널을 통해 원격 접속을 제공하는 기술로, 프록시보다 더 강력한 보안을 제공합니다.
- **[[Firewall]]**: 네트워크 트래픽을 규칙에 따라 허용/차단하는 보안 장치입니다.
- **[[Gateway]]**: 서로 다른 네트워크를 연결하는 진입점으로, 프록시와 유사한 역할을 합니다.
- **HTTP 캐싱**: 웹 캐싱 표준으로, 프록시의 캐싱 기능은 이 표준을 따릅니다.
