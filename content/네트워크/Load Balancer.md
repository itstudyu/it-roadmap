# Load Balancer (부하 분산기)

## 📝 정의

Load Balancer는 **들어오는 요청을 여러 서버에 나눠 보내는 장치**다.

사용자는 주소 하나만 알면 되고, 그 뒤에 서버가 몇 대인지는 몰라도 된다. 한 대가 죽어도 나머지로 넘겨주기 때문에 서비스는 계속 돌아간다.

### 이름
Load :: 밀려드는 일감
Balancer :: 고르게 나누는 것
= 붙여 읽으면 "밀려드는 일감을 고르게 나누는 것". 나누는 게 전부라 한 대의 처리 속도는 그대로다

### 비유
은행 창구 앞의 번호표 기계. 손님은 기계 앞에만 서면 되고, 어느 창구가 비었는지는 기계가 안다. 창구 하나가 자리를 비워도 줄은 계속 줄어든다.

### 예
새벽에 점검 공지도 없이 앱이 새 버전으로 바뀌어 있는 일이 있다. 서버를 한 대씩 빼고 갈아 끼운 결과다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청 하나가 어느 서버로 가는지 누가 정하나
사용자 :: `shop.com` 으로 요청을 보낸다
분산기 :: 지금 살아 있는 서버가 어디인지 본다
분산기 :: 규칙에 따라 한 대를 고른다
서버 B :: 요청을 처리한다
< 사용자 :: 응답을 받는다. 어느 서버였는지는 모른다
= 서버를 늘리고 줄이는 일이 사용자에게 보이지 않게 만드는 게 이 장치의 목적이다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버 한 대로 버티면 무슨 일이 생기나
분산기 없이 || 분산기로
서버 고장 :: 서비스 전체 중단 || 나머지가 받는다
트래픽 급증 :: 한 대가 감당 || 나눠서 감당
서버 교체 :: 내려야 한다 || 한 대씩 빼고 넣는다
= 늘릴 수 있게 되는 것보다, 한 대가 죽어도 되는 게 더 큰 이득이다
```

서버 한 대로 서비스하면 그 한 대가 곧 서비스의 상한이자 약점이 된다. 사람이 몰리면 느려지고, 재부팅하려면 서비스를 내려야 하고, 하드웨어가 고장 나면 복구할 때까지 아무도 못 들어온다.

분산기를 앞에 두면 서버가 여러 대라는 사실을 사용자가 알 필요가 없어진다. 배포할 때도 한 대씩 빼서 새 버전을 올리고 다시 넣는 식으로 서비스를 내리지 않고 바꿀 수 있다.

## ⚙️ 작동 원리

어느 서버로 보낼지 고르는 규칙이 몇 가지 있다.

| 규칙 | 어떻게 고르나 | 언제 맞나 |
|---|---|---|
| 라운드 로빈 | 차례대로 돌아가며 | 서버 성능이 같을 때 |
| 최소 연결 | 지금 가장 한가한 곳 | 요청 처리 시간이 들쭉날쭉할 때 |
| 가중치 | 좋은 서버에 더 많이 | 서버 사양이 다를 때 |
| IP 해시 | 같은 사용자는 늘 같은 서버 | 세션을 서버에 들고 있을 때 |

**헬스체크**가 이 장치의 핵심이다. 분산기는 서버마다 주기적으로 신호를 보내 살아 있는지 확인하고, 답이 없으면 목록에서 뺀다. 그래서 서버가 죽어도 사용자는 오류를 보지 않는다.

## 💡 실제 사례

- **무중단 배포** — 한 대를 목록에서 빼고 새 버전을 올린 뒤 다시 넣기를 반복한다. 사용자는 배포 중인지 모른다.
- **자동 확장** — 트래픽이 늘면 서버를 자동으로 띄우고 분산기 목록에 넣는다. 줄면 반대로 뺀다.
- **장애 격리** — 특정 서버만 오류율이 튀면 헬스체크가 걸러내고, 나머지가 그 몫을 받는다.

## 🚫 흔한 오해

- **분산기를 두면 무조건 빨라진다** — 요청을 나눌 뿐 처리 속도를 올리지는 않는다. 서버 한 대가 느리면 나눠도 느리다.
- **분산기 자체는 안 죽는다** — 죽는다. 그래서 분산기를 이중으로 두거나 관리형 서비스를 쓴다. 여기가 새로운 단일 장애점이 된다.
- **어느 서버로 갈지 사용자가 고를 수 있다** — 고를 수 없다. 그래서 로그인 정보를 서버 메모리에 들고 있으면 다음 요청에서 로그인이 풀린다.

## 🚨 주의사항

- **세션을 서버 메모리에 두지 않는다.** 다음 요청이 다른 서버로 가면 그 정보가 없다. Redis 같은 공용 저장소로 빼거나 토큰에 담는다.
- **헬스체크는 실제로 일을 시켜본다.** 포트가 열려 있는지만 보면, DB 연결이 끊긴 서버도 살아 있는 것으로 나온다.

## 📝 정리

**"앞에 서서 빈 창구로 나눠 보내는 그 장치"** 라고 읽으면 된다. 헬스체크로 답 없는 서버를 목록에서 빼기 때문에 한 대가 죽어도 사용자는 오류를 보지 않는다. 얻는 것은 속도보다 여유이고, 대신 세션을 어디에 둘지 다시 정해야 한다.

## 🧒 열 살에게

은행에 가면 번호표 뽑는 기계가 있지? 손님은 그 기계 앞에만 서면 되고, 어느 창구가 비었는지는 기계가 대신 봐 줘. 창구 한 곳이 문을 닫아도 기계가 그쪽으로 안 보내니까, 손님은 뭐가 닫혔는지도 모르고 줄은 계속 줄어들어.
