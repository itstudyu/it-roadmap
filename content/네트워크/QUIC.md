# QUIC

## 📝 정의

QUIC 는 UDP 위에서 **신뢰성과 암호화를 직접 챙기는** 전송 규약이다.

RFC 9000 이 붙인 부제가 그대로 설명이다 — "UDP 를 바탕으로 한 다중화된 안전한 전송". 순서 맞추기·재전송·혼잡 제어처럼 원래 TCP 가 하던 일을 QUIC 이 자기 안에서 하고, UDP 는 그냥 실어 보내는 통로로만 쓴다. HTTP/3 은 TCP 자리에 이 QUIC 을 놓고 돈다.

### 비유
엽서 뭉치에 스스로 번호와 봉인을 붙여 보내는 것 — 우체국이 순서를 안 챙겨주니 보내는 쪽이 챙긴다.

### 예
지하철에서 와이파이가 끊기고 데이터로 넘어가는 순간에도 보던 영상이 이어지는 쪽이 이것이다.

## 🖼️ 그림으로 보기

```도해
층: QUIC 은 무엇 위에 무엇을 얹은 것인가
HTTP/3 :: 웹 요청과 응답. 전송으로 QUIC 을 고른다
QUIC :: 스트림·재전송·TLS 암호화를 여기서 다 한다
UDP :: 그냥 던지는 통로. 순서도 확인도 없다
IP :: 어느 기계까지 갈지만 정한다
= TCP 가 하던 일을 UDP 위의 QUIC 이 스스로 챙긴다
```

## ⚠️ 해결하는 문제

```도해
대조: 연결을 TCP 로 맺으면 무엇이 아쉬운가
TCP + TLS 로 || QUIC 로
연결 시작 :: 악수를 두 번 한다 || 한 번으로 합친다
패킷 손실 :: 전부 같이 멈춘다 || 그 갈래만 멈춘다
암호화 :: 따로 얹어야 한다 || 규약에 들어 있다
= QUIC 은 TCP 가 하던 일을 UDP 위에서 다시 지은 것이다
```

TCP 로 연결을 맺으면 먼저 TCP 악수를 하고, 그 위에 TLS(오가는 내용을 암호로 감싸는 규약) 악수를 또 한다. 둘이 다 끝나기 전에는 아무 데이터도 못 보낸다. 그리고 그 연결 하나에 요청 수십 개를 태우면, 중간에서 패킷 하나만 잃어도 TCP 는 순서를 지키려고 뒤따라온 것까지 전부 붙잡아 둔다. 무관한 이미지 한 장 때문에 글씨가 안 나오는 일이 여기서 생긴다.

QUIC 은 두 가지로 이걸 없앤다. 암호 협상과 전송 설정 협상을 **한 악수로 합쳐서** 연결이 서는 데 드는 왕복을 줄이고, 손실 감지와 재전송을 스트림마다 따로 해서 잃어버린 갈래만 멈추게 한다. 악수를 두 번 하던 것을 한 번으로 줄이니 연결을 세우는 비용이 대략 절반이 된다.

## ⚙️ 작동 원리

```도해
흐름: QUIC 은 연결을 어떻게 한 번에 세우나
클라이언트 :: 암호 협상과 전송 설정을 첫 패킷에 함께 싣는다
UDP :: 그대로 던진다. 순서도 확인도 안 해준다
서버 :: 두 협상을 한꺼번에 처리하고 키를 정한다
< 서버 :: 키와 전송 설정을 함께 돌려준다. 여기서 연결이 선다
= 악수 두 번을 한 번에 합쳤다. 그래서 연결이 빨리 선다
```

한 번 연결이 선 뒤에는 **연결 ID** 가 그 연결의 이름표가 된다. IP 나 포트 같은 아래 계층의 주소가 바뀌어도 이 번호를 보고 같은 연결로 이어붙이기 때문에, 경로가 갈리는 순간에도 연결이 그대로 살아 있다.

전에 붙어본 서버라면 서버의 답을 기다리지 않고 첫 요청을 미리 보내는 길(0-RTT)도 있다. 다만 이 자리는 같은 요청이 되풀이 전송되는 공격을 막아주지 않으므로, 여러 번 실행되면 곤란한 요청을 여기에 실으면 안 된다.

## 📊 비교: TCP + TLS vs QUIC

| | TCP + TLS | QUIC |
|---|---|---|
| 밑에 깔린 것 | TCP | UDP |
| 악수 | 전송·암호 두 번 | 한 번에 합친다 |
| 패킷 하나를 잃으면 | 연결 전체가 기다린다 | 잃은 스트림만 기다린다 |
| 암호화 | 위에 따로 얹는다 | 규약 안에 들어 있다 |

## 💡 실제 사례

- **웹 페이지 첫 로딩** — HTTP/3 이 QUIC 위에서 돌아, 연결과 암호 협상을 한 악수로 끝내고 바로 문서를 받기 시작한다.
- **지하철에서 영상 보기** — 와이파이에서 셀룰러로 경로가 바뀌어도 연결 ID 가 같으면 같은 연결로 이어붙인다.
- **손실이 잦은 회선** — 이미지 한 장의 패킷이 사라져도 다른 스트림은 그대로 흘러서 화면이 통째로 멈추지 않는다.

## 🚫 흔한 오해

- **QUIC 는 UDP 라서 데이터가 새어 나갈 수 있다** — 아니다. 순서 맞추기와 재전송을 QUIC 이 직접 한다. UDP 는 실어 보내는 통로로만 쓰인다.
- **QUIC 가 TCP 보다 항상 낫다** — 이득은 한 연결에 여러 갈래를 태울 때 나온다. 갈래가 하나뿐인 통신이라면 손실 때 막힐 것도 하나뿐이라 얻는 게 적다.
- **QUIC 과 HTTP/3 은 같은 말이다** — QUIC 은 전송 규약이고, HTTP/3 은 그 위에서 도는 웹 규약이다. 규격도 따로 있다.

## 📝 정리

QUIC 은 TCP 가 하던 일을 UDP 위에서 다시 지은 전송 규약이다. 악수를 한 번으로 합쳐 연결이 빨리 서고, 스트림을 갈라놔서 손실 하나가 나머지 전부를 붙잡지 않는다. 대신 이 이득은 한 연결에 여러 갈래를 태울 때 나온다.
