# Socket (소켓)

## 📝 정의

Socket은 **프로그램이 네트워크에 데이터를 넣고 빼는 창구**다.

IP 주소로 어느 컴퓨터인지, 포트 번호로 그 안의 어느 프로그램인지를 가리킨다. 한 번 열고 나면 파일에 쓰고 읽듯 다룬다.

### 비유
전화기와 전화번호. 번호가 있어야 걸 수 있고, 받는 쪽이 수화기를 들어야 말이 오간다.

## 🖼️ 그림으로 보기

```도해
흐름: 두 프로그램이 소켓으로 이어지기까지 무엇을 하나
서버 :: 소켓을 만들어 9000번 포트에 붙인다
서버 :: 연결을 받겠다며 대기 상태로 들어간다
클라이언트 :: 자기 소켓을 만들어 그 주소로 건다
서버 :: 걸려온 연결을 받아 전용 소켓을 하나 연다
클라이언트 :: 그 소켓에 보낼 것을 쓴다
< 서버 :: 읽고 답을 써서 돌려준다. 끝나면 닫는다
= 대기하던 소켓과 대화하는 소켓은 서로 다른 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 다른 컴퓨터의 프로그램에 값을 보내려면 어떻게 하나
소켓 없이 || 소켓으로
전달 수단 :: 직접 궁리한다 || 읽고 쓰기로
상대 지목 :: 방법이 없다 || IP 와 포트로
다른 언어 :: 서로 못 맞춤 || 같은 규격
= 네트워크 통신을 파일 다루듯 만들어 놓은 것이다
```

같은 컴퓨터 안이라면 파일에 적어두거나 메모리를 나눠 쓸 수 있다. 다른 컴퓨터에 있는 프로그램에는 그 방법이 통하지 않는다. 어디로 보낼지 가리킬 방법도, 보낸 것을 받을 방법도 각자 만들어야 한다.

소켓은 그 자리를 하나로 정해 둔 것이다. 주소와 포트로 상대를 가리키고, 열고 난 뒤에는 읽고 쓰기만 한다. 규격이 같으니 파이썬으로 만든 쪽과 자바스크립트로 만든 쪽이 그대로 붙는다.

## ⚙️ 작동 원리

```도해
층: 소켓은 어느 자리에 있나
내 프로그램 :: send 와 recv 를 부르는 쪽
소켓 :: 운영체제가 들고 있는 통신 창구
TCP 나 UDP :: 창구를 만들 때 둘 중 하나를 고른다
IP :: 조각을 어느 길로 보낼지 정하는 아래층
= 소켓은 내 프로그램과 운영체제가 만나는 자리다
```

TCP 소켓은 연결을 먼저 맺는다. 서버가 대기하고 클라이언트가 걸면 그때 전용 통로가 생기고, 그 뒤로 오가는 것은 순서대로 빠짐없이 도착한다. UDP 소켓은 연결을 맺지 않고 주소를 붙여 그냥 던진다.

한 서버에 여러 클라이언트가 붙을 때는 대기용 소켓 하나가 연결을 받고, 연결마다 소켓이 새로 하나씩 생긴다. 그 각각을 별도 스레드에 맡기거나, 한 스레드에서 비동기로 번갈아 처리한다.

## 📊 비교: TCP 소켓 vs UDP 소켓

| | TCP 소켓 | UDP 소켓 |
|---|---|---|
| 연결 | 먼저 맺고 시작 | 맺지 않는다 |
| 빠진 조각 | 다시 보낸다 | 그대로 잃는다 |
| 순서 | 맞춰 준다 | 보장하지 않는다 |
| 쓰는 곳 | HTTP, 파일 전송 | 동영상, 게임 |

## 💡 실제 사례

- **웹 요청** — 브라우저가 서버의 443번 포트로 소켓을 열고 그 위에 HTTP 를 실어 보낸다.
- **채팅 서버** — 접속한 소켓들을 목록에 담아 두고 한 명이 보낸 글을 나머지에게 그대로 밀어준다.
- **여러 접속 처리** — 연결마다 스레드를 하나씩 붙이거나 한 스레드에서 비동기로 돌아가며 읽는다.

## 🚫 흔한 오해

- **소켓은 서버에만 있다** — 양쪽 끝에 하나씩 있다. 전화기가 양쪽에 있어야 통화가 되는 것과 같다.
- **소켓을 열면 선이 이어진다** — 전용선이 깔리는 게 아니라 양쪽 운영체제가 서로의 상태를 기억할 뿐이다. 오가는 조각은 매번 다른 길로 간다.
- **소켓은 곧 TCP 다** — 창구의 이름이지 규칙의 이름이 아니다. 만들 때 TCP 로 할지 UDP 로 할지 고르는 것이다.

## 🚨 주의사항

- **다 쓴 소켓은 닫는다.** 연결마다 하나씩 생기므로 안 닫으면 열 수 있는 개수가 바닥난다.
- **보낸 덩어리와 받는 덩어리가 같지 않다.** TCP 는 흐름이라 한 번에 보낸 것이 받는 쪽에서 나뉘어 도착할 수 있다.

## 📝 정리

Socket은 프로그램이 네트워크에 데이터를 넣고 빼는 창구다. IP 주소로 컴퓨터를, 포트 번호로 그 안의 프로그램을 가리키고 열고 난 뒤에는 파일처럼 읽고 쓴다. 만들 때 TCP 를 고르느냐 UDP 를 고르느냐에 따라 챙겨주는 것이 달라진다.

## ❓ 이해했는지

- 서버가 대기하던 소켓과 클라이언트와 실제로 대화하는 소켓이 다른 이유는?
- 같은 컴퓨터 안에서는 필요 없던 것이 다른 컴퓨터가 되면 필요해지는 이유는?
- 소켓을 만들 때 TCP 를 고르는 것과 UDP 를 고르는 것은 무엇이 달라지나?
