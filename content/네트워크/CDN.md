# CDN (Content Delivery Network)

## 📝 정의

CDN은 **파일을 사용자 가까운 곳에 미리 복사해두는 서버망**이다.

서울 사용자가 미국 서버에서 이미지를 받으면 지구를 한 바퀴 돌아야 한다. 같은 이미지를 서울에 복사해두면 그 왕복이 사라진다.

### 비유
편의점. 본사 창고가 아무리 커도 물 한 병 사러 거기까지 가지 않는다. 자주 팔리는 것만 동네마다 갖다 놓는다.

## 🖼️ 그림으로 보기

```도해
흐름: 이미지 하나를 받을 때 어디까지 다녀오나
사용자 :: 서울에서 이미지를 요청한다
서울 거점 :: 갖고 있나? 있으면 바로 준다
서울 거점 :: 없으면 원본 서버에 한 번만 물어본다
원본 서버 :: 미국. 파일을 내려준다
< 서울 거점 :: 받아서 저장해두고 사용자에게 전달
= 첫 사람만 미국까지 가고, 그다음 사람들은 서울에서 끝난다
```

## ⚠️ 해결하는 문제

```도해
대조: 원본 서버 한 곳에서만 주면 어떻게 되나
CDN 없이 || CDN 으로
먼 나라 사용자 :: 매번 지구 한 바퀴 || 가까운 거점에서
원본 서버 부하 :: 모든 요청을 받음 || 첫 요청만 받음
갑작스런 트래픽 :: 원본이 무너진다 || 거점이 흡수한다
= 거리를 줄이는 것과 원본을 지키는 것, 두 가지를 동시에 한다
```

빛도 지구 반대편까지 가는 데 시간이 걸린다. 서울에서 미국 서버까지는 왕복 200밀리초 남짓이고, 페이지 하나에 파일이 50개면 그 지연이 계속 쌓인다.

CDN은 거리를 줄인다. 동시에 원본 서버가 받는 요청 수를 크게 떨어뜨린다. 이미지, CSS, 동영상처럼 사용자마다 다르지 않은 파일은 한 번 복사해두면 계속 재사용되기 때문이다.

## ⚙️ 작동 원리

어느 거점으로 보낼지는 대개 [[DNS]]가 정한다. 같은 도메인을 물어도 한국에서는 서울 거점 IP를, 미국에서는 버지니아 거점 IP를 돌려준다.

```도해
층: 요청이 어디까지 올라가나
브라우저 캐시 :: 내 컴퓨터. 두 번째부터는 여기서 끝
CDN 거점 :: 같은 도시. 대부분 여기서 끝난다
CDN 상위 :: 지역 허브. 거점에 없을 때만
원본 서버 :: 진짜 파일이 있는 곳. 여기까지 오는 건 드물다
= 위에서 끝날수록 빠르다. 원본까지 오는 비율을 낮추는 게 CDN 튜닝이다
```

## 💡 실제 사례

- **정적 파일 배포** — 이미지, JS, CSS를 CDN에 올려두면 원본 서버는 화면 조립만 한다.
- **동영상 스트리밍** — 조각으로 쪼갠 영상 파일을 거점마다 두고, 시청자는 가장 가까운 곳에서 받는다.
- **트래픽 급증 방어** — 기사 하나가 터져 접속이 몰려도 거점이 대부분을 받아내서 원본은 평소와 비슷한 부하를 유지한다.

## 🚫 흔한 오해

- **CDN을 쓰면 서버가 빨라진다** — 서버 처리 속도는 그대로다. 줄어드는 건 파일이 오가는 거리와 원본이 받는 요청 수다.
- **모든 페이지가 빨라진다** — 사용자마다 다른 내용(장바구니, 마이페이지)은 캐시할 게 없어서 그대로 원본까지 간다.
- **파일을 바꾸면 바로 반영된다** — 거점에 이미 복사된 옛 파일이 만료될 때까지 남는다. 그래서 파일 이름에 버전을 붙이거나 무효화를 따로 요청한다.

## 🚨 주의사항

- **개인 정보가 담긴 응답은 캐시하지 않는다.** 설정을 잘못하면 A의 마이페이지가 B에게 그대로 나간다. 실제로 종종 일어나는 사고다.
- **캐시 무효화는 즉시가 아니다.** 배포 직후 옛 파일과 새 파일이 섞여 보일 수 있어서, 파일명에 해시를 붙이는 방식이 더 안전하다.

## 📝 정리

CDN은 자주 쓰이는 파일을 사용자 가까이 복사해두는 망이다. 거리를 줄이고 원본 부하를 덜어주지만, 사람마다 다른 내용에는 도움이 되지 않는다.

## ❓ 이해했는지

- 로그인한 사용자의 마이페이지가 CDN에서 빨라지지 않는 이유는?
- 새 이미지를 올렸는데 옛 이미지가 계속 보인다면 무엇 때문인가?
- CDN을 붙였는데 원본 서버 부하가 그대로라면 어디를 봐야 하나?
