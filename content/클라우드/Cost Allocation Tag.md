# Cost Allocation Tag (비용 배분 꼬리표)

## 📝 정의

Cost Allocation Tag 는 자원마다 붙여 **청구서를 나눠 보는 이름표**다.

키와 값 한 쌍(`팀=결제`)으로 자원에 붙는다. AWS 는 이것을 비용 배분 태그, Azure 는 그냥 태그, Google Cloud 는 라벨이라 부른다. 같은 물건인데 셋의 한도와 규칙이 조금씩 다르고, 특히 "붙였다" 와 "청구서에 나온다" 가 같은 말이 아니라는 점이 셋 다 걸리는 자리다.

### 이름
Cost :: 값
Allocation :: 나눠 붙이기
Tag :: 이름표
= 붙여 읽으면 "값을 나눠 붙이는 이름표". 이름이 곧 하는 일이다

### 비유
여럿이 함께 시켜 먹고 값을 나눠 낼 때, 시키는 그 자리에서 주문서에 이름을 적어 두는 일.

### 예
클라우드 요금 고지서에 큰 숫자 한 줄만 찍혀 있고, 어느 팀이 얼마를 썼는지 아무도 답을 못 하던 그 회의다.

### 직접
휴대폰 요금 명세서를 열어 항목별로 나뉜 줄을 보라. 총액 한 줄만 있었다면 무엇을 줄일지 정할 수 없다.

## 🖼️ 그림으로 보기

```도해
흐름: 요금이 팀별로 갈려 나오기까지 무엇을 거치나
자원 :: 만들 때 `팀=결제` 같은 이름표를 단다
이름표 :: 키와 값 한 쌍으로 그 자원에 붙는다
활성화 :: 청구 화면에서 그 키를 따로 켠다
청구 자료 :: 켠 키가 표의 열 하나로 생긴다
읽는 사람 :: 팀별로 갈린 금액을 그 열에서 본다
= 붙이는 일과 켜는 일은 다르다. 켜야 청구서에 열이 생긴다
```

## ⚠️ 해결하는 문제

```도해
대조: 이름표가 없으면 요금 고지서에서 무엇을 못 하나
이름표 없이 || 이름표를 붙이면
누가 썼나 :: 총액만 보인다 || 팀별로 갈린다
줄일 자리 :: 짐작으로 고른다 || 큰 것부터 짚는다
새는 자원 :: 주인이 없다 || 주인이 적혀 있다
= 나뉘지 않은 숫자는 아무도 자기 것으로 여기지 않는다
```

클라우드 요금은 한 계정 안에서 수천 개의 자원이 뒤섞여 한 덩어리로 나온다. 그 덩어리를 놓고 "이번 달에 왜 늘었나" 를 물으면 아무도 답할 수 없고, 답할 수 없으면 아무도 줄이지 않는다. 자원을 만든 사람과 요금을 받는 사람이 다른 순간부터 이 문제가 시작된다.

꼬리표는 **자원 하나하나에 주인과 용도를 미리 적어 두는 일**이다. AWS 는 켜 둔 꼬리표 키를 청구 자료의 열로 만들어 주고, 태그가 붙지 않은 자원까지 같은 보고서에 함께 담아 총액이 청구서와 맞아떨어지게 한다. 그래서 이 자료 하나로 "누가" 와 "얼마나" 가 동시에 나온다.

다만 이건 **미리 해 두는 일**이다. 켜는 것은 나중에 해도 된다 — AWS 는 관리 계정이 활성화 상태를 최대 12개월까지 소급해 채우는 길을 열어 둔다. 그런데 소급되는 것은 켜고 끈 상태뿐이고, 문서는 그 기간에 자원에 꼬리표가 실제로 붙어 있었어야 값이 채워진다고 못 박는다. 그러니 늦어도 되는 것은 켜는 일이고, 늦으면 영영 못 메우는 것은 붙이는 일이다.

## ⚙️ 작동 원리

꼬리표는 자원의 속성으로 붙는다. 그리고 요금 기록은 시간 단위로 한 줄씩 쌓이는데, 그 한 줄이 만들어지는 순간에 붙어 있던 꼬리표가 그 줄에 함께 찍힌다. 그래서 오늘 붙인 꼬리표는 어제까지의 줄에 없다 — 그 줄들은 이미 찍혀 나갔기 때문이다.

켜는 일은 그다음이다. 청구 화면에서 키를 켜면 그 키가 청구 자료의 열 하나로 올라서고, 그때부터 요금을 그 값으로 갈라 볼 수 있다. 켜기 전에도 값은 줄에 실려 있었고 열로 꺼내지 않았을 뿐이라, AWS 가 활성화 상태를 최대 열두 달까지 소급해 채워 줄 수 있는 것이다. 반대로 그 기간에 꼬리표가 안 붙어 있던 줄은 소급해도 빈칸으로 남는다.

열이 서고 값이 채워지기까지는 시간이 걸린다. AWS 는 켠 뒤 화면에 나타나기까지 최대 24시간이라고 적고, 소급 요청은 24시간에 한 번만 받는다. 보고서에서는 사람이 붙인 것이 `user:`, AWS 가 붙인 것이 `aws:` 접두사로 갈려 나온다.

## 📊 비교: 붙인 꼬리표가 청구서까지 어떻게 넘어가나

꼬리표를 붙이는 규칙 자체는 [[Resource Tag]] 쪽 얘기다. 여기서 갈리는 것은 그다음 — **붙인 것이 요금 표의 열이 되기까지 무엇을 더 해야 하나**다.

| 물음 | AWS | Azure | Google Cloud |
|---|---|---|---|
| **부르는 이름** | Cost Allocation Tag (비용 배분 태그) | Tag (태그) | Label (라벨) |
| **청구서에 나오려면** | 붙인 뒤 청구 화면에서 그 키를 따로 **켜야** 한다 | 붙이면 사용 내역 파일의 태그 칸에 실려 나온다 | 붙이면 청구 자료로 넘어가 요금을 쪼갠다 |
| **보고서에 적히는 꼴** | 사용자가 붙인 것은 `user:`, AWS 가 붙인 것은 `aws:` 로 갈린다 | 적은 대소문자가 그대로 실릴 수 있다 | 라벨 이름 그대로 |

셋의 차이는 하나로 줄어든다. **붙이는 일과 청구서에 나오는 일 사이에 단계가 하나 더 있느냐.** AWS 에는 있고 나머지 둘에는 없다. 그래서 "다 붙였는데 왜 그대로냐" 는 물음이 AWS 에서만 유독 자주 나온다.

## 💡 실제 사례

- **부서별 정산** — `팀`, `환경`, `제품` 세 키를 표준으로 정하고 전 자원에 강제한다. 월말에 고지서가 그대로 부서별 표가 된다.
- **주인 없는 자원 찾기** — AWS 의 비용 배분 보고서는 꼬리표가 붙은 자원과 안 붙은 자원을 같은 표에 담아 총액이 청구서와 맞아떨어지게 한다. 그 표에서 안 붙은 쪽만 뽑으면 대개 쓰지도 않으면서 돈만 먹는 자원 목록이 된다.
- **예산 알림 걸기** — 팀 꼬리표별로 한도를 걸어 두면, 총액이 터지기 전에 어느 팀이 넘겼는지가 먼저 온다.

## 🚫 흔한 오해

- **이번 달에 켰으니 지난달 요금은 영영 못 가른다** — 반만 맞다. AWS 는 관리 계정이 활성화 상태를 최대 12개월까지 소급해 채우게 해 준다. 다만 문서는 그 기간에 자원에 꼬리표가 실제로 붙어 있었어야 값이 채워진다고 적는다. 안 붙이고 지나간 달은 소급해도 빈칸이다.
- **붙이기만 하면 청구 화면에 바로 보인다** — AWS 는 붙인 뒤 그 키를 따로 켜야 하고, 켠 뒤에도 화면에 나타나기까지 최대 24시간이 걸린다고 적는다. 오늘 붙여 오늘 확인하려는 계획은 어긋난다.
- **켠 키는 모두 금액으로 갈려 나온다** — AWS 문서는 사용량을 재지 않는 서비스에 붙인 꼬리표는 켜도 비용 관리 화면에 채워지지 않는다고 적는다. 켠 키의 목록과 실제로 갈리는 금액은 같지 않다.

## 🚨 주의사항

- **키 이름을 먼저 정하고 시작한다.** `team`, `Team`, `팀` 이 섞이면 요금 표의 열이 셋으로 갈라진다. Azure 는 키의 대소문자를 가리지 않고 처리하지만, 적은 대소문자를 그대로 간직할 수 있고 그게 요금 보고서에 보인다고 적는다.
- **켜는 것은 관리 계정만 할 수 있다.** AWS 는 조직의 관리 계정과 조직에 속하지 않은 단독 계정만 비용 배분 태그 화면에 들어갈 수 있다고 적는다. 계정이 다른 조직으로 옮겨 가면 켜 두었던 것이 풀려서, 새 관리 계정이 다시 켜야 한다.
- **소급은 하루에 한 번뿐이다.** AWS 는 소급이 도는 중에는 새 요청을 넣을 수 없고 24시간에 한 번만 넣을 수 있다고 적는다. 정산 마감 직전에 몰아서 손볼 수 있는 일이 아니다.

## 📝 정리

**"청구서를 팀별로 가르는 그 이름표"** 라고 읽으면 된다. 붙이는 일과 청구 화면에서 켜는 일은 다르고, 켜는 일은 최대 열두 달까지 되돌릴 수 있지만 붙이지 않고 지나간 달은 되돌려도 빈칸이다. 그래서 이건 요금이 놀라운 달에 시작하는 일이 아니라 자원을 만드는 첫날에 정해 두는 일이다.

## 🧒 열 살에게

여럿이 같이 시켜 먹고 값을 나눠 낼 때, 시킬 때마다 누가 시킨 건지 적어 두지 않으면 마지막에 합친 숫자 하나만 남아. 그래서 시키는 그 순간에 이름을 적는 거야. 다 먹고 나서 나눠 달라고 하면, 적어 둔 것만 나뉘고 나머지는 영영 못 나눠.
