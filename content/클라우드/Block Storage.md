# Block Storage (블록 스토리지)

## 📝 정의

Block Storage 는 서버에 붙여 **디스크처럼 쓰는** 저장소다.

저장 공간을 일정한 크기의 조각(블록)으로 나눠 번호만 매겨 두고, 그 위에 파일 시스템을 얹는 일은 붙인 서버가 한다. 클라우드는 이 조각 묶음을 볼륨이라는 이름으로 판다 — AWS 는 EBS, Azure 는 관리 디스크, Google Cloud 는 Persistent Disk 와 Hyperdisk 다.

### 이름
Block :: 번호 매긴 같은 조각
Storage :: 넣어 두는 곳
= 붙여 읽으면 "조각 단위로 넣어 두는 곳". 조각만 골라 고칠 수 있다는 뜻이다

### 비유
책상 옆에 붙여 두는 서랍장. 서랍 하나만 열어 안의 것을 바꿔 넣을 수 있고, 책상을 새것으로 바꿔도 서랍장은 떼어서 그대로 붙이면 된다.

### 예
클라우드에서 가상 서버를 만들 때 "루트 볼륨 30GB" 처럼 디스크 크기와 종류를 고르는 그 칸이다.

### 직접
지금 쓰는 컴퓨터의 디스크 정보를 열어 보라. 전체 용량과 남은 용량이 먼저 나오는데, 클라우드의 볼륨도 똑같이 크기를 미리 잡아 두고 그만큼 낸다.

## 🖼️ 그림으로 보기

```도해
층: 서버가 파일 하나를 읽을 때 블록 스토리지는 어디에 있나
파일 :: 사람이 이름과 경로로 부르는 것
파일 시스템 :: 그 파일이 몇 번 조각에 있는지 적어 둔다
블록 볼륨 :: 서버에 붙은 번호뿐인 조각들. 클라우드가 파는 자리
저장 장치 :: 같은 조각을 여러 벌로 복제해 두는 실제 장치
= 붙이고 나면 그냥 디스크다. 클라우드는 조각까지 팔고 그 위는 서버가 얹는다
```

## ⚠️ 해결하는 문제

```도해
대조: 가상 서버에 딸린 임시 디스크만 쓰면 무엇이 달라지나
임시 디스크만 || 블록 볼륨으로
서버를 끄면 :: 내용이 날아간다 || 그대로 남는다
용량 늘리기 :: 서버를 다시 만든다 || 붙인 채로 늘린다
서버 교체 :: 옮겨 담아야 한다 || 떼서 붙이면 된다
= 저장을 서버의 수명에서 떼어 내는 것이 볼륨이 하는 일이다
```

가상 서버에는 대개 임시 디스크가 딸려 온다. 빠르지만 서버가 멈추면 그 안의 것이 사라진다. Azure 문서는 유지 관리나 재배포, 서버 중지 때 임시 디스크의 내용이 사라질 수 있다고 적고, Google Cloud 문서도 로컬 SSD 는 어떤 이유로든 인스턴스가 멈추면 저장된 것이 사라진다고 적는다.

블록 볼륨은 저장을 서버의 수명에서 떼어 놓는다. AWS 문서는 EBS 볼륨이 인스턴스가 도는 것과 무관하게 남는다고 적는다. 서버를 지워도 볼륨은 남고, 다른 서버에 다시 붙일 수 있고, 붙인 채로 크기와 성능을 바꿀 수도 있다.

## ⚙️ 작동 원리

볼륨은 만들 때 가용 영역 하나에 놓인다. 한 서버에 여러 볼륨을 붙일 수 있지만 볼륨과 서버는 같은 가용 영역에 있어야 한다. 볼륨의 내용은 그 영역 안의 여러 대에 자동으로 복제되어, 한 대가 고장 나도 남는다. Azure 는 같은 일을 세 벌 복제로 적는다.

기본은 한 볼륨에 한 서버다. 여러 서버가 같은 볼륨에 동시에 붙는 설정이 따로 있긴 하지만, Azure 문서는 그 구성에 노드 사이의 통신과 쓰기 잠금을 맡는 클러스터 관리자가 필요하다고 적는다. 잠금을 맡는 쪽 없이 두 서버가 같은 조각을 고치면 파일 시스템이 깨진다.

성능은 미리 사 둔다. 볼륨 종류와 크기가 초당 처리 횟수(IOPS)와 처리량을 정하고, 요금도 실제로 쓴 양이 아니라 잡아 둔 크기와 성능에 붙는다. 그 시점 그대로 떠 두는 스냅샷은 볼륨과 따로 남아서, 거기서 새 볼륨을 만들어 다른 영역이나 다른 계정에 붙일 수 있다.

## 📊 비교: 어떤 볼륨 종류를 고르나

| | SSD 계열 | HDD 계열 |
|---|---|---|
| AWS 의 예 | gp3 · io2 | st1 · sc1 |
| 잘 하는 일 | 작은 읽기·쓰기를 많이 | 큰 덩어리를 몰아서 |
| 재는 값 | 초당 처리 횟수(IOPS) | 초당 처리량 |
| 쓰는 자리 | 데이터베이스, 부팅 디스크 | 로그 분석, 순차 읽기 |

## 💡 실제 사례

- **데이터베이스 저장 자리** — 조각 단위로 고쳐 쓰는 일이 많아 오브젝트 저장소로는 대신할 수 없다.
- **부팅 디스크** — 운영체제가 올라가는 볼륨. 서버마다 하나씩 붙고, 나머지 자료는 따로 붙인 볼륨에 둔다.
- **스냅샷으로 옮기기** — 볼륨을 그 시점 그대로 떠 두고, 그 스냅샷에서 다른 가용 영역에 새 볼륨을 만들어 붙인다.

## 🚫 흔한 오해

- **볼륨은 아무 서버에나 붙일 수 있다** — 볼륨과 서버는 같은 가용 영역에 있어야 한다. 다른 영역으로 옮기려면 스냅샷을 떠서 그쪽에 새 볼륨을 만든다.
- **여러 서버가 같은 볼륨을 나눠 쓰면 된다** — 기본은 한 서버다. 동시에 붙이는 설정을 쓰더라도 쓰기 잠금을 맡는 클러스터 관리자가 따로 있어야 하고, 그냥 붙이면 내용이 엉킨다.
- **빠르니까 무엇이든 볼륨에 두면 된다** — 사진과 영상, 백업처럼 통째로 넣고 꺼내는 것은 [[Object Storage]] 쪽이 훨씬 싸다. 볼륨은 붙인 서버 하나만 보고, 쓴 만큼이 아니라 잡아 둔 크기만큼 낸다.

## 🚨 주의사항

- **서버를 지워도 볼륨은 남는다.** 안 쓰는 볼륨과 스냅샷이 조용히 쌓여 요금만 나가는 일이 흔하다.
- **잡아 둔 만큼 낸다.** 1TB 를 잡고 10GB 만 써도 1TB 값이다. 붙인 채로 늘릴 수는 있으니 처음부터 크게 잡을 이유가 없다.
- **복제 범위를 확인하고 쓴다.** AWS 문서가 말하는 EBS 의 복제 범위는 가용 영역 안이다. 영역이 통째로 멈추는 경우까지 버티려면 스냅샷이나 [[Availability Zone]] 을 나눈 설계를 따로 세운다.

## 📝 정리

**"서버에 붙여 쓰는 그 디스크"** 라고 읽으면 된다. 조각 단위로 고칠 수 있어 데이터베이스와 부팅 디스크가 여기 얹히고, 서버를 지워도 볼륨은 남아 다른 서버에 다시 붙는다. 대신 볼륨과 서버는 같은 가용 영역에 있어야 하고 값은 쓴 만큼이 아니라 잡아 둔 크기만큼 나간다.

## 🧒 열 살에게

책상 옆에 붙여 쓰는 서랍장 알지? 서랍 하나만 열어서 안에 든 걸 바꿔 넣을 수 있고, 책상을 새것으로 바꿔도 서랍장은 떼어서 그대로 옆에 붙이면 돼. 대신 두 사람이 동시에 같은 서랍을 뒤지면 안에 든 게 엉키니까 보통은 한 책상에만 붙여 둬.

## 🔗 관련 용어

- [[Object Storage]] — 같은 자리를 두고 겨루는 다른 저장 방식. 통째로 넣고 꺼낸다
- [[EC2]] — 이 볼륨을 붙여 쓰는 쪽
- [[Availability Zone]] — 볼륨과 서버가 같이 있어야 하는 범위
- [[File System]] — 조각 위에 서버가 얹는 층
- [[VM]] — 임시 디스크가 딸려 오는 그 가상 서버
