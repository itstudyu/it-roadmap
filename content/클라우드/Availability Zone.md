# Availability Zone (가용 영역)

## 📝 정의

가용 영역은 **한 리전 안에서 전원과 망이 따로 도는 데이터센터 묶음**이다.

AWS 서울 리전에는 가용 영역이 네 개 있고, 서로 떨어진 위치에 있다. 그러면서도 사이 지연은 1~2밀리초라, 여러 곳에 나눠 두어도 응답이 느려지지 않는다.

### 비유
같은 도시에 흩어진 여러 지점. 강남 지점이 정전으로 문을 닫아도 강북 지점은 그대로 손님을 받는다.

### 예
어떤 서비스가 멈췄다는데 옆 사람은 멀쩡히 쓰고 있는 일이 있다. 나눠 둔 곳 가운데 한 곳만 죽으면 그렇게 된다.

## 🖼️ 그림으로 보기

```도해
층: 리전과 가용 영역은 어떻게 겹쳐 있나
리전 :: 서울, 도쿄처럼 지리적으로 나눈 큰 단위
가용 영역 :: 한 리전 안의 독립된 데이터센터 묶음
데이터센터 :: 가용 영역 하나에 여러 건물이 들어간다
랙과 서버 :: 실제로 내 코드가 도는 자리
= 리전을 고르면 그 안의 영역들을 쓸 수 있고, 어디에 놓을지는 내가 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터센터 한 곳에만 두면 어떻게 되나
한 곳에만 || 여러 영역에
정전 :: 전부 멈춘다 || 남은 곳이 받음
화재나 침수 :: 복구까지 정지 || 몇 분 안에 복구
DB 쓰기 :: 손이 묶인다 || 복제본이 승격
= 장애가 안 나게 하는 게 아니라, 나도 서비스가 이어지게 하는 것이다
```

서버를 건물 한 곳에 모아두면 그 건물의 정전이나 화재가 그대로 서비스 전체의 정지가 된다. 전원 계통 하나, 냉방 하나, 네트워크 경로 하나에 모든 것이 매달려 있기 때문이다.

가용 영역은 그 매달림을 끊어둔 단위다. 영역마다 전원과 냉방과 망이 따로 있어서, 한쪽이 멈춰도 다른 쪽은 영향을 받지 않는다. 로드밸런서가 죽은 영역을 대상에서 빼고, 데이터베이스는 다른 영역의 복제본을 새 주인으로 올린다.

## ⚙️ 작동 원리

```도해
흐름: 가용 영역 하나가 죽으면 무슨 일이 일어나나
사용자 :: 평소처럼 사이트에 들어온다
로드밸런서 :: A, B, C 세 곳에 요청을 나눠 보낸다
헬스 체크 :: A 가 응답하지 않는 것을 알아챈다
로드밸런서 :: A 를 대상에서 빼고 B, C 로만 보낸다
DB :: B 에 있던 복제본을 새 주인으로 올린다
< 사용자 :: 화면은 그대로다. 무슨 일이 있었는지 모른다
= 한 곳이 죽어도 나머지가 받아내는 것이 여러 영역에 나눠 두는 이유다
```

고가용성 배치는 대개 두 단계다. 먼저 서버를 둘 이상의 영역에 나눠 두고 로드밸런서를 앞에 놓는다. 로드밸런서가 주기적으로 상태를 확인하다가 응답이 없으면 그 대상을 빼고, 남은 영역으로만 요청을 보낸다.

데이터베이스는 한 영역에 주인을, 다른 영역에 복제본을 둔다. 주인이 있는 영역이 죽으면 복제본 중 하나가 주인으로 올라가 쓰기까지 이어진다. Auto Scaling 을 걸어두면 잃은 만큼을 살아 있는 영역에 새로 띄운다.

## 📊 비교

| | 한 영역 | 두 영역 | 세 영역 |
|---|---|---|---|
| 가용성 | 99.9% | 99.95% | 99.99% |
| 비용 | 낮음 | 중간 | 높음 |
| 어디에 쓰나 | 개발, 테스트 | 일반 서비스 | 금융, 의료 |

같은 리전 안 다른 영역은 1~2밀리초, 다른 리전은 50~200밀리초다. 실시간 복제를 걸 곳과 재해 대비로 둘 곳이 갈리는 지점이 이 자릿수 차이다.

## 💡 실제 사례

- **쇼핑몰** — 웹 서버를 세 영역에 나눠 두고, 데이터베이스는 한 영역에 주인, 나머지에 복제본을 둔다.
- **금융 거래** — 규제가 요구하는 가용성을 맞추려고 리전의 모든 영역에 서버를 배치한다.
- **게임 서버** — 영역 하나가 죽어도 접속이 다른 영역으로 넘어가고, 진행 상황은 별도 저장소에 있어 이어진다.

## 🚫 흔한 오해

- **가용 영역은 리전을 부르는 다른 말이다** — 리전 하나 안에 가용 영역이 여럿 들어 있다. 서울 리전에도 네 개가 있다.
- **여러 영역을 쓰기로 했으니 안전하다** — 리소스를 실제로 나눠 놓아야 한다. 인스턴스를 전부 한 영역에 띄워두면 영역이 몇 개든 상관이 없다.
- **영역을 걸치면 느려진다** — 같은 리전 안이라 1~2밀리초다. 다른 리전으로 넘어갈 때와는 자릿수가 다르다.

## 🚨 주의사항

- **영역 사이 데이터 전송에는 비용이 붙는다.** 대량 동기화나 백업 이동을 무심코 걸면 요금이 크게 뛴다.
- **세션이나 임시 파일을 서버 로컬에 두지 않는다.** 요청이 다른 영역으로 넘어가는 순간 그 값이 사라진다.

## 📝 정리

가용 영역은 한 리전 안에서 전원과 망을 따로 쓰는 데이터센터 묶음이다. 둘 이상에 나눠 두면 한 곳이 죽어도 남은 곳이 받아내고, 같은 리전 안이라 지연은 1~2밀리초에 그친다. 나눠 두기로 정하는 것과 실제로 나눠 놓는 것은 다른 일이다.

## ❓ 이해했는지

- 서울 리전에 인스턴스를 세 대 띄웠는데 전부 같은 영역에 있다. 무엇이 문제인가 → 흔한 오해
- 로드밸런서는 어느 영역이 죽었는지 어떻게 알아채나 → 작동 원리
- 복제본을 다른 리전에 두는 것과 다른 가용 영역에 두는 것은 무엇이 갈리나 → 비교
