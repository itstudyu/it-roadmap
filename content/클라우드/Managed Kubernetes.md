# Managed Kubernetes (관리형 쿠버네티스)

## 📝 정의

Managed Kubernetes 는 **컨트롤 플레인을 클라우드가 맡는** 쿠버네티스다.

쿠버네티스 한 판은 무엇을 어디에 띄울지 정하는 컨트롤 플레인과, 그 지시를 받아 앱을 실제로 돌리는 노드로 나뉜다. 관리형은 앞의 것을 제공자가 세우고 지키고 판까지 올려 준다. AWS 의 EKS, Azure 의 AKS, Google Cloud 의 GKE 가 그것이다.

### 이름
Managed :: 남이 맡아 돌봄
Kubernetes :: 그리스말로 키잡이
= 붙여 읽으면 "키잡이를 남이 맡는다". 배와 짐은 내 것이고 조타실만 빌린다

### 비유
아파트 관리사무소. 집 안을 어떻게 쓸지는 내가 정하지만, 승강기와 물이 늘 돌아가게 지키는 일은 관리 회사가 대신 한다.

### 예
클러스터를 만들어 달라고 누른 지 몇 분 만에 쓸 수 있는 쿠버네티스가 생기는 그 순간이다. 조타실을 세운 적이 없는데 이미 돌고 있다.

## 🖼️ 그림으로 보기

```도해
층: 쿠버네티스 한 판에서 어디까지를 클라우드가 맡나
파드와 설정 :: 무엇을 몇 개 띄울지. 전부 내가 쓴다
노드 :: 앱이 실제로 도는 가상 머신. 내가 고르고 값을 낸다
컨트롤 플레인 :: 어디에 띄울지 정하는 머리. 클라우드가 세우고 지킨다
= 선은 노드와 컨트롤 플레인 사이에 그어져 있다. 아래를 빌리고 위를 내가 진다
```

## ⚠️ 해결하는 문제

```도해
대조: 클러스터를 직접 세우면 무엇이 달라지나
직접 세우면 || 관리형으로
머리 쪽 고장 :: 내가 깨서 고친다 || 맡긴 쪽이 고친다
판 올리기 :: 손으로 하나씩 || 눌러서 돌린다
보안 패치 :: 내가 챙긴다 || 자동으로 붙는다
= 쿠버네티스가 아니라 쿠버네티스를 돌보는 일을 덜어 주는 것이다
```

쿠버네티스는 켜 두면 저절로 도는 물건이 아니다. 컨트롤 플레인은 요청을 받는 API 서버, 파드를 어느 노드에 붙일지 고르는 스케줄러, 원하는 상태로 끌고 가는 컨트롤러, 그리고 클러스터의 모든 상태가 들어 있는 키-값 저장소로 이루어져 있다. 이 넷을 여러 대로 세우고, 백업하고, 판을 올리고, 새벽에 죽으면 살리는 일이 전부 사람 몫이다.

관리형은 그 몫을 제공자에게 넘긴다. Azure 문서는 클러스터를 만들면 Azure 가 컨트롤 플레인을 자동으로 만들어 설정하고 상태 감시와 유지 관리를 맡는다고 적는다. Google 문서도 GKE 에서는 Google Cloud 가 컨트롤 플레인과 시스템 구성 요소를 관리하며 판을 자동으로 올린다고 적는다. 남는 일은 노드를 얼마나 둘지와 그 위에 무엇을 띄울지다.

## ⚙️ 작동 원리

책임이 갈리는 선이 어디 그어지는지가 이 단어의 전부다. 기본 모드에서 제공자는 컨트롤 플레인까지만 맡고, 노드는 내가 고르고 값을 내고 판을 올린다. 그래서 파드를 많이 띄워도 노드에 자리가 없으면 스케줄러가 붙일 데를 못 찾아 그 파드는 뜨지 못한 채 기다린다. 노드를 자동으로 늘리는 설정은 따로 켜는 것이다.

노드까지 맡기는 모드가 세 곳에 다 있다. Azure 의 AKS Automatic 은 노드 생성과 확장과 판올림을 Azure 가 하고, Google 의 GKE Autopilot 도 워커 노드까지 Google Cloud 가 관리하며, AWS 의 EKS Auto Mode 는 그 범위를 데이터 플레인까지 넓힌다. 편해지는 만큼 노드를 내가 세밀하게 고를 여지는 줄어든다.

어느 쪽이든 쿠버네티스 자체는 그대로다. AWS 는 EKS 가 쿠버네티스 적합성 인증을 받았다고 적고 Azure 는 AKS 가 CNCF 인증이라고 적는다. 같은 설정 파일이 세 곳에서 그대로 돈다는 뜻이고, 클러스터를 옮기는 일이 앱을 다시 쓰는 일이 되지는 않는다.

## 📊 비교: 언제 관리형 쿠버네티스를 고르나

| | 컨테이너 실행 서비스 | 관리형 쿠버네티스 | 직접 세운 클러스터 |
|---|---|---|---|
| 내가 지는 일 | 컨테이너만 | 노드와 그 위 전부 | 컨트롤 플레인까지 전부 |
| 잘 맞는 일 | 앱 하나, 배치 작업 | 여러 앱을 한 판에서 | 규제·특수 환경 |
| 배울 것 | 거의 없다 | 쿠버네티스 전부 | 쿠버네티스와 그 운영 |
| 걸리는 자리 | 세밀한 제어가 없다 | 노는 노드도 값이 나간다 | 사람이 계속 붙는다 |

## 💡 실제 사례

- **환경마다 클러스터를 따로 만든다** — 컨트롤 플레인을 세울 일이 없으니 시험용과 운영용을 나눠 만들고, 안 쓰는 클러스터는 지운다.
- **노드 풀을 갈라 둔다** — 일반 작업용과 무거운 계산용 노드를 따로 두고, 파드가 필요한 쪽에만 붙게 한다.
- **판 올리기** — 컨트롤 플레인은 제공자가 올리고, 노드는 하나씩 비워 가며 새 판으로 갈아 끼운다.

## 🚫 흔한 오해

- **관리형이니까 알아서 커진다** — 맡긴 것은 컨트롤 플레인이지 클러스터의 크기가 아니다. 노드를 자동으로 늘리는 설정은 따로 켜는 것이고, 켜지 않으면 자리가 없어 파드가 뜨지 못한 채 기다린다.
- **컨트롤 플레인을 맡겼으니 보안도 다 맡긴 것이다** — 갈린 선 위쪽은 그대로 내 몫이다. 노드의 운영체제, 띄우는 이미지, 권한 설정, 통신 규칙은 여전히 내가 지킨다.
- **컨테이너를 쓰면 쿠버네티스를 써야 한다** — 앱 하나를 띄우는 데 클러스터를 세우면 배울 것과 낼 것만 늘어난다. Azure 는 컨테이너 하나만 돌리는 실행 서비스와 관리형 쿠버네티스를 아예 다른 선택지로 나열해 둔다.

## 🚨 주의사항

- **노드 값은 따로 나간다.** 컨트롤 플레인을 맡겼다고 클러스터가 공짜인 것은 아니다. 노드로 쓰는 가상 머신과 붙은 디스크는 그대로 청구된다.
- **판에는 지원 기한이 있다.** AWS 는 판마다 표준 지원과 연장 지원 기간을 정해 두고, Azure 는 자동 판올림 채널을 켤지 고르게 한다. 언제 올릴지는 미리 정해 둔다.
- **기본 모드에서 노드는 내 것이다.** AKS Standard 와 GKE Standard 는 노드 풀을 내가 만들고 관리한다고 문서에 적혀 있다. 관리형이라는 말만 보고 노드까지 맡겨졌다고 읽으면 안 된다.

## 📝 정리

**"조타실만 빌려 쓰는 쿠버네티스"** 라고 읽으면 된다. 컨트롤 플레인을 세우고 지키고 판 올리는 일이 제공자에게 넘어가고, 노드를 몇 대 둘지와 그 위에 무엇을 띄울지는 그대로 내 몫으로 남는다. 그래서 고를 때 물을 것은 쿠버네티스가 정말 필요한가와 노드까지 맡길 것인가 둘이다.

## 🧒 열 살에게

아파트에 살면 집 안을 어떻게 꾸밀지는 네가 정하지? 그런데 한밤중에 승강기가 멈추면 네가 고치러 가는 게 아니라 관리사무소에서 사람이 나와 고쳐 줘. 일하는 기계를 여러 대 빌려 쓸 때도 똑같아서, 무슨 일을 시킬지는 내가 정하고 기계들한테 일을 나눠 주는 반장이 새벽에 쓰러지면 대신 일으켜 세우는 건 빌려준 쪽이야.
