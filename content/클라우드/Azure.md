# Azure (Microsoft Azure)

## 📝 정의

Azure는 **Microsoft가 빌려주는 클라우드 플랫폼**이다.

200개가 넘는 제품과 서비스를 60개가 넘는 리전에서 제공한다. 서버실을 직접 두는 대신 필요한 자원만 골라 쓰고 쓴 만큼 값을 치른다.

### 비유
전력 회사. 집집마다 발전기를 두는 대신 계량기를 달고 쓴 만큼 값을 치른다.

### 예
사무실 구석에서 윙윙거리던 서버실이 없어지고 같은 업무 시스템을 웹 주소로 열게 되는 일, 그 뒤에 있는 것이 이런 플랫폼이다.

## 🖼️ 그림으로 보기

```도해
흐름: Azure 에 서비스 하나를 올리면 무엇이 만들어지나
구독 :: 요금이 붙는 단위를 고른다
리소스 그룹 :: 관련 자원을 한 묶음에 담는다
가상머신 :: 앱이 돌아갈 서버를 띄운다
Blob :: 이미지와 파일을 올린다
SQL DB :: 데이터를 담을 데이터베이스를 붙인다
사용자 :: 만들어진 주소로 들어온다
= 자원을 낱개로 두지 않고 그룹에 담아 한꺼번에 만들고 지운다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버실을 직접 두면 어떻게 되나
서버실 직접 || Azure 로
초기 투자 :: 장비값을 먼저 || 없이 시작한다
운영 :: 전기와 냉방까지 || 맡기고 안 본다
재해 복구 :: 따로 구축한다 || 기능으로 있다
= 발전소를 짓는 대신 전기를 사 쓰는 쪽으로 바꾼 것이다
```

서버실을 직접 두면 장비값 말고도 계속 나가는 돈이 있다. 전기와 냉방이 붙고 관리할 사람이 붙는다. 장애가 났을 때 대비하려면 그 설비를 한 벌 더 갖춰야 한다.

Azure는 그 설비를 빌려주고 쓴 만큼 청구한다. 사라지는 것은 건물 쪽 일이고, 그 위에 올린 OS 패치와 접근 권한은 여전히 쓰는 쪽 몫이다.

## 🧱 구성

```도해
층: Azure 의 자원은 무엇 안에 무엇으로 담기나
관리 그룹 :: 구독 여럿을 묶어 정책을 한꺼번에 건다
구독 :: 요금이 매겨지고 한도가 걸리는 단위
리소스 그룹 :: 한 서비스에 딸린 자원을 담는 묶음
리소스 :: 가상머신과 저장소처럼 실제로 도는 것
= 아래로 갈수록 실체고 위로 갈수록 청구와 정책의 단위다
```

## ⚙️ 작동 원리

Azure에서 만든 자원은 반드시 리소스 그룹 하나에 속한다. 서비스 하나를 이루는 가상머신과 저장소와 네트워크를 같은 그룹에 담아두면 권한을 그룹 단위로 주고, 다 쓴 뒤 그룹째 지울 수 있다.

명령줄에서는 `az` 로 다룬다.

```bash
az group create --name myResourceGroup --location koreacentral
az vm create --resource-group myResourceGroup --name myVM --image UbuntuLTS
```

## 📊 비교: Azure 와 AWS 의 짝

| 하는 일 | Azure | AWS |
|---|---|---|
| 가상 서버 | Virtual Machines | EC2 |
| 서버리스 함수 | Azure Functions | Lambda |
| 파일 저장소 | Blob Storage | S3 |
| 관계형 DB | Azure SQL | RDS |
| NoSQL | Cosmos DB | DynamoDB |
| Kubernetes | AKS | EKS |

## 💡 실제 사례

- **사내 서버 이전** — 서버실에서 돌던 업무 시스템을 가상머신으로 옮기고 서버실을 없앤다.
- **정기 작업** — 5분마다 도는 정리 작업을 Azure Functions의 타이머 트리거에 맡긴다.
- **배포 자동화** — Azure DevOps 파이프라인이 테스트를 돌리고 통과한 것만 앱 서비스에 올린다.

## 🚫 흔한 오해

- **Azure는 Windows 서버만 돌린다** — Microsoft 것이라 그렇게 보이지만 Linux 가상머신을 똑같이 띄운다. 이미지 목록에 Ubuntu가 그대로 있다.
- **AWS와 이름만 다르고 같은 서비스다** — 대응되는 짝은 있어도 이름과 동작이 다르다. EC2에 해당하는 것은 Virtual Machines고 S3에 해당하는 것은 Blob Storage다.
- **클라우드로 옮기면 유지보수가 사라진다** — 사라지는 것은 전기와 냉방 같은 건물 쪽 일이다. OS 패치와 권한 관리는 그대로 남는다.

## 📝 정리

Azure는 서버실을 직접 두지 않고 Microsoft의 설비를 빌려 쓰게 만든 플랫폼이다. 만든 자원은 리소스 그룹에 담겨 한꺼번에 관리된다. 건물 쪽 부담은 줄지만 빌린 서버 안쪽의 관리는 그대로 남는다.

## ❓ 이해했는지

- 자원을 리소스 그룹에 담아두면 다 쓰고 나서 무엇이 편해지나 → 작동 원리
- 클라우드로 옮겨도 줄어들지 않는 관리 업무는 무엇인가 → 흔한 오해
- AWS의 S3를 쓰던 사람이 Azure에서 같은 일을 하려면 무엇을 찾아야 하나 → 비교
