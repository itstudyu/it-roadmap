# Reserved Instance (예약 인스턴스)

## 📝 정의

Reserved Instance는 **오래 쓰겠다고 약속하고 요금을 깎는 계약**이다.

잡히는 것은 기계가 아니라 값이다. AWS 문서는 이를 "물리적 인스턴스가 아니라 계정 안의 온디맨드 인스턴스 사용에 적용되는 청구 할인" 이라 적고, Azure 문서도 예약은 청구 할인을 줄 뿐 자원의 실행 상태에는 영향을 주지 않는다고 적는다.

### 이름
Reserved :: 미리 잡아 둔
Instance :: 빌려 쓰는 한 대
= 붙여 읽으면 "미리 잡아 둔 한 대". 실제로 잡히는 것은 기계가 아니라 값이다

### 비유
한 해 치를 미리 끊으면 훨씬 싸지지만 안 가도 돈은 그대로 나가는 1년 회원권이다.

### 예
매달 같은 크기의 기계를 계속 켜 두면서 정가를 그대로 물던 청구서가, 약정 하나로 뚝 떨어지는 자리다.

## 🖼️ 그림으로 보기

```도해
대조: 정가로 쓸 때와 약정을 살 때는 무엇이 다른가
정가로 |=| 약정으로
요금 :: 시간당 정가 || 크게 깎인다
묶임 :: 언제든 그만 || 1년이나 3년
안 쓰는 달 :: 안 낸다 || 그대로 낸다
= 값을 깎는 대신 기간을 묶는다. 잡히는 것은 기계가 아니라 값이다
```

## ⚠️ 해결하는 문제

```도해
대조: 늘 켜 두는 자리에 정가를 계속 내면 어떻게 되나
정가로 계속 || 약정을 사면
같은 기계 값 :: 그대로 다 낸다 || 크게 깎인다
다음 달 청구 :: 그때마다 다르다 || 미리 정해진다
할인 적용 :: 붙을 게 없다 || 저절로 붙는다
= 늘 켜 두는 만큼만 미리 약속해 두면 그 몫의 값이 내려간다
```

클라우드의 기본 규칙은 쓴 만큼 낸다는 것이다. 그런데 실제 청구서를 보면 밑바닥에 늘 같은 높이로 깔려 있는 몫이 있다. 새벽에도 꺼지지 않는 데이터베이스, 늘 떠 있는 기본 대수 같은 것들이다. 그 몫에까지 "언제든 그만둘 수 있다" 는 값을 내는 것은 안 쓰는 보험료를 내는 셈이다.

예약은 그 보험을 되판다. Azure 문서는 예약 가능한 자원을 꾸준히 쓰고 있다면 예약이 비용을 줄여 준다고 적고, 종량 요금 대비 최대 72% 까지 낮아질 수 있다고 적는다. 그래서 자격증 지문에 "사용량이 일정하다", "1년 이상 계속 운영한다" 가 나오면 답은 대개 이쪽이다.

## ⚙️ 작동 원리

할인이 붙으려면 조건이 맞아야 한다. AWS 는 인스턴스 타입·리전·테넌시·플랫폼 네 가지 속성으로 가격이 정해지고, 그 속성에 맞는 온디맨드 인스턴스가 돌고 있을 때 할인이 붙는다고 적는다. Azure 도 구매할 때 고른 SKU·지역·범위에 맞는 사용량에 할인이 자동으로 적용된다고 적는다. 기계를 켜 주는 것이 아니라, 켜져 있는 기계의 청구서에 붙는 것이다.

깎이는 폭을 정하는 손잡이는 셋이다. **기간**은 1년이나 3년이고 3년이 더 깎인다. **선결제**는 전액 선결제·일부 선결제·선결제 없음 셋이며, AWS 는 대체로 선결제를 많이 할수록 더 아낀다고 적는다. **종류**는 Standard 와 Convertible 로, Standard 가 더 깎이지만 교환이 안 되고 Convertible 은 덜 깎이는 대신 다른 조건으로 바꿀 수 있다.

만료되면 자동으로 갱신되지 않는다. AWS 문서는 만료 뒤에도 인스턴스는 끊기지 않고 그대로 돌지만 온디맨드 요금이 다시 붙는다고 적는다. 그리고 산 뒤에는 취소할 수 없다 — 조건이 바뀌면 수정·교환·재판매를 시도하는 것이 전부다. AWS 는 요즘 특정 구성 대신 시간당 금액을 약속하는 Savings Plans 를 먼저 권한다.

## 💡 실제 사례

- **바닥 사용량만 묶는다** — 1년 내내 켜 두는 최소 대수만 약정하고, 오르내리는 몫은 정가나 [[Spot Instance]] 로 채운다.
- **약정이 끝난 달** — 만료돼도 기계는 안 끊기고 그대로 돈다. 청구서만 조용히 정가로 돌아가서, 안 보고 있으면 몇 달이 지난다.
- **덮이지 않는 항목을 따로 본다** — Azure 의 가상 머신 예약은 컴퓨팅 비용만 덮는다. 소프트웨어·네트워킹·저장 비용은 따로 청구된다.

## 🚫 흔한 오해

- **예약을 사면 그 기계가 잡혀 있거나 켜진다** — 예약은 청구서에 붙는 할인이다. 조건이 맞는 자원이 실제로 돌고 있어야 할인이 붙는다.
- **길게 묶을수록 무조건 이득이다** — 3년이 더 깎이는 것은 맞지만 그 사이에 안 써도 돈은 나간다. AWS 는 구매 뒤 취소가 안 된다고 적는다.
- **약정은 언제나 정가보다 낫다** — 몇 달 뒤에 끌 자리라면 정가가 싸고, 끊겨도 되는 일이라면 남는 자리가 더 싸다.

## 📝 정리

**"오래 쓰겠다는 약속을 값으로 바꾼 것"** 이라고 읽으면 된다. 잡히는 것은 기계가 아니라 청구서에 붙는 할인이라, 조건이 맞는 자원이 돌고 있어야 붙는다. 1년이나 3년을 묶는 대가로 값을 깎는 것이므로 그만큼 계속 쓸 바닥 사용량에만 건다.

## 🧒 열 살에게

수영장에 갈 때마다 표를 한 장씩 사면 비싸지? 그런데 1년 치를 미리 끊으면 한 번 갈 때 값이 훨씬 싸져. 대신 중간에 안 가고 싶어져도 낸 돈은 안 돌아오니까, 진짜 계속 갈 때만 끊는 거야.

## ❓ 이해했는지

- 예약을 샀는데 할인이 하나도 안 붙는 일은 왜 생기나 → 작동 원리
- 늘 켜 두는 몫과 오르내리는 몫을 왜 다른 방식으로 사나 → 실제 사례
- 1년을 다 못 채울 것 같으면 무엇을 먼저 따져야 하나 → 흔한 오해
