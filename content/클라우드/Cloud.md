# Cloud (클라우드)

## 📝 정의

Cloud는 **컴퓨터 자원을 필요한 만큼 빌려 쓰는 방식**이다.

서버와 저장소를 사서 두는 대신, 남이 갖춰둔 것을 인터넷 너머로 쓰고 쓴 만큼 낸다. 필요 없어지면 반납하고 그 순간부터 요금도 멈춘다.

### 비유
전기. 발전기를 집에 두지 않고 쓴 만큼 요금을 낸다.

### 예
휴대폰을 바꿔도 사진이 그대로 따라오고, 용량이 차면 매달 얼마씩 내고 늘리는 그 저장 공간이다.

## 🖼️ 그림으로 보기

```도해
층: 어디까지 빌리고 어디부터 내가 하나
SaaS :: 완성된 소프트웨어. 계정만 만들면 끝
PaaS :: 코드 올릴 자리까지. 실행은 맡긴다
IaaS :: 서버와 저장소만. 그 위는 내가 올린다
직접 운영 :: 기계를 사서 전원까지 내가 관리한다
= 위로 갈수록 맡기는 범위가 넓고 손댈 수 있는 범위는 좁다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버를 직접 사서 두면 어떻게 되나
직접 사면 || 빌려 쓰면
시작 :: 사고 설치해야 || 몇 분이면 뜬다
사용량 급증 :: 증설까지 몇 주 || 즉시 늘린다
놀 때 :: 비용 그대로 || 줄이면 준다
= 자원을 미리 사두는 문제를 쓴 만큼 내는 문제로 바꾼다
```

서버를 직접 사려면 얼마나 필요할지를 미리 맞혀야 한다. 넉넉히 잡으면 대부분의 시간 동안 놀고, 빠듯하게 잡으면 사람이 몰릴 때 버티지 못한다. 어느 쪽이든 결정은 몇 년치를 미리 거는 일이 된다.

클라우드는 그 결정을 나중으로 미룬다. 지금 필요한 만큼만 켜고 부족하면 그때 늘린다. 대신 계속 최대치로 돌아가는 서비스는 빌리는 값이 사는 값보다 비싸질 수 있다.

## ⚙️ 작동 원리

한 대의 물리 서버 위에 여러 개의 가상 서버를 올려 나눠 쓰는 것이 바탕이다. 그래서 "서버 하나 더"가 기계를 들이는 일이 아니라 설정 한 번으로 끝난다.

같은 서비스가 여러 지역의 데이터센터에 나뉘어 있고, 한 지역 안에서도 전력과 네트워크가 분리된 구역으로 다시 나뉜다. 서버를 두 구역에 걸쳐 두면 한쪽에 사고가 나도 서비스가 남는다.

## 📊 비교

| | 클라우드 | 온프레미스 |
|---|---|---|
| 초기 비용 | 낮다 | 높다. 서버를 산다 |
| 운영 비용 | 사용량에 따라 | 고정. 전기와 인건비 |
| 확장 | 설정으로 즉시 | 장비를 들여야 한다 |
| 관리 | 제공자가 한다 | 직접 한다 |

## 💡 실제 사례

- **트래픽이 몰리는 행사** — 며칠간 서버 수를 늘렸다가 끝나면 원래대로 줄인다.
- **테스트 환경** — 운영과 같은 구성을 잠깐 만들어 쓰고 검증이 끝나면 통째로 지운다.
- **백업 보관** — 잘 안 꺼내는 파일을 값싼 저장소에 두고 필요할 때만 꺼낸다.

## 🚫 흔한 오해

- **클라우드는 무조건 싸다** — 하루 종일 최대치로 도는 서비스는 직접 사는 편이 쌀 때가 많다. 싸지는 것은 쓰는 양이 오르내릴 때다.
- **클라우드에는 서버가 없다** — 남의 서버다. 어딘가의 데이터센터에서 도는 기계 위에 있고, 그 데이터센터에 사고가 나면 내 서비스도 멈춘다.
- **올리기만 하면 알아서 확장된다** — 자동 확장은 따로 켜고 조건을 적어야 동작한다. 그냥 올려두면 사람이 몰릴 때 그대로 죽는다.

## 📝 정리

Cloud는 서버와 저장소를 사서 두는 대신 필요한 만큼 빌려 쓰는 방식이다. 미리 맞혀야 했던 용량 결정을 나중으로 미루는 대신, 계속 최대로 쓰는 경우에는 값이 더 나갈 수 있다.
