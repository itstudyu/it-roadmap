# AWS (Amazon Web Services)

## 📝 정의

AWS는 **서버와 저장소를 빌려 쓰는 클라우드 묶음**이다.

Amazon이 운영하는 클라우드 서비스 제공자이고, 30개가 넘는 리전과 90개가 넘는 가용 영역에 장비를 두고 있다. 쓰는 쪽은 장비를 사지 않고 필요한 만큼 빌려 쓴다.

### 비유
장비 대여점. 촬영에 쓸 카메라와 조명을 사들이는 대신 쓰는 동안만 빌리고 끝나면 반납한다.

## 🖼️ 그림으로 보기

```도해
흐름: 웹 서비스 하나를 올리려면 무엇을 빌리나
리전 :: 서비스를 둘 지역을 고른다. 서울이면 서울
EC2 :: 앱이 돌아갈 가상 서버를 띄운다
RDS :: 데이터를 담을 데이터베이스를 붙인다
S3 :: 이미지와 정적 파일을 올린다
< 사용자 :: 붙인 도메인으로 들어와 화면을 받는다
= 서버 한 대를 사는 대신 필요한 조각만 하나씩 빌려 끼운다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버를 직접 장만하면 무엇이 걸리나
직접 장만 || AWS 로
준비 기간 :: 주문하고 몇 주 || 몇 분이면 뜬다
초기 비용 :: 미리 다 낸다 || 쓴 만큼 낸다
트래픽 급증 :: 장비를 더 산다 || 대수를 늘린다
= 장비를 소유하는 일을 빌리는 일로 바꾼 것이다
```

서버를 직접 사면 얼마나 필요할지를 미리 맞혀야 한다. 적게 사면 트래픽이 몰릴 때 못 버티고, 넉넉히 사면 평소에 놀린다. 게다가 주문해서 들어오기까지 시간이 걸린다.

AWS는 그 판단을 나중으로 미룬다. 일단 작게 띄우고 부족하면 그때 늘린다. 남는 장비를 껴안고 있지 않아도 되는 대신, 켜둔 것은 안 써도 계속 청구된다.

## ⚙️ 작동 원리

이름이 많지만 갈래는 몇 안 된다. 계산은 EC2와 Lambda, 저장은 S3와 EBS가 맡는다. 데이터베이스는 관계형인 RDS와 NoSQL인 DynamoDB로 나뉜다. 여기에 접근 권한을 정하는 IAM과 지표를 모으는 CloudWatch가 붙는다.

```도해
층: 사용자의 요청은 AWS 안 어디까지 들어오나
Route 53 :: 도메인을 받아 어느 IP 로 갈지 알려준다
CloudFront :: 캐시된 이미지와 파일은 여기서 끝난다
EC2 :: 화면을 만들어야 하는 요청만 여기까지 온다
RDS :: 값을 꺼내야 할 때만 마지막으로 열린다
= 안쪽으로 갈수록 느리고 비싸다. 바깥에서 끝낼수록 좋다
```

## 💡 실제 사례

- **작게 시작하는 서비스** EC2 한 대와 RDS 하나로 띄우고, 사용자가 늘면 인스턴스 크기만 올린다.
- **정적 파일 분리** 이미지와 JS를 S3에 올리고 CloudFront로 내보내 서버는 화면 조립만 하게 둔다.
- **가끔 도는 작업** 하루에 몇 번만 도는 처리를 Lambda로 옮겨 서버를 띄워두지 않는다.

## 🚫 흔한 오해

- **AWS를 쓰면 서버 관리가 없어진다** — EC2는 가상 서버를 빌리는 것이라 OS 패치와 보안 설정을 여전히 직접 해야 한다. 관리가 줄어드는 쪽은 Lambda 같은 서버리스다.
- **클라우드는 무조건 싸다** — 쓴 만큼 낸다는 말은 안 쓰면 싸다는 뜻이지 늘 싸다는 뜻이 아니다. 켜두고 잊은 인스턴스는 그대로 청구된다.
- **계정 하나면 어디서나 같은 자원을 본다** — 자원은 리전마다 따로 논다. 서울에서 만든 S3 버킷은 다른 리전 목록에 나오지 않는다.

## 🚨 주의사항

- **IAM 권한을 넓게 열어두지 않는다.** 키 하나가 새면 열어둔 범위 전부가 열린다.
- **안 쓰는 자원을 지운다.** 멈춘 인스턴스에 붙은 디스크와 고정 IP는 따로 요금이 붙는다.

## 📝 정리

AWS는 장비를 사는 대신 빌려 쓰게 만든 서비스 묶음이다. 계산과 저장과 데이터베이스를 조각으로 나눠 팔고, 필요한 조각만 골라 끼우면 서비스가 된다. 빌린 것이라 관리가 줄어드는 부분이 있지만, 빌린 서버 안쪽은 여전히 쓰는 쪽 몫이다.

- 사용자 요청이 RDS까지 안 오고 앞에서 끝나면 무엇이 좋아지나?
