# Elastic IP (탄력적 IP)

## 📝 정의

Elastic IP는 **계정이 쥐고 옮겨 붙이는 고정 공인 주소**다.

그냥 붙는 공인 주소는 자원에 딸려 있다. Azure 문서는 이 갈림을 동적 할당과 정적 할당으로 부르는데, 동적으로 받은 주소는 자원을 멈추거나 지우면 회수되고 다시 켜면 다른 주소가 붙는다. 탄력적 IP 는 반대다 — 내가 명시적으로 반납하기 전까지 계정 앞으로 남아 있고, 그 주소를 어느 자원에 붙일지는 내가 정한다.

### 이름
Elastic :: 옮겨 붙는
IP :: 인터넷 주소
= 붙여 읽으면 "옮겨 붙일 수 있는 주소". 주소가 변한다는 뜻이 아니라 주소는 그대로 두고 붙는 자리를 바꾼다는 뜻이다

### 비유
가게 간판에 적어 둔 전화번호. 안에서 전화기를 새것으로 바꿔 꽂아도 손님이 거는 번호는 그대로다.

### 예
거래처에 "우리 쪽은 이 주소 하나로만 나갑니다" 하고 알려 준 그 주소가 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 서버를 갈아 끼워도 바깥이 왜 같은 주소로 닿나
주소 받기 :: 계정 앞으로 고정된 공인 주소 하나를 받아 둔다
붙이기 :: 서버의 네트워크 인터페이스에 그 주소를 붙인다
서버 정지 :: 서버가 멈춰도 주소는 계정에 그대로 남는다
옮겨 붙이기 :: 같은 주소를 새 서버에 다시 붙인다
바깥 :: 상대 방화벽도 주소록도 고칠 것이 없다
= 주소는 계정이 쥐고 있고, 그 주소가 가리키는 기계만 바뀐다
```

## ⚠️ 해결하는 문제

```도해
대조: 주소가 기계에 딸려 있으면 무엇이 곤란한가
기계에 딸린 주소 || 계정이 쥔 주소
껐다 켜면 :: 주소가 바뀐다 || 그대로 남는다
서버 교체 :: 새 주소를 알린다 || 옮겨 붙이면 끝
상대 방화벽 :: 매번 고쳐야 || 한 번 열면 끝
= 바깥이 아는 주소와 안에서 도는 기계를 떼어 놓는 것이다
```

공인 주소가 기계에 딸려 있으면 기계를 갈아 끼울 때마다 주소가 바뀐다. 바뀐 주소는 나 혼자 아는 것으로 끝나지 않는다. 상대 회사 방화벽의 허용 목록, 주소로 묶어 둔 인증서, 주소를 가리키는 레코드가 전부 그 주소를 붙들고 있다.

탄력적 IP 는 주소를 계정 쪽으로 옮겨 놓는다. 기계가 죽으면 같은 주소를 다른 기계에 다시 붙여 장애를 가린다. 바깥에서 보기에는 같은 주소가 계속 응답하고, 안에서는 기계를 몇 번이고 갈아 끼울 수 있다.

## ⚙️ 작동 원리

주소는 인스턴스가 아니라 **네트워크 인터페이스의 속성**이다. 인터페이스째 다른 인스턴스로 옮기면 거기 달린 설정이 한 번에 같이 넘어가기 때문에, 문서도 인스턴스에 직접 붙이는 것보다 이 방식을 권한다.

한 주소는 한 번에 하나의 인스턴스나 인터페이스에만 붙는다. 주 인터페이스에 탄력적 IP 를 붙이면 원래 있던 공인 주소는 풀로 회수되고, 나중에 떼면 몇 분 안에 새 공인 주소가 다시 붙는다. 기본 할당량은 다섯 개이며, 문서는 아껴 쓰라면서 밖으로 나가는 통로가 필요할 뿐이라면 NAT 장치를 쓰라고 적는다.

## 💡 실제 사례

- **상대 방화벽 허용 목록** — 우리 쪽 출발지 주소를 하나로 고정해 상대가 그 주소만 열게 한다.
- **장애 시 대체** — 인스턴스가 죽으면 같은 주소를 다른 인스턴스에 옮겨 붙여 바깥에서 보이는 끝점을 유지한다.
- **주소로 묶인 설정** — 주소를 가리키는 레코드나 주소에 묶인 인증서가 있으면, 기계가 바뀌어도 그 설정을 안 건드려도 된다.

## 🚫 흔한 오해

- **탄력적이라니까 주소가 늘었다 줄었다 하나 보다** — 반대다. 주소 자체는 고정이고, 탄력적인 것은 그 주소를 어느 자원에 붙일지다.
- **잡아만 두고 안 쓰면 공짜다** — 공인 주소는 붙여 쓰는 것에도 값이 붙고, 아무 데도 안 붙였거나 꺼진 자원에 붙어 있는 주소는 유휴 주소로 따로 세어 잡힌다. 안 쓸 주소는 반납한다.
- **서버마다 하나씩 붙여 두면 편하다** — 기본 다섯 개 제한이 있고, 밖으로 나가기만 하면 되는 서버라면 NAT 장치 하나로 충분하다. 여러 대에 트래픽을 나누는 일은 로드 밸런서의 몫이다.

## 🚨 주의사항

- **리전 밖으로는 못 가져간다.** 탄력적 IP 는 리전에 매인 주소다. 리전을 넘나드는 고정 주소가 필요하면 그런 용도의 다른 수단을 봐야 한다.
- **IPv6 에는 없다.** 탄력적 IP 는 IPv4 전용이다.
- **주소가 있다고 열리는 것은 아니다.** 바깥에서 그 주소로 닿으려면 보안 그룹과 네트워크 ACL 이 허용해야 하고, 돌아나가는 길에는 인터넷 게이트웨이가 있어야 한다.

## 📝 정리

**"내가 쥐고 옮겨 다니는 그 고정 주소"** 라고 읽으면 된다. 주소는 계정에 남고 그것이 가리키는 기계만 바뀌니 바깥에 알린 주소를 건드리지 않고 안을 갈아 끼울 수 있다. 잡아만 두고 안 쓰는 주소에도 요금이 붙는다는 것을 같이 외워 둔다.

## 🧒 열 살에게

가게 간판에 적힌 번호는 그대로인데 안에서 전화기만 새것으로 바꿔 꽂는다고 해 봐. 손님은 늘 같은 번호로 걸고, 누가 받는지만 조용히 바뀌는 거야. 그래서 전화기가 고장 나도 손님한테 새 번호를 알릴 일이 없어.
