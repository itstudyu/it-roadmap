# Offline Bulk Data Transfer (장비로 실어 나르는 대량 전송)

## 📝 정의

Offline Bulk Data Transfer 는 큰 자료를 **선 대신 차로** 옮기는 방법이다.

클라우드 회사가 저장 장비를 택배로 보내 주면, 회사 안 망으로 거기에 자료를 붓고, 잠근 채로 되돌려 보내고, 데이터센터에서 통으로 옮겨 담는다. AWS 는 Snowball 계열, Azure 는 Data Box, Google Cloud 는 Transfer Appliance 라는 이름으로 이 일을 판다. 용량이 커지면 트럭이 인터넷보다 빠르다는, 농담처럼 들리지만 계산해 보면 맞는 이야기다.

### 이름
Offline :: 선을 안 타고
Bulk :: 한꺼번에 많이
Data :: 옮길 자료
Transfer :: 옮기기
= 붙여 읽으면 "선을 안 타고 한꺼번에 많이 옮기기". 옮기는 길이 인터넷이 아니라 도로다

### 비유
책 만 권을 한 권씩 들고 왕복하는 대신 한 번 부르는 이삿짐 트럭.

### 예
사진 몇백 장 올리는 데도 업로드 막대가 한참 돌던 걸 떠올려 보면, 옮길 것이 300테라일 때 무슨 일이 나는지 짐작이 된다.

## 🖼️ 그림으로 보기

```도해
흐름: 선으로 못 보낼 만큼 큰 자료는 어떻게 옮기나
신청 :: 장비를 보내 달라고 주문한다
붓기 :: 회사 안 망으로 그 장비를 채운다
배송 :: 잠긴 장비를 택배로 되돌려 보낸다
올리기 :: 데이터센터에서 통으로 옮겨 담는다
지우기 :: 장비의 저장 장치를 규격대로 지운다
= 옮기는 시간을 정하는 건 거리가 아니라 용량이다
```

## ⚠️ 해결하는 문제

```도해
대조: 100메가 선으로 300테라를 보내면 무엇이 달라지나
선으로만 보내면 || 장비로 실어 나르면
걸리는 시간 :: 아홉 달쯤 걸린다 || 한 달 안에 끝난다
그동안 망 :: 다른 일이 느려진다 || 회사 망만 쓴다
중간에 끊기면 :: 처음부터 다시 || 그런 일이 없다
= Google 문서의 숫자다 — 같은 300테라가 선으로는 아홉 달, 장비로는 25일 안쪽이다
```

인터넷으로 올리는 시간은 용량 나누기 대역폭이다. 이 나눗셈은 자릿수가 커지면 사람의 직관을 배신한다. 100메가 선은 하루에 1테라 남짓을 겨우 올리므로 300테라는 계산상 아홉 달이다. 그동안 그 선으로 하는 다른 일은 다 느려지고, 중간에 한 번 끊기면 이어 올리기가 되는지부터 확인해야 한다.

장비를 부르면 이 나눗셈이 바뀐다. 붓는 것은 회사 안 망에서 하므로 인터넷 회선과 무관하고, 옮기는 시간은 택배가 걸리는 며칠이 전부다. 그래서 이 방법은 대개 **처음 한 번**에 쓴다. 큰 덩어리는 장비로 옮겨 씨를 뿌려 두고, 그 뒤에 생기는 자잘한 변화만 선으로 따라 올린다.

## ⚙️ 작동 원리

고르는 기준은 용량 자체가 아니라 "지금 이 선으로 며칠 걸리나" 다.

```도해
층: 옮길 것이 얼마나 크면 어느 길을 고르나
몇 기가 :: 그냥 올린다. 몇 분에서 몇 시간
몇 테라 :: 전송 도구로 밤새 올린다. 며칠
수십 테라 :: 선이 좁으면 장비를 부른다. 40테라가 갈림길
수백 테라 :: 장비가 확실히 빠르다. 선으로는 달 단위
= 재는 것은 크기가 아니라 걸리는 날수다. 일주일이 넘으면 장비 쪽이다
```

Azure 문서는 Data Box 가 **40테라를 넘고 망이 없거나 좁은 경우**에 잘 맞는다고 적고, Google 문서는 인터넷으로 올리는 데 일주일이 넘게 걸린다면 장비를 쓰라고 적는다.

붓는 속도는 회사 안 망이 정한다. 장비는 10기가·40기가·100기가 이더넷 같은 빠른 포트를 달고 오지만, 원본 저장소나 사내 망이 못 따라가면 장비는 안 찬 채로 돌아간다. 붓는 데만 며칠이 걸린다고 잡아 두는 편이 맞다.

가는 동안의 안전은 세 가지로 지킨다. 저장된 자료는 AES 256비트로 잠겨 있고, 상자에는 훼손이 보이는 봉인과 특수 나사가 붙고, 열쇠는 장비에 같이 들어가지 않는다. Azure 는 포털에서 받은 비밀번호로만 열리게 하고, Google 은 고객이 쥔 열쇠를 쓰게 한다. 다 올린 뒤에는 NIST 800-88 규격대로 장치를 지운다.

## 📊 비교: 세 클라우드는 무엇을 보내 주나

| | AWS | Azure | Google Cloud |
|---|---|---|---|
| 장비 이름 | Snowball Edge | Data Box | Transfer Appliance |
| 담기는 양 | 스토리지 최적화 210TB | 120TB · 525TB(쓸 수 있는 양) | TA40 · TA300 |
| 붓는 포트 | 최대 100Gbit/s | 10GbE · 100GbE | 10G · 40G · 100G |
| 잠금 | 저장 중·이송 중 암호화가 강제된다 | AES-256, 포털이 준 비밀번호로만 열린다 | AES-256, 열쇠를 고객이 쥔다 |
| 다 쓴 뒤 | 반납 | NIST 800-88r1 대로 지운다 | NIST 800-88 대로 지운다 |
| 지금 상태 | 신규 고객에게는 안 판다. 온라인은 DataSync, 물리 전송은 Data Transfer Terminal 로 안내한다 | 판다 | 판다 |

## 💡 실제 사례

- **데이터센터 철수** — 수백 테라짜리 옛 저장소를 통째로 실어 보내고, 그 뒤 바뀐 것만 선으로 따라 올린다.
- **선이 없는 현장** — 배나 시추선, 촬영 현장처럼 회선이 없는 곳에서 쌓인 영상을 주기적으로 실어 보낸다.
- **되가져오기** — 재해 복구나 규정 때문에 클라우드에 있는 것을 사내로 내려받을 때도 같은 장비를 반대 방향으로 쓴다.

## 🚫 흔한 오해

- **아무리 커도 인터넷이 트럭보다는 빠르다** — 용량이 커지면 뒤집힌다. Google 문서는 100메가 선으로 300테라를 올리면 아홉 달, 장비로는 25일 안쪽이라고 적는다.
- **택배로 보내니 위험하다** — 자료는 저장된 채로 잠겨 있고 상자에는 훼손이 보이는 봉인이 붙으며, 다 올린 뒤에는 규격대로 지운다. 열쇠는 장비와 따로 다닌다.
- **한 번 실어 보내면 그걸로 끝이다** — 대개 첫 대량만 장비로 보내고 그 뒤의 변화는 선으로 올린다. Azure 문서도 이 방식을 초기 대량 전송이라 부른다.

## 🚨 주의사항

- **왕복 날짜를 일정에 넣어라.** Google 문서는 붓는 데 25일 안쪽, 그 뒤 통에 올라오기까지 열 영업일쯤이 더 걸린다고 적는다. 마감이 빠듯하면 이 방법이 오히려 느리다.
- **국경을 넘지 못한다.** Azure 문서는 장비 자체를 상거래 경계 밖으로는 배송하지 않는다고 적는다. 자료는 클라우드 망을 타고 다른 나라 리전으로 갈 수 있지만 상자는 그 나라 안에서만 오간다.
- **붓는 쪽이 병목이다.** 장비 포트가 100기가여도 원본 저장소와 사내 망이 못 따라가면 그 속도는 안 나온다.

## 📝 정리

**"선이 좁으면 트럭이 빠른 그 방법"** 이라고 읽으면 된다. 고를 때 보는 숫자는 용량이 아니라 지금 선으로 며칠 걸리느냐이고, 일주일이 넘으면 장비 쪽이다. 다만 왕복에 몇 주가 드니 급한 복구용이 아니라 이사용이라는 것도 같이 기억해야 한다.

## 🧒 열 살에게

옆 동네로 책 만 권을 옮긴다고 해 봐. 한 권씩 손에 들고 왔다 갔다 하면 몇 달이 걸리지만, 트럭을 한 번 불러서 다 싣고 가면 하루면 끝나. 짐이 아주 많을 때는 길이 좁을수록 차로 나르는 게 빨라.
