# Cloud Migration (클라우드 마이그레이션)

## 📝 정의

클라우드 마이그레이션은 **쓰던 것을 클라우드로 옮겨 가는 일**이다.

Google 문서는 이 일을 평가·계획·배포·최적화 네 단계로 나눈다. AWS 문서는 옮길 것 하나하나에 어떤 방식을 쓸지를 일곱 가지(7 Rs)로 정리해 두고, 그중 둘은 아예 안 옮기는 선택이다.

### 이름
Cloud :: 남의 기계 위
Migration :: 옮겨 살기
= 붙여 읽으면 "남의 기계 위로 옮겨 살기". 새로 짓는 일이 아니라 살던 것을 옮기는 일이다

### 비유
이사. 짐을 그대로 쌀지, 버릴지, 새로 살지를 짐마다 따로 정한다.

### 예
옮길 목록을 뽑다가 평균 사용률이 5% 도 안 되는 애플리케이션이 줄줄이 나오는 그 순간이다.

## 🖼️ 그림으로 보기

```도해
흐름: 쓰던 것은 어떤 순서로 클라우드에 옮겨 가나
평가 :: 무엇이 있고 무엇과 얽혀 있는지 센다
계획 :: 받을 자리를 먼저 만든다. 계정·망·조직 구조
배포 :: 짐마다 정한 방식대로 실제로 옮긴다
최적화 :: 옮긴 뒤에 클라우드 방식으로 고쳐 쓴다
= 옮기는 일은 세 번째다. 세는 일이 먼저고 고치는 일이 나중이다
```

## ⚠️ 해결하는 문제

```도해
대조: 방식을 안 정하고 통째로 옮기면 무엇이 잘못되나
통째로 옮기면 || 짐마다 골라서
안 쓰는 것 :: 같이 옮겨 간다 || 거기서 끈다
급한 것 :: 다 같이 멈춘다 || 먼저 옮겨 돌린다
고치는 시점 :: 옮기며 같이 고친다 || 옮긴 뒤에 고친다
= 이 일의 알맹이는 옮기는 것이 아니라 짐마다 무엇을 할지 정하는 것이다
```

옮기기 전 환경은 목록으로 정리되어 있는 경우가 드물다. 무엇이 도는지는 알아도 무엇이 무엇에 붙어 있는지는 잘 안 적혀 있다. 그래서 Google 문서는 첫 단계를 애플리케이션 재고 조사와 의존 관계 파악으로 둔다. 세지 않고 옮기면 옮기는 도중에 그것이 튀어나온다.

방식을 안 정하고 통째로 옮기는 것도 같은 문제다. 안 쓰는 것까지 같이 옮겨 요금만 늘고, 정작 급한 것은 뒤에 밀린다. AWS 문서가 일곱 가지 방식을 나눠 둔 이유가 여기 있다 — 짐마다 답이 다르다.

## 📊 비교: 옮기는 방식 일곱 가지는 무엇이 다른가

| 방식 | 무엇을 하나 | 언제 고르나 |
|---|---|---|
| **폐기 (Retire)** | 끄고 없앤다 | 쓰는 사람도 값어치도 없다 |
| **유지 (Retain)** | 아직 안 옮긴다 | 규제·의존 관계·최근 투자 |
| **재호스팅 (Rehost)** | 손 안 대고 옮긴다 | 수가 많고 빨라야 한다 |
| **재배치 (Relocate)** | 플랫폼째 옮긴다 | 구조를 안 건드리고 통째로 |
| **재구매 (Repurchase)** | 파는 제품으로 바꾼다 | 대체할 SaaS 가 있다 |
| **리플랫폼 (Replatform)** | 조금 고쳐 옮긴다 | 관리형으로 바꿔 운영을 줄인다 |
| **리팩터 (Refactor)** | 구조를 다시 짠다 | 지금 구조가 발목을 잡는다 |

## 💡 실제 사례

- **옮길 목록 만들기** — 평균 사용률이 바닥인 것은 옮기지 말고 거기서 끄는 쪽이 답이다.
- **규제가 걸린 것** — 데이터가 있어야 할 나라가 정해져 있으면 그대로 두는 유지가 정식 선택지다.
- **관리형으로 갈아타기** — 직접 굴리던 SQL Server 를 관리형 데이터베이스로 옮긴다. 옮기고 나면 패치와 백업이 제공자 칸으로 넘어간다.

## 🚫 흔한 오해

- **옮기는 김에 같이 고치는 게 이득이다** — AWS 문서는 대규모 이전에서 리팩터를 권하지 않는다. 가장 복잡하고 비싸니 먼저 옮기고 나중에 현대화하라고 적는다.
- **옮겨 놓으면 끝이다** — Google 문서는 네 단계의 마지막을 최적화로 둔다. 옮긴 모양 그대로면 클라우드의 값어치를 못 쓴다.
- **전부 옮기는 것이 목표다** — 일곱 가지 중 둘은 안 옮기는 선택이다. 끄는 것과 그대로 두는 것도 정답이 된다.

## 🚨 주의사항

- **평가를 건너뛰지 않는다.** 첫 단계가 재고 조사와 의존 관계 파악인 이유는 옮기는 도중에 그것이 튀어나오기 때문이다.
- **받을 자리를 먼저 만든다.** 계정 구조·망·권한은 짐이 도착하기 전에 서 있어야 한다.
- **대규모 이전에서 리팩터는 마지막 수단이다.** 다른 방식이 다 안 될 때만 고른다고 적혀 있다.

## 📝 정리

**"짐마다 어떻게 할지 정해서 옮기는 이사"** 라고 읽으면 된다. 세고, 받을 자리를 만들고, 옮기고, 그다음에 고치는 네 걸음이고, 짐마다 고를 수 있는 방식이 일곱 가지다. 그중 둘은 안 옮기는 선택이라, "전부 올렸다" 가 아니라 "짐마다 왜 그 방식인지 말할 수 있다" 가 잘한 이전이다.

## 🧒 열 살에게

이사 갈 때 짐을 다 싸 가지는 않지? 안 쓰는 건 버리고, 낡은 건 새로 사고, 멀쩡한 건 그대로 싸서 옮겨. 짐마다 어떻게 할지 먼저 정하는 게 진짜 이사 준비야.
