# Container Registry (컨테이너 레지스트리)

## 📝 정의

Container Registry 는 컨테이너 이미지를 **모아 두고 나눠 주는 곳**이다.

이미지는 앱과 그것을 돌리는 데 필요한 것을 한 덩어리로 굳혀 놓은 판이다. 만드는 자리와 도는 자리가 다르니 그 사이에 판을 둘 창고가 필요하다. Docker Hub 가 누구나 쓰는 공개 레지스트리이고, AWS 의 ECR 과 Azure Container Registry 가 클라우드가 파는 사설 레지스트리다.

### 이름
Container :: 앱을 통째로 담은 상자
Registry :: 등록해 두는 장부
= 붙여 읽으면 "상자를 등록해 두는 장부". 받아 두고 이름으로 내주는 곳이다

### 비유
도서관. 누가 쓴 책이든 청구기호를 붙여 꽂아 두면, 빌리는 사람은 그 기호만 대고 언제 와도 같은 책을 받아 간다.

### 예
docker pull nginx 를 쳤을 때 아무 설정도 안 했는데 어딘가에서 파일이 내려오는 그 순간이다. 기본 레지스트리가 Docker Hub 라서 그렇다.

### 직접
Docker Hub 웹사이트에서 nginx 를 검색해 보라. 거기 늘어선 태그 목록이 그 저장소에 꽂혀 있는 판의 목록이다.

## 🖼️ 그림으로 보기

```도해
흐름: 내가 만든 이미지는 어떻게 남의 서버에서 도나
빌드 :: 이미지를 만들고 태그를 붙인다
로그인 :: 레지스트리에 자격을 증명한다
푸시 :: 만든 판을 레지스트리에 올린다
저장소 :: 같은 이름의 판들을 태그로 갈라 둔다
< 노드 :: 태그를 대고 받아 컨테이너를 띄운다
= 만드는 자리와 도는 자리 사이에 놓인 창고다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버마다 이미지를 따로 만들면 무엇이 달라지나
서버마다 만들면 || 레지스트리에서
같은 판인가 :: 서버마다 다르다 || 어디서나 같다
새 서버 :: 처음부터 만든다 || 받아서 띄운다
되돌리기 :: 다시 만들어야 || 옛 태그를 받는다
= 한 번 만든 판을 한곳에 두고 여럿이 같은 것을 받아 가게 하는 자리다
```

같은 소스라도 만드는 기계가 다르면 결과가 달라진다. 기반 이미지가 그새 바뀌었거나, 설치되는 꾸러미 판이 다르거나, 명령 순서가 조금 어긋나면 서버마다 다른 판이 돈다. 그러면 한 대에서만 나는 문제를 다른 데서 재현할 수 없다.

레지스트리는 판을 한 번만 만들고 그 판 자체를 옮긴다. 올릴 때 붙인 태그로 어느 판인지 부르고, 받아 가는 쪽은 이름만 대면 같은 것을 받는다. 되돌릴 때도 다시 만들지 않고 옛 태그를 받으면 된다.

## ⚙️ 작동 원리

레지스트리 안에는 저장소가 있고, 저장소 안에는 태그로 갈린 판들이 있다. Azure 문서는 저장소에 묶인 이미지 하나하나를 "읽기 전용 스냅숏" 이라고 적는다. 이미지는 층으로 이루어지고 한 번 만들어진 층은 바뀌지 않아서, 같은 층은 여러 이미지가 나눠 쓴다.

올리고 받으려면 먼저 자격을 증명해야 한다. AWS 문서는 사설 레지스트리에 로그인해야 푸시와 풀 명령을 쓸 수 있다고 적고, Azure 문서는 표준 도커 로그인이나 명령줄 도구로 인증한다고 적는다. 누가 무엇을 할 수 있는지는 계정 권한과 저장소 정책이 함께 정한다.

담기는 형식은 Open Container Initiative 규격이라 만드는 도구와 받는 쪽이 서로 달라도 통한다. 여기에 클라우드 레지스트리는 올릴 때마다 취약점을 검사하는 기능, 오래된 판을 자동으로 지우는 수명주기 규칙, 같은 판을 다른 리전에 복제해 두는 기능을 얹어 판다.

## 📊 비교: 공개 레지스트리와 사설 레지스트리

| | 공개 레지스트리 | 클라우드 사설 레지스트리 |
|---|---|---|
| 누가 받나 | 누구나 받아 간다 | 권한을 준 계정만 |
| 어디에 두나 | 인터넷 저편 | 배포할 리전 안에 만든다 |
| 딸린 기능 | 보관과 배포 | 취약점 검사·리전 복제·수명주기 규칙 |
| 고르는 자리 | 공개 기반 이미지를 받을 때 | 내 앱의 판을 올릴 때 |

## 💡 실제 사례

- **배포 자동화** — 코드가 합쳐지면 만들기와 올리기가 자동으로 돌고, 클러스터는 새 태그를 받아 띄운다.
- **올릴 때 검사** — 푸시할 때마다 취약점 검사를 돌려서 문제 있는 판이 배포까지 가지 않게 막는다.
- **리전 복제** — 같은 판을 배포할 리전마다 미리 복제해 두고, 각 리전의 노드가 가까운 쪽에서 받는다.

## 🚫 흔한 오해

- **레지스트리는 파일 저장소와 다를 게 없다** — 규격이 정해진 창고다. 이미지를 층으로 나눠 두고 같은 층을 여러 이미지가 나눠 쓰며, 올리고 받는 절차 자체가 규격으로 정해져 있다.
- **latest 를 받으면 늘 최신 판이다** — 태그를 안 적었을 때 붙는 기본 이름일 뿐이다. 태그는 다른 판을 가리키도록 옮길 수 있어서, 아무도 옮겨 주지 않으면 몇 년 전 판이 계속 latest 로 남는다.
- **레지스트리 하나만 두고 전 세계가 거기서 받으면 된다** — 받는 쪽에서 멀면 새 서버가 뜨는 데 그만큼 오래 걸리고, 그 하나가 멈추면 어느 리전에서도 새 판이 안 뜬다. 그래서 사설 레지스트리는 배포할 리전에 두고 리전 간 복제를 건다.

## 🚨 주의사항

- **태그를 덮어쓰지 못하게 잠근다.** 같은 태그에 새 판을 올리면 어제 받은 것과 오늘 받은 것이 달라진다. 태그 불변 설정을 켜거나 판마다 다른 태그를 붙인다.
- **안 쓰는 판을 치운다.** 수명주기 규칙을 걸어 두지 않으면 실패한 빌드까지 그대로 쌓여 보관 요금이 계속 오른다.
- **올리는 권한과 받는 권한을 나눈다.** 클러스터에는 받는 권한만 주고, 올리는 권한은 자동 배포 흐름에만 준다.

## 📝 정리

**"만든 판을 꽂아 두고 이름으로 내주는 그 창고"** 라고 읽으면 된다. 만드는 자리와 도는 자리를 갈라 놓은 덕에 한 번 만든 판을 여럿이 똑같이 받아 가고, 되돌릴 때도 옛 태그만 부르면 된다. 대신 태그는 그냥 이름이라 같은 태그에 새 판을 덮어쓰면 어제 받은 것과 오늘 받은 것이 달라진다.

## 🧒 열 살에게

도서관에 책을 꽂아 두면 누가 언제 오든 똑같은 책을 빌려 갈 수 있지? 네가 만든 것도 이름표를 붙여 거기 꽂아 두면, 멀리 사는 친구가 그 이름표만 대고 똑같은 걸 받아 가. 고친 것이 나와도 옛것을 빼지 않고 옆에 나란히 꽂아 둬서, 예전 것이 필요하면 그것도 그대로 빌릴 수 있어.

## ❓ 이해했는지

- 같은 소스로 만들었는데 서버마다 다른 판이 도는 일은 왜 생기나 → 해결하는 문제
- 아무나 이 판을 받아 가지 못하게 막는 것은 무엇인가 → 작동 원리
- 배포할 곳에서 먼 리전에 레지스트리를 두면 무엇이 손해인가 → 비교
