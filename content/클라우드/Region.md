# Region (리전)

## 📝 정의

Region은 **클라우드 업체가 한 지역에 세운 독립된 데이터센터 묶음**이다.

리전끼리는 수천 킬로미터 떨어져 있고 전원과 네트워크도 따로 쓴다. 그래서 한 리전에서 난 사고가 다른 리전으로 번지지 않고, 어느 리전에 두느냐가 곧 지연과 규제와 요금을 정한다.

### 비유
체인점의 지역 창고. 간판은 같아도 창고마다 재고가 따로라, 서울에 없는 물건이 부산에는 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 한국 사용자의 요청은 어디로 가나
사용자 :: 사이트 주소를 연다
DNS :: 접속 지역을 보고 리전을 고른다
서울 리전 :: 그 리전의 로드 밸런서가 받는다
서버 :: 같은 리전의 DB 에서 데이터를 읽는다
< 사용자 :: 가까운 곳에서 처리된 응답을 받는다
= 리전이 여럿이면 요청 하나는 가장 가까운 한 곳에서 끝난다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터센터 한 곳만 쓰면 어떻게 되나
한 리전만 || 여러 리전에
그 지역 사고 :: 서비스 멈춤 || 다른 곳이 받음
먼 나라 사용자 :: 왕복이 길다 || 가까운 곳에서
데이터 규제 :: 맞추기 어렵다 || 지역별로 저장
= 거리 때문에 나누기도 하고, 사고와 규제 때문에 나누기도 한다
```

한 곳에만 두면 그 지역에 생긴 일이 그대로 서비스의 사정이 된다. 지진이나 대규모 정전처럼 데이터센터 하나가 아니라 지역 전체가 멈추는 사고는 같은 지역 안에서 아무리 나눠 두어도 피할 수 없다.

거리도 마찬가지다. 지구 반대편 사용자에게는 회선을 오가는 시간만으로 이미 느린 서비스가 된다. 데이터를 그 나라 안에 두라는 규제가 걸리면 아예 선택지가 없어진다.

## ⚙️ 작동 원리

```도해
층: 리전을 고를 때 무엇부터 보나
규제 :: 데이터를 그 나라 안에 둬야 하는가
지연 :: 주 사용자와 얼마나 떨어져 있나
서비스 :: 쓰려는 기능이 그 리전에 있나
비용 :: 리전마다 요금이 다르다
= 위에서 걸리면 아래는 볼 필요가 없다. 규제는 협상 대상이 아니다
```

리전 안은 다시 가용 영역으로 나뉜다. 같은 지역 안의 서로 떨어진 데이터센터라, 여기에 나눠 두면 건물 한 곳의 사고는 견딘다. 지역 전체가 멈추는 사고를 견디려면 리전을 나눠야 한다.

리전이 여럿일 때 요청을 어디로 보낼지는 DNS가 정한다. 접속 지역에 따라 다른 리전의 주소를 돌려주고, 한 리전이 응답하지 않으면 다른 리전 주소로 바꿔 돌려준다. 이게 동작하려면 그쪽 리전에도 받을 것이 미리 올라가 있어야 한다.

데이터는 리전 사이로 복제한다. 저장소를 자동으로 복사해두거나 데이터베이스의 읽기 사본을 다른 리전에 두는 식이다. 복제에는 시차가 있어서 방금 쓴 것이 저쪽에서는 아직 안 보일 수 있다.

## 📊 비교: 리전과 그 아래 단위들

| | 리전 | 가용 영역 | 엣지 로케이션 |
|---|---|---|---|
| 크기 | 지역 하나 | 리전 안의 데이터센터 | 도시 단위 지점 |
| 떨어진 정도 | 수천 킬로미터 | 같은 지역 안 | 사용자 가까이 |
| 견디는 사고 | 지역 전체 | 건물 한 곳 | 해당 없음 |
| 리소스 | 리전마다 따로 만든다 | 리전 안에서 나눠 배치 | 캐시만 둔다 |

## 💡 실제 사례

- **재해 대비** — 다른 리전에 복제본을 두고, 주 리전이 응답하지 않으면 그쪽으로 넘긴다.
- **데이터 거주 규제** — 특정 국가 사용자의 개인정보는 그 지역 리전에만 저장한다.
- **요금 차이 활용** — 사용자와 실시간으로 주고받는 것은 가까운 리전에, 밤에 몰아 도는 작업은 요금이 낮은 리전에 둔다.

## 🚫 흔한 오해

- **리전 하나에 만들어두면 다른 리전에도 생긴다** — 리전마다 따로 만들어야 한다. 서울에서 만든 서버와 저장소는 도쿄 콘솔에서는 보이지도 않는다.
- **리전을 여러 개 쓰면 자동으로 장애에 강해진다** — 저쪽에 아무것도 없으면 넘어갈 곳이 없다. 복제와 전환 경로를 미리 만들어둔 만큼만 강해진다.
- **가용 영역을 나눠 뒀으니 리전 장애도 견딘다** — 가용 영역은 같은 지역 안에 있다. 그 지역 전체가 멈추는 사고는 리전을 나눠야 견딘다.

## 🚨 주의사항

- **리전 사이로 데이터를 옮기는 데는 요금과 시간이 든다.** 자주 오가도록 설계하면 청구서와 지연이 같이 올라간다.
- **복제에는 시차가 있다.** 방금 쓴 값을 다른 리전에서 바로 읽으면 옛 값이 나올 수 있어서, 어느 쪽을 기준으로 읽을지 정해야 한다.

## 📝 정리

Region은 클라우드 업체가 지역마다 따로 세운 독립된 인프라 묶음이다. 리소스는 리전마다 따로 만들어야 하고, 리전을 여럿 쓴다고 해서 저절로 이어지지는 않는다. 어디에 둘지는 규제와 거리와 요금이 함께 정한다.

## ❓ 이해했는지

- 서울 리전에서 만든 서버가 도쿄 리전 화면에서 안 보이는 이유는?
- 가용 영역을 여러 개 쓰는 것으로는 막을 수 없는 사고는 어떤 것인가?
- 리전 두 곳을 쓰는데도 한쪽이 멈췄을 때 서비스가 끊긴다면 무엇이 빠진 것인가?

- [[CDN]] — 리전보다 촘촘한 지점에 복사본을 두어 거리를 더 줄이는 쪽
