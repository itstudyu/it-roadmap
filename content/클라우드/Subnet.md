# Subnet (서브넷)

## 📝 정의

Subnet은 **큰 네트워크를 쪼개놓은 작은 구획**이다.

클라우드에서 네트워크를 하나 만들면 `10.0.0.0/16`처럼 넓은 주소 범위를 받는다. 이걸 통째로 쓰면 안에 있는 것들을 갈라놓을 방법이 없다. 서브넷은 그 범위를 여러 구획으로 나눠서 구획마다 다른 규칙을 붙일 수 있게 한다.

### 비유
건물의 층. 건물은 하나지만 층마다 출입 규칙이 다르고, 한 층에 문제가 생겨도 다른 층은 돌아간다.

## 🖼️ 그림으로 보기

```도해
흐름: 바깥에서 온 요청이 데이터베이스까지 어떻게 가나
인터넷 :: 요청이 들어온다
공개 구획 :: 인터넷 게이트웨이로 연결된 구획이다
웹 서버 :: 요청을 받아 처리하고 안쪽에 묻는다
비공개 구획 :: 바깥에서 직접 들어올 길이 없는 구획이다
< DB :: 웹 서버의 요청에만 답한다
= 바깥에 열어둘 것과 감출 것을 구획으로 갈라두는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 네트워크를 안 나누면 어떻게 되나
한 덩어리로 || 구획으로 나누면
보안 규칙 :: 전부에 똑같이 || 구획마다 다르게
DB 노출 :: 같은 층에 있다 || 바깥 길이 없다
장애 :: 범위를 모른다 || 어느 구획인지 안다
= 나눠야 다르게 다룰 수 있다
```

네트워크가 한 덩어리면 웹 서버와 데이터베이스가 같은 자리에 있게 된다. 바깥에서 들어오는 길을 열면 둘 다 열리고, 규칙을 조이면 둘 다 조인다.

구획을 나누면 웹 서버가 있는 곳만 바깥으로 열고 데이터베이스가 있는 곳은 안쪽에서만 닿게 할 수 있다. 데이터베이스로 가는 경로 자체가 없으면 방화벽 설정을 실수해도 바깥에서는 도달하지 못한다.

## ⚙️ 작동 원리

서브넷이 공개인지 비공개인지는 붙어 있는 라우팅 규칙이 정한다. 인터넷 게이트웨이로 나가는 길이 적혀 있으면 공개 구획이고, 그 길이 없거나 NAT를 거치게 되어 있으면 비공개 구획이다. 서브넷 자체에 공개라는 표시가 붙는 게 아니다.

주소 범위는 CIDR 표기로 적는다. `/24`는 앞의 24비트가 고정이라는 뜻이고 남는 8비트로 256개 주소가 나온다. 숫자가 클수록 좁은 범위다.

```도해
층: 클라우드 네트워크는 어떤 단위로 겹쳐 있나
네트워크 :: 10.0.0.0/16 전체 주소 범위
가용 영역 :: 물리적으로 떨어진 데이터센터
서브넷 :: 한 가용 영역 안의 주소 구획
자원 :: 그 구획 안에서 주소를 하나 받는 서버
= 서브넷 하나는 반드시 가용 영역 하나 안에 들어간다
```

서브넷이 가용 영역 하나에 묶인다는 점이 설계를 정한다. 한 곳이 멈춰도 서비스가 이어지려면 같은 역할의 구획을 여러 가용 영역에 하나씩 만들어야 한다.

## 💡 실제 사례

- **3계층 구성** — 웹은 공개 구획, 애플리케이션과 데이터베이스는 비공개 구획에 둔다.
- **여러 가용 영역** — 같은 역할의 구획을 두세 영역에 만들어두고 앞에서 나눠 보낸다. 한 영역이 멈춰도 나머지가 받는다.
- **온프레미스 연결** — 사내 네트워크와 주소 범위가 겹치면 연결했을 때 경로가 꼬인다. 처음에 겹치지 않게 정한다.

## 🚫 흔한 오해

- **퍼블릭 서브넷은 누구나 들어올 수 있는 곳이다** — 경로가 있다는 것뿐이다. 실제로 들어오려면 방화벽 규칙이 열려 있고 공인 주소가 붙어 있어야 한다.
- **서브넷을 나누면 통신이 막힌다** — 같은 네트워크 안이면 구획이 달라도 기본적으로 서로 닿는다. 막는 것은 방화벽 규칙이지 구획 자체가 아니다.
- **나중에 좁으면 넓히면 된다** — 만든 뒤에는 범위를 바꿀 수 없다. 새로 만들어 옮겨야 하고 그러면 주소가 전부 바뀐다.

## 🚨 주의사항

- **주소 계획을 먼저 세운다.** 사내 네트워크나 다른 클라우드 네트워크와 범위가 겹치면 나중에 연결할 때 손댈 곳이 많아진다.
- **구획마다 몇 개의 주소가 예약되어 있다.** 표기상 256개여도 실제로 쓸 수 있는 수는 그보다 적다.

## 📝 정리

Subnet은 큰 네트워크를 쪼갠 구획이고, 공개인지 비공개인지는 붙어 있는 경로 규칙이 정한다. 한 구획은 한 가용 영역에 묶이므로, 장애에 견디려면 같은 역할의 구획을 여러 영역에 나눠 만든다.

## ❓ 이해했는지

- 데이터베이스를 비공개 구획에 두면 방화벽 설정을 실수해도 덜 위험한 이유는 → 해결하는 문제
