# VPC Peering (VPC 피어링)

## 📝 정의

VPC 피어링은 **두 사설망을 사설 주소로 잇는 1대1 연결**이다.

게이트웨이도 VPN 도 아니고 따로 놓는 장비도 없다. AWS 문서는 이미 있는 VPC 인프라를 그대로 써서 만들기 때문에 단일 장애점도 대역폭 병목도 없다고 적는다. 내 계정끼리도, 다른 계정과도, 다른 리전과도 맺을 수 있다. 리전이 다른 연결은 트래픽이 나가기 전에 암호화되어 AWS 백본만 타고 공용 인터넷을 지나지 않는다.

### 이름
VPC :: 클라우드 속 사설망
Peering :: 둘이 짝을 맺음
= 붙여 읽으면 "두 사설망이 짝을 맺는 일". 짝은 둘뿐이라 짝의 짝은 여전히 남이다

### 비유
옆집과 담에 낸 쪽문. 두 집만 오갈 수 있고, 옆집이 또 다른 집과 쪽문을 냈다고 해서 그 집까지 이어지지는 않는다.

### 예
계정이나 망을 나눠 쓰다가 "저쪽 서버에서 이쪽 DB 를 봐야 한다" 는 말이 나오는 그 순간에 꺼내는 방법이다.

## 🖼️ 그림으로 보기

```도해
흐름: 피어링을 맺은 두 망 사이에서 접속 하나는 어떻게 가나
내 망 서버 :: 상대 망의 사설 주소로 보낸다
피어링 :: 두 망만 맞댄 1대1 길. 게이트웨이도 VPN 도 없다
상대 망 DB :: 같은 망 안에서 온 것처럼 받는다
< 내 망 서버 :: 공인 주소를 거치지 않은 답을 받는다
= 두 사설망을 사설 주소로 잇는 1대1 연결이다. 셋째 망은 이 길을 못 쓴다
```

## ⚠️ 해결하는 문제

```도해
대조: 두 사설망을 이으면 무엇이 달라지나
피어링 없이 || 피어링으로
주소 :: 공인 주소로 돌아 || 사설 주소로 곧장
장비 :: 게이트웨이나 VPN || 둘 다 없다
지연 :: 바깥을 한 바퀴 || 한 망 안과 같다
= 두 망이 한 망처럼 사설 주소로 서로 닿는다
```

망을 나누는 이유는 격리다. 개발과 운영을 갈라 두고, 계정을 팀별로 쪼갠다. 그런데 나눠 놓고 나면 그 사이로 자료를 옮겨야 할 일이 반드시 생긴다. 이때 자원을 인터넷 쪽으로 열어 공인 주소로 부르면 격리해 둔 보람이 사라진다.

피어링은 격리를 유지한 채 두 망만 맞대 준다. 구글 클라우드 문서는 피어링 트래픽의 지연·처리량·가용성이 같은 망 안의 트래픽과 같다고 적는다. 두 망은 여전히 따로 관리되고, 오가는 것은 경로 정보뿐이다 — 방화벽 규칙은 서로 넘어가지 않는다.

## ⚙️ 작동 원리

맺는 일은 청하고 받는 두 단계다. 한쪽이 요청을 보내고 상대가 수락해야 연결이 살아난다. 요청을 7일 안에 수락하지 않으면 만료된다.

연결이 살아난 것만으로는 아무것도 통하지 않는다. **양쪽이 각자 라우팅 표에 상대 대역으로 가는 경로를 손으로 넣어야 하고**, 보안 그룹도 상대 쪽 트래픽을 막고 있지 않아야 한다. 같은 리전이면 규칙의 출발지 자리에 상대 망의 보안 그룹을 그대로 적을 수 있다. 접속이 안 될 때 보는 순서도 이 순서다 — 연결 상태, 양쪽 라우팅 표, 양쪽 보안 그룹.

## 💡 실제 사례

- **계정을 넘는 공유** — 계정마다 망이 따로일 때 그 사이를 이어 파일을 주고받는 망을 만든다.
- **리전 간 복제** — 다른 리전의 망과 이어 지리적 이중화를 위해 자료를 복제하거나 자원을 나눠 쓴다.
- **공용 도구 망** — 로그 수집이나 사내 도구를 한 망에 모아 두고 다른 망들이 그것만 쓰게 한다.

## 🚫 흔한 오해

- **피어링을 걸었는데 왜 안 통하지** — 연결은 문을 만든 것뿐이다. 양쪽 라우팅 표에 경로를 넣고 보안 그룹도 열어야 비로소 통한다.
- **A-B 가 되고 A-C 가 되면 B-C 도 된다** — 전이가 없다. B 와 C 를 통하게 하려면 그 둘 사이에 연결을 따로 만들어야 한다. 상대 망의 인터넷 게이트웨이나 VPN 을 빌려 쓰는 것도 안 된다.
- **망은 일단 피어링으로 다 이으면 된다** — 짝마다 연결이 하나씩 필요해서 망이 늘면 연결 수가 빠르게 불어난다. AWS 문서도 경우에 따라 피어링 대신 트랜짓 게이트웨이 연결을 쓰라고 적는다.

## 🚨 주의사항

- **IP 대역이 겹치면 아예 못 만든다.** 대역이 일치하거나 겹치는 두 망은 연결할 수 없고, 대역이 여럿일 때 그중 하나만 겹쳐도 안 된다. 망을 만들 때 대역을 겹치지 않게 정해 두는 이유가 이것이다.
- **상대의 출구를 빌려 쓸 수 없다.** 상대 망의 인터넷 게이트웨이, NAT 장치, VPN, Direct Connect, 게이트웨이 엔드포인트는 내 망의 자원이 쓸 수 없다.
- **같은 두 망 사이에 연결은 하나뿐이다.** 이미 있는데 또 만들 수 없고, 상대 망의 DNS 서버에 직접 질의할 수도 없다.

## 📝 정리

**"두 망만 맞대는 그 쪽문"** 이라고 읽으면 된다. 전이가 없어서 짝의 짝은 남이고, 대역이 겹치면 시작조차 못 하며, 연결을 만든 뒤에도 라우팅 표와 보안 그룹을 손으로 열어야 통한다.

## 🧒 열 살에게

옆집이랑 담에 작은 문을 하나 내면 큰길로 돌지 않고 바로 오갈 수 있지? 그런데 그 문은 딱 두 집만 쓰는 거야. 옆집이 또 다른 집이랑 문을 냈다고 해서 네가 그 집까지 갈 수 있는 건 아니야.

## ❓ 이해했는지

- 연결을 만들었는데도 상대 망에 닿지 않으면 무엇부터 보나 → 작동 원리
- 망 셋을 서로 통하게 하려면 연결이 몇 개 필요한가 → 흔한 오해
- 두 망을 이을 수 없게 만드는 주소 설계 실수는 무엇인가 → 주의사항
