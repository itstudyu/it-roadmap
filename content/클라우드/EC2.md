# EC2 (Elastic Compute Cloud)

## 📝 정의

EC2는 **AWS 에서 시간 단위로 빌려 쓰는 가상 서버**다.

서버를 사서 데이터센터에 넣고 전원을 넣기까지는 몇 주가 걸린다. EC2 는 사양과 위치를 고르는 것으로 그 과정을 대신하고, 다 쓰면 반납한다.

### 비유
렌터카. 차를 사지 않고 필요한 기간만 빌리며, 배기량과 옵션을 고르듯 사양을 고른다.

### 예
게임 서버를 빌려주는 사이트에서 인원과 사양을 고르면 몇 분 뒤 접속 주소가 오는데, 그 화면과 같은 방식이다.

## 🖼️ 그림으로 보기

```도해
흐름: 서버 한 대를 빌리면 어떤 순서로 뜨나
이미지 :: 어떤 OS 와 초기 상태로 시작할지 고른다
타입 :: CPU 와 메모리 조합을 고른다
네트워크 :: 어느 VPC 와 서브넷에 놓을지 정한다
열쇠 :: 접속에 쓸 키 쌍을 지정한다
AWS :: 몇 분 안에 인스턴스가 뜨고 IP 가 붙는다
< 사용자 :: SSH 로 들어가 평소 쓰던 대로 쓴다
= 서버를 사는 일이 사양과 위치를 고르는 일로 바뀐다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버를 직접 사서 쓰면 어떻게 되나
직접 사면 || EC2 로
준비 시간 :: 주 단위로 걸림 || 몇 분이면 뜬다
사양 변경 :: 부품을 교체 || 타입만 바꾼다
안 쓸 때 :: 그대로 돈이 나감 || 끄면 과금 정지
= 서버가 사두는 자산에서 빌려 쓰는 것으로 바뀐다
```

직접 사는 방식에서는 대수를 미리 정해야 한다. 얼마나 쓰일지 모르는 상태에서 몇 주 뒤에 올 장비 수량을 결정해야 하고, 많이 사면 놀고 적게 사면 모자란다. 잘못 골라도 되돌리는 데 다시 몇 주가 든다.

EC2 는 이 결정을 미룰 수 있게 만든다. 부족하면 몇 분 만에 더 띄우고, 남으면 지운다. 사양이 안 맞으면 인스턴스를 멈추고 타입만 바꿔 다시 켠다.

## ⚙️ 작동 원리

시작할 때 고르는 것은 크게 셋이다. 어떤 상태의 디스크로 시작할지 정하는 이미지, CPU 와 메모리 조합을 정하는 인스턴스 타입, 그리고 어느 네트워크에 놓을지다.

타입은 용도별 계열로 나뉜다. 범용, CPU 를 많이 쓰는 계열, 메모리를 많이 쓰는 계열, GPU 가 붙은 계열이 있고 계열 안에서 크기를 고른다.

디스크는 인스턴스와 별개로 붙는다. 그래서 인스턴스를 멈췄다 켜도 디스크 내용은 남고, 인스턴스를 지워도 디스크를 따로 남길 수 있다.

## 📊 비교: 요금 방식

| 방식 | 조건 | 언제 쓰나 |
|---|---|---|
| 온디맨드 | 쓴 시간만큼 낸다 | 얼마나 쓸지 모를 때 |
| 예약 | 1년에서 3년 약정, 최대 75% 할인 | 계속 켜둘 서버 |
| 스팟 | 여유 용량을 싸게, 최대 90% 할인 | 중간에 끊겨도 되는 작업 |

## 💡 실제 사례

- **웹 서버** — 인스턴스 몇 대를 띄우고 앞에 로드 밸런서를 붙여 요청을 나눈다.
- **테스트 환경** — 업무 시간에만 켜두고 퇴근할 때 정지시켜 요금을 줄인다.
- **일회성 계산** — 큰 작업을 스팟 인스턴스로 돌리고 끝나면 지운다.

## 🚫 흔한 오해

- **Elastic 이라는 이름처럼 알아서 늘어난다** — 늘리고 줄이기 쉽다는 뜻이지 자동은 아니다. 대수를 자동으로 조절하려면 오토 스케일링을 따로 붙여야 한다.
- **인스턴스를 껐으니 요금이 안 나간다** — 컴퓨팅 요금은 멈추지만 붙어 있는 디스크와 고정 IP 는 계속 과금된다.
- **종료는 잠시 멈추는 것이다** — 종료는 반납이다. 인스턴스가 사라지고 기본 설정이면 붙어 있던 디스크도 같이 지워진다.

## 🚨 주의사항

- **키 파일을 잃으면 그 인스턴스에는 못 들어간다.** 나중에 다시 내려받을 수 없어서, 디스크를 떼어 다른 인스턴스에 붙이는 식으로 돌아가야 한다.
- **접속 포트를 전체에 열지 않는다.** SSH 포트를 모든 주소에 열어두면 뜨는 즉시 자동 공격이 들어온다.

## 📝 정리

EC2 는 AWS 에서 가상 서버를 빌려 쓰는 서비스다. 사양과 위치를 고르면 몇 분 만에 뜨고, 정지와 종료가 서로 다른 일이라는 점이 요금과 데이터를 가른다.
