# S3 (Simple Storage Service)

## 📝 정의

S3는 **AWS가 파일을 맡아 보관해주는 저장소**다.

디스크를 서버에 붙이는 방식이 아니라 파일 하나하나를 통에 넣고 이름으로 꺼낸다. 통을 버킷, 넣어둔 파일을 객체라고 부른다.

### 비유
물품 보관소. 창고를 직접 짓고 관리하는 대신 짐을 맡기고 번호표로 찾아간다. 짐이 몇 개가 되든 보관소가 알아서 자리를 낸다.

## 🖼️ 그림으로 보기

```도해
흐름: 사용자가 올린 사진은 S3 에서 어떻게 다뤄지나
앱 :: 사진을 버킷에 올린다
S3 :: 객체로 저장하고 키라는 이름표를 붙인다
Lambda :: 올라온 것을 신호로 받아 썸네일을 만든다
CDN :: 자주 열리는 사진을 가까운 곳에 둔다
브라우저 :: 주소로 사진을 받아 화면에 띄운다
= 파일은 한 번 올려두고 나머지는 주소로 꺼내 쓰는 구조다
```

## ⚠️ 해결하는 문제

```도해
대조: 업로드 파일을 서버 디스크에 두면 무엇이 달라지나
서버 디스크에 || S3 에
용량 :: 차면 늘려야 함 || 신경 안 씀
서버 여러 대 :: 파일이 흩어짐 || 어디서든 같음
서버 교체 :: 옮겨야 한다 || 그대로 남음
= 파일을 서버 밖으로 빼면 서버는 언제든 버릴 수 있는 것이 된다
```

업로드 파일을 서버 디스크에 저장하면 그 서버가 파일을 들고 있게 된다. 트래픽이 늘어 서버를 두 대로 늘리면 한쪽에 올린 파일이 다른 쪽에서는 안 보이고, 서버를 새로 띄우면 그동안 쌓인 것을 옮겨야 한다. 디스크가 차면 그때마다 늘려야 한다.

S3는 파일을 서버 밖으로 뺀다. 서버는 파일을 들고 있지 않고 주소만 안다. 서버가 몇 대든 같은 파일을 보고, 서버를 지우고 새로 띄워도 파일은 그 자리에 남는다.

## ⚙️ 작동 원리

```도해
층: S3 는 무엇 안에 무엇을 담나
버킷 :: 파일을 담는 통. 이름으로 구분한다
키 :: 통 안에서 파일을 가리키는 이름표
객체 :: 실제 파일 내용과 딸린 정보
= 폴더처럼 보이는 것은 키 안에 들어간 슬래시일 뿐이다
```

누가 무엇을 할 수 있는지는 버킷에 붙이는 정책이 정한다. `"Principal": "*"` 에 `"Action": "s3:GetObject"` 를 합쳐두면 아무나 이 버킷의 파일을 읽을 수 있게 된다. 정적 웹사이트를 올릴 때 필요한 설정이고, 비공개로 둘 파일이 같은 버킷에 있으면 그것까지 함께 열린다.

저장할 때 암호화를 걸 수도 있다. 올리면서 `ServerSideEncryption` 을 지정하면 S3가 저장 시점에 암호화해서 넣는다.

## 📊 비교: 스토리지 클래스

| | S3 Standard | Infrequent Access | Glacier |
|---|---|---|---|
| 어떤 데이터 | 자주 여는 것 | 가끔 여는 것 | 보관만 하는 것 |
| GB당 월 요금 | $0.023 | $0.0125 | $0.004 |
| 쓰는 자리 | 서비스 중인 이미지 | 지난달 로그 | 오래 남겨야 할 기록 |

## 💡 실제 사례

- **정적 웹사이트** — HTML, CSS, JS 를 버킷에 올려 그대로 공개한다. 앞에 CDN을 두면 더 빨리 열린다.
- **백업 보관** — 데이터베이스 백업과 지난 로그를 옮겨둔다. 자주 안 여는 것은 싼 클래스로 내린다.
- **사용자 업로드** — 올라온 이미지와 영상을 저장하고, 저장된 것을 신호 삼아 Lambda가 뒤처리를 돌린다.

## 🚫 흔한 오해

- **S3는 서버에 붙이는 디스크다** — 마운트해서 쓰는 디스크가 아니라 파일 단위로 올리고 내려받는 저장소다. 큰 파일의 가운데만 조금 고치는 식의 사용에는 맞지 않는다.
- **파일을 올리면 바로 인터넷에 공개된다** — 아무나 읽게 하는 규칙을 버킷 정책에 넣어야 열린다. 반대로 정적 사이트용으로 그 규칙을 넣어두면 그 버킷의 파일은 전부 공개된다.
- **내구성 11 nines 면 파일이 사라질 일이 없다** — 저장된 것이 스스로 손상되거나 유실되지 않는다는 이야기다. 실수로 지우거나 덮어쓴 것까지 막아주지는 않는다.

## 🚨 주의사항

- **공개할 것과 안 할 것을 버킷부터 나눈다.** 정책은 버킷 전체에 걸리므로 정적 사이트용 버킷에 개인 파일을 같이 두면 안 된다.
- **자주 안 여는 데이터를 Standard 에 계속 두지 않는다.** 같은 1GB라도 Glacier로 옮기면 월 요금이 크게 내려간다.

## 📝 정리

S3는 파일을 객체 단위로 맡아 보관하는 AWS 저장소다. 파일을 서버 밖으로 빼두면 서버를 몇 대로 늘리거나 통째로 갈아도 파일은 그대로 남는다. 열 수 있는 사람은 버킷 정책이 정하고, 얼마나 자주 여는지에 따라 클래스를 나눠 비용을 조절한다.

## ❓ 이해했는지

- 서버를 두 대로 늘렸을 때 생기는 업로드 파일 문제가 S3로 어떻게 풀리나 → 해결하는 문제
- 버킷에 올린 파일이 인터넷에 공개되려면 무엇이 있어야 하나 → 작동 원리
- 지난달 로그를 Standard 에 그대로 두면 무엇이 손해인가 → 비교
