# Fault Domain and Update Domain (고장 묶음과 갱신 묶음)

## 📝 정의

둘 다 **한꺼번에 같이 내려가는 묶음**인데, 하나는 고장이고 하나는 갱신이다.

고장 묶음은 같은 전원과 같은 네트워크 스위치를 쓰는 서버들이고, 갱신 묶음은 유지 보수 때 같이 껐다 켜지는 서버들이다. 서버를 여러 대로 늘렸어도 그 여러 대가 같은 묶음에 몰려 있으면 한 번에 같이 죽는다 — 그래서 "몇 대냐" 보다 "어느 묶음에 놓였냐" 가 먼저다.

### 이름
Fault :: 고장
Update :: 갱신
Domain :: 함께 묶인 구역
= 붙여 읽으면 "고장이 함께 미치는 구역" 과 "갱신이 함께 미치는 구역"

### 비유
아파트의 전기 차단기 — 같은 차단기에 물린 집은 사고가 나도 같이 꺼지고, 점검할 때도 같이 꺼진다.

### 예
서버를 세 대로 늘려 뒀는데 정전 한 번에 셋이 동시에 죽어서, 늘린 보람이 하나도 없던 그 새벽이다.

### 직접
집의 두꺼비집을 열어 방마다 어느 차단기에 물려 있는지 보라. 냉장고와 컴퓨터가 같은 차단기면 그 둘은 한 묶음이다.

## 🖼️ 그림으로 보기

```도해
대조: 고장 묶음과 갱신 묶음은 무엇이 다른가
고장 묶음 |=| 갱신 묶음
막는 사고 :: 전원·스위치 고장 || 계획된 재시작
가르는 기준 :: 같은 전원을 쓰나 || 같이 껐다 켜나
세는 단위 :: 최대 3개 || 최대 20개
= 하나는 예고 없이 닥치고 하나는 순서대로 온다. 그래서 나누는 축이 둘이다
```

## ⚠️ 해결하는 문제

```도해
대조: 묶음을 안 나누면 여러 대로 늘린 보람이 있나
한 묶음에 몰면 || 묶음을 나누면
전원이 나갈 때 :: 전부 같이 죽는다 || 일부만 죽는다
정기 점검 :: 동시에 재시작 || 하나씩 돌아간다
늘린 효과 :: 대수만 늘었다 || 실제로 버틴다
= 여러 대로 늘리는 것과 서로 떨어뜨려 놓는 것은 다른 일이다
```

서버를 세 대로 늘리는 이유는 하나가 죽어도 나머지가 버티라는 것이다. 그런데 세 대가 같은 랙에 꽂혀 있으면 그 랙의 전원 하나가 나갈 때 셋이 같이 죽는다. 대수를 늘려도 **같이 죽는 이유**가 그대로면 아무것도 안 늘어난 것이다.

여기에 하나가 더 있다. 클라우드 사업자는 밑바닥 하드웨어를 정기적으로 껐다 켜야 하는데, 그때 내 서버 전부가 동시에 재시작되면 계획된 유지 보수 한 번이 그대로 장애가 된다. 이건 고장이 아니라 예정된 일인데도 결과는 같다.

그래서 축을 둘로 나눈다. **고장 묶음**은 "같은 전원과 스위치를 쓰느냐" 로 가르고, **갱신 묶음**은 "유지 보수 때 같이 껐다 켜느냐" 로 가른다. 두 축은 겹치지 않아서, Azure 는 같은 가용성 집합 안에서 고장 묶음은 최대 3개로 갱신 묶음은 최대 20개로 따로 센다.

## ⚙️ 작동 원리

Azure 의 가용성 집합에 가상 머신을 넣으면 플랫폼이 각 대에 고장 묶음 번호와 갱신 묶음 번호를 하나씩 붙인다. 새로 넣는 대는 아직 덜 찬 묶음으로 가고, 갱신 묶음이 다섯 개인 집합에 여섯 번째를 넣으면 첫 번째와 같은 묶음에 들어간다. 이 값들은 집합을 만든 뒤에는 바꿀 수 없다.

유지 보수가 시작되면 갱신 묶음이 **한 번에 하나씩만** 재시작된다. Azure 문서는 재시작된 묶음에 30분의 회복 시간을 준 다음에야 다른 묶음의 작업이 시작된다고 적는다. 순서가 번호대로 도는 것은 아니지만, 동시에 둘이 내려가는 일은 없다.

AWS 는 같은 목적을 배치 그룹으로 부른다. 랙 단위 spread 그룹은 인스턴스를 각각 다른 랙에 놓고, 문서는 그 랙마다 자체 네트워크와 전원이 있다고 적는다. 대신 자리가 한정되어 있어 가용 영역 하나당 7대까지고, 여덟 번째는 아예 안 뜬다. partition 그룹은 파티션마다 랙 묶음을 따로 잡아 주고 가용 영역당 7개까지 나눈다. Google 은 spread 배치 정책의 availability domain 으로 부르며 최대 8개까지 지정할 수 있다.

## 📊 비교: 세 곳은 이 나눔을 무엇이라 부르나

| 어디 | 부르는 이름 | 몇 개까지 | 무엇으로 가르나 |
|---|---|---|---|
| **Azure** | 가용성 집합의 Fault Domain · Update Domain | 3개 · 20개 | 전원과 스위치를 같이 쓰나 · 유지 보수 때 같이 껐다 켜나 |
| **AWS** | 배치 그룹의 spread (랙 단위) · partition | 가용 영역당 7대 · 파티션 7개 | 각기 다른 랙. 랙마다 자체 네트워크와 전원 |
| **Google Cloud** | spread 배치 정책의 availability domain | 최대 8개 | 서로 격리된 별개의 하드웨어 |

세 곳 다 **고장 묶음** 쪽은 이름만 다르고 하는 일이 같다. 갈리는 건 갱신 쪽이다 — Azure 만 갱신 묶음을 별도 축으로 세어 주고, AWS 와 Google 은 유지 보수를 이벤트로 알려 주고 대응은 사용자가 짜는 쪽이다.

## 💡 실제 사례

- **데이터베이스 이중화** — 주 서버와 대기 서버를 다른 고장 묶음에 넣는다. 같은 묶음이면 이중화가 아니라 그냥 두 대다.
- **정기 유지 보수 견디기** — 갱신 묶음을 나눠 두면 사업자가 밑바닥을 껐다 켜도 한 번에 일부만 내려가고 서비스는 계속 뜬다.
- **분산 저장소 배치** — 같은 자료의 사본들을 서로 다른 묶음에 흩는다. AWS 는 파티션 정보를 앱에 알려 줘 사본을 어디에 둘지 스스로 정하게 한다.

## 🚫 흔한 오해

- **여러 대로 늘려 뒀으니 한꺼번에 죽을 일은 없다** — 어디에 놓일지를 안 정하면 세 대가 같은 전원과 같은 스위치에 물릴 수 있다. Azure 는 고장 묶음을 "같은 전원과 네트워크 스위치를 공유하는 가상 머신들" 로 정의한다.
- **고장 묶음과 갱신 묶음은 같은 말이다** — 나누는 축이 다르다. 하나는 전원과 스위치를 같이 쓰느냐고, 하나는 유지 보수 때 같이 껐다 켜느냐다. 그래서 같은 집합 안에서 3과 20 으로 다르게 센다.
- **묶음만 나눠 두면 무슨 장애든 막힌다** — Azure 문서는 가용성 집합이 운영체제나 앱 자체의 문제는 막지 못하고, 데이터센터 전체의 네트워크 장애처럼 여러 고장 묶음에 한꺼번에 걸치는 사고에도 여전히 약하다고 적는다.

## 🚨 주의사항

- **만든 뒤에는 못 바꾼다.** Azure 는 집합의 묶음 개수를 만든 다음에 변경할 수 없다고 적는다. 처음 만들 때 정해야 한다.
- **자리가 한정되어 있다.** AWS 의 랙 단위 spread 그룹은 가용 영역마다 7대까지고, 여덟 번째를 띄우려 하면 실패한다. 더 필요하면 그룹을 여러 개로 나눈다.
- **더 큰 사고에는 더 큰 단위가 필요하다.** 묶음 나누기는 한 데이터센터 안의 얘기다. 건물이 통째로 흔들리는 경우는 [[Availability Zone]] 이, 지역이 흔들리는 경우는 [[Multi-Region]] 이 맡는다.

## 📝 정리

**"같이 죽는 묶음과 같이 멈추는 묶음"** 이라고 읽으면 된다. 대수를 늘려도 같은 묶음에 몰려 있으면 하나가 죽을 때 다 같이 죽으니, 몇 대냐보다 어느 묶음에 놓였냐가 먼저다. 나누는 축이 둘이라는 것과 만든 뒤에는 못 바꾼다는 것, 이 둘만 기억하면 된다.

## 🧒 열 살에게

같은 차단기에 물린 방들은 하나가 말썽을 부리면 같이 깜깜해지지? 그래서 꼭 켜져 있어야 하는 것들은 일부러 다른 차단기에 나눠 꽂아 둬. 점검하는 날도 차단기를 하나씩 차례로 내려서, 온 집이 한꺼번에 깜깜해지는 일은 없게 해.

## ❓ 이해했는지

- 서버를 세 대로 늘렸는데 정전 한 번에 셋이 같이 죽는 일은 왜 생기나 → 흔한 오해
- 유지 보수로 껐다 켤 때 전부가 한꺼번에 안 내려가는 까닭은 무엇인가 → 작동 원리
- 만들고 나서 묶음 수를 늘리고 싶으면 어떻게 해야 하나 → 주의사항

## 🔗 관련 용어

- [[Availability Zone]] — 묶음보다 한 단계 큰 나눔. 건물이 통째로 흔들릴 때를 맡는다
- [[High Availability]] — 이 나눔이 떠받치는 목표 그 자체
- [[Fault Tolerance]] — 일부가 죽어도 계속 도는 성질. 묶음 나누기가 그 바탕이다
- [[Rolling Update]] — 갱신 묶음과 같은 생각을 내 배포에 적용한 것
- [[Multi-Region]] — 지역이 통째로 흔들릴 때를 맡는 더 큰 나눔
