# VPC (Virtual Private Cloud)

## 📝 정의

VPC는 **클라우드 안에 내 것만 있는 사설 네트워크**다.

같은 데이터센터에 다른 회사의 서버가 잔뜩 있지만 내 VPC 안의 자원끼리만 서로 보인다. IP 대역, 어디까지 열지, 인터넷으로 나갈지를 내가 정한다.

### 이름
Virtual :: 진짜 선이 아닌
Private :: 나만 쓰는
Cloud :: 빌려 쓰는 저쪽
= 붙여 읽으면 "빌린 자리에 선 없이 그은 나만의 망". 벽이 아니라 규칙으로 갈라 놓은 것이다

### 비유
공유 오피스 안의 전용 사무실. 건물은 같이 쓰지만 내 방은 문을 잠그고 누가 들어올지 내가 정한다. 옆 회사와 벽을 맞대고 있어도 서로 왕래가 없다.

### 예
회사 시스템이 사무실 밖에서는 열리지 않고 VPN 을 켜야 들어가지는 것이 이 경계가 하는 일이다.

## 🖼️ 그림으로 보기

```도해
층: VPC 안은 어떻게 나뉘어 있나
VPC :: 내가 정한 IP 대역 전체. 예를 들어 10.0.0.0/16
퍼블릭 서브넷 :: 인터넷에서 닿는다. 웹 서버 자리
프라이빗 서브넷 :: 인터넷에서 못 닿는다. DB 자리
보안 그룹 :: 자원 하나하나에 붙는 방화벽 규칙
= DB 를 프라이빗에 두는 것만으로 외부 공격 경로 하나가 통째로 사라진다
```

## ⚠️ 해결하는 문제

```도해
대조: 클라우드에 그냥 서버를 띄우면 무엇이 열려 있나
VPC 없이 || VPC 로
DB 접근 :: 인터넷에 노출 || 내부에서만
IP 대역 :: 클라우드가 정함 || 내가 정함
사내 연결 :: 인터넷 경유 || 전용 연결 가능
= 무엇을 밖에 열지 내가 정하게 만드는 것이 이 경계의 목적이다
```

서버를 인터넷에 그대로 띄우면 전 세계에서 접근할 수 있다. 웹 서버는 그래야 하지만 데이터베이스는 그럴 이유가 없다. 그런데 경계가 없으면 DB도 같은 인터넷 위에 놓인다.

VPC는 안과 밖을 나눈다. 웹 서버만 밖에 두고 DB는 안쪽에 둔다. DB에는 인터넷에서 닿는 경로 자체가 없어서, 비밀번호를 뚫는 문제 이전에 문 앞까지 갈 수가 없다.

## ⚙️ 작동 원리

방화벽이 두 층이다.

| | 보안 그룹 | 네트워크 ACL |
|---|---|---|
| 붙는 곳 | 자원 하나하나 | 서브넷 전체 |
| 규칙 | 허용만 적는다 | 허용과 거부 둘 다 |
| 상태 | 나간 요청의 응답은 자동 허용 | 응답도 따로 열어야 |

프라이빗 서브넷의 서버도 밖으로 나가야 할 때가 있다. 패키지를 내려받거나 외부 API를 부를 때다. 이때 NAT 게이트웨이를 두면 나가는 것은 되고 들어오는 것은 안 되는 한 방향 통로가 생긴다.

## 💡 실제 사례

- **3계층 구성** — 웹 서버는 퍼블릭, 애플리케이션과 DB는 프라이빗에 둔다.
- **사내망 연결** — 전용선이나 VPN으로 사무실과 VPC를 잇는다.
- **환경 분리** — 개발용과 운영용 VPC를 따로 만들어 서로 닿지 않게 한다.

## 🚫 흔한 오해

- **VPC 안이면 안전하다** — 안쪽에 들어온 공격자에게는 다 열려 있다. 보안 그룹으로 내부에서도 필요한 경로만 연다.
- **프라이빗 서브넷은 인터넷을 아예 못 쓴다** — NAT를 두면 나가는 건 된다. 들어오는 것만 막힌다.
- **IP 대역은 아무렇게나 정해도 된다** — 나중에 사내망이나 다른 VPC와 연결할 때 대역이 겹치면 잇지 못한다. 처음에 겹치지 않게 정해야 한다.

## 🚨 주의사항

- **`0.0.0.0/0` 으로 열지 않는다.** 특히 22번 포트를 전 세계에 열어두면 몇 분 안에 대입 시도가 들어온다.
- **NAT 게이트웨이 비용을 확인한다.** 시간당 요금에 처리량 요금이 붙어서, 프라이빗에서 큰 파일을 자주 내려받으면 예상보다 많이 나온다.

## 📝 정리

**"남의 건물 안에 문 달아 놓은 그 내 방"** 이라고 읽으면 된다. 무엇을 밖에 열고 무엇을 안에 둘지 정하는 경계이고, IP 대역은 나중에 바꾸기 어려우니 처음에 신중하게 정한다.

## 🧒 열 살에게

커다란 건물을 여러 회사가 나눠 쓰지만, 우리 방은 문을 잠그고 누가 들어올지 우리가 정한다고 해 봐. 옆방과 벽 하나 사이여도 서로 오갈 길이 없어. 그래서 정말 중요한 물건은 복도에 붙은 방 말고 맨 안쪽 방에 두면, 열쇠를 훔쳐도 그 문 앞까지 올 길이 아예 없어.

## ❓ 이해했는지

- DB를 프라이빗 서브넷에 두면 어떤 공격 경로가 통째로 사라지나 → 해결하는 문제
- 프라이빗 서브넷의 서버가 패키지를 내려받을 수 있는 이유는 → 작동 원리
- IP 대역을 아무렇게나 정하면 나중에 무엇을 못 하게 되나 → 흔한 오해
