# IaaS / PaaS / SaaS

## 📝 정의

IaaS, PaaS, SaaS는 **클라우드가 어디까지 맡느냐**로 나뉜 세 단계다.

서비스 하나를 올리려면 하드웨어부터 운영체제, 실행 환경, 애플리케이션까지 층층이 필요하다. 그 층을 아래에서부터 몇 번째까지 제공사가 맡느냐에 따라 이름이 갈린다.

### 비유
피자를 오븐과 재료만 빌려 직접 굽느냐, 주방과 요리사를 빌려 지시만 하느냐, 배달시켜 먹느냐의 차이다.

## 🖼️ 그림으로 보기

```도해
흐름: 서비스를 하나 올리려면 무엇을 해야 하나
서버 마련 :: 하드웨어와 네트워크를 갖춘다
OS 설치 :: 운영체제를 올리고 보안 설정을 한다
실행 환경 :: 런타임과 데이터베이스를 붙인다
코드 배포 :: 만든 애플리케이션을 올린다
< 운영 :: 감시하고 고치고 늘렸다 줄인다
= 이 중 몇 번째까지를 남이 맡아주느냐가 셋을 가른다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버를 직접 사서 운영하면 어떻게 되나
직접 장만 || 빌려 쓰기
시작 비용 :: 장비값 선불 || 쓴 만큼 후불
늘리기 :: 사서 설치 || 설정만 바꿈
장애 대비 :: 한 건물에 몰림 || 지역을 나눔
= 자산으로 사두던 것을 필요할 때만 빌리는 것으로 바꾼다
```

물리 장비를 직접 사면 쓰기도 전에 큰돈이 나가고, 부족해지면 다시 사서 설치할 때까지 기다려야 한다. 서버 관리와 보안 패치와 백업을 맡을 사람도 계속 있어야 한다.

빌려 쓰면 그 부담이 층별로 넘어간다. 하드웨어만 넘기면 IaaS, 운영체제와 실행 환경까지 넘기면 PaaS, 소프트웨어까지 넘기면 SaaS다.

## ⚙️ 작동 원리

```도해
층: 어디까지를 제공사가 맡나
SaaS :: 소프트웨어까지 제공사. 나는 쓰기만 한다
PaaS :: 실행 환경까지 제공사. 나는 코드만 올린다
IaaS :: 하드웨어까지 제공사. 운영체제부터 내가 한다
온프레미스 :: 하드웨어부터 데이터까지 전부 내가 한다
= 위로 갈수록 할 일이 줄고, 바꿀 수 있는 것도 같이 줄어든다
```

IaaS는 가상 서버를 만들어 원하는 운영체제를 올리는 데서 시작한다. 리소스를 늘렸다 줄이는 것도 직접 하고 쓴 시간만큼 낸다.

PaaS는 코드를 올리면 빌드와 배포와 확장이 따라붙는다. 대신 어떤 언어와 버전을 쓸지는 플랫폼이 정해둔 범위 안에서 고른다.

SaaS는 완성된 소프트웨어를 구독한다. 업데이트와 보안 패치는 제공사가 하고, 쓰는 쪽에 남는 선택은 설정 화면에 있는 것뿐이다.

## 📊 비교

| 항목 | 온프레미스 | IaaS | PaaS | SaaS |
|---|---|---|---|---|
| 내가 관리하는 것 | 전부 | 운영체제부터 | 애플리케이션만 | 없다 |
| 초기 비용 | 크다 | 작다 | 작다 | 거의 없다 |
| 자유도 | 가장 높다 | 높다 | 중간 | 낮다 |
| 옮겨 타기 | 자유롭다 | 어렵다 | 어렵다 | 가장 어렵다 |

## 💡 실제 사례

- **아이디어를 빨리 띄울 때** — 코드만 올리면 배포와 확장이 따라붙는 PaaS를 써서 인프라를 만들지 않고 시작한다.
- **쓰던 시스템을 그대로 옮길 때** — 서버만 빌려 오면 애플리케이션을 고치지 않고 옮길 수 있어서 IaaS를 고른다.
- **협업 도구 도입** — 메일이나 메신저는 완성된 것을 구독해서 쓰고, 업데이트와 보안은 제공사에 맡긴다.

## 🚫 흔한 오해

- **셋 중에 SaaS가 제일 좋은 것이다** — 좋고 나쁨이 아니라 맡길 범위의 차이다. 맡길수록 편해지는 만큼 바꿀 수 있는 여지도 줄어든다.
- **클라우드로 옮기면 보안은 제공사 책임이다** — 나눠 진다. IaaS에서 운영체제 패치와 접근 권한은 여전히 쓰는 쪽 몫이고, 그 자리를 비워두면 뚫린다.
- **클라우드가 언제나 더 싸다** — 없어지는 건 초기 장비값이다. 부하가 늘 높게 유지되면 빌리는 값이 사두는 값을 넘어가기도 한다.

## 🚨 주의사항

- **옮겨 탈 때를 미리 생각해둔다.** 제공사에 맡긴 층이 많을수록 나올 때 옮길 것도 많아진다.
- **데이터가 어느 나라에 저장되는지 확인한다.** 금융이나 의료처럼 저장 위치가 규제에 걸리는 분야가 있다.

## 📝 정리

IaaS, PaaS, SaaS는 서비스에 필요한 층을 어디까지 제공사에 넘기느냐로 나뉜다. 넘길수록 할 일이 줄지만 고칠 수 있는 범위와 옮겨 탈 자유도 같이 줄어든다. 어느 하나가 우월한 게 아니라 무엇을 직접 쥐고 있어야 하는지에 따라 고르는 것이다.

## ❓ 이해했는지

- 운영체제 보안 패치를 누가 하느냐는 IaaS와 PaaS에서 어떻게 갈리나?
- 쓰던 시스템을 고치지 않고 클라우드로 옮기려면 셋 중 무엇을 고르나?
- SaaS가 가장 편한데도 모두가 SaaS만 쓰지 않는 이유는?
