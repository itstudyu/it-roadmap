# IaaS / PaaS / SaaS

## 📝 정의

클라우드 컴퓨팅은 인터넷을 통해 IT 리소스를 대여하는 서비스 모델입니다. 클라우드 서비스는 제공 범위에 따라 3가지로 분류됩니다. IaaS(Infrastructure as a Service)는 컴퓨팅 인프라(서버, 스토리지, 네트워크)만 제공하여 사용자가 OS와 애플리케이션을 관리합니다. PaaS(Platform as a Service)는 개발 플랫폼을 제공하여 사용자가 애플리케이션 개발과 배포에만 집중합니다. SaaS(Software as a Service)는 완성된 소프트웨어를 웹 브라우저로 사용하므로 사용자는 서비스만 소비합니다.

> **한 줄 요약**: 클라우드 서비스는 제공 범위에 따라 IaaS(인프라), PaaS(플랫폼), SaaS(소프트웨어)로 나뉩니다.

**비유 1**: 자동차로 비유하면, IaaS는 자동차 본체(엔진, 바디)를 빌리는 것(직접 조립하고 운전), PaaS는 완성된 자동차를 빌리는 것(직접 운전), SaaS는 택시 서비스를 이용하는 것(전문가가 운전).

**비유 2**: 피자로 비유하면, IaaS는 오븐과 재료(자신이 요리), PaaS는 주방과 요리사(자신이 레시피 지시), SaaS는 피자 배달 서비스(서비스 이용만).

## 🎯 핵심 개념

### 1. IaaS (Infrastructure as a Service)
가상 서버, 스토리지, 네트워크 등 컴퓨팅 인프라를 제공합니다. 사용자는 운영체제, 미들웨어, 애플리케이션을 직접 설치하고 관리합니다. 가장 낮은 추상화 수준이므로 자유도가 높지만 관리 부담이 큽니다. 대표 서비스: AWS EC2, Microsoft Azure VM, Google Cloud Compute Engine.

### 2. PaaS (Platform as a Service)
애플리케이션 개발과 배포를 위한 플랫폼을 제공합니다. OS, 런타임, 미들웨어는 클라우드 제공자가 관리하므로 개발자는 코드 작성과 배포에만 집중합니다. 자유도는 낮지만 개발 생산성이 높습니다. 대표 서비스: Heroku, Google App Engine, AWS Elastic Beanstalk.

### 3. SaaS (Software as a Service)
완성된 소프트웨어를 웹 브라우저나 모바일 앱을 통해 구독 방식으로 제공합니다. 사용자는 서비스만 이용하고, 소프트웨어 관리(업데이트, 보안 패치)는 제공자가 담당합니다. 최고의 추상화 수준으로 즉시 사용 가능합니다. 대표 서비스: Gmail, Microsoft 365, Slack, Salesforce, Figma.

### 4. 책임 범위 (Responsibility Matrix)
온프레미스에서는 사용자가 모든 것(하드웨어부터 애플리케이션까지)을 관리하지만, IaaS → PaaS → SaaS로 갈수록 클라우드 제공자의 책임이 증가합니다.

## ⚠️ 해결하는 문제

### 문제 1: 높은 초기 자본 비용
물리 서버, 스토리지, 네트워크 장비를 직접 구입하면 수백만 원대의 초기 투자가 필요합니다. 클라우드 서비스는 종량제로 필요한 만큼만 결제하여 초기 비용을 줄입니다.

### 문제 2: IT 운영 인력 부담
서버 관리, 보안 패치, 백업, 업그레이드를 전담하는 IT 팀이 필요합니다. PaaS/SaaS는 이러한 운영 부담을 클라우드 제공자에게 전가합니다.

### 문제 3: 확장성 제한
물리 서버는 새로 구입해야 확장 가능하지만, 클라우드는 클릭 하나로 즉시 확장할 수 있습니다.

### 문제 4: 지리적 가용성
온프레미스는 한 지역의 재해에 취약하지만, 클라우드는 전 세계 데이터센터를 활용할 수 있습니다.

## ⚙️ 작동 원리

### IaaS 작동 원리
1. 클라우드 제공자가 물리 서버와 네트워크 인프라를 제공합니다.
2. 사용자가 가상 머신(VM)을 생성하고, 원하는 OS를 선택합니다.
3. 사용자가 원격으로 접속하여 애플리케이션을 설치하고 실행합니다.
4. 필요에 따라 VM의 리소스(CPU, 메모리, 스토리지)를 조정합니다.
5. 사용한 리소스에 대해 시간 또는 분 단위로 결제합니다.

### PaaS 작동 원리
1. 클라우드 제공자가 완벽하게 구성된 개발 환경(OS, 런타임, 데이터베이스)을 제공합니다.
2. 개발자가 코드만 작성하여 Git에 push합니다.
3. 플랫폼이 자동으로 코드를 빌드, 테스트, 배포합니다.
4. 플랫폼이 자동 스케일링, 부하 분산, 모니터링을 담당합니다.
5. 사용한 리소스 또는 배포 수에 따라 결제합니다.

### SaaS 작동 원리
1. 클라우드 제공자가 완성된 소프트웨어를 운영하고 유지보수합니다.
2. 사용자는 웹 브라우저 또는 API를 통해 소프트웨어에 접근합니다.
3. 제공자가 모든 업데이트, 보안 패치, 백업을 자동으로 관리합니다.
4. 사용자 데이터는 제공자의 서버에 저장되고, 언제 어디서나 접근 가능합니다.
5. 구독료를 매월 또는 매년 지불합니다.

## 📊 비교

| 항목 | 온프레미스 | IaaS | PaaS | SaaS |
|------|-----------|------|------|------|
| **자유도/제어도** | 매우 높음 | 높음 | 중간 | 낮음 |
| **초기 구축 비용** | 매우 높음 | 낮음 | 낮음 | 매우 낮음 |
| **운영 비용** | 높음 (인력 포함) | 중간 | 낮음 | 낮음 |
| **확장성** | 낮음 (구매 필요) | 높음 (즉시 확장) | 높음 (자동) | 높음 |
| **보안 책임** | 전적으로 사용자 | 공유 | 공유 | 제공자 |
| **사용자 관리 대상** | 모두 | OS 이상 | 애플리케이션 | 없음 |
| **배포 속도** | 느림 (구매/설치) | 중간 | 빠름 | 즉시 |
| **벤더 종속성** | 없음 | 높음 | 높음 | 매우 높음 |

## ✅ 장단점

### IaaS의 장단점
**장점**: 최대 자유도, 선택지 다양, 비용 효율성, 확장성
**단점**: 운영 복잡도 높음, 보안 책임 커짐, 기술 난이도 높음

### PaaS의 장단점
**장점**: 개발 생산성 높음, 운영 부담 적음, 빠른 배포, 자동 스케일링
**단점**: 자유도 제한, 벤더 종속, 비용 예측 어려움, 레거시 통합 어려움

### SaaS의 장단점
**장점**: 즉시 사용, 관리 부담 없음, 저가, 멀티 디바이스 지원, 자동 업데이트
**단점**: 최소 자유도, 데이터 프라이버시 우려, 커스터마이징 제한, 종료 시 데이터 이전 어려움

## 💡 실제 사례

### Case 1: 스타트업의 빠른 서비스 출시 (PaaS)
스타트업이 Heroku를 사용하여 개발에만 집중하고 2주 안에 MVP를 출시합니다. PaaS 덕분에 인프라 관리 없이 아이디어를 빠르게 검증할 수 있습니다.

### Case 2: 대규모 기업의 레거시 시스템 (IaaS)
기존 온프레미스 환경을 AWS로 마이그레이션한 기업이 IaaS를 선택합니다. 레거시 애플리케이션을 수정 없이 클라우드로 이전하고, 자동 스케일링으로 비용을 절감합니다.

### Case 3: 협업 도구 도입 (SaaS)
회사 전체가 Slack, Microsoft Teams, Google Workspace를 도입하여 별도의 IT 관리 없이 즉시 사용합니다. 자동 업데이트와 보안 관리는 제공자가 담당합니다.

### Case 4: 하이브리드 구성
대규모 기업이 보안이 중요한 핵심 시스템은 온프레미스, 개발/테스트 환경은 IaaS, 협업 도구는 SaaS로 구성합니다. 비즈니스 요구에 따라 최적의 모델을 선택합니다.

### Case 5: 마이크로서비스 아키텍처 (PaaS)
Google App Engine이나 AWS Lambda를 사용하여 각 마이크로서비스를 쉽게 배포하고, 자동 스케일링으로 비용을 최적화합니다.

## 🔗 관련 용어

- **클라우드 네이티브**: 클라우드 환경에 최적화된 애플리케이션 설계 (컨테이너, 마이크로서비스)
- **하이브리드 클라우드**: 온프레미스와 퍼블릭 클라우드를 혼합 운영
- **멀티 클라우드**: 여러 클라우드 제공자(AWS, Azure, GCP)를 동시에 사용
- **Serverless**: 서버 관리 없이 코드만 실행 (AWS Lambda, Google Cloud Functions)
- **컨테이너**: Docker 컨테이너로 애플리케이션을 패키징 (IaaS와 PaaS 간 중간 수준)
- **API 퍼스트**: SaaS 간 데이터 통합을 API로 구현
- **데이터 주권**: 특정 국가에 데이터 저장 의무 (금융, 의료 규제)
- **총 소유 비용 (TCO)**: 초기 비용 + 운영 비용의 합계 (온프레미스 vs 클라우드 비교)
