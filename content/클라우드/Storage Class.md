# Storage Class (저장 등급)

## 📝 정의

Storage Class 는 **얼마나 자주 꺼낼지**로 나눈 저장 요금제다.

같은 통에 같은 파일을 넣어도 등급이 다르면 값이 다르다. 등급을 내릴수록 보관비는 내려가고, 대신 꺼낼 때 돈이 붙고 최소로 맡겨야 하는 기간이 길어지고 어떤 등급은 몇 시간을 기다려야 열린다. AWS 는 스토리지 클래스, Azure 는 액세스 계층, Google Cloud 는 스토리지 클래스라고 부른다.

### 이름
Storage :: 넣어 두는 곳
Class :: 나눠 놓은 등급
= 붙여 읽으면 "저장소를 나눠 놓은 등급". 나누는 잣대는 꺼내는 빈도다

### 비유
옷장과 계절 창고. 매일 입는 옷은 손 닿는 곳에 걸고 겨울 이불은 값싼 창고에 맡기되, 창고 것은 꺼낼 때마다 삯을 치른다.

### 예
지난달 백업본은 바로 열리는데 3년 전 것은 "복원 요청" 을 누르고 한참 기다려야 하던 그 화면이다.

### 직접
클라우드 저장소에서 파일 하나의 속성을 열어 보라. "스토리지 클래스" 또는 "액세스 계층" 이라는 칸이 있고, 거기 적힌 낱말 하나가 그 파일의 이번 달 요금을 정한다.

## 🖼️ 그림으로 보기

```도해
층: 저장 등급은 무엇을 기준으로 나뉘나
자주 꺼냄 :: 보관비가 가장 비싸고 꺼내는 값은 안 붙는다
가끔 꺼냄 :: 보관비가 내려가고 꺼낼 때 돈이 붙는다
드물게 꺼냄 :: 더 싸지고 최소로 맡겨야 하는 기간이 길어진다
거의 안 꺼냄 :: 가장 싸지만 되살리는 데 몇 시간이 걸리기도 한다
= 등급은 성능표가 아니라 "얼마나 자주 꺼내나" 한 축으로 늘어선 요금표다
```

## ⚠️ 해결하는 문제

```도해
대조: 등급이 하나뿐이면 무엇이 문제인가
한 등급만 || 등급을 나누면
3년 전 로그 :: 새것과 같은 값 || 몇 분의 일 값
값을 내리려면 :: 지우는 수밖에 || 옮기면 내려간다
관리 :: 사람이 챙긴다 || 규칙이 옮긴다
= 값을 정하는 건 파일 크기가 아니라 얼마나 자주 꺼내느냐다
```

저장한 것의 대부분은 넣은 뒤 며칠만 뜨겁고 그 뒤로는 아무도 열지 않는다. 그런데 등급이 하나뿐이면 어제 올린 사진과 3년 전 로그가 같은 값을 문다. 값을 내리는 방법이 "지운다" 밖에 없으니, 아직 지우면 안 되는 것 때문에 요금이 해마다 쌓인다.

등급은 그 축을 요금표 쪽으로 옮긴다. 자주 안 꺼낼 것을 아래 등급에 두면 보관비가 몇 분의 일로 떨어지고, 나이를 조건으로 건 규칙이 사람 손 없이 옮겨 준다. 대신 값이 사라진 게 아니라 **꺼내는 쪽으로 옮겨 갔다** — 그래서 고르는 잣대는 크기가 아니라 빈도다.

## ⚙️ 작동 원리

등급은 파일 하나하나에 붙는다. 올릴 때 지정하지 않으면 통의 기본 등급이 붙고, 나중에 바꿀 수도 있다. 사람이 매번 손대는 대신 **수명주기 규칙**을 걸어 둔다 — AWS 는 "전환(transition)" 과 "만료(expiration)" 두 가지 동작을 규칙으로 적고, Google Cloud 는 `SetStorageClass` 와 `Delete` 를 나이 같은 조건에 건다. 조건을 모두 만족한 것만 옮겨지거나 지워진다.

값이 붙는 자리가 셋이라는 것이 이 자리의 핵심이다. 보관비는 등급이 내려갈수록 싸지고, 꺼내는 값(검색 요금)과 요청 요금은 등급이 내려갈수록 비싸진다. 여기에 **최소 보관 기간**이 세 번째 자리로 붙는다. AWS 는 Standard-IA 와 One Zone-IA 에 30일, Glacier Instant Retrieval 과 Flexible Retrieval 에 90일, Deep Archive 에 180일을 매기고, 그전에 지우거나 옮기면 남은 날짜만큼을 그대로 물린다. Azure 문서가 든 예가 가장 또렷하다 — 쿨 계층에 올린 것을 21일 만에 지우면 9일치를 물어야 한다.

되살리는 시간도 등급이 정한다. Azure 아카이브 계층은 읽거나 고칠 수 없는 오프라인 계층이라 온라인 계층으로 되살려야 하고 최대 15시간이 걸린다. AWS Glacier Flexible Retrieval 과 Deep Archive 도 먼저 복원해야 열린다. 반면 Google Cloud 는 Archive 등급까지 "다른 클라우드의 가장 차가운 저장소와 달리 밀리초 안에 열린다" 고 적는다. 같은 이름이 같은 성질을 뜻하지 않는다.

패턴을 모르겠으면 자동으로 옮겨 주는 등급도 있다. AWS 는 S3 Intelligent-Tiering 이 30일·90일·180일 안 열린 것을 알아서 아래 계층으로 내리고 꺼내는 값을 안 물리는 대신 감시 수수료를 받는다. Azure 는 스마트 계층, Google Cloud 는 Autoclass 가 같은 일을 한다.

## 📊 비교: 세 회사는 같은 등급을 뭐라 부르나

| 얼마나 자주 꺼내나 | AWS S3 | Azure Blob | Google Cloud Storage |
|---|---|---|---|
| 한 달에 여러 번 | Standard | 핫(Hot) | Standard |
| 한 달에 한 번쯤 | Standard-IA · One Zone-IA (최소 30일) | 쿨(Cool, 최소 30일) | Nearline (최소 30일) |
| 분기에 한 번쯤 | Glacier Instant Retrieval (최소 90일) | 콜드(Cold, 최소 90일) | Coldline (최소 90일) |
| 일 년에 한 번도 안 | Glacier Deep Archive (최소 180일) | 아카이브(Archive, 최소 180일) | Archive (최소 365일) |
| 꺼내기 전에 할 일 | Flexible Retrieval·Deep Archive 만 복원부터. Instant Retrieval 은 바로 열린다 | 아카이브는 되살리기 최대 15시간 | 없다. 밀리초 안에 열린다 |
| 알아서 옮겨 주는 것 | S3 Intelligent-Tiering | 스마트 계층 | Autoclass |

이름만 외우면 이 표가 세 벌이 되지만, "얼마나 자주 꺼내나" 한 줄만 잡으면 세 회사가 같은 칸을 채운 것이 보인다. 다만 마지막 두 줄처럼 **이름이 같아도 성질이 다른 자리**가 있으니 거기서만 문서를 확인하면 된다.

## 💡 실제 사례

- **로그를 규칙 하나에 맡기기** — S3 수명주기 규칙에 전환과 만료를 함께 적어 30일 뒤 Standard-IA 로 내리고 1년 뒤 지우게 한다. 사람이 달마다 챙기던 일이 규칙 한 줄이 된다.
- **법이 정한 보존** — 몇 년을 지울 수 없지만 열 일은 거의 없는 기록은 Glacier Deep Archive(최소 180일)에 넣고, 꺼낼 때의 값과 복원 대기를 감수한다.
- **언제 읽힐지 모를 때** — 패턴을 못 잡는 사용자 업로드는 S3 Intelligent-Tiering 에 둔다. 30일·90일·180일 안 열리면 알아서 내려가고, 꺼내는 값 대신 감시 수수료를 낸다.

## 🚫 흔한 오해

- **자주 안 쓰는 건 무조건 제일 싼 등급에 넣으면 된다** — 꺼내는 값과 최소 보관 기간이 함께 붙는다. 한 달에 몇 번만 꺼내도, 또는 최소 기간 전에 지워도 표준 등급보다 비싸진다.
- **등급을 내리면 그 순간부터 싸진다** — 옮기는 요청 자체가 요금이고, 이전 등급의 최소 기간을 못 채웠으면 남은 날짜치가 그대로 청구된다.
- **싼 등급은 잘 깨진다** — 아니다. AWS 는 아카이브 등급까지 같은 99.999999999% 내구성으로 설계한다고 적는다. 등급이 정하는 것은 안전이 아니라 꺼내는 속도와 꺼내는 값이고, 안전 쪽은 [[Storage Redundancy]] 가 따로 정한다.

## 🚨 주의사항

- **최소 보관 기간부터 본다.** 30일·90일·180일·365일이 등급마다 다르다. 그보다 짧게 살 파일은 내려도 손해다.
- **꺼내는 횟수를 곱해 본다.** 보관비만 보고 고르면, 한 달에 몇 번 읽는 것만으로 순서가 뒤집힌다.
- **되살리는 시간을 복구 목표와 맞춘다.** 한 시간 안에 되돌려야 하는 백업을 몇 시간짜리 아카이브 등급에 두면 그 목표는 이미 깨진 것이다.

## 📝 정리

**"얼마나 자주 꺼내느냐로 값을 다시 매긴 자리"** 라고 읽으면 된다. 등급을 내리면 보관비가 꺼내는 값과 최소 보관 기간으로 옮겨 갈 뿐 사라지지 않으니, 고를 때 세 자리를 함께 곱해 본다. 세 회사가 이름을 저마다 달리 붙였어도 칸은 같으므로 이름이 아니라 빈도를 외운다.

## 🧒 열 살에게

쓰지도 않는 겨울 이불을 방 한가운데 두면 자리가 아깝지? 그래서 값싼 창고에 맡기는데, 대신 꺼내러 갈 때마다 돈을 내고 한참 기다려야 해. 그러니까 얼마나 자주 꺼낼지를 먼저 세어 보고 어디에 둘지 정하는 거야.

## ❓ 이해했는지

- 한 달에 한 번은 읽어야 하는 파일을 가장 싼 아카이브 등급에 두면 왜 손해가 나나 → 흔한 오해
- 차가운 등급으로 내린 지 열흘 만에 지운 파일에 왜 요금이 더 붙나 → 작동 원리
- AWS 에서 쓰던 아카이브 등급을 Azure 에서 고르려면 어느 이름을 찾아야 하나 → 비교

## 🔗 관련 용어

- [[Object Storage]] — 등급이 붙는 대상. 오브젝트 하나하나가 제 등급을 갖는다
- [[S3]] — AWS 가 이 등급들을 파는 이름
- [[Storage Redundancy]] — 같은 저장소를 값이 아니라 여벌의 위치로 나눈 다른 축
- [[Egress Cost]] — 밖으로 내보낼 때 붙는 또 다른 값. 등급의 꺼내기 요금과 따로 센다
- [[FinOps]] — 등급 고르기를 한 번이 아니라 매달의 일로 만드는 자리
