# Object Versioning (객체 판 보관)

## 📝 정의

Object Versioning 은 덮어쓰거나 지운 옛 파일을 **그대로 남겨 두는** 설정이다.

같은 이름에 새 파일을 올리면 옛것이 사라지는 게 보통인데, 이걸 켜 두면 옛것이 판(version)으로 뒤에 남는다. AWS 는 S3 버전 관리, Azure 는 Blob 버전 관리, Google Cloud 는 객체 버전 관리라 부른다. 셋 다 목적이 같다 — 사람의 실수와 털린 계정을 견디는 것.

### 이름
Object :: 통에 넣은 덩어리
Version :: 그때그때의 판
-ing :: 계속 그러고 있음
= 붙여 읽으면 "덩어리를 판마다 계속 남겨 두기". 지운다는 말이 진짜 삭제가 아니게 된다

### 비유
앞장을 지우개로 지우는 대신 다음 장에 새로 적어 나가는 공책.

### 예
문서 편집기에서 실수로 다 지우고 저장했다가 "버전 기록" 에서 어제 것으로 되돌린 그 순간이다.

## 🖼️ 그림으로 보기

```도해
흐름: 같은 이름으로 다시 올리면 옛 파일은 어디로 가나
첫 올리기 :: 판 하나가 생기고 그게 지금 판이 된다
덮어쓰기 :: 새 판이 지금 판이 되고 옛 판은 뒤로 물러난다
지우기 :: 실제로 지우는 게 아니라 지움 표를 맨 위에 얹는다
되살리기 :: 그 표를 걷어내면 옛 판이 도로 지금 판이 된다
= 이름은 하나인데 그 밑에 판이 여러 장 쌓여 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 판을 안 남기면 실수로 덮어썼을 때 어떻게 되나
안 남기면 || 판을 남기면
덮어쓰기 :: 옛 내용은 없다 || 옛 판이 남는다
지우기 :: 그대로 사라진다 || 표만 얹힌다
털렸을 때 :: 한 번에 날아간다 || 옛 판이 버틴다
= 여러 벌 복제는 장치가 상하는 걸 막을 뿐, 사람이 지운 것은 못 막는다
```

오브젝트 스토리지는 같은 이름에 올리면 통째로 덮어쓴다. 가운데만 고치는 문이 없기 때문이다. 그래서 배포 스크립트 한 줄, 동기화 도구의 설정 하나가 수천 개 파일을 한 번에 덮어쓸 수 있다. 복제는 여기서 도움이 안 된다 — 복제본까지 똑같이 덮이기 때문이다.

판 보관은 이 구멍을 막는 거의 유일한 장치다. 덮어써도 옛 판이 남고, 지워도 지움 표가 얹힐 뿐이라 그 표만 걷어내면 돌아온다. 랜섬웨어가 파일을 통째로 암호화해 덮어써도 그 이전 판은 그대로 남는다. 개체 잠금이 판 단위로 걸리는 것도 이 때문이다.

## ⚙️ 작동 원리

판마다 고유한 이름표가 붙는다. AWS 는 버전 ID, Google 은 세대 번호(generation), Azure 는 고친 시각을 그대로 쓴 버전 ID 다. 이름표를 대면 그 판을 그대로 읽거나 지울 수 있고, 안 대면 지금 판에 대해 동작한다.

핵심은 판이 **차이분이 아니라는 것**이다. AWS 문서는 각 판이 통째로 한 개이며 이전 판과의 차이만 담은 것이 아니라고, 그래서 판이 셋이면 개체 세 개만큼 값을 낸다고 못 박는다. 이 한 문장이 요금과 운영을 거의 다 설명한다.

지우는 방식은 세 곳이 조금씩 다르다. AWS 는 지움 표(delete marker)를 얹어 그것이 지금 판이 되게 하고, Google 은 지금 판을 비현행 판으로 내려 보내며, Azure 는 지금 판을 이전 판으로 내리고 지금 판이 없는 상태로 만든다. 어느 쪽이든 되돌릴 때는 옛 판을 지금 판 자리로 올린다.

끄는 방법도 다르다. AWS 는 **한 번 켜면 안 켠 상태로 영영 못 돌아간다** — 끄는 게 아니라 일시 중지만 된다. Azure 와 Google 은 끌 수 있고, 끄더라도 이미 만들어진 판은 그대로 남는다.

## 📊 비교: 세 클라우드는 판을 어떻게 다루나

| | AWS S3 | Azure Blob | Google Cloud Storage |
|---|---|---|---|
| 켜는 자리 | 버킷 | 저장소 계정 | 버킷 |
| 판 이름표 | 버전 ID | 버전 ID(고친 시각) | 세대 번호 |
| 지웠을 때 | 지움 표가 맨 위에 얹힌다 | 지금 판이 이전 판으로 내려간다 | 지금 판이 비현행 판이 된다 |
| 되돌리는 법 | 지움 표를 지운다 | 이전 판을 복사해 새 지금 판으로 | 비현행 판을 복사해 덮는다 |
| 다시 끄기 | 못 끈다. 일시 중지만 된다 | 끌 수 있다. 기존 판은 남는다 | 끌 수 있다. 기존 판은 남는다 |
| 값 | 판마다 통째로 한 개 값 | 겹치지 않는 조각 단위로 매긴다 | 판마다 그 등급 값 그대로 |

## 💡 실제 사례

- **덮어쓰기 되돌리기** — 배포가 통째로 덮어쓴 정적 파일을 어제 판으로 되돌린다.
- **랜섬웨어 버티기** — 파일이 통째로 암호화돼 덮여도 그 이전 판이 남아 있어 그 시점으로 돌아간다.
- **잠금의 밑바탕** — 개체 잠금은 판 하나하나에 걸리므로 AWS 에서는 판 보관을 먼저 켜야 잠글 수 있다.

## 🚫 흔한 오해

- **켜 둬도 요금은 그대로다** — 판 하나가 통째로 한 벌이다. AWS 문서는 판이 셋이면 개체 셋만큼 값을 낸다고, 차이분이 아니라고 못 박는다.
- **지우면 지워진다** — 판 보관을 켠 통에서 그냥 지우면 지움 표가 얹힐 뿐 옛 판은 그대로 남아 계속 값이 나간다.
- **켰다가 마음에 안 들면 끄면 된다** — AWS 는 켠 뒤에 안 켠 상태로 돌아갈 수 없고 일시 중지만 된다. 켜기 전에 어느 통에 켤지부터 정해야 한다.

## 🚨 주의사항

- **자주 덮어쓰는 통에는 켜지 마라.** Azure 문서는 개체당 판이 많으면 목록 조회가 느려진다며 1,000판 이하를 권하고, 자주 덮어쓰는 자료는 판 보관을 끈 별도 계정에 두라고 적는다.
- **반드시 수명 규칙과 짝지어라.** 옛 판을 정리하는 규칙이 없으면 판은 무한히 쌓인다. Google 은 판 개수에 기본 한도가 없다고 적는다.
- **통이나 계정이 통째로 지워지는 건 못 막는다.** Azure 문서는 판 보관이 계정·컨테이너 삭제로부터는 지켜 주지 못하니 자원 잠금을 따로 걸라고 적는다.

## 📝 정리

**"이름은 하나인데 판이 쌓이는 그 설정"** 이라고 읽으면 된다. 판은 차이분이 아니라 통째로 한 벌이라 되돌리기는 확실하고 값은 정직하게 늘어난다. 그래서 이건 늘 두 벌로 쓴다 — 판을 남기는 설정과 옛 판을 정리하는 수명 규칙.

## 🧒 열 살에게

공책에 쓴 답을 고칠 때 지우개로 박박 지우면 원래 뭐라 썼는지 영영 못 보지? 그래서 앞장은 그대로 두고 다음 장에 새로 적는 거야. 그러면 잘못 고쳤다는 걸 나중에 알아도 앞장을 다시 펴면 돼.

## ❓ 이해했는지

- 파일을 지웠는데 요금이 안 줄어드는 이유는 무엇인가 → 흔한 오해
- 지운 파일을 되돌릴 때 실제로 무엇을 걷어내나 → 그림
- 자주 덮어쓰는 통에 이걸 켜면 무엇이 나빠지나 → 주의사항
