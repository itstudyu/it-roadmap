# Consistent Hashing (일관된 해싱)

## 📝 정의

Consistent Hashing은 **서버가 바뀌어도 대부분의 키가 제자리에 남는 분배 방식**이다.

서버 개수로 나눈 나머지를 쓰면 서버 하나만 늘어도 거의 모든 키의 담당이 바뀐다. 이 방식은 서버와 키를 같은 원 위에 올려두고 시계 방향으로 담당을 정한다.

### 비유
원형으로 늘어선 우편함. 새 우편함을 하나 끼워 넣어도 자리를 옮기는 건 그 앞 구간의 편지뿐이고 나머지는 그대로다.

## 🖼️ 그림으로 보기

```도해
흐름: 키 하나가 어느 서버로 갈지 어떻게 정해지나
키 :: 해시를 구해 원 위의 한 점으로 삼는다
원 :: 서버들도 각자 해시로 원 위에 놓여 있다
탐색 :: 그 점에서 시계 방향으로 돈다
탐색 :: 처음 만나는 서버가 담당이 된다
결과 :: 배치가 그대로면 같은 키는 늘 같은 곳으로
= 담당을 서버 개수가 아니라 원 위의 위치로 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버를 3대에서 4대로 늘리면 캐시는 어떻게 되나
나머지 연산 || 해시 링
옮기는 키 :: 거의 전부 || 한 구간만
캐시 적중 :: 바닥으로 || 대체로 유지
증설 직후 :: 원본에 몰림 || 평소와 비슷
= 서버 개수를 나눗셈에 쓰면 개수가 바뀔 때마다 전부 흔들린다
```

`key % 3` 으로 담당을 정하면 서버가 4대가 되는 순간 나머지 값이 전부 달라진다. 3으로 나눠 0이던 키가 4로 나누면 다른 값이 되고, 그렇게 거의 모든 키가 다른 서버로 옮겨간다. 캐시라면 전부 빈 상태가 되어 원본으로 요청이 한꺼번에 몰린다.

Consistent Hashing은 서버 개수를 계산에 넣지 않는다. 서버도 키도 같은 원 위의 점이라, 서버 하나를 끼워 넣으면 그 서버가 맡게 되는 구간의 키만 움직인다.

## ⚙️ 작동 원리

원 위에 서버를 하나씩만 올리면 위치가 우연히 몰려서 담당 구간이 고르지 않다. 한 서버가 절반을 맡고 다른 서버는 거의 놀게 된다.

그래서 서버 하나를 여러 개의 이름으로 원 위에 흩어 놓는다. 이렇게 복제한 점들을 가상 노드라고 한다. 개수를 늘릴수록 구간이 고르게 나뉘고, 서버가 빠질 때 그 몫도 남은 서버들에 골고루 흩어진다.

## 💡 실제 사례

- **캐시 서버 증설** — 서버를 늘리면서 기존 캐시 대부분을 살려서, 증설 직후 원본이 몰매를 맞는 일을 피한다.
- **분산 데이터베이스** — 어느 노드가 어느 키 구간을 맡을지 정하고, 노드를 더할 때 옮길 범위를 계산한다.
- **노드 장애 대응** — 노드 하나가 빠지면 그 구간만 시계 방향 이웃이 넘겨받고 나머지 배치는 그대로 둔다.

## 🚫 흔한 오해

- **이름처럼 특별한 해시 함수를 쓴다** — 해시 함수는 평범한 것을 쓴다. 달라지는 건 그 값을 서버에 어떻게 대응시키느냐다.
- **키가 서버마다 고르게 나뉜다** — 원 위 위치가 몰리면 한 서버가 훨씬 넓은 구간을 맡는다. 가상 노드를 여러 개 두는 이유가 그 쏠림을 없애기 위해서다.
- **서버가 바뀌어도 데이터는 안 옮겨진다** — 안 옮겨지는 게 아니라 적게 옮겨진다. 새로 들어온 서버가 맡을 구간의 키는 이동한다.

## 📊 비교

| | 나머지 연산 | Consistent Hashing |
|---|---|---|
| 담당 정하기 | 키를 서버 수로 나눈 나머지 | 원 위에서 시계 방향 |
| 서버 추가 시 | 거의 모든 키가 이동 | 한 구간만 이동 |
| 구현 | 한 줄 | 링과 가상 노드가 필요 |
| 맞는 상황 | 서버 수가 고정된 곳 | 서버가 드나드는 곳 |

## 📝 정리

Consistent Hashing은 서버와 키를 같은 원 위에 올려두고 시계 방향으로 담당을 정하는 방식이다. 서버 개수를 계산에 넣지 않아서, 서버가 드나들어도 움직이는 키가 한 구간으로 묶인다.

## ❓ 이해했는지

- 캐시 서버를 3대에서 4대로 늘렸더니 원본 부하가 치솟았다면 담당을 어떻게 정하고 있던 것인가 → 해결하는 문제
- 가상 노드를 두지 않으면 어떤 문제가 생기나 → 작동 원리
- 노드 하나가 빠지면 그 노드가 맡던 키는 어디로 가나 → 실제 사례
