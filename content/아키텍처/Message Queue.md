# Message Queue (메시지 큐)

## 📝 정의

Message Queue는 **할 일을 줄에 넣어두고 나중에 처리하게 하는 장치**다.

보내는 쪽은 줄에 넣고 바로 돌아온다. 받는 쪽은 자기 속도로 하나씩 꺼내 처리한다. 둘이 같은 시각에 살아 있지 않아도 된다.

### 이름
Message :: 남겨 둔 할 일 한 건
Queue :: 차례를 기다리는 줄
= 붙여 읽으면 "할 일이 차례를 기다리는 줄". 넣는 쪽과 꺼내는 쪽이 같은 시각에 살아 있지 않아도 된다

### 비유
음식점 주방의 주문서 꽂이. 홀 직원은 주문서를 꽂고 바로 다음 손님을 받는다. 주방은 꽂힌 순서대로 만든다. 주방이 바쁘다고 홀이 멈추지는 않는다.

### 예
가입 완료 화면은 바로 떴는데 인증 메일은 몇 분 뒤에 도착하는 것이 줄에서 기다린 흔적이다.

## 🖼️ 그림으로 보기

```도해
흐름: 회원가입 뒤 메일 발송이 어떻게 분리되나
사용자 :: 가입 버튼을 누른다
가입 서비스 :: DB에 저장하고 "메일 보내라" 를 큐에 넣는다
사용자 :: 가입 완료 화면을 즉시 본다
메일 워커 :: 큐에서 하나 꺼낸다
메일 워커 :: 메일을 보낸다. 3초 걸려도 상관없다
= 사용자를 기다리게 하는 일과 아닌 일을 갈라놓는 것이 핵심이다
```

## ⚠️ 해결하는 문제

```도해
대조: 무거운 일을 그 자리에서 처리하면 어떻게 되나
큐 없이 || 큐로
응답 시간 :: 메일 시간까지 포함 || 저장만 하고 끝
메일 서버 장애 :: 가입도 실패 || 가입은 성공
갑작스런 몰림 :: 서버가 무너진다 || 줄이 길어질 뿐
= 급한 일과 나중에 해도 되는 일을 갈라놓으면 둘 다 살아남는다
```

가입 처리 안에서 메일까지 보내면, 사용자는 메일이 나갈 때까지 화면 앞에서 기다린다. 메일 서버가 잠시 응답하지 않으면 가입 자체가 실패한다. 가입과 메일은 원래 함께 성공하거나 함께 실패할 이유가 없는 일이다.

큐를 두면 가입은 저장까지만 책임지고 끝난다. 메일은 나중에 처리되고, 실패하면 다시 시도하면 된다. 트래픽이 몰려도 큐가 길어질 뿐 서버가 무너지지 않는다.

## ⚙️ 작동 원리

메시지를 넣는 쪽을 프로듀서, 꺼내 처리하는 쪽을 컨슈머라고 한다. 컨슈머를 여러 개 띄우면 줄이 그만큼 빨리 줄어든다.

```도해
흐름: 메시지 하나가 어디를 지나나
프로듀서 :: 할 일을 만들어 큐에 넣는다
큐 :: 순서대로 쌓아둔다. 여기가 완충 지대
컨슈머 :: 하나씩 꺼내 처리한다
< 컨슈머 :: 성공했다고 큐에 알려야 그때 지워진다
= 확인이 오기 전까지 지우지 않는 덕에 컨슈머가 죽어도 일이 사라지지 않는다
```

처리에 실패한 메시지를 몇 번 재시도한 뒤에도 안 되면 따로 모아두는 곳을 둔다. 이걸 데드레터 큐라고 하고, 여기에 쌓인 것을 보는 게 운영의 절반이다.

## 💡 실제 사례

- **알림 발송** — 이메일, 푸시, 문자를 큐에 넣고 워커가 처리한다. 실패하면 재시도한다.
- **이미지 변환** — 업로드는 즉시 끝내고 썸네일 생성은 큐로 넘긴다.
- **주문 처리** — 결제 완료 메시지를 큐에 넣으면 재고, 배송, 정산이 각자 꺼내 처리한다.

## 🚫 흔한 오해

- **큐를 쓰면 빨라진다** — 전체 처리 시간은 그대로거나 오히려 길다. 짧아지는 건 사용자가 기다리는 시간뿐이다.
- **순서가 항상 지켜진다** — 컨슈머를 여러 개 띄우면 처리 순서가 섞인다. 순서가 중요하면 키를 정해 같은 줄로 몰아야 한다.
- **한 번만 처리된다** — 대부분의 큐는 "최소 한 번"을 보장한다. 같은 메시지가 두 번 올 수 있으니 두 번 처리해도 결과가 같게 만들어야 한다.

## 🚨 주의사항

- **중복 처리를 대비한다.** 결제 메시지를 두 번 받아 두 번 결제하는 사고가 여기서 나온다. 처리한 메시지 ID를 기록해 걸러낸다.
- **데드레터 큐를 본다.** 아무도 안 보면 실패한 일들이 조용히 쌓인다.

## 📝 정리

**"넣어두고 먼저 가는 그 줄"** 이라고 읽으면 된다. 할 일을 줄에 넣어 보내는 쪽과 처리하는 쪽을 떼어놓는다. 사용자 응답은 빨라지고 장애는 번지지 않지만, 순서와 중복은 직접 챙겨야 한다.

## 🧒 열 살에게

음식점에서 홀 직원이 주문서를 주방에 꽂아 두고 바로 다음 손님을 받으러 가지? 주방이 아무리 바빠도 홀은 안 멈춰. 대신 음식은 꽂힌 순서가 올 때까지 기다렸다 나오니까, 자리에는 금방 앉아도 먹는 건 좀 뒤야.

## ❓ 이해했는지

- 큐를 넣었는데 전체 처리 시간이 안 줄었다면 정상인가 → 흔한 오해
- 결제 메시지가 두 번 도착하면 무슨 일이 벌어지고, 어떻게 막나 → 주의사항
- 컨슈머가 처리 도중 죽으면 그 메시지는 어떻게 되나 → 작동 원리
