# LangGraph

## 📝 정의

LangGraph는 **LLM 앱의 흐름을 그래프로 적어 실행하는 도구**다.

질문을 분류하고 자료를 찾고 답을 만들고 검증하는 식으로 단계가 늘어나면 조건문이 겹겹이 쌓여 어디로 흘러가는지 읽기 어려워진다. LangGraph는 그 단계를 노드로, 이동을 엣지로 따로 적게 한다.

### 비유
지하철 노선도. 역과 이어진 선만 그려두면 어디서 어디로 갈 수 있는지가 그림 하나로 보인다.

### 예
AI 챗봇이 답을 내기 전에 자료 찾는 중과 정리하는 중을 차례로 보여주는 그 단계들이다.

## 🖼️ 그림으로 보기

```도해
흐름: 질문 하나가 그래프를 어떻게 지나가나
상태 :: 질문과 중간 결과를 담을 그릇을 만든다
노드 :: 할 일 하나를 함수로 등록한다
엣지 :: 이 노드 다음에 어디로 갈지 잇는다
분기 :: 상태를 보고 갈래를 고르게 한다
실행 :: 시작 값을 넣으면 끝 노드까지 흘러간다
@ 되돌림 :: 답이 부족하면 앞 노드로 돌아가 한 바퀴 더
= 각 노드는 상태를 받아 고쳐 넘긴다. 흐름은 코드가 아니라 그래프에 적혀 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 단계가 늘어나면 코드는 어떻게 되나
조건문으로 || 그래프로
흐름 파악 :: 코드를 다 읽음 || 그림으로 보임
단계 추가 :: 분기를 파고듦 || 노드 하나 추가
중간 상태 :: 변수로 흩어짐 || 한 곳에 모임
= 흐름을 코드에서 떼어내 따로 적어두면 고칠 자리가 한 곳으로 모인다
```

에이전트는 대개 한 번에 끝나지 않는다. 질문을 분류하고, 필요하면 자료를 찾고, 답을 만들고, 마음에 안 들면 다시 찾는다. 이걸 조건문으로 짜면 되돌아가는 길이 생길 때마다 중첩이 깊어진다.

LangGraph는 할 일을 노드로 등록하고 이동을 엣지로 잇는다. 무엇을 하는지와 어디로 가는지가 나뉘므로, 단계를 하나 더 붙일 때 기존 함수를 건드리지 않는다.

## ⚙️ 작동 원리

```python
graph = StateGraph(State)
graph.add_node("retrieve", retrieve_docs)
graph.add_node("generate", generate_answer)
graph.add_edge("retrieve", "generate")

result = graph.invoke({"question": "RAG가 뭐에요?"})
```

상태는 그래프 전체가 함께 쓰는 그릇이다. 각 노드는 상태를 받아 자기 몫을 채워 넣고 다음 노드로 넘긴다. 노드끼리 값을 직접 주고받지 않기 때문에, 순서를 바꾸거나 중간에 하나를 끼워 넣어도 함수를 고칠 일이 적다.

엣지는 고정으로 이을 수도 있고, 상태를 보고 갈래를 고르게 할 수도 있다. 뒤쪽이 있어서 앞 노드로 되돌아가는 흐름을 만들 수 있고, 그래서 반복해서 다듬는 에이전트를 짤 수 있다.

## 💡 실제 사례

- **검색 후 답변** — 자료를 찾는 노드와 답을 만드는 노드를 잇고, 찾은 게 부족하면 검색 노드로 되돌린다.
- **질문 분류** — 첫 노드에서 질문 종류를 가르고, 종류마다 다른 노드로 보낸다.
- **검증 단계** — 답을 만든 뒤 확인하는 노드를 붙이고, 통과하지 못하면 다시 만들게 한다.

## 🚫 흔한 오해

- **LangGraph가 답을 만들어준다** — 만들지 않는다. 어느 순서로 무엇을 부를지를 관리할 뿐이고, 답은 안에 등록한 함수와 모델이 만든다.
- **그래프니까 순서가 한 줄로 정해진다** — 상태를 보고 갈래를 고르거나 앞 노드로 되돌아가게 만들 수 있다. 되돌아가는 길이 있어서 에이전트가 된다.
- **LangChain을 대체하는 것이다** — 대체가 아니다. LangChain 쪽이 상위 프레임워크이고, LangGraph는 그 안에서 흐름을 맡는 자리다.

## 📝 정리

LangGraph는 LLM 앱의 단계를 노드로, 이동을 엣지로 적어 실행하는 도구다. 흐름이 코드가 아니라 그래프에 적혀 있어서 단계를 붙이거나 되돌리는 길을 만들기 쉽다. 답을 만드는 일 자체는 안에 등록한 함수가 한다.

## ❓ 이해했는지

- 조건문으로 짠 에이전트에 단계를 하나 더 붙일 때 그래프 쪽이 편한 이유는 → 해결하는 문제
- 노드끼리 값을 직접 주고받지 않는데 앞 노드의 결과를 어떻게 쓰나 → 작동 원리
- 답이 이상하게 나올 때 LangGraph 쪽만 고쳐서는 소용없는 이유는 → 흔한 오해
