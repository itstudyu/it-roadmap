# API 외부 공개 (로컬 API 를 남이 쓰게 하기)

## 📝 정의

API 외부 공개는 **내 컴퓨터에만 있던 API 를 인터넷에서 부를 수 있게 하는 일**이다.

`localhost` 는 그 컴퓨터 안에서만 통하는 주소다. 다른 사람이 부르게 하려면 공인 IP 가 있는 자리에 코드를 올리고, 이름과 암호화와 인증을 차례로 얹어야 한다.

### 비유
집에서 만든 음식은 가족만 먹는다. 손님을 받으려면 가게 자리를 얻고 간판을 달고 위생 검사를 받아야 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 로컬에서 만든 API 를 남이 부르려면 무엇이 필요하나
내 PC :: localhost 는 이 컴퓨터 안에서만 통한다
서버 :: 공인 IP 가 있는 자리에 코드를 올린다
도메인 :: IP 대신 이름으로 찾아오게 한다
인증서 :: HTTPS 로 오가는 내용을 가린다
관문 :: 키를 확인하고 호출 횟수를 센다
< 외부 사용자 :: 이제 주소만 알면 부를 수 있다
= 코드를 다 짜도 이 다섯 자리를 지나야 남이 쓸 수 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 로컬에만 있는 API 는 무엇을 못 하나
공개 전 || 공개 후
접근 범위 :: 내 컴퓨터만 || 어디서나
전달 방법 :: 파일로 넘김 || 주소로 호출
내 PC 를 끄면 :: 바로 끊긴다 || 계속 떠 있다
= 코드가 도는 것과 남이 쓸 수 있는 것은 다른 문제다
```

API 를 다 만들어도 팀원이 그 주소를 열면 아무것도 뜨지 않는다. `127.0.0.1` 은 "이 컴퓨터"를 가리키는 주소라, 각자의 컴퓨터에서 각자의 컴퓨터를 가리킬 뿐이다.

외부 공개는 그 주소를 바깥에서 닿을 수 있는 것으로 바꾸는 작업이다. 주소가 생기면 그다음 문제가 따라온다. 누가 부르는지 확인해야 하고, 오가는 내용을 가려야 하고, 한 사람이 초당 수백 번 부르는 것을 막아야 한다.

## ⚙️ 작동 원리

```도해
층: 공개하는 방법은 어디까지 갈 수 있나
터널링 :: ngrok 이 임시 주소를 내준다. 끄면 회수된다
클라우드 :: 공인 IP 를 받은 서버에 코드를 올린다
도메인 :: DNS 에 이름을 등록하고 인증서를 붙인다
관문 :: API Gateway 가 키와 호출 제한과 로그를 맡는다
= 위는 몇 분이면 되고, 아래로 갈수록 준비가 늘지만 오래 간다
```

ngrok 은 로컬 포트와 인터넷을 잇는 터널을 만든다. 설치하고 한 줄만 치면 `https://...` 로 시작하는 주소가 생기지만, 끄면 그 주소는 회수된다. 시연과 잠깐의 공유용이다.

계속 떠 있어야 하면 클라우드에 인스턴스를 만들고 공인 IP 를 받는다. IP 를 그대로 알려주는 대신 도메인을 등록하고, Let's Encrypt 나 클라우드가 주는 인증서로 HTTPS 를 건다. 마지막으로 API Gateway 를 앞에 두면 클라이언트마다 키를 발급하고 호출 횟수를 세는 일을 코드 밖에서 처리할 수 있다.

## 📊 비교

| | localhost | ngrok | 클라우드 서버 |
|---|---|---|---|
| 외부 접근 | 안 됨 | 임시 주소 | 계속 유지 |
| 도메인 | 필요 없음 | 필요 없음 | 등록해야 함 |
| HTTPS | 필요 없음 | 자동 | 인증서 설치 |
| 어디에 쓰나 | 개발 중 | 시연, 테스트 | 실제 서비스 |

## 💡 실제 사례

- **팀 리뷰** 만든 API 를 리더가 확인해야 할 때 ngrok 주소를 띄워 그 자리에서 눌러보게 한다.
- **테스트 환경** 클라우드에 인스턴스를 하나 두고 `test-api` 같은 도메인을 붙여 내부 인원이 계속 쓰게 한다.
- **외부 고객 연동** API Gateway 를 앞에 두고 고객사마다 키를 발급한 뒤, 키별로 분당 호출 수를 정해둔다.

## 🚫 흔한 오해

- **서버에 올리고 주소만 알려주면 끝이다** — 인증을 안 걸면 주소를 아는 누구나 데이터를 가져간다. 공개는 시작이고 그다음이 인증과 제한이다.
- **ngrok 주소를 그대로 서비스에 쓰면 된다** — 끄고 켤 때마다 주소가 바뀐다. 문서나 앱에 박아두면 다음 날 전부 끊긴다.
- **HTTPS 는 있으면 좋은 것이다** — 브라우저가 HTTP 요청을 막는다. 인증 정보가 평문으로 오가는 것도 문제라 선택 사항이 아니다.

## 🚨 주의사항

- **공개 전에 열려 있는 포트를 확인한다.** 데이터베이스 포트까지 같이 열려 있는 사고가 흔하다.
- **키 없이 부를 수 있는 경로가 남았는지 본다.** 인증을 붙여도 한 곳이 뚫려 있으면 나머지가 무의미하다.

## 📝 정리

API 외부 공개는 로컬에서 도는 코드를 바깥에서 부를 수 있는 주소로 옮기는 일이다. 터널링은 몇 분이면 되지만 임시고, 계속 쓸 것이라면 서버와 도메인과 인증서와 관문을 차례로 붙여야 한다. 주소가 생긴 순간부터 인증과 호출 제한이 같이 필요해진다.

## ❓ 이해했는지

- 팀원에게 `localhost:3000` 주소를 알려줬는데 접속이 안 된다. 왜 그런가?
- 시연용으로 만든 ngrok 주소를 문서에 적어두면 며칠 뒤 무엇이 문제가 되나?
- 한 사용자가 초당 수백 번 API 를 부르고 있다. 코드를 고치지 않고 어디서 막나?
