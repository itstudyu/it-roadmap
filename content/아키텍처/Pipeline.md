# Pipeline (파이프라인)

## 📝 정의

Pipeline은 **작업을 단계로 나눠 차례로 흘려보내는 구조**다.

앞 단계의 결과가 뒤 단계의 입력이 된다. 단계마다 맡은 일이 하나씩이라 어디서 멈췄는지 바로 보이고, 멈춘 자리부터 다시 돌릴 수 있다.

### 이름
Pipe :: 흘려보내는 관
line :: 죽 이어 놓은 줄
= 붙여 읽으면 "죽 이어 놓은 관". 앞자리가 내놓은 것이 다음 자리로 그대로 흘러 들어간다

### 비유
공장 컨베이어 벨트. 한 사람이 완제품을 만들지 않고, 각 자리가 자기 몫만 하고 다음으로 넘긴다.

### 예
올린 영상이 한동안 저화질로만 보이다가 고화질이 뒤늦게 열리는 것이 단계가 차례로 도는 모습이다.

## 🖼️ 그림으로 보기

```도해
흐름: 원본 데이터가 저장되기까지 무엇을 거치나
수집 :: 여기저기서 원본 데이터를 가져온다
정제 :: 빠진 값과 중복을 걷어낸다
변환 :: 쓰기 좋은 형태로 바꾼다
집계 :: 필요한 단위로 묶어 계산한다
저장 :: 결과를 목적지에 넣는다
재실행 :: 실패한 단계부터만 다시 돌린다
= 나뉘어 있으니 어디서 멈췄는지와 어디부터 다시 할지를 알 수 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 전부 한 스크립트에 적어두면 무엇이 달라지나
한 덩어리로 || 파이프라인으로
실패했을 때 :: 처음부터 다시 || 그 단계부터
멈춘 자리 :: 로그를 뒤진다 || 단계가 표시됨
한 곳만 수정 :: 전체를 건드림 || 그 단계만
= 나누는 값은 속도가 아니라 되돌릴 수 있다는 것이다
```

데이터를 받아 정제하고 변환해서 저장하는 일을 스크립트 하나에 다 적으면, 세 시간짜리 작업이 마지막 저장에서 실패했을 때 처음부터 다시 돌려야 한다. 어디가 문제였는지도 로그를 처음부터 읽어야 안다.

파이프라인은 그 일을 끊어놓는다. 단계마다 성공과 실패가 따로 기록되므로 실패한 곳부터 다시 돌릴 수 있고, 정제 방식만 바꾸고 싶을 때 그 단계만 손대면 된다.

## ⚙️ 작동 원리

단계 사이에는 지켜야 할 것이 하나 있다. 앞 단계가 내놓는 형태와 뒤 단계가 받는 형태가 맞아야 한다. 이 약속이 지켜지면 중간에 단계를 끼워 넣거나 빼도 나머지는 그대로 돈다.

실행하는 방법은 여러 가지다. 함수를 정해진 순서로 부르는 것도 파이프라인이고, CI/CD 도구에 build, test, deploy 를 적어두고 도구가 순서와 실패 처리를 맡게 하는 것도 파이프라인이다. 앞의 결과를 뒤가 받는다는 뼈대는 같다.

## 💡 실제 사례

- **CI/CD** — 커밋이 올라오면 빌드, 테스트, 배포가 차례로 돈다. 테스트에서 멈추면 배포는 시작조차 하지 않는다.
- **데이터 처리** — 수집, 정제, 변환, 저장을 나눠 두고 매일 정해진 시각에 돌린다. 변환에서 실패하면 그 단계부터 다시 돌린다.
- **이미지 업로드** — 올린 파일을 검사하고, 크기를 줄이고, 저장소에 넣고, 주소를 DB에 적는 순서로 흘려보낸다.

## 🚫 흔한 오해

- **파이프라인으로 바꾸면 빨라진다** — 단계를 나눈다고 총 작업량이 줄지는 않는다. 얻는 것은 멈춘 자리를 알고 거기서부터 다시 돌릴 수 있다는 것이다.
- **단계는 잘게 나눌수록 좋다** — 단계마다 넘기고 받는 비용이 붙는다. 같이 실패하고 같이 다시 돌려야 하는 일은 한 단계에 두는 편이 낫다.
- **파이프라인은 CI/CD 를 가리키는 말이다** — CI/CD 가 파이프라인을 쓰는 한 가지 경우일 뿐이다. 데이터 처리나 이미지 변환에도 같은 구조가 쓰인다.

## 📝 정리

**"앞이 내놓은 것을 뒤가 받는 그 줄"** 이라고 읽으면 된다. 나누는 이유는 속도가 아니라 어디서 멈췄는지 알고 거기서부터 다시 돌리기 위해서다. 단계 사이에 주고받는 형태만 맞으면 중간을 갈아 끼울 수 있다.

## 🧒 열 살에게

공장에서는 한 사람이 물건을 처음부터 끝까지 다 만들지 않고, 벨트를 따라 자리마다 자기 몫만 하고 다음 자리로 넘기지? 그러면 어느 자리에서 잘못됐는지 딱 보여. 그 자리부터 다시 하면 되니까 처음부터 도로 만들지 않아도 돼.

## ❓ 이해했는지

- 세 시간짜리 작업이 마지막 단계에서 실패했다. 파이프라인이면 무엇이 달라지나 → 해결하는 문제
- 단계를 무조건 잘게 나누면 왜 손해가 생기나 → 흔한 오해
- 중간 단계 하나를 갈아 끼워도 나머지가 그대로 도는 조건은 → 작동 원리
