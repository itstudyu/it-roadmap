# Service Discovery (서비스 디스커버리)

## 📝 정의

Service Discovery는 **서비스가 지금 어디 있는지 찾아주는 장치**다.

서비스를 여러 개로 나누고 컨테이너로 띄우면 주소가 계속 바뀐다. 재시작할 때마다 IP가 달라지고 대수도 늘었다 줄었다 하는데, 부르는 쪽 코드에 주소를 박아두면 그때마다 끊긴다.

### 비유
회사 내선 안내판. 자리가 바뀌어도 안내판만 고쳐두면 이름만 알고 찾아갈 수 있다.

### 예
서버 대수가 밤새 늘었다 줄었다 했는데 부르는 쪽 설정에 적힌 주소는 그대로다.

## 🖼️ 그림으로 보기

```도해
흐름: 주소가 계속 바뀌는 서비스를 어떻게 찾아 부르나
결제 :: 뜨자마자 이름과 주소를 등록한다
레지스트리 :: 주기적으로 살아 있는지 물어 명단을 고친다
주문 :: 부르기 전에 "결제 어디 있나" 를 묻는다
< 레지스트리 :: 살아 있는 주소를 돌려준다. 주문은 그리로 부른다
= 부르는 쪽이 아는 것은 주소가 아니라 이름뿐이다
```

## ⚠️ 해결하는 문제

```도해
대조: 주소를 코드에 박아두면 어떻게 되나
주소를 박아두면 || 등록해서 찾으면
재시작 :: 연결이 끊긴다 || 새 주소로 간다
대수 늘리기 :: 설정을 다 고친다 || 등록만 하면 끝
죽은 서버 :: 그대로 부른다 || 명단에서 빠진다
= 주소가 자주 바뀌는 곳에서는 이름으로 부르게 만들어야 한다
```

주문 서비스가 결제 서비스를 `192.168.1.100:8080`으로 부르고 있었다면, 결제 서비스를 재시작해 IP가 바뀌는 순간 호출이 실패한다. 대수를 늘릴 때도 부르는 쪽 설정을 전부 찾아 고쳐야 한다.

레지스트리를 두면 이 일이 없어진다. 서비스는 뜰 때 자기 이름과 주소를 올리고, 부르는 쪽은 이름으로 물어 지금 쓸 수 있는 주소를 받는다.

## ⚙️ 작동 원리

레지스트리가 맡는 일은 넷이다.

- **등록** — 서비스가 뜰 때 이름과 주소를 올린다.
- **헬스체크** — 10초마다 살아 있는지 물어본다.
- **조회** — 이름을 주면 지금 쓸 수 있는 주소를 돌려준다.
- **해지** — 답이 없거나 내려가면 명단에서 뺀다.

명단이 실제와 어긋나면 없느니만 못하다. 헬스체크와 해지가 그걸 막는 자리다.

누가 레지스트리에 묻느냐로 두 가지가 갈린다. 부르는 쪽이 직접 물어 주소를 받아 호출하는 방식은 구조가 단순한 대신 서비스마다 그 코드를 넣어야 한다. 앞에 로드 밸런서를 세워 대신 묻게 하면 부르는 쪽은 아무것도 몰라도 되지만 그 장비가 하나 더 필요하다.

## 💡 실제 사례

- **대수 늘리기** — 부하가 늘어 인스턴스가 세 대 더 떠도 각자 등록하니 부르는 쪽은 고칠 게 없다.
- **배포** — 새 버전을 띄워 등록한 뒤 옛 인스턴스를 명단에서 빼면 요청이 그쪽으로 옮겨간다.
- **장애 격리** — 헬스체크에 답하지 않는 인스턴스는 명단에서 빠져 요청을 받지 않는다.

## 🚫 흔한 오해

- **디스커버리가 부하도 나눠준다** — 어디 있는지 알려주는 데까지가 일이다. 받은 주소가 여럿일 때 어디로 보낼지 고르는 것은 로드 밸런싱이고, 붙어 다닐 뿐 같은 일은 아니다.
- **한 번 등록해두면 명단은 알아서 맞는다** — 서버가 갑자기 죽으면 스스로 해지하지 못한다. 레지스트리가 주기적으로 물어보고 답이 없는 것을 빼기 때문에 명단이 실제와 맞는 것이다.
- **서비스가 몇 개 안 되면 안 써도 된다** — 개수가 아니라 주소가 바뀌느냐의 문제다. 컨테이너는 재시작할 때마다 주소가 달라져서 서비스가 둘이어도 필요해진다.

## 📝 정리

Service Discovery는 이름으로 부르면 지금 살아 있는 주소를 돌려주는 명단이다. 서비스가 뜰 때 등록하고 헬스체크로 죽은 것을 빼기 때문에 주소가 바뀌어도 부르는 쪽 코드는 그대로다.

## ❓ 이해했는지

- 결제 서비스를 재시작해 IP가 바뀌었는데 주문 서비스 코드를 안 고쳐도 되는 이유는 → 해결하는 문제
- 서버가 갑자기 죽었을 때 명단에서 빠지는 것은 무엇 덕분인가 → 작동 원리
- 주소를 여러 개 받아온 다음 그중 어디로 보낼지 정하는 것은 어디가 하는 일인가 → 흔한 오해
