# API (Application Programming Interface)

## 📝 정의

API는 **다른 프로그램의 기능을 빌려 쓰는 창구**다.

날씨 기능을 앱에 넣으려고 관측 데이터를 모으고 예측 알고리즘을 만들면 몇 달이 걸린다. 날씨 API를 부르면 그 기능을 그대로 빌려 쓴다. 안쪽이 어떻게 생겼는지는 몰라도 된다.

### 비유
식당 메뉴판. 주방에 들어가 요리하는 대신 메뉴판에 적힌 이름을 대면 음식이 나온다. 주방 설비가 바뀌어도 메뉴판이 그대로면 손님은 아무것도 안 바꿔도 된다.

## 🖼️ 그림으로 보기

```도해
흐름: 앱에 날씨를 붙이면 무슨 순서로 오가나
내 앱 :: "서울 날씨 줘" 라고 요청을 보낸다
API :: 정해진 형식인지 확인하고 안쪽에 넘긴다
날씨 서버 :: 관측값을 찾아 결과를 만든다
API :: 약속한 형식으로 포장해서 돌려준다
< 내 앱 :: 받은 값에서 온도만 꺼내 화면에 쓴다
= 안쪽을 몰라도 창구 쓰는 법만 알면 된다
```

## ⚠️ 해결하는 문제

```도해
대조: 남이 만든 기능을 쓰려면 어떻게 해야 하나
API 없이 || API 로
날씨 기능 :: 직접 다 만든다 || 불러 쓴다
상대의 변경 :: 같이 깨진다 || 창구는 그대로
연동 방식 :: 서비스마다 제각각 || 정해진 규칙
= 창구를 정해두면 안쪽이 바뀌어도 쓰는 쪽이 안 흔들린다
```

기능을 하나 붙일 때마다 처음부터 만들면 시간이 아무리 많아도 모자란다. 지도, 결제, 번역, 인증은 이미 잘 만들어진 것이 있고 그걸 부르는 편이 낫다.

혼자 만든 코드 안에서도 마찬가지다. 함수 이름과 넘길 값만 정해두면, 그 함수를 나중에 통째로 다시 짜도 부르는 쪽 코드는 손댈 필요가 없다. API가 하는 일은 결국 이 경계를 그어두는 것이다.

## ⚙️ 작동 원리

웹 API는 대개 HTTP로 오간다. 주소로 무엇을 다룰지 정하고, 메서드로 무엇을 할지 정한다.

```
GET    /users/123     123번 사용자를 가져온다
POST   /users         새 사용자를 만든다
DELETE /users/123     123번 사용자를 지운다
```

같은 주소에 메서드만 바꿔 보내면 다른 일이 일어난다. 이렇게 주소를 자원 이름으로 쓰는 방식이 [[REST]]다. 응답은 보통 [[JSON]]으로 온다.

## 💡 실제 사례

- **지도 붙이기** — 지도 API에 좌표를 보내면 지도 조각을 돌려준다. 지도 데이터를 직접 갖지 않아도 화면에 지도가 뜬다.
- **결제** — 카드 정보는 결제사 쪽으로 바로 보내고 우리 서버는 결과만 받는다. 민감한 값을 우리가 들고 있지 않아도 된다.
- **사내 서비스 사이** — 주문 서비스가 재고 서비스의 API를 부른다. 재고 쪽이 데이터베이스를 바꿔도 주문 쪽은 그대로 돈다.

## 🚫 흔한 오해

- **API는 웹에서만 쓰는 말이다** — 아니다. 라이브러리가 열어둔 함수도 API고, 운영체제가 프로그램에 열어주는 창구도 API다. 웹 API가 흔해서 그렇게 보일 뿐이다.
- **API를 붙이면 그 기능이 내 서버로 들어온다** — 들어오지 않는다. 계산은 여전히 상대 서버에서 일어나고, 그쪽이 멈추면 내 화면의 그 부분도 같이 멈춘다.
- **주소만 알면 아무나 부를 수 있다** — 대개 키가 있어야 한다. 주소는 창구 위치일 뿐이고 통과 여부는 키와 권한이 정한다.

## 📝 정리

API는 프로그램 사이에 그어둔 경계이자 그 경계를 넘는 방법이다. 부르는 쪽은 안쪽 구현을 몰라도 되고, 만드는 쪽은 창구만 지키면 안을 마음대로 바꿀 수 있다.

## ❓ 이해했는지

- 날씨가 나오던 화면이 갑자기 비었다면 어디를 먼저 의심해야 하나 → 흔한 오해
- 상대 서비스가 내부 계산 방식을 고쳤는데 내 코드를 안 바꿔도 되는 이유는 → 해결하는 문제
- 같은 `/users/123` 주소로 보낸 두 요청이 서로 다른 일을 한다. 무엇이 그것을 정하나 → 작동 원리

## 🔗 관련 용어

- [[REST]] — 주소를 자원 이름으로 쓰는 대표적인 API 설계 방식
- [[HTTP]] — 웹 API의 요청과 응답을 실어 나르는 규약
- [[JSON]] — API가 주고받는 값을 담는 형식
- [[GraphQL]] — 필요한 필드만 골라 받는 다른 방식의 API
- [[API Gateway]] — 여러 API 앞에 서서 인증과 제한을 대신 맡는 자리
