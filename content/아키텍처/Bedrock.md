# AWS Bedrock

## 📝 정의

Bedrock은 **여러 회사의 AI 모델을 한 API로 부르는 AWS 서비스**다.

모델을 직접 돌리려면 GPU 서버를 사고 모델을 설치하고 사용량에 맞춰 늘렸다 줄였다 해야 한다. Bedrock은 그 일을 AWS가 맡고, 쓰는 쪽은 요청을 보내고 응답을 받는 일만 한다.

### 비유
여러 브랜드를 함께 파는 대리점. 제품마다 본사를 찾아가지 않고 한 창구에서 고른다.

## 🖼️ 그림으로 보기

```도해
흐름: 내 코드가 모델을 부를 때 어디를 거치나
내 코드 :: 질문과 함께 요청을 보낸다
Bedrock :: `modelId` 로 어느 모델인지 고른다
모델 :: AWS 안에서 실행되고 답을 만든다
< Bedrock :: 같은 형식으로 응답을 돌려준다
= 다른 모델로 갈아타도 바뀌는 건 이름 한 줄이다
```

## ⚠️ 해결하는 문제

```도해
대조: LLM 을 직접 돌리려면 무엇이 필요한가
직접 운영 || Bedrock 으로
시작 준비 :: GPU 서버부터 || API 호출부터
모델 교체 :: 새로 설치한다 || 이름만 바꾼다
네트워크 :: 직접 구성한다 || VPC 안에서
= 모델을 굴리는 일을 넘기고 부르는 일만 남긴다
```

모델 하나를 직접 서비스에 올리려면 GPU 서버를 마련하고, 모델을 내려받아 설치하고, 요청이 몰릴 때 서버를 늘리는 장치까지 붙여야 한다. 모델을 바꾸고 싶으면 그 과정을 처음부터 다시 한다.

Bedrock은 그 자리를 API 호출로 바꾼다. 서버도 설치도 확장도 AWS 쪽에 있고, 쓰는 쪽에 남는 것은 어느 모델을 부를지 정하는 일이다.

## ⚙️ 작동 원리

호출은 `modelId`로 모델을 지정하고 메시지를 넘기는 형태다.

```python
import boto3

bedrock = boto3.client('bedrock-runtime')

response = bedrock.invoke_model(
    modelId='anthropic.claude-3-sonnet-20240229-v1:0',
    body={
        "messages": [{"role": "user", "content": "안녕하세요"}],
        "max_tokens": 1000
    }
)
```

모델을 바꾸려면 `modelId` 문자열을 바꾼다. 호출하는 코드의 모양은 그대로다.

## 📊 비교

| 항목 | Bedrock | 모델 회사 API 직접 호출 |
|---|---|---|
| 제공사 | AWS | 모델을 만든 회사 |
| 모델 | Claude, Llama 등 여러 곳 | 그 회사 모델만 |
| 통신 경로 | VPC 안에 둘 수 있다 | 인터넷을 통해 나간다 |
| 계정 | 쓰던 AWS 계정 그대로 | 따로 만든다 |

## 💡 실제 사례

- **사내 문서를 다루는 기능** — 통신이 VPC 안에서 끝나도록 잡으면 문서가 인터넷으로 나가지 않는다.
- **모델 갈아타며 시험하기** — 응답이 마음에 안 들 때 `modelId`만 바꿔서 같은 코드로 다른 모델을 시험한다.
- **이미 AWS를 쓰는 서비스** — 별도 연동 없이 같은 계정과 권한 안에서 모델을 부른다.

## 🚫 흔한 오해

- **Bedrock이 만든 모델을 쓰는 것이다** — Bedrock은 모델을 만들지 않는다. Claude나 Llama처럼 다른 곳이 만든 모델을 AWS 안에서 부를 수 있게 모아둔 창구다.
- **관리형이니 모델도 알아서 골라준다** — 어느 모델을 쓸지는 부르는 쪽이 `modelId`로 지정한다. 대신해주는 건 서버와 확장이지 선택이 아니다.
- **내 서버 안에서 모델이 도는 것이다** — 모델은 AWS가 관리하는 쪽에서 돈다. 통신이 밖으로 나가지 않게 경로를 잡을 수는 있지만 모델이 내 서버에 설치되는 건 아니다.

## 📝 정리

Bedrock은 여러 회사의 AI 모델을 AWS 안에서 하나의 API로 부르게 해주는 서비스다. 서버와 설치와 확장을 넘기는 대신, 어느 모델을 쓸지 고르는 일은 그대로 남는다. 통신을 VPC 안에 둘 수 있어서 데이터를 밖으로 내보내지 않는 구성이 가능하다.
