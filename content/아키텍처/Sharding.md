# Sharding (샤딩)

## 📝 정의

Sharding은 **하나의 데이터베이스를 여러 대로 쪼개 나눠 담는 것**이다.

사용자 1번부터 백만 번까지는 A 서버, 백만 한 번부터는 B 서버에 둔다. 각 서버는 전체의 일부만 갖고 있어서 그만큼 가볍다.

### 이름
= Shard 는 깨진 그릇의 조각 하나를 뜻하는 말이다. 그릇 하나를 조각으로 갈라 나눠 담는다는 그림이 이름에 그대로 들어 있다

### 비유
도서관의 분관. 장서가 백만 권이 되면 한 건물에 다 넣을 수 없다. ㄱ부터 ㅅ은 본관, ㅇ부터 ㅎ은 분관에 두면 각 건물은 감당할 만해진다. 대신 어느 책이 어디 있는지 아는 규칙이 있어야 한다.

### 예
게임에 들어갈 때 서버를 먼저 고르게 하고 다른 서버 친구와는 못 만나는 그 구조와 같다.

## 🖼️ 그림으로 보기

```도해
흐름: 사용자 정보를 찾을 때 어느 서버로 가나
앱 :: 사용자 ID 8,451,203 번 정보를 찾는다
샤드 규칙 :: ID 를 샤드 수로 나눈 나머지를 본다
샤드 규칙 :: 나머지가 3 이다. 4번 서버 담당
4번 서버 :: 자기가 가진 25만 건 안에서 찾는다
< 앱 :: 결과를 받는다. 몇 번 서버였는지는 몰라도 된다
= 어느 서버에 있는지 계산으로 알 수 있어야 샤딩이 성립한다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터가 서버 한 대에 안 들어가면 어떻게 하나
샤딩 없이 || 샤딩으로
저장 한계 :: 서버 사양이 상한 || 서버를 늘리면 됨
검색 범위 :: 전체를 뒤진다 || 자기 몫만 뒤진다
장비 교체 :: 더 비싼 한 대 || 평범한 여러 대
= 한 대를 키우는 데는 끝이 있지만 대수를 늘리는 데는 없다
```

데이터가 늘면 서버를 키우는 것으로 한동안 버틸 수 있다. 메모리를 늘리고 디스크를 늘리고 CPU를 늘린다. 하지만 그 방법에는 끝이 있고, 끝에 가까워질수록 값이 가파르게 오른다.

샤딩은 방향을 바꾼다. 한 대를 키우는 대신 평범한 서버를 여러 대 두고 데이터를 나눈다. 각 서버가 다루는 양이 줄어드니 검색도 빨라진다.

## ⚙️ 작동 원리

어떤 기준으로 나눌지가 전부다. 이 기준을 샤드 키라고 한다.

| 방식 | 어떻게 나누나 | 문제 |
|---|---|---|
| 범위 | ID 1~100만은 A, 그다음은 B | 새 데이터가 한쪽에 몰린다 |
| 해시 | ID를 해시해서 나머지로 정한다 | 고르게 퍼지지만 범위 검색이 어렵다 |
| 지역 | 한국 사용자는 A, 미국은 B | 지역별 크기 차이가 그대로 온다 |

샤드 키를 잘못 고르면 한 서버에만 데이터와 요청이 몰린다. 이걸 핫스팟이라고 하고, 샤딩 실패의 대부분이 여기서 나온다.

## 💡 실제 사례

- **대형 서비스의 사용자 테이블** — 수억 건을 사용자 ID 기준으로 수십 대에 나눈다.
- **메신저 대화방** — 방 ID로 나눠서, 한 방의 메시지는 항상 같은 서버에 모이게 한다.
- **지역 분리** — 데이터를 나라별로 두면 규제도 만족하고 응답도 빨라진다.

## 🚫 흔한 오해

- **샤딩하면 무조건 빨라진다** — 여러 샤드를 뒤져야 하는 질의는 오히려 느려진다. 샤드 키로 찾는 질의만 빨라진다.
- **나중에 샤드 키를 바꿀 수 있다** — 바꾸려면 전체 데이터를 다시 배치해야 한다. 서비스 중에 하기가 매우 어려워서 처음 결정이 사실상 마지막 결정이다.
- **샤딩이 백업을 대신한다** — 나눠 담는 것과 복제해 두는 것은 다르다. 샤드 하나가 날아가면 그 몫의 데이터가 사라진다.

## 🚨 주의사항

- **샤드를 넘는 조인과 트랜잭션을 피한다.** 서버가 다르면 한 번에 묶을 수 없다. 같이 읽는 데이터는 같은 샤드에 모이도록 키를 고른다.
- **샤딩은 마지막 수단이다.** 인덱스, 캐시, 읽기 전용 복제본을 먼저 써본다. 샤딩은 되돌리기가 가장 어렵다.

## 📝 정리

**"한 대에 안 들어가서 나눠 담는 그 조각"** 이라고 읽으면 된다. 데이터를 여러 서버에 나눠 담아 한 대의 한계를 넘는다. 샤드 키 선택이 성패를 가르고, 한 번 정하면 바꾸기가 매우 어렵다.

## 🧒 열 살에게

책이 백만 권이 되면 한 건물에 다 못 넣지? 그래서 ㄱ부터 ㅅ은 본관, ㅇ부터 ㅎ은 옆 건물에 나눠 둬. 대신 어느 글자가 어느 건물인지를 먼저 정해 둬야 하고, 한 번 정한 걸 바꾸려면 책을 전부 다시 옮겨야 해.

## ❓ 이해했는지

- 최근 가입자 조회가 유독 느리다면 어떤 샤드 키를 썼을 가능성이 큰가 → 작동 원리
- 샤드 키로 찾지 않는 질의는 왜 느려지나 → 흔한 오해
- 샤딩보다 먼저 시도해볼 것은 무엇이고 그 이유는 → 주의사항
