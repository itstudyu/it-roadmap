# Caching (캐싱)

## 📝 정의

Caching은 **한 번 가져온 것을 가까이 두고 다시 쓰는 일**이다.

같은 질문에 같은 답이 나온다면 두 번째부터는 답을 만들 필요가 없다. 만들어둔 답을 빠른 곳에 놓아두고 꺼내 쓰는 것이 캐싱이다.

### 이름
= Cache 는 프랑스어 cacher(감추다)에서 온 말로, 나중에 쓰려고 가까이 감춰 둔 곳간을 뜻한다. 멀리 가지 않고 감춰 둔 데서 바로 꺼내 쓴다는 뜻이 그대로 남았다

### 비유
자주 보는 책은 도서관에 반납하지 않고 책상 위에 둔다.

### 예
뒤로 가기를 눌렀을 때 페이지가 다시 뜨지 않고 곧바로 나타나는 것이 이것이 일한 결과다.

### 직접
아무 사이트나 열었다가 다른 곳으로 갔다 뒤로 가기를 눌러 보라. 처음보다 빨리 뜨는 건 그림과 글을 다시 받지 않고 컴퓨터에 남겨 둔 것을 쓰기 때문이다.

## 🖼️ 그림으로 보기

```도해
흐름: 같은 값을 두 번째로 부르면 무엇이 달라지나
앱 :: 캐시에 있는지 먼저 본다
캐시 :: 없다. 이것을 미스라고 부른다
DB :: 앱이 대신 물어본다. 여기가 느린 구간이다
앱 :: 받은 값을 캐시에 넣어둔다
@ 다음 요청 :: 처음부터 다시. 이번엔 캐시에서 끝난다
= 첫 사람만 DB 까지 가고 나머지는 캐시에서 돌아온다
```

## ⚠️ 해결하는 문제

```도해
대조: 같은 값을 매번 DB 에서 읽으면 어떻게 되나
캐시 없이 || 캐시로
같은 조회 :: 매번 DB 까지 || 두 번째는 생략
DB 부하 :: 요청 수만큼 || 미스일 때만
응답 시간 :: 밀리초 단위 || 마이크로초 단위
= 값이 안 바뀌는 동안에는 같은 일을 두 번 하지 않는다
```

공지사항이나 상품 정보처럼 잘 바뀌지 않는 값도 조회할 때마다 DB 까지 간다. 사용자가 천 명이면 같은 질의가 천 번 나가고, DB 는 매번 같은 답을 만들어 돌려준다. 느린 것도 문제지만 DB 가 먼저 한계에 닿는다.

캐싱은 이 반복을 없앤다. 처음 한 번만 DB 에서 읽고 이후에는 메모리에서 꺼내니, 응답이 빨라지는 동시에 DB 가 받는 요청 수 자체가 줄어든다.

## 🧱 구성

```도해
층: 데이터를 찾으러 어디까지 내려가나
CPU 캐시 :: 프로세서 안. 나노초 단위
앱 메모리 :: 같은 프로세스 안. 서버마다 따로 갖는다
분산 캐시 :: 별도 서버. 여러 앱이 같은 값을 본다
DB :: 원본. 여기까지 내려오는 비율을 낮추는 게 목표다
= 위에서 끝날수록 빠르고, 아래로 갈수록 여러 곳이 같은 값을 본다
```

## ⚙️ 작동 원리

넣고 빼는 방식은 보통 셋 중 하나다. 읽을 때 없으면 그때 채우는 방식이 가장 흔하고, 쓸 때 DB 와 캐시에 같이 넣는 방식은 옛 값이 남을 일이 적다. 캐시에 먼저 쓰고 DB 에는 나중에 몰아 넣는 방식은 가장 빠르지만 그 사이에 죽으면 쓴 값을 잃는다.

## 💡 실제 사례

- **로그인 세션** — 요청마다 DB 를 보지 않고 캐시에서 세션을 꺼내 확인한다.
- **목록 화면** — 인기 상품처럼 모두에게 같은 목록은 한 번 만들어 잠시 재사용한다.
- **외부 API 응답** — 환율처럼 자주 안 바뀌는 값을 받아두고 정해진 시간 동안 그대로 쓴다.

## 🚫 흔한 오해

- **캐시를 붙이면 무조건 빨라진다** — 같은 값을 다시 안 부르는 데이터라면 미스만 쌓인다. DB 조회 앞에 캐시 조회가 얹혀서 오히려 느려진다.
- **캐시에 있는 값은 최신 값이다** — 원본이 바뀌어도 캐시는 모른다. 만료되거나 지워질 때까지 옛 값을 그대로 준다.
- **캐시도 데이터 저장소다** — 언제 사라져도 되는 사본이다. 캐시에만 있는 값은 서버가 재시작되면 없어진다.

## 🚨 주의사항

- **사람마다 다른 값은 키를 나눈다.** 사용자 구분 없이 키를 잡으면 A 가 담은 장바구니가 B 에게 나간다.
- **만료를 한 시각에 몰지 않는다.** 캐시가 한꺼번에 비면 그 순간 모든 요청이 DB 로 쏟아진다.

## 📝 정리

**"한 번 간 길을 두 번 가지 않게 두는 그 사본"** 이라고 읽으면 된다. 자주 쓰는 값을 빠른 곳에 두고 다시 쓰니 응답 시간과 원본 부하가 함께 줄어든다. 대가로 원본과 어긋난 값이 잠시 남으며, 언제 지울지를 정하는 일이 캐싱의 어려운 부분이다.

## 🧒 열 살에게

자주 보는 책을 볼 때마다 도서관까지 걸어갔다 오면 힘들지? 그래서 책상 위에 두고 봐. 대신 도서관 책이 새것으로 바뀌어도 네 책상 위 책은 옛날 그대로라, 언제 다시 빌려 올지를 미리 정해 둬야 해.

## ❓ 이해했는지

- 상품 값을 고쳤는데 화면에는 옛 값이 계속 보인다면 무엇 때문인가 → 흔한 오해
- 사용자마다 다른 장바구니를 캐시할 때 무엇을 조심해야 하나 → 주의사항
- 서버를 두 대로 늘렸더니 같은 값을 물어도 서버마다 다르게 답한다. 캐시를 어디에 둔 것인가 → 구성
