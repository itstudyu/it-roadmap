# Load Balancing (로드 밸런싱)

## 📝 정의

Load Balancing은 **들어오는 요청을 여러 서버에 나눠 보내는 일**이다.

서버 한 대가 감당할 수 있는 동시 요청 수는 정해져 있다. 그 앞에 나눠주는 장치를 두면 서버를 늘리는 것으로 처리량을 늘릴 수 있고, 한 대가 죽어도 나머지가 받는다.

### 이름
Load :: 짊어질 짐, 일감
Balancing :: 고르게 나눔
= 붙여 읽으면 "일감을 고르게 나누기". 한 대에 묶여 있던 일감을 여러 대로 흩는다

### 비유
마트 계산대 앞의 안내 직원. 줄 하나에 다 세우는 대신 비어 있는 계산대로 보낸다.

### 예
새로 고칠 때마다 페이지 아래 찍힌 서버 번호가 달라지는 사이트를 본 적이 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청 하나가 어느 서버로 가는지 어떻게 정해지나
사용자 :: 사이트 주소로 요청을 보낸다
DNS :: 로드 밸런서의 주소를 알려준다
밸런서 :: 살아 있는 서버 목록을 본다
밸런서 :: 정해둔 규칙으로 한 대를 고른다
서버 3 :: 요청을 처리해서 결과를 만든다
< 밸런서 :: 결과를 사용자에게 전달한다
= 사용자는 서버가 몇 대인지 끝내 모른다
```

## ⚠️ 해결하는 문제

```도해
대조: 접속이 몰리면 어떻게 되나
서버 한 대 || 밸런서 뒤에 여러 대
동시 접속 :: 한 대가 다 받는다 || 나눠서 받는다
한 대가 죽으면 :: 사이트가 멈춘다 || 나머지가 받는다
배포 :: 잠깐 끊긴다 || 하나씩 교체
= 한 대에 묶여 있던 처리량과 생존을 여러 대로 흩는 것이다
```

서버 한 대로 버티는 구조에서는 그 한 대가 곧 전체 한계다. 사양을 올리는 방법에는 끝이 있고, 올려도 그 한 대가 죽으면 사이트가 통째로 멈춘다.

밸런서를 앞에 두면 서버 대수를 늘려 처리량을 늘릴 수 있다. 배포도 달라진다. 한 대씩 목록에서 빼고 새 버전으로 바꿔 넣으면 사용자 쪽에서는 끊기는 순간이 없다.

## ⚙️ 작동 원리

밸런서는 뒤에 있는 서버들에 주기적으로 신호를 보내 응답하는지 확인한다. 이 확인이 실패하면 그 서버를 목록에서 빼고, 다시 응답하면 되돌린다. 죽은 서버로 요청이 가지 않는 이유가 이것이다.

살아 있는 서버 중 어디로 보낼지는 규칙이 정한다. 몇 가지가 흔하다.

- **순서대로** — 1번, 2번, 3번, 다시 1번. 아무것도 보지 않아 가장 단순하다.
- **연결 수** — 지금 붙어 있는 요청이 가장 적은 곳으로 보낸다.
- **가중치** — 사양이 좋은 서버에 더 많이 보낸다.
- **주소 해시** — 같은 사용자는 늘 같은 서버로 보낸다.

## 💡 실제 사례

- **트래픽 증가 대응** — 접속이 늘면 서버를 몇 대 더 띄워 목록에 넣는다. 코드는 그대로다.
- **무중단 배포** — 한 대씩 빼서 새 버전으로 바꾸고 되돌린다. 사용자 쪽에서는 끊긴 순간이 없다.
- **장애 격리** — 서버 한 대가 응답을 멈추면 확인 신호에서 걸러져 목록에서 빠지고, 요청은 나머지로만 간다.

## 🚫 흔한 오해

- **로드 밸런서를 붙이면 서버가 빨라진다** — 한 요청을 처리하는 속도는 그대로다. 늘어나는 것은 동시에 받을 수 있는 요청 수다.
- **밸런서를 두면 장애가 없어진다** — 밸런서 자체가 죽으면 전부 멈춘다. 그래서 밸런서도 여러 대를 두거나 관리형 서비스를 쓴다.
- **요청을 똑같이 나눠 주는 게 항상 좋다** — 요청마다 무게가 다르다. 무거운 요청이 한 서버에 몰릴 수 있어서 연결 수를 보고 고르는 규칙을 쓰기도 한다.

## 🚨 주의사항

- **세션을 서버 메모리에 두면 깨진다.** 다음 요청이 다른 서버로 가면 로그인이 풀린다. 세션은 공용 저장소에 두는 편이 맞다.
- **확인 신호를 너무 얕게 만들지 않는다.** 프로세스만 살아 있고 데이터베이스 연결이 끊긴 서버가 계속 요청을 받을 수 있다.

## 📝 정리

**"비어 있는 쪽으로 보내 주는 그 안내"** 라고 읽으면 된다. 요청을 여러 서버에 나눠 보내 처리량과 생존을 한 대에서 떼어낸다. 한 요청의 처리 속도를 올려주지는 않고, 세션을 어디에 두느냐가 함께 정해져야 한다.

## 🧒 열 살에게

마트에서 다들 줄 하나에만 서 있으면 답답하지? 그래서 안내하는 사람이 비어 있는 계산대로 한 명씩 보내 줘. 계산하는 속도가 빨라지는 건 아니고, 같은 시간에 계산을 마치고 나가는 사람 수가 늘어나는 거야.

## ❓ 이해했는지

- 서버를 늘렸는데 페이지 하나 여는 시간이 그대로인 이유는 → 흔한 오해
- 로그인이 자꾸 풀린다면 무엇이 잘못 놓여 있는 것인가 → 주의사항
- 밸런서는 죽은 서버로 요청이 가지 않게 하려고 무엇을 하고 있나 → 작동 원리
