# Latency (지연 시간)

## 📝 정의

Latency는 **요청을 보내고 응답이 올 때까지 걸리는 시간**이다.

한 번에 얼마나 많이 나르느냐가 아니라, 하나가 갔다 오는 데 얼마나 걸리느냐를 잰다. 사용자가 느리다고 말할 때 실제로 가리키는 값이 대개 이것이다.

### 비유
우편과 전화의 차이. 편지는 부치고 며칠을 기다리고, 전화는 말하는 순간 닿는다.

## 🖼️ 그림으로 보기

```도해
흐름: 검색 버튼을 누르고 결과가 뜰 때까지 어디서 시간이 드나
브라우저 :: 요청을 만들어 보낸다
회선 :: 서버까지 물리적으로 오간다
서버 :: 요청을 받아 처리한다
DB :: 조회하고 결과를 돌려준다
< 브라우저 :: 받은 것을 화면에 그린다
= 한 군데가 아니라 각 마디에서 쌓인 합이 사용자가 느끼는 시간이다
```

## ⚠️ 해결하는 문제

```도해
대조: 응답이 몇 초씩 걸리면 무엇이 달라지나
느릴 때 || 빠를 때
사용자 :: 다시 누른다 || 기다린다
서버 :: 중복 요청 쌓임 || 요청 한 번
결과 :: 그냥 떠난다 || 계속 쓴다
= 느린 것은 불편으로 끝나지 않고 부하를 더 만들어낸다
```

화면이 멈춰 있으면 사람은 기다리다가 버튼을 다시 누른다. 그 순간 서버는 같은 일을 두 번 하게 되고, 느려서 생긴 재요청이 다시 서버를 느리게 만든다.

지연을 재는 이유는 그래서다. 어느 마디에서 시간이 드는지 알아야 줄일 곳을 고를 수 있고, 줄일 수 없는 마디가 어디인지도 그때 드러난다.

## ⚙️ 작동 원리

```도해
층: 어디서 끝날수록 빠른가
브라우저 캐시 :: 이미 받은 것. 왕복이 없다
가까운 거점 :: 같은 지역의 서버. 거리를 줄인다
원본 서버 :: 처리와 조립. 코드가 걸리는 만큼
데이터베이스 :: 조회. 인덱스가 없으면 여기서 늘어진다
= 위에서 끝날수록 짧다. 지연을 줄이는 일은 대개 위로 끌어올리는 일이다
```

지연은 성격이 다른 조각들의 합이다. 회선을 오가는 시간은 거리가 정하고, 처리 시간은 코드와 서버가 정하고, 조회 시간은 데이터 양과 인덱스가 정한다. 어느 조각이 큰지 모르면 엉뚱한 곳을 고치게 된다.

줄이는 방법도 조각마다 다르다. 거리는 사용자 가까운 곳에 복사본을 두어 줄이고, 반복되는 조회는 캐시에 담아 없애고, 서로 상관없는 작업은 순서대로 기다리는 대신 동시에 건다. 인덱스가 없어 전체를 훑는 조회는 인덱스를 붙여야 줄어든다.

## 📊 비교: 응답 시간대별 체감

| 지연 | 느낌 | 예 |
|---|---|---|
| 100ms 아래 | 즉각 반응한다 | 로컬 작업 |
| 300ms 아래 | 빠르다 | 일반적인 API |
| 1초 아래 | 참을 만하다 | 복잡한 검색 |
| 1초 넘음 | 느리다고 느낀다 | 이탈이 시작된다 |
| 3초 넘음 | 대부분 떠난다 | |

## 💡 실제 사례

- **먼 나라 서버** 지구 반대편 서버를 부르면 회선에서만 왕복 시간이 붙는다. 코드를 고쳐도 이 부분은 줄지 않는다.
- **같은 조회의 반복** 매번 DB에서 같은 값을 꺼내면 그때마다 대기가 생긴다. 캐시에 두면 그 왕복이 사라진다.
- **차례로 기다리기** 서로 상관없는 조회 세 개를 순서대로 부르면 셋의 합이 되고, 동시에 걸면 가장 느린 하나가 된다.

## 🚫 흔한 오해

- **서버를 좋은 걸로 바꾸면 지연이 준다** — 처리 시간만 준다. 거리 때문에 생기는 왕복이나 순서 때문에 생기는 대기는 그대로 남는다.
- **평균 응답 시간이 괜찮으면 괜찮은 것이다** — 평균은 느린 쪽을 가린다. 열 명 중 한 명이 3초를 기다려도 평균은 크게 움직이지 않는다.
- **지연이 낮으면 처리량도 높다** — 다른 값이다. 하나가 빨리 갔다 오는 것과 동시에 여럿을 감당하는 것은 각각 따로 막힌다.

## 📝 정리

Latency는 요청 하나가 갔다 오는 데 걸리는 시간이고, 성격이 다른 여러 조각의 합이다. 어느 조각이 큰지 재지 않으면 줄일 수 없는 곳을 붙잡고 고치게 된다. 평균만 보면 오래 기다리는 소수가 통계 뒤에 숨는다.

- 사용자는 느리다고 하는데 평균 응답 시간은 정상이라면 무엇을 놓친 것인가?
- 서로 상관없는 조회 세 개를 차례로 부르면 왜 느려지나?
