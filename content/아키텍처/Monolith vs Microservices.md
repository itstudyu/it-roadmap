# 모놀리스 vs 마이크로서비스

## 📝 정의

모놀리스와 마이크로서비스는 **기능을 한 덩어리로 둘지 쪼갤지**의 차이다.

모놀리스는 모든 기능이 한 코드베이스에서 돌고 한 번에 배포된다. 마이크로서비스는 기능마다 서비스와 데이터베이스를 따로 두고 각각 배포한다.

### 비유
백화점과 상가. 백화점은 한 건물에서 중앙이 관리하고, 상가는 가게마다 따로 열고 닫는 대신 오가려면 밖으로 나와야 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 주문 하나가 마이크로서비스에서 어떻게 처리되나
클라이언트 :: 상품 구매를 요청한다
게이트웨이 :: 요청을 받아 각 서비스로 나눠 보낸다
상품 서비스 :: 재고를 확인하고 자기 DB 에 적는다
결제 서비스 :: 결제를 처리하고 자기 DB 에 적는다
배송 서비스 :: 배송을 잡고 자기 DB 에 적는다
< 게이트웨이 :: 응답을 모아 하나로 돌려준다
= 모놀리스에서 함수 호출이던 자리가 여기서는 네트워크 통신이다
```

## ⚠️ 해결하는 문제

```도해
대조: 결제에만 트래픽이 몰리면 어떻게 되나
모놀리스 || 마이크로서비스
확장 :: 전체를 늘린다 || 결제만 늘린다
배포 :: 전부 다시 올림 || 그 서비스만
장애 :: 전체가 내려감 || 그 기능만 막힘
= 나누면 늘릴 때도 고칠 때도 필요한 부분만 건드린다
```

모놀리스에서는 결제 코드 한 줄을 고쳐도 전체를 다시 배포한다. 결제에만 부하가 몰려도 서버 전체를 늘려야 하고, 어느 한 곳에서 난 오류가 프로세스를 내리면 나머지 기능도 같이 멈춘다. 코드가 커지고 팀이 늘수록 이 대가가 커진다.

마이크로서비스는 그 대가를 다른 대가와 맞바꾼다. 필요한 부분만 늘리고 배포하는 대신, 함수 호출이던 것이 네트워크 통신이 되고 한 데이터베이스에서 끝나던 처리가 여러 서비스에 걸치게 된다.

## ⚙️ 작동 원리

나누는 기준은 코드가 아니라 데이터다. 결제 서비스가 상품 테이블을 직접 읽고 있으면 둘은 여전히 붙어 있는 것이고, 한쪽 스키마를 바꿀 때 다른 쪽이 깨진다. 그래서 남의 데이터가 필요하면 API로 물어본다.

가장 까다로운 자리는 트랜잭션이다. 한 데이터베이스 안에서는 결제 기록과 재고 차감이 함께 성공하거나 함께 취소된다. 서비스가 나뉘면 결제는 됐는데 재고 차감이 실패한 상태가 생길 수 있어서, 되돌리는 절차를 따로 만들어야 한다.

서비스 앞에는 대개 게이트웨이를 둔다. 클라이언트가 서비스 주소를 하나하나 알 필요가 없어지고, 인증이나 요청 제한처럼 공통으로 할 일을 한자리에서 처리한다.

## 📊 비교

| 항목 | 모놀리스 | 마이크로서비스 |
|---|---|---|
| 배포 | 전체를 한 번에 | 서비스마다 따로 |
| 기술 선택 | 하나로 통일 | 서비스마다 다르게 |
| 확장 | 전체를 늘린다 | 필요한 것만 |
| 데이터 처리 | 한 DB 안에서 끝난다 | 여러 서비스에 걸친다 |
| 초기 운영 비용 | 낮다 | 높다 |
| 장애 범위 | 전체 | 그 서비스 |

## 💡 실제 사례

- **처음 시작할 때** 사용자가 적은 동안은 모놀리스로 빨리 내놓는 편이 낫다. 나누는 데 드는 인프라가 얻는 것보다 크다.
- **한 기능에 몰리는 부하** 결제나 검색처럼 요청이 집중되는 기능만 떼어내 그 부분만 따로 늘린다.
- **팀이 늘어날 때** 한 코드베이스에 여러 팀이 붙으면 배포 순서를 맞추느라 서로 기다린다. 나누면 각 팀이 자기 것만 배포한다.

## 🚫 흔한 오해

- **마이크로서비스가 모놀리스보다 발전한 방식이다** — 나중에 나온 것이지 더 나은 것이 아니다. 사람도 기능도 적을 때는 나누는 값이 얻는 것보다 크다.
- **서비스를 잘게 쪼개면 마이크로서비스다** — 서비스는 나뉘었는데 데이터베이스를 함께 쓰면 배포도 함께 해야 한다. 나뉜 척하는 모놀리스가 된다.
- **나누기만 하면 장애가 안 번진다** — 저절로 되지 않는다. 응답 없는 서비스를 계속 부르면 부르는 쪽도 같이 멈춘다. 타임아웃과 차단기를 따로 붙여야 격리가 생긴다.

## 🚨 주의사항

- **나눌 준비가 됐는지 먼저 본다.** 배포 자동화와 모니터링이 없으면 서비스 수만큼 손이 늘어난다.
- **경계는 데이터로 긋는다.** 두 서비스가 같은 데이터를 고쳐야 한다면 그 경계는 잘못 그은 것이다.

## 📝 정리

모놀리스는 기능을 한 덩어리에 두고, 마이크로서비스는 기능마다 서비스와 데이터베이스를 나눈다. 나누면 필요한 것만 늘리고 배포할 수 있지만 함수 호출이 네트워크 통신이 되고 처리가 여러 곳에 걸친다. 어느 쪽이 옳은 게 아니라 지금 무엇이 더 아픈지를 보고 고르는 것이다.

## ❓ 이해했는지

- 결제 코드 한 줄만 고쳤는데 서비스 전체를 다시 배포해야 한다면 어느 구조인가?
- 서비스를 나눴는데도 배포를 늘 같이 해야 한다면 무엇을 잘못한 건가?
- 결제는 됐는데 재고 차감이 실패하는 일이 모놀리스에서는 왜 잘 안 생기나?
