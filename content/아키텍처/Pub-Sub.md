# Pub/Sub (발행-구독)

## 📝 정의

Pub/Sub은 **한 번 발행한 소식을 관심 있는 쪽이 각자 받아가는 방식**이다.

보내는 쪽은 누가 받는지 모른다. 받는 쪽은 누가 보냈는지 모른다. 둘 사이에 주제만 있고, 그래서 받는 쪽을 추가해도 보내는 쪽 코드는 그대로다.

### 비유
잡지 구독. 출판사는 구독자 명단을 신경 쓰지 않고 발행만 한다. 새 구독자가 늘어도 인쇄 방식은 바뀌지 않고, 구독을 끊어도 출판사는 하던 일을 계속한다.

### 예
단톡방에 글 하나를 올리면 방에 있는 사람들 폰이 한꺼번에 울리는 그 모양이다.

## 🖼️ 그림으로 보기

```도해
흐름: 주문 하나가 여러 서비스에 어떻게 퍼지나
주문 서비스 :: "주문 완료" 를 주제에 발행한다
주제 :: 이 주제를 구독한 곳 모두에게 복사해 보낸다
구독자들 :: 재고·배송·알림이 저마다 받는다. 순서도 없고 서로 모른다
새 구독자 :: 나중에 붙어도 주제만 구독하면 끝난다
= 구독자를 하나 더 붙여도 주문 서비스는 고칠 게 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 주문 완료를 세 곳에 알려야 할 때 무엇이 달라지나
직접 호출 || Pub/Sub
새 기능 추가 :: 주문 코드 수정 || 구독만 추가
한 곳 장애 :: 주문도 실패 || 그곳만 밀린다
아는 대상 :: 세 곳을 다 안다 || 주제만 안다
= 보내는 쪽이 받는 쪽을 모르게 만드는 것이 이 방식의 전부다
```

주문이 끝났을 때 재고, 배송, 알림을 차례로 부르면 주문 코드가 그 셋을 전부 알게 된다. 나중에 정산 서비스가 생기면 주문 코드를 또 고쳐야 하고, 셋 중 하나가 죽으면 주문 자체가 실패한다.

발행-구독으로 바꾸면 주문은 "주문이 끝났다"는 사실만 알린다. 누가 그 소식으로 무엇을 하든 주문이 알 바가 아니다. 새 서비스는 구독만 시작하면 된다.

## ⚙️ 작동 원리

[[Message Queue]]와 자주 헷갈리는데, 메시지 하나를 몇 곳이 받느냐가 다르다.

| | 큐 | Pub/Sub |
|---|---|---|
| 한 메시지를 | 한 곳이 가져간다 | 구독한 곳 전부가 받는다 |
| 목적 | 일을 나눠서 처리 | 소식을 퍼뜨리기 |
| 예 | 이미지 변환 작업 | 주문 완료 알림 |

구독자가 잠시 죽었을 때 그동안의 소식을 나중에 받을지, 그냥 놓칠지도 정해야 한다. 놓치면 안 되는 소식이면 구독자마다 별도의 저장 공간을 두는 방식을 쓴다.

## 💡 실제 사례

- **이벤트 기반 아키텍처** — 상태가 바뀔 때마다 소식을 발행하고 각 서비스가 알아서 반응한다.
- **실시간 화면 갱신** — 서버가 변경 사항을 발행하면 접속 중인 브라우저들이 각자 받아 화면을 고친다.
- **로그 수집** — 여러 서비스가 같은 주제로 로그를 발행하고, 저장용과 분석용이 각각 구독한다.

## 🚫 흔한 오해

- **Pub/Sub과 큐는 같은 것이다** — 큐는 한 메시지를 한 곳이 가져가고, Pub/Sub은 구독한 전부가 받는다. 일을 나누려는데 Pub/Sub을 쓰면 같은 일이 세 번 처리된다.
- **발행하면 무조건 전달된다** — 구독자가 죽어 있으면 놓칠 수 있다. 놓치면 안 되는 소식은 저장 방식을 따로 정해야 한다.
- **결합이 완전히 사라진다** — 주제 이름과 메시지 모양에 여전히 묶여 있다. 메시지 구조를 바꾸면 구독자가 전부 깨진다.

## 🚨 주의사항

- **메시지 모양을 함부로 바꾸지 않는다.** 구독자가 누구인지 모르기 때문에 무엇이 깨지는지도 모른다. 필드는 더하기만 하고 빼지 않는 쪽이 안전하다.
- **흐름을 추적하기 어렵다.** 요청 하나가 어디까지 퍼졌는지 보려면 추적 ID를 메시지에 넣고 끝까지 따라가야 한다.

## 📝 정리

Pub/Sub은 소식을 주제에 발행하고 구독한 쪽들이 각자 받아가는 방식이다. 보내는 쪽과 받는 쪽이 서로를 몰라도 되지만, 그 대가로 무엇이 어디까지 갔는지 추적하기 어려워진다.

## ❓ 이해했는지

- 이미지 변환 작업을 Pub/Sub으로 돌리면 무엇이 잘못되나 → 흔한 오해
- 정산 서비스를 새로 붙일 때 주문 서비스를 고쳐야 하나 → 해결하는 문제
- 메시지에 필드를 하나 빼면 왜 위험한가 → 주의사항
