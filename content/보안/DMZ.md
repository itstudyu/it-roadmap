# DMZ (Demilitarized Zone, 비무장 지대)

## 📝 정의

DMZ는 **외부에 열어야 할 서버만 따로 모아두는 중간 구역**이다.

웹 서버나 메일 서버는 바깥에서 접속할 수 있어야 하고, 고객 데이터베이스는 그러면 안 된다. 이 둘을 같은 망에 두지 않고 사이에 방화벽을 한 겹 더 두는 것이 DMZ다.

### 비유
아파트 로비. 방문자는 로비까지 들어와 택배를 맡기거나 받을 수 있지만, 위층으로 올라가려면 카드 키가 있어야 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 웹 요청 하나가 어디까지 들어오나
인터넷 :: 사용자가 443 포트로 접속한다
외부 FW :: 열어둔 포트만 통과시킨다
웹 서버 :: DMZ 안에서 요청을 처리한다
내부 FW :: DB 포트 하나만 안쪽으로 열어둔다
< DB 서버 :: 내부망에 있고 웹 서버 요청만 받는다
= 바깥에서 온 사람은 DMZ 까지만 오고, 그 안은 서버가 대신 다녀온다
```

## ⚠️ 해결하는 문제

```도해
대조: 웹 서버를 내부망에 그냥 두면 어떻게 되나
DMZ 없이 || DMZ 로
서버가 뚫리면 :: 내부망이 열림 || 방화벽이 하나 더
공격 표면 :: 내부망 전체 || 공개 서버만
방화벽 규칙 :: 한 겹 || 두 겹
= 뚫린 다음에 무슨 일이 벌어지는지를 바꾸는 것이 DMZ 다
```

웹 서버는 인터넷에 열려 있어야 하니 언젠가는 노려진다. 그 서버가 고객 DB와 같은 망에 있으면, 웹 서버가 뚫린 순간 공격자는 이미 내부망 안에 서 있게 된다.

DMZ는 그 사이에 방화벽을 한 겹 더 세운다. 웹 서버를 장악해도 안쪽으로 가려면 내부 방화벽을 다시 뚫어야 하고, 그 방화벽은 DB 포트 하나 말고는 아무것도 열어두지 않는다.

## ⚙️ 작동 원리

트래픽의 방향마다 규칙이 다르다.

```도해
층: 어느 방향까지 열어두나
인터넷에서 DMZ :: 정해둔 포트만. 보통 80 과 443
DMZ 에서 내부망 :: 꼭 필요한 것만. DB 포트 정도
내부망에서 DMZ :: 열어둔다. 서버를 관리해야 하니까
인터넷에서 내부망 :: 막는다. 직접 가는 길은 없다
= 안에서 밖으로는 넓고, 밖에서 안으로는 좁다
```

방화벽을 두 대 쓰는 구성이 표준으로 불린다. 외부 방화벽은 인터넷에서 들어오는 것을 걸러 DMZ로 넘기고, 내부 방화벽은 DMZ에서 내부망으로 가는 것을 막는다. 두 방화벽을 서로 다른 제품으로 두기도 한다. 한쪽에 있는 약점이 다른 쪽에는 없기를 기대하는 것이다.

클라우드에서는 물리적인 방화벽 대신 공개 구역과 사설 구역을 나누고, 각 서버에 붙은 규칙으로 같은 구조를 만든다.

## 💡 실제 사례

- **회사 웹사이트** 웹 서버는 DMZ에, 고객 DB와 사내 시스템은 내부망에 둔다. 웹 서버는 DB의 정해진 포트로만 질의한다.
- **메일 서버** 외부와 메일을 주고받는 서버는 DMZ에 두고, 사내 사용자의 사서함은 안쪽에 둔다.
- **클라우드 구성** 공개 구역에 로드 밸런서를 두고, 애플리케이션 서버와 데이터베이스는 사설 구역에 둔다.

## 🚫 흔한 오해

- **DMZ 는 안전한 구역이다** — 반대다. 뚫릴 것을 전제로 만든 구역이라 가장 위험한 자리다. 안전한 쪽은 그 뒤에 있는 내부망이다.
- **DMZ 에 두면 그 서버는 보호받는다** — 그 서버가 보호받는 게 아니라 그 서버가 뚫렸을 때 나머지가 보호받는다.
- **방화벽만 있으면 DMZ 다** — 구역을 나누는 게 핵심이다. 방화벽이 있어도 웹 서버와 DB가 같은 망에 있으면 뚫린 뒤에 막을 것이 없다.

## 🚨 주의사항

- **DMZ 서버에 내부망 계정 정보를 두지 않는다.** 그 서버는 가장 먼저 노려지는 자리라, 거기서 나온 열쇠는 그대로 안쪽 열쇠가 된다.
- **내부 방화벽을 열어달라는 요청이 쌓이면 벽이 사라진다.** 예외를 하나씩 허용하다 보면 결국 두 망이 이어져 버린다.

## 📝 정리

DMZ는 외부에 열어야 하는 서버를 내부망에서 떼어 놓고 그 사이에 방화벽을 한 겹 더 두는 구조다. 공개 서버가 뚫리는 것을 막는 장치가 아니라, 뚫린 뒤에 안쪽까지 이어지지 않게 하는 장치다. 방향마다 열어둘 것을 정하는 규칙이 실제 내용이다.

## ❓ 이해했는지

- 웹 서버가 뚫렸을 때 DMZ가 있는 쪽과 없는 쪽은 그다음이 어떻게 다른가?
- 인터넷에서 내부망으로 바로 가는 길이 없는데 사용자는 어떻게 DB의 데이터를 보나?
- DMZ 안의 서버가 내부망에서 가장 위험한 자리로 취급되는 이유는?
