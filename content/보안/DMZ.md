# DMZ (Demilitarized Zone, 비무장 지대)

## 📝 정의

DMZ(비무장 지대)는 인터넷(외부 네트워크)과 내부 네트워크(사내망) 사이에 위치한 격리된 중간 네트워크 영역입니다. 웹 서버, 메일 서버, DNS 서버처럼 외부에서 접근해야 하는 공개 서버들을 이 영역에 배치하여, 외부에서는 DMZ까지만 접근할 수 있고 내부 네트워크는 직접 노출되지 않도록 보호합니다.

군사 용어인 "비무장 지대"에서 유래했으며, 두 적대 세력(인터넷과 내부망) 사이의 완충 지대 역할을 합니다. 외부에서 DMZ의 서버가 해킹당해도, 방화벽이 그 다음 방어선 역할을 하기 때문에 내부 네트워크로의 침입을 추가로 막을 수 있습니다. 현대 네트워크 설계의 표준적인 보안 아키텍처 패턴입니다.

> **한 줄 요약**: "공개 서버는 DMZ에, 핵심 데이터는 내부망에 — 두 방화벽이 지키는 완충 지대"

**비유**:
- **아파트 경비실 비유**: 방문자는 로비(DMZ)까지는 들어올 수 있지만, 각 층으로 올라가는 엘리베이터(내부 네트워크)는 카드 키가 없으면 사용 불가. 경비실에 맡겨진 택배는 방문자가 직접 집까지 오지 않아도 받을 수 있음
- **공항 입국심사 비유**: 도착 로비(DMZ)는 누구나 접근 가능하지만, 입국심사를 통과해야 국내(내부망)로 들어올 수 있음

## 🎯 핵심 개념

### 1. 이중 방화벽 구조 (Dual Firewall)
표준 DMZ 설계에서는 두 개의 방화벽을 사용합니다. 외부 방화벽은 인터넷 트래픽을 필터링하여 DMZ로 전달하고, 내부 방화벽은 DMZ에서 내부 네트워크로의 접근을 엄격히 제어합니다. 외부 방화벽이 뚫려도 내부 방화벽이 내부망을 보호합니다.

### 2. DMZ에 배치하는 서버
- **웹 서버**: 외부 사용자가 접근하는 웹사이트 (nginx, Apache)
- **메일 서버**: 이메일 송수신 (SMTP, IMAP)
- **DNS 서버**: 도메인 이름 해석
- **FTP 서버**: 파일 전송
- **API Gateway**: 외부 API 요청을 받는 게이트웨이

### 3. 트래픽 흐름 원칙
- 인터넷 → DMZ: 허용 (특정 포트만)
- DMZ → 내부망: 제한적 허용 (반드시 필요한 통신만)
- 내부망 → DMZ: 허용 (내부에서 서버 관리)
- 인터넷 → 내부망: 차단 (직접 접근 불가)

### 4. 단일 방화벽 DMZ vs 이중 방화벽 DMZ
단일 방화벽에서 3개의 인터페이스(인터넷, DMZ, 내부망)를 사용하는 방식도 있으나, 이중 방화벽이 더 강력한 보안을 제공합니다. 이중 방화벽은 서로 다른 벤더의 제품을 사용하면 한 벤더의 취약점이 있어도 다른 방화벽이 방어할 수 있습니다.

## ⚠️ 해결하는 문제

### 문제 1: 공개 서버를 통한 내부망 침입
웹 서버나 메일 서버를 내부 네트워크에 바로 배치하면, 서버가 해킹당했을 때 공격자가 내부 데이터베이스나 다른 시스템에 직접 접근할 수 있습니다. DMZ는 공개 서버와 내부 네트워크를 분리하여, 서버 침해가 내부망 침해로 이어지지 않도록 합니다.

### 문제 2: 모든 서비스를 외부에 노출하거나 모두 차단하는 이분법
DMZ 없이는 "모든 서버를 인터넷에 직접 노출"하거나 "VPN을 통해서만 접근 가능"한 두 가지 선택밖에 없습니다. DMZ는 필요한 서버만 적절한 수준으로 공개하는 중간 방법을 제공합니다.

### 문제 3: 규정 준수 및 데이터 보호
금융, 의료 등 규제 산업에서는 고객 데이터와 공개 서비스를 분리하는 것이 법적 요구사항인 경우가 많습니다. DMZ는 개인 정보와 공개 서버를 물리적/논리적으로 분리하여 컴플라이언스를 지원합니다.

## ⚙️ 작동 원리

### 1단계: 외부 요청 수신
인터넷 사용자가 웹사이트에 접속하면, 요청이 먼저 외부 방화벽에 도달합니다. 외부 방화벽은 허용된 포트(80, 443)의 트래픽만 DMZ로 전달합니다.

### 2단계: DMZ 서버 처리
DMZ의 웹 서버가 요청을 처리합니다. 정적 콘텐츠는 웹 서버에서 직접 응답하고, 동적 데이터가 필요하면 내부 방화벽을 통해 내부 애플리케이션 서버 또는 DB에 요청합니다.

### 3단계: 내부망 접근 제한
DMZ에서 내부망으로의 접근은 내부 방화벽이 엄격히 제어합니다. 예를 들어, 웹 서버는 DB 서버의 특정 포트(3306)로만 접근 가능하고, 나머지 모든 통신은 차단됩니다.

### 4단계: 침해 시 피해 최소화
만약 DMZ의 서버가 해킹당해도, 내부 방화벽이 추가 방어선 역할을 합니다. 공격자가 웹 서버를 완전히 장악해도, 내부 네트워크로 이동하려면 내부 방화벽을 추가로 뚫어야 합니다.

## ✅ 장단점

**장점**:
- 공개 서버와 내부 네트워크를 분리하여, 서버 침해가 내부망 침해로 이어지는 것을 방지
- 외부에서 접근 가능한 서버의 수와 범위를 최소화하여 공격 표면 축소
- 방화벽 로그를 통해 외부에서 내부망으로의 침입 시도를 조기 탐지 가능
- 금융, 의료 등 규제 환경에서 데이터 보호 요건 충족에 유리
- 공개 서비스와 내부 서비스를 독립적으로 운영하여 장애 격리 가능

**단점**:
- 두 개 이상의 방화벽과 네트워크 장비가 필요하여 초기 구축 비용이 높음
- 네트워크 규칙이 복잡해져 관리 부담 증가
- 잘못 설정하면 보안 허점이 생기거나 정상 서비스가 차단될 수 있음
- 클라우드 환경에서는 보안 그룹과 VPC로 대체하는 추세

## 💡 실제 사례

### 1. 기업 웹사이트 운영
일반적인 기업 네트워크에서 웹 서버는 DMZ에 배치하고, 고객 DB와 ERP 시스템은 내부 네트워크에 둡니다. 웹 서버가 고객 데이터를 요청할 때만 내부 방화벽을 통해 DB에 접근하고, 웹 서버 자체는 DB에 대한 쓰기 권한을 최소화합니다.

### 2. 게임 서버 아키텍처
온라인 게임 회사는 게임 서버와 로그인 서버를 DMZ에 두고, 결제 처리 서버와 유저 데이터 DB는 내부망에 보호합니다. 게임 클라이언트는 DMZ와만 통신하며, 결제 처리는 내부에서 보안된 경로로 처리됩니다.

### 3. AWS에서의 DMZ 구현
AWS에서는 Public Subnet을 DMZ처럼 활용합니다. Internet Gateway를 통해 외부에서 접근 가능한 Public Subnet에 로드밸런서와 API Gateway를 배치하고, Private Subnet에 애플리케이션 서버와 데이터베이스를 둡니다. Security Group과 NACL이 방화벽 역할을 합니다.

## 🔗 관련 용어

- **방화벽 (Firewall)**: 네트워크 트래픽을 필터링하여 허가된 통신만 허용하는 보안 장치
- **Bastion Host**: DMZ나 외부에서 내부 네트워크로 접근하기 위한 강화된 진입점 서버
- **NAT (Network Address Translation)**: 내부 사설 IP를 공인 IP로 변환하는 기술
- **Port Forwarding**: 특정 포트로 들어오는 트래픽을 내부 서버로 전달하는 기법
- **인바운드/아웃바운드**: 네트워크로 들어오는(인바운드)/나가는(아웃바운드) 트래픽 방향
- **VPC (Virtual Private Cloud)**: 클라우드 환경에서 논리적으로 분리된 가상 네트워크
- **Zero Trust**: 내부 네트워크도 신뢰하지 않고 모든 접근을 검증하는 보안 패러다임
- **IDS/IPS**: 침입 탐지/방지 시스템. DMZ에 배치하여 공격을 감지하고 차단
