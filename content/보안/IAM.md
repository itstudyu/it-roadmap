# IAM (Identity and Access Management)

## 📝 정의

IAM(Identity and Access Management)은 클라우드나 시스템 리소스에 대한 접근 권한을 관리하는 서비스입니다. "누가(Who), 어떤 리소스에(What), 언제 어디서(When/Where), 어떤 조건에서(Condition) 접근할 수 있는가"를 정의하고 통제합니다. AWS IAM, Azure AD, Google Cloud IAM 등 클라우드 제공자들이 제공하며, 기업의 보안 정책을 자동으로 실행하는 핵심 서비스입니다. 최소 권한 원칙(Principle of Least Privilege)을 기반으로 필요한 최소한의 권한만 부여합니다.

> **한 줄 요약**: 누가 어떤 리소스에 어떤 권한으로 접근할 수 있는지를 중앙에서 관리하는 보안 서비스입니다.

**비유 1**: IAM은 마치 회사의 빌딩 출입 통제 시스템처럼, 누가 어느 층(리소스)에 들어갈 수 있는지(권한)를 ID 카드로 관리합니다.

**비유 2**: 도서관의 열람권 시스템처럼, 학생(User)은 교과서(리소스)만 열람 가능하고, 사서(Admin)는 모든 책을 관리할 수 있으며, 일반인(Guest)은 도서관 입장 자체가 불가합니다.

---

## 🎯 핵심 개념

### 1. User (사용자)
AWS 계정 내에서 작업하는 개인입니다. 사용자는 고유의 보안 자격 증명(AccessKey, 비밀번호)을 가지며, 각 사용자에게 정책을 직접 부여하거나 그룹을 통해 권한을 받습니다.

### 2. Group (그룹)
권한을 효율적으로 관리하기 위해 사용자를 모아 놓은 집합입니다. 그룹에 정책을 부여하면 그룹 내 모든 사용자가 해당 권한을 갖게 되어, 개별 사용자 관리보다 효율적입니다.

### 3. Role (역할)
AWS 서비스나 외부 사용자에게 권한을 부여할 때 사용합니다. 사용자와 달리 역할은 장기 자격 증명이 아닌 임시 보안 자격 증명(임시 Access Key)을 제공하여 보안성이 높습니다.

### 4. Policy (정책)
권한을 정의하는 JSON 문서입니다. "Principal(누가) Action(무엇을) Resource(어디에) 언제 어떤 조건에서 할 수 있는가"를 명시합니다. AWS는 관리형 정책(AWS 제공)과 커스텀 정책(사용자 정의)을 제공합니다.

### 5. Resource (리소스)
S3 버킷, EC2 인스턴스, RDS 데이터베이스, Lambda 함수 등 사용자가 접근하려는 AWS 서비스 자산입니다. 정책에서 ARN(Amazon Resource Name)으로 식별됩니다.

## ⚠️ 해결하는 문제

### 문제 1: 권한 관리의 복잡성
조직이 커지면서 수백 명의 사용자가 수천 개의 리소스에 접근하는데, 이를 수동으로 관리하면 실수와 보안 위험이 증가합니다.

### 문제 2: 과도한 권한 부여 (Over-provisioning)
보안 검토 없이 모든 권한을 부여하면, 실수나 악의적 행동으로 인한 피해 범위가 커집니다. 최소 권한 원칙을 적용해야 합니다.

### 문제 3: 비활성 사용자 계정의 방치
퇴사자나 프로젝트 완료 후 계정을 삭제하지 않으면, 오래된 자격 증명이 악용될 수 있습니다.

### 문제 4: 임직원 간 권한 관리의 일관성
부서마다 다른 권한 정책을 적용하면 혼란과 보안 위협이 발생합니다. 중앙 집중식 관리가 필요합니다.

### 문제 5: 외부 서비스와의 안전한 연동
API 키나 비밀번호를 코드에 하드코딩하면 보안이 취약합니다. IAM Role을 통해 임시 자격 증명을 발급하는 것이 안전합니다.

## ⚙️ 작동 원리

1. **권한 요청**: 개발자 또는 애플리케이션이 AWS 리소스에 접근하려고 합니다.

2. **인증 (Authentication)**: AWS는 요청자의 신원을 확인합니다 (Access Key, 비밀번호, 임시 토큰 등).

3. **권한 검사**: IAM이 해당 사용자/역할에 할당된 정책을 확인합니다.

4. **정책 평가**: 정책 엔진이 요청의 Principal(누가), Action(무엇을), Resource(어디에)를 정책과 비교합니다.

5. **조건 확인**: IP 주소, 시간대, MFA 여부 등 추가 조건이 있으면 확인합니다.

6. **최종 판단**: 모든 조건이 만족하면 Allow, 하나라도 Deny 규칙이 있으면 Deny입니다.

7. **결과 반환**: 권한이 있으면 리소스 접근 허용, 없으면 403 Access Denied 오류를 반환합니다.

## ✅ 장단점

### 장점
- **세밀한 권한 제어**: 리소스 단위, 액션 단위로 세밀하게 권한 설정 가능
- **최소 권한 원칙 적용**: 필요한 권한만 부여하여 보안 강화
- **감사 추적**: 모든 권한 부여 및 거부 기록이 남아 규정 준수 용이
- **중앙 집중식 관리**: 한 곳에서 전체 권한을 관리하여 일관성 유지
- **임시 자격 증명**: STS(Security Token Service)로 만료 가능한 임시 자격 증명 발급
- **통합된 보안**: MFA, IP 제한, 시간대 제한 등 추가 보안 조건 적용 가능

### 단점
- **복잡성**: 정책 문법과 권한 모델이 복잡하여 학습 곡선 가파름
- **잘못된 설정 위험**: 과도한 권한이나 너무 제한적인 설정으로 인한 문제 발생 가능
- **관리 부담**: 사용자 추가/삭제, 권한 변경 시 수동 작업 필요
- **비용**: 추가 IAM 기능이나 감사 로깅으로 인한 비용 증가
- **디버깅 어려움**: 권한 거부 오류 원인 파악이 어려울 수 있음
- **성능 오버헤드**: 모든 요청마다 권한 검사로 인한 미세한 지연

## 💡 실제 사례

### Case 1: S3 버킷 읽기 전용 역할 생성
데이터 분석팀에게 특정 S3 버킷의 파일을 읽기만 가능하도록 IAM 역할을 생성합니다. 정책은 s3:GetObject와 s3:ListBucket 권한만 허용하고, 삭제나 업로드는 차단합니다.

### Case 2: EC2 인스턴스에서 RDS 접근
EC2 서버가 실행되는 애플리케이션이 RDS 데이터베이스에 접근해야 합니다. IAM 역할을 EC2에 부여하여 데이터베이스 비밀번호를 하드코딩하지 않고 임시 자격 증명으로 안전하게 접근합니다.

### Case 3: 개발자별 권한 분리
junior 개발자에게는 테스트 환경(dev-) 리소스만 접근 가능하고, senior 개발자에게는 스테이징과 운영 환경 모두 접근 가능하도록 정책을 설정합니다.

### Case 4: 외부 컨설턴트 임시 접근
프로젝트 진행 중 외부 컨설턴트에게 3개월 간 특정 프로젝트 리소스에만 접근 가능한 임시 계정을 생성합니다. 계약 종료 후 자동으로 계정이 비활성화되도록 설정합니다.

### Case 5: 자동화 도구의 권한 최소화
CI/CD 파이프라인이 배포 시 필요한 최소 권한(특정 ECR 이미지 push, ECS 서비스 업데이트)만 부여합니다. 이를 통해 파이프라인 탈취 시에도 다른 리소스는 보호됩니다.

### Case 6: 규정 준수 (Compliance)
금융 회사가 모든 S3 접근을 CloudTrail로 로깅하고, IAM 정책으로 암호화되지 않은 버킷 생성을 차단합니다. 이를 통해 금융 규제(PCI-DSS, SOC 2)를 준수합니다.

## 🔗 관련 용어

- **ARN (Amazon Resource Name)**: AWS 리소스를 고유하게 식별하는 형식 (arn:aws:s3:::my-bucket/*)
- **STS (Security Token Service)**: 임시 보안 자격 증명을 발급하는 서비스
- **MFA (Multi-Factor Authentication)**: 비밀번호 + OTP 같은 다중 인증으로 보안 강화
- **AssumeRole**: 특정 역할의 권한을 가정(assume)하여 임시 자격 증명을 획득
- **Cross-Account Access**: 다른 AWS 계정의 리소스에 접근하기 위한 역할 설정
- **Identity Federation**: 온프레미스 Active Directory나 소셜 로그인(Google, Facebook)과 IAM 연동
- **Principle of Least Privilege (PoLP)**: 최소 권한 원칙으로 필요한 최소한의 권한만 부여
- **Access Advisor**: IAM 역할/사용자의 실제 사용 권한 추적 (미사용 권한 제거)
- **Policy Simulator**: 정책이 특정 요청을 허용할지 거부할지 미리 테스트하는 도구
