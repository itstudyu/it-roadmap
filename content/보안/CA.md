# CA (Certificate Authority, 인증 기관)

## 📝 정의

CA는 **인증서에 서명해 서버 신원을 보증하는 기관**이다.

브라우저는 처음 보는 서버를 믿을 근거가 없다. 대신 미리 믿기로 정해둔 기관 목록을 갖고 있고, 그중 하나가 서명한 인증서를 내밀면 그 서명을 근거로 믿는다.

### 비유
여권. 종이 자체를 믿는 게 아니라 그것을 발급한 나라를 믿기 때문에 다른 나라에서도 통한다.

### 예
주소창의 자물쇠를 눌러 인증서 정보를 열면 발급한 기관 이름이 적혀 있다. 브라우저가 확인한 것이 그 이름이다.

## 🖼️ 그림으로 보기

```도해
흐름: 인증서 하나가 브라우저에 믿길 때까지 무슨 일이 있나
관리자 :: 공개 키와 도메인을 담은 요청서를 낸다
CA :: 그 도메인이 정말 신청자 것인지 확인한다
CA :: 확인되면 자기 개인 키로 서명해 발급한다
서버 :: 받은 인증서를 웹서버에 설치한다
브라우저 :: 접속할 때 인증서를 받아 서명을 검증한다
브라우저 :: 믿는 기관 목록에 있으면 자물쇠를 띄운다
= 서버를 믿는 게 아니라 서명한 기관을 믿는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 서명해줄 기관이 없으면 어떻게 되나
보증 없이 || CA 로
상대 확인 :: 말만 믿는다 || 서명을 검증
가짜 서버 :: 구분이 안 된다 || 경고가 뜬다
암호화 :: 되긴 된다 || 상대까지 확인
= 암호화는 내용만 가릴 뿐 상대가 누구인지는 말해주지 않는다
```

공격자가 진짜와 똑같이 생긴 서버를 세우고 사용자를 그쪽으로 끌어들이는 일은 어렵지 않다. 통신이 암호화돼 있어도 소용이 없다. 암호화는 오가는 내용을 가릴 뿐, 그 상대가 원래 가려던 곳인지는 말해주지 않기 때문이다.

CA 는 이 자리에 제3자를 넣는다. 도메인의 주인만 인증서를 받을 수 있게 해두면, 가짜 서버는 그 도메인에 맞는 서명된 인증서를 구할 수 없다. 그래서 브라우저가 경고를 띄운다.

## 🧱 구성

```도해
층: 인증서는 어디까지 거슬러 올라가 검증되나
루트 CA :: 브라우저와 OS 에 미리 들어 있는 최상단
중간 CA :: 루트가 서명해준 기관. 실제 발급을 맡는다
서버 인증서 :: 중간 CA 가 서명한 것. 서버가 이걸 제시한다
= 한 단계라도 서명이 안 맞으면 전체가 거부된다
```

## ⚙️ 작동 원리

도메인 소유를 확인하는 방법은 대개 셋이다. 지정한 값을 DNS 레코드에 넣게 하거나, 그 도메인의 메일 주소로 확인 링크를 보내거나, 웹사이트의 정해진 경로에 파일을 올리게 한다. 셋 다 도메인을 실제로 다룰 수 있는 사람만 할 수 있는 일이다.

루트를 직접 쓰지 않고 중간 단계를 두는 이유는 루트 키가 새어 나가면 되돌릴 방법이 없기 때문이다. 루트 키는 인터넷에 연결되지 않은 곳에 두고 중간 CA 만 서명해준다. 중간 CA 가 뚫리면 그 중간 CA 만 폐기하고 새로 발급하면 된다.

## 📊 비교: 검증 수준

| 등급 | 확인하는 것 | 쓰이는 곳 |
|---|---|---|
| DV | 도메인 소유 여부만 | 대부분의 일반 사이트 |
| OV | 도메인에 더해 조직 실체 | 회사 서비스 |
| EV | 법적 서류까지 확인 | 금융처럼 신원 표시가 중요한 곳 |

## 💡 실제 사례

- **무료 인증서 자동 갱신** — Let's Encrypt 는 유효 기간이 90일이라 갱신을 자동화해두고 쓴다.
- **사내 전용 인증서** — 외부에서 접속하지 않는 시스템은 회사가 만든 루트를 직원 PC 에 심어 쓴다.
- **도메인 여러 개** — 한 인증서에 여러 도메인을 넣어 발급받아 서버 하나로 처리한다.

## 🚫 흔한 오해

- **자물쇠가 떠 있으면 안전한 사이트다** — 그 주소가 맞다는 것만 보증한다. 사기 사이트도 자기 도메인으로 인증서를 받을 수 있고, 그때도 자물쇠는 똑같이 뜬다.
- **인증서가 통신을 암호화한다** — 암호화는 TLS 가 한다. 인증서는 상대가 그 도메인의 주인인지 확인하는 데 쓰이고, 그 확인이 끝난 뒤에 암호화가 시작된다.
- **인증서는 직접 만들어 붙이면 된다** — 만들 수는 있지만 아무도 서명해주지 않았으니 브라우저가 거부한다. 믿을지 말지는 누가 서명했는지로 정해진다.

## 🚨 주의사항

- **만료일을 놓치면 서비스가 멈춘 것처럼 보인다.** 서버는 멀쩡한데 브라우저가 경고를 띄워 사용자가 못 들어온다.
- **인증서의 도메인과 접속 주소가 다르면 거부된다.** 도메인을 바꾸거나 늘릴 때는 인증서에도 그 이름을 넣어야 한다.

## 📝 정리

CA 는 도메인 소유를 확인하고 인증서에 서명해 서버 신원을 보증하는 기관이다. 브라우저가 믿는 것은 서버가 아니라 그 서명이며, 그래서 인증서는 신원만 말할 뿐 그 사이트의 선의까지 보증하지 않는다.

## ❓ 이해했는지

- 직접 만든 인증서를 서버에 붙였을 때 브라우저가 경고를 띄우는 이유는 → 흔한 오해
- 자물쇠만으로는 그 회사가 실재하는지 알 수 없다. 조직까지 확인하는 등급은 무엇인가 → 비교
- 루트를 직접 쓰지 않고 중간 CA 를 두는 이유는 → 작동 원리
