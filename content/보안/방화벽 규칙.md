# 방화벽 규칙 (Firewall Rules)

## 📝 정의

방화벽 규칙은 **어떤 통신을 통과시키고 무엇을 막을지 적어둔 목록**이다.

규칙 한 줄은 출발지, 목적지, 포트, 프로토콜, 방향, 그리고 허용할지 막을지로 이루어진다. 방화벽은 이 목록을 위에서 아래로 읽는다.

### 비유
빌딩 경비원의 체크리스트. 위에서부터 읽다가 맞는 줄이 나오면 거기서 판단을 끝내고 아랫줄은 보지 않는다.

## 🖼️ 그림으로 보기

```도해
흐름: 들어온 패킷 하나는 어떤 판정을 거치나
패킷 도착 :: 출발지, 목적지, 포트, 프로토콜이 적혀 있다
규칙 1 :: 그 값들이 맞는지 본다. 안 맞으면 다음 줄
규칙 2 :: 맞으면 적힌 대로 허용하거나 막고 끝낸다
기본 정책 :: 끝까지 아무 줄도 안 맞으면 여기로 온다
로그 :: 막힌 것은 기록에 남는다
= 첫 번째로 맞는 줄에서 판정이 끝나므로 순서가 곧 정책이다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버의 포트를 다 열어두면 어떻게 되나
규칙 없이 || 규칙을 두면
포트 스캔 :: 열린 곳이 다 보임 || 두셋만 보인다
DB 접근 :: 밖에서 바로 || 앱 서버만 허용
감염된 뒤 :: 어디로든 내보냄 || 나가는 곳도 막힘
= 열어 둔 만큼만 공격받을 면이 된다
```

열려 있는 포트는 전부 두드려 볼 수 있는 문이다. 공격하는 쪽은 무작위로 포트를 훑어 열린 곳을 찾고, 거기에 알려진 구멍이 있으면 그리로 들어온다. 데이터베이스나 관리자 화면이 인터넷에서 바로 닿으면 웹 서버를 뚫는 단계를 아예 건너뛴다.

규칙은 필요한 문만 남긴다. DB 포트를 앱 서버 IP 에서 오는 것만 허용하면 밖에서는 그 문이 보이지도 않는다. 나가는 쪽까지 정해 두면 서버가 감염됐을 때 데이터를 아무 데로나 실어 내는 것도 막힌다.

## ⚙️ 작동 원리

```도해
층: 판정은 어느 줄에서 끝나나
위쪽 규칙 :: 먼저 읽는다. 여기서 맞으면 끝이다
아래쪽 규칙 :: 위에서 안 맞은 것만 여기까지 내려온다
기본 정책 :: 끝까지 안 맞은 것에 적용된다. 대개 차단
= 넓은 규칙을 위에 두면 아래의 세밀한 규칙은 영영 안 읽힌다
```

요즘 방화벽은 대개 상태를 기억한다. 안에서 밖으로 나간 요청을 적어 두었다가 그 응답이 돌아오면 인바운드 규칙에 없어도 통과시킨다. 덕분에 나가는 통신마다 돌아오는 규칙을 짝지어 적지 않아도 된다.

기본 정책을 무엇으로 두느냐가 방식을 가른다. 다 막아 놓고 필요한 것만 적는 쪽이 화이트리스트, 다 열어 놓고 문제 되는 것만 적는 쪽이 블랙리스트다.

## 📊 비교: 화이트리스트 vs 블랙리스트

| | 화이트리스트 | 블랙리스트 |
|---|---|---|
| 기본 정책 | 전부 차단 | 전부 허용 |
| 목록에 적는 것 | 허용할 것 | 막을 것 |
| 모르는 공격 | 자동으로 막힌다 | 그대로 들어온다 |
| 관리 | 필요한 걸 다 적어야 한다 | 문제 생길 때만 추가 |

## 💡 실제 사례

- **3층 구조** 웹 서버는 80과 443만 열고, DB 는 앱 서버에서 오는 3306 만 받는다.
- **SSH 접근 제한** 22번을 아무 데나 열지 않고 사무실 IP 와 VPN 대역에서만 허용한다.
- **공격 IP 차단** 로그에서 찾은 출발지 IP 를 막는 규칙을 목록 맨 위에 넣는다.

## 🚫 흔한 오해

- **방화벽 규칙이 위험한 것을 알아서 걸러준다** — 규칙에 적힌 것만 본다. 출발지와 포트가 맞으면 그 안에 무엇이 들었든 통과시킨다.
- **규칙 순서는 상관없다** — 첫 번째로 맞는 줄에서 판정이 끝난다. 넓은 허용 규칙을 위에 두면 아래에 적어 둔 차단 규칙은 읽히지도 않는다.
- **인바운드만 막으면 된다** — 나가는 쪽을 열어두면 감염된 서버가 데이터를 밖으로 실어 낸다. 아웃바운드도 필요한 것만 남긴다.

## 🚨 주의사항

- **넓은 규칙을 위에 두지 않는다.** 맨 위의 `0.0.0.0/0` 허용 한 줄이 아래 규칙 전부를 무력화한다.
- **IP 로 묶은 규칙은 IP 가 바뀌면 끊어진다.** 주소가 자주 바뀌는 환경에서는 규칙이 조용히 낡는다.

## 📝 정리

방화벽 규칙은 어떤 통신을 통과시키고 무엇을 막을지 위에서 아래로 적어둔 목록이다. 첫 번째로 맞는 줄에서 판정이 끝나므로 무엇을 적었는지만큼 어느 순서로 적었는지가 중요하다. 기본은 다 막고 필요한 것만 여는 쪽이며, 나가는 쪽까지 정해야 절반만 한 게 아니게 된다.

## ❓ 이해했는지

- 맨 위에 넓은 허용 규칙을 하나 넣으면 그 아래 규칙들은 어떻게 되나?
- 밖으로 나간 요청의 응답에는 인바운드 규칙을 따로 안 적어도 되는 이유는?
- 인바운드만 잠그고 아웃바운드를 열어두면 무엇을 못 막나?
