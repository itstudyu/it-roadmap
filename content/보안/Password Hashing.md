# Password Hashing (비밀번호 해싱)

## 📝 정의

Password Hashing은 **비밀번호를 되돌릴 수 없는 값으로 바꿔 저장하는 것**이다.

저장할 때는 사람마다 다른 값 하나(솔트)를 함께 섞고, 일부러 느린 함수로 뭉갠다. 저장소가 통째로 새어 나가도 그 안에 원래 비밀번호가 없게 만드는 것이 목적이다.

### 이름
Password :: 비밀번호
Hashing :: 되돌릴 수 없게 뭉개기
= 붙여 읽으면 "비밀번호를 되돌릴 수 없게 뭉개 두기". 맞는지 견주기만 하고 원래 값은 갖지 않는다

### 비유
지문. 손가락을 보관하는 게 아니라 눌러 찍은 자국만 두고, 다음에 또 찍어서 같은지만 본다.

### 예
비밀번호를 잊었을 때 어느 사이트도 원래 값을 알려 주지 못하고 새로 정하게만 하는 그 화면이다.

### 직접
쓰던 사이트에서 "비밀번호 찾기" 를 눌러 보라. 원래 비밀번호를 보여 주는 곳은 없고 전부 새로 정하라고만 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 로그인할 때 저장된 비밀번호와 어떻게 견주나
가입할 때 :: 사람마다 다른 솔트를 뽑아 함께 뭉갠다
저장 :: 뭉갠 결과와 솔트만 남기고 원래 값은 버린다
로그인 :: 입력받은 값에 그 사람의 솔트를 다시 붙인다
같은 계산 :: 저장할 때와 똑같이, 일부러 느리게 뭉갠다
견주기 :: 두 결과가 같으면 통과시킨다
= 원래 비밀번호는 어디에도 없고, 매번 다시 뭉개서 같은지만 본다
```

## ⚠️ 해결하는 문제

```도해
대조: 저장소가 통째로 새어 나가면 무엇이 달라지나
그대로 저장하면 || 뭉개서 저장하면
털린 직후 :: 전부 즉시 쓰인다 || 아직 못 쓴다
같은 비밀번호 :: 한 번에 다 뚫림 || 하나씩 풀어야
다른 사이트 :: 같이 뚫린다 || 시간을 번다
= 새어 나가는 것을 막는 자리가 아니라, 새고 난 뒤를 대비하는 자리다
```

저장소는 언젠가 새어 나간다. 비밀번호를 그대로 적어 두었다면 그날이 곧 끝이고, 사람들이 다른 사이트에서 같은 비밀번호를 쓰는 습관 때문에 피해는 그 사이트 밖으로 번진다.

뭉개서 저장하면 새어 나간 쪽이 할 수 있는 일이 "찍어서 맞혀 보기" 하나로 줄어든다. 솔트가 사람마다 다르면 한 번 계산한 값을 모두와 비교하는 수법이 안 통하고, 같은 비밀번호를 쓴 두 사람의 저장값도 서로 달라진다. 그래서 공격자는 하나씩 따로 풀어야 한다. 여기에 함수가 느리기까지 하면 그 "하나씩" 이 감당 못 할 시간이 된다.

## ⚙️ 작동 원리

솔트는 비밀을 더하는 장치가 아니라 **묶어서 푸는 길을 막는 장치**다. 사람마다 다르게 뽑아 뭉갠 결과와 함께 남기고, 다음 로그인 때 같은 계산을 그대로 재현하는 데 쓴다. 노리는 것은 한 번 계산한 값을 모두와 견주는 수법을 못 쓰게 만드는 것 하나다. NIST 는 솔트를 최소 32비트 이상으로, 저장값끼리 겹치지 않게 고르라고 적는다. 저장소 밖에 따로 두는 값인 후추와 갈리는 자리가 여기다.

두 번째 장치가 느림이다. 비밀번호용 함수에는 계산을 몇 겹으로 되풀이하게 하는 값(작업 계수)이 붙어 있다. 이 값을 올리면 공격자가 한 번 찍는 비용도 같이 올라간다. NIST 는 검증하는 쪽 성능을 해치지 않는 선에서 최대한 높게 잡고, 기계가 빨라지는 만큼 시간이 지나면 올리라고 적는다. OWASP 가 드는 실용적인 기준은 해시 한 번 계산이 1초 안에 끝나는 선이다.

같은 문서가 비밀번호 정책도 함께 정리한다. 주기적으로 바꾸게 요구하지 말고, 대소문자와 특수문자를 섞으라는 조합 규칙도 걸지 말라는 것이다. 털린 정황이 있을 때만 강제로 바꾸게 한다.

## 📊 비교: 어떤 함수를 쓰나

| 함수 | 권고 설정 | 언제 |
|---|---|---|
| **Argon2id** | 메모리 19MiB · 반복 2 · 병렬 1 | 기본 선택 |
| **scrypt** | 비용 2^17 · 블록 8 · 병렬 1 | Argon2id 를 못 쓸 때 |
| **bcrypt** | 작업 계수 10 이상 · 입력 72바이트 제한 | 이미 쓰고 있는 곳 |
| **PBKDF2** | 60만 회 이상 · HMAC-SHA-256 | 규격 준수가 필요할 때 |

## 💡 실제 사례

- **비밀번호 찾기** — 원래 값을 되돌려 줄 수 없으니 어느 사이트도 새로 정하게만 한다.
- **작업 계수 올리기** — 기계가 빨라지면 같은 계산이 싸진다. 그래서 계수는 한 번 정하고 두는 값이 아니라 주기적으로 올리는 값이다.
- **후추 한 줌 더하기** — 저장소 밖에 둔 비밀값을 함께 섞어 두면, 저장소만 새어 나갔을 때 그것만으로는 못 푼다.

## 🚫 흔한 오해

- **비밀번호는 암호화해서 저장한다** — 암호화는 열쇠가 있으면 원래 값이 되돌아온다. 되돌아오면 안 되는 값이라서 해시를 쓴다.
- **해시니까 SHA-256 으로 하면 된다** — 빠른 해시는 공격자가 짧은 시간에 어마어마하게 많이 찍어보게 해 준다. 비밀번호용 함수는 일부러 느리게 만든 것이다.
- **작업 계수는 높일수록 좋다** — 로그인 검증도 그만큼 느려진다. OWASP 는 계산 한 번이 1초 안에 끝나는 선을 기준으로 잡으라고 적는다.

## 📝 정리

**"원래 비밀번호를 안 갖고도 맞는지 볼 수 있게 뭉개 두는 그 저장법"** 이라고 읽으면 된다. 사람마다 다른 솔트가 한꺼번에 푸는 길을 막고, 일부러 느리게 만든 계산이 하나씩 찍어보는 속도를 떨어뜨린다. 새는 것을 막는 장치가 아니라 새고 난 뒤에 시간을 버는 장치다.

## 🧒 열 살에게

손가락 지문을 생각해 봐. 도장처럼 꾹 찍은 자국만 남겨 두면 다음에 또 찍어서 같은지는 볼 수 있는데, 그 자국만 보고 손가락을 만들어 낼 수는 없잖아. 그래서 자국을 몽땅 훔쳐 가도 바로는 못 쓰는 거야.

## ❓ 이해했는지

- 어느 사이트도 잊어버린 비밀번호를 그대로 알려 주지 못하는 까닭은 무엇인가 → 그림
- 같은 비밀번호를 쓴 두 사람의 저장값이 서로 다른 까닭은 무엇인가 → 작동 원리
- 계산이 빠른 해시를 비밀번호에 쓰면 무엇이 문제가 되나 → 흔한 오해
