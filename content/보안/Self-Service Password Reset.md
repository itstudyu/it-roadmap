# Self-Service Password Reset (스스로 푸는 비밀번호)

## 📝 정의

Self-Service Password Reset은 **잊은 비밀번호를 본인이 직접 되돌리는 길**이다.

Microsoft 문서는 이 말을 "관리자나 헬프데스크가 끼어들지 않고 사용자가 스스로 비밀번호를 바꾸거나 되돌릴 수 있게 하는 것" 으로 적고, 그 효과를 "헬프데스크 전화와 생산성 손실이 준다" 로 적는다. 줄여서 SSPR 이라 부른다.

### 이름
Self :: 스스로
Service :: 알아서 처리
Password :: 비밀번호
Reset :: 처음으로 되돌리기
= 붙여 읽으면 "비밀번호를 스스로 되돌리기". 누가 하느냐가 이름 맨 앞에 박혀 있다

### 비유
사물함 열쇠를 잃었을 때 관리인을 찾아가는 대신, 미리 맡겨 둔 내 확인 수단 두 가지를 대고 새 열쇠를 받는 것.

### 예
로그인 화면에서 "비밀번호를 잊으셨나요" 를 눌러 문자로 온 숫자를 넣고 새 비밀번호를 정하던 그 3분이다.

### 직접
지금 쓰는 계정의 보안 설정을 열어 보라. 잊었을 때 쓸 확인 수단이 몇 개 등록돼 있는지 거기 적혀 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 비밀번호를 잊은 사람이 어떻게 스스로 다시 들어가나
미리 등록 :: 잊기 전에 확인 수단을 둘 이상 걸어 둔다
막힌다 :: 로그인 화면에서 "못 들어감" 을 누른다
자격 확인 :: 그 사람이 이 길을 쓸 수 있는지 먼저 본다
본인 확인 :: 걸어 둔 수단으로 하나씩 답한다
새로 정함 :: 새 비밀번호를 걸고 잠긴 계정도 함께 풀린다
= 사람에게 부탁하는 대신, 잊기 전에 걸어 둔 것으로 본인을 증명한다
```

## ⚠️ 해결하는 문제

```도해
대조: 남이 대신 풀어 주면 무엇이 달라지나
사람이 풀어 주면 || 스스로 풀면
새벽에 잊으면 :: 아침까지 못 쓴다 || 그 자리에서 푼다
확인 방법 :: 목소리로 넘겨짚음 || 걸어 둔 수단으로
쌓이는 일 :: 전화가 계속 쌓인다 || 사람 손이 안 든다
= 잊는 일은 반드시 생긴다. 누가 푸느냐만 미리 정해 둘 수 있다
```

비밀번호를 잊는 일은 사고가 아니라 정해진 확률로 계속 일어나는 일이다. 그런데 푸는 쪽을 사람에게 맡기면 시간대에 갇힌다. 새벽이나 주말에 막힌 사람은 담당자가 출근할 때까지 아무것도 못 한다.

더 나쁜 것은 확인 방법 쪽이다. 급한 전화로 "저 아무개인데요" 를 받아 주기 시작하면, 그 통로가 그대로 남을 속이는 길이 된다. 스스로 푸는 길은 **잊기 전에 미리 걸어 둔 수단**으로만 확인하게 해서 이 두 가지를 같이 없앤다.

## ⚙️ 작동 원리

핵심은 순서다. 이 길은 **잊은 다음이 아니라 잊기 전에** 준비된다. 사용자는 먼저 확인 수단을 등록하고, 관리자는 그중 무엇을 허용할지와 몇 개를 요구할지를 정한다. Microsoft 문서가 드는 수단은 인증 앱 알림, 하드웨어·소프트웨어 일회용 코드, 문자, 음성 통화, 이메일 일회용 코드다.

요구 개수는 하나 또는 둘 중에서 고른다. 여기서 자주 사고가 난다 — 하나만 등록해 둔 사람이 있는 상태에서 정책을 둘로 올리면, 그 사람은 이 길을 쓰지 못하고 결국 관리자를 부르게 된다. 그래서 문서는 두 개 이상 등록을 권한다.

관리자 역할이 붙은 계정에는 더 센 정책이 따로 걸린다. 회사 안 저장소에 비밀번호가 있는 경우에는 바뀐 값을 되돌려 쓰는 설정이 켜져 있어야 하고, 그게 없으면 그 사람은 이 길을 쓸 수 없다. 비밀번호를 바꾸지 않고 잠금만 푸는 것도 따로 허용할 수 있다.

## 💡 실제 사례

- **월요일 아침 전화** — 주말 뒤 첫 로그인에서 막히는 사람이 몰린다. 스스로 푸는 길이 열려 있으면 그 줄이 통째로 사라진다.
- **잠금만 풀기** — 비밀번호는 기억나는데 계정만 잠긴 경우가 있다. 되돌리기와 잠금 해제를 갈라 두면 비밀번호를 그대로 두고 풀 수 있다.
- **등록을 강제하기** — 로그인할 때마다 등록 화면을 띄우게 해 두면, 정작 잊었을 때 걸어 둘 수단이 없어 못 쓰는 일이 준다.

## 🚫 흔한 오해

- **비밀번호를 주기적으로 바꾸게 하는 게 안전하다** — NIST 는 정기 변경을 요구하지 말라고 못 박는다. 다만 털린 정황이 있으면 그때는 강제로 바꾸게 한다.
- **비밀 질문을 걸어 두면 스스로 풀 수 있다** — 같은 문서가 "첫 반려동물 이름" 같은 지식 기반 확인을 쓰지 말라고 적는다. 남이 알아낼 수 있는 답은 확인 수단이 못 된다.
- **수단은 하나만 등록해 두면 충분하다** — 그 하나에 손이 안 닿는 날이 온다. 폰을 잃었거나 번호를 바꿨거나 정책이 둘로 올라간 순간, 그 사람은 결국 관리자를 부른다.

## 📝 정리

**"잊었을 때 누구를 부르느냐를 미리 정해 두는 길"** 이라고 읽으면 된다. 잊는 일 자체는 못 막으니 잊기 전에 확인 수단을 둘 이상 걸어 두는 쪽에 힘을 쓴다. 걸어 둔 수단이 정책보다 적으면 그 사람은 결국 관리자를 부른다.

## 🧒 열 살에게

사물함 열쇠를 잃어버리면 관리하는 어른을 찾아가야 하지? 그런데 미리 네 목소리랑 손도장을 맡겨 두면, 어른을 안 부르고도 네가 맞다는 걸 보여 주고 새 열쇠를 바로 받을 수 있어.

## ❓ 이해했는지

- 잊기 전에 반드시 해 두어야 하는 일은 무엇이고 왜 그런가 → 그림
- 비밀번호를 90일마다 바꾸게 하는 규칙이 왜 권장되지 않나 → 흔한 오해
- 담당자에게 전화가 계속 쌓이는 일을 이 길이 어떻게 없애나 → 해결하는 문제

## 🔗 관련 용어

- [[MFA]] — 스스로 풀 때 본인을 증명하는 수단이 곧 이것이다
- [[Password Hashing]] — 새로 정한 비밀번호가 저장되는 방식
- [[User Provisioning]] — 계정을 만들고 지우는 쪽. 되돌리기는 그 계정 일생의 한 대목이다
- [[SSO]] — 한 번 들어가면 여러 곳이 열리는 쪽. 그 하나가 막히면 전부 막힌다
- [[IAM]] — 이 길을 누구에게 열어 줄지 정하는 자리
