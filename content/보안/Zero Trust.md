# Zero Trust (제로 트러스트)

## 📝 정의

Zero Trust는 **어디서 왔든 매번 다시 확인하는 보안 원칙**이다.

사내망에 있다는 이유로 통과시키지 않는다. 요청마다 누구인지, 어떤 기기인지, 그 자원에 권한이 있는지를 확인한다.

### 비유
공항의 보안 검색. 이미 입국 심사를 통과했더라도 탑승구마다 다시 확인한다. 한 번 들어왔다는 사실이 다음 문을 여는 근거가 되지 않는다.

## 🖼️ 그림으로 보기

```도해
흐름: 사내 위키에 접속할 때 무엇을 확인하나
사용자 :: 사내 위키를 연다
확인 :: 로그인된 사람이 맞는지 본다
확인 :: 회사가 관리하는 기기인지 본다
확인 :: 이 문서를 볼 권한이 있는지 본다
확인 :: 평소와 다른 나라에서 접속하는지 본다
허용 :: 넷 다 통과했을 때만 열어준다
@ 다음 요청에 :: 넷을 처음부터 또 확인한다
= 사내망 여부는 판단 근거 목록에 아예 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 공격자가 사내망 안으로 들어오면 어떻게 되나
경계 방어 || 제로 트러스트
내부 이동 :: 자유롭다 || 매번 막힌다
재택 근무 :: VPN 으로 내부 취급 || 어디서든 같은 검사
피해 범위 :: 전체로 번진다 || 그 자원 하나
= 안과 밖을 나누는 선이 이미 무의미해졌다는 인정에서 출발한다
```

전통적인 보안은 성벽 모델이었다. 방화벽으로 안과 밖을 나누고, 안에 들어온 것은 믿는다. 이 모델은 직원이 사무실에서만 일하고 서버가 사내에만 있을 때 성립했다.

지금은 그 전제가 깨졌다. 직원은 집과 카페에서 일하고 서버는 클라우드에 있고 협력사도 사내 시스템을 쓴다. 무엇보다 공격자가 직원 계정 하나만 뚫으면 그 성벽 안쪽에 서게 된다. 안에 들어온 것을 믿는 순간 나머지가 전부 열린다.

## ⚙️ 작동 원리

요청 하나를 받을 때마다 네 가지를 함께 본다. 위아래로 쌓인 것이 아니라 한자리에서 같이 견주는 값들이다.

- **신원** — 이 사람이 누구인가. 다단계 인증으로 확인한다.
- **기기** — 회사가 관리하는 장비인가. 보안 패치 상태는 어떤가.
- **권한** — 이 자원에 접근할 자격이 있는가.
- **맥락** — 시간과 위치가 평소와 다르지 않은가.

넷을 종합해 매번 판단하고, 하나라도 어긋나면 막거나 재인증을 요구한다.

핵심 규칙이 몇 가지 있다. 필요한 최소 권한만 준다. 권한은 기간을 정해 주고 만료시킨다. 모든 접근을 기록한다.

## 💡 실제 사례

- **VPN 없는 원격 근무** — 사내망에 넣는 대신 서비스마다 신원과 기기를 확인한다.
- **한시 권한** — 운영 서버 접근 권한을 30분만 발급하고 자동으로 회수한다.
- **이상 감지** — 평소 서울에서 접속하던 계정이 다른 나라에서 열리면 추가 인증을 요구한다.

## 🚫 흔한 오해

- **제로 트러스트는 제품이다** — 원칙이다. 이걸 통째로 파는 제품은 없고, 신원 관리와 기기 관리와 로그를 합쳐서 만든다.
- **VPN을 없애는 것이 목적이다** — 목적은 위치를 신뢰 근거에서 빼는 것이다. VPN을 쓰더라도 그 안에서 다시 확인하면 원칙은 지켜진다.
- **아무도 못 믿으니 불편해진다** — 잘 구현하면 오히려 편해진다. 신원과 기기가 확인되면 사용자는 아무것도 입력하지 않고 통과한다.

## 🚨 주의사항

- **한 번에 전부 바꾸려 하지 않는다.** 중요한 자원부터 하나씩 옮긴다. 전면 전환을 시도하면 대개 중간에 멈춘다.
- **로그가 없으면 원칙이 아니라 구호다.** 무엇을 언제 누가 열었는지 남지 않으면 확인했다는 사실을 증명할 수 없다.

## 📝 정리

Zero Trust는 위치를 신뢰의 근거에서 빼고 요청마다 신원과 기기와 권한을 확인하는 원칙이다. 제품이 아니라 방향이고, 뚫렸을 때 번지는 범위를 줄이는 것이 실질적인 이득이다.
