# XSS (Cross-Site Scripting)

## 📝 정의

XSS는 **남의 브라우저에서 내 스크립트를 실행시키는 공격**이다.

댓글이나 프로필에 스크립트를 심어두면, 그 페이지를 여는 다른 사용자의 브라우저가 그것을 실행한다. 공격자는 그 사람의 쿠키를 훔치거나 그 사람인 척 요청을 보낼 수 있다.

### 비유
게시판에 붙인 가짜 안내문. 지나가는 사람들이 그것을 공식 안내로 믿고 시키는 대로 한다. 안내문을 붙인 사람이 아니라 읽은 사람들이 피해를 본다.

## 🖼️ 그림으로 보기

```도해
흐름: 댓글 하나가 남의 계정을 어떻게 털어가나
공격자 :: 댓글에 스크립트 태그를 넣어 저장한다
서버 :: 그 문자열을 그대로 DB 에 저장한다
피해자 :: 게시글을 연다
서버 :: 댓글을 HTML 에 그대로 끼워 넣어 보낸다
브라우저 :: 스크립트로 인식하고 실행한다
< 공격자 :: 피해자의 쿠키가 공격자 서버로 전송된다
= 공격자는 피해자를 만난 적도 없고 피해자는 클릭한 적도 없다
```

## ⚠️ 해결하는 문제

이 항목은 해결하는 문제가 아니라 **막아야 할 공격**이다.

```도해
대조: 사용자 입력을 화면에 어떻게 넣나
그대로 넣기 || 이스케이프
`<script>` :: 태그로 실행된다 || 글자로 보인다
따옴표 :: 속성을 끊는다 || 글자로 보인다
방어 방식 :: 나쁜 것을 찾아 지움 || 전부 글자 취급
= 무엇이 위험한지 목록을 만드는 대신, 전부 글자로 취급하는 쪽이 이긴다
```

[[SQL Injection]]과 뿌리가 같다. 데이터로 들어온 것이 명령으로 해석되는 문제다. 다만 실행되는 곳이 데이터베이스가 아니라 사용자의 브라우저라는 점이 다르고, 그래서 피해자가 서버가 아니라 다른 사용자다.

막는 방법도 같은 성격이다. 위험한 문자를 찾아 지우는 대신, 화면에 넣는 모든 값을 글자로만 취급하도록 이스케이프한다.

## ⚙️ 작동 원리

세 갈래로 나뉜다.

| 종류 | 스크립트가 어디 있나 | 특징 |
|---|---|---|
| 저장형 | 서버 DB에 저장됨 | 보는 사람 전부가 당한다 |
| 반사형 | URL 파라미터에 실려 옴 | 링크를 클릭해야 당한다 |
| DOM 기반 | 서버를 거치지 않음 | 프론트엔드 코드가 원인 |

DOM 기반은 서버 로그에 흔적이 남지 않아서 발견이 특히 늦다. `innerHTML`에 사용자 입력을 넣는 코드가 대표적인 원인이다.

## 💡 실제 사례

- **쿠키 탈취** 세션 쿠키를 공격자 서버로 보내 그 계정으로 로그인한다.
- **가짜 로그인 창** 페이지 안에 진짜처럼 보이는 입력 폼을 그려 비밀번호를 받아간다.
- **자동 요청** 피해자의 권한으로 글을 쓰거나 설정을 바꾼다.

## 🚫 흔한 오해

- **`<script>` 만 막으면 된다** — `onerror`, `onload` 같은 이벤트 속성으로도 실행된다. `<img src=x onerror=...>` 가 대표적이다.
- **HTTPS를 쓰면 막힌다** — 오가는 길을 가릴 뿐이다. 페이지 안에서 실행되는 스크립트와는 무관하다.
- **로그인이 필요한 페이지는 안전하다** — 로그인한 사용자가 피해자가 되는 것이 오히려 공격 목적이다.

## 🚨 주의사항

- **쿠키에 `HttpOnly` 를 건다.** 그러면 스크립트가 쿠키를 읽지 못해 탈취 경로 하나가 막힌다.
- **`innerHTML` 대신 `textContent` 를 쓴다.** 마크업이 꼭 필요하면 검증된 정화 라이브러리를 거친다.

## 📝 정리

XSS는 남의 브라우저에서 스크립트를 실행시키는 공격이다. 화면에 넣는 모든 값을 글자로 취급하는 이스케이프가 기본 방어이고, 위험한 태그 목록을 관리하는 방식은 계속 새는다.
