# SQL Injection

## 📝 정의

SQL Injection은 악의적인 SQL 코드를 입력 필드에 삽입하여, 데이터베이스에 대한 비정상적인 쿼리를 실행시키는 보안 공격입니다. 애플리케이션이 사용자 입력값을 검증하지 않고 직접 SQL 쿼리에 연결할 때 발생하며, 공격자는 데이터베이스 조회, 수정, 삭제는 물론 관리자 권한 획득까지 가능합니다.

SQL Injection은 가장 오래되고 치명적인 웹 보안 취약점 중 하나입니다. 공격자가 데이터베이스에 직접 접근하므로, 애플리케이션의 보안 메커니즘을 모두 우회할 수 있고, 전체 데이터베이스가 노출되거나 손상될 수 있습니다.

> **한 줄 요약**: SQL Injection은 악의적인 SQL 코드를 입력값에 삽입하여 데이터베이스를 조작하는 공격

**비유 1**: SQL Injection은 정상적인 편지에 몰래 추가 지시문을 써 넣는 것과 같습니다. 편지를 받는 사람은 원래 요청과 추가된 악의적인 지시문을 구분하지 못하고 모두 따릅니다.

**비유 2**: SQL Injection은 정상적인 약속에 공격자가 숨어서 끼어드는 것과 같습니다. 마치 원래 초대받은 손님인 것처럼 행동하여 집 안의 모든 것에 접근하고 조작할 수 있습니다.

## 🎯 핵심 개념

### 1. 입력값의 직접 삽입
개발자가 사용자 입력값을 검증하거나 이스케이프하지 않고, SQL 쿼리 문자열에 직접 연결할 때 SQL Injection 취약점이 발생합니다.

### 2. SQL 문법의 해석
데이터베이스는 최종적으로 전달받은 SQL 문자열을 분석하여 실행하므로, 문자열에 포함된 모든 SQL 키워드가 명령으로 해석됩니다.

### 3. 공격의 종류
**Classic SQL Injection**: 에러 메시지를 통해 데이터베이스 구조를 파악합니다. **Blind SQL Injection**: 참/거짓 응답을 통해 정보를 추출합니다. **Time-based Injection**: 쿼리 실행 시간 차이를 이용합니다. **Union-based Injection**: UNION 연산자를 통해 다른 테이블의 데이터를 조회합니다.

### 4. 파라미터 바인딩 (Prepared Statement)
SQL 쿼리의 구조와 데이터를 분리하여, 데이터베이스가 입력값을 문자열이 아닌 데이터로 처리하도록 하는 방어 기법입니다.

### 5. 입력 검증 및 필터링
화이트리스트를 통해 허용된 입력만 받거나, 특수 문자를 제거/변환하여 SQL 구문이 되지 않도록 합니다.

## ⚠️ 해결하는 문제

### 문제 1: 전체 데이터베이스 탈취
공격자가 SELECT 쿼리를 조작하여, 사용자가 접근할 수 없는 민감한 데이터(다른 사용자의 정보, 신용카드 번호, 의료 기록 등)를 읽을 수 있습니다.

### 문제 2: 데이터 무결성 훼손
UPDATE나 DELETE 쿼리를 악용하여, 데이터를 임의로 수정하거나 삭제할 수 있습니다. 예를 들어 모든 사용자의 잔액을 0으로 만들거나, 중요한 레코드를 삭제할 수 있습니다.

### 문제 3: 관리자 권한 획득
INSERT 쿼리를 조작하여 새로운 관리자 계정을 생성하거나, UPDATE를 통해 사용자 권한을 관리자로 상향 조정하여, 시스템에 대한 완전한 제어권을 획득할 수 있습니다.

### 문제 4: 데이터베이스 시스템 명령 실행
일부 데이터베이스(MSSQL, MySQL 등)에서는 SQL 확장 기능을 통해 운영체제 명령을 실행할 수 있으므로, 악의적인 파일을 생성하거나 서버 시스템을 장악할 수 있습니다.

## ⚙️ 작동 원리

SQL Injection 공격은 다음과 같은 단계로 진행됩니다:

1. **취약점 발견**: 공격자가 로그인 폼, 검색창, 필터 등 사용자 입력을 받는 부분을 찾습니다.

2. **페이로드 구성**: 공격자가 SQL 문법을 이용한 악의적인 입력값(페이로드)을 구성합니다. 예: `' OR '1'='1`, `UNION SELECT ...` 등

3. **입력값 전송**: 공격자가 악의적인 입력값을 폼이나 URL 파라미터를 통해 애플리케이션에 전송합니다.

4. **쿼리 문자열 생성**: 애플리케이션이 입력값을 검증하지 않고, SQL 쿼리 문자열에 직접 연결합니다.

5. **데이터베이스 실행**: 조작된 SQL 쿼리가 데이터베이스에 전송되어 실행됩니다.

6. **결과 반환**: 비정상적인 쿼리 결과가 애플리케이션을 통해 공격자에게 반환되거나, 데이터가 조작됩니다.

## ✅ 장단점

### 공격 방식 관점

#### 장점 (공격자 입장)
- **강력한 접근성**: 데이터베이스에 직접 접근하므로 모든 데이터 조회 가능
- **우회 능력**: 애플리케이션의 보안 로직을 모두 우회 가능
- **광범위한 피해**: 단일 공격으로 전체 데이터베이스 손상 가능
- **추적 어려움**: 적절한 로깅 없으면 공격 증거 제거 가능

#### 단점 (공격자 입장)
- **고급 기술 필요**: 데이터베이스 문법과 SQL을 깊이 있게 이해해야 함
- **시스템 구조 파악 필요**: 테이블명, 컬럼명 등을 사전에 알아야 효과적
- **블라인드 공격의 시간 소모**: 정보를 한 글자씩 추출하는 데 시간이 오래 걸림

### 방어 관점

#### 장점 (방어)
- **완벽한 방어 가능**: Prepared Statement 사용 시 거의 100% 방어 가능
- **프레임워크 지원**: 대부분의 ORM과 웹 프레임워크가 자동 방어 제공
- **구현 간단**: 방어 기법 적용이 비교적 간단함

#### 단점 (방어)
- **모든 입력점 보호 필요**: 하나의 취약점도 공격 경로가 될 수 있음
- **개발자 교육 필요**: 안전한 쿼리 작성 습관이 중요
- **기존 시스템 리팩토링**: 레거시 코드 수정에 시간과 비용 소모

## 💡 실제 사례

### 사례 1: 로그인 우회
로그인 폼의 사용자명 필드에 `admin' --` 를 입력하면, SQL 쿼리가 `SELECT * FROM users WHERE username = 'admin' -- AND password = '...'` 로 변환되어, 비밀번호 검증이 주석처리되고 관리자 계정으로 로그인됩니다.

### 사례 2: 전체 사용자 정보 탈취
검색 기능에 `1' UNION SELECT username, password, email FROM users --` 를 입력하면, 원래 쿼리와 UNION을 통해 결합되어 모든 사용자의 정보가 조회됩니다.

### 사례 3: 데이터 변조
제품 평점 입력 필드에 `5; UPDATE products SET price = 0 WHERE id = 1; --` 를 입력하면, 쿼리가 여러 개 실행되어 특정 제품의 가격이 0으로 변조됩니다.

### 사례 4: 관리자 계정 생성
회원가입 폼에 `username'); INSERT INTO users (username, password, role) VALUES ('hacker', 'password', 'admin'); --` 를 입력하면, 새로운 관리자 계정이 생성되어 공격자가 시스템을 제어할 수 있게 됩니다.

### 사례 5: 시간 기반 공격
검색창에 `1' AND SLEEP(5) --` 를 입력하여 쿼리 실행 시간이 5초 지연되면, 입력값이 처리되었다는 증거를 얻습니다. 이를 반복하여 `1' AND IF(SUBSTRING(password,1,1)='a', SLEEP(5), 0) --` 형태로 비밀번호를 한 글자씩 추출합니다.

### 사례 6: 데이터베이스 내용 삭제
악의적인 사용자가 `1'; DROP TABLE users; --` 를 입력하면, users 테이블 전체가 삭제되어 시스템이 마비될 수 있습니다.

## 🔗 관련 용어

- **Prepared Statement**: SQL Injection 방어의 표준 기법
- **파라미터 바인딩 (Parameter Binding)**: 쿼리 구조와 데이터 분리
- **ORM (Object-Relational Mapping)**: SQL Injection에 강한 데이터베이스 추상화 계층
- **입력 검증 (Input Validation)**: 사용자 입력을 필터링하는 방어 기법
- **화이트리스트 (Whitelist)**: 허용된 입력만 받아들이는 방식
- **SQL 이스케이핑 (SQL Escaping)**: 특수 문자를 변환하는 방어 기법 (권장하지 않음)
- **WAF (Web Application Firewall)**: SQL Injection을 탐지하고 차단하는 방화벽
- **데이터베이스 권한 관리**: 최소 권한 원칙으로 계정 접근 제한
