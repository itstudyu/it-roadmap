# Phishing (피싱)

## 📝 정의

피싱은 **믿을 만한 곳인 척해 비밀을 직접 받아내는 속임수**다.

NIST 용어집은 이것을 "정당한 사업체나 평판 있는 사람으로 위장해 은행 계좌 번호 같은 민감한 정보를 얻어내려는 기법" 으로 적는다. MITRE ATT&CK 은 한 단계 더 넓게 잡아 "전자적으로 배달되는 사회공학" 전부를 이 이름 아래 묶는다. 아무나 노리고 뿌리는 대량 살포와 특정 인물·회사를 겨눈 스피어피싱이 같은 항목에 들어간다.

### 이름
= 낚시(fishing)를 떠올리면 된다. 미끼를 뿌려 두고 무는 사람만 건져 올린다

### 비유
옆집 사람 옷을 입고 문을 두드려, 주인에게 열쇠를 직접 받아 가는 일.

### 예
택배가 반송됐다는 문자에 적힌 주소를 눌렀더니 낯익은 로그인 화면이 뜨던 그 순간이다.

### 직접
메일이나 문자의 링크를 누르지 말고 길게 눌러 실제 주소를 먼저 보라. 글자로 적힌 이름과 실제로 가는 곳이 다를 수 있다.

## 🖼️ 그림으로 보기

```도해
대조: 피싱은 다른 공격과 무엇이 다른가
뚫는 공격 |=| 피싱
노리는 곳 :: 기계의 허점 || 사람의 믿음
다가서는 법 :: 몰래 넘어간다 || 아는 곳인 척한다
비밀을 쥐는 법 :: 훔쳐 낸다 || 본인이 적어 준다
= 믿게 만들어 비밀을 받아 내는 공격이라, 고쳐 메울 허점이 애초에 없다
```

## ⚠️ 해결하는 문제

이 항목은 해결하는 문제가 아니라 **막아야 할 문제**다.

```도해
대조: 조심하라는 교육만으로는 왜 안 막히나
사람이 알아채기 || 주의력에 안 기대기
가짜 화면 :: 진짜와 똑같다 || 주소가 다르면 멈춘다
한 번의 실수 :: 그걸로 끝난다 || 실수해도 안 넘어간다
피곤한 날 :: 판단이 흐려진다 || 판단할 일이 없다
= 사람의 주의력을 마지막 방어선으로 두면 언젠가 한 번은 뚫린다
```

피싱에는 고쳐 막을 취약점이 없다. [[SQL Injection]] 처럼 코드 한 줄을 바로잡으면 사라지는 종류가 아니라, 사람이 판단하는 자리를 노리기 때문이다. 그래서 대응이 오래도록 "조심하라" 는 교육에 머물렀다.

NIST 는 이 문제를 인증 방식의 성질로 옮겨 놓았다. **피싱 저항**(phishing resistance)을 "사칭한 검증자에게 인증 비밀과 유효한 인증자 출력이 넘어가지 않게 하는 능력" 으로 정의하면서, 그 뒤에 단서를 하나 붙인다 — **주장자의 주의력에 기대지 않고**. 교육이 필요 없다는 말이 아니라, 교육을 마지막 방어선으로 삼지 말라는 말이다.

## ⚙️ 작동 원리

```도해
흐름: 피싱 한 통은 어떤 순서로 사람을 움직이나
공격자 :: 아는 곳의 이름과 화면을 그대로 베낀다
배달 :: 메일·문자·전화·메신저로 보낸다
급한 이유 :: "계정이 잠깁니다" 로 생각할 틈을 줄인다
가짜 화면 :: 진짜와 같은 화면에서 비밀번호를 받는다
< 공격자 :: 받아 낸 비밀번호로 진짜 화면에 로그인한다
= 어느 칸에도 뚫린 자리가 없다. 사람이 스스로 한 일만 이어져 있다
```

MITRE ATT&CK 은 배달 방식으로 갈래를 나눈다. 첨부 파일을 여는 것, 링크를 누르는 것, 소셜 미디어 같은 제3자 서비스를 거치는 것, 그리고 음성 통화로 악성 주소를 안내하는 것 넷이다. 전화도 같은 기법의 한 갈래로 번호가 붙어 있다.

속이는 방식도 목록에 있다. 보낸 사람 주소를 진짜처럼 위조하는 것, 이미 오가던 메일 대화의 중간에 끼어드는 것(thread hijacking)이 여기 들어간다. ATT&CK 이 이 항목에 적어 둔 노림수는 대개 피해자의 기기에서 악성 코드가 도는 쪽이다. 악성 파일을 내려받게 하거나, 원격 관리 도구를 깔게 하거나, 악성 사이트를 열게 만든다.

## 💡 실제 사례

- **결재 요청으로 온 첨부 파일** — 익숙한 양식의 문서를 열게 만들고, 그 문서가 악성 코드를 실행한다. MITRE 의 첫 번째 갈래다.
- **오가던 대화에 끼어든 답장** — 새 메일이 아니라 이미 진행 중이던 메일 줄기에 답장이 하나 붙는다. 앞의 대화가 진짜라서 의심이 잘 안 든다.
- **전화로 안내하는 주소** — 통화로 상황을 설명하며 특정 주소를 불러 준다. 메일 필터를 거치지 않으므로 걸러낼 지점 자체가 없다.

## 🚫 흔한 오해

- **맞춤법이 어색한 메일만 걸러내면 된다** — 표적형은 그렇게 오지 않는다. MITRE 는 보낸 사람 위조와 진행 중인 대화에 끼어드는 수법까지 같은 기법으로 적는다.
- **메일만 조심하면 된다** — 문자·전화·메신저도 같은 항목 안에 있다. 음성 통화를 쓰는 갈래에는 따로 번호까지 붙어 있다.
- **다단계 인증을 켰으니 피싱은 못 뚫는다** — 인증 방식마다 피싱에 견디는 정도가 다르다. NIST 가 피싱 저항을 따로 정의해 둔 이유가 그것이다.

## 📝 정리

**"열쇠를 훔치는 게 아니라 달라고 하는 그 수법"** 이라고 읽으면 된다. 노리는 것은 기계의 허점이 아니라 사람의 믿음이라, 고쳐서 메울 자리가 없다. 그래서 판단의 기준을 사람의 주의력에서 인증 방식 자체로 옮기는 것이 지금의 방향이다.

## 🧒 열 살에게

우리 집 열쇠를 훔치기는 어렵지? 그래서 어떤 사람은 아빠 친구인 척 옷을 차려입고 찾아와서 "아빠가 열쇠 좀 가져오래" 하고 네 손으로 건네게 만들어. 문은 멀쩡한데 열린 거야.

## ❓ 이해했는지

- 메일을 걸러내는 장치를 아무리 잘 고쳐도 이 공격이 안 사라지는 이유는 무엇인가 → 해결하는 문제
- 진짜 같은 화면에 비밀번호를 적은 다음 공격자는 곧바로 무엇을 하나 → 작동 원리
- 표적형이 어색한 문장으로 오지 않는다는 말은 무슨 뜻인가 → 흔한 오해
