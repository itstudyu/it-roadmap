# Bastion Host (배스천 호스트)

## 📝 정의

Bastion Host는 **내부 서버로 들어가는 유일한 진입점 서버**다.

내부 서버에는 외부에서 닿을 주소를 주지 않고, 바깥에서 오는 접속은 이 서버 한 대만 받는다. 여기를 거쳐야만 안쪽으로 넘어갈 수 있어서 점프 서버(Jump Server)라고도 부른다.

### 비유
건물 정문의 경비초소. 어느 사무실을 가든 여기서 신분을 확인하고 기록을 남긴 다음에 들어간다.

### 예
서버 주소를 받아 바로 붙으려 하면 연결이 안 되고, 먼저 거쳐야 할 서버 주소를 따로 받는다. 그 한 대가 배스천이다.

## 🖼️ 그림으로 보기

```도해
흐름: 사설망 안의 DB 서버에 어떻게 들어가나
개발자 :: 공개키로 배스천에 SSH 접속한다
배스천 :: 신원을 확인하고 접속을 기록한다
개발자 :: 배스천을 거쳐 DB 서버로 넘어간다
DB 서버 :: 배스천에서 온 접속만 받도록 열려 있다
배스천 :: 세션이 끝날 때까지 기록을 남긴다
= 문이 하나뿐이라 누가 언제 어디에 들어갔는지 한 곳에서 보인다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버마다 SSH 를 열어두면 어떻게 되나
배스천 없이 || 배스천으로
외부 노출 :: 서버마다 열림 || 한 대만 열림
접속 기록 :: 서버마다 흩어짐 || 한 곳에 모임
퇴사자 차단 :: 전부 찾아 지움 || 계정 하나 막음
= 들어오는 문을 하나로 줄이면 지킬 곳도 볼 곳도 하나가 된다
```

DB 서버와 애플리케이션 서버를 각각 인터넷에서 접속할 수 있게 열어두면, 지켜야 할 문이 서버 수만큼 늘어난다. 문 하나에만 설정 실수가 있어도 그리로 들어온다.

배스천을 두면 내부 서버는 사설 주소만 갖고, 접속은 배스천에서 오는 것만 받는다. 사람이 바뀌거나 나갈 때도 배스천의 계정 하나만 정리하면 안쪽 전체에 대한 접근이 함께 끊긴다.

## ⚙️ 작동 원리

배스천은 인터넷에서 보이는 서버라 자동화된 접속 시도를 계속 받는다. 그래서 필요한 것만 남기고 나머지는 꺼둔다. 루트 로그인과 비밀번호 인증을 막고 공개키만 받는 것이 기본이고, 여기에 추가 인증을 더 걸기도 한다.

내부 서버로 넘어갈 때는 배스천에 키를 올려두지 않는다. 키를 올리는 순간 그 서버 하나에 모든 사람의 키가 모이기 때문이다. 대신 SSH의 ProxyJump나 에이전트 포워딩으로, 키는 각자 PC에 둔 채 배스천을 통로로만 쓴다.

```
# ~/.ssh/config
Host bastion
  HostName 54.123.45.67
  User ec2-user

Host internal-db
  HostName 10.0.1.50
  User ubuntu
  ProxyJump bastion
```

이렇게 적어두면 `ssh internal-db` 한 줄로 끝난다. 경유는 하지만 사람이 두 번 로그인하지는 않는다.

## 💡 실제 사례

- **사설 서브넷 접근** — 외부 주소가 없는 서버에 들어갈 때, 공개 구역에 배스천 한 대를 두고 그 뒤로 넘어간다.
- **감사 대응** — 규제를 받는 곳에서는 배스천에서 실행한 명령을 전부 기록해두고, 누가 언제 무엇을 했는지 그대로 제출한다.
- **관리형 서비스로 대체** — SSH 포트를 아예 열지 않고 권한 체계와 에이전트로 접속하게 만드는 방식으로 배스천을 대신하기도 한다.

## 🚫 흔한 오해

- **배스천을 두면 내부 서버가 안전해진다** — 안전해진 게 아니라 문이 하나로 줄어든 것이다. 그 한 대가 뚫리면 뒤가 전부 열리므로 가장 세게 잠가야 할 서버가 된다.
- **배스천에 키를 올려두고 쓰면 편하다** — 편한 대신 모두의 키가 한 서버에 모인다. 키는 각자 PC에 두고 통로로만 지나가게 한다.
- **거쳐 가니까 로그인을 두 번 해야 한다** — 설정 파일에 ProxyJump를 적어두면 명령 한 줄로 끝난다. 경유하는 것과 사람이 두 번 치는 것은 다르다.

## 🚨 주의사항

- **배스천이 멈추면 아무도 못 들어간다.** 길이 하나라는 말은 그 길이 끊기면 길이 없다는 뜻이라, 여분을 어떻게 둘지 미리 정해야 한다.
- **접속 기록을 쌓아만 두면 소용이 없다.** 이상한 시간대의 접속이나 대량 전송처럼 볼 조건을 정해둬야 기록이 일을 한다.

## 📝 정리

Bastion Host는 외부에서 내부 서버로 들어가는 길을 한 곳으로 모아둔 서버다. 접근 통제와 기록을 한 대에서 하게 되지만, 그만큼 그 한 대가 가장 위험한 자리가 된다. 키는 올려두지 않고 통로로만 쓰는 것이 기본이다.

## ❓ 이해했는지

- 배스천을 뒀는데도 내부 서버 전체가 위험해지는 경우는 언제인가 → 흔한 오해
- 퇴사자의 서버 접근을 끊을 때 배스천이 있으면 무엇이 달라지나 → 해결하는 문제
- 배스천에 개인 키를 올려두면 안 되는 이유는 → 작동 원리
