# Bastion Host (배스천 호스트)

## 📝 정의

Bastion Host(배스천 호스트)는 인터넷 같은 외부 네트워크에서 내부 서버에 접근하기 위한 **유일한 공식 진입점 역할을 하는 강화된 서버**입니다. 내부 서버들은 외부에서 직접 SSH나 RDP로 접근할 수 없고, 반드시 Bastion Host를 통해서만 접근해야 합니다. 보안 취약점을 최소화하기 위해 불필요한 소프트웨어를 제거하고, 강화된 보안 설정을 적용한 서버입니다.

"Jump Server" 또는 "Jump Box"라고도 불리며, 성(castle)의 방어 요충지인 "bastion(성벽 돌출부)"에서 이름이 유래했습니다. 모든 외부 접근을 단일 경로로 집중시킴으로써, 보안 감사(audit)와 접근 제어가 훨씬 용이해집니다. AWS, GCP, Azure 같은 클라우드 환경에서는 Private Subnet의 서버에 접근하기 위해 필수적으로 사용하는 패턴입니다.

> **한 줄 요약**: "내부 서버로 들어가는 단 하나의 공식 관문 — 모든 접근은 여기를 반드시 거친다"

**비유**:
- **사령부 출입 비유**: 군사 기지 내 건물들로 들어가려면 반드시 정문의 경비초소(Bastion Host)를 통과해야 합니다. 경비초소에서 신분 확인 후 해당 건물의 출입증을 받습니다.
- **호텔 프론트 비유**: 모든 투숙객은 프론트(Bastion Host)에서 체크인한 후 객실 카드 키를 받습니다. 직접 객실에 들어갈 수 없고, 프론트를 통해서만 접근 가능합니다.

## 🎯 핵심 개념

### 1. 단일 진입점 (Single Entry Point)
외부에서 내부 서버로 접근하는 모든 경로를 Bastion Host 하나로 집중시킵니다. 개발자, 운영자, 관리자 모두 반드시 Bastion Host를 통해 내부 서버에 접근합니다. 이를 통해 "누가, 언제, 어떤 서버에 접근했는가"를 한 곳에서 완전히 감시할 수 있습니다.

### 2. 하드닝 (Hardening, 강화)
Bastion Host는 불필요한 서비스와 포트를 모두 제거하고, 꼭 필요한 기능(SSH)만 활성화합니다. 보안 패치를 최우선으로 유지하며, 기본 설정보다 훨씬 강화된 SSH 설정을 적용합니다. 루트 로그인 비활성화, 비밀번호 인증 비활성화(공개키만 허용), 2FA 적용 등이 표준입니다.

### 3. SSH 터널링과 프록시 점프
Bastion Host를 통해 내부 서버에 접근하는 방법:
- **SSH ProxyJump**: `ssh -J bastion@bastion-ip user@internal-ip`
- **SSH 포트 포워딩**: 로컬 포트를 내부 서버로 포워딩
- **에이전트 포워딩**: Bastion Host에 개인 키 없이 내부 서버까지 키 전달

### 4. 감사 로그 (Audit Log)
모든 Bastion Host 접근과 내부에서 수행한 명령어를 로깅합니다. "언제 누가 어떤 서버에 접근해서 무슨 명령을 실행했는가"를 기록하여, 보안 사고 발생 시 추적이 가능합니다.

## ⚠️ 해결하는 문제

### 문제 1: 내부 서버의 직접 인터넷 노출
DB 서버, 애플리케이션 서버 등을 인터넷에 직접 노출하면 공격 표면이 매우 커집니다. Bastion Host를 통해 이 서버들을 완전히 사설 네트워크에 격리하고, 오직 Bastion Host만 외부에서 접근 가능하게 합니다.

### 문제 2: 분산된 접근 경로로 인한 감사 불가
각 서버마다 별도로 외부 접근을 허용하면, "누가 어느 서버에 접속했는지"를 일일이 추적하기 어렵습니다. Bastion Host 하나를 통해서만 접근하므로, 이 서버의 로그만 모니터링하면 전체 접근 현황을 파악할 수 있습니다.

### 문제 3: 퇴사자나 권한 변경 시 보안 관리
직원이 퇴사하거나 권한이 변경될 때, 여러 서버에 개별적으로 설정된 계정을 모두 찾아 변경하기 어렵습니다. Bastion Host 하나에서 접근을 차단하면, 해당 직원은 어떤 내부 서버에도 접근할 수 없게 됩니다.

```도해
Bastion Host :: 접속 허용

Bastion Host :: 내부 SSH 연결 중계

Bastion Host :: DB 서버 터미널 제공
개발자 (외부) :: 관리 작업 수행
DB 서버 (내부) :: 응답
```

## ⚙️ 작동 원리

### 1단계: Bastion Host 접속
개발자가 인터넷에서 Bastion Host의 공인 IP로 SSH 접속합니다. 반드시 공개키(SSH Key) 인증만 허용하고, 비밀번호 로그인은 비활성화합니다. 필요에 따라 MFA(Google Authenticator 등)를 추가로 적용합니다.

### 2단계: 신원 확인 및 로깅 시작
Bastion Host는 접속한 사용자의 신원을 확인하고, 접속 시간, IP, 사용자를 로그에 기록합니다. 관리형 Bastion 서비스(AWS Systems Manager Session Manager 등)에서는 세션 전체가 녹화됩니다.

### 3단계: 내부 서버로 점프
Bastion Host에서 내부 서버로 SSH를 통해 접근합니다. ProxyJump 기능을 사용하면 로컬 PC에서 마치 직접 연결하는 것처럼 내부 서버에 접속할 수 있습니다. Bastion Host 자체에는 개인 키를 저장하지 않도록 에이전트 포워딩을 활용합니다.

### 4단계: 작업 수행 및 세션 종료
내부 서버에서 필요한 작업을 완료한 후 세션을 종료합니다. 모든 명령어와 세션 시간이 감사 로그에 기록됩니다. 이상 행동(대용량 데이터 전송, 비정상 시간 접속 등)은 알람을 발생시킬 수 있습니다.

## ✅ 장단점

**장점**:
- 내부 서버를 인터넷에서 완전히 숨기고, 하나의 서버만 관리하면 되므로 공격 표면이 최소화됨
- 모든 접근 로그가 한 서버에 집중되어 감사와 모니터링이 용이함
- 인원 변경(신규 입사, 퇴사) 시 Bastion Host 계정만 관리하면 되어 관리 부담 감소
- 클라우드 환경(Private Subnet)에서 외부 접근을 위한 사실상 표준 패턴
- 네트워크 방화벽 규칙이 단순해짐 (Bastion Host → 내부 서버만 허용)

**단점**:
- Bastion Host 자체가 단일 장애점(SPOF)이 될 수 있음 (HA 구성 필요)
- Bastion Host가 해킹당하면 내부 서버 전체가 위험에 노출될 수 있음
- 접속 단계가 늘어나 개발자 입장에서 불편함 (ProxyJump 설정으로 완화 가능)
- 서버 비용 발생 (클라우드에서는 AWS SSM 등으로 대체 추세)

## 💡 실제 사례

### 1. AWS Private Subnet 서버 접근
AWS에서 Private Subnet에 배치된 EC2 서버에 접근하려면, Public Subnet에 Bastion Host(EC2 인스턴스)를 배치합니다. 개발자는 먼저 Bastion Host에 SSH 접속한 후, 내부 서버에 SSH 점프합니다. SSH config 파일에 ProxyJump를 설정하면 마치 직접 접속하는 것처럼 편리하게 사용할 수 있습니다.

```
# ~/.ssh/config
Host bastion
  HostName 54.123.45.67  # Bastion 공인 IP
  User ec2-user
  IdentityFile ~/.ssh/my-key.pem

Host internal-db
  HostName 10.0.1.50     # DB 서버 사설 IP
  User ubuntu
  ProxyJump bastion
  IdentityFile ~/.ssh/my-key.pem
```

### 2. AWS Systems Manager Session Manager (현대적 대안)
최신 AWS 환경에서는 Bastion Host 대신 SSM Session Manager를 사용합니다. EC2 서버에 SSM 에이전트를 설치하면, SSH 포트 없이 IAM 권한만으로 서버에 접속할 수 있습니다. SSH 키 관리 부담이 없고, 세션이 자동으로 CloudTrail에 기록됩니다.

### 3. 금융권 서버 접근 관리
은행이나 증권사에서는 Bastion Host(Jump Server)를 통한 서버 접근을 의무화하고, Bastion Host에서 수행한 모든 명령어를 녹화합니다. 내부 감사나 금감원 감사 시 "누가 언제 어떤 서버에서 무엇을 했는지"를 정확히 제출할 수 있습니다.

## 🔗 관련 용어

- **DMZ (Demilitarized Zone)**: 내부망과 외부망 사이의 격리된 중간 네트워크 영역
- **SSH (Secure Shell)**: 암호화된 원격 서버 접속 프로토콜
- **Jump Server**: Bastion Host의 다른 이름. 내부 서버로 "점프"하는 중간 서버
- **SSH ProxyJump**: Bastion Host를 경유하여 내부 서버에 직접 접속하는 SSH 기능
- **Private Subnet**: 인터넷에서 직접 접근 불가능한 사설 서브넷 (Bastion Host 사용 대상)
- **Audit Log**: 누가 언제 무엇을 했는지 기록하는 보안 감사 로그
- **MFA (Multi-Factor Authentication)**: 이중 인증. Bastion Host 보안 강화에 권장
- **Zero Trust**: 내부망도 신뢰하지 않고 매번 검증하는 보안 패러다임. Bastion Host의 대안이 되기도 함
