# DDoS Mitigation (떼로 몰려오는 공격 막기)

## 📝 정의

DDoS Mitigation은 **몰려온 가짜 물량을 걸러 내 진짜 손님을 계속 받는 일**이다.

AWS 문서는 DDoS 공격을 "여러 대의 장악된 기계가 한 대상에 물량을 쏟아붓는 공격" 으로 적고, 그 결과를 "정상 사용자가 그 서비스를 쓰지 못하게 되고, 물량에 짓눌려 대상이 죽을 수도 있다" 로 적는다. 훔쳐 가는 공격이 아니라 **못 쓰게 만드는 공격**이라, 막는 쪽의 목표도 "공격을 이기는 것" 이 아니라 "정상 사용자가 계속 들어오게 두는 것" 이 된다.

### 이름
Distributed :: 여러 곳에서
Denial :: 못 하게 막음
Service :: 쓰는 일
Mitigation :: 누그러뜨리기
= 붙여 읽으면 "여러 곳에서 못 쓰게 막는 짓을 누그러뜨리기". 없애는 게 아니라 견디게 만드는 쪽이다

### 비유
놀이공원 인기 놀이기구 줄. 탈 생각도 없는 사람들이 몰려와 줄을 채우면 진짜 타려는 사람이 못 타니, 입구를 여러 군데로 늘리고 표를 미리 검사해 돌려보낸다.

### 예
예매가 열리는 순간 사이트가 통째로 안 열리고 "잠시 후 다시 시도해 주세요" 만 돌던 그 화면이다.

## 🖼️ 그림으로 보기

```도해
층: 몰려오는 물량은 어디서 걸러지나
가장자리 :: 세계 곳곳의 접점이 물량을 나눠 받는다
망 계층 :: SYN 홍수처럼 3·4계층을 노린 것을 여기서 끊는다
앱 계층 :: 정상 요청처럼 생긴 7계층 홍수를 규칙으로 거른다
원본 :: 여기까지 닿는 것은 걸러지고 남은 몫뿐이다
= 한 자리에서 다 막는 게 아니라 바깥부터 겹겹이 깎는다. 안쪽에 닿는 양을 줄이는 것이 전부다
```

## ⚠️ 해결하는 문제

```도해
대조: 미리 준비해 두지 않으면 몰려올 때 무엇이 달라지나
준비 없이 || 걸러 내면
받는 자리 :: 한 곳에서 터진다 || 곳곳이 나눠 받는다
가짜 골라내기 :: 사람이 뒤진다 || 자동으로 걸러진다
진짜 손님 :: 같이 못 들어온다 || 그대로 들어온다
= 공격을 이겨서 없애는 게 아니다. 진짜 손님이 계속 들어오게 두면 그걸로 이긴 것이다
```

들어오는 양은 내가 정하지 못한다. 준비가 없으면 물량은 전부 한 자리로 몰리고, 그 자리의 용량이 곧 서비스의 수명이 된다. 사람이 로그를 뒤져 가짜를 골라내는 사이 진짜 손님도 함께 못 들어오고, 급하게 서버를 늘리면 요금만 따라 오른다.

막는 쪽은 이 일을 **바깥으로 밀어낸다.** AWS 문서는 세계 곳곳에 흩어진 가장자리 접점이 물량을 여러 곳으로 흩어 공격을 근원 가까이에서 깎는다고 적고, SYN 홍수는 앞에 선 대리자가 연결을 먼저 받아 확인한 뒤에야 안으로 넘긴다고 적는다. Azure 문서는 평소 패턴을 학습해 기준값을 스스로 잡고, 그 기준을 넘긴 주소에 대해서만 걸러 내기가 걸린다고 적는다.

## 📊 비교: 세 곳은 이 일을 뭐라 부르나

| 무엇 | AWS | Azure | Google Cloud |
|---|---|---|---|
| **3·4계층 막기** | Shield Standard 가 기본으로 붙는다 | DDoS Protection (Network / IP) | Cloud Armor 가 상시로 붙는다 |
| **7계층 막기** | AWS WAF 를 함께 쓴다 | WAF 를 따로 붙여야 한다 | Cloud Armor 보안 정책 |
| **스스로 기준 잡기** | Shield Advanced 가 지난 30일 치 평소 흐름을 기준선으로 삼는다 | 적응형 실시간 조정 | Adaptive Protection |
| **먼저 지켜보기** | 기준선을 쌓는 동안 사고 기록과 지표를 남긴다 | 5분 단위 보고서와 알림 | 규칙을 막지 않고 기록만 남기는 미리보기 |

이름은 셋 다 다르지만 나누는 자리는 같다 — **망 계층과 앱 계층은 다른 물건이 막는다.** Azure 문서는 자기 서비스가 3·4계층까지이고 7계층은 WAF 를 얹으라고 못 박는다.

## 💡 실제 사례

- **예매가 열리는 날** — 물량이 몰릴 시각이 정해져 있으니, 가장자리 접점을 앞에 세워 원본이 있는 지역까지 오는 몫부터 줄여 둔다.
- **로그인 화면만 계속 두드릴 때** — 한 주소에서 오는 요청을 초당 몇 건으로 묶어, 정상처럼 생긴 7계층 홍수를 깎는다.
- **공격이 끝난 뒤 청구서** — 공격 때문에 자동으로 늘어난 비용은 따로 신청해 일부를 되돌려 받는 길이 있다.

## 🚫 흔한 오해

- **DDoS 는 뚫고 들어와 훔쳐 가는 공격이다** — 대개 아무것도 훔치지 않는다. 정상으로 보이는 양을 쏟아부어 남이 못 쓰게 만드는 것이 목적이다.
- **막아 주는 기능을 켜면 7계층까지 다 막힌다** — Azure 문서는 자기 몫이 3·4계층까지라고 적고 7계층은 WAF 를 얹으라고 한다. 켜 놓고 안심하다가 웹 요청 홍수에 그대로 당한다.
- **서버를 넉넉히 키워 두면 해결된다** — 키운 만큼 요금이 오르고, 7계층 홍수는 정상 요청 모양이라 늘린 만큼 같이 늘어난다.

## 📝 정리

**"공격을 이기는 게 아니라 진짜 손님을 계속 받는 일"** 이라고 읽으면 된다. 걸러 내기는 바깥부터 겹겹이 서고, 망 계층과 앱 계층은 서로 다른 물건이 맡는다. 켜 놓았다는 사실보다 어느 계층까지 켜 놓았는지가 갈림길이다.

## 🧒 열 살에게

놀이공원에서 제일 인기 있는 놀이기구 줄에, 탈 생각도 없는 사람들이 백 명씩 끼어들면 진짜 타려는 너는 영영 못 타겠지? 그래서 입구를 여러 군데로 늘려 두고, 탈 사람인지 표를 미리 검사해서 아닌 사람은 줄 밖에서 돌려보내는 거야.

## ❓ 이해했는지

- 아무것도 훔쳐 가지 않았는데 왜 보안 사고로 치나 → 흔한 오해
- 망을 노린 물량과 웹 요청 홍수는 각각 어디서 걸러지나 → 그림
- 막아 주는 기능을 켰는데도 웹 앱이 계속 멈춘다면 무엇이 빠진 것인가 → 비교
