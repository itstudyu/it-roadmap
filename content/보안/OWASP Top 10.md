# OWASP Top 10 (Open Worldwide Application Security Project Top 10)

## 📝 정의

OWASP Top 10 은 **웹 앱에서 가장 흔한 보안 결함 열 부류**다.

몇 년에 한 번씩 다시 나오고 2025년판이 여덟 번째다. 2021년판과 견주면 두 자리가 새로 생겼다 — 3위의 Software Supply Chain Failures(공급망 실패)와 10위의 Mishandling of Exceptional Conditions(예외 상황 처리 실패)다.

### 이름
Open :: 누구나 볼 수 있는
Worldwide :: 온 세계가 함께
Application Security :: 앱을 지키는 일
Project :: 그 일을 하는 단체
Top 10 :: 자주 나오는 열 부류
= 붙여 읽으면 "앱 보안 단체가 추린 열 부류". 취약점 열 개가 아니라 부류 열 개다

### 비유
해마다 사고가 잦은 자리를 다시 세어 붙이는 학교의 안전 안내문.

### 예
보안 점검 결과지나 개발자 채용 공고에 이름이 그대로 적혀 오는 그 목록이다.

### 직접
`owasp.org/Top10` 을 열어 보라. A01 부터 A10 까지 번호가 붙어 있고, 항목마다 "이러면 걸린다" 는 조건이 적혀 있다.

## 🖼️ 그림으로 보기

```도해
층: 2025년판이 꼽은 위험은 무엇이 위인가
1위 접근 통제 :: 남의 것을 볼 수 있게 열려 있다
2위 설정 실수 :: 켤 것을 끄고 끌 것을 켰다
3위 공급망 :: 가져다 쓴 것이 이미 망가져 있다
4위 암호 실패 :: 가려야 할 것이 그냥 보인다
5위 주입 :: 넣은 글자가 명령으로 실행된다
= 열 부류 중 위의 다섯이다. 결함 하나하나가 아니라 결함의 부류를 세워 둔 목록이다
```

## ⚠️ 해결하는 문제

```도해
대조: 이런 목록이 없으면 보안 점검은 어떻게 되나
목록 없이 || 열 부류로
무엇을 볼지 :: 사람마다 다르다 || 같은 열 개를 본다
결과 말하기 :: 이름이 제각각 || 번호로 통한다
빠뜨림 :: 조용히 넘어간다 || 빈칸이 드러난다
= 열 부류는 정답이 아니라 모두가 같은 자리를 보게 하는 눈금이다
```

보안 결함은 부르는 이름이 조직마다 다르다. 같은 문제를 누구는 "권한 문제", 누구는 "설정 실수" 라고 적으면 두 보고서를 나란히 놓아도 어디가 비었는지 안 보인다.

Top 10 은 번호를 준다. A01 부터 A10 까지 자리를 정해 두면 점검 결과가 그 자리에 떨어지고, 아무것도 안 떨어진 칸이 곧 "여기는 아직 안 봤다" 가 된다. 이 목록이 하는 일의 절반은 순위가 아니라 **공통 좌표**다.

## ⚙️ 작동 원리

```도해
흐름: 열 부류는 어떻게 정해지나
데이터 모으기 :: 검사한 앱 280만 개의 결과를 받는다
약점 묶기 :: 약점 유형 589개를 부류로 나눠 담는다
발생률 :: 부류마다 몇 %의 앱에서 나왔나 센다
점수 얹기 :: CVE 에 매겨진 공격·피해 점수를 평균낸다
현장 설문 :: 데이터에 안 잡히는 위험을 투표로 받는다
= 열 자리 중 여덟은 데이터가, 나머지 둘은 현장 설문이 채운다
```

여기서 말하는 약점 유형은 CWE(약점 유형마다 번호를 붙인 목록)다. Top 10 의 한 항목은 CWE 하나가 아니라 여러 개를 묶은 부류이고, 2025년판은 열 부류 안에 CWE 248개를 담았다. 부류당 평균 25개이고, 가장 적은 부류가 5개, 가장 많은 1위 접근 통제가 40개다.

점수는 [[CVE]] 쪽에서 온다. NVD(미국 정부가 운영하는 취약점 저장소)에서 CWE 에 연결된 CVE 기록 약 17만 5천 건을 긁어 공격 난이도와 피해 크기를 평균냈다. 2021년판은 12만 5천 건, CWE 241개였으니 세는 범위가 눈에 띄게 넓어졌다.

여덟 자리만 데이터로 정하는 이유를 OWASP 는 직접 적어 두었다. 데이터는 "검사 도구가 이미 잡을 수 있는 것" 만 보여 주고, 새 위험이 도구에 들어가기까지는 몇 년이 걸린다. 그 빈틈을 현장 설문 두 자리가 메운다.

## 📊 비교: 2021년판과 2025년판

| 자리 | 2025년판 | 2021년판에서 |
|---|---|---|
| **A01** | Broken Access Control | 그대로 1위 |
| **A02** | Security Misconfiguration | 5위에서 올라옴 |
| **A03** | Software Supply Chain Failures | 취약 구성요소(A06)가 넓어진 것 |
| **A04** | Cryptographic Failures | 2위에서 내려옴 |
| **A05** | Injection | 3위에서 내려옴 |
| **A06** | Insecure Design | 4위에서 내려옴 |
| **A07** | Authentication Failures | 이름이 짧아짐 |
| **A08** | Software or Data Integrity Failures | 그대로 8위 |
| **A09** | Security Logging & Alerting Failures | Monitoring 이 Alerting 으로 |
| **A10** | Mishandling of Exceptional Conditions | 새로 들어옴 |

## 💡 실제 사례

- **점검 결과 읽기** — 결과지가 A01 · A03 같은 번호로 오면 어느 부류가 비었는지 표에서 바로 보인다.
- **점검 범위 넓히기** — 2025년판에서 3위로 올라온 공급망 부류는 빌드 서버와 개발자 노트북까지 점검 대상에 넣으라는 뜻이다.
- **교육 범위 정하기** — 부류 하나에 약점 유형이 평균 25개라, 쓰는 언어에 해당하는 것만 골라 가르칠 수 있다.

## 🚫 흔한 오해

- **Top 10 만 막으면 보안은 끝난다** — 자주 나오는 것을 추린 목록이지 전부가 아니다. MITRE 가 배포하는 약점 유형은 968개인데 열 부류에 담긴 것은 248개다.
- **열 개가 취약점 열 개다** — 부류 열 개다. 1위 접근 통제 한 칸 안에만 약점 유형이 40개 들어 있다.
- **순위가 곧 위험한 순서다** — 위쪽은 "많이 발견된" 쪽에 가깝다. 3위 공급망은 연결된 CVE 가 11건뿐인데도 현장 설문에서 응답자의 정확히 절반이 1위로 꼽아 올라왔다.

## 📝 정리

**"자주 걸리는 자리를 열 부류로 세워 둔 눈금"** 이라고 읽으면 된다. 열 자리 중 여덟은 검사 데이터가, 둘은 현장 설문이 채우므로 순위는 "가장 위험한 순서" 라기보다 데이터와 현장 감각을 섞은 결과다. 2025년판에서 새로 볼 자리는 3위 공급망과 10위 예외 상황 처리다.

## 🧒 열 살에게

학교에서 다친 아이들 기록을 다 모아 보면, 계단이랑 급식실 앞처럼 유난히 자주 다치는 자리 열 군데가 나오지? 그 열 군데를 크게 적어서 벽에 붙여 두는 거야. 그러면 다들 어디부터 조심할지 같은 데를 보게 돼.

## ❓ 이해했는지

- 공급망 부류는 연결된 CVE 가 11건뿐인데 어떻게 3위에 올랐나 → 작동 원리
- 열 부류를 다 막았는데도 남는 위험이 있는 이유는 무엇인가 → 흔한 오해
- 2021년판을 외운 사람이 2025년판에서 새로 봐야 할 자리는 어디인가 → 비교
