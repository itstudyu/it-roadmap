# Post-Quantum Cryptography (양자내성암호)

## 📝 정의

양자내성암호는 **양자컴퓨터로도 못 푸는 공개키 암호**다.

이름의 "post-quantum" 은 양자컴퓨터로 돌린다는 뜻이 아니라 그것이 나온 뒤에도 버틴다는 뜻이다. 표준으로 뽑힌 것은 키를 나눠 갖는 ML-KEM(옛 이름 Kyber)과 서명하는 ML-DSA · SLH-DSA 다.

### 이름
Post :: ~이 나온 뒤에도
Quantum :: 아주 빠른 새 계산기
Cryptography :: 자물쇠 거는 법
= 붙여 읽으면 "새 계산기가 나온 뒤에도 버티는 자물쇠". 지금 푸는 게 아니라 나중에도 안 풀리게 하는 것이다

### 비유
만능 열쇠가 곧 풀린다는 소문이 돌 때 자물쇠를 미리 바꾸는 일. 열쇠가 실제로 나온 뒤에 바꾸면 그 사이에 열린 문은 되돌릴 수 없다.

### 예
Go 로 만든 서버는 1.24부터 HTTPS 손잡기에 이 방식을 기본으로 섞는다. 설정을 건드린 적이 없어도 그렇다.


### 직접
주소창의 자물쇠를 눌러 연결 정보를 열어 보라. 손잡기에 쓰인 방식 이름이 적혀 있고, 요즘 서버는 거기에 새 방식이 섞여 있다.

## 🖼️ 그림으로 보기

```도해
대조: 양자컴퓨터가 나오면 오늘 쓰는 공개키 암호는 어떻게 되나
지금의 공개키 || 양자내성 암호
안전 근거 :: 양자에 약하다 || 양자에도 견딘다
키 나누기 :: X25519 · ECDH || ML-KEM
서명 :: RSA · ECDSA || ML-DSA
= 하는 일은 그대로고, 그 일을 하는 알고리즘만 갈아끼운다
```

## ⚠️ 해결하는 문제

```도해
대조: 양자컴퓨터가 나온 다음에 바꾸면 왜 늦나
그때 가서 || 지금 미리
오늘의 통신 :: 기록해 두면 열린다 || 그때도 못 연다
준비 :: 급히 다 바꾼다 || 이미 끝나 있다
지나간 일 :: 되돌릴 수 없다 || 겪을 일이 없다
= 암호를 바꾸는 일은 깨지기 전에만 뜻이 있다
```

암호문은 지금 못 풀어도 지금 **받아 적어둘 수는 있다**. 회선을 지나가는 것을 통째로 저장해 두었다가 몇 년 뒤 푸는 일이 가능하기 때문에, 오늘 오간 통신의 수명은 오늘 쓴 알고리즘이 정한다.

그래서 전환의 첫 자리가 키 교환이었다. 서명은 그때 가서 위조를 막으면 되지만, 키 교환이 나중에 뚫리면 그때까지 쌓인 기록이 한꺼번에 열린다.

## ⚙️ 작동 원리

```도해
흐름: 양자내성 키 교환은 접속할 때 무엇을 주고받나
클라이언트 :: 열쇠 한 쌍을 만든다
클라이언트 :: 공개분(캡슐화 키)만 보낸다
서버 :: 그 키로 비밀 하나를 캡슐에 넣는다
서버 :: 캡슐만 돌려보낸다. 비밀 자체는 안 보낸다
< 클라이언트 :: 개인 열쇠로 캡슐을 열어 같은 비밀을 얻는다
= 비밀을 실어 보내지 않는데도 양쪽이 같은 값을 손에 쥔다
```

이 주고받기를 KEM(키 캡슐화 방식)이라고 부르고, ML-KEM 은 그중 표준으로 정해진 것이다. 매개변수가 512 · 768 · 1024 셋인데 대부분은 768 을 쓴다.

실제 배포는 새 방식 하나로 갈아타지 않고 기존 방식과 **묶어서** 한다. Go 1.24의 기본 키 교환 목록에 들어간 `X25519MLKEM768` 은 이름 그대로 X25519 와 ML-KEM-768 을 합친 것이고, Go 1.26에는 `SecP256r1MLKEM768` 같은 조합이 더해졌다. 둘을 묶어두면 새 알고리즘 쪽에 구현 결함이 나와도 기존 쪽이 남는다.

## 💡 실제 사례

- **HTTPS 손잡기** — Go 1.24부터 기본 키 교환 목록에 X25519MLKEM768 하이브리드가 들어간다. 서버 코드는 그대로다.
- **런타임에서 열쇠 만들기** — Node.js 는 `ml-kem-768` 로 열쇠 한 쌍을 만들고 encapsulate · decapsulate 로 같은 비밀을 나눠 갖는다.
- **문제가 생겼을 때 되돌리기** — Go 는 `GODEBUG=tlsmlkem=0` 으로 예전 방식만 쓰게 되돌릴 수 있다.

## 🚫 흔한 오해

- **양자컴퓨터가 나오면 그때 바꾸면 된다** — 오늘 오간 암호문을 받아 적어뒀다가 그때 푸는 일이 가능하다. 늦게 바꾸면 이미 지나간 통신까지 같이 열린다.
- **양자컴퓨터로 돌리는 암호다** — 아니다. 평범한 서버에서 도는 보통 알고리즘이고, 양자컴퓨터로 풀기 어렵게 설계했을 뿐이다.
- **양자내성으로 바꾸면 무조건 더 안전하다** — 새 알고리즘일수록 구현이 덜 닳았다. 그래서 실제 기본값은 기존 방식을 버리는 대신 둘을 묶은 하이브리드다.

## 📝 정리

**"나중에 나올 계산기로도 안 풀리는 그 자물쇠"** 라고 읽으면 된다. 키를 나눠 갖는 자리와 서명하는 자리에 각각 표준이 정해졌고, 실제 배포는 기존 방식과 묶은 하이브리드로 이미 언어 런타임의 기본값에 들어와 있다. 늦게 바꿀수록 손해가 소급되는 것이 이 전환의 특징이다.

## 🧒 열 살에게

누가 우리 집 자물쇠를 다 열 수 있는 만능 열쇠를 곧 만든대. 그런데 그 열쇠가 나온 다음에 자물쇠를 바꾸면 이미 열린 문은 되돌릴 수 없잖아. 그래서 열쇠가 나오기 전에 미리 안 열리는 자물쇠로 갈아 끼우는 거야.

## ❓ 이해했는지

- 오늘 오간 HTTPS 통신이 몇 년 뒤에 열릴 수 있다는 말은 무슨 뜻인가 → 해결하는 문제
- 비밀을 회선에 실어 보내지 않았는데 어떻게 양쪽이 같은 값을 갖게 되나 → 작동 원리
- 이미 양자내성으로 바꿨다면서 왜 X25519 가 아직 이름에 붙어 있나 → 흔한 오해
