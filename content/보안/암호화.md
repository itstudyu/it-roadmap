# 암호화 (Encryption)

## 📝 정의

암호화는 **열쇠를 가진 사람만 읽을 수 있게 바꾸는 일**이다.

원래 내용을 평문, 바꾼 결과를 암호문이라고 한다. 되돌리는 것을 복호화라고 하고, 그 되돌리기가 열쇠 없이는 안 되도록 설계한 것이 이 기술의 전부다.

### 비유
자물쇠가 달린 상자. 안에 무엇이 들었는지는 열쇠를 가진 사람만 알고, 상자를 흔들어봐야 알 수 없다.

## 🖼️ 그림으로 보기

```도해
흐름: 메시지 하나가 암호화되어 어떻게 되돌아오나
평문 :: 보낼 내용. 그대로 두면 누구나 읽는다
암호화 :: 열쇠를 써서 뜻 없는 값으로 바꾼다
전송 :: 중간에서 가로채도 읽을 것이 없다
받는 쪽 :: 맞는 열쇠로 되돌린다
< 평문 :: 원래 내용이 그대로 나온다
= 열쇠가 없으면 값은 손에 있어도 뜻이 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 내용을 그대로 두면 어떻게 되나
암호화 없이 || 암호화해서
가로챈 사람 :: 그대로 읽는다 || 뜻 없는 값
DB 가 털리면 :: 내용이 다 나간다 || 값만 나간다
저장 매체 분실 :: 꽂으면 열린다 || 못 연다
= 새는 것을 막는 게 아니라 새어도 못 읽게 만드는 것이다
```

데이터는 오가는 도중에도 새고 쌓여 있는 동안에도 샌다. 공용 와이파이에서 오가는 통신은 같은 망에 있는 사람이 잡을 수 있고, DB가 통째로 유출되는 사고도 계속 일어난다.

암호화는 새는 경로를 막지 않는다. 새더라도 가져간 쪽이 읽지 못하게 만든다. 그래서 접근 통제가 뚫린 다음에 남는 마지막 방어선이 된다.

## ⚙️ 작동 원리

```도해
층: 암호화는 어떤 갈래로 나뉘나
대칭키 :: 같은 열쇠로 잠그고 푼다. 빠르다
비대칭키 :: 공개키로 잠그고 개인키로 푼다. 느리다
해시 :: 잠그기만 하고 되돌리는 길이 없다
= 되돌릴 필요가 있느냐가 첫 갈림길이다
```

대칭키는 빠르지만 열쇠를 상대에게 어떻게 건네느냐가 문제로 남는다. 열쇠를 그냥 보내면 그것부터 가로채이기 때문이다. 비대칭키는 이 문제가 없다. 공개키는 누구에게 알려줘도 되고, 그것으로 잠근 것은 개인키로만 풀린다.

그래서 둘을 같이 쓴다. 처음 연결할 때는 비대칭키로 대칭키를 안전하게 나눠 갖고, 그다음부터는 빠른 대칭키로 주고받는다. 대칭키 쪽 표준은 AES고, 비대칭키에서는 RSA가 널리 쓰인다.

## 💡 실제 사례

- **HTTPS** — 브라우저와 서버 사이가 TLS로 감싸져서 중간에 있는 누구도 내용을 못 읽는다.
- **비밀번호 저장** — 원문 대신 되돌릴 수 없는 값으로 바꿔 저장하고, 로그인할 때 같은 방식으로 바꿔 비교한다.
- **파일 잠그기** — 파일을 키로 암호화해두면 그 파일이 새어나가도 키 없이는 열리지 않는다.

## 🚫 흔한 오해

- **Base64로 바꾸면 암호화된 것이다** — 되돌리는 데 열쇠가 필요 없다. 누구나 원래대로 돌릴 수 있으니 표현을 바꾼 것이지 가린 것이 아니다.
- **비밀번호는 암호화해서 저장한다** — 비밀번호는 되돌릴 이유가 없다. 되돌릴 수 있게 두면 열쇠가 새는 순간 전부 나가므로, 되돌릴 길이 없는 해시로 저장한다.
- **암호화하면 내용이 바뀌는 것도 막는다** — 못 읽는 것과 못 바꾸는 것은 다르다. 중간에서 값을 헝클어 놓을 수는 있고, 그것까지 막으려면 무결성 확인이 따로 붙는다.

## 🚨 주의사항

- **직접 만든 방식을 쓰지 않는다.** 오래 검증된 AES나 RSA를 라이브러리가 정한 대로 쓴다.
- **열쇠를 코드에 적어두지 않는다.** 저장소에 올라간 열쇠는 암호화를 한 적 없는 것과 같다.

## 📝 정리

암호화는 열쇠 없이는 못 읽게 내용을 바꾸는 일이다. 대칭키는 빠르고 비대칭키는 열쇠를 나눠 갖는 문제를 풀기 때문에 둘을 같이 쓰며, 되돌릴 필요가 없는 비밀번호에는 해시를 쓴다.
