# OAuth 2.0

## 📝 정의

OAuth는 **비밀번호를 넘기지 않고 권한만 빌려주는 규약**이다.

어떤 앱이 내 구글 캘린더를 읽어야 할 때, 구글 비밀번호를 그 앱에 알려주는 대신 구글이 발급한 토큰만 준다. 그 토큰으로는 캘린더 읽기만 되고 다른 건 안 된다.

### 비유
호텔의 발레파킹 열쇠. 시동은 걸리지만 트렁크는 안 열린다. 주인이 열쇠 전체를 넘기지 않고 필요한 권한만 빌려주는 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 구글 로그인 버튼을 누르면 무슨 일이 일어나나
사용자 :: 앱에서 "구글로 계속하기" 를 누른다
앱 :: 구글 로그인 화면으로 보낸다
구글 :: 사용자가 로그인하고 권한 범위를 확인한다
구글 :: 일회용 코드를 앱에 돌려준다
앱 :: 그 코드와 자기 비밀키로 토큰을 받아온다
< 앱 :: 토큰으로 프로필만 읽는다. 비밀번호는 본 적 없다
= 앱이 비밀번호를 만지지 않는 것이 이 규약의 목적 전부다
```

## ⚠️ 해결하는 문제

```도해
대조: 다른 서비스 데이터를 쓰려면 무엇을 넘겨야 하나
비밀번호 공유 || OAuth
앱이 아는 것 :: 비밀번호 전부 || 제한된 토큰
권한 범위 :: 전부 || 허용한 것만
철회 :: 비밀번호 변경 || 토큰만 회수
= 전부 아니면 전무였던 것을 필요한 만큼으로 쪼갠 것이다
```

예전에는 다른 서비스의 데이터를 쓰려면 그 서비스의 아이디와 비밀번호를 대신 입력받았다. 그 앱은 내 계정으로 무엇이든 할 수 있게 되고, 앱이 털리면 내 계정도 같이 털린다. 권한을 거두려면 비밀번호를 바꾸는 수밖에 없었다.

OAuth는 권한을 잘게 쪼개고 회수할 수 있게 만들었다. 앱마다 다른 토큰을 주므로 하나를 지워도 나머지는 멀쩡하다.

## ⚙️ 작동 원리

토큰이 두 종류다.

| 토큰 | 수명 | 하는 일 |
|---|---|---|
| 접근 토큰 | 몇 분에서 몇 시간 | 실제 API 호출에 쓴다 |
| 갱신 토큰 | 길다 | 접근 토큰이 만료되면 새로 받아온다 |

접근 토큰을 짧게 두는 이유는 유출됐을 때 피해 시간을 줄이기 위해서다. 갱신 토큰은 서버 안쪽에만 두고 밖으로 내보내지 않는다.

권한 범위는 처음 동의 화면에서 정해진다. 나중에 더 필요해지면 다시 동의를 받아야 한다.

## 💡 실제 사례

- **소셜 로그인** 구글이나 카카오 계정으로 가입한다. 다만 이건 엄밀히는 OIDC 의 영역이다.
- **캘린더 연동** 일정 관리 앱이 구글 캘린더를 읽고 쓴다.
- **결제 연동** 판매자 계정에 접근 권한을 주되 정산 정보는 못 보게 범위를 좁힌다.

## 🚫 흔한 오해

- **OAuth는 로그인 방식이다** — 인가(무엇을 할 수 있는가)를 다루는 규약이지 인증(누구인가)이 아니다. 로그인에 쓰려면 그 위에 얹은 OIDC 가 필요하다.
- **토큰이 있으면 무엇이든 할 수 있다** — 동의한 범위 안에서만 된다. 캘린더 읽기 토큰으로 메일을 읽을 수 없다.
- **한 번 동의하면 영구적이다** — 사용자가 계정 설정에서 언제든 회수할 수 있고, 그러면 토큰이 즉시 죽는다.

## 🚨 주의사항

- **비밀키를 브라우저나 앱에 두지 않는다.** 클라이언트 비밀은 서버에만 둔다. 프론트엔드에서만 도는 앱은 PKCE라는 별도 방식을 쓴다.
- **범위를 최소로 요청한다.** 필요 이상을 요구하면 동의 화면에서 사용자가 이탈하고, 유출 시 피해도 커진다.

## 📝 정리

OAuth는 비밀번호를 넘기지 않고 권한만 빌려주는 규약이다. 범위를 좁혀 발급하고 언제든 회수할 수 있으며, 인증이 아니라 인가를 다룬다는 점이 요점이다.

## ❓ 이해했는지

- 앱이 내 구글 비밀번호를 모르는데 어떻게 내 캘린더를 읽나?
- 접근 토큰을 몇 분짜리로 짧게 두는 이유는?
- OAuth만으로 "이 사람이 누구인지" 를 알 수 없는 이유는?

## 🔗 관련 용어

- [[JWT]] — 발급되는 토큰의 형식으로 자주 쓰인다
- [[SSO]] — 한 번 로그인으로 여러 서비스를 쓰는 구조
- [[Refresh Token]] — 만료된 액세스 토큰을 다시 받는 장치
- [[API Key]] — 권한 범위나 회수 개념이 없는 더 단순한 방식
