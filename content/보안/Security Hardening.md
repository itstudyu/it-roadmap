# Security Hardening (굳히기)

## 📝 정의

Security Hardening은 **공격받을 자리를 미리 줄여 두는 일**이다.

미국 표준 기관 NIST 는 이 말을 "취약점에 패치를 붙이고 꼭 필요하지 않은 서비스를 꺼서 공격 수단을 없애려는 과정" 으로 적는다. 무엇을 새로 사서 얹는 일이 아니라 이미 켜져 있는 것을 끄는 일이라는 뜻이 정의 안에 들어 있다.

### 이름
Security :: 안전
Hard :: 단단한
-en :: ~하게 만들다
-ing :: 하는 일
= 붙여 읽으면 "안전을 단단하게 만드는 일". 더 얹는 게 아니라 무른 데를 없애는 쪽이다

### 비유
겨울 오기 전 집 단속. 안 쓰는 뒷문은 아예 막아 버리고, 계속 드나들 현관에만 자물쇠를 새로 단다.

### 예
새 노트북을 켜자마자 안 쓰는 기본 앱을 지우고 자동 로그인을 꺼 두던 그 시간이 굳히기다.

### 직접
폰 설정의 앱 권한 목록을 열어 보라. 안 쓰는 앱이 아직 위치나 마이크를 쥐고 있으면 그게 줄일 자리다.

## 🖼️ 그림으로 보기

```도해
층: 공격받을 자리는 어느 켜에 쌓여 있나
안 쓰는 것 :: 끄면 끝난다. 안 쓰는 기능·포트·계정
기본값 :: 바꾸면 끝난다. 초기 암호와 기본 관리자
과한 권한 :: 누가 무엇까지 되는지 다시 짜야 한다
낡은 판 :: 계속 붙여야 한다. 새 구멍이 계속 나온다
= 위는 한 번 끄면 영영 줄고, 아래로 갈수록 계속 손이 간다
```

## ⚠️ 해결하는 문제

```도해
대조: 기본 설치 그대로 두면 무엇이 달라지나
기본 그대로 || 굳혀 두면
열린 문 :: 안 쓰는 것도 열림 || 쓸 것만 열림
초기 암호 :: 문서에 다 적혀 있다 || 처음에 바꿔 둔다
새 취약점 :: 어디가 뚫릴지 모름 || 닿는 면이 좁다
= 공격은 열려 있는 자리로만 들어온다. 자리를 줄이면 뚫릴 일도 준다
```

기본 설치 상태는 "누구나 바로 쓸 수 있게" 를 노리고 만들어진다. 그래서 잘 쓰지 않는 기능도 켜져 있고, 초기 관리자 이름과 초기 암호는 설명서에 그대로 적혀 있다. 편하라고 열어 둔 자리가 그대로 남의 입구가 된다.

굳히기는 그 자리를 **하나씩 세어 없애는 일**이다. 없애고 남은 면이 좁을수록, 다음 달에 새 취약점이 나와도 내 것에 닿을 확률이 줄어든다. 어떤 공격을 막을지 미리 맞히지 않아도 되는 것이 이 방법의 값어치다.

## ⚙️ 작동 원리

굳히기는 감으로 하지 않는다. **기준 문서를 놓고 지금 설정과 한 줄씩 견주는 일**로 한다. Kubernetes 는 인증·권한, 망, 파드, 기록, 비밀, 이미지 같은 갈래로 나눈 보안 검사 목록을 공식 문서로 둔다. Azure 는 서비스마다 "이 서비스는 어떻게 동작하나 · 어떤 보안 기능이 있나 · 무엇으로 설정하기를 권하나" 세 가지를 적어 둔 보안 기준선 문서를 낸다.

기준 문서에는 항목마다 **기본값으로 켜져 있는지**와 **누가 설정할 책임인지**가 붙는다. 이 두 칸이 굳히기의 실제 작업 목록이다. 기본값으로 이미 켜진 것은 확인만 하고, 고객 책임이라고 적힌 것이 내가 손댈 자리다.

다만 Kubernetes 문서는 스스로 단서를 단다 — 검사 목록만으로는 좋은 보안 태세가 서지 않고, 어떤 항목은 우리에게 너무 빡빡하거나 너무 느슨할 수 있다는 것이다. 목록은 출발점이지 도장이 아니다.

## 📊 비교: 굳히기와 이웃한 세 말은 무엇이 다른가

| 말 | 무엇을 하나 | 언제 끝나나 |
|---|---|---|
| **굳히기** | 켜져 있는 것을 끄고 기본값을 바꾼다 | 새 기계·새 판을 올릴 때마다 다시 |
| **패치** | 이미 알려진 구멍을 메운다 | 구멍이 새로 나올 때마다 계속 |
| **최소 권한** | 남겨 둔 문에 누가 들어올지 좁힌다 | 사람과 역할이 바뀔 때마다 |
| **위협 탐지** | 그래도 들어온 것을 알아챈다 | 끝나지 않는다 |

넷은 같은 목표를 서로 다른 시점에 맡는다. 굳히기만 해 두고 나머지를 안 하면, 굳혀 둔 그 상태가 몇 달 뒤에는 낡은 상태가 된다.

## 💡 실제 사례

- **새 서버 첫 설정** — 안 쓰는 포트를 닫고, 초기 관리자 계정을 지우고, 원격 접속을 열쇠 방식으로만 바꾼다.
- **클러스터 점검** — Kubernetes 는 기본 거부 망 정책, 파드 보안 기준 적용, 감사 기록 보호 같은 항목을 검사 목록으로 준다. 한 번에 다 하지 않고 갈래별로 훑는다.
- **기준선과 견주기** — Azure 는 서비스마다 권장 설정을 문서로 굳혀 둔다. 우리 설정과 그 문서를 맞춰 보면 어긋난 칸이 그대로 할 일 목록이 된다.

## 🚫 흔한 오해

- **보안 제품을 사면 굳어진다** — 굳히기는 사는 일이 아니라 끄는 일이다. 새 도구를 얹으면 지켜야 할 자리가 오히려 하나 늘어난다.
- **검사 목록을 다 통과했으니 안전하다** — Kubernetes 문서 자신이 "검사 목록만으로는 좋은 보안 태세를 얻을 수 없다" 고 적는다. 목록은 끝없는 길의 첫걸음이지 합격 도장이 아니다.
- **한 번 굳혀 두면 계속 굳어 있다** — 판을 올리고 기능을 켜는 순간 되돌아간다. 굳히기는 상태가 아니라 되풀이하는 일이다.

## 📝 정리

**"켜져 있는 것을 줄여 두는 일"** 이라고 읽으면 된다. 무엇을 더 사서 얹는 쪽이 아니라 기본값으로 열려 있던 문을 닫는 쪽이고, 그래서 새 취약점이 나와도 닿는 면이 좁다. 기준 문서와 견줘 보는 일은 시작이지 끝이 아니다.

## 🧒 열 살에게

집에 안 쓰는 뒷문이 열 개나 열려 있으면 다 지키기 힘들지? 안 쓰는 문은 아예 막아 버리고 드나드는 현관 하나만 잘 잠그면, 도둑이 와도 들어올 데가 한 군데뿐이야.

## ❓ 이해했는지

- 안 쓰는 기능을 끄는 일이 아직 나오지도 않은 취약점까지 왜 막아 주나 → 해결하는 문제
- 검사 목록을 다 통과했는데도 안심할 수 없는 이유는 무엇인가 → 흔한 오해
- 굳힐 자리 중 한 번 끄면 끝나는 것과 계속 손이 가는 것은 어떻게 갈리나 → 그림
