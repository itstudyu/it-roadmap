# MFA (Multi-Factor Authentication)

## 📝 정의

MFA는 **종류가 다른 증거를 둘 이상 요구하는 인증**이다.

비밀번호는 새어나갈 수 있고, 새어나갔다는 사실을 본인이 알아채기도 어렵다. 성격이 다른 증거를 하나 더 요구하면 비밀번호 하나만으로는 문이 열리지 않는다.

### 비유
금고. 열쇠 하나로는 안 열리고 서로 다른 열쇠 두 개를 함께 돌려야 열린다.

### 예
로그인 버튼을 누르면 문자로 여섯 자리 숫자가 오고 그것까지 넣어야 들어가진다. 그 한 단계가 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 비밀번호가 새어나갔을 때 MFA 는 어디서 막나
공격자 :: 어디선가 얻은 비밀번호를 넣는다
서버 :: 비밀번호는 맞다. 여기서 끝내지 않는다
서버 :: 두 번째 증거를 요구한다. 6자리 코드
공격자 :: 본인의 기기가 없어 코드를 못 만든다
< 서버 :: 로그인 거부. 본인에게는 시도 기록이 남는다
= 비밀번호를 통과하고도 못 들어간다. 그게 두 번째 요소의 일이다
```

## ⚠️ 해결하는 문제

```도해
대조: 비밀번호 하나만으로 지키면 어떻게 되나
비밀번호만 || MFA 로
유출되면 :: 바로 로그인됨 || 한 단계가 남음
재사용 :: 다른 곳도 뚫림 || 그것만으론 안 됨
알아채기 :: 모르고 지나감 || 시도 기록이 남음
= 증거를 하나 더 두면 하나가 새어도 문이 열리지 않는다
```

비밀번호는 한 번 유출되면 그것으로 끝이다. 여러 사이트에서 같은 비밀번호를 쓰고 있으면 한 곳에서 샌 것이 다른 곳의 열쇠가 된다.

MFA는 문을 두 개로 만든다. 비밀번호를 아는 것만으로는 통과가 안 되고, 두 번째 문을 열려면 본인이 실제로 갖고 있는 것이나 몸에 붙은 것이 필요하다.

## 🧱 구성

```도해
층: 인증 요소는 뺏기가 얼마나 어려운가
아는 것 :: 비밀번호, PIN. 말해주면 그대로 넘어간다
가진 것 :: 폰, OTP 기기, 보안 키. 뺏어야 넘어간다
자신인 것 :: 지문, 얼굴. 몸에서 뗄 수 없다
= 아래로 갈수록 뺏기 어렵다. 서로 다른 칸에서 둘을 골라야 MFA 다
```

## ⚙️ 작동 원리

가장 흔한 두 번째 요소는 시간 기반 OTP다. 서버와 인증 앱이 같은 비밀 키를 나눠 갖고, 거기에 현재 시각을 함께 넣어 계산해서 6자리 숫자를 만든다. 양쪽이 같은 재료로 같은 계산을 하기 때문에 서로 연락하지 않아도 같은 값이 나오고, 시각이 지나면 값이 바뀐다.

## 💡 실제 사례

- **회사 계정 로그인** — 비밀번호를 넣은 뒤 인증 앱에 뜬 6자리 숫자를 추가로 넣는다.
- **관리자 접근** — 서버나 클라우드 콘솔은 MFA를 통과하지 않으면 아예 들어가지 못하게 막아둔다.
- **위험한 동작 앞에서** — 이체나 설정 변경처럼 되돌리기 어려운 일 직전에 한 번 더 확인한다.

## 🚫 흔한 오해

- **비밀번호에 보안 질문을 더하면 2단계다** — 둘 다 아는 것이라 같은 칸이다. 하나를 알아낸 사람이 다른 하나도 알아낼 수 있다.
- **OTP 앱은 인터넷이 있어야 코드를 받는다** — 서버가 보내주는 게 아니라 앱이 직접 계산한다. 비행기 모드에서도 맞는 숫자가 나온다.
- **MFA를 켜면 비밀번호는 대충 지어도 된다** — 두 번째 요소는 첫 번째를 대신하지 않는다. 하나가 무너지면 남는 벽이 하나로 줄어든다.

## 🚨 주의사항

- **복구 수단을 미리 만들어둔다.** 기기를 잃어버리면 공격자뿐 아니라 본인도 못 들어간다.
- **모든 화면에 다 걸면 사람들이 우회한다.** 위험한 동작에 집중해서 거는 편이 실제로 지켜진다.

## 📝 정리

MFA는 종류가 다른 증거를 둘 이상 요구하는 인증 방식이다. 비밀번호가 새어나가도 두 번째 요소가 남아 있어서 그것만으로는 문이 열리지 않는다.

## ❓ 이해했는지

- 비밀번호가 유출됐는데도 계정이 열리지 않는 이유는 → 그림
- 비밀번호와 보안 질문을 함께 묻는 것을 MFA로 치지 않는 이유는 → 흔한 오해
- 인증 앱이 인터넷 없이도 맞는 코드를 만들어내는 이유는 → 작동 원리
