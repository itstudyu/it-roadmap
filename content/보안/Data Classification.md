# Data Classification (데이터 등급 나누기)

## 📝 정의

Data Classification은 **자료마다 새어 나갔을 때의 크기를 매겨 등급을 붙이는 일**이다.

AWS 문서는 이 일을 "보안 위험 관리의 맨 처음 걸음" 으로 적고, 그 안에 두 가지가 들어 있다고 한다 — 어떤 종류의 자료를 다루고 있는지 알아내는 일, 그리고 **그것이 새거나 망가지거나 잘못 쓰였을 때 얼마나 아픈지를 판정하는 일**이다. 등급은 이름표가 아니라, 그 등급에 딸린 최소한의 보호 조치를 부르는 열쇠다.

### 이름
Data :: 다루는 자료
Classification :: 등급 나누기
= 붙여 읽으면 "자료에 등급 매기기". 등급이 정해져야 어디까지 지킬지가 정해진다

### 비유
서류함에 붙이는 색깔 딱지. 빨강은 금고에, 파랑은 책상 위에 — 딱지 하나가 그 서류의 보관 방법을 통째로 정한다.

### 예
"이 파일 외부 저장소에 올려도 되나요?" 라는 물음에 그 자리의 누구도 확답을 못 하던 그 회의다.

### 직접
폰 사진첩의 "숨겨진 앨범" 을 열어 보라. 같은 사진인데 어느 칸에 넣느냐만으로 누구에게 보일지가 달라진다.

## 🖼️ 그림으로 보기

```도해
층: 등급을 붙이면 그 자료에 무엇이 따라붙나
공개 :: 누구나 봐도 된다. 홈페이지에 그냥 올린다
내부 :: 직원까지. 사내 저장소에 두고 밖으로는 안 내보낸다
대외비 :: 맡은 사람만. 열람 기록을 남기고 반출을 통제한다
극비 :: 정해진 몇 명만. 따로 잠그고 사본을 세어 관리한다
= 등급마다 지켜야 할 최소 조치가 다르다. 등급은 부르는 이름이 아니라 그 조치를 부르는 열쇠다
```

## ⚠️ 해결하는 문제

```도해
대조: 전부를 똑같이 다루면 무엇이 문제인가
등급 없이 || 등급을 매기면
비용 :: 전부에 금고를 || 필요한 데만
급한 자리 :: 어디가 급한지 모름 || 급한 데부터
일하는 속도 :: 공개 자료도 막힌다 || 그냥 쓴다
= 다 똑같이 지키면 결국 아무것도 못 지킨다. 등급은 힘을 어디에 쏟을지 정하는 자다
```

지킬 것이 늘어나면 힘은 흩어진다. 전부를 최고 등급으로 다루면 안전해 보이지만, AWS 문서는 그것을 **과잉 분류**라 부르며 위험으로 적는다 — 필요 없는 비용이 붙고, 정작 중요한 자료에서 눈이 떠나고, 안 걸어도 될 규정이 걸려 업무가 막힌다.

그래서 순서가 뒤집힌다. 먼저 목록을 만들고, 업무에 얼마나 치명적인지 따져 보고, 딱지를 붙이고, 그 등급의 취급 지침대로 다루고, 그다음에도 계속 지켜본다. ISO 와 NIST 같은 표준 기구가 등급 체계를 권하는 이유도 같다고 AWS 문서는 적는다 — **모든 자료를 똑같이 대하는 방식을 하지 말라는 것**이고, 등급마다 기준이 되는 보호 조치 묶음을 붙여 두라는 것이다.

## ⚙️ 작동 원리

훑는 일이 먼저다. 도구는 값의 무늬로 후보를 찾는다 — 자릿수와 구분자가 주민번호 꼴인지, 카드번호라면 검사 숫자가 맞아떨어지는지를 본다. 무늬만 보는 것이라 결과에는 "이 칸에 이런 것이 몇 건, 확신은 이만큼" 이라는 정도까지만 실린다.

그다음이 딱지를 붙이는 자리다. 사람이 정한 등급은 자원에 붙는 태그나 문서 안의 항목으로 저장된다. 여기서부터 등급은 사람이 읽는 글자가 아니라 기계가 읽는 값이 된다. 권한 정책과 검사 규칙은 자료를 하나하나 알 필요 없이 그 값 하나만 보고 갈린다.

딱지를 파일 바깥의 목록이 아니라 파일 안에 심어 두는 이유가 여기 있다. 목록에 적어 두면 파일이 메일에 실려 회사를 떠나는 순간 그 목록과 끊긴다. 안에 심어 두면 어디로 옮겨 가도 따라가고, 받는 쪽 프로그램도 그 값을 읽어 같은 취급을 건다.

## 📊 비교: 세 곳은 등급을 어떻게 매기나

| 무엇 | AWS | Microsoft Purview | Google Cloud |
|---|---|---|---|
| **찾아내기** | Macie 가 S3 를 훑어 민감 자료를 찾는다 | 민감 정보 유형으로 문서와 메일을 훑는다 | Sensitive Data Protection 이 infoType 으로 훑는다 |
| **딱지 붙이기** | 목록을 Glue Data Catalog 에 모으고 태그를 단다 | 민감도 레이블을 문서에 붙인다 | 자료 프로필과 태그를 붙인다 |
| **딱지가 하는 일** | 태그 조건으로 권한을 가른다 | 레이블이 암호화·워터마크까지 함께 건다 | 찾아낸 자리를 가리거나 바꾸는 변환으로 잇는다 |

Microsoft 문서는 그 딱지의 성질을 셋으로 적는다 — 조직이 직접 만드는 것, 평문으로 저장돼 남의 프로그램도 읽을 수 있는 것, 그리고 **파일을 어디에 옮겨도 따라다니는 것**이다. 한 문서에는 한 번에 하나만 붙는다.

## 💡 실제 사례

- **목록부터 만들기** — 무슨 종류의 자료가 어디에 있는지 세는 일이 먼저다. 세지 않은 자료에는 등급을 붙일 수 없다.
- **등급이 조치를 부른다** — "대외비" 딱지 하나로 암호화와 열람 기록과 반출 통제가 한꺼번에 걸리게 해 둔다.
- **다시 훑기** — 새로 쌓이는 자료를 계속 훑어 딱지가 빠진 자리를 찾는다. 한 번 매기고 끝나는 일이 아니다.

## 🚫 흔한 오해

- **중요한 건 전부 최고 등급으로 두면 안전하다** — AWS 문서는 과잉 분류를 위험으로 적는다. 비싼 통제가 필요 없는 데까지 붙고, 눈이 흩어져 정작 급한 자료를 놓친다.
- **등급은 문서에 붙이는 이름표일 뿐이다** — 등급마다 취급 지침과 최소 보호 조치가 딸려 있어야 뜻이 있다. 이름만 있고 조치가 없으면 아무것도 안 달라진다.
- **자동으로 찾아 주는 도구를 켜면 끝난다** — 도구는 후보를 찾아 줄 뿐이고, 그것이 우리 업무에서 얼마나 치명적인지는 사람이 판정한다.

## 🚨 주의사항

- **등급은 업무 쓰임에서 거슬러 올라가 정한다.** AWS 문서는 자료의 쓰임을 놓고 그것이 조직 운영에 큰 영향을 주는지부터 따지라고 적는다.
- **딱지를 내리는 일에 흔적을 남긴다.** Microsoft 문서는 낮은 등급으로 바꿀 때 사유를 적게 하고 그 기록을 남길 수 있게 해 둔다.
- **한 자료에 하나만 붙는다.** 등급이 겹치면 무엇을 지켜야 하는지가 흐려진다. 대신 하위 구분을 두어 나눈다.

## 📝 정리

**"새면 얼마나 아픈지를 미리 매겨 두는 일"** 이라고 읽으면 된다. 등급은 이름표가 아니라 그 등급에 딸린 보호 조치를 부르는 열쇠이고, 전부를 최고 등급으로 두는 것은 안전이 아니라 낭비다. 목록·판정·딱지·취급·다시 보기 순서로 돈다.

## 🧒 열 살에게

책가방에는 굴러다녀도 그만인 종이가 있고 잃어버리면 큰일 나는 종이가 있지? 그걸 미리 나눠서 색깔 딱지를 붙여 두면, 어떤 건 아무 데나 둬도 되고 어떤 건 꼭 잠기는 곳에 넣게 돼. 전부 다 금고에 넣어 버리면 정작 급할 때 아무것도 못 꺼내.
