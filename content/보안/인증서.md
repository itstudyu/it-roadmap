# 인증서 (SSL/TLS Certificate)

## 📝 정의

인증서는 **이 사이트가 맞다고 제3자가 보증한 문서**다.

주소창의 자물쇠와 `https://`는 이 문서가 서버에 설치되어 있고 검증을 통과했다는 표시다. 안에는 사이트 이름과 공개키, 발급 기관, 유효기간이 들어 있고 발급 기관의 서명이 붙어 있다.

### 이름
SSL/TLS :: 연결을 감싸는 겹
Certificate :: 보증해 준 문서
= 붙여 읽으면 "연결을 감싸는 겹에 쓰는 보증 문서". 문서는 상대를 확인하는 데 쓰고, 감싸는 일은 그다음이다

### 비유
여권. 입국 심사대는 그 사람을 원래 알지 못하고, 정부가 발급한 문서와 거기 붙은 위조 방지 장치를 보고 확인한다.

### 예
휴대폰 날짜가 엉뚱하게 맞춰져 있으면 어느 사이트를 열어도 안전하지 않다는 경고가 뜬다. 유효기간을 견주기 때문이다.

### 직접
지금 보는 페이지의 주소창 자물쇠를 눌러 "인증서" 를 열어 보라. 누가 발급했고 언제까지 쓸 수 있는지가 그대로 적혀 있다.

## 🖼️ 그림으로 보기

```도해
흐름: https 주소를 열면 자물쇠가 뜨기까지 무엇이 오가나
브라우저 :: 연결을 걸고 쓸 수 있는 암호 방식을 알린다
서버 :: 자기 인증서를 보낸다. 안에 공개키가 들어 있다
브라우저 :: 서명, 유효기간, 도메인이 맞는지 확인한다
브라우저 :: 이번 대화에 쓸 열쇠를 만들어 공개키로 잠가 보낸다
서버 :: 개인키로 열어 같은 열쇠를 갖는다
둘 다 :: 그 열쇠로 암호화해서 주고받는다
= 인증서는 상대를 확인하는 데 쓰이고 대화는 새 열쇠로 한다
```

## ⚠️ 해결하는 문제

```도해
대조: 인증서 없이 접속하면 회선 위에서 무슨 일이 생기나
인증서 없이 || 인증서로
상대 확인 :: 가짜여도 모름 || 이름을 확인함
주고받는 내용 :: 그대로 읽힌다 || 암호화된다
중간 변조 :: 바뀌어도 모름 || 바뀌면 드러남
= 누구와 말하는지, 무슨 말인지, 그대로인지를 함께 지킨다
```

암호화되지 않은 연결에서는 비밀번호가 평문으로 흐른다. 중간 구간에 있는 누군가가 패킷을 뜨면 그대로 읽히고, 100만원 이체 요청을 1000만원으로 바꿔 보내도 양쪽 다 모른다.

주소만 보고 판단할 수 없는 문제도 있다. 진짜와 비슷하게 생긴 글자를 섞어 만든 주소는 눈으로 구별하기 어렵다. 인증서는 이 주소가 이 서버의 것이 맞는지를 브라우저가 기계적으로 확인하게 만들고, 통과한 경우에만 자물쇠를 보여준다.

## 🧱 구성

```도해
층: 브라우저는 처음 보는 사이트를 어떻게 믿나
루트 CA :: 브라우저와 운영체제에 미리 들어 있다
중간 CA :: 루트가 서명해준 발급 기관
사이트 인증서 :: 중간 CA 가 서명해준 이 사이트의 것
= 미리 믿는 하나에서 시작해 서명을 따라 내려오며 믿는다
```

## ⚙️ 작동 원리

브라우저는 세상의 모든 사이트를 알 수 없다. 대신 신뢰할 수 있는 최상위 발급 기관([[CA]])의 인증서를 미리 품고 있고, 그것이 서명한 것으로 신뢰를 이어 내려간다. 사슬이 끊기거나 모르는 기관이 서명했으면 경고가 뜬다.

검증은 세 가지를 본다. 서명이 알려진 기관의 것이 맞는지, 유효기간 안인지, 인증서에 적힌 이름이 지금 접속한 도메인과 같은지다. 셋 중 하나라도 어긋나면 연결을 막는다.

유효기간은 짧게 잡는다. 보통 1년 안쪽이고 최대 398일까지 허용되며, 무료로 발급하는 곳은 90일짜리를 주는 대신 자동 갱신을 전제로 한다.

## 📊 비교: 인증서 종류

| 종류 | 확인하는 것 | 발급까지 | 주로 쓰는 곳 |
|---|---|---|---|
| DV | 도메인 소유 여부만 | 몇 분 | 개인 블로그, 중소 서비스 |
| OV | 조직이 실제로 있는지 | 1~3일 | 중소기업, 공공기관 |
| EV | 신원을 엄격하게 확인 | 1~2주 | 금융, 대기업 |
| Wildcard | 서브도메인을 한꺼번에 | DV나 OV 기준 | www, api, admin 을 한 장으로 |

## 💡 실제 사례

- **주소창의 자물쇠** — 검증이 통과했다는 표시일 뿐이고, 누르면 어느 기관이 발급했는지 볼 수 있다.
- **90일 인증서 자동 갱신** — 만료 전에 갱신하고 웹 서버를 다시 읽히는 작업을 예약해둔다.
- **갱신을 놓친 사이트** — 서비스는 멀쩡한데 경고 화면 때문에 사용자가 들어오지 못한다.

## 🚫 흔한 오해

- **자물쇠가 떠 있으면 안전한 사이트다** — 인증서가 보증하는 것은 주소가 맞다는 것과 내용이 암호화된다는 것뿐이다. 피싱 사이트도 자기 도메인으로 인증서를 받을 수 있다.
- **인증서가 데이터를 암호화한다** — 인증서는 신원 확인과 공개키 전달에 쓰인다. 실제 내용은 그 과정에서 새로 만든 세션 열쇠로 암호화된다.
- **한 번 받아두면 계속 쓴다** — 유효기간이 있다. 보통 1년 안쪽이고 짧은 것은 90일이라 갱신을 자동으로 걸어두지 않으면 어느 날 갑자기 경고가 뜬다.

## 🚨 주의사항

- **개인키를 형상 관리에 올리지 않는다.** 인증서는 공개해도 되지만 개인키가 새면 그것으로 남을 흉내 낼 수 있다.
- **HTTPS 페이지에서 HTTP 자원을 불러오지 않는다.** 한 군데라도 섞이면 그 부분은 보호받지 못한다.

## 📝 정리

**"이 사이트가 맞다고 남이 도장 찍어 준 여권"** 이라고 읽으면 된다. 브라우저는 서명과 유효기간과 도메인을 확인해 통과할 때만 연결을 이어주고, 실제 대화를 암호화하는 열쇠는 인증서 안의 공개키를 써서 그 자리에서 새로 만든다. 유효기간이 있으므로 갱신을 자동화해두지 않으면 언젠가 끊긴다.

## 🧒 열 살에게

공항 심사대 아저씨는 너를 처음 보잖아? 그런데도 들여보내 주는 건 네 얼굴을 알아서가 아니라, 나라에서 만들어 준 여권에 찍힌 도장이 진짜라서야. 그 여권에는 언제까지 쓸 수 있는지도 적혀 있어서, 날짜가 지나면 같은 사람이라도 문 앞에서 막혀.
