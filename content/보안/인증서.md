# 인증서 (SSL/TLS Certificate)

## 📝 정의

**인증서는 웹사이트의 신원을 증명하고 암호화 통신을 가능하게 하는 디지털 문서입니다.**

브라우저에서 "자물쇠" 아이콘이 보이고 주소가 `https://`로 시작하는 것은 **인증서가 설치되어 있다는 증거**입니다. 인증서는 "이 사이트가 진짜 google.com이 맞는가?"를 보증하고, 데이터를 암호화해서 안전하게 전송합니다.

## 🎯 핵심 개념

### 1. **3가지 역할**

| 역할 | 설명 | 예시 |
|---|---|---|
| **신원 확인** | 이 사이트가 진짜인지 검증 | google.com이 진짜 Google인지 |
| **암호화** | 데이터를 암호화해서 전송 | 비밀번호, 카드번호 안전 전송 |
| **무결성** | 데이터 변조 방지 | 중간에 해커가 수정 불가 |

### 2. **인증 기관 (CA - Certificate Authority)**
- 인증서를 발급하는 **신뢰할 수 있는 제3자**
- 예: Let's Encrypt, DigiCert, GlobalSign, Comodo
- 브라우저에 CA의 Root 인증서가 사전 설치됨

### 3. **인증서 체인**
```
Root CA (최상위 인증 기관)
  └─ Intermediate CA (중간 인증 기관)
       └─ 사이트 인증서 (example.com)
```

### 4. **유효 기간**
- 보통 1년 (최대 398일)
- Let's Encrypt: 90일 (자동 갱신 권장)
- 만료되면 브라우저가 경고 표시

## 🤔 왜 필요한가? (문제와 해결)

### 문제 1: 가짜 사이트 (피싱)

```
상황: 사용자가 naver.com이라고 생각하고 로그인
실제: 해커가 만든 naver.com과 비슷한 nαver.com (알파 대신 α)
결과: 아이디/비밀번호가 해커에게 전달

[사용자] --로그인--> [가짜 네이버] --정보 탈취--> [해커]
```

**인증서 해결법:**
```
1. 진짜 naver.com은 CA가 발급한 인증서 보유
2. 가짜 nαver.com은 인증서 없음 (또는 경고 표시)
3. 브라우저가 자동으로 검증:
   ✅ 인증서 있음: 자물쇠 아이콘 표시
   ❌ 인증서 없음: "안전하지 않음" 경고

4. 사용자가 쉽게 구분 가능
```

### 문제 2: 중간자 공격 (Man-in-the-Middle)

```
HTTP (암호화 X):
[사용자] --평문 전송--> [해커가 엿듣기] --전달--> [서버]
           ↓
    "password: hunter2"  ← 해커가 다 볼 수 있음!
```

**인증서 해결법:**
```
HTTPS (암호화 O):
[사용자] --암호화 전송--> [해커가 봐도 이해 못 함] --전달--> [서버]
           ↓
    "Gj8$kL#mQ9pR..."  ← 해커가 봐도 무의미!
                         ↓
                    [서버만 복호화 가능]
```

### 문제 3: 데이터 변조

```
HTTP:
1. 사용자: "100만원 이체" 전송
2. 해커: 중간에 가로채서 "1000만원 이체"로 변조
3. 서버: "1000만원 이체" 받음
4. 사용자는 모름!
```

**인증서 해결법:**
```python
# HTTPS는 데이터에 디지털 서명 포함
data = "100만원 이체"
signature = sign(data, private_key)  # 서명 생성

# 서버에서 검증
if verify(data, signature, public_key):
    print("데이터 변조 없음")
else:
    print("⚠️ 데이터가 변조되었습니다!")  # 거부
```

## 🔄 작동 원리 (SSL/TLS Handshake)

```도해
흐름: 인증서, 무슨 순서로 오가나
브라우저 (Client) :: ClientHello (지원하는 암호화 방식 목록)
웹서버 (Server) :: ServerHello + 인증서 (Public Key 포함)
브라우저 (Client) :: CA 서명 확인 유효기간 확인 도메인 일치 확인
브라우저 (Client) :: 임시 세션 키 생성
브라우저 (Client) :: 암호화된 세션 키 (서버 Public Key로 암호화)
웹서버 (Server) :: Private Key로 복호화 세션 키 획득
브라우저 (Client) :: 암호화된 데이터 (세션 키 사용)
웹서버 (Server) :: 암호화된 응답 (세션 키 사용)
브라우저 (Client) :: 경고 표시 "안전하지 않은 연결
```

### 동작 과정 설명

1. **ClientHello**: 브라우저가 서버에 연결 시도, 지원하는 암호화 알고리즘 전송
2. **인증서 전송**: 서버가 자신의 인증서 + Public Key 전송
3. **인증서 검증**: 브라우저가 CA 서명 확인, 유효기간 확인, 도메인 일치 확인
4. **키 교환**: 브라우저가 임시 세션 키 생성 후 서버 Public Key로 암호화해서 전송
5. **복호화**: 서버가 Private Key로 복호화해서 세션 키 획득
6. **암호화 통신**: 이후 모든 데이터는 세션 키로 암호화해서 주고받음

## 🏠 일상적 비유

인증서는 **부동산 등기부등본**과 같습니다:

| 부동산 등기부등본 | SSL/TLS 인증서 |
|---|---|
| 이 집이 진짜 홍길동 소유인지 증명 | 이 사이트가 진짜 google.com인지 증명 |
| 등기소(공신력 있는 기관)가 발급 | CA(인증 기관)가 발급 |
| 위조 불가능한 특수 용지 | CA의 디지털 서명 |
| 유효기간 없음 (영구) | 유효기간 90일~1년 (갱신 필요) |
| 부동산 거래 시 확인 | 웹사이트 접속 시 확인 |

**또 다른 비유: 여권**
- 정부(CA)가 발급한 신분증
- 사진, 이름, 유효기간 포함
- 위조 방지 장치 (홀로그램 = 디지털 서명)
- 만료되면 갱신 필요

### 2. Nginx 설정 (자동 생성됨)

```nginx
# /etc/nginx/sites-available/p3.conf

server {
    listen 80;
    server_name p3.example.com www.p3.example.com;

    # HTTP → HTTPS 자동 리다이렉트 (Certbot이 추가)
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name p3.example.com www.p3.example.com;

    # SSL 인증서 경로 (Certbot이 자동 설정)
    ssl_certificate /etc/letsencrypt/live/p3.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/p3.example.com/privkey.pem;

    # 최신 TLS 프로토콜만 허용
    ssl_protocols TLSv1.2 TLSv1.3;

    # 강력한 암호화 알고리즘
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256';
    ssl_prefer_server_ciphers on;

    # SSL 세션 캐시 (성능 향상)
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # HSTS (HTTP Strict Transport Security)
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # P3 백엔드로 프록시
    location / {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 4. Python 코드에서 인증서 확인

```python
# p3_backend/security/ssl_checker.py

import ssl
import socket
from datetime import datetime
from cryptography import x509
from cryptography.hazmat.backends import default_backend

def check_certificate_expiry(hostname: str, port: int = 443) -> dict:
    """인증서 만료일 확인"""
    context = ssl.create_default_context()

    try:
        with socket.create_connection((hostname, port), timeout=10) as sock:
            with context.wrap_socket(sock, server_hostname=hostname) as ssock:
                # DER 형식 인증서 가져오기
                cert_der = ssock.getpeercert(binary_form=True)

                # 인증서 파싱
                cert = x509.load_der_x509_certificate(cert_der, default_backend())

                # 정보 추출
                subject = cert.subject.rfc4514_string()
                issuer = cert.issuer.rfc4514_string()
                not_before = cert.not_valid_before
                not_after = cert.not_valid_after

                # 남은 일수 계산
                days_left = (not_after - datetime.now()).days

                return {
                    "hostname": hostname,
                    "subject": subject,
                    "issuer": issuer,
                    "valid_from": not_before.isoformat(),
                    "valid_until": not_after.isoformat(),
                    "days_left": days_left,
                    "is_valid": days_left > 0,
                    "needs_renewal": days_left < 30  # 30일 이내 갱신 필요
                }

    except Exception as e:
        return {"error": str(e)}

# 모니터링 스크립트
def monitor_certificates():
    """P3 인증서 모니터링"""
    domains = [
        "p3.example.com",
        "p3-admin.example.com",
        "api.p3.example.com"
    ]

    for domain in domains:
        cert_info = check_certificate_expiry(domain)

        if cert_info.get("error"):
            send_alert(f"⚠️ {domain}: 인증서 확인 실패 - {cert_info['error']}")
        elif cert_info["needs_renewal"]:
            send_alert(f"⚠️ {domain}: 인증서 {cert_info['days_left']}일 후 만료! 갱신 필요")
        else:
            logger.info(f"✅ {domain}: 인증서 정상 ({cert_info['days_left']}일 남음)")

# Celery Beat으로 매일 실행
@celery_app.task
def daily_certificate_check():
    monitor_certificates()
```

### 1. 인증서 정보 확인

```python
import ssl
import socket

def get_certificate_info(hostname: str, port: int = 443):
    """인증서 정보 가져오기"""
    context = ssl.create_default_context()

    with socket.create_connection((hostname, port)) as sock:
        with context.wrap_socket(sock, server_hostname=hostname) as ssock:
            cert = ssock.getpeercert()

            print("=== 인증서 정보 ===")
            print(f"Subject: {dict(x[0] for x in cert['subject'])}")
            print(f"Issuer: {dict(x[0] for x in cert['issuer'])}")
            print(f"Version: {cert['version']}")
            print(f"Serial Number: {cert['serialNumber']}")
            print(f"Valid From: {cert['notBefore']}")
            print(f"Valid Until: {cert['notAfter']}")
            print(f"Subject Alt Names: {cert.get('subjectAltName')}")
```

### 2. 인증서 검증

```python
import ssl
import certifi

def verify_certificate(hostname: str) -> bool:
    """인증서 유효성 검증"""
    context = ssl.create_default_context(cafile=certifi.where())

    try:
        with socket.create_connection((hostname, 443), timeout=5) as sock:
            with context.wrap_socket(sock, server_hostname=hostname) as ssock:
                cert = ssock.getpeercert()
                # 여기까지 오면 인증서 유효
                return True
    except ssl.SSLError as e:
        print(f"⚠️ SSL 오류: {e}")
        return False
    except Exception as e:
        print(f"⚠️ 연결 오류: {e}")
        return False

# 사용 예시
if verify_certificate("google.com"):
    print("✅ 인증서 유효")
else:
    print("❌ 인증서 무효")
```

## 🔄 인증서 종류 비교

| 종류 | 검증 수준 | 발급 시간 | 비용 | 사용 사례 |
|---|---|---|---|---|
| **DV (Domain Validated)** | ⭐ 도메인 소유만 확인 | 수분 | 무료 (Let's Encrypt) | 개인 블로그, 중소 서비스 |
| **OV (Organization Validated)** | ⭐⭐ 조직 실존 확인 | 1~3일 | 연 $50~200 | 중소기업, 공공기관 |
| **EV (Extended Validation)** | ⭐⭐⭐ 엄격한 신원 확인 | 1~2주 | 연 $150~1000 | 금융, 대기업 (주소창에 회사명 표시) |
| **Wildcard** | 서브도메인 전체 커버 | DV/OV 기준 | +$50~100 | *.example.com (api, www, admin 등) |

### Let's Encrypt vs 유료 인증서

| 특성 | Let's Encrypt | 유료 (DigiCert 등) |
|---|---|---|
| **비용** | ✅ 무료 | ❌ 연 $50~1000 |
| **유효기간** | 90일 (자동 갱신) | 1~2년 |
| **검증 수준** | DV만 | DV, OV, EV |
| **와일드카드** | ✅ 지원 | ✅ 지원 |
| **브라우저 신뢰** | ✅ 모든 브라우저 | ✅ 모든 브라우저 |
| **보증금** | ❌ 없음 | ✅ 최대 $1M |
| **고객 지원** | ❌ 커뮤니티만 | ✅ 24/7 전화 지원 |

### 3. 인증서 갱신 자동화

```python
# p3_backend/tasks/ssl_renewal.py
from celery import Celery
from celery.schedules import crontab

celery_app = Celery('p3')

@celery_app.on_after_configure.connect
def setup_periodic_tasks(sender, **kwargs):
    # 매일 오전 3시에 인증서 확인
    sender.add_periodic_task(
        crontab(hour=3, minute=0),
        check_and_renew_certificate.s(),
    )

@celery_app.task
def check_and_renew_certificate():
    """인증서 만료 확인 및 갱신"""
    import subprocess

    # Certbot으로 갱신 시도
    result = subprocess.run(
        ['certbot', 'renew', '--quiet'],
        capture_output=True,
        text=True
    )

    if result.returncode == 0:
        logger.info("✅ 인증서 갱신 성공 (또는 갱신 불필요)")

        # Nginx 리로드
        subprocess.run(['systemctl', 'reload', 'nginx'])
    else:
        logger.error(f"❌ 인증서 갱신 실패: {result.stderr}")
        send_alert("인증서 갱신 실패! 수동 확인 필요")
```

### 4. Mixed Content 방지

```html
<!-- ❌ 나쁜 예: HTTPS 페이지에서 HTTP 리소스 로드 -->
<script src="http://example.com/script.js"></script>
<img src="http://example.com/image.jpg">

<!-- ✅ 좋은 예: HTTPS 또는 프로토콜 상대 경로 -->
<script src="https://example.com/script.js"></script>
<script src="//example.com/script.js"></script>
```

## 🔗 관련 용어

- **[[HTTPS]]**: HTTP + SSL/TLS (암호화된 HTTP)
- **[[TLS]]**: Transport Layer Security (SSL의 후속 프로토콜)
- **[[Public Key Infrastructure (PKI)]]**: 인증서 기반 보안 체계
- **[[Certificate Pinning]]**: 특정 인증서만 신뢰하도록 고정
- **[[HSTS]]**: HTTP Strict Transport Security (강제 HTTPS)
- **[[CSR]]**: Certificate Signing Request (인증서 발급 요청)

## 📝 정리

### 핵심 3줄
1. **인증서 = 웹사이트 신분증**: CA가 발급한 신뢰할 수 있는 신원 증명
2. **3가지 역할**: 신원 확인, 데이터 암호화, 변조 방지
3. **Let's Encrypt**: 무료, 90일, 자동 갱신 (대부분의 서비스에 충분)
