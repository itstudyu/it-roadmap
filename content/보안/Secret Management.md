# Secret Management (시크릿 관리)

## 📝 정의

Secret Management는 **열쇠 노릇을 하는 값을 코드 밖에서 다루는 일**이다.

시크릿은 비밀번호만이 아니다. OWASP 는 API 키, 데이터베이스 접속 정보, 접근 권한, SSH 키, 인증서를 한 묶음으로 부르고, 이것들을 소스 코드나 설정 파일에 박아 두는 것을 가장 흔한 출발점으로 꼽는다.

### 이름
Secret :: 남이 알면 안 되는 값
Management :: 만들고 바꾸고 끊기
= 붙여 읽으면 "남이 알면 안 되는 값을 만들고 바꾸고 끊기". 숨기는 일이 아니라 수명을 다루는 일이다

### 비유
아파트 관리사무소의 열쇠함. 각자 주머니에 넣고 다니는 대신 한 곳에 걸어 두고, 누가 가져갔는지 적고, 이사 나가면 걷어 온다.

### 예
설정 파일에 적어 둔 접속 비밀번호가 저장소에 그대로 올라가 있는 걸 한참 뒤에 발견하는 순간이다.

## 🖼️ 그림으로 보기

```도해
흐름: 열쇠 하나는 태어나서 어떻게 사라지나
만들기 :: 필요한 권한만 담아 새로 뽑는다
맡기기 :: 코드가 아니라 보관소에 넣는다
꺼내 쓰기 :: 쓸 때 꺼내 가고 꺼낸 기록이 남는다
바꾸기 :: 정해 둔 기간마다 새것으로 갈아 끼운다
@ 다시 만들기로 :: 새것이 돌면 옛것은 그날로 끊는다
= 값을 숨기는 일이 아니라 수명을 한 바퀴 돌리는 일이다
```

## ⚠️ 해결하는 문제

```도해
대조: 접속 키를 어디에 두느냐로 무엇이 달라지나
코드 안에 적으면 || 밖에 맡기면
바꾸기 :: 고쳐서 다시 올린다 || 그 자리만 바꾼다
누가 봤나 :: 알 길이 없다 || 꺼낸 기록이 남는다
새어 나가면 :: 지난 이력에 남는다 || 즉시 끊는다
= 값 자체를 숨기는 일이 아니라, 바꾸고 끊을 수 있게 밖에 두는 일이다
```

소스 코드에 적어 둔 키는 지운다고 사라지지 않는다. 저장소의 지난 이력에 그대로 남고, 복제본을 받아 간 사람의 노트북에도 남는다. 새어 나간 키에 할 수 있는 일은 "그 값을 못 쓰게 끊는 것" 하나뿐인데, 코드에 박아 둔 값은 그걸 하려면 코드를 고쳐 다시 올려야 한다.

Twelve-Factor App 이 이 문제를 한 문장짜리 시험으로 만들어 두었다 — 지금 이 저장소를 그대로 공개해도 자격 증명이 새어 나가지 않는가. 2025년판 OWASP Top 10 도 같은 자리를 짚는다. 2위로 올라온 보안 설정 오류 항목이 "코드·설정 파일·파이프라인에 정적인 키나 시크릿을 박아 넣는 대신 신원 연합이나 짧게 사는 자격 증명을 쓰라" 고 적는다.

## ⚙️ 작동 원리

보관소에 넣는 것만으로는 절반이다. OWASP 는 시크릿에도 최소 권한을 그대로 적용하라고 적는다 — 엔지니어가 보관소의 모든 시크릿을 다 볼 수 있으면 보관소를 둔 뜻이 없다.

나머지 절반이 수명이다. 값이 오래 살수록 새어 나갔을 때 쓸 수 있는 기간도 길어지므로, 정해 둔 주기마다 갈아 끼워 훔쳐 간 값이 짧게만 통하게 만든다. 더 나아간 방식이 동적 시크릿이다. 프로그램이 뜰 때마다 그 판에서만 쓸 값을 새로 받아 가고, 다시 뜨면 앞의 것은 이미 만료다.

기록도 함께 남긴다. 누가 어떤 용도와 역할로 요청했는지, 승인됐는지, 언제 누가 실제로 썼는지가 남아야 사고가 났을 때 무엇을 끊어야 하는지가 나온다.

## 💡 실제 사례

- **파드 밖에 두기** — 쿠버네티스는 시크릿을 파드 명세와 따로 두어 이미지 안에 값이 들어가지 않게 한다.
- **주기적 교체** — 정해 둔 기간마다 새 키를 발급하고 옛 키를 끊는다. 훔쳐 간 값의 유효 기간이 그만큼 짧아진다.
- **환경 변수로 넘기기** — 설정 파일 대신 환경 변수에 담으면 실수로 저장소에 올라갈 일이 줄어든다.

## 🚫 흔한 오해

- **깃 이력에서 지웠으니 괜찮다** — 복제본을 받아 간 사람에게는 그대로 남아 있다. 새어 나간 키는 지우는 게 아니라 못 쓰게 끊는 것이다.
- **쿠버네티스 시크릿에 넣으면 암호화된다** — 기본값은 base64 로 적어 둔 것뿐이고 저장소에는 암호화 없이 들어간다. 저장 시 암호화를 따로 켜야 한다.
- **짧게 사는 값으로 다 바꾸는 쪽이 항상 낫다** — 그런 값을 못 받는 서비스가 있고, 암호화 키처럼 한 판보다 오래 살아야 하는 값도 있다. 그런 자리는 그대로 두고 대신 꺼낼 수 있는 사람을 좁힌다.

## 📝 정리

**"코드 밖에 두고 언제든 끊을 수 있게 만든 그 열쇠 관리법"** 이라고 읽으면 된다. 값을 숨기는 일이 아니라 만들고 갈아 끼우고 끊는 수명을 다루는 일이고, 꺼낸 기록이 없으면 사고가 났을 때 무엇을 끊어야 할지도 모른다. 지금 이 저장소를 그대로 공개해도 새어 나갈 것이 없는지가 가장 빠른 시험이다.

## 🧒 열 살에게

우리 집 열쇠를 아무 데나 놓고 다니면 잃어버렸을 때 손쓸 방법이 없지? 그래서 열쇠는 한 곳에 걸어 두고, 누가 가져갔는지 적고, 가끔 자물쇠를 통째로 갈아 끼우는 거야. 그러면 열쇠 하나가 사라져도 그날로 못 쓰게 만들 수 있어.
