# XML (eXtensible Markup Language)

## 📝 정의

XML은 **여는 태그와 닫는 태그로 데이터의 구조를 적는 형식**이다.

값 하나하나에 이름표를 붙이고 그 이름표를 겹쳐서 계층을 만든다. 태그 이름을 쓰는 쪽이 직접 정하기 때문에 어떤 종류의 데이터든 담을 수 있다.

### 비유
서류철 안의 서류철. 겉장에 이름이 적혀 있고 열면 또 이름이 적힌 것들이 들어 있다.

## 🖼️ 그림으로 보기

```도해
흐름: XML 한 덩어리를 프로그램이 어떻게 읽나
문서 :: <user><name>Alice</name></user>
파서 :: 태그를 하나씩 열고 닫으며 훑는다
트리 :: 겹친 태그를 부모와 자식 관계로 세운다
접근 :: user 아래 name 을 찾아 값을 꺼낸다
= 글자 나열을 계층 구조로 세워서 원하는 자리를 찾아간다
```

## ⚠️ 해결하는 문제

```도해
대조: 프로그램끼리 데이터를 주고받으려면 어떻게 하나
형식 없이 || XML 로
읽는 방법 :: 서로 약속해야 함 || 파서가 처리
구조 :: 평평하다 || 계층을 담는다
검증 :: 직접 짠다 || 스키마로 확인
= 값과 그 값의 이름을 함께 실어 보내는 형식이다
```

쉼표로 나눈 텍스트 같은 형식은 값만 있고 그 값이 무엇인지는 없다. 열 순서를 양쪽이 미리 맞춰야 하고, 중간에 항목이 하나 늘면 읽는 쪽이 전부 어긋난다.

XML은 값마다 이름표를 붙여 보낸다. 순서가 바뀌어도 이름으로 찾으면 되고, 겹쳐 쓸 수 있어서 목록 안의 목록 같은 구조도 그대로 담긴다.

## 📊 비교

| | XML | JSON |
|---|---|---|
| 표기 | 여는 태그와 닫는 태그 | 중괄호와 대괄호 |
| 같은 데이터 | 길다 | 짧다 |
| 속성 | 태그 안에 따로 둘 수 있다 | 값과 구분이 없다 |
| 형식 검증 | 스키마 규격이 있다 | 별도 도구를 쓴다 |
| 주로 쓰는 곳 | 문서, 설정, 옛 시스템 연동 | 웹 API |

## 💡 실제 사례

- **RSS** — 블로그 글 목록을 정해진 태그 구조로 내보내면 읽기 앱이 그대로 받아 온다.
- **문서 파일 내부** — 오피스 문서 파일을 풀어보면 안에 XML 문서들이 들어 있다.
- **기업 시스템 연동** — 오래전에 만들어진 시스템은 요청과 응답을 XML로 주고받는 경우가 많다.

## 🚫 흔한 오해

- **XML은 HTML의 다른 버전이다** — 태그를 쓴다는 점만 같다. HTML은 태그 이름이 정해져 있고 화면에 어떻게 그릴지를 적지만, XML은 태그 이름을 직접 정해서 무슨 데이터인지를 적는다.
- **XML은 낡아서 이제 안 쓴다** — 웹 API에서는 거의 JSON으로 넘어갔지만 문서 형식과 기업 시스템 연동에서는 여전히 쓰인다.
- **태그 이름만 맞으면 읽힌다** — 닫는 태그가 빠지거나 겹치는 순서가 어긋나면 파서가 아예 거부한다. 대소문자도 가린다.

## 🚨 주의사항

- **최상위 태그는 하나여야 한다.** 문서 전체를 감싸는 태그가 둘이면 읽히지 않는다.
- **본문에 `<` 나 `&` 를 그대로 넣지 않는다.** 태그 시작으로 읽혀서 문서가 깨지므로 정해진 표기로 바꿔 써야 한다.

## 📝 정리

XML은 값마다 이름표를 붙이고 겹쳐서 계층을 만드는 데이터 형식이다. 같은 내용을 담을 때 JSON보다 길지만, 구조를 규격으로 정해두고 검증하는 일에는 여전히 쓰인다.

## ❓ 이해했는지

- 쉼표로 나눈 텍스트 대신 XML을 쓰면 항목이 하나 늘었을 때 무엇이 달라지나?
- 닫는 태그를 하나 빠뜨리면 어떤 일이 일어나나?
- 같은 태그를 쓰는데도 HTML 과 XML 이 하는 일이 다른 이유는?
