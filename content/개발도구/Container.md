# Container (컨테이너)

## 📝 정의

Container는 **하나의 프로세스를 격리해서 돌리는 방식**이다.

컴퓨터는 하나인데 그 안에서 도는 프로그램이 서로를 못 보게 만든다. 각자 자기만의 파일 시스템과 네트워크를 가진 것처럼 보이지만 실제로는 같은 커널을 함께 쓴다.

### 비유
한 건물 안의 원룸. 벽으로 나뉘어 서로의 방을 볼 수 없지만 수도와 전기는 건물 것을 함께 쓴다. 집을 통째로 새로 짓는 것보다 훨씬 싸다.

## 🖼️ 그림으로 보기

```도해
층: 컨테이너와 가상 머신은 무엇이 다른가
하드웨어 :: 실제 장비. 둘 다 여기서 시작
호스트 OS :: 컨테이너는 이 커널을 함께 쓴다
컨테이너 :: 프로세스만 격리. 수백 MB, 수 초
가상 머신 :: 게스트 OS 를 통째로. 수 GB, 수 분
= 운영체제를 새로 띄우느냐 마느냐가 무게 차이의 전부다
```

## ⚠️ 해결하는 문제

```도해
대조: 한 서버에서 앱 여러 개를 돌리면 어떻게 되나
격리 없이 || 컨테이너로
라이브러리 :: 버전이 충돌한다 || 각자 갖는다
하나가 폭주 :: 전부 느려진다 || 자원 상한을 건다
설정 실수 :: 옆 앱도 영향 || 그 안에서 끝
= 서버를 나누지 않고도 앱끼리 남남으로 만들 수 있게 된다
```

한 서버에 앱을 여러 개 올리면 서로 간섭한다. A는 파이썬 3.9가 필요하고 B는 3.12가 필요한데 한 대에 하나만 깔린다. 하나가 메모리를 다 먹으면 나머지도 죽는다.

가상 머신으로 나누면 해결되지만 무겁다. 앱 하나 돌리려고 운영체제를 통째로 띄우는 셈이다. 컨테이너는 커널을 공유하면서 필요한 만큼만 격리해서 그 비용을 없앤다.

## ⚙️ 작동 원리

리눅스 커널의 두 기능이 뼈대다.

| 기능 | 하는 일 |
|---|---|
| 네임스페이스 | 프로세스, 네트워크, 파일 시스템을 각자 것처럼 보이게 한다 |
| cgroups | CPU와 메모리를 얼마나 쓸지 상한을 건다 |

네임스페이스가 "보이지 않게" 하고 cgroups가 "가져가지 못하게" 한다. 이 둘이 격리의 전부이고, Docker 같은 도구는 이걸 쓰기 편하게 감싼 것이다.

## 💡 실제 사례

- **마이크로서비스** 서비스마다 컨테이너 하나씩 띄워 독립 배포한다.
- **일회용 작업** 배치 작업을 컨테이너로 띄우고 끝나면 지운다.
- **개발 환경** 프로젝트마다 다른 언어 버전을 한 노트북에서 충돌 없이 쓴다.

## 🚫 흔한 오해

- **컨테이너는 가상 머신의 가벼운 버전이다** — 목적은 비슷하지만 구조가 다르다. 가상 머신은 하드웨어를 흉내 내고 컨테이너는 프로세스를 가린다.
- **컨테이너 안에서는 무엇을 해도 안전하다** — 커널을 공유하므로 커널 취약점은 그대로 통한다. 격리 수준이 가상 머신보다 낮다.
- **컨테이너 하나에 프로세스 여러 개를 넣어도 된다** — 넣을 수는 있지만 하나가 죽었을 때 관리가 어려워진다. 하나만 두는 것이 기본이다.

## 🚨 주의사항

- **자원 상한을 반드시 건다.** 안 걸면 컨테이너 하나가 호스트 메모리를 전부 먹고 나머지를 다 죽인다.
- **루트로 돌리지 않는다.** 컨테이너 안의 루트가 호스트 커널에 닿을 수 있는 경로가 남는다.

## 📝 정리

Container는 커널을 공유하면서 프로세스를 격리하는 방식이다. 네임스페이스로 가리고 cgroups로 상한을 걸며, 가상 머신보다 가벼운 대신 격리 수준은 낮다.

## ❓ 이해했는지

- 자원 상한을 걸지 않으면 무슨 일이 생기나?
- 보안이 매우 중요한 격리에 컨테이너만으로 부족한 이유는?
