# Shell (셸)

## 📝 정의

Shell은 **내가 친 명령을 알아듣고 실행하는 프로그램**이다.

POSIX 규격은 셸을 딱 한 문장으로 정의한다 — "셸은 명령 언어 해석기다." Bash 매뉴얼은 한 걸음 더 나가서, 유닉스 셸은 명령 해석기이면서 **프로그래밍 언어**라고 적는다. 그래서 명령을 모아 적어둔 파일이 그대로 새 명령이 되고, `/bin` 에 있는 시스템 명령과 같은 자격을 얻는다.

### 비유
통역사. 내가 한 말을 알아듣고 안쪽 사람에게 시키는데, 통역사를 바꾸면 쓸 수 있는 표현도 달라진다.

## 🖼️ 그림으로 보기

```도해
흐름: 한 줄을 치면 셸이 그것을 어떻게 실행하나
셸 :: 받은 줄을 낱말과 연산자로 쪼갠다
셸 :: `*` 나 `$HOME` 같은 것을 펼친다
셸 :: `>` 로 입출력을 옮겨 붙인다
셸 :: 내장 명령이면 스스로, 아니면 파일을 띄운다
프로그램 :: 실제 일을 하고 끝난다
< 셸 :: 종료 상태를 받아 다음 판단에 쓴다
= 셸은 한 줄을 낱말로 쪼개고 펼친 뒤에야 프로그램을 띄운다
```

## ⚠️ 해결하는 문제

```도해
대조: 셸이 없으면 명령을 어떻게 조합하나
셸 없이 || 셸로
명령 조합 :: 직접 코드로 짠다 || `|` 로 이어붙임
같은 일 또 하기 :: 매번 새로 짠다 || 파일로 두고 부름
`cd` 같은 것 :: 프로그램으론 안 됨 || 셸이 직접 한다
= 해석하는 자리가 있어서 명령 몇 개가 새 명령 하나가 된다
```

유틸리티 하나하나는 자기 일만 안다. `grep` 은 거르고 `wc` 는 센다. 이 둘을 이어 붙이려면 누군가 앞의 출력을 뒤의 입력으로 넘겨줘야 하는데, 그것을 코드로 짜야 한다면 아무도 하지 않는다.

셸이 그 자리를 맡는다. Bash 매뉴얼이 셸의 프로그래밍 언어 기능이 "이 유틸리티들을 조합할 수 있게 한다" 고 적어둔 것이 이 말이다. 그리고 조합해 놓은 것을 파일에 적으면 그 파일이 새 명령이 된다. `cd` 나 `exec` 처럼 **셸 자신을 만지는 일**은 애초에 별도 프로그램으로 만들 수 없어서 셸이 직접 처리한다.

## 📊 비교: Shell vs Terminal

| | Terminal | Shell |
|---|---|---|
| 무엇인가 | 글자를 주고받는 창 | 명령 언어 해석기 |
| 하는 일 | 글자를 넘기고 그린다 | 쪼개고 펼치고 실행한다 |
| 예 | iTerm2, Windows Terminal | Bash, Zsh, PowerShell |
| 없으면 | 스크립트는 그대로 돈다 | 명령을 해석할 것이 없다 |

같은 창에서 셸만 갈아 끼울 수 있고, 같은 셸을 다른 창에서 띄울 수도 있다. 글꼴과 탭을 고르는 것은 창 쪽 일이고, 어떤 문법을 쓸 수 있는지는 셸 쪽 일이다.

## 💡 실제 사례

- **로그 걸러 세기** — `cat app.log | grep ERROR | wc -l` 의 세 프로그램은 서로를 모르지만, 셸이 이어 붙이면 한 도구가 된다.
- **배포 절차 파일로 두기** — 손으로 치던 명령을 파일 하나에 적어두면 그 파일이 시스템 명령과 같은 자격의 새 명령이 된다.
- **위치 옮기기** — `cd` 는 셸 자신의 현재 위치를 바꾸는 일이라 별도 프로그램으로는 만들 수 없고, 셸이 직접 처리한다.

## 🚫 흔한 오해

- **터미널과 셸은 같은 말이다** — 셸은 키보드로 들어오거나 파일에 적혀 있는 명령을 읽어 해석하는 프로그램이다. 그 글자를 화면에 그리고 키 입력을 받는 창은 따로 있고, 같은 창에서 셸만 바꿔 끼울 수 있다.
- **셸은 명령어 치는 것뿐이다** — 명령 해석기이면서 프로그래밍 언어다. 변수와 조건과 반복이 있고, 명령을 모아 적은 파일이 그대로 새 명령이 된다.
- **Bash 로 적었으면 어디서나 돈다** — Bash 는 POSIX 셸 규격을 따르려는 구현이면서 `ksh` · `csh` 에서 가져온 자기 기능도 갖고 있다. `#!/bin/sh` 로 적어놓고 그 기능을 쓰면 다른 셸에서 깨진다.

## 🚨 주의사항

- **어느 셸로 돌 것인지를 먼저 정한다.** POSIX 가 정한 공통 문법과 그 셸만의 확장이 따로 있다. `sh` 로 실행되는 파일에 Bash 확장을 쓰면 다른 시스템에서 그대로 깨진다.
- **명령 하나가 프로그램 하나라는 법이 없다.** `cd` `break` `continue` `exec` 는 셸이 스스로 처리하는 내장 명령이라 실행 파일이 아니다. 셸 밖에서 같은 이름을 찾아도 없다.

## 📝 정리

셸은 명령 언어 해석기다. 한 줄을 낱말로 쪼개고 `*` 나 `$HOME` 을 펼치고 입출력을 옮겨 붙인 다음에야 프로그램을 띄우고, 그 종료 상태를 받아 다음 판단에 쓴다. 창을 띄우는 것은 터미널이고 그 안에서 말을 알아듣는 것은 셸이라, 창을 바꿔도 문법은 그대로다.

## ❓ 이해했는지

- 창을 iTerm2 로 바꿨는데 쓰던 명령이 그대로 되는 까닭은 → 비교
- `cat a.log | grep ERROR` 의 두 프로그램이 서로를 모르는데도 이어 붙는 까닭은 → 해결하는 문제
- `bash` 로 잘 돌던 파일을 `sh` 로 돌렸더니 깨졌다. 무엇을 봐야 하나 → 주의사항
