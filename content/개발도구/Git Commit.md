# Git Commit (커밋)

## 📝 정의

Git Commit 은 **그 순간의 프로젝트 전체를 남긴 기록 하나**다.

다른 버전 관리 도구는 파일마다 무엇이 바뀌었는지를 시간순으로 쌓는다. Git 은 커밋할 때마다 모든 파일이 그때 어떤 모습이었는지를 찍어 두고, 안 바뀐 파일은 다시 저장하지 않고 앞서 저장해 둔 같은 파일을 가리키는 링크만 남긴다. 그래서 커밋 하나는 "바뀐 줄 목록" 이 아니라 "그때의 전체 모습" 이다.

### 비유
사진첩. 한 장 한 장이 그날 방 전체를 찍은 것이고, 어제와 달라진 물건만 적어둔 쪽지가 아니다.

### 예
GitHub 저장소에서 파일 목록 오른쪽에 붙어 있는 한 줄 설명과 날짜가 그 파일의 마지막 커밋이다.

## 🖼️ 그림으로 보기

```도해
대조: 커밋은 바뀐 줄을 담나 전체를 담나
변경으로 쌓기 |=| 스냅샷으로 쌓기
한 커밋에 든 것 :: 바뀐 줄 목록 || 그때의 전 파일
안 바뀐 파일 :: 적지 않는다 || 링크만 남긴다
예전 판 꺼내기 :: 변경을 되짚는다 || 그 하나를 펼친다
= 커밋 하나는 그 순간 프로젝트 전체를 남긴 기록이다
```

## ⚠️ 해결하는 문제

```도해
대조: 고친 것을 골라 담지 못하면 어떻게 되나
고친 대로 전부 || 골라 담고 커밋
한 커밋의 크기 :: 그날 고친 전부 || 한 가지 일만
나중에 되짚기 :: 뭐가 뭔지 모름 || 커밋 하나 = 한 일
급한 수정 :: 실험 코드도 같이 || 그것만 먼저
= 담는 자리를 따로 둔 덕에 커밋 하나가 한 가지 일로 남는다
```

파일을 고치면 작업 폴더는 바뀌지만 이력은 아직 아무것도 모른다. 고친 것이 곧바로 기록이 되는 구조라면, 급한 버그 하나를 고쳐 올리려 할 때 반쯤 짜다 만 실험 코드까지 같이 딸려 들어간다.

Git 은 그 사이에 **스테이징 영역**을 한 칸 둔다. `git add` 로 이번 커밋에 넣을 것만 골라 담고, `git commit` 은 담긴 것만 굳힌다. 그래서 한 번에 열 파일을 고쳤어도 커밋은 세 개로 나눌 수 있고, 커밋 하나가 한 가지 일로 남으면 나중에 그 커밋만 꺼내 보거나 그 커밋만 되돌릴 수 있다.

## ⚙️ 작동 원리

```도해
흐름: 파일을 고치면 커밋까지 어떤 상태를 거치나
작업 폴더 :: 고쳤다. 이력은 아직 이 파일을 모른다
add :: 지금 이 판을 스테이징에 담는다
또 고침 :: 담긴 판과 폴더의 판이 갈라진다
commit :: 담긴 판만 굳는다. 뒤에 고친 것은 안 들어간다
해시 :: 그 스냅샷에 40자 이름이 붙는다
= 커밋에 들어가는 것은 폴더의 지금이 아니라 담아둔 그때다
```

Git 이 보는 파일의 상태는 셋이다. **modified** 는 고쳤지만 아직 기록에 안 넣은 것, **staged** 는 다음 커밋에 넣기로 지금 판을 표시해 둔 것, **committed** 는 내 컴퓨터의 저장소에 안전히 들어간 것이다. `git add` 를 "이 파일을 프로젝트에 추가한다" 가 아니라 "정확히 이 내용을 다음 커밋에 담는다" 로 읽어야 이 구분이 맞아떨어진다.

굳어진 커밋에는 내용을 가지고 계산한 SHA-1 체크섬 40자가 이름으로 붙는다. Git 은 모든 것을 저장하기 전에 체크섬을 뜨고 그 값으로 부르기 때문에, 파일이나 폴더의 내용이 Git 모르게 바뀌는 일이 있을 수 없다. 이미 추적 중인 파일만 담을 거라면 `git commit -a` 가 `add` 를 대신 해준다.

## 💡 실제 사례

- **부분 커밋** — 한 폴더에서 버그 수정만 골라 담아 먼저 커밋하고, 실험 코드는 작업 폴더에 그대로 남겨 둔다.
- **커밋 메시지** — 커밋할 때는 무엇을 바꿨는지 짧게 적어야 한다. 몇 달 뒤 이력을 뒤지는 사람에게는 이 한 줄이 유일한 설명이다.
- **해시로 지목** — 커밋마다 붙는 40자 해시가 무엇이 바뀌었는지, 언제인지, 누가 했는지를 함께 가리켜서 "그 시점" 을 정확히 꺼내 올 수 있다.

## 🚫 흔한 오해

- **커밋은 바뀐 부분만 저장한다** — 커밋 하나가 그때의 전체 모습이다. 안 바뀐 파일을 두 번 저장하지는 않지만, 그건 앞서 저장한 같은 파일을 가리키는 링크로 대신하는 것이고 커밋이 담는 것은 여전히 전체다.
- **add 한 뒤에 또 고친 것도 커밋에 들어간다** — 들어가는 것은 `add` 를 돌린 그때의 판이다. 그 뒤에 같은 파일을 또 고쳤으면 `add` 를 다시 해야 한다.
- **커밋을 하려면 서버에 연결되어 있어야 한다** — 커밋은 내 컴퓨터의 저장소에 쌓인다. 비행기 안에서도 커밋은 되고, 남에게 보내는 것은 그다음 일이다.

## 📝 정리

커밋은 그 순간의 프로젝트 전체를 남긴 기록 하나다. 변경 목록이 아니라 스냅샷이라서 커밋 하나를 꺼내면 그때의 전체가 그대로 나온다. 스테이징을 한 칸 거치게 만든 이유는 고친 것 전부가 아니라 이번에 남길 것만 골라 담게 하려는 것이다.

## ❓ 이해했는지

- `add` 를 한 뒤에 같은 파일을 또 고쳤다. 커밋하면 어느 판이 들어가나 → 작동 원리
- 커밋 하나만 꺼내도 그때의 전체 모습이 나오는 이유는 → 그림
- 열 개 파일을 한 번에 고쳤는데 커밋을 세 개로 나눌 수 있는 이유는 → 해결하는 문제
