# CLI (Command Line Interface)

## 📝 정의

CLI는 **글자로 명령을 적어 컴퓨터를 시키는 방식**이다.

마우스로 버튼을 찾는 대신 무엇을 할지 한 줄로 적어 넣는다. 적어 넣은 것이라 파일로 저장해 다시 돌릴 수 있다.

### 이름
Command :: 시킬 일
Line :: 한 줄
Interface :: 주고받는 자리
= 붙여 읽으면 "시킬 일을 한 줄로 주고받는 자리". 손가락이 아니라 글자로 시킨다

### 비유
음식 주문. 메뉴판을 손가락으로 짚는 대신 이름을 말한다. 이름을 외워야 하지만 한 번에 여러 개를 시킬 수 있다.

### 예
설치 안내에 적힌 명령 한 줄을 복사해 검은 창에 붙여 넣고 엔터를 쳐 본 적이 있다면 그게 CLI다.

### 직접
윈도우면 `Win+R` 에 `cmd`, 맥이면 터미널을 열고 `dir` 또는 `ls` 를 쳐 보라. 지금 자리의 파일 목록이 글자로 나온다.

## 🖼️ 그림으로 보기

```도해
흐름: ls -la 를 치면 무엇이 오가나
사용자 :: 명령어를 친다
터미널 :: 받은 글자를 셸에 넘긴다
셸 :: 명령과 옵션으로 쪼갠다
운영체제 :: 파일 목록을 읽어준다
< 셸 :: 결과를 보기 좋게 다듬는다
< 터미널 :: 화면에 글자로 찍는다
= 터미널은 창일 뿐이고 명령을 해석하는 것은 셸이다
```

## ⚠️ 해결하는 문제

```도해
대조: 파일 100개 이름을 바꾸려면 어떻게 하나
GUI 로 || CLI 로
반복 작업 :: 100번 클릭 || 한 줄로 끝
남는 기록 :: 남지 않는다 || 명령이 남는다
원격 서버 :: 화면을 통째로 || 글자만 오간다
= 손으로 반복하던 것을 글로 적어두면 다음부터는 그 글이 대신 한다
```

버튼을 누르는 일은 한 번 하고 나면 아무것도 남지 않는다. 같은 일을 내일 또 하려면 똑같이 눌러야 하고, 어제 무엇을 눌렀는지는 기억에만 있다.

CLI는 그 작업을 문장으로 남긴다. 남은 문장은 파일에 모아두었다가 그대로 다시 돌릴 수 있고, 다른 사람에게 그대로 건넬 수도 있다. 원격 서버를 다룰 때 글자만 오가는 것도 여기서 나오는 이점이다.

## 🧱 구성

```도해
층: 명령 하나가 어디를 거쳐 실행되나
터미널 :: 글자를 띄우고 입력을 받는 창
셸 :: 명령을 해석하고 프로그램을 찾는다
프로그램 :: ls, git 같은 실제 실행 파일
커널 :: 파일과 장치에 실제로 손대는 자리
= 아래로 갈수록 실제 일이고 위로 갈수록 사람이 보는 것이다
```

## ⚙️ 작동 원리

명령 하나는 프로그램 하나다. 셸이 그 이름을 찾아 실행하고 결과를 화면에 넘긴다. 여기까지는 단순한데, 파이프를 쓰면 앞 명령의 결과가 뒤 명령의 입력이 된다.

```bash
cat app.log | grep ERROR | wc -l
```

로그를 읽어서, ERROR가 들어간 줄만 걸러서, 몇 줄인지 센다. 세 프로그램은 서로를 모르고 각자 글자를 받아 글자를 내놓을 뿐인데 이어붙이면 새 도구가 된다.

## 💡 실제 사례

- **버전 관리** — `git status` 로 바뀐 파일을 보고 `git commit` 으로 묶어 남긴다.
- **컨테이너 관리** — `docker ps` 로 도는 것을 보고 `docker logs` 로 그 안의 기록을 꺼낸다.
- **장애 확인** — `tail -f logs/app.log` 로 쌓이는 기록을 실시간으로 보고 `grep ERROR` 로 걸러낸다.

## 🚫 흔한 오해

- **CLI는 옛날 방식이라 GUI로 다 대체됐다** — 원격 서버는 지금도 대부분 글자만 오가는 통로로 관리한다. 화면을 통째로 보내는 것보다 가볍고 기록으로 남기기도 쉽다.
- **터미널과 셸은 같은 말이다** — 터미널은 글자를 띄우는 창이고, 명령을 해석하는 것은 그 안에서 도는 셸이다. 같은 터미널에서 셸만 바꿔 쓸 수 있다.
- **명령을 다 외워야 쓸 수 있다** — 실제로 손에 붙는 것은 열 개 남짓이고 나머지는 필요할 때 찾는다. 자주 쓰는 조합은 파일로 적어두고 이름만 기억한다.

## 🚨 주의사항

- **`rm` 에는 되돌리기가 없다.** 휴지통을 거치지 않고 바로 지운다. 지울 대상이 애매하면 먼저 `ls` 로 무엇이 걸리는지 본다.
- **`sudo` 는 확인 없이 실행한다.** 관리자 권한으로 도는 명령은 막아주는 것이 없어서 오타 하나가 그대로 반영된다.

## 📝 정리

**"손가락 대신 글자로 시키는 그 방식"** 이라고 읽으면 된다. 적어 넣은 것이라 저장하고 다시 돌리고 남에게 건넬 수 있고, 그것이 버튼과 갈리는 자리다. 창을 띄우는 것은 터미널이고 명령을 해석하는 것은 셸이다.

## 🧒 열 살에게

식당에서 메뉴판을 손가락으로 짚는 대신 먹고 싶은 걸 입으로 말할 때가 있지? 컴퓨터한테도 그렇게 하고 싶은 일을 글자로 적어서 시킬 수 있어. 짚은 손가락은 그냥 사라지지만 적어 둔 글자는 남아서, 내일 똑같은 걸 시킬 때 그대로 다시 쓰면 돼.

## ❓ 이해했는지

- 같은 작업을 매일 반복해야 할 때 버튼보다 명령줄이 나은 이유는 → 해결하는 문제
- 같은 터미널을 쓰는데 명령 해석 방식이 달라질 수 있는 이유는 → 흔한 오해
- `cat app.log | grep ERROR | wc -l` 의 세 프로그램이 서로를 모르는데도 이어 붙는 까닭은 → 작동 원리
