# Dockerfile (도커파일)

## 📝 정의

Dockerfile은 **이미지를 만드는 순서를 적은 텍스트 파일**이다.

첫 줄은 `FROM` 으로 시작해 바탕 이미지를 고르고, 그 아래 적은 명령이 위에서 아래로 차례로 실행된다. 그렇게 나온 결과물이 [[Docker Image]] 다.

### 비유
요리 조리법. 재료와 순서를 적어두면 누가 그대로 따라 해도 같은 음식이 나온다.

### 예
코드 한 줄만 고치고 다시 빌드했는데 라이브러리 설치가 처음부터 다시 도는 그 답답한 순간이다.

## 🖼️ 그림으로 보기

```도해
흐름: Dockerfile 에 적은 한 줄은 이미지에서 무엇이 되나
FROM :: 바탕 이미지를 고른다. 여기서부터 쌓는다
RUN :: 라이브러리를 깐다 — 층 하나가 생긴다
COPY :: 소스 코드를 넣는다 — 층 하나가 더
CMD :: 뜰 때 실행할 명령을 적어둔다
이미지 :: 그 층들을 순서대로 쌓아 굳힌 것
= 위에서 아래로 한 줄씩 실행되고, 한 줄이 한 층이 된다
```

## ⚠️ 해결하는 문제

```도해
대조: 실행 환경을 사람이 맞추면 무엇이 달라지나
설치 문서로 || Dockerfile 로
새 팀원 :: 문서 보고 따라함 || 명령 한 줄
빠뜨린 단계 :: 나중에 터진다 || 빌드가 실패한다
같은 환경인가 :: 아무도 못 보장 || 같은 이미지가 나옴
= 설치 순서를 읽는 글이 아니라 실행되는 파일로 적어 둔 것이다
```

환경 설정을 문서로 적어두면 두 가지가 어긋난다. 사람이 한 단계를 빠뜨려도 아무 표시가 없어서 나중에 엉뚱한 데서 터지고, 문서가 낡아도 아무도 모른다.

Dockerfile은 같은 내용을 **실행되는 파일**로 적는다. 빠뜨린 단계가 있으면 빌드가 그 자리에서 실패하고, 성공한 빌드는 언제 어디서 돌려도 같은 이미지를 낸다.

## ⚙️ 작동 원리

```도해
흐름: 한 줄만 고쳤는데 왜 그 아래가 전부 다시 빌드되나
빌드 :: 위에서부터 한 줄씩 캐시와 견준다
같은 줄 :: 지난번 층을 그대로 쓴다
바뀐 줄 :: 여기서 캐시가 끊긴다
그 아래 :: 내용이 같아도 다시 실행된다
= 캐시는 위에서 아래로만 이어진다. 자주 바뀌는 줄을 아래에 두는 이유다
```

캐시가 위에서 아래로만 이어지기 때문에 **줄 순서가 빌드 시간을 정한다**. 잘 안 바뀌는 것을 위에, 자주 바뀌는 것을 아래에 두는 것이 규칙이다.

가장 흔한 자리가 의존성 설치와 소스 복사의 순서다. 의존성 목록을 먼저 복사해서 설치하고 그다음에 소스를 복사하면, 코드만 고친 빌드에서는 설치 줄이 캐시에 걸려 통째로 건너뛴다. 순서를 뒤집으면 한 글자만 고쳐도 설치가 처음부터 다시 돈다. 설치가 빌드 시간의 열에 아홉을 먹는 프로젝트라면 줄 순서 하나로 빌드가 열 배 차이 난다.

## 💡 실제 사례

- **CI 빌드 단축** — 의존성 설치 줄을 소스 복사보다 위에 둬서, 코드만 바뀐 커밋에서는 설치를 건너뛴다.
- **명령 묶기** — 내려받기와 설치와 삭제를 한 `RUN` 에 묶는다. 다음 줄에서 지우면 그 파일이 아래 층에 그대로 남는다.
- **빌드에 안 쓰는 파일 빼기** — `.dockerignore` 에 적어두면 그 파일들이 빌드로 넘어가지 않는다.

## 🚫 흔한 오해

- **RUN 을 하나로 묶을수록 좋다** — 층은 줄지만 캐시도 같이 줄어든다. 묶어둔 것 중 하나만 바뀌어도 그 묶음 전체가 다시 돌아간다.
- **어차피 같은 이미지가 나오니 줄 순서는 상관없다** — 결과는 같아도 빌드 시간이 달라진다. 캐시가 끊긴 줄부터 아래는 내용이 같아도 다시 실행된다.
- **Dockerfile을 고치면 처음부터 다시 빌드된다** — 고친 줄 위쪽은 캐시를 그대로 쓴다. 다시 도는 것은 그 줄과 그 아래뿐이다.

## 🚨 주의사항

- **자주 바뀌는 줄을 위에 두지 않는다.** 소스 복사가 의존성 설치보다 위에 있으면 커밋마다 설치가 처음부터 다시 돈다.
- **지울 파일은 만든 줄에서 같이 지운다.** 다음 줄에서 지우면 아래 층에 그대로 남아 이미지 크기에 계속 잡힌다.

## 📝 정리

Dockerfile은 이미지를 만드는 순서를 적은 파일이다. 한 줄이 한 층이 되고 그 층이 캐시되기 때문에, 무엇을 위에 두고 무엇을 아래에 두느냐가 빌드 시간을 정한다.

## ❓ 이해했는지

- 소스 코드 한 줄만 고쳤는데 의존성 설치가 매번 다시 도는 이유는 → 주의사항
- 명령을 한 `RUN` 으로 묶으면 층은 줄어드는데 무엇을 잃나 → 흔한 오해
- Dockerfile 한 줄은 이미지에서 무엇이 되나 → 그림
