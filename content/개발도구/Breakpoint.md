# Breakpoint (중단점)

## 📝 정의

Breakpoint는 **실행이 이 줄에 닿으면 멈추라고 남기는 표시**다.

Visual Studio 문서는 "디버거 실행을 멈추고 싶은 자리마다 찍는 것" 이라고 적고, 곧이어 **실행되는 줄에만 찍을 수 있다**고 못 박는다. 멈추면 그 줄이 실행되기 **전**이라, 그 시점 변수 값과 호출 스택을 그대로 볼 수 있다. Python 에서는 `pdb` 의 `b 줄번호` 로 걸거나 코드에 `breakpoint()` 를 적어 같은 일을 한다.

### 비유
고속도로 검문소. 지나가는 차를 세워 안을 들여다보는 자리이고, 조건을 걸어두면 그 조건에 맞는 차만 세운다.

## 🖼️ 그림으로 보기

```도해
흐름: 중단점을 찍어두면 실행 중에 무슨 일이 일어나나
개발자 :: 멈추고 싶은 줄에 표시를 남긴다
디버거 :: 그 줄을 중단점 목록에 올려둔다
실행 :: 그 줄에 닿으면 조건을 따진다
멈춤 :: 조건이 참일 때만 그 자리에서 선다
개발자 :: 값과 호출 스택을 보고 다시 풀어준다
= 여기서 멈춰 달라는 표시다. 조건을 달면 그때만 멈춘다
```

## ⚠️ 해결하는 문제

```도해
대조: 중단점이 없으면 무엇을 하게 되나
중단점 없이 || 중단점으로
멈출 자리 :: 정할 수 없다 || 고른 줄에서 선다
반복 1000회 :: 다 넘겨야 한다 || 조건 걸어 한 번
코드 :: 출력문을 심는다 || 손대지 않는다
= 코드를 고치지 않고 "여기서 세워라" 를 표시해 두는 것이다
```

멈출 자리를 못 정하면 디버거는 그냥 프로그램을 처음부터 끝까지 돌리는 도구다. 값을 보려면 출력문을 심어야 하고, 심는 순간 그 파일은 고쳐진 파일이 된다.

중단점은 그 지시를 **소스 밖에** 둔다. 편집기 여백을 누르면 디버거가 그 줄을 기억하고, 실행이 거기 닿을 때 세운다. 지우는 것도 한 번 더 누르는 것이라 찍고 지우는 값이 싸다. 그래서 여러 곳에 흩뿌려 두고 목록 창에서 켜고 끄는 식으로 쓴다.

## ⚙️ 작동 원리

표시만 남기면 그 줄에 닿을 때마다 멈춘다. 반복문 안이면 수천 번 멈춘다. 그래서 실전에서 값을 하는 것은 **언제 멈출지까지 같이 적는 것**이다.

Visual Studio 는 세 가지로 조인다.

- **조건식** — 식이 참일 때만 선다. `testInt == 4` 처럼 적는다. 값이 바뀔 때만 세우는 모드도 있다.
- **히트 횟수** — 정한 회차에 선다. 1000번째 반복부터 이상해진다면 `F5` 를 999번 누르는 대신 이걸 쓴다.
- **필터** — 특정 기계·프로세스·스레드에서만 선다. `ThreadId` 나 `ProcessName` 으로 좁힌다.

Python 도 같은 자리가 있다. `b 12, x > 100` 으로 조건을 함께 걸고, `condition 번호 식` 으로 이미 걸린 중단점의 조건을 나중에 바꾼다. `tbreak` 는 한 번 맞으면 스스로 사라진다.

조건 문법이 틀렸을 때가 재미있다. 문서는 **조건이 유효하고 거짓으로 평가될 때만 건너뛴다**고 적는다. 즉 오타가 난 조건은 건너뛰기는커녕 그대로 멈춘다. 조건을 걸었는데 계속 멈춘다면 버그가 아니라 조건식을 볼 차례다.

## 📊 비교: 중단점의 종류

| 종류 | 언제 멈추나 | 쓰는 자리 |
|---|---|---|
| 줄 중단점 | 그 줄에 닿을 때마다 | 실행되는 줄 |
| 조건부 | 식이 참일 때만 | 같은 줄에 조건을 얹어 |
| 히트 횟수 | 정한 회차에 | 반복문 안 |
| 함수 중단점 | 그 이름의 함수가 불릴 때 | 위치를 몰라도 이름만으로 |
| 데이터 중단점 | 그 값이 바뀔 때 | 누가 고쳤는지 모를 때 |
| 임시 중단점 | 딱 한 번 | 맞으면 스스로 사라진다 |
| 추적점 | 멈추지 않고 기록만 남긴다 | 세우면 안 되는 자리 |

## 💡 실제 사례

- **1000번째 반복만 보기** — 반복문 안 중단점에 히트 횟수를 걸면 그 회차에서만 선다. `F5` 를 999번 누르지 않아도 된다.
- **특정 값일 때만 멈추기** — `testInt == 4` 같은 조건식을 얹어 그 값이 됐을 때만 세운다. 나머지 호출은 그대로 지나간다.
- **위치 모르는 함수 잡기** — 이름만 알고 어느 파일인지 모를 때 함수 중단점으로 그 함수가 불리는 순간을 잡는다.

## 🚫 흔한 오해

- **중단점을 찍으면 코드가 바뀐다** — 소스는 그대로다. 디버거가 그 줄을 목록에 들고 있다가 실행이 닿을 때 세운다. 그래서 찍고 지우기가 여백 한 번 누르는 값이다.
- **아무 줄에나 찍을 수 있다** — 실행되는 줄에만 걸린다. 메서드 서명, 네임스페이스나 클래스 선언, 대입도 접근자도 없는 변수 선언에는 못 찍는다.
- **많이 찍을수록 빨리 찾는다** — 반복문 안 중단점 하나가 수천 번 멈춘다. 실제로 시간을 줄이는 것은 개수가 아니라 조건과 히트 횟수다.

## 📝 정리

중단점은 실행이 여기 닿으면 멈추라고 실행되는 줄에 남기는 표시다. 소스는 그대로 두고 디버거가 그 줄을 기억하는 방식이라, 찍고 지우는 값이 싸서 흩뿌려 두고 골라 쓴다. 쓸모를 가르는 것은 개수가 아니라 조건과 히트 횟수여서, 언제 멈출지까지 적어두면 반복문 안에서도 한 번만 선다.

## ❓ 이해했는지

- 반복문 안 중단점이 수천 번 멈출 때 무엇을 걸어 한 번만 세우나 → 작동 원리
- 함수 이름만 알고 어느 파일에 있는지 모를 때 어디에 찍나 → 비교
- 변수 선언 줄에 찍었는데 표시가 안 걸리는 까닭은 → 흔한 오해
