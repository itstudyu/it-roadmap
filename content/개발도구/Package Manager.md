# Package Manager (패키지 매니저)

## 📝 정의

패키지 매니저는 **남이 만든 코드를 받아다 놓아 주는** 도구다.

무엇을 쓸지는 사람이 파일에 적고, 그것을 어디서 어떤 버전으로 받아 어디에 풀어 놓을지는 도구가 정한다. `npm` 은 Node.js 의 표준 패키지 매니저이고, Go 는 `go` 명령이 그 일을 한다.

### 비유
장 보기 대행. 목록만 적어 주면 알아서 사다 정해진 칸에 넣어 두고, 목록에 없는 건 치운다.

## 🖼️ 그림으로 보기

```도해
흐름: npm install 한 줄이 무슨 일을 하나
목록 :: package.json 에 적힌 의존성을 읽는다
버전 :: semver 규칙에 맞는 버전을 고른다
받기 :: 그 버전의 코드를 내려받는다
자리 :: node_modules 폴더에 풀어 놓는다
< 내 코드 :: import 한 줄로 그것을 불러 쓴다
= 이름과 버전만 적어 두면 받아 오는 일은 도구가 한다
```

## ⚠️ 해결하는 문제

```도해
대조: 라이브러리를 손으로 챙기면 무엇이 힘든가
손으로 || 패키지 매니저로
받기 :: 찾아가 내려받는다 || 이름만 적는다
딸린 것 :: 직접 쫓아다닌다 || 같이 받아 온다
버전 올리기 :: 파일을 갈아 끼운다 || 명령 한 줄
= 무엇을 쓰는지만 적어 두면 나머지는 도구가 맡는다
```

라이브러리 하나를 쓰려면 그 라이브러리가 기대는 다른 라이브러리도 있어야 한다. 손으로 챙기면 그 사슬을 사람이 끝까지 쫓아야 하고, 팀원마다 받은 버전이 달라지면 "내 컴퓨터에서는 되는데" 가 시작된다.

패키지 매니저는 **쓰는 것을 파일에 적어 두게** 해서 이 둘을 한꺼번에 없앤다. `package.json` 이 있는 프로젝트에서 `npm install` 을 치면 그 프로젝트에 필요한 것이 전부 `node_modules` 에 깔린다. 폴더가 없으면 만들어서 깐다.

## ⚙️ 작동 원리

```도해
층: 패키지 매니저는 무엇을 어디에 적고 어디에 두나
선언 :: package.json 이나 go.mod 에 이름과 버전을 적는다
해석 :: 그 조건을 만족하는 버전을 고른다
내려받기 :: 레지스트리나 모듈 캐시로 실물을 가져온다
설치 자리 :: node_modules 처럼 정해진 폴더에 풀어 놓는다
= 적어 두는 자리와 받아 두는 자리가 따로 있다
```

`npm install <이름>` 은 받기만 하는 게 아니라 그 이름을 `package.json` 의 `dependencies` 에 적어 둔다(npm 5 부터). 나중에 그 파일만 있으면 같은 구성을 다시 만들 수 있다는 뜻이다.

Go 는 자리를 더 뚜렷하게 나눈다. `go get` 은 인자를 특정 모듈 버전으로 풀어내고, `go.mod` 를 그 버전으로 고치고, 소스는 프로젝트가 아니라 **모듈 캐시**로 내려받는다. `go mod tidy` 는 빌드에 필요한데 빠진 모듈을 채우고, 아무 데서도 안 쓰는 모듈은 걷어낸다.

## 📊 비교: npm 과 Go 모듈

| | npm (Node.js) | Go |
|---|---|---|
| 적는 파일 | `package.json` | `go.mod` |
| 받는 명령 | `npm install` | `go get` |
| 받아 두는 곳 | `node_modules` 폴더 | 모듈 캐시 |
| 버전 콕 집기 | `npm install 이름@1.2.3` | `go get 주소@v1.2.3` |

## 💡 실제 사례

- **남의 프로젝트 받아 돌리기** — 소스만 받으면 라이브러리는 없다. `npm install` 한 줄이 `package.json` 을 읽어 필요한 것을 전부 깔아 준다.
- **개발용과 배포용 나누기** — 테스트 라이브러리처럼 개발할 때만 쓰는 것은 `devDependencies` 로, 실제 서비스에 실리는 것은 `dependencies` 로 둔다.
- **긴 명령에 이름 붙이기** — `package.json` 의 `scripts` 에 적어 두고 `npm run dev` 로 부른다. 매번 옵션을 외워 치지 않아도 된다.

## 🚫 흔한 오해

- **패키지 매니저가 코드를 만들어 준다** — 아니다. 남이 만들어 올려 둔 것을 받아다 정해진 자리에 풀어 놓을 뿐이다. 무엇을 쓸지 고르는 건 사람이다.
- **한 번 설치하면 버전은 그대로다** — 버전을 범위로 적어 두면 `npm update` 가 그 범위를 만족하는 더 높은 버전을 찾아 올린다. 그대로 두고 싶으면 `이름@1.2.3` 처럼 콕 집어 적는다.
- **설치한 코드는 내 프로젝트 폴더 안에 들어온다** — 도구마다 다르다. npm 은 `node_modules` 에 풀지만 Go 는 모듈 캐시로 받아 두고 프로젝트에는 이름과 버전만 남긴다.

## 📝 정리

패키지 매니저는 쓸 코드의 이름과 버전만 적어 두면 그것과 그것이 기대는 것까지 받아다 정해진 자리에 놓아 주는 도구다. 선언하는 파일과 받아 두는 자리가 나뉘어 있어서, 파일 하나만 있으면 같은 구성을 어디서든 다시 만들 수 있다. 버전을 범위로 적을지 콕 집을지가 "언제 올라가느냐"를 정한다.
