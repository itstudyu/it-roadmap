# Docker Volume (도커 볼륨)

## 📝 정의

Docker Volume은 **컨테이너가 지워져도 남는 데이터 저장 칸**이다.

컨테이너 안에 쓴 파일은 그 컨테이너만의 쓰기 층에 쌓이고, 컨테이너를 지우면 쓰기 층도 함께 없어진다. 볼륨은 그 층 밖에 도커가 따로 만들어 관리하는 칸이라 컨테이너의 수명과 상관없이 남는다.

### 이름
Docker :: 상자를 싣는 도구
Volume :: 담기는 칸
= 붙여 읽으면 "상자 밖에 따로 둔 담는 칸". 상자를 버려도 이 칸은 남는다

### 비유
세탁기 옆 빨래 바구니. 세탁기를 새것으로 바꿔도 바구니에 담아둔 옷은 그 자리에 그대로 있다.

### 예
컨테이너를 지웠다 다시 띄웠는데 어제 만든 계정이 그대로 남아 있으면 그 데이터는 볼륨에 있던 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 컨테이너를 새로 띄워도 데이터가 남는 이유는 무엇인가
컨테이너 :: 밖에 있는 볼륨을 자기 폴더처럼 붙인다
쓰기 :: 그 폴더에 쓴 파일은 볼륨에 쌓인다
삭제 :: 컨테이너를 지운다. 쓰기 층도 함께 사라진다
볼륨 :: 컨테이너 밖에 있어서 그대로 남는다
@ 새 컨테이너 :: 같은 볼륨을 붙이고 이어서 쓴다
= 지워지는 것과 남는 것을 나눠 둔 칸이 볼륨이다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터를 컨테이너 안에 두면 어떻게 되나
컨테이너 안에 || 볼륨에
버전 올리기 :: 데이터가 날아간다 || 그대로 남는다
백업 :: 어디를 뜰지 모름 || 그 칸만 뜬다
컨테이너 둘 :: 각자 따로 쓴다 || 한 칸을 같이 쓴다
= 컨테이너는 언제든 지워진다고 보고, 남아야 할 것은 밖에 둔다
```

컨테이너는 갈아 끼우는 것을 전제로 쓴다. 새 버전을 배포하면 옛 컨테이너를 지우고 새로 띄우는데, 그때 안에 쌓아둔 데이터가 같이 사라진다. 죽은 컨테이너를 지우고 새로 만들어 되살리는 자리에서는, 되살아난 쪽이 깨끗한 상태에서 시작한다.

볼륨은 **남아야 할 것만 컨테이너 밖으로 빼낸다**. 컨테이너는 계속 버리고 새로 만들면서 데이터는 이어 쓸 수 있게 되고, 볼륨 하나를 여러 컨테이너에 동시에 붙일 수도 있다.

## ⚙️ 작동 원리

```도해
흐름: 볼륨을 붙인 컨테이너가 파일을 쓰면 그것이 어디로 가나
띄울 때 :: 볼륨 이름과 붙일 경로를 준다. 없는 이름이면 도커가 만든다
붙이기 :: 컨테이너 안 그 경로에 볼륨을 겹쳐 놓는다
그 아래 :: 그 경로 아래에 쓴 것은 쓰기 층을 안 거치고 볼륨으로 간다
그 밖 :: 다른 경로에 쓴 것은 컨테이너의 쓰기 층에 쌓인다
지울 때 :: 컨테이너를 지우면 쓰기 층만 사라진다
= 같은 컨테이너 안이라도 붙인 경로 아래와 그 밖은 사는 곳이 다르다
```

도커는 볼륨마다 그것을 붙이고 있는 컨테이너 수를 센다. 마지막 컨테이너가 지워져도 그 수가 0 이 될 뿐 볼륨은 그대로 남는데, 안에 든 것이 지워도 되는 캐시인지 지우면 끝인 DB 파일인지를 도커가 알 수 없어서다. 그 판단은 사람에게 남겨 둔다.

그래서 새 컨테이너를 띄울 때 같은 볼륨 이름만 대면 이어 쓴다. 볼륨은 이름으로 찾는 칸이고, 컨테이너는 그 이름을 자기 경로에 붙였다 떼는 쪽이다.

## 📊 비교: 볼륨 · 바인드 마운트 · tmpfs

| | **볼륨** | **바인드 마운트** | **tmpfs** |
|---|---|---|---|
| 어디에 두나 | 도커가 관리하는 칸 | 호스트의 특정 경로 | 호스트 메모리 |
| 컨테이너를 지우면 | 남는다 | 남는다 | 사라진다 |
| 언제 쓰나 | 남아야 할 데이터 | 호스트 파일을 그대로 보여줄 때 | 디스크에 안 남겨야 할 것 |

바인드 마운트는 호스트의 디렉터리 구조와 운영체제에 매이는 반면, 볼륨은 도커가 통째로 관리한다. 그래서 도커 문서는 데이터를 남길 때 볼륨을 먼저 권한다 — 백업과 옮기기가 더 쉽고, 여러 컨테이너가 나눠 쓰기에도 더 안전하고, 리눅스 컨테이너와 윈도우 컨테이너에서 똑같이 쓴다.

## 💡 실제 사례

- **데이터베이스 컨테이너** — DB 파일을 볼륨에 두면 컨테이너를 새 버전으로 갈아도 데이터가 그대로 남는다.
- **올린 파일 공유** — 사용자가 올린 파일을 볼륨에 쌓아두고, 컨테이너를 몇 개 띄우든 같은 칸을 보게 한다.
- **백업과 이전** — 뜰 대상이 볼륨 하나로 정해지니, 데이터 백업을 이미지 배포와 따로 다룰 수 있다.

## 🚫 흔한 오해

- **컨테이너를 지우면 볼륨도 같이 지워진다** — 안 지워진다. 쓰는 컨테이너가 하나도 없어도 볼륨은 도커에 그대로 남아 있다.
- **데이터는 무조건 볼륨에 넣는 게 맞다** — 호스트에서 고친 파일이 컨테이너에 바로 보여야 하는 개발 중에는 바인드 마운트가 맞다. 볼륨은 호스트의 특정 경로를 겨누는 장치가 아니다.
- **볼륨은 호스트 폴더를 붙이는 것과 같은 것이다** — 붙여 쓰는 모양은 비슷해도 관리 주체가 다르다. 볼륨은 도커가 만들고 관리해서 호스트의 폴더 구조나 운영체제에 안 매인다.

## 🚨 주의사항

- **안 쓰는 볼륨은 저절로 없어지지 않는다.** 컨테이너를 다 지워도 볼륨은 남아서 디스크를 계속 차지한다. 쓰지 않는 것은 따로 정리해야 한다.
- **붙일 자리에 원래 파일이 있으면 어느 쪽이 보이는지 갈린다.** 빈 볼륨을 붙이면 그 자리의 파일이 볼륨으로 복사되고, 내용이 있는 볼륨을 붙이면 원래 파일이 가려진다.

## 📝 정리

**"상자를 버려도 남는 그 바깥 칸"** 이라고 읽으면 된다. 컨테이너를 언제든 버릴 수 있는 것으로 다루려면 남아야 할 데이터를 이 칸으로 빼야 한다.

## 🧒 열 살에게

세탁기가 고장 나서 새것으로 바꿔도 옆에 둔 빨래 바구니 속 옷은 그대로 있지? 컴퓨터도 상자 안에 넣어 둔 건 상자를 갈아 끼울 때 같이 없어지니까, 남겨야 할 건 일부러 바깥 바구니에 담아 둬. 그래서 낡은 상자를 버리고 새것을 놓아도 어제 넣어 둔 게 그 자리에 그대로 있어.
