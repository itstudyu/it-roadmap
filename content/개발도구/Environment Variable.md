# 환경 변수 (Environment Variable)

## 📝 정의

환경 변수는 **코드 밖에서 넣어주는 설정값**이다.

데이터베이스 주소나 API 키처럼 개발 환경과 운영 환경에서 달라지는 값이 있다. 이걸 코드에 그대로 적으면 환경마다 코드가 갈라진다. 밖으로 빼두면 같은 코드가 어디서든 돈다.

### 비유
영화 배우의 분장실. 배우는 같은 사람인데 의상과 분장만 바꿔서 다른 배역이 된다.

## 🖼️ 그림으로 보기

```도해
흐름: 같은 코드가 환경마다 다르게 도는 이유는 무엇인가
설정 파일 :: `.env` 에 KEY=VALUE 로 적어둔다
로더 :: 앱이 뜰 때 그 파일을 읽는다
프로세스 :: 읽은 값이 환경 변수로 올라간다
코드 :: `process.env.DATABASE_URL` 로 꺼내 쓴다
앱 :: 그 값으로 접속하고 동작을 정한다
= 코드는 그대로 두고 바깥 값만 갈아끼운다
```

## ⚠️ 해결하는 문제

```도해
대조: 설정값을 코드에 그대로 적으면 어떻게 되나
코드에 적으면 || 환경 변수로
비밀번호 :: 저장소에 남음 || 코드에 없음
환경 변경 :: 코드를 고침 || 값만 바꿈
배포 :: 환경마다 빌드 || 하나로 배포
= 코드와 설정을 떼어놓으면 같은 빌드를 어디에나 올릴 수 있다
```

비밀번호나 API 키를 코드에 적으면 저장소에 그대로 들어간다. 공개 저장소에 실수로 올라가는 것도 문제지만, 지운 뒤에도 커밋 기록에 남아 있다는 점이 더 성가시다.

설정이 코드 안에 있으면 환경마다 다른 코드를 배포해야 한다는 문제도 생긴다. 개발용으로 빌드한 것과 운영용으로 빌드한 것이 달라지면, 개발에서 되던 것이 운영에서 안 되는 이유를 찾기 어려워진다.

## ⚙️ 작동 원리

`.env` 파일에 `KEY=VALUE` 형식으로 적어두고, 앱이 시작할 때 라이브러리가 읽어 프로세스의 환경 변수로 올린다. 코드는 그 이름으로 값을 꺼낸다.

```
DATABASE_URL=postgresql://localhost:5432/myapp_dev
API_TIMEOUT=30000
DEBUG=true
```

이 파일은 `.gitignore` 에 넣어 버전 관리에서 뺀다. 대신 값을 지운 `.env.example` 을 같이 두어 어떤 변수가 필요한지 알린다.

```도해
층: 같은 이름이 여러 곳에 있으면 어느 값이 이기나
직접 넘긴 값 :: 실행할 때 넘긴 것. 가장 세다
.env 파일 :: 파일에서 읽어 올린 값
코드 기본값 :: 위에 아무것도 없을 때만 쓰인다
= 위가 아래를 덮는다. 그래서 운영에서는 위에서 주입한다
```

운영 환경에서는 파일 대신 시크릿 관리 서비스에서 값을 넣어주는 경우가 많다. AWS Secrets Manager, Azure Key Vault, HashiCorp Vault 같은 것들이 암호화와 접근 제어를 함께 맡는다.

## 💡 실제 사례

- **환경별 데이터베이스** — 개발은 로컬 주소, 운영은 운영 주소를 넣어 같은 코드가 양쪽에서 돈다.
- **컨테이너 실행** — 이미지는 하나만 만들고 실행할 때 값을 넘겨 개발용과 운영용을 나눈다.
- **클라우드 함수** — 대상 테이블 이름이나 알림 채널을 환경 변수로 두고 코드는 건드리지 않는다.

## 🚫 흔한 오해

- **환경 변수에 넣으면 암호화된다** — 평문 그대로다. 저장소에 안 올라갈 뿐이고, 서버에 들어온 사람은 그대로 읽을 수 있다.
- **`.env` 는 각자 알아서 만들면 된다** — 어떤 변수가 필요한지 적어둔 `.env.example` 이 없으면 새로 온 사람은 앱을 띄우지 못한다.
- **값을 빠뜨리면 에러가 나서 바로 안다** — 기본값이 조용히 쓰이면 로컬용 설정으로 운영이 돌아간다. 시작할 때 필수 변수를 확인해야 드러난다.

## 🚨 주의사항

- **`.gitignore` 를 먼저 걸어둔다.** 한 번 커밋된 키는 나중에 파일을 지워도 기록에 남는다.
- **기본값을 안전한 쪽에 둔다.** 디버그 모드나 개발용 키가 기본값이면 설정을 빠뜨린 순간 그게 운영에서 돈다.

## 📝 정리

환경 변수는 코드를 고치지 않고 바깥에서 설정값을 넣어주는 방법이다. 같은 빌드를 어느 환경에나 올릴 수 있게 해주지만 값 자체를 숨겨주지는 않으므로, 민감한 값은 시크릿 관리가 따로 따라와야 한다.

## ❓ 이해했는지

- API 키를 환경 변수로 옮겼는데도 여전히 조심해야 하는 이유는 → 흔한 오해
