# REPL (Read-Eval-Print Loop)

## 📝 정의

REPL은 **한 줄을 치면 그 자리에서 실행해 답을 보여주는 창**이다.

Node.js 문서는 이 창이 하는 일을 그대로 적어 둔다 — "사용자 입력을 한 줄씩 받아, 평가 함수에 따라 평가하고, 결과를 내보낸다." 입력과 출력이 터미널일 수도 있고 다른 통로에 물려 있을 수도 있지만, 한 줄마다 이 세 가지가 돌고 다시 기다린다는 것은 같다.

### 이름
Read :: 친 줄을 읽고
Eval :: 그 자리에서 실행하고
Print :: 결과를 보여주고
Loop :: 다시 기다린다
= 붙여 읽으면 "읽고-실행하고-보여주고-되돌아가기". 이름 네 글자가 그대로 한 바퀴다

### 비유
계산기. 숫자를 누르고 = 를 누르면 곧바로 답이 뜨고, 그 답을 이어서 다음 계산에 쓸 수 있다.

### 예
파일 하나 만들지 않고 터미널에 `node` 만 쳐서 한 줄씩 시험해 보던 그 `>` 창이다.

### 직접
터미널에 `node` 를 치고 `1 + 1` 을 입력해 보라. 파일도 저장도 없이 곧바로 `2` 가 뜬다.

## 🖼️ 그림으로 보기

```도해
흐름: 한 줄을 치면 REPL 안에서 무엇이 도나
읽기 :: 사람이 친 한 줄을 받는다
실행 :: 그 줄을 그 자리에서 평가한다
보이기 :: 나온 값을 화면에 찍는다
@ 다시 읽기로 :: 방금 만든 값을 그대로 둔 채 다음 줄을 기다린다
= 이름 네 글자가 그대로 한 바퀴다. 파일을 거치지 않고 한 줄이 곧 답이 된다
```

## ⚠️ 해결하는 문제

```도해
대조: 한 줄을 시험하려고 파일부터 만들면 무엇이 번거로운가
파일로 || 대화 창으로
한 줄 시험 :: 만들고 저장하고 실행 || 치면 바로 답
앞서 만든 값 :: 매번 처음부터 다시 || 그대로 남아 있다
고쳐 보기 :: 편집기와 터미널 왕복 || 한 자리에서 이어감
= 시험 한 번에 드는 동작이 셋에서 하나로 줄어든다
```

"이 함수가 무엇을 돌려주지" 를 확인하려고 파일을 만들고 저장하고 실행하면, 알고 싶은 것 한 줄에 딸린 동작이 셋이다. 게다가 그 실행이 끝나면 만들어 둔 값도 같이 사라져서, 다음 한 줄을 시험하려면 앞의 준비를 처음부터 다시 하게 된다.

REPL 은 그 준비를 창이 대신 들고 있게 한다. Node.js 의 기본 REPL 에서 블록이나 함수 안이 아닌 자리에 선언한 변수는 전역 범위에 놓이고, IRB 는 마지막으로 평가한 식의 결과를 `=>` 뒤에 그대로 보여준다. **앞줄이 남아 있으니 다음 줄은 이어서 물으면 된다.**

## ⚙️ 작동 원리

평가하는 부분은 갈아끼울 수 있는 자리다. Node.js 문서는 기본 평가 함수가 자바스크립트 식을 평가하고 내장 모듈에 접근하게 해 준다고 적으면서, 창을 만들 때 다른 평가 함수를 넘기면 그 동작을 대신할 수 있다고 밝힌다. 창의 뼈대는 "한 줄 받아 → 평가해 → 내보낸다" 이고, 가운데만 바꿔 끼우는 셈이다.

한 줄로 안 끝나는 입력을 위한 손잡이도 마침표 명령으로 들어 있다. `.editor` 로 편집기 모드에 들어가면 여러 줄을 쓴 뒤 한꺼번에 평가되고, `.save` 와 `.load` 는 지금 세션을 파일로 내보내거나 파일을 세션 안으로 들인다. `.break` 는 쓰다 만 여러 줄 입력을 버리고, `.clear` 는 창의 문맥을 빈 것으로 되돌린다.

친 줄 자체는 창을 닫아도 남는다. Node.js 는 기본적으로 홈 디렉터리의 `.node_repl_history` 에 입력을 적어 다음 세션에서 다시 꺼내 쓸 수 있게 하고, 남길 줄 수는 `NODE_REPL_HISTORY_SIZE` 로 정하며 기본값은 1000줄이다.

## 💡 실제 사례

- **문서 읽다 말고 확인하기** — 처음 보는 함수 한 줄을 그대로 쳐서 무엇이 돌아오는지 눈으로 본다.
- **여러 줄 한꺼번에 넣기** — `.editor` 로 편집기 모드에 들어가 함수 하나를 통째로 정의하고 빠져나온다.
- **어제 치던 줄 이어 쓰기** — Node.js 는 입력을 홈 디렉터리의 `.node_repl_history` 에 남겨 두어서 새 창에서도 지난 줄이 그대로 남아 있다.

## 🚫 흔한 오해

- **계산기 정도만 되는 장난감이다** — 그 언어의 실행 환경 전체가 그대로 붙어 있다. Node.js 의 기본 평가 함수는 내장 모듈에 그대로 접근하게 해 준다.
- **여기서 됐으면 파일에서도 똑같이 돈다** — 범위가 다르다. 창에서 블록이나 함수 밖에 선언한 변수는 전역 범위에 놓이는데, 파일로 옮기면 그 전제가 사라진다.
- **친 것이 어딘가에 저장되니 그대로 코드가 된다** — 남는 것은 "무엇을 쳤는지" 하는 입력 이력뿐이다. 값과 문맥은 창을 닫으면 사라진다.

## 📝 정리

**"치면 바로 답이 오는 그 창"** 이라고 읽으면 된다. 파일을 만들지 않아도 한 줄이 곧 실행이고, 앞줄에서 만든 값이 남아 있으니 다음 줄을 이어서 물을 수 있다. 대신 그 편의는 창이 잡아 준 문맥에서 나온 것이라, 여기서 됐다고 파일에서도 같으리라 믿으면 범위에서 갈린다.

## 🧒 열 살에게

계산기에 숫자를 누르면 곧바로 답이 뜨고, 그 답을 이어서 또 계산할 수 있지? 글자로 시키는 일도 그렇게 한 줄 쓸 때마다 바로 답을 보여 주는 창이 있어. 공책을 따로 만들어 적어 두지 않아도 되니까 궁금한 걸 그냥 물어보면 돼.
