# Git Tag (깃 태그)

## 📝 정의

Git Tag 는 **특정 커밋에 붙여 두는 움직이지 않는 이름표**다.

태그는 `refs/tags/` 아래에 놓이는 이름이다. 브랜치의 이름표는 개발이 진행되면 앞으로 옮겨지지만, 태그는 커밋 명령이 건드리지 않는다. 그래서 `v1.0`, `v2.0` 처럼 내보낸 판을 표시하는 데 쓴다.

### 비유
책에 붙여 둔 색인 딱지. 뒤를 계속 읽어도 딱지는 처음 붙인 쪽에 그대로 남는다.

### 예
오픈소스 저장소의 릴리스 목록에 v1.4.0 처럼 붙어 있는 그 이름들이 태그다.

## 🖼️ 그림으로 보기

```도해
대조: 브랜치 이름과 태그는 무엇이 다른가
브랜치 이름 |=| 태그
커밋하면 :: 끝으로 따라간다 || 그 자리에 남는다
가리키는 뜻 :: 지금 만드는 중 || 그때 내보낸 판
이 이름으로 :: 이어서 커밋한다 || 그때를 꺼내 본다
push 할 때 :: 같이 올라간다 || 따로 밀어야 간다
= 브랜치는 따라 움직이는 이름이고, 태그는 한 커밋에 박아 둔 이름이다
```

## ⚠️ 해결하는 문제

```도해
대조: 태그가 없으면 지난 판을 어떻게 찾나
태그 없이 || 태그로
지난 판 지목 :: 커밋 해시를 왼다 || v1.4.0 이라 부른다
되돌리기 :: 어느 커밋인지 뒤진다 || 그 이름을 꺼낸다
릴리스 :: 무엇이 기준인지 모름 || 여기에 붙는다
= 지난 판에 이름이 없으면, 되돌아갈 자리에도 이름이 없다
```

커밋 해시는 사람이 외우거나 주고받을 수 있는 이름이 아니다. "지난주에 내보낸 그거" 를 다시 꺼내려면 로그를 뒤져서 어느 커밋이었는지 추리해야 하고, 그 추리는 급할 때 틀린다.

태그는 그 커밋에 **사람이 부를 수 있는 이름**을 박아 둔다. 이름이 안 움직이니 한 달 뒤에 불러도 같은 커밋이 나온다. GitHub 의 릴리스도 이 태그를 바탕으로 만들어진다 — 태그가 그 판의 기준점이다.

## ⚙️ 작동 원리

태그는 두 가지다. 만드는 방법이 다르고, 남는 것도 다르다.

| | 경량 태그 | 주석 태그 |
|---|---|---|
| 만드는 법 | `git tag v1.0` | `-a` · `-s` · `-u` 를 붙인다 |
| 저장 형태 | 객체를 가리키는 이름뿐 | 저장소 안의 독립된 객체 |
| 같이 남는 것 | 없다 | 만든 날짜 · 만든 사람 · 메시지, 서명도 가능 |
| 쓰는 자리 | 개인용 · 임시 표시 | 내보내는 판 |

문서가 용도를 못 박아 두었다. **주석 태그는 릴리스용, 경량 태그는 개인용이거나 임시 표시용이다.** 그래서 `git describe` 처럼 이름으로 커밋을 부르는 명령은 기본으로 경량 태그를 **무시한다.** 방금 붙인 태그가 안 잡히면 대개 `-a` 를 빼먹은 것이다.

## 💡 실제 사례

- **릴리스 만들기** — GitHub 의 릴리스는 태그를 바탕으로 만들어진다. 태그를 먼저 찍고, 릴리스는 나중에 만들어도 된다.
- **지난 판 열어 보기** — 태그를 체크아웃하면 그때의 파일들이 그대로 나온다. 고쳐야 하면 그 태그에서 브랜치를 새로 딴다.
- **판마다 이름 남기기** — `v1.0`, `v2.0` 처럼 내보내는 시점마다 이름을 박아 둔다. 커밋이 수천 개로 늘어도 되돌아갈 자리는 태그 개수만큼이다.

## 🚫 흔한 오해

- **커밋을 push 하면 태그도 같이 올라간다** — 아니다. `git push` 는 기본으로 태그를 원격에 보내지 않는다. 만든 뒤 따로 밀어야 동료가 본다.
- **태그는 브랜치의 다른 이름이다** — 브랜치 이름표는 커밋할 때마다 앞으로 옮겨진다. 태그는 커밋 명령에 따라 움직이지 않는 것이 존재 이유다.
- **태그는 나중에 옮기면 된다** — Git 은 사용자 모르게 태그를 바꾸지 않는다. `-f` 를 주지 않으면 그 이름은 아직 없어야 하고, 남이 이미 받아 간 이름을 옮기면 그쪽이 보는 판과 어긋난다.

## 🚨 주의사항

- **push 는 태그를 따라 보내지 않는다** — 태그를 만든 뒤 원격으로 따로 밀어야 한다. `--follow-tags` 는 그 push 로 올라가는 커밋에 걸린 **주석** 태그만 따라 보낸다.
- **덮어쓰기는 기본이 아니다** — `-f` 없이는 이미 있는 이름으로 다시 만들 수 없다. 막아 둔 이유가 있으니 이름을 옮기기보다 새 이름을 쓴다.
- **태그를 체크아웃하면 붙어 있는 브랜치가 없다** — `detached HEAD` 상태가 된다. 거기서 한 커밋은 어느 브랜치에도 남지 않으니, 이어서 작업할 참이면 브랜치를 먼저 딴다.

## 📝 정리

태그는 한 커밋에 박아 두는 이름이다. 브랜치 이름표가 개발이 진행되며 앞으로 옮겨지는 것과 달리 태그는 커밋해도 그 자리에 남아서, "그때 내보낸 판" 을 언제든 같은 이름으로 꺼낼 수 있게 한다. 내보내는 판에는 주석 태그를 쓰고, 만든 뒤 원격으로 따로 밀어 준다.
