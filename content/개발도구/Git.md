# Git (형상 관리 시스템)

## 📝 정의

Git은 **코드가 바뀐 이력을 시점마다 기록해두는 도구**다.

파일 이름 뒤에 final, real, v2를 붙여가며 관리하면 어느 것이 최신인지도, 무엇이 바뀌었는지도 알 수 없고 되돌릴 수도 없다. Git은 변경을 기록한 시점들을 따로 쌓아서 그 셋을 한꺼번에 해결한다.

### 비유
게임의 세이브 포인트. 어려운 구간 앞에서 저장해두고, 실패하면 그 지점부터 다시 한다.

## 🖼️ 그림으로 보기

```도해
흐름: 고친 파일이 원격 저장소까지 어떻게 가나
작업 공간 :: 파일을 고친다. 아직 기록은 없다
add :: 이번에 남길 변경만 골라 담는다
스테이징 :: 담아둔 것들이 기록을 기다린다
commit :: 담긴 것을 한 덩어리로 굳혀 기록한다
로컬 저장소 :: 이력이 내 컴퓨터 안에 쌓인다
< push :: 원격 저장소로 올려 공유하고 백업한다
= 고르는 자리와 기록하는 자리가 나뉘어 있어 일부만 남길 수 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 파일 이름으로 버전을 관리하면 어떻게 되나
이름으로 관리 || Git 으로
최신 판 :: 헷갈린다 || 하나로 정해짐
바뀐 내용 :: 열어서 비교 || 기록에 남음
되돌리기 :: 못 한다 || 그 시점으로
= 무엇이 언제 왜 바뀌었는지가 파일 밖에 따로 남는다
```

이름으로 관리하면 최신판을 고르는 일부터 사람 기억에 달린다. 무엇이 바뀌었는지 알려면 두 파일을 열어 눈으로 비교해야 하고, 잘못 지운 코드는 되돌릴 방법이 없다.

여럿이 같은 파일을 고칠 때는 더 나빠진다. 나중에 저장한 사람의 파일이 앞사람 작업을 통째로 덮는데, 덮였다는 사실조차 남지 않는다. Git은 그 상황을 충돌로 잡아내고 어느 쪽을 남길지 물어본다.

## ⚙️ 작동 원리

브랜치는 이력을 갈라놓는 장치다. main에서 가지를 하나 내서 거기서 실험하면 main 쪽은 그대로 남는다. 잘되면 합치고, 아니면 가지를 버린다.

```bash
git switch -c feature/search   # 가지를 만들고 그리로 옮긴다
git add .
git commit -m "검색 정확도 개선"

git switch main
git merge feature/search       # 다 됐으면 합친다
```

되돌리는 방법도 갈린다. `git reset`은 이력 자체를 되감고, `git revert`는 되돌리는 커밋을 새로 하나 쌓는다. 이미 공유한 이력에는 revert 쪽이 안전하다. 남들이 받아간 이력을 뒤에서 바꾸지 않기 때문이다.

## 📊 비교

| 항목 | Git | SVN |
|---|---|---|
| 이력이 있는 곳 | 각자 컴퓨터에 전부 | 서버에만 |
| 오프라인 작업 | 된다 | 안 된다 |
| 브랜치 | 흔하게 쓴다 | 부담이 크다 |

## 💡 실제 사례

- **버그가 들어온 지점 찾기** — 이력에서 언제부터 어긋났는지 짚고, 그 커밋만 되돌려 나머지 작업은 그대로 둔다.
- **동시 작업** — 두 사람이 각자 가지에서 다른 기능을 만들고 나중에 합친다. 서로의 작업을 덮어쓰지 않는다.
- **백업** — 원격 저장소에 올려두면 컴퓨터가 고장 나도 다른 컴퓨터에서 이력째로 이어서 한다.

## 🚫 흔한 오해

- **Git이랑 GitHub는 같은 것이다** — Git은 내 컴퓨터에서 도는 도구고, GitHub는 그 이력을 올려두는 서비스다. 계정 없이도 Git은 그대로 쓸 수 있다.
- **파일을 고치면 Git이 알아서 기록한다** — `git add`로 고르고 `git commit`으로 굳혀야 이력이 된다. 그전까지는 그냥 고쳐진 파일일 뿐이다.
- **커밋했으니 팀원도 볼 수 있다** — 커밋은 내 컴퓨터에만 쌓인다. `git push`로 올려야 다른 사람에게 간다.

## 🚨 주의사항

- **비밀 값을 커밋하지 않는다.** API 키나 `.env`는 나중에 지워도 이력에 남는다. `.gitignore`로 처음부터 빼둔다.
- **main에서 바로 작업하지 않는다.** 가지에서 작업하고 확인한 뒤 합치면 main은 언제든 돌아갈 수 있는 상태로 남는다.
- **커밋 메시지에 무엇을 바꿨는지 쓴다.** "수정"이라고만 적힌 커밋은 몇 달 뒤 이력을 뒤질 때 아무것도 알려주지 않는다.

## 📝 정리

Git은 코드가 바뀐 이력을 시점마다 기록해두는 도구다. 파일을 고치는 일과 이력으로 남기는 일이 나뉘어 있어서, 고친 것 중 무엇을 남기고 언제 내보낼지 직접 고른다. 가지를 나눠 작업하면 여러 사람이 같은 코드를 동시에 고쳐도 서로를 덮어쓰지 않는다.
