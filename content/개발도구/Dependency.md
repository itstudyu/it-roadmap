# Dependency (의존성)

## 📝 정의

의존성은 **내 코드가 돌아가려면 있어야 하는 남의 코드**다.

이름 그대로 "기대고 있다"는 뜻이다. 무엇에 기대는지는 사람이 `package.json` 의 `dependencies` 나 Python 의 `install_requires` 같은 자리에 이름과 버전으로 적고, 그것을 실제로 받아다 놓는 일은 [[Package Manager]] 가 한다.

### 비유
결혼식에 친구 한 명을 부르면 배우자와 아이까지 같이 오는 것과 같다.

## 🖼️ 그림으로 보기

```도해
층: 하나를 적었는데 왜 수십 개가 깔리나
내 코드 :: 내가 쓴 것. 쓸 남의 코드 이름을 적는다
직접 의존성 :: 내가 적은 남의 코드. 여기까지가 내 목록이다
전이 의존성 :: 그것들이 기대는 남의 코드. 나는 적지 않았다
그 아래 :: 전이 의존성이 또 기대는 것. 끝까지 딸려 온다
= 내가 적은 것은 맨 위 한 줄, 없으면 안 돌아가는 것은 그 아래 전부다
```

## ⚠️ 해결하는 문제

```도해
대조: 남의 코드에 기대지 않으면 무엇이 달라지나
직접 다 만들기 || 의존성으로
만드는 시간 :: 몇 달이 든다 || 한 줄로 끝난다
숨은 버그 :: 내가 다 만난다 || 남이 다 겪었다
보안 수정 :: 내가 알아채야 한다 || 새 버전을 받는다
= 안 만들고 갖다 쓰는 대신, 남의 코드를 내 것처럼 책임진다
```

로그인, 날짜 계산, 이미지 변환 같은 것을 전부 직접 만들면 만드는 데만 몇 달이 들고, 남들이 이미 다 밟은 버그를 처음부터 다시 밟는다. 의존성은 그 시간을 사 오는 장치다 — 이름 한 줄을 적으면 검증된 코드가 내 프로젝트에서 돌아간다.

대신 값을 치른다. 갖다 쓴 코드는 남의 것이지만 **내 서비스에서 돌아가는 것은 내 것**이다. 거기서 나는 문제는 내 문제이고, 내가 적지도 않은 전이 의존성에서 난 문제도 내 문제다.

## ⚙️ 작동 원리

의존성은 버전 하나가 아니라 **범위**로 적는다. npm 문서는 `dependencies` 를 "패키지 이름을 버전 범위에 대응시키는 객체"라고 설명하고, `^버전` 은 "그 버전과 호환되는 것", `~버전` 은 "그 버전과 거의 같은 것" 이라는 뜻으로 쓴다. 그러니 파일에 적힌 것은 "이것" 이 아니라 "이 안이면 아무거나" 다.

내 의존성의 의존성은 내가 적지 않는다. Python 패키징 문서는 `install_requires` 에 하위 의존성(내 의존성의 의존성)까지 적는 것은 좋은 관행이 아니라고 못 박는다. 대신 설치할 때 도구가 따라간다 — npm 문서는 `npm install` 을 "패키지 하나와 그 패키지가 기대는 패키지들을 설치하는" 명령이라고 적는다.

그래서 적은 수와 깔린 수가 어긋난다. npm 문서에 실린 가장 작은 예에서도 `A` 는 `B`·`C` 둘만 적었는데 트리에는 `B`·`C`·`D` 셋이 선다. 둘을 적어 셋이 깔리는 이 배수가 사슬의 깊이만큼 겹쳐진다.

적는 자리는 둘로 나뉜다.

| 자리 | 무엇을 적나 | 남이 내 코드를 쓸 때 |
|---|---|---|
| `dependencies` | 실행에 꼭 있어야 하는 것 | 같이 받는다 |
| `devDependencies` | 테스트 도구, 빌드 도구 | 안 받는다 |

npm 문서는 테스트 도구나 트랜스파일러를 `dependencies` 에 넣지 말라고 하고, 그 이유로 "내 모듈을 받아 쓰는 사람은 내가 쓰는 테스트·문서 도구까지 받고 싶지 않을 것" 이라고 든다.

## 💡 실제 사례

- **프레임워크 하나 설치** — `package.json` 에는 한 줄이 늘지만 그것이 기대는 것까지 함께 깔려서, 목록에 없는 이름이 폴더에 잔뜩 생긴다.
- **개발용과 배포용 나누기** — 테스트 도구는 `devDependencies` 에 적어 둔다. 그래야 내 코드를 받아 쓰는 사람에게 내 테스트 도구까지 따라가지 않는다.
- **본 적도 없는 패키지의 취약점 통보** — 내가 적은 목록에는 없는 이름이다. 전이 의존성으로 깔려 있었기 때문에 내 프로젝트가 그 목록에 걸린다.

## 🚫 흔한 오해

- **내가 적은 것만 깔린다** — 아니다. npm 문서는 설치가 "그 패키지와 그것이 기대는 패키지들" 을 함께 받는다고 적는다. 내가 적지 않은 이름이 대부분이다.
- **직접 만드는 것보다 갖다 쓰는 게 항상 낫다** — 하나를 들이면 그것이 끌고 오는 것까지 전부 내 서비스에 실린다. 세 줄로 되는 일에 의존성을 하나 늘리는 값이 그 세 줄보다 클 수 있다.
- **버전을 적어 뒀으니 늘 같은 게 깔린다** — 적은 것은 대개 범위다. `^1.2.3` 은 "1.2.3 과 호환되는 것" 이라는 뜻이라, 조건을 만족하는 더 높은 버전이 나오면 그것이 깔린다.

## 🚨 주의사항

- **하나 늘리기 전에 무엇이 따라오는지 본다.** 늘어나는 것은 목록 한 줄이 아니라 그 아래 사슬 전체다.
- **내가 안 쓴 코드도 내 책임이다.** 전이 의존성에서 난 문제는 "내가 적지 않았다" 로 넘어가지 않는다. 서비스에 실려서 돌아가는 순간 내 코드와 같은 자리에 있다.
- **범위로 적었으면 언제 올라갈지는 내가 정하지 않는다.** 어느 버전이 실제로 깔렸는지 못 박으려면 [[Lock File]] 이 필요하다.

## 📝 정리

의존성은 내 코드가 남의 코드에 기대는 관계이고, 사람은 그중 직접 쓸 것만 이름과 범위로 적는다. 나머지는 전이 의존성으로 따라 들어와서 적은 수보다 깔린 수가 훨씬 많아진다. 갖다 쓰는 값은 공짜가 아니라 남의 코드를 내 서비스에 싣는 값이다.
