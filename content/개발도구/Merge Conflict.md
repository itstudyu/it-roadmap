# Merge Conflict (병합 충돌)

## 📝 정의

병합 충돌은 **git 이 한쪽을 못 골라 사람에게 넘긴 상태**다.

두 갈래가 같은 파일을 고쳐도 대개는 조용히 합쳐진다. 한쪽만 손댄 자리는 그 수정이 그대로 결과에 들어가고, 양쪽이 **같은 자리**를 고친 곳에서만 git 이 멈춘다. 거기서는 어느 쪽을 남길지 고를 근거가 git 에게 없다.

### 이름
Merge :: 둘을 하나로 합침
Conflict :: 서로 부딪힘
= 붙여 읽으면 "합치다가 부딪힌 자리". 부딪힌 몇 줄만 사람에게 넘어온다

### 비유
한 칸에 두 사람이 다른 답을 적어 낸 신청서. 접수원은 어느 쪽이 맞는지 모르니 본인에게 되묻는다.

### 예
파일 한가운데에 부등호 일곱 개가 줄줄이 박힌 낯선 줄이 나타나는 그 순간이다.

## 🖼️ 그림으로 보기

```도해
흐름: 같은 줄을 둘이 고치면 git 은 무엇을 하나
나 :: `git merge` 로 두 갈래를 합치라 한다
git :: 갈라진 지점과 양쪽 수정을 견준다
안 겹친 곳 :: 한쪽 수정을 그대로 넣는다
겹친 곳 :: 고를 근거가 없어 여기서 멈춘다
git :: 양쪽 내용을 충돌 표시로 감싸 남긴다
< 나 :: 남길 것을 골라 고치고 `git add` 로 알린다
= 합칠 수 있는 데까지 합치고, 못 고를 자리만 사람에게 넘긴다
```

## ⚠️ 해결하는 문제

```도해
대조: git 이 충돌을 안 알려주면 어떻게 되나
말없이 덮기 || 충돌로 멈추기
같은 줄 :: 나중 것이 덮는다 || 둘 다 남는다
덮인 코드 :: 흔적이 없다 || 표시로 드러난다
아는 시점 :: 배포 뒤에 || 합치는 그때
= 충돌은 고장이 아니라, 말없이 덮이는 것을 막으려고 멈춘 것이다
```

같은 파일을 각자 고쳐 덮어쓰는 방식에서는 나중에 저장한 사람이 앞사람 작업을 통째로 덮는다. 덮였다는 사실이 어디에도 남지 않으니, 없어진 코드는 한참 뒤에 "그 기능 어디 갔지" 로 발견된다.

git 은 두 갈래를 합칠 때 갈라진 지점까지 되짚어 셋을 나란히 본다. 한쪽만 고친 자리는 그 수정을 결과에 그대로 넣고, 양쪽이 같은 자리를 고친 곳만 표시로 감싸 남긴다. 충돌은 그 자리를 사람 눈앞에 끌어다 놓는 방식이다.

## ⚙️ 작동 원리

충돌한 파일은 세 판이 함께 보관된다 — 갈라진 지점의 것, 내 쪽(`HEAD`)의 것, 상대 쪽(`MERGE_HEAD`)의 것. 작업 중인 파일에는 겹친 자리가 이렇게 감싸여 나온다.

```text
<<<<<<< HEAD
내 쪽에서 고친 줄
=======
상대 쪽에서 고친 줄
>>>>>>> other-branch
```

`=======` 앞이 대개 내 쪽이고 뒤가 상대 쪽이다. 여기서 갈 길은 둘뿐이다.

- **해결한다** — 파일을 원하는 모양으로 고치고 `git add` 로 해결했다고 알린 뒤, `git commit` 이나 `git merge --continue` 로 마무리한다.
- **안 합친다** — `git merge --abort` 로 병합을 없던 일로 돌린다.

표시를 지우는 것과 해결을 알리는 것은 다른 일이다. `git add` 를 하지 않으면 병합은 끝나지 않은 상태로 남는다.

## 💡 실제 사례

- **같은 함수를 둘이 고쳤다** — 겹친 몇 줄만 표시로 남고, 같은 파일의 나머지 수정은 이미 합쳐진 채로 들어 있다.
- **한쪽이 파일을 지웠다** — 다른 쪽이 그 파일을 고쳤다면, 지울지 살릴지도 충돌로 잡힌다.
- **PR 에 충돌이 붙었다** — 단순한 줄 충돌은 GitHub 화면에서 고칠 수 있고, 그보다 복잡하면 내려받아 고친 뒤 다시 올려야 한다.

## 🚫 흔한 오해

- **충돌이 났으니 뭔가 고장 났다** — git 이 제대로 돈 결과다. 한쪽을 몰래 고를 수 없으니 판단을 사람에게 넘긴 것이고, 넘겨받은 자리는 겹친 몇 줄뿐이다.
- **충돌이 나면 그 파일에 한 수정이 다 날아간다** — 겹치지 않은 수정은 이미 합쳐져 파일에 들어 있다. 골라야 하는 것은 표시로 감싼 자리뿐이다.
- **표시만 지우면 해결된 것이다** — 표시를 지운 뒤 `git add` 로 해결을 알려야 병합이 이어진다. 그전까지는 합치는 중인 상태로 멈춰 있다.

## 📝 정리

**"합치다가 못 고르고 사람에게 넘겨진 그 자리"** 라고 읽으면 된다. 겹치지 않은 수정은 이미 합쳐져 있으니 표시로 감싼 곳만 골라 고치고 `git add` 로 알리면 병합이 이어진다. 그러니 충돌은 일이 잘못됐다는 신호가 아니라, 말없이 덮이는 일을 막았다는 신호다.

## 🧒 열 살에게

신청서 한 칸에 두 사람이 서로 다른 답을 적어 오면 접수하는 분이 마음대로 하나를 고를 수 없지? 그래서 나머지 칸은 다 받아 두고 그 한 칸만 어느 쪽이 맞는지 되물어. 되묻는 건 일이 잘못됐다는 뜻이 아니라, 한쪽 답이 소리 없이 지워지는 걸 막아 주는 거야.

## ❓ 이해했는지

- 충돌 표시를 다 지웠는데도 병합이 끝나지 않는다. 무엇이 남았나 → 작동 원리
- 충돌이 난 파일인데 내가 고친 다른 줄은 이미 합쳐져 있다. 왜인가 → 흔한 오해
- 충돌을 알려주지 않는 도구로 여럿이 일하면 무엇을 잃게 되나 → 해결하는 문제
