# Backend (백엔드)

## 📝 정의

Backend는 **화면 뒤 서버에서 데이터와 규칙을 다루는 쪽**이다.

사용자가 보는 것은 화면뿐이지만, 로그인이 맞는지 판단하고 값을 계산하고 데이터를 저장하는 일은 전부 서버에서 일어난다. 그 부분을 백엔드라고 부른다.

### 비유
식당의 주방. 손님은 홀에서 메뉴판을 보고 주문하지만, 재료를 확인하고 조리하고 재고를 줄이는 일은 안에서 일어난다.

## 🖼️ 그림으로 보기

```도해
흐름: 주문 버튼을 누르면 서버에서 무슨 일이 일어나나
사용자 :: 화면에서 주문 버튼을 누른다
프론트 :: 주문 내용을 서버로 보낸다
백엔드 :: 로그인한 사람이 맞는지 확인한다
백엔드 :: 재고를 보고 주문을 데이터베이스에 쓴다
< 프론트 :: 결과를 받아 "주문 완료"를 띄운다
= 판단하고 저장하는 일은 전부 서버 쪽에서 끝난다
```

## ⚠️ 해결하는 문제

```도해
대조: 브라우저에서 전부 처리하면 어떻게 되나
백엔드 없이 || 백엔드로
가격 계산 :: 브라우저가 함 || 서버가 함
데이터 :: 각자 기기에만 || 한 곳에 모임
검증 :: 고쳐서 우회됨 || 서버가 다시 봄
= 믿을 수 없는 곳에서 판단하지 않으려고 서버를 둔다
```

브라우저에서 도는 코드는 사용자가 열어보고 고칠 수 있다. 결제 금액을 화면에서 계산해 그대로 보내면 그 값을 바꿔서 보내는 것도 가능하다.

데이터가 있을 자리도 문제가 된다. 주문 기록이 각자 기기에만 남으면 다른 기기에서는 아무것도 보이지 않고, 관리자도 전체를 볼 수 없다. 백엔드는 판단과 저장을 한 곳으로 모아 이 두 가지를 함께 해결한다.

## ⚙️ 작동 원리

```도해
층: 요청 하나가 백엔드 안에서 어디를 지나나
API 진입 :: 어떤 주소로 온 요청인지 가른다
인증 :: 누구인지, 이 일을 해도 되는지 본다
로직 :: 값을 계산하고 규칙을 적용한다
데이터베이스 :: 실제로 읽고 쓴다
= 위에서 걸러진 요청은 아래까지 내려가지 않는다
```

각 층은 앞 층을 통과한 요청만 받는다. 로그인하지 않은 요청은 인증에서 끊기고 데이터베이스까지 가지 않는다. 그래서 권한 검사를 어느 층에 두느냐가 그대로 보안 경계가 된다.

## 📊 비교: 프론트엔드 vs 백엔드

| | 프론트엔드 | 백엔드 |
|---|---|---|
| 도는 곳 | 사용자 기기 | 서버 |
| 하는 일 | 보여주고 입력받기 | 판단하고 저장하기 |
| 사용자가 고칠 수 있나 | 있다 | 없다 |
| 흔한 언어 | JavaScript | Python, Java, Go 등 |

## 💡 실제 사례

- **로그인** 아이디와 비밀번호가 맞는지 확인하고 세션이나 토큰을 내주는 일은 서버에서 한다.
- **결제** 화면에 적힌 금액을 믿지 않고 서버가 다시 계산한 뒤 결제사에 요청을 보낸다.
- **목록 조회** 상품 목록을 데이터베이스에서 꺼내 내려주면, 화면은 받은 것을 그리기만 한다.

## 🚫 흔한 오해

- **백엔드는 서버 컴퓨터를 말한다** — 서버는 기계고 백엔드는 그 위에서 도는 코드다. 서버 한 대에 여러 백엔드가 같이 돌기도 한다.
- **화면을 안 만드니 사용자 경험과는 상관없다** — 응답이 3초 걸리면 사용자는 그걸 앱이 느린 것으로 느낀다. 체감 속도는 상당 부분 여기서 정해진다.
- **프론트에서 검사했으면 서버는 안 해도 된다** — 브라우저 쪽 검사는 사용자가 고칠 수 있어서 검사로 치지 않는다. 서버는 같은 검사를 다시 해야 한다.

## 📝 정리

Backend는 화면 뒤에서 데이터를 저장하고 규칙을 판단하는 쪽이다. 프론트엔드가 보낸 요청을 인증과 계산을 거쳐 처리하고 결과만 돌려주며, 밖에서 온 값은 서버에서 다시 확인한다.

## ❓ 이해했는지

- 브라우저에서 이미 금액을 계산했는데 서버가 또 계산하는 이유는?
- 로그인하지 않은 요청이 데이터베이스까지 내려가지 않는 이유는?
- 주문 버튼을 누른 뒤 "주문 완료"가 뜨기까지 서버에서는 무엇이 일어나나?
