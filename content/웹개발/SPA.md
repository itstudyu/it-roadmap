# SPA (Single Page Application)

## 📝 정의

SPA는 **HTML 한 장으로 시작해 화면만 갈아 끼우는 웹 앱**이다.

예전 방식은 링크를 누를 때마다 서버에서 페이지를 통째로 새로 받았다. SPA는 처음 한 번만 받고, 그다음부터는 필요한 데이터만 가져와 바뀔 부분을 자바스크립트로 다시 그린다.

### 비유
무대 하나에 배경만 바꿔 다는 연극. 장면이 바뀌어도 관객은 자리에서 일어나지 않는다.

## 🖼️ 그림으로 보기

```도해
흐름: SPA 에서 메뉴를 누르면 무슨 일이 일어나나
첫 방문 :: HTML 한 장과 자바스크립트 묶음을 받는다
메뉴 클릭 :: 브라우저가 새 페이지를 요청하지 않는다
JS :: 주소만 바꿔 적고 어느 화면인지 고른다
API :: 필요한 데이터만 JSON 으로 받아온다
< 화면 :: 바뀔 부분만 갈아 끼운다
= 페이지를 다시 받지 않으니 흰 깜빡임이 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 링크마다 페이지를 새로 받으면 어떻게 되나
페이지마다 새로 || SPA 로
받는 것 :: HTML 전체 || 데이터만
화면 :: 흰 깜빡임 || 그대로 이어짐
공통 부분 :: 매번 다시 그린다 || 그대로 둔다
= 안 바뀌는 부분까지 다시 받는 일을 없앤 것이다
```

메뉴와 헤더와 사이드바는 화면을 옮겨도 그대로다. 그런데 페이지를 통째로 받는 방식에서는 이것들까지 매번 다시 내려받아 다시 그린다. 그사이 화면이 한 번 비므로 클릭할 때마다 흰 깜빡임이 생긴다.

SPA는 바뀌는 부분만 다시 그린다. 서버에서 받아오는 것도 화면이 아니라 데이터뿐이라 오가는 양이 줄고, 앱을 쓰는 것처럼 이어지는 느낌이 난다.

## ⚙️ 작동 원리

SPA 하나는 네 가지로 이루어진다.

- **HTML 한 장** — 내용이 비어 있는 껍데기 하나
- **자바스크립트** — 화면을 그리고 갈아 끼우는 코드
- **라우터** — 주소와 화면을 짝지어 둔 표
- **API** — 데이터를 JSON 으로 주고받는 창구

넷 중 어디에도 화면을 만드는 서버가 없다. 서버는 데이터만 내주는 자리로 물러난다.

주소는 그대로 바뀐다. 자바스크립트가 브라우저 주소창을 고쳐 쓰되 서버에는 요청을 보내지 않는 방식이다. 그래서 `/about`을 눌렀을 때 주소가 바뀌고 뒤로 가기와 북마크도 동작한다.

라우터는 그 주소와 보여줄 화면을 짝지어 둔 표다. 주소가 바뀌면 표에서 짝을 찾아 그 화면을 그린다.

## 💡 실제 사례

- **대시보드** — 메뉴를 오가도 헤더와 사이드바는 그대로 있고 가운데 영역만 바뀐다.
- **메일함** — 목록에서 한 통을 열 때 목록은 남겨두고 본문 자리만 채운다.
- **단계가 나뉜 입력 폼** — 다음 단계로 넘어가도 페이지를 다시 받지 않아 앞에서 적은 값이 그대로 남는다.

## 🚫 흔한 오해

- **페이지가 하나니까 주소가 안 바뀐다** — 주소는 바뀐다. 브라우저에 주소만 새로 적고 서버에는 요청하지 않는 것이라 뒤로 가기와 북마크도 그대로 된다.
- **SPA는 항상 빠르다** — 두 번째 화면부터 빠른 것이고 첫 화면은 오히려 느리다. 자바스크립트 묶음을 다 받아 실행해야 첫 글자가 보인다.
- **SPA는 서버가 필요 없다** — 서버가 화면 만드는 일에서 빠진 것이지 사라진 게 아니다. 데이터는 여전히 API로 받아온다.

## ✅ 장단점

### 장점
- **전환이 빠르다** 안 바뀌는 부분을 다시 받지 않으니 클릭과 화면 사이가 짧다.
- **화면과 데이터가 갈린다** 서버는 API만 내주면 되고, 같은 API를 앱에서도 쓴다.

### 단점
- **첫 화면이 늦다** 자바스크립트 묶음을 다 받아야 무엇이든 보인다.
- **검색 엔진이 못 읽을 수 있다** 처음 받은 HTML이 비어 있어서 내용은 자바스크립트가 돈 뒤에 생긴다.

## 📝 정리

SPA는 HTML 한 장을 받아두고 그다음부터 데이터만 가져와 화면을 갈아 끼우는 방식이다. 화면 전환은 빨라지지만 첫 로딩과 검색 노출은 오히려 불리해지므로, 그 대가를 감당할 화면인지 보고 고른다.
