# Frontend (프론트엔드)

## 📝 정의

Frontend 는 **사용자 기기에서 실행되는 화면 쪽 코드**다.

서버가 통째로 그려준 화면을 받는 것이 아니라, 뼈대와 규칙을 받아 브라우저 안에서 조립한다. 그래서 클릭 한 번에 서버를 다시 다녀오지 않고도 화면이 바뀐다.

### 이름
Front :: 앞쪽, 손님 쪽
End :: 끝, 쪽
= 붙여 읽으면 "앞쪽 끝". 손님이 마주 보고 앉는 자리라는 뜻이다

### 비유
식당의 홀. 손님이 앉는 자리와 메뉴판과 응대는 여기서 하고, 요리는 주방에서 한다.

### 예
좋아요를 눌렀을 때 새로고침 없이 그 자리에서 하트가 빨개지는 일은 내 기기 안에서 일어난다.

### 직접
컴퓨터에서 F12 를 눌러 요소 칸의 아무 글자나 고쳐 보라. 화면이 바로 바뀌지만 새로고침하면 되돌아온다. 내 기기에서만 바뀐 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 주소를 치면 화면은 어떻게 만들어지나
브라우저 :: 서버에서 HTML 을 받아온다
HTML :: 문단과 버튼이 어디 있는지 정해진다
CSS :: 색과 간격과 배치가 입혀진다
JS :: 클릭과 입력에 반응하게 된다
API :: 필요한 데이터를 서버에 따로 요청한다
< 화면 :: 받아온 값으로 그 부분만 다시 그린다
= 화면은 서버가 통째로 주는 게 아니라 사용자 기기에서 조립된다
```

## ⚠️ 해결하는 문제

```도해
대조: 화면과 서버를 나누지 않으면 어떻게 되나
안 나누면 || 나누면
화면 수정 :: 서버까지 배포 || 화면만 배포
같은 데이터 :: 웹용만 만든다 || 앱도 같이 쓴다
클릭 반응 :: 매번 새로고침 || 그 자리에서
= 화면과 데이터를 갈라두면 한쪽을 고쳐도 다른 쪽이 멈추지 않는다
```

화면과 데이터가 한 덩어리면 버튼 색 하나를 바꾸는 데도 서버를 다시 배포해야 한다. 모바일 앱을 붙일 때는 같은 데이터를 위한 코드를 한 벌 더 만들게 된다.

화면을 앞으로 떼어내면 서버는 데이터만 돌려주는 자리가 된다. 웹과 앱이 같은 API 를 쓰고, 화면 수정은 화면만 다시 올리면 끝난다.

## 🧱 구성

```도해
층: 프론트엔드 코드는 무엇 위에 얹혀 도나
프레임워크 :: React, Vue, Angular. 아래를 묶어 다루는 도구
HTML·CSS·JS :: 구조와 모양과 동작. 브라우저가 아는 말
브라우저 :: 이것들을 읽어 실제 화면으로 만든다
= 위를 걷어내도 아래는 돌지만, 아래를 모르면 고장 난 자리를 못 짚는다
```

## ⚙️ 작동 원리

프레임워크가 하는 일은 대체로 하나다. 데이터가 바뀌면 화면의 어느 부분을 다시 그릴지 사람이 일일이 적지 않게 해주는 것이다. 데이터를 바꾸면 화면이 따라오는 방식으로 코드를 쓰게 된다.

## 💡 실제 사례

- **목록 화면** — 서버에서 JSON 을 받아 카드를 그리고, 스크롤이 끝에 닿으면 다음 묶음을 더 요청한다.
- **입력 폼** — 값을 치는 동안 형식을 확인해 바로 알려주고, 보내기를 누를 때 서버에서 다시 확인한다.
- **화면만 배포** — 문구와 배치를 고친 뒤 정적 파일만 다시 올린다. 서버는 건드리지 않는다.

## 🚫 흔한 오해

- **프론트엔드는 디자인하는 일이다** — 디자인을 화면으로 옮기는 일이다. 실제로 시간이 드는 쪽은 상태 관리와 성능이다.
- **화면에서 검사했으니 서버 검사는 안 해도 된다** — 사용자 기기에서 도는 코드는 얼마든지 건너뛸 수 있다. 서버가 다시 확인해야 한다.
- **React 를 쓰면 프론트엔드다** — 도구를 바꿔도 하는 일은 같다. HTML, CSS, 자바스크립트 위에 얹힌 것이다.

## 📝 정리

**"손님 앞에서 화면을 조립하는 그 쪽"** 이라고 읽으면 된다. HTML 과 CSS 와 자바스크립트가 각각 구조와 모양과 동작을 맡고, 프레임워크는 그 셋을 묶어 다루게 해준다. 데이터는 서버에서 오지만 화면을 조립하는 것은 사용자 쪽이다.

## 🧒 열 살에게

식당에 가면 자리랑 메뉴판이랑 인사해 주는 사람은 다 홀에 있지? 음식은 주방에서 나오지만, 자리를 옮기거나 메뉴판을 넘기는 건 홀에서 그 자리에 바로 돼. 그래서 주방에 다시 물어보지 않고도 네 앞의 것들이 바뀌어.

## ❓ 이해했는지

- 버튼을 눌러도 화면이 안 바뀌는데 서버 로그에 요청이 남았다면 어느 단계에서 멈춘 것인가 → 그림
- 회원가입 폼에서 화면 쪽 검사만 하면 무엇이 뚫리나 → 흔한 오해
- 문구를 고쳤는데 서버를 다시 배포하지 않아도 되는 이유는 → 해결하는 문제
