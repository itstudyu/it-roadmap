# HTML (HyperText Markup Language)

## 📝 정의

HTML은 웹 내용의 **뜻과 구조**를 표시하는 마크업 언어다.

이름이 곧 구조다 — HyperText 는 문서와 문서가 링크로 이어진다는 뜻이고, Markup 은 글에 표시를 달아 "이건 제목, 이건 목록" 이라고 알려주는 일이다. 생김새는 [[CSS]] 가, 동작은 JavaScript(브라우저에서 도는 프로그래밍 언어)가 맡는다.

### 이름
Hyper :: 건너뛰는
Text :: 글
Markup :: 표시 달기
Language :: 적어 내는 말
= 붙여 읽으면 "건너뛰는 글에 표시를 다는 말". 표시가 뜻을 붙이고 링크가 글끼리 잇는다

### 비유
택배 상자에 붙이는 내용물 라벨 — 겉포장이 어떻게 생겼든 "깨지는 것" 이라고 적혀 있으면 받는 사람이 알아서 다룬다.

### 예
브라우저에서 페이지 소스 보기를 눌렀을 때 쏟아지는 꺾쇠 괄호투성이 글자가 그것이다.

### 직접
아무 페이지에서 오른쪽 클릭 → 페이지 소스 보기를 누르고 `<h1` 을 찾아보라. 그 페이지가 무엇을 제목으로 표시해 뒀는지 나온다.

## 🖼️ 그림으로 보기

```도해
대조: 어떤 태그를 쓰든 화면이 같은데 왜 골라 쓰나
div 로만 || 뜻이 있는 태그로
뜻 :: 이름표가 없다 || 태그가 곧 이름표
스크린 리더 :: 한 덩어리로 읽힘 || 제목으로 건너뛴다
키보드 :: 직접 만들어야 || 그냥 눌린다
= HTML 이 표시하는 것은 생김새가 아니라 "이게 무엇인가" 다
```

## ⚠️ 해결하는 문제

```도해
대조: 글에 표시를 달지 않으면 무엇을 못 하나
표시 없이 || HTML 로
글 구조 :: 줄바꿈만 남는다 || 제목·목록이 산다
문서 잇기 :: 주소를 옮겨 적는다 || 눌러서 건너간다
기계가 읽기 :: 통째로 훑어야 || 태그로 골라낸다
= 표시가 없으면 글은 글자 뭉치일 뿐이다. 태그가 거기에 뜻을 붙인다
```

HTML 은 원래 과학 문서를 뜻 단위로 기술하려고 만든 언어였다. 명세가 스스로 밝히는 범위는 "정적인 문서부터 동적인 애플리케이션까지, 접근 가능한 페이지를 저술하기 위한 의미 수준의 마크업 언어" 이고, **매체별로 표현을 손보는 장치는 범위에서 빼두었다.** 어떻게 보일지는 CSS 같은 스타일 언어에 넘긴다.

그래서 태그를 고르는 일은 취향이 아니다. 스크린 리더는 제목 태그를 목록으로 뽑아 목차처럼 쓰고, `<button>` 은 Tab 으로 옮겨가 Space·Enter 로 눌리는 조작을 기본으로 준다. `<div>` 로 겉모습만 따라 만들면 그 둘이 함께 사라진다.

## ⚙️ 작동 원리

브라우저는 HTML 글자를 그대로 화면에 뿌리지 않는다. 먼저 글자를 토큰으로 자르고(tokenization), 그 토큰으로 트리를 세운다(tree construction). 명세는 결과를 한 줄로 못 박는다 — "출력은 Document 객체다." 우리가 보는 화면의 정체는 원문이 아니라 그렇게 만들어진 [[DOM]] 트리다.

닫는 태그를 빠뜨렸는데도 화면이 그려지는 이유가 여기 있다. 어긋난 자리는 **파스 에러**로 이름이 붙어 있고, 그때 무엇을 할지까지 명세가 정해 두었다. 그래서 결과물이 원문과 어긋나기도 한다 — `<table>` 안에 `<tr>` 만 적으면 브라우저가 만든 마크업에는 적지도 않은 `<tbody>` 가 끼어 있다.

## 📊 비교: 셋이 나눠 맡는 것

| | HTML | CSS | JavaScript |
|---|---|---|---|
| 맡는 것 | 뜻과 구조 | 생김새 | 동작 |
| 답하는 말 | 이게 무엇인가 | 어떻게 보일까 | 무슨 일이 일어나나 |
| 빠지면 | 내용 자체가 없다 | 기본 모습으로 나온다 | 가만히 있는 문서가 된다 |

매체마다 다르게 보이게 하는 일은 HTML 이 자기 범위에서 빼둔 자리다. 그 자리를 CSS 가 맡고, HTML 은 셋 모두에게 같은 내용을 내준다.

## 💡 실제 사례

- **스크린 리더로 훑기** — 제목 태그를 목록으로 뽑아 원하는 대목으로 바로 건너뛴다.
- **검색 엔진 수집** — 제목과 링크 안에 든 낱말을 본문 속 낱말보다 무겁게 본다.
- **CSS 갈아 끼우기** — 태그 이름과 클래스가 선택자의 표적이 되어, 내용을 안 건드리고 생김새만 바꾼다.

## 🚫 흔한 오해

- **HTML 은 프로그래밍 언어다** — 조건도 반복도 없다. 무엇이 있는지 표시하는 마크업 언어이고, 계산과 동작은 JavaScript 가 맡는다.
- **`<div>` 로 다 만들어도 화면이 같으니 상관없다** — 보이는 것만 같다. 스크린 리더는 페이지를 통째로 한 덩어리로 읽고, `<button>` 이 기본으로 주던 키보드 조작이 사라진다.
- **HTML 이 화면 생김새를 정한다** — 브라우저의 기본 표시 규칙이 있을 뿐이다. 어떻게 보일지는 CSS 같은 스타일 언어로 따로 정한다.

## 📝 정리

**"내용마다 이게 무엇인지 붙여 두는 이름표"** 라고 읽으면 된다. 생김새는 CSS 가, 동작은 JavaScript 가 맡는다. 그래서 뜻에 맞는 태그를 고르는 일이 그대로 접근성이 되고, 기계가 읽을 수 있는 문서가 된다.

## 🧒 열 살에게

택배 상자에 "깨지는 거예요" 라고 적힌 딱지 붙은 거 봤지? 글에도 그런 딱지를 하나하나 붙여 두는 거야 — 여기는 제목, 여기는 그냥 줄, 여기는 눌러야 하는 단추. 딱지가 붙어 있으니까 눈으로 안 보고 소리로 듣는 사람도 제목만 골라서 건너뛸 수 있어.

## ❓ 이해했는지

- 제목 태그 없이 `<div>` 로만 짠 페이지가 스크린 리더에서 왜 한 덩어리로 읽히나 → 그림
- 닫는 태그를 빠뜨렸는데도 페이지가 멀쩡히 그려지는 까닭은 → 작동 원리
- 내용은 그대로 두고 생김새만 바꾸려면 셋 중 무엇을 고쳐야 하나 → 비교
