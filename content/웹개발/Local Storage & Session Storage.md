# Local Storage & Session Storage (브라우저 저장소)

## 📝 정의

Local Storage 와 Session Storage 는 **브라우저에 값을 남기는 두 저장소**다.

둘은 같은 `Storage` 인터페이스를 쓴다. 넣고 꺼내는 방법이 같고, 갈리는 것은 값이 언제까지 남고 어디까지 보이는지다. [[Cookie]] 와 가장 다른 점은 서버로 자동 전송되지 않는다는 것이다 — MDN 은 이 저장소들이 "저장을 염두에 두고 설계되었고 데이터를 서버로 절대 보내지 않는다" 고 적는다.

### 이름
Local :: 이 브라우저 안에만
Session :: 탭이 열려 있는 동안
Storage :: 값을 넣어 두는 통
= 붙여 읽으면 "이 브라우저에 남는 통" 과 "탭이 닫히면 비는 통". 이름이 곧 사는 기간이다

### 비유
책상 서랍은 다음에 와도 그대로지만, 회의실 화이트보드는 회의가 끝나면 지워진다.

### 예
로그인도 안 한 사이트인데 다크 모드로 바꿔 둔 것이 다음에 들어가도 그대로인 그 자리다.

### 직접
아무 사이트에서 개발자 도구의 콘솔에 `localStorage` 를 쳐 보라. 그 사이트가 내 브라우저에 남겨 둔 값들이 그대로 나온다.

## 🖼️ 그림으로 보기

```도해
대조: 탭을 닫으면 저장한 값은 남나 사라지나
Local Storage |=| Session Storage
탭을 닫으면 :: 그대로 남는다 || 사라진다
탭 두 개에서 :: 같은 값을 본다 || 각자 따로 본다
어울리는 값 :: 다시 와도 쓸 것 || 이 탭에서만 쓸 것
= 브라우저에 값을 남기는 두 통이고, 갈리는 것은 어디까지 남는지다
```

## ⚠️ 해결하는 문제

```도해
대조: 브라우저에 둘 값을 쿠키로만 담으면 어떻게 되나
쿠키에 담으면 || 브라우저 저장소로
전송 :: 요청마다 딸려 간다 || 서버로 안 간다
한 통 크기 :: 4KB 안팎 || 5MiB 쯤
탭 두 개 :: 같은 값을 공유 || 따로 둘 수 있다
= 서버가 볼 필요 없는 값을 요청마다 실어 보낼 이유가 없다
```

브라우저에 값을 남기는 방법이 오랫동안 쿠키뿐이었다. 표준은 이 저장소들을 들이면서 쿠키가 못 하는 일 둘을 들었다. 하나는 창을 가리지 않는다는 것이다 — 같은 사이트의 두 창에서 각각 항공권을 고르는 사람이 있으면, 고른 표를 쿠키로 따라가는 사이트에서는 한 창의 선택이 다른 창으로 새어 나간다. 다른 하나는 양이다. 클라이언트에 메가바이트 단위로 값을 두고 싶을 때 쿠키는 맞지 않고, 표준이 든 이유가 쿠키는 "모든 요청과 함께 전송되기 때문" 이다. 한 통이 4KB 안팎으로 작기도 하다.

Web Storage 는 서버가 볼 필요 없는 값을 브라우저 안에만 두게 해서 두 문제를 함께 없앤다. 요청에 안 실리니 크기 제한이 훨씬 느슨하고(출처당 5MiB 쯤, 쿠키 한 통의 천 배가 넘는다), `sessionStorage` 쪽은 통을 탭 단위로 아예 나눠 둔다.

## ⚙️ 작동 원리

```도해
층: 브라우저에 둔 값은 어디까지 살아남나
localStorage :: 지우지 않으면 계속. 만료가 없다
sessionStorage :: 그 탭을 닫을 때까지
페이지 안의 변수 :: 새로고침 한 번에 사라진다
= 아래로 갈수록 짧게 산다. 어디까지 남길지로 통을 고른다
```

`setItem` 으로 넣고 `getItem` 으로 꺼내고 `removeItem` 과 `clear` 로 지우며, `length` 와 `key` 로 훑는다. 잡는 통만 다르니 `localStorage` 를 `sessionStorage` 로 바꿔 써도 코드는 그대로 돈다.

키와 값은 UTF-16 문자열로 저장된다. 숫자 키도 문자열로 바뀌므로 객체나 배열은 `JSON.stringify` 로 바꿔 넣고 꺼낼 때 되돌려야 한다. 용량은 출처마다 정해져 있는데, MDN 은 어느 브라우저에서든 Web Storage 가 최대 10MiB 이고 출처당 local 5MiB · session 5MiB 라고 적으며, 넘기면 `QuotaExceededError` 가 던져진다.

"세션" 이 얼마인지는 브라우저 탭이 정한다. MDN 은 탭에 문서가 실릴 때마다 그 탭에 페이지 세션 하나가 생기고, 그 세션은 탭이나 브라우저가 열려 있는 동안 이어지며 **새로고침과 복원을 견딘다** 고 적는다. 그래서 새로고침해도 `sessionStorage` 는 남아 있고, 탭을 닫으면 사라진다.

읽고 쓰는 일은 동기로 일어나 그동안 다른 자바스크립트가 멈춘다. 같은 출처의 다른 창에서 값이 바뀌면 그 창들에 `storage` 이벤트가 간다.

## 💡 실제 사례

- **다크 모드 설정** — 고른 테마를 `localStorage` 에 넣어두면 서버로 보내지 않고도 다음에 들어올 때 그대로 적용된다.
- **쓰던 글의 임시 저장** — 작성 중인 내용을 `localStorage` 에 계속 덮어써 두면 창을 잘못 닫아도 되살릴 수 있다.
- **탭마다 따로 가는 절차** — 같은 사이트의 두 탭에서 각각 항공권을 고르는 경우처럼, 탭마다 다른 선택을 들고 있어야 하는 값은 `sessionStorage` 에 둔다. 표준이 이 저장소를 만든 이유로 든 상황이 이것이다.

## 🚫 흔한 오해

- **브라우저에 저장했으니 서버도 그 값을 안다** — 요청에 딸려 가지 않는다. 서버가 알아야 하는 값이면 직접 담아 보내야 하고, 그 일을 자동으로 해주는 것은 쿠키 쪽이다.
- **`sessionStorage` 의 세션이 로그인 세션이다** — 이름만 겹친다. 서버가 들고 있는 [[Session]] 과는 관계가 없고, 여기서 말하는 세션은 그 탭이 열려 있는 동안이다.
- **브라우저에 둘 값은 `localStorage` 에 넣으면 된다** — 읽고 쓰는 동안 다른 자바스크립트가 멈추고 출처당 5MiB 에서 막힌다. 양이 많으면 브라우저가 함께 주는 비동기 저장소 IndexedDB 쪽이고, 서버가 봐야 하는 값이면 쿠키 쪽이다.

## 🚨 주의사항

- **민감한 값을 두지 않는다.** 표준은 여기 담긴 것을 민감할 수 있는 데이터로 다루라고 적어 두었고, 같은 출처에서 도는 스크립트라면 무엇이든 값을 읽는다. 쿠키의 `HttpOnly` 같은 잠금이 없어서 [[XSS]] 하나에 통째로 새어 나간다.
- **문자열만 들어간다.** 객체를 그대로 넣으면 내용이 아니라 그것을 문자열로 바꾼 결과가 저장된다. `JSON.stringify` 와 `JSON.parse` 를 짝으로 쓴다.
- **비공개 창에서는 `localStorage` 도 세션처럼 산다.** MDN 은 비공개 모드에서 `localStorage` 가 `sessionStorage` 처럼 다뤄지고, 마지막 비공개 탭이 닫히면 지워진다고 적는다.

## 📝 정리

**"서버로 안 가고 브라우저에만 남는 그 통"** 이라고 읽으면 된다. localStorage 는 지울 때까지 남고 sessionStorage 는 그 탭을 닫을 때까지만 남는다. 서버가 봐야 하는 값이면 쿠키를, 민감한 값이면 브라우저에 두지 않는 쪽을 고른다.

## 🧒 열 살에게

네 방 책상 서랍에 넣어 둔 건 다음 날에도 그대로 있지? 그런데 교실 칠판에 적은 건 수업이 끝나면 지워져. 화면을 어둡게 바꿔 둔 게 다음에 또 들어가도 그대로인 건, 그걸 칠판 말고 서랍에 넣어 뒀기 때문이야.
