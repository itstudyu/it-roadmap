# GraphQL

## 📝 정의

GraphQL은 **필요한 필드를 골라서 요청하는 API 방식**이다.

주소마다 응답 모양이 정해져 있는 방식과 달리, 요청하는 쪽이 "이름과 이메일만 달라"고 적어 보낸다. 서버는 요청한 모양 그대로 돌려준다.

### 비유
뷔페와 주문서의 차이. 정해진 정식은 다 나오고 남기지만, 주문서에는 먹을 것만 적어 낸다.

## 🖼️ 그림으로 보기

```도해
흐름: 필드를 골라 적어 보내면 무슨 순서로 오가나
클라이언트 :: 필요한 필드를 적어 한 곳으로 보낸다
스키마 검사 :: 없는 필드를 물었는지 먼저 확인한다
리졸버 :: 필드마다 담당 함수가 값을 가져온다
데이터 소스 :: DB 나 다른 API 에서 값을 읽는다
< 클라이언트 :: 요청한 모양 그대로 결과를 받는다
= 주소를 여러 번 부르는 대신 필요한 것을 한 번에 적어 보낸다
```

## ⚠️ 해결하는 문제

```도해
대조: 화면 하나에 필요한 데이터를 모으면 어떻게 되나
주소별 API 로 || GraphQL 로
요청 횟수 :: 화면마다 여러 번 || 한 번
받는 양 :: 안 쓸 필드까지 || 적은 것만
화면이 바뀌면 :: 서버도 손댄다 || 쿼리만 고친다
= 받는 쪽이 모양을 정하니 서버를 덜 건드린다
```

주소마다 응답이 고정된 API에서는 두 가지가 자주 걸린다. 이름만 필요한데 사용자 정보 전체가 오는 것이 하나고, 사용자와 그 사람의 글을 함께 보여주려고 요청을 두 번 세 번 보내는 것이 다른 하나다.

모바일에서 이 둘은 그대로 체감된다. GraphQL은 요청하는 쪽이 필드를 적게 해서 두 문제를 같은 방식으로 다룬다.

## ⚙️ 작동 원리

서버는 어떤 타입에 어떤 필드가 있는지 미리 적어둔다. 이 정의를 스키마라고 한다. 요청이 들어오면 스키마와 대조해서 없는 필드를 물었는지, 타입이 맞는지 먼저 확인한다.

통과한 요청은 필드마다 붙어 있는 함수가 처리한다. 이 함수를 리졸버라고 한다. 중첩된 필드는 리졸버가 다시 리졸버를 부르는 식으로 내려간다.

```graphql
query {
  user(id: "123") {
    name
    posts { title }
  }
}
```

읽기는 `query`, 쓰기는 `mutation`으로 나눈다. 주소는 하나뿐이고 무엇을 할지는 본문이 정한다.

## 📊 비교

| | GraphQL | REST |
|---|---|---|
| 주소 | 하나 | 자원마다 |
| 응답 모양 | 요청한 대로 | 서버가 정한 대로 |
| 화면 하나에 | 요청 한 번 | 여러 번일 때가 많다 |
| 캐시 | 직접 다뤄야 한다 | 주소 단위로 쉽다 |

## 💡 실제 사례

- **모바일 목록 화면** 목록에는 이름과 썸네일만 있으면 되므로 그 두 필드만 적어 보낸다.
- **화면 개편** 표시할 항목이 늘어도 쿼리에 필드를 추가하면 되고 서버 쪽은 그대로다.
- **여러 저장소에서 모으기** 사용자 정보는 DB, 결제 내역은 다른 서비스에서 오더라도 요청하는 쪽은 한 번만 부른다.

## 🚫 흔한 오해

- **GraphQL은 데이터베이스다** — 아니다. 이름에 Query가 들어가서 그렇게 보이지만 저장소가 아니고, 값은 여전히 뒤에 있는 DB나 다른 API에서 가져온다.
- **요청이 한 번이니 항상 빠르다** — 서버 안에서는 여러 번 조회할 수 있다. 목록의 항목마다 관련 데이터를 따로 읽으면 오히려 느려지고, 이걸 막으려고 묶어서 읽는 장치를 따로 둔다.
- **REST를 대체한다** — 골라 쓰는 것이다. 응답이 단순하고 캐시가 중요한 곳에서는 주소 단위로 나뉜 쪽이 다루기 쉽다.

## 🚨 주의사항

- **깊게 중첩된 쿼리를 막아둔다.** 요청하는 쪽이 모양을 정하므로, 제한이 없으면 한 번의 요청으로 서버를 크게 흔들 수 있다.
- **필드 단위 권한을 따로 본다.** 주소로 막던 것을 필드로 막아야 해서 확인할 자리가 늘어난다.

## 📝 정리

GraphQL은 요청하는 쪽이 필요한 필드를 적어 보내고 서버가 그 모양대로 돌려주는 API 방식이다. 안 쓸 데이터와 요청 횟수를 줄여주지만, 캐시와 권한과 쿼리 제한은 직접 다뤄야 한다.

## ❓ 이해했는지

- 화면에 표시할 항목이 늘었는데 서버 코드를 안 고쳐도 되는 이유는?
- 요청을 한 번만 보내는데도 응답이 느려질 수 있는 경우는?
- 깊게 중첩된 쿼리를 제한하지 않으면 무슨 일이 생기나?
