# Middleware (미들웨어)

## 📝 정의

Middleware는 **요청이 처리기에 닿기 전에 거쳐 가는 중간 함수**다.

인증 확인, 로그 남기기, 형식 검사처럼 거의 모든 요청에 똑같이 필요한 일이 있다. 그걸 처리기마다 다시 쓰는 대신 앞에 한 줄로 세워두는 것이 미들웨어다.

### 이름
Middle :: 가운데
Ware :: 갖춰 둔 물건
= 붙여 읽으면 "가운데에 세워 둔 물건". 요청과 처리기 사이에 서 있어서 붙은 이름이다

### 비유
공항 검색대. 어느 게이트로 가든 같은 줄을 지나고, 여기서 걸리면 게이트까지 가지 못한다.

### 예
로그인이 풀린 뒤에는 어느 메뉴를 눌러도 곧장 로그인 화면으로 튕기는데, 그 줄에서 걸린 것이다.

### 직접
어느 사이트에서 로그아웃한 뒤 뒤로 가기로 내 정보 화면에 돌아가 보라. 그 화면이 뜨지 않고 로그인 화면으로 튕긴다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청 하나가 처리기까지 어떻게 가나
요청 :: GET /api/user 가 도착한다
인증 :: 토큰을 확인한다. 없으면 여기서 끝
로깅 :: 무엇이 들어왔는지 남기고 넘긴다
핸들러 :: 실제 업무를 처리해 결과를 만든다
< 응답 :: 왔던 순서를 거꾸로 지나 밖으로 나간다
= 각 칸이 다음으로 넘길지 여기서 끊을지를 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 공통 처리를 처리기마다 쓰면 어떻게 되나
미들웨어 없이 || 미들웨어로
인증 코드 :: 핸들러마다 || 한 곳에
규칙 변경 :: 전부 찾아 고침 || 한 곳만 고침
빠뜨림 :: 한 곳 빠지면 구멍 || 줄에 세우면 끝
= 빠뜨릴 수 있는 자리를 아예 없애는 것이 이 구조의 값이다
```

로그인 확인을 처리기마다 쓰면 처리기가 늘어날 때마다 같은 코드가 늘어난다. 규칙이 바뀌면 전부 찾아 고쳐야 하고, 새로 만든 화면 하나에서 그걸 빠뜨리면 그곳만 뚫린 채 남는다.

앞에 한 줄로 세워두면 그 자리가 사라진다. 보호할 경로는 전부 같은 줄을 지나고, 규칙은 한 곳에만 있다.

## ⚙️ 작동 원리

각 미들웨어는 요청과 응답 객체를 받고, 자기 일을 끝낸 뒤 다음으로 넘길지 여기서 끊을지를 스스로 정한다.

```javascript
function auth(req, res, next) {
  const token = req.headers.authorization;
  if (!token) return res.status(401).send('Unauthorized');
  req.user = verify(token);
  next();   // 여기서 다음 칸으로 넘어간다
}
```

`next()`를 부르면 다음 미들웨어로, 부르지 않고 응답하면 거기서 끝난다. 둘 다 하지 않으면 요청은 그 자리에 멈춘 채 응답도 나가지 않는다.

등록한 순서가 곧 실행 순서다. 그리고 응답은 온 길을 거꾸로 되짚어 나가기 때문에, 각 미들웨어는 들어올 때와 나갈 때 두 번 손을 댈 수 있다. 압축이나 응답 헤더 조정이 나가는 길에서 일어난다.

## 📊 비교: 비슷한 이름들

| | 미들웨어 | 필터 | 인터셉터 |
|---|---|---|---|
| 걸리는 자리 | 라우팅 앞뒤 | 서블릿 앞뒤 | 특정 핸들러 앞뒤 |
| 다음으로 넘기는 법 | `next()` 호출 | 체인에 넘김 | 메서드 반환값 |
| 보는 범위 | 요청 전체 | 요청 전체 | 그 핸들러 |

## 💡 실제 사례

- **로그인 확인** — 보호된 경로 앞에 한 번 걸어두면 각 처리기에서 다시 확인하지 않아도 된다.
- **CORS 헤더** — 다른 도메인에서 부르는 요청에 필요한 헤더를 모든 응답에 자동으로 붙인다.
- **응답 압축** — 응답이 크면 나가는 길에서 압축한다. 처리기는 그런 게 있는지도 모른다.

## 🚫 흔한 오해

- **미들웨어는 요청이 들어올 때만 실행된다** — 응답이 나갈 때도 지난다. 들어올 때는 앞에서 뒤로, 나갈 때는 뒤에서 앞으로 거꾸로 지나간다.
- **등록만 해두면 순서는 상관없다** — 순서가 곧 동작이다. 로깅을 인증 뒤에 두면 거부된 요청은 기록에 남지 않는다.
- **미들웨어에서 막히면 알아서 오류 응답이 나간다** — 넘기지도 응답하지도 않으면 요청은 멈춘 채로 남는다. 넘기는 일도 끊는 일도 직접 해야 한다.

## 🚨 주의사항

- **모든 요청이 지나는 줄이라 여기에 무거운 일을 넣으면 전부 느려진다.** 특정 경로에만 필요한 검사는 그 경로에만 건다.
- **줄이 길어지면 문제가 어디서 났는지 찾기 어려워진다.** 어느 칸까지 지나갔는지 남겨두는 편이 낫다.

## 📝 정리

**"처리기 앞에 줄지어 선 그 검색대"** 라고 읽으면 된다. 각 칸은 다음으로 넘기거나 거기서 끊고, 응답은 그 줄을 거꾸로 되짚어 나간다. 등록 순서가 동작을 정하기 때문에 순서가 설정의 일부다.

## 🧒 열 살에게

공항에서 비행기 타러 갈 때는 어느 문으로 가든 짐 검사하는 줄을 먼저 지나지? 인터넷 화면 뒤에도 똑같은 줄이 세워져 있어. 그래서 로그인이 풀리면 어느 단추를 눌러도 그 줄에서 붙잡혀 로그인 화면으로 되돌아가.

- 미들웨어에서 넘기지도 응답하지도 않으면 무슨 일이 벌어지나 → 작동 원리
