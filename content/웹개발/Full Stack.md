# Full Stack (풀스택)

## 📝 정의

Full Stack은 **화면부터 서버까지 전부 다루는 것**이다.

여기서 말하는 스택은 웹 서비스 하나를 세우는 데 필요한 층 전체다. 화면, 서버, 데이터 저장, 그리고 그것을 띄우는 일까지 포함한다.

### 이름
Full :: 전부
Stack :: 쌓아 올린 층
= 붙여 읽으면 "쌓인 층 전부". 화면부터 띄우는 일까지 그 더미 전체를 가리킨다

### 비유
집을 짓는 목수 중에 마감만 하는 사람과 기초부터 지붕까지 다 잡는 사람이 있다. 풀스택은 뒤쪽이다.

### 예
채용 공고 목록에서 프론트엔드·백엔드와 나란히 걸려 있는 세 번째 이름이 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 버튼 하나를 누르면 어디까지 내려갔다 오나
화면 :: 목록을 보여달라는 요청을 만든다
서버 :: 요청을 받아 권한이 있는지 본다
DB :: 조건에 맞는 줄을 찾아 돌려준다
< 서버 :: 화면이 쓸 수 있는 형태로 다듬는다
< 화면 :: 받은 것을 목록으로 그린다
= 클릭 한 번이 화면과 서버와 DB 를 지나 돌아온다
```

## ⚠️ 해결하는 문제

```도해
대조: 화면과 서버를 한 사람이 맡으면 무엇이 달라지나
나눠 맡으면 || 한 사람이 맡으면
API 규격 :: 회의로 맞춘다 || 바로 정한다
버그 위치 :: 서로 미룬다 || 한 번에 찾는다
작은 수정 :: 두 사람 대기 || 혼자 끝낸다
= 층 사이를 오가는 시간이 코드 쓰는 시간보다 길어지는 일이 흔하다
```

화면 담당과 서버 담당이 나뉘면 둘 사이에 규격을 맞추는 일이 생긴다. 응답에 필드를 하나 더하는 작은 일도 요청하고 기다리고 확인하는 절차를 거친다. 화면이 이상하게 뜰 때 원인이 어느 쪽인지부터 다투게 되는 일도 잦다.

한 사람이 양쪽을 보면 그 절차가 사라진다. 요청 하나가 화면을 떠나 DB까지 갔다가 돌아오는 길 전체를 머릿속에 두고 고칠 수 있어서, 어느 층에서 고치는 게 나은지도 판단할 수 있다.

## 🧱 구성

```도해
층: 풀스택이 말하는 스택은 무엇으로 이루어져 있나
화면 :: HTML, CSS, JavaScript. React 나 Vue
서버 :: Python, Node.js. Django 나 Express
데이터 :: MySQL, MongoDB. 무엇을 어떻게 담을지
배포 :: Docker, AWS. 만든 것을 띄우고 지키는 일
= 아래로 갈수록 사용자에게서 멀어지고 고장이 나면 영향은 커진다
```

## ⚙️ 작동 원리

층마다 쓰는 언어와 도구가 다르지만 풀스택이 익히는 건 도구 목록이 아니라 층 사이의 경계다. 어디까지를 화면에서 계산하고 어디부터 서버에 맡길지, 데이터를 어떤 모양으로 넘길지 같은 것들이다.

## 💡 실제 사례

- **작은 팀의 초기 제품** — 사람이 두세 명뿐이라 한 사람이 화면과 서버를 다 잡고 빠르게 붙였다 뗐다 한다.
- **혼자 만드는 사이드 프로젝트** — 화면부터 배포까지 전부 필요한데 맡길 사람이 없다.
- **층을 오가는 버그** — 목록이 비어 보이는 원인이 화면 코드인지 서버 응답인지 DB 조건인지 한 사람이 순서대로 짚어 내려간다.

## 🚫 흔한 오해

- **풀스택이면 뭐든 혼자 다 만들 수 있다** — 만들 수는 있어도 각 층의 깊은 곳까지 다 아는 것은 아니다. 대개 한쪽이 주력이고 나머지는 막히지 않을 만큼만 안다.
- **풀스택은 프론트엔드에 백엔드를 더한 것이다** — 외울 목록이 두 배가 되는 일이 아니다. 요청 하나가 화면에서 DB까지 어떻게 흘러가는지 이어서 보는 쪽에 가깝다.
- **풀스택을 쓰면 사람이 덜 든다** — 한 사람이 두 몫을 하는 게 아니라 층 사이 인수인계가 없어지는 것이다. 일의 양 자체는 줄지 않는다.

## 📝 정리

**"화면부터 저장까지 층을 이어서 보는 그 자리"** 라고 읽으면 된다. 층마다 도구를 다 외우는 일이 아니라 요청 하나가 층을 지나 돌아오는 길을 통째로 보는 일이고, 그래서 층 사이에서 생기는 낭비가 줄어든다.

## 🧒 열 살에게

집 짓는 사람 중에는 벽지만 예쁘게 바르는 사람도 있고, 땅 파는 것부터 지붕 얹는 것까지 다 하는 사람도 있지? 뒤쪽 사람은 물이 새면 지붕 탓인지 바닥 탓인지 혼자 짚어 내려가. 그래서 누구한테 물어보러 갔다 오느라 기다리는 시간이 없어.

## ❓ 이해했는지

- 버튼을 눌러 목록이 뜨기까지 요청은 어느 곳들을 지나가나 → 그림
- 화면과 서버를 다른 사람이 맡을 때 작은 수정 하나가 오래 걸리는 이유는 → 해결하는 문제
- 풀스택 개발자라고 해서 모든 층을 같은 깊이로 알지는 못하는 이유는 → 흔한 오해
