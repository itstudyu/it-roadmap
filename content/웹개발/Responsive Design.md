# Responsive Design (반응형 디자인)

## 📝 정의

Responsive Design 은 **화면 크기에 따라 배치가 스스로 바뀌는** 웹 설계 방식이다.

기술 하나의 이름이 아니라 접근 방식의 이름이다. 2010년에 이름이 붙었고, 그전에는 서버가 접속한 기기를 알아내 휴대폰용 사이트를 따로 보내주는 방식이었다. 그래서 기기 종류만큼 판이 늘어났다.

### 비유
물. 어떤 그릇에 담아도 그릇 모양대로 퍼지고, 그릇 밖으로 넘치지 않는다.

## 🖼️ 그림으로 보기

```도해
대조: 기기마다 사이트를 따로 만들면 무엇이 달라지나
기기별로 따로 || 반응형 하나로
좁은 화면 :: 다른 사이트로 보냄 || 배치가 한 줄로 접힘
새 화면 크기 :: 판을 하나 더 만듦 || 있는 규칙이 받아냄
고칠 곳 :: 판마다 전부 || 한 군데만
= 판을 여러 벌 만드는 대신, 한 벌이 화면 크기에 맞춰 스스로 바뀐다
```

## ⚠️ 해결하는 문제

```도해
대조: 폭을 960px 로 못 박으면 390px 화면에서 어떻게 되나
고정 폭 || 유연한 폭
글 :: 좌우로 밀어야 함 || 세로로만 내림
그림 :: 화면 밖으로 넘침 || 폭에 맞춰 줄어듦
넓은 화면 :: 한쪽에 빈 띠 || 여백으로 돌림
= 폭을 숫자로 못 박는 순간, 그 숫자가 아닌 화면은 다 어긋난다
```

폭을 픽셀 숫자로 정해두면 그보다 좁은 화면에서는 가로로 밀어야 하고, 넓은 화면에서는 한쪽에 빈 띠가 남는다. 기기를 알아내 따로 만든 사이트로 보내는 길도 있었지만, 화면 크기는 계속 새로 생긴다. 판을 하나 더 만들 때마다 고칠 곳도 하나씩 늘어난다.

반응형은 **폭을 숫자가 아니라 비율로 다룬다.** 기본 배치를 늘고 줄게 짜 두고, 그 유연함이 무너지는 지점에서만 규칙을 갈아 끼운다. 그래서 아직 나오지 않은 화면 크기도 대개 그냥 받아낸다.

## ⚙️ 작동 원리

```도해
층: 화면이 넓어질수록 무엇이 얹히나
좁은 화면 :: 한 줄로 쌓는다. 이게 기본값이다
중간 화면 :: 두 칸으로 나누고 사이에 여백을 준다
넓은 화면 :: 본문 폭을 묶고 남는 자리를 여백으로 둔다
= 좁은 쪽이 기본이고 넓은 쪽이 얹히는 것이다. 이 순서를 mobile first 라 한다
```

반응형을 이루는 것은 셋이다.

| 무엇 | 하는 일 |
|---|---|
| `viewport` 메타 태그 | 모바일 브라우저가 화면의 실제 폭을 쓰게 만든다 |
| 유연한 단위 | `max-width: 100%` 같은 값으로 한 판이 늘고 준다 |
| 미디어 쿼리 | 폭 같은 조건을 재서 참일 때만 규칙을 갈아 끼운다 |

셋 중에서 유연한 단위가 바탕이다. 요즘의 배치 방식은 유연한 격자를 짠다는 것을 전제로 만들어져 있어서, 있을 수 있는 화면 크기를 하나하나 겨냥해 픽셀을 맞출 필요가 없다.

미디어 쿼리는 조건을 재서 참·거짓을 내는 문장이다. `(min-width: 600px)` 은 `(width >= 600px)` 와 같은 뜻이고, 그 조건이 참인 동안만 안쪽 규칙이 산다. 여기서 재는 `width` 는 화면에 그려지는 영역의 폭이다.

`viewport` 메타 태그가 필요한 이유는 따로 있다. 모바일 브라우저는 폭을 자기 기본값으로 우겨서 페이지를 통째로 줄여 보여준다. `width=device-width` 를 적어야 그 기본값을 실제 화면 폭으로 덮어쓴다.

## 💡 실제 사례

- **이 단어장 앱** — 390px 을 기본 폭으로 잡고 짰다. 화면이 48rem 을 넘으면 본문 폭을 40rem 에 묶고 남는 자리를 여백으로 돌린다.
- **두 칸이 한 칸으로** — 좁은 화면에서는 목록과 본문을 세로로 쌓고, 넓어지면 나란히 세운다. 내용은 그대로고 배치만 바뀐다.
- **그림 넘침 막기** — 이미지에 `max-width: 100%` 를 걸어두면 칸이 좁아질 때 같이 줄어들고, 원래 크기보다 커지지는 않는다.

## 🚫 흔한 오해

- **CSS 만 고치면 반응형이 된다** — HTML 에 `viewport` 메타 태그가 없으면 모바일 브라우저는 폭을 980px 쯤이라고 우기고 페이지를 통째로 줄여 보여준다. 미디어 쿼리는 그 거짓 폭을 잰다.
- **반응형이면 어느 기기에서나 똑같이 보인다** — 같아 보이게 만드는 게 아니다. 화면마다 다르게 배치하는 것이고, 같아야 하는 것은 내용이지 모양이 아니다.
- **반응형은 미디어 쿼리를 잔뜩 넣는 일이다** — 미디어 쿼리는 도움이 되지만 필수는 아니다. 유연한 격자와 상대 단위, 최소·최대값만으로도 반응형이 된다. 끊는 지점을 화면 크기 목록으로 만들면 새 기기가 나올 때마다 줄이 하나씩 늘어난다.

## 🚨 주의사항

- **끊는 자리를 기기 이름으로 잡지 마라.** 미디어 쿼리가 재는 것은 폭이지 기기가 아니다. 특정 기기 크기에 맞춰 끊어두면 그 크기를 벗어난 기기에서 어긋난다.
- **`viewport` 메타 태그를 빠뜨리지 마라.** 이것 하나가 없으면 아래의 모든 규칙이 엉뚱한 폭을 기준으로 잰다.
- **그림도 같이 줄어들게 해라.** 배치는 유연한데 이미지가 고정폭이면 그 이미지 하나가 칸을 밀어내 가로 스크롤을 만든다.

## 📝 정리

반응형은 기술 하나가 아니라 접근 방식이다. 폭을 숫자로 못 박지 않고 비율로 다루면서, 유연함이 무너지는 지점에서만 미디어 쿼리로 규칙을 갈아 끼운다. 좁은 화면을 기본으로 두고 넓은 쪽을 얹으면 아직 나오지 않은 화면 크기도 대개 그냥 받아낸다.

## ❓ 이해했는지

- 미디어 쿼리를 다 써 놨는데 휴대폰에서 페이지가 통째로 줄어들어 보인다. 왜 그런가 → 흔한 오해
- 폭을 960px 로 못 박은 페이지를 390px 화면에서 열면 무엇이 먼저 깨지나 → 해결하는 문제
- 좁은 화면 규칙을 먼저 쓰고 넓은 화면 규칙을 나중에 얹는 방식을 무엇이라 부르나 → 작동 원리
