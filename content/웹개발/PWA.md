# PWA (Progressive Web App)

## 📝 정의

PWA는 **웹 기술로 만들어 기기에 설치되는 앱**이다.

MDN 은 이 말을 "웹 플랫폼 기술로 만들었지만 설치형 앱 같은 사용 경험을 주는 앱" 이라고 적어두었다. 웹사이트처럼 코드 한 벌로 여러 기기에서 돌면서, 설치형 앱처럼 기기에 설치되고 오프라인에서도 돌고 배경에서도 돈다는 것이다.

### 비유
가게에서 사 와 냉장고에 넣어 둔 반찬. 가게가 문을 닫은 밤에도 집에서 꺼내 먹는다.

### 예
홈 화면 아이콘으로 열었더니 주소창 없이 화면을 꽉 채워 뜨는 사이트를 본 적이 있다면 그것이다.

## 🖼️ 그림으로 보기

```도해
대조: 같은 웹 페이지가 PWA 가 되면 무엇이 달라지나
보통 웹 페이지 || PWA
여는 법 :: 브라우저에서 주소로 || 홈 화면 아이콘으로
연결이 끊기면 :: 오류 화면만 뜬다 || 받아둔 화면이 뜬다
화면 :: 브라우저 껍데기 안 || 화면 전체를 쓴다
= 만드는 것은 웹 그대로인데, 열리는 방식이 설치한 앱이 된다
```

## ⚠️ 해결하는 문제

```도해
대조: 웹과 설치형 앱은 서로 무엇을 못 하나
웹사이트 |=| 설치형 앱
코드 :: 한 벌로 어디서나 || OS 마다 따로 짠다
찾는 길 :: 검색·주소로 바로 || 스토어를 거친다
연결 끊길 때 :: 아무것도 못 본다 || 그대로 쓴다
= 둘의 장점이 갈라져 있었다. PWA 는 한쪽을 버리지 않으려는 시도다
```

MDN 은 두 진영의 장점을 따로 적어둔다. 설치형 앱 쪽은 자기 아이콘을 갖고, 사용자가 손대지 않을 때나 연결이 없을 때도 돌고, 브라우저 껍데기 없이 자기 화면을 쓰고, 기기 기능과 운영체제에 붙는다. 웹사이트 쪽은 코드 한 벌로 여러 운영체제와 기기에서 돌고, 검색에 잡히고 주소로 공유되며 스토어 등록 절차가 필요 없다.

문제는 이 둘이 **양쪽을 다 가질 수 없는 선택**처럼 놓여 있었다는 것이다. 웹으로 만들면 아이콘도 오프라인도 못 얻고, 앱으로 만들면 운영체제마다 다시 짜야 했다.

PWA 는 웹으로 만든 것에 설치와 오프라인을 붙여 이 선택을 없앤다. 배포 경로도 둘 다 쓴다 — 스토어에도 올릴 수 있고 웹으로 그냥 열어 둘 수도 있다.

## ⚙️ 작동 원리

```도해
흐름: 처음 열어 본 페이지가 오프라인에서도 열리기까지 무엇을 거치나
첫 방문 :: 브라우저가 매니페스트를 읽는다
등록 :: 페이지가 서비스 워커를 등록한다
저장 :: 워커가 설치될 때 쓸 파일을 받아둔다
설치 :: 사용자가 설치하면 아이콘이 생긴다
실행 :: 시작 주소를 열기 전에 매니페스트를 적용한다
< 워커 :: 연결이 없어도 받아둔 파일로 화면을 낸다
= 매니페스트가 앱처럼 열어 주고, 서비스 워커가 오프라인을 맡는다
```

두 다리가 하는 일이 다르다 — 매니페스트와 [[Service Worker]] 다.

**매니페스트**는 앱의 신원과 겉모습을 적은 JSON 파일이다. W3C 규격은 이것을 "웹 애플리케이션에 딸린 메타데이터를 한군데 모아 두는 곳" 이라고 적고, 이름·아이콘 링크·실행할 때 열 주소·화면 방향·표시 방식이 그 안에 든다고 밝힌다. 설치된 웹앱이 북마크와 갈라지는 지점이 여기다 — 규격은 웹앱을 실행할 때 **시작 주소를 불러오기 전에 매니페스트를 먼저 적용한다**고 정해 두었고, 북마크로 연 페이지에는 그 값이 붙지 않는다고 못 박는다. 그래서 `display` 를 `standalone` 으로 적어두면 브라우저 UI 없이 열린다.

**서비스 워커**는 요청을 가로채는 자리다. 페이지와 네트워크 사이에 앉아 받아둔 응답으로 먼저 답할 수 있어서, 연결이 없어도 화면이 뜬다. 다만 설치의 요건은 아니다 — MDN 은 서비스 워커가 설치 가능 조건에 들어가지는 않지만 많은 PWA 가 오프라인 경험을 주기 위해 쓴다고 적어두었다.

## 💡 실제 사례

- **비행기 모드에서 열리는 이 학습 앱** — 서비스 워커가 설치 때 받아둔 화면과 단어 데이터로 답하므로 연결이 없어도 그대로 뜬다.
- **주소창이 없는 창** — 매니페스트의 `display` 를 `standalone` 으로 적어두면 브라우저 UI 없이 설치형 앱처럼 열린다.
- **스토어에도 올려 둔 같은 앱** — 웹으로 바로 배포하면서 스토어에도 함께 올릴 수 있다. 배포 경로가 하나 늘어나는 것이다.

## 🚫 흔한 오해

- **PWA 를 만들면 스토어 앱은 필요 없다** — 대체가 아니다. MDN 은 PWA 의 장점으로 스토어와 웹 양쪽 배포를 함께 든다. 그리고 설치를 지원하는 정도가 브라우저마다 달라서, 웹만으로 모두에게 아이콘을 꽂아 줄 수는 없다.
- **매니페스트를 넣으면 오프라인에서 돈다** — 설치 요건에 서비스 워커는 들어 있지 않다. 매니페스트는 앱처럼 열리게 할 뿐이고, 오프라인은 워커가 따로 해주는 일이다.
- **홈 화면에 추가한 것은 그냥 북마크다** — 다르다. 설치된 웹앱은 매니페스트에 적은 값이 적용된 채로 열리고, 북마크로 연 페이지에는 그 값이 붙지 않는다.

## 🚨 주의사항

- **`https` 가 아니면 설치되지 않는다.** `localhost` 나 `127.0.0.1` 로 여는 개발 환경만 예외다. 사내 `http` 주소에 올리면 개발 컴퓨터에서만 되고 실제 사용자에게는 설치 단추가 안 뜬다.
- **매니페스트에 빠진 칸이 있으면 설치 대상이 안 된다.** 크로미움 계열은 `name` 또는 `short_name`, 192px 과 512px 아이콘, `start_url`, `display` 를 요구한다.
- **설치를 지원하는 정도가 브라우저마다 다르다.** 데스크톱 Firefox 는 매니페스트로 설치하는 것을 지원하지 않는다. 설치를 전제로 기능을 설계하면 그 사용자들은 길이 막힌다.

## 📝 정리

PWA 는 웹 기술로 만들어 기기에 설치되는 앱이다. 매니페스트가 이름·아이콘·표시 방식을 적어 앱처럼 열리게 하고, 서비스 워커가 요청을 가로채 오프라인을 맡는다. 웹의 배포 방식을 그대로 두고 설치형 앱의 자리까지 얻자는 것이 PWA 의 노림수다.

## ❓ 이해했는지

- 매니페스트만 넣어 배포했는데 비행기 모드에서 안 열린다. 왜인가 → 흔한 오해
- 아이콘으로 열었을 때 주소창이 사라지는 것은 무엇이 시킨 일인가 → 작동 원리
- 같은 웹 페이지가 PWA 가 되면 여는 방식이 어떻게 달라지나 → 그림

## 🔗 관련 용어

- [[Service Worker]] — 오프라인을 맡는 다리. PWA 의 절반이 이것이다
- [[HTTPS]] — 설치의 전제 조건. 개발용 주소 말고는 예외가 없다
- [[Cache]] — 워커가 오프라인에 쓸 응답을 담아두는 곳
- [[SPA]] — PWA 가 흔히 올라타는 화면 구성 방식. 서로 다른 층의 말이다
- [[JavaScript]] — 서비스 워커를 비롯해 PWA 의 동작을 이 언어로 쓴다
