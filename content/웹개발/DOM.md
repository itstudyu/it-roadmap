# DOM (Document Object Model)

## 📝 정의

DOM은 문서를 프로그램이 고칠 수 있게 만든 **객체 트리**다.

이름이 곧 구조다 — Document(문서)를 Object(객체)로 본 Model(모형). 명세는 이것을 "이벤트와 중단 처리, 노드 트리를 위한 플랫폼 중립 모형" 이라고 말하고, MDN 은 "DOM 은 JavaScript 언어의 일부가 아니라 웹 API" 라고 못 박는다.

### 비유
설명서대로 다 조립해 세워 놓은 레고 — 이제 고칠 것은 종이가 아니라 손에 잡히는 블록이다.

### 예
웹페이지에서 오른쪽 클릭하고 검사를 눌렀을 때 옆에 펼쳐지는, 접었다 폈다 하는 목록이 이 트리다.

## 🖼️ 그림으로 보기

```도해
흐름: 글자로 된 문서가 어떻게 만질 수 있는 트리가 되나
원문 :: 태그까지 그냥 글자다
파서 :: 토큰으로 자르고 트리를 세운다
Document :: 트리의 뿌리 객체가 생긴다
마디들 :: 요소와 텍스트마다 객체가 붙는다
스크립트 :: 마디를 찾아 고치고 지운다
= 원문은 한 번 읽히고 끝난다. 그 뒤로 화면의 정체는 이 트리다
```

## ⚠️ 해결하는 문제

```도해
대조: 문서가 글자로만 있으면 무엇을 못 하나
글자로만 || 객체 트리로
찾기 :: 글자를 세어 뒤진다 || 태그로 짚는다
고치기 :: 문자열을 이어 붙인다 || 마디만 바꾼다
깨진 태그 :: 그대로 남는다 || 트리로 정리된다
= 글자에는 안팎이 없다. 트리가 되면 부모와 자식이 생긴다
```

프로그램이 문서를 문자열로만 다룰 수 있다면, "세 번째 문단의 색을 바꿔라" 가 "이 글자 뭉치에서 그 자리를 찾아 잘라 붙여라" 가 된다. 여는 태그와 닫는 태그가 한 짝이라는 사실이 문자열에는 없기 때문이다.

DOM 은 문서를 **트리**로 바꿔 그 문제를 없앤다. 부모와 자식과 형제가 생기고, 마디마다 객체가 있으니 메서드로 찾아 고칠 수 있다. MDN 의 표현으로는 "프로그램이 문서의 구조와 스타일과 내용을 바꿀 수 있도록 페이지를 표현한 것" 이다.

## 🧱 구성

```도해
층: DOM 은 무엇이 무엇을 품고 있나
window :: 창 하나. 그 안에 문서 하나가 들어간다
document :: 문서의 뿌리. 트리 전체가 여기 매달린다
요소 :: 태그 하나가 마디 하나. 요소가 요소를 품는다
텍스트 :: 더 안 쪼개지는 글자. 트리의 맨 끝이다
= 위가 아래를 품는다. 그래서 어느 마디에서든 부모를 거슬러 올라갈 수 있다
```

## ⚙️ 작동 원리

트리라는 형태는 이벤트에서 한 번 더 값을 한다. 명세는 이벤트를 "네트워크 활동이나 사용자 조작 같은 일이 일어났음을 알리려고 객체에 보내는 것" 이라고 정의하고, 그 객체가 트리에 속해 있으면 **그 조상들에 걸린 청취자에도 닿는다**고 규정한다.

그래서 목록 항목이 100개라도 청취자를 100개 달 필요가 없다. 부모 하나에 달아두면 어느 자식에서 일어난 일이든 올라오면서 거기에 걸린다. 항목을 나중에 새로 붙여도 따로 달아줄 것이 없다.

## 💡 실제 사례

- **누르면 화면이 바뀌는 페이지** — 서버를 다시 부르지 않고 트리의 마디만 갈아 끼워 내용을 바꾼다.
- **청취자를 부모에 몰아 달기** — 항목마다 달지 않고 목록 하나에 달아, 올라오는 이벤트를 한자리에서 받는다.
- **원문에 없던 태그가 보이는 일** — `<table>` 안에 `<tr>` 만 적어도 브라우저가 만든 마크업에는 `<tbody>` 가 끼어 있다.

## 🚫 흔한 오해

- **화면에 있는 구조가 내가 쓴 HTML 그대로다** — 파서가 끼워 넣은 태그도, 스크립트가 나중에 만든 마디도 트리에 함께 있다. 원문은 트리를 세우는 재료일 뿐이다.
- **DOM 을 고치면 HTML 파일도 바뀐다** — 파일은 그대로다. 새로 고치면 브라우저가 원문을 다시 읽어 트리를 세우니 손댄 것이 사라진다.
- **DOM 은 JavaScript 의 일부다** — MDN 이 "DOM 은 JavaScript 언어의 일부가 아니라 웹사이트를 만들 때 쓰는 웹 API" 라고 적어 두었다. 명세도 플랫폼 중립 모형이라고 밝힌다.

## 📝 정리

DOM 은 글자로 된 문서를 객체 트리로 바꿔 놓은 모형이다. 그래서 프로그램이 마디를 찾아 고칠 수 있고, 트리라서 이벤트가 조상까지 올라간다. 원문은 그 트리를 한 번 세우는 재료일 뿐, 화면의 정체는 트리 쪽이다.

## ❓ 이해했는지

- 원문에 없던 `<tbody>` 가 브라우저가 만든 마크업에는 왜 들어 있나 → 실제 사례
- 목록 항목이 100개인데 청취자를 하나만 달아도 되는 까닭은 → 작동 원리
- 문단 하나의 색을 바꾸는 일이 문자열로는 왜 어려운가 → 해결하는 문제
