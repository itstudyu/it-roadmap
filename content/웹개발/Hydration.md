# Hydration (하이드레이션)

## 📝 정의

Hydration은 **서버가 보낸 HTML에 동작을 붙여 살리는 일**이다.

이름이 곧 그림이다. 마른 것에 물을 부어 되살리는 일을 가리킨다. 서버가 보낸 HTML은 글자와 모양은 다 갖췄지만 눌러도 아무 일이 없는 마른 상태이고, 자바스크립트가 요소마다 "눌렀을 때 할 일"을 붙이면 그때부터 반응한다.

### 이름
Hydrate :: 마른 것에 물을 붓다
-tion :: ~하는 일
= 붙여 읽으면 "마른 것에 물을 붓는 일". 마른 쪽은 서버가 보낸 HTML 이고, 붓는 물이 자바스크립트다

### 비유
컵라면. 면과 스프는 이미 모양대로 들어 있고, 뜨거운 물을 부어야 먹을 수 있는 상태가 된다.

### 예
쇼핑 화면이 다 떴는데 장바구니 담기를 눌러도 몇 초 동안 아무 반응이 없던 그 순간이다.

### 직접
컴퓨터에서 F12 로 네트워크 칸을 열어 속도를 느린 쪽으로 바꾸고 새로고침한 뒤, 뜨자마자 단추를 눌러 보라. 몇 초는 안 먹는다.

## 🖼️ 그림으로 보기

```도해
흐름: 화면이 벌써 보이는데 왜 눌러도 반응이 없나
서버 :: 글자와 모양이 다 든 HTML 을 보낸다
브라우저 :: 화면은 뜨지만 눌러도 아무 일이 없다
브라우저 :: 자바스크립트 파일을 받아 실행한다
스크립트 :: 같은 화면을 다시 계산해 맞춰 본다
스크립트 :: 요소마다 눌렀을 때 할 일을 붙인다
화면 :: 이제부터 누르면 반응한다
= 다 보이는 화면에 동작만 나중에 얹히는 구간이 있다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버가 보낸 HTML 을 버리고 다시 그리면 어떻게 되나
지우고 다시 그림 || 있는 것에 붙이기
보이던 화면 :: 사라졌다 온다 || 그대로 있다
서버가 채운 값 :: 버려진다 || 그대로 쓴다
받은 HTML :: 껍데기가 된다 || 본체로 쓴다
= 일찍 뜬 화면을 살려 쓰려고 동작만 나중에 붙인다
```

서버가 그려 보낸 화면은 빨리 보이는 대신 죽어 있다. 글자는 읽히는데 버튼도 입력칸도 반응하지 않는다. 그렇다고 브라우저가 화면을 처음부터 다시 만들면, 이미 보이던 것이 지워졌다 다시 나타나서 서버가 일찍 보내준 보람이 없어진다.

Hydration은 받은 [[DOM]]을 지우지 않는다. 같은 화면을 한 번 더 계산해서 어느 요소가 어느 [[Component]]인지 맞춰 본 다음, 그 요소에 동작만 얹는다. 그래서 첫 화면의 속도와 조작 가능한 화면을 둘 다 가진다.

## ⚙️ 작동 원리

브라우저가 처음 계산한 결과는 서버가 보낸 HTML과 **같아야 한다.** 붙일 자리를 그 대조로 찾기 때문이다. 현재 시각처럼 서버와 브라우저에서 다른 값이 나오는 것을 첫 화면에 넣거나, 화면 폭을 재는 것처럼 브라우저에만 있는 기능으로 무엇을 그릴지 정하면 두 결과가 어긋난다. 어긋나면 잘해야 느려지고, 나쁘면 동작이 엉뚱한 요소에 붙는다. React 문서는 이 어긋남을 성능 문제가 아니라 버그로 취급하라고 못 박는다.

서버가 화면을 만들 때 쓴 데이터를 문서 안에 함께 실어 보내는 것도 같은 이유다. 브라우저가 같은 데이터를 다시 요청하지 않고도 같은 결과를 낼 수 있어야 한다.

## 💡 실제 사례

- **뉴스 기사** — 본문은 서버가 보낸 HTML로 즉시 읽히고, 댓글 접기 버튼은 하이드레이션이 끝난 뒤부터 눌린다.
- **검색창** — 입력칸이 보이는데 타이핑이 잠깐 먹지 않는다. 처리기가 아직 안 붙은 구간이다.
- **느린 휴대폰** — 자바스크립트 실행이 느려 이 구간이 몇 초를 넘기기도 한다. 빠른 노트북에서는 안 보였던 문제가 여기서 드러난다.

## 🚫 흔한 오해

- **화면이 보이면 다 된 것이다** — 글자와 모양만 왔을 수 있다. 동작이 붙기 전까지는 눌러도 아무 일이 없다.
- **하이드레이션이 화면을 다시 그린다** — 다시 그리는 게 아니라 이미 있는 요소에 동작만 붙인다. 다시 그리면 보이던 화면이 사라졌다 나온다.
- **서버 렌더링에 하이드레이션을 얹으면 늘 빨라진다** — 빨라지는 것은 첫 화면이 뜨는 시점이다. 같은 화면을 서버와 브라우저에서 두 번 계산하는 셈이라 눌리기까지는 오히려 늦어질 수 있다.

## 📝 정리

**"마른 화면에 동작을 부어 살리는 그 일"** 이라고 읽으면 된다. 그래서 화면은 일찍 보이지만 눌리는 것은 자바스크립트가 실행된 뒤이고, 그 사이가 사용자에게는 먹통으로 느껴진다. 서버와 브라우저가 같은 화면을 내놓아야 이 붙이기가 어긋나지 않는다.

## 🧒 열 살에게

컵라면 뚜껑을 열면 면이랑 스프가 이미 모양대로 다 들어 있지? 그래도 뜨거운 물을 붓기 전에는 못 먹잖아. 화면도 글씨랑 그림은 벌써 다 보이는데, 물 붓는 것 같은 일이 한 번 더 끝나야 눌러도 반응해.

## ❓ 이해했는지

- 화면이 다 보이는데 버튼이 안 먹는 구간이 생기는 이유는 → 그림
- 서버가 보낸 화면을 지우고 처음부터 다시 그리지 않는 이유는 → 해결하는 문제
- 첫 화면에 현재 시각을 그대로 넣으면 무엇이 어긋나나 → 작동 원리

## 🔗 관련 용어

- [[SSR]] — 하이드레이션이 살려낼 HTML을 요청마다 만들어 보내는 쪽
- [[SSG]] — 빌드 때 미리 만들어 둔 HTML도 같은 방식으로 살린다
- [[CSR]] — 붙일 HTML 없이 브라우저가 처음부터 그리는 쪽
- [[DOM]] — 하이드레이션이 손대는 대상. 이미 만들어진 요소에 동작을 건다
- [[Component]] — 동작을 붙일 단위. 서버와 브라우저가 같은 것을 그려야 맞춰진다
