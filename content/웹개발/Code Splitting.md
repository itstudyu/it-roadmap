# Code Splitting (코드 분할)

## 📝 정의

Code Splitting은 **자바스크립트를 나눠 두고 필요할 때 받게 하는 일**이다.

첫 화면을 띄울 때 앱의 자바스크립트를 전부 보내면, 그것을 받고 해석하고 실행하는 시간이 시작 시간에 그대로 얹힌다. 코드 분할은 그 덩어리를 여러 조각으로 나눠 맨 처음에는 꼭 필요한 것만 보내고, 나머지는 **받는 시점**을 그 화면을 열 때까지 미룬다.

### 비유
이삿짐 상자. 전부 한 상자에 넣으면 들 수 없어서 방별로 나눠 담고, 지금 쓸 방 상자만 먼저 푼다.

### 예
앱에서 잘 안 쓰던 메뉴를 처음 눌렀을 때 잠깐 도는 동그라미가 그 조각을 그제야 받는 시간이다.

### 직접
컴퓨터 브라우저에서 F12 를 눌러 네트워크 칸을 열어 둔 채 안 쓰던 메뉴를 눌러 보라. 그 순간 새 파일이 하나 더 떨어진다.

## 🖼️ 그림으로 보기

```도해
흐름: 첫 화면에 필요 없는 코드는 언제 받나
빌드 :: 코드를 화면 단위 덩어리로 나눈다
첫 화면 :: 지금 그릴 덩어리만 받아 실행한다
사용자 :: 설정 메뉴를 누른다
브라우저 :: 그때 설정 덩어리를 요청한다
< 브라우저 :: 받은 덩어리를 실행해 화면에 넣는다
= 다 받아 두는 대신, 필요해진 시점에 나눠 받는다
```

## ⚠️ 해결하는 문제

```도해
대조: 첫 화면에 안 쓰는 코드까지 다 받으면 무엇이 걸리나
한 덩어리로 || 나눠서
받는 양 :: 전부 || 첫 화면 몫만
해석과 실행 :: 안 쓸 것까지 || 쓸 것만
입력 반응 :: 그동안 밀린다 || 덜 밀린다
= 시작이 늦는 것은 첫 화면과 무관한 코드까지 실행하기 때문이다
```

덩어리가 커지면 받는 시간만 늘어나는 것이 아니다. 받은 것을 해석하고 실행하는 동안 브라우저의 일손 하나가 거기에 붙잡혀서, 화면이 떠도 그 사이에 누른 것은 뒤늦게 처리된다. 3초를 넘기면 절반이 넘는 사용자가 떠난다는 조사가 이 시간을 아끼는 이유다.

코드 분할은 첫 화면에 쓰는 것만 남기고 나머지를 따로 떼어 둔다. 떼어낸 덩어리는 그 화면을 열 때 비로소 요청되므로, 끝까지 안 열면 끝까지 받지 않는다.

## ⚙️ 작동 원리

경계를 만드는 것은 `import('./설정')` 처럼 괄호를 붙여 쓰는 동적 불러오기다. 이 식은 모듈을 그 자리에서 바로 들여오지 않고 나중에 받아오겠다는 약속을 돌려주며, [[Build]] 도구가 그 자리를 경계로 삼아 파일을 쪼갠다. 조건이 맞을 때만, 또는 나중에 필요할 때만 받고 싶은 코드가 이걸 쓴다.

React의 `lazy`는 그 동적 불러오기를 [[Component]]로 감싼 것이다. 처음 그려질 때까지 코드를 받지 않고, 받는 동안에는 `<Suspense>`에 적어둔 대기 화면을 보여준다.

## 💡 실제 사례

- **경로 단위 분할** — 주소마다 덩어리를 따로 두고, 그 주소로 옮겨갈 때 받는다. 가장 무난한 경계다.
- **무거운 편집기** — 문서를 읽는 화면은 가볍게 띄우고, 편집 버튼을 누른 뒤에 편집기 코드를 받는다.
- **관리자 화면** — 일반 사용자는 한 번도 열지 않는 화면이라 첫 덩어리에서 아예 빼 둔다.

## 🚫 흔한 오해

- **잘게 쪼갤수록 빨라진다** — 조각이 늘면 요청과 대기 화면도 늘어난다. 목적은 조각 수를 늘리는 것이 아니라 첫 화면과 무관한 코드를 첫 화면에서 빼는 것이다.
- **코드 분할이 코드 양을 줄여준다** — 총량은 그대로다. 언제 받을지를 옮기는 것뿐이다.
- **파일을 여러 개로 나눠 두면 코드 분할이다** — 나누기만 해서는 아니다. 첫 화면이 그 파일들을 전부 불러오면 받는 시점은 하나도 안 바뀐다.

## 🚨 주의사항

- **경계는 경로부터 잡는다.** 화면 단위로 먼저 나누는 것이 가장 간단하고, 그다음에 무거운 조각을 따로 뗀다.
- **`lazy`를 컴포넌트 안에서 선언하지 마라.** 다시 그릴 때마다 새로 만들어져서 그 안의 상태가 초기화된다. 파일 맨 바깥에 선언한다.

## 📝 정리

**"쓸 때가 되어야 받게 미뤄 두는 그 쪼개기"** 라고 읽으면 된다. 총량을 줄이는 것이 아니라 받고 실행하는 시점을 옮기는 것이다. 조각을 늘리는 데 목적이 있는 것이 아니라 첫 화면과 무관한 코드를 첫 화면에서 빼는 데 있다.

## 🧒 열 살에게

이사할 때 짐을 한 상자에 다 넣으면 무거워서 못 들지? 그래서 방마다 상자를 나눠 담고, 오늘 잘 방 상자만 먼저 풀어. 안 쓰는 방 상자는 그 방에 들어가는 날까지 그냥 묶어 둬.

## ❓ 이해했는지

- 파일을 여러 개로 나눠 뒀는데도 첫 화면이 안 빨라졌다면 무엇을 봐야 하나 → 흔한 오해
- 설정 화면 코드를 첫 덩어리에서 뺐다면 그 코드는 언제 받게 되나 → 그림
- 무거운 화면을 받는 동안 대기 표시를 띄우려면 무엇으로 감싸나 → 작동 원리
