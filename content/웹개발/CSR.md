# CSR (Client Side Rendering)

## 📝 정의

CSR은 **브라우저가 자바스크립트로 화면을 그리는 방식**이다.

서버는 거의 빈 HTML과 자바스크립트 파일만 내려주고, 화면에 무엇을 어떻게 놓을지는 브라우저 안에서 정해진다. 서버는 그리는 일에서 빠지고 데이터만 넘긴다.

### 비유
조립식 가구. 상자에는 부품과 설명서만 들어 있고, 완성된 모양은 집에서 만들어진다.

## 🖼️ 그림으로 보기

```도해
흐름: 주소를 열면 화면이 언제 나타나나
서버 :: 거의 빈 HTML 을 내려준다
브라우저 :: 아직 화면에 아무것도 없다
브라우저 :: 자바스크립트 묶음을 내려받는다
스크립트 :: 실행되면서 화면을 만들어 넣는다
< 브라우저 :: 이후 화면 이동은 서버 없이 처리한다
= 첫 화면이 늦게 뜨는 대신 그다음 이동이 빨라진다
```

## ⚠️ 해결하는 문제

```도해
대조: 화면을 옮길 때마다 서버가 다시 그리면 어떻게 되나
서버가 매번 그림 || CSR 로
화면 이동 :: 전체를 다시 받음 || 바뀐 부분만
서버 부담 :: 요청마다 조립 || 파일만 내려줌
조작 반응 :: 왕복을 기다림 || 바로 반응한다
= 그리는 일을 브라우저로 옮기면 첫 화면만 늦고 그다음이 빨라진다
```

서버가 매번 완성된 HTML을 만들어 보내면, 메뉴를 누를 때마다 헤더와 사이드바까지 통째로 다시 받는다. 이미 화면에 있던 것을 지우고 거의 같은 것을 다시 그리는 셈이다.

CSR은 화면 틀을 브라우저에 한 번만 만들어두고, 이동할 때는 바뀐 데이터만 받아 그 부분만 갈아 끼운다. 서버가 하는 일은 파일과 데이터를 내주는 것으로 줄어든다.

## ✅ 장단점

**얻는 것**
- 서버가 화면을 조립하지 않으니 요청당 하는 일이 줄어든다.
- 화면 이동이 왕복을 기다리지 않아 앱처럼 반응한다.

**내주는 것**
- 첫 화면이 늦다. 자바스크립트를 다 받고 실행할 때까지 빈 화면이다.
- 서버가 준 HTML에는 내용이 없어서 검색 노출에 불리하다.

## 💡 실제 사례

- **관리자 화면** 로그인한 사람만 쓰고 검색에 잡힐 필요도 없어서 CSR이 잘 맞는다.
- **대시보드** 필터를 바꿀 때마다 데이터만 새로 받고 화면 틀은 그대로 둔다.
- **상품 상세 페이지** 검색 결과에 떠야 하는 화면은 CSR만으로 불리해서 서버에서 그리는 방식을 섞는다.

## 🚫 흔한 오해

- **CSR이 SSR보다 빠르다** — 첫 화면은 대개 더 느리다. 빨라지는 건 화면을 이미 띄운 뒤의 이동이다.
- **자바스크립트를 쓰면 CSR이다** — 서버가 완성된 HTML을 보내고 자바스크립트는 동작만 붙이는 경우는 CSR이 아니다. 화면을 누가 만드느냐가 기준이다.
- **CSR로 만들면 검색에 아예 안 잡힌다** — 불리한 것과 불가능한 것은 다르다. 그래서 노출이 필요한 화면만 서버에서 그리는 식으로 섞어 쓴다.

## 📝 정리

CSR은 서버가 빈 껍데기만 주고 브라우저가 자바스크립트로 화면을 그리는 방식이다. 첫 화면이 뜨기까지 시간을 내주는 대신 그 뒤의 이동과 반응을 얻는다. 검색 노출이 필요한 화면에는 서버에서 그리는 방식을 섞는 것이 보통이다.

- 검색 결과에 떠야 하는 페이지를 CSR로만 만들면 무엇이 걸리나?
