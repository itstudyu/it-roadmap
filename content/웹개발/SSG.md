# SSG (Static Site Generation)

## 📝 정의

SSG는 **요청이 오기 전에 HTML을 미리 만들어 두는 방식**이다.

[[SSR]]과 [[CSR]]이 갈리는 지점은 "화면을 누가 조립하나"였다. SSG가 갈리는 지점은 "언제 조립하나"다. 요청이 올 때도 브라우저에서도 아니고, 빌드할 때 주소마다 HTML 파일을 하나씩 만들어 둔다.

### 비유
미리 인쇄해 쌓아둔 안내문. 손님이 올 때마다 새로 적지 않고 쌓아둔 것에서 한 장 집어 준다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청이 오기 전에 화면을 만들어 두면 어떻게 되나
빌드 :: 주소마다 HTML 을 한 번씩 만든다
파일 :: 주소 하나에 완성된 파일 하나가 남는다
CDN :: 그 파일들을 여러 지역에 복사해 둔다
사용자 :: 주소를 연다
< 브라우저 :: 이미 있던 파일을 그대로 받아 그린다
= 만드는 시점을 요청보다 앞으로 당겨 두는 것이 SSG 다
```

## ⚠️ 해결하는 문제

```도해
대조: 안 바뀌는 화면을 요청마다 새로 만들면 무엇이 걸리나
요청마다 만들기 || 미리 만들어 두기
같은 화면 :: 올 때마다 조립 || 한 번만 조립
첫 응답 :: 만들 때까지 기다림 || 있는 것을 보낸다
받는 곳 :: 그 서버에서 || 가까운 CDN 에서
= 결과가 같을 화면을 매번 다시 만들 이유가 없다
```

문서나 소개 페이지는 사용자가 누구든 같은 화면이 나온다. 그런데 요청이 올 때 조립하는 방식은 그 같은 결과를 접속자 수만큼 다시 만든다. 만드는 데는 시간이 걸리므로 첫 응답이 시작되는 시점도 그만큼 밀린다.

SSG는 그 조립을 **빌드할 때 한 번**으로 끝낸다. 남는 것은 주소마다 하나씩 만들어진 HTML 파일이고, 요청에 대고 하는 일은 그 파일을 내주는 것뿐이다. 파일이라서 여러 지역의 [[CDN]]에 미리 복사해 두고 가까운 곳에서 내보낼 수도 있다.

## 📊 비교: SSG vs SSR vs CSR

| | SSG | SSR | CSR |
|---|---|---|---|
| 만드는 시점 | 빌드할 때 | 요청이 올 때 | 브라우저에서 |
| 사람마다 다른 화면 | 안 맞는다 | 맞는다 | 맞는다 |
| 내용을 고쳤을 때 | 다시 빌드해야 | 바로 반영된다 | 바로 반영된다 |
| 요청당 서버가 하는 일 | 파일만 내준다 | 조립한다 | 파일만 내준다 |

만드는 시점이 이르면 요청당 하는 일이 줄고, 늦으면 최신 데이터와 사람마다 다른 화면을 담을 수 있다. SSG를 고르는 것은 그 두 번째를 내놓겠다는 뜻이다.

## 💡 실제 사례

- **문서 사이트** — 내용이 배포할 때만 바뀌니 빌드 때 만들어 두고 요청에는 파일만 내준다.
- **블로그 글 목록** — 글마다 주소가 정해져 있어서 글 수만큼 HTML을 미리 만들어 둔다.
- **로그인 후 대시보드** — 사람마다 내용이 달라 미리 만들 수 없다. 이 화면은 SSR이나 CSR로 넘긴다.

## 🚫 흔한 오해

- **SSG가 더 빠르니 전부 SSG로 만들면 된다** — 사람마다 다른 화면은 미리 만들 수 없다. 미리 만들 주소를 다 예측할 수 없는 사이트에서도 쓰기 어렵다.
- **한 번 만들어 두면 내용이 알아서 갱신된다** — 빌드 시점의 데이터가 파일에 그대로 굳는다. 새 내용은 다시 빌드해서 파일을 갈아야 나온다.
- **미리 만들었으니 자바스크립트가 필요 없다** — 화면을 그리는 데만 필요 없다. 버튼과 입력이 동작하려면 받은 HTML에 동작을 붙이는 [[Hydration]]이 뒤따른다.

## 🚨 주의사항

- **주소 수만큼 파일이 생긴다.** 페이지가 수만 개면 미리 만들 주소를 전부 예측해야 하고, 빌드 시간도 그만큼 늘어난다.
- **바뀌는 값을 굳히지 마라.** 재고 수량이나 잔여 좌석처럼 자주 바뀌는 값을 빌드 때 박아두면 낡은 숫자를 보여준다.

## 📝 정리

SSG는 요청보다 앞선 빌드 시점에 주소마다 HTML을 만들어 두는 방식이다. 조립을 한 번으로 줄이는 대신 미리 만들 주소가 정해져 있어야 하고, 내용이 바뀌면 다시 빌드해야 한다. 사람마다 다른 화면에는 쓸 수 없다.

## ❓ 이해했는지

- 로그인한 사람마다 다른 대시보드를 SSG로 만들 수 없는 이유는 → 흔한 오해
- 글을 고쳤는데 사이트에는 옛 내용이 그대로인 이유는 → 주의사항

## 🔗 관련 용어

- [[SSR]] — 같은 HTML을 요청이 올 때 만드는 쪽

- [[Hydration]] — 미리 만든 HTML에 동작을 붙이는 다음 단계
