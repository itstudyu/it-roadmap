# Webhook (웹훅)

## 📝 정의

Webhook은 **일이 생겼을 때 서버가 먼저 알려주는 방식**이다.

보통은 필요한 쪽이 상대를 부른다. 웹훅은 반대로 알릴 것이 생긴 쪽이 미리 등록해둔 주소로 요청을 보낸다. 그래서 역방향 API라고도 부른다.

### 이름
Web :: 인터넷 주소로
Hook :: 걸어 두는 고리
= 붙여 읽으면 "인터넷 주소에 걸어 두는 고리". 일이 생기면 그 고리가 당겨져 알림이 온다

### 비유
택배 도착 알림. 매시간 문 앞을 내다보는 대신, 도착했을 때 문자가 온다.

### 예
결제를 마치자마자 주문 상태가 결제완료로 바뀌어 있는 것은 결제 쪽에서 먼저 알려준 결과다.

### 직접
`webhook.site` 를 열면 나만 쓰는 주소가 하나 생긴다. 그 주소를 다른 창에 붙여 넣어 열면 방금 그 요청이 화면에 그대로 찍힌다.

## 🖼️ 그림으로 보기

```도해
흐름: 결제가 끝났다는 사실이 어떻게 전해지나
받는 쪽 :: 미리 "여기로 보내달라" 며 주소를 등록한다
결제 서비스 :: 결제가 승인되는 순간 이벤트가 생긴다
전송 :: 등록된 주소로 결제 내용을 담아 POST 한다
받는 쪽 :: 서명을 확인하고 주문 상태를 바꾼다
< 응답 :: 잘 받았다는 뜻으로 200 을 돌려준다
= 물으러 가지 않는다. 생긴 쪽에서 먼저 온다
```

## ⚠️ 해결하는 문제

```도해
대조: 계속 물어보는 방식이면 어떻게 되나
1분마다 묻기 || 웹훅으로
요청 수 :: 하루 1440번 || 생길 때 1번
헛걸음 :: 대부분 없다는 답 || 없다
알기까지 :: 최대 1분 늦음 || 거의 바로
= 언제 생길지 모르는 일은 생긴 쪽이 알리는 게 싸다
```

결제가 언제 끝날지 모르니 1분마다 물어본다고 하자. 하루에 1440번을 묻고 그중 대부분은 아무 일도 없다는 답을 받는다. 요청을 받는 쪽도 그 헛걸음을 다 처리해야 한다.

간격을 좁히면 부하가 늘고, 넓히면 알아채는 게 늦어진다. 웹훅은 이 저울질을 없앤다. 일이 생긴 순간에만 한 번 요청이 오간다.

## ⚙️ 작동 원리

```도해
흐름: 보낸 알림이 도착하지 않으면 어떻게 되나
전송 :: 등록된 주소로 알림을 POST 한다
받는 쪽 :: 서명을 먼저 확인하고 내용을 처리한다
응답 :: 잘 받았으면 200 을 돌려준다
보낸 쪽 :: 200 이 없으면 실패로 본다
@ 다시 보내기 :: 간격을 늘려가며 될 때까지 되풀이한다
= 그래서 같은 알림이 두 번 도착할 수 있다
```

웹훅 한 번에는 네 가지가 실린다. 받는 쪽이 미리 등록해둔 **주소**, 무슨 일이 있었는지 담은 **페이로드**, 정말 그쪽이 보낸 것인지 확인할 **서명**, 그리고 잘 받았다는 **응답** 이다. 이 넷이 갖춰져야 가짜 알림과 유실을 둘 다 막는다.

받는 주소는 인터넷에서 닿을 수 있어야 한다. 그래서 아무나 그 주소로 가짜 알림을 보낼 수 있고, 보낸 쪽만 만들 수 있는 서명을 같이 실어 보내 이를 가린다. 받는 쪽은 서명을 먼저 확인하고 나서 내용을 처리한다.

응답이 없거나 오류가 오면 보낸 쪽이 다시 보낸다. 간격을 늘려가며 재시도하는 것이 보통이라, 받는 서버가 잠깐 멈춰 있었어도 뒤늦게 도착한다. 대신 같은 알림이 두 번 올 수 있으므로 같은 것을 두 번 처리해도 결과가 같도록 만들어야 한다.

## 💡 실제 사례

- **저장소에 푸시** — 코드를 올리면 그 알림을 받아 빌드와 배포 흐름이 자동으로 시작된다.
- **결제 완료** — 결제 서비스가 알려주면 쇼핑몰이 주문을 결제완료로 바꾸고 배송 준비로 넘긴다.
- **PR 생성** — 새 Pull Request가 열리면 팀 채널에 글이 올라가 바로 검토가 시작된다.

## 🚫 흔한 오해

- **웹훅은 API의 한 종류다** — 부르는 방향이 반대다. API는 내가 필요할 때 상대를 부르지만 웹훅은 상대가 내 서버를 부른다. 그래서 받을 주소가 바깥에서 닿을 수 있어야 한다.
- **웹훅은 연결을 계속 열어둔다** — 일이 생길 때 요청 한 번을 보내고 끊는다. 계속 붙어 있는 것은 WebSocket 쪽이고, 웹훅은 평소에 아무 연결도 없다.
- **보냈으면 도착했을 것이다** — 받는 쪽이 죽어 있으면 못 받는다. 그래서 간격을 늘려가며 다시 보내고, 그 탓에 같은 알림이 두 번 도착하기도 한다.

## 📊 비교

| | 웹훅 | 폴링 | WebSocket |
|---|---|---|---|
| 누가 먼저 부르나 | 알릴 쪽이 | 알고 싶은 쪽이 | 양쪽 다 |
| 연결 | 그때만 열린다 | 그때만 열린다 | 계속 열어둔다 |
| 헛요청 | 없다 | 대부분이 헛걸음 | 없다 |
| 어디에 쓰나 | 가끔 생기는 사건 | 간단한 상태 확인 | 채팅처럼 잦은 주고받기 |

## 📝 정리

**"생긴 쪽이 먼저 알려 주는 그 방식"** 이라고 읽으면 된다. 물어보러 가는 헛걸음이 없어지는 대신, 받는 주소가 바깥에 열려 있어야 하고 서명 확인과 중복 처리를 받는 쪽에서 맡아야 한다.

## 🧒 열 살에게

택배가 언제 오나 궁금하다고 십 분마다 문 앞에 나가 보면 힘들지? 그래서 미리 내 번호를 적어 두면 물건이 도착한 그때 문자가 와. 인터넷에서도 그렇게 미리 주소를 적어 두면 일이 생긴 쪽에서 먼저 알려 줘서, 물어보러 갈 일이 아예 없어.
