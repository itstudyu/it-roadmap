# HTTP Status Code (HTTP 상태 코드)

## 📝 정의

HTTP 상태 코드는 **서버가 요청 결과를 알리는 세 자리 숫자**다.

첫 자리가 분류를 맡는다. 2 로 시작하면 됐다는 뜻, 4 로 시작하면 보낸 쪽 잘못, 5 로 시작하면 받은 쪽 잘못이다. 처음 보는 코드도 첫 자리만 보면 다음에 무엇을 할지 정할 수 있다.

### 이름
HTTP :: 웹에서 오가는 약속
Status :: 지금 어떻게 됐는지
Code :: 짧게 줄인 숫자
= 붙여 읽으면 "웹 약속에서 결과를 짧게 줄인 숫자". 첫 자리가 곧 분류다

### 비유
택배 상태 알림. 배송 완료인지, 주소가 잘못됐는지, 배송사 사정인지를 한 줄로 알려준다.

### 예
주소를 잘못 눌러 404 라는 숫자와 함께 페이지를 찾을 수 없다는 화면을 만난 적이 있다.

### 직접
개발자 도구 네트워크 탭을 열어 둔 채 아무 사이트나 새로 고쳐 보라. 줄마다 200·304·404 같은 숫자가 찍혀 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 요청 하나가 어느 단계에서 어떤 숫자를 받나
주소 확인 :: 그런 자원이 없으면 404
로그인 확인 :: 로그인을 안 했으면 401
권한 확인 :: 로그인은 했는데 권한이 없으면 403
입력 확인 :: 보낸 값이 잘못됐으면 400
처리 :: 처리하다 서버가 터지면 500
< 응답 :: 여기까지 통과하면 200 이나 201
= 앞 단계에서 걸릴수록 서버는 일을 덜 한 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 결과를 본문 글로만 알려주면 어떻게 되나
숫자가 없으면 || 상태 코드로
성공 판단 :: 본문을 읽어야 || 숫자만 보면 됨
잘못한 쪽 :: 알 수 없다 || 4 와 5 로 구분
자동 처리 :: 서비스마다 다름 || 어디서나 동일
= 기계가 읽을 결과와 사람이 읽을 설명을 분리한 것이다
```

응답 본문에 "처리되었습니다" 같은 문장만 있으면 그 판단을 프로그램이 할 수 없다. 서비스마다 문구가 다르고 언어도 다르고, 오류 문구가 바뀌면 그 문구를 보고 있던 코드가 같이 깨진다.

상태 코드는 이 판단을 숫자로 떼어낸다. 브라우저가 3xx 를 받으면 알아서 새 주소로 다시 요청하고, 앱이 401 을 받으면 로그인 화면을 띄운다. 사람이 읽을 설명은 본문에 따로 담으면 된다.

## ⚙️ 작동 원리

서버는 요청을 받고 순서대로 확인한다. 그 주소에 해당하는 것이 있는지, 요청자가 누구인지, 그 사람에게 권한이 있는지, 보낸 값이 규칙에 맞는지를 보고, 어느 단계에서 걸리느냐에 따라 다른 숫자를 돌려준다.

숫자와 함께 헤더도 같이 온다. 3xx 에는 어디로 가라는 주소가, 429 에는 얼마 뒤에 다시 오라는 값이, 201 에는 새로 만들어진 자원의 주소가 헤더에 실린다. 숫자만으로 부족한 정보를 여기서 채운다.

## 📊 비교: 자주 만나는 코드

| 코드 | 뜻 | 언제 |
|---|---|---|
| 200 | 성공 | 요청한 대로 처리됐다 |
| 201 | 만들어짐 | 새 자원을 만든 직후 |
| 301 | 영구 이동 | 주소가 아주 바뀌었다 |
| 302 | 임시 이동 | 잠깐만 다른 곳으로 |
| 400 | 잘못된 요청 | 값이나 형식이 틀렸다 |
| 401 | 인증 필요 | 누구인지 모르겠다 |
| 403 | 접근 금지 | 누군지는 아는데 권한이 없다 |
| 404 | 없음 | 그 주소에 해당하는 게 없다 |
| 429 | 너무 잦음 | 정해둔 횟수를 넘겼다 |
| 500 | 서버 오류 | 처리하다 예외가 났다 |
| 503 | 이용 불가 | 점검이나 과부하로 잠시 못 받는다 |

## 💡 실제 사례

- **사이트 개편** — 옛 주소에 301 을 두면 링크가 살아 있고 검색 순위도 새 주소로 넘어간다.
- **호출 제한** — 정해진 횟수를 넘긴 요청에 429 와 함께 언제 다시 오라는 값을 준다.
- **앱의 분기 처리** — 401 이면 로그인 화면으로 보내고, 5xx 면 잠시 뒤 다시 시도한다.

## 🚫 흔한 오해

- **404 가 뜨면 서버가 고장 난 것이다** — 서버는 정상으로 답한 것이다. 그 주소에 해당하는 게 없다는 답이고, 서버가 고장 난 경우는 500 쪽이다.
- **401 과 403 은 같은 말이다** — 401 은 누구인지 모르겠다는 뜻이고 403 은 누군지는 아는데 권한이 없다는 뜻이다. 401 은 로그인하면 풀리지만 403 은 로그인해도 안 풀린다.
- **200 이 왔으니 잘된 것이다** — 오류를 본문에만 담고 200 을 주는 서버가 있다. 그러면 받는 쪽 프로그램은 실패를 성공으로 처리한다.

## 🚨 주의사항

- **4xx 는 그대로 다시 보내도 소용없다.** 보낸 쪽이 고쳐야 풀리는 오류라, 재시도를 붙이려면 5xx 와 429 에만 붙인다.
- **오류 본문에 내부 정보를 담지 않는다.** 500 응답에 예외 추적이나 질의문을 그대로 내보내면 공격에 쓸 재료를 주는 셈이다.

## 📝 정리

**"결과를 세 자리 숫자로 줄여 알리는 답"** 이라고 읽으면 된다. 사람이 읽을 설명은 본문에 두고, 프로그램이 볼 판단만 숫자로 떼어 놓은 것이다. 첫 자리가 분류를 맡아서, 처음 보는 숫자도 그 자리만 보면 다음에 무엇을 할지 정해진다.

## 🧒 열 살에게

택배 앱에 "도착했어요", "주소가 틀렸어요", "차가 고장 났어요" 처럼 짧게 뜨는 거 봤지? 인터넷에서도 뭘 달라고 할 때마다 그런 짧은 숫자가 하나씩 붙어서 와. 그 숫자만 보면 잘된 건지, 내가 잘못 적은 건지, 저쪽 사정인지 바로 갈라져.

## ❓ 이해했는지

- 401 은 로그인하면 풀리는데 403 은 왜 로그인해도 안 풀리나 → 흔한 오해
- 사이트 주소를 아주 옮길 때 301 과 302 중 무엇을 쓰나 → 비교
- 500 은 재시도해도 되고 400 은 안 되는 이유는 → 주의사항
