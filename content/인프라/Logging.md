# 로그 / 로깅 (Log / Logging)

## 📝 정의

로그(Log)는 애플리케이션과 시스템의 동작 과정에서 발생하는 **모든 사건과 상태 변화를 기록한 데이터**입니다. 로깅(Logging)은 이러한 로그를 체계적으로 생성, 수집, 저장, 분석하는 행위를 말합니다. 로그는 소프트웨어 개발에서 가장 중요한 도구 중 하나로, 문제 해결(디버깅), 성능 모니터링, 보안 감시, 법적 감사 등에 필수적입니다.

로깅의 핵심은 시스템의 **"검은 상자"를 투명하게 만드는 것**입니다. 프로그램이 어떤 결정을 내렸고, 어떤 데이터를 처리했으며, 어디서 실패했는지 추적할 수 있게 합니다. 효과적인 로깅은 문제를 재현하지 않고도 원인을 파악할 수 있게 해주는 강력한 도구입니다.

> **한 줄 요약**: 시스템과 애플리케이션의 동작 기록을 생성하고 관리하여 디버깅, 모니터링, 감사에 활용하는 기술

**비유 1**: 로깅은 항공기의 블랙박스와 같습니다. 비행 중 발생한 모든 데이터(고도, 속도, 경고음, 조종사 음성 등)를 기록하여, 사고가 발생했을 때 원인을 파악할 수 있게 합니다.

**비유 2**: 로깅은 병원의 의료 기록(EMR)과 같습니다. 환자의 방문 기록, 처방약, 검사 결과 등을 모두 기록해두어야 의료진이 환자의 상태를 정확히 파악하고 적절한 치료를 할 수 있습니다.

## 🎯 핵심 개념

### 1. 로그 레벨 (Log Level)
로그 레벨은 로그의 **중요도와 심각성을 나타내는 계층 구조**입니다. 낮은 레벨부터 높은 레벨까지:
- **DEBUG**: 개발자가 디버깅을 위해 상세한 정보 출력
- **INFO**: 일반적인 정보성 메시지 (애플리케이션 시작, 중요 이벤트)
- **WARN**: 경고 메시지 (문제가 될 가능성 있음)
- **ERROR**: 오류 발생 (시스템이 여전히 작동하지만 기능 일부 실패)
- **FATAL/CRITICAL**: 치명적 오류 (시스템이 더 이상 작동할 수 없음)

### 2. 구조화된 로그 vs 비구조화 로그
- **구조화 로그**: JSON 형식으로 필드가 명확하게 구분된 로그 (예: `{"timestamp": "2024-01-15", "level": "ERROR", "service": "payment", "message": "..."}`)
- **비구조화 로그**: 일반 텍스트 형식의 로그 (예: `2024-01-15 10:30:45 ERROR Payment service failed to process order`)

구조화 로그는 검색과 분석이 훨씬 쉬워서 현대적 로깅 시스템에서 선호됩니다.

### 3. 로그 수집 및 관리 도구
로그를 효율적으로 관리하기 위해 ELK Stack (Elasticsearch + Logstash + Kibana), CloudWatch, Datadog, Splunk 같은 도구들이 사용됩니다. 이들은 대규모 로그를 수집, 처리, 저장, 시각화하는 기능을 제공합니다.

## ⚠️ 해결하는 문제

### 문제 1: 프로덕션 환경에서의 문제 원인 파악 불가
개발 환경에서는 디버거를 이용해 실시간으로 코드 실행을 추적할 수 있지만, 프로덕션 환경에서는 불가능합니다. 사용자가 보고한 오류를 재현하기 위해 몇 시간을 낭비할 수 있습니다. 체계적인 로깅 없이는 실시간 문제 파악이 거의 불가능합니다.

### 문제 2: 성능 저하와 병목 지점 미파악
시스템이 느려지면 어느 부분이 문제인지 알 수 없습니다. API 응답이 느린가? 데이터베이스 쿼리가 느린가? 네트워크 지연인가? 각 단계마다 로그를 남겨야만 병목 지점을 식별할 수 있습니다.

## ⚙️ 작동 원리

1. **로그 생성**: 애플리케이션 코드의 특정 지점에서 로그 문장을 작성합니다. 예: `logger.info("User logged in: userId=123")`

2. **로그 레벨 확인**: 로깅 라이브러리(Log4j, SLF4J, Winston 등)가 설정된 로그 레벨에 따라 어떤 로그를 출력할지 결정합니다. 예를 들어 운영 환경의 최소 레벨이 INFO라면, DEBUG 로그는 출력되지 않습니다.

3. **로그 포맷 적용**: 설정된 포맷에 따라 타임스탬프, 로그 레벨, 메시지 등을 조합하여 최종 로그 메시지를 생성합니다.

4. **로그 출력 및 전달**: 로그를 콘솔, 파일, 또는 네트워크를 통해 로그 수집 시스템으로 전송합니다.

5. **로그 수집**: Logstash, Filebeat 같은 수집 도구가 여러 소스에서 로그를 수집합니다.

6. **로그 처리 및 저장**: 로그를 파싱하고, 필요한 필드를 추출하고, Elasticsearch 같은 데이터베이스에 저장합니다.

7. **로그 검색 및 분석**: Kibana 같은 도구를 이용해 로그를 검색하고, 대시보드를 생성하고, 문제를 분석합니다.

8. **알림 및 대응**: 특정 조건(예: ERROR 로그 10개 이상)을 감지하면 자동으로 알림을 발송합니다.

## ✅ 장단점

**장점:**
- **빠른 문제 해결**: 장애 발생 시 원인을 빠르게 파악할 수 있어 MTTR(Mean Time To Recovery) 단축
- **성능 최적화**: 병목 지점을 정확히 식별하여 최적화 작업 진행 가능
- **감시 및 모니터링**: 시스템 건강 상태를 실시간으로 감시 가능
- **보안 감시**: 비정상적인 접근 시도, 데이터 유출 등을 감지 가능
- **규정 준수**: 금융, 의료, 법적 감사 요구사항을 충족
- **사용자 행동 분석**: 사용자의 행동 패턴을 이해하여 제품 개선
- **장기 트렌드 분석**: 장시간 수집된 로그로부터 패턴과 트렌드 발견

**단점:**
- **성능 오버헤드**: 로그 기록이 시스템 성능을 저하시킬 수 있음 (특히 DEBUG 레벨)
- **저장 공간 증가**: 대규모 시스템에서 로그량이 매우 많아 저장 비용 증가
- **개인정보 보호 우려**: 로그에 민감한 정보(비밀번호, 신용카드번호 등)가 포함될 위험
- **복잡한 분석**: 대량의 로그에서 의미 있는 정보를 추출하기 어려움
- **로그 순서 보장 어려움**: 분산 시스템에서 여러 서버의 로그를 동기화하기 복잡
- **높은 도구 비용**: ELK, Datadog 같은 로그 관리 도구의 라이선스 비용 증가
- **클라우드 비용**: 대량 로그 전송, 저장, 분석에 클라우드 비용 증가

## 💡 실제 사례

### 사례 1: API 오류 추적
사용자가 "주문 결제에 실패했습니다"라고 보고합니다. 로그 관리 시스템에서 다음과 같이 검색합니다:
```
timestamp: "2024-01-15 14:32:18"
service: "payment-service"
level: "ERROR"
userId: "user_12345"
```

로그에서 다음을 발견합니다:
- 14:32:10 - 결제 API 호출
- 14:32:11 - 외부 결제 게이트웨이 접속 실패 (타임아웃)
- 14:32:18 - 재시도 후에도 실패, 오류 메시지 기록

이를 통해 외부 결제 게이트웨이의 장애가 원인임을 5분 안에 파악합니다.

### 사례 2: 성능 저하 진단
운영팀이 "오늘 오후 3시 이후로 사이트가 느려졌습니다"라고 보고합니다. 로그 분석 결과:
- 15:00 - 대량의 크롤러 접근 (로그 볼륨 500% 증가)
- 15:05 - 데이터베이스 연결 풀 고갈 시작
- 15:10 - 쿼리 응답 시간 평균 50ms → 2000ms로 증가

이를 통해 크롤러 차단 정책 강화, DB 연결 풀 확대 등의 대응책을 수립합니다.

### 사례 3: 보안 감시
로그 모니터링 시스템이 다음 패턴을 감지합니다:
- 특정 IP에서 짧은 시간에 200번의 로그인 시도
- 대부분 다른 username으로 시도
- 모두 실패

이를 통해 브루트포스 공격을 감지하고, 해당 IP를 즉시 차단합니다.

### 사례 4: 사용자 행동 분석
마케팅 팀이 로그를 분석하여:
- 월요일 오전 9시에 트래픽 피크 발생
- 특정 상품 페이지에서 70% 이탈률
- 장바구니에 담은 후 30분 이내에 결제하는 사용자가 80%

이 정보로 마케팅 캠페인 시간 조정, 상품 페이지 개선 등을 추진합니다.

## 🔗 관련 용어

- **로그 레벨 (Log Level)**: DEBUG, INFO, WARN, ERROR, FATAL 등 로그의 중요도 구분
- **구조화 로그 (Structured Logging)**: JSON 형식으로 정규화된 로그
- **로그 수집 (Log Aggregation)**: 여러 소스의 로그를 한 곳으로 모으기
- **ELK Stack**: Elasticsearch + Logstash + Kibana 조합
- **모니터링 (Monitoring)**: 로그를 통한 실시간 시스템 감시
- **분산 추적 (Distributed Tracing)**: 마이크로서비스 환경에서 요청 흐름 추적
- **MTTR (Mean Time To Recovery)**: 문제 발생에서 복구까지의 평균 시간
- **저장소 로그 (Persistent Logging)**: 장기간 로그 보관 및 아카이빙
