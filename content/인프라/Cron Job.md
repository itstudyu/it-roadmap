# Cron Job (크론 잡)

## 📝 정의

Cron Job은 **Unix/Linux 시스템에서 정해진 시간에 자동으로 실행되는 예약 작업**입니다. Cron은 "Chronology"에서 파생된 용어로, 시간을 관리하는 데몬(백그라운드 프로세스)을 의미합니다. Cron Job을 이용하면 개발자가 직접 개입하지 않아도 반복적이고 정기적인 작업을 자동화할 수 있으므로, 운영 업무의 효율성이 크게 향상됩니다.

Cron Job의 핵심은 **Crontab(Cron Table)** 파일에 작업을 등록하는 것입니다. Crontab은 사용자별로 별도로 관리되며, 정해진 시간이 되면 자동으로 설정된 명령어를 실행합니다. 간단한 텍스트 형식으로 작업을 등록하기만 하면 되므로 구현이 매우 간단합니다.

> **한 줄 요약**: 정해진 날짜와 시간에 자동으로 명령어를 실행하도록 예약하는 Unix/Linux 시스템 기능

**비유 1**: Cron Job은 손목시계의 알람과 같습니다. 특정 시간에 알람을 설정해두면, 그 시간이 되면 자동으로 울려서 당신이 잊지 않도록 상기시킵니다. Cron Job도 정해진 시간에 도달하면 자동으로 작업을 실행합니다.

**비유 2**: Cron Job은 병원의 정기 검진 예약 시스템과 같습니다. 환자가 한 번 예약을 등록하면, 의료진이 매년 같은 시기에 환자에게 검진을 권유합니다. Cron Job도 한 번 등록하면 매일, 매주, 매달 자동으로 실행됩니다.

## 🎯 핵심 개념

### 1. Cron 표현식 (Cron Expression)
Cron Job은 다음과 같은 6개 필드로 구성된 표현식으로 스케줄을 정의합니다:
```
분(0-59) 시(0-23) 일(1-31) 월(1-12) 요일(0-6) 명령어
```

예시:
- `0 9 * * 1 /path/to/script.sh` → 매주 월요일 오전 9시에 스크립트 실행
- `*/5 * * * * /path/to/script.sh` → 매 5분마다 스크립트 실행
- `0 0 1 * * /path/to/script.sh` → 매월 1일 자정에 스크립트 실행
- `0 2 * * * /path/to/backup.sh` → 매일 오전 2시 백업 스크립트 실행

### 2. 와일드카드와 특수 문자
- `*` : 모든 값 (예: `*`는 "매시간" 또는 "매일")
- `?` : 값 무시 (일과 요일에만 사용, 둘 다 제약 없을 때)
- `-` : 범위 (예: `1-5`는 1부터 5까지)
- `,` : 여러 값 (예: `1,3,5`는 1, 3, 5)
- `/` : 간격 (예: `*/5`는 5 단위, `0-30/5`는 0부터 30까지 5 단위)

### 3. Crontab 명령어
- `crontab -e` : Crontab 파일 편집
- `crontab -l` : 등록된 Cron Job 목록 확인
- `crontab -r` : Crontab 파일 삭제
- `crontab -i` : 삭제 전 확인 요청

## ⚠️ 해결하는 문제

### 문제 1: 반복적인 수동 작업의 비효율
매일 자정마다 데이터베이스 백업을 수행해야 한다면, 운영자가 매일 자정에 수동으로 백업 명령어를 실행해야 합니다. 이는 휴일, 야간, 휴가를 가리지 않고 계속되어야 하는 작업입니다. Cron Job을 사용하면 한 번 설정 후 자동으로 실행되므로 인적 오류를 제거하고 운영 비용을 절감할 수 있습니다.

### 문제 2: 일정한 시간 유지의 어려움
주간 리포트를 매주 월요일 오전 9시에 생성하고 이메일로 발송해야 한다면, 수동으로 실행할 경우 시간이 일정하지 않을 수 있습니다. 어느 날은 8시 50분에 실행되고, 어느 날은 9시 10분에 실행될 수 있습니다. Cron Job은 분초 단위로 정확한 시간에 작업을 실행하므로 일관성을 보장합니다.

## ⚙️ 작동 원리

1. **Cron Daemon 시작**: 시스템 부팅 시 Cron Daemon이 백그라운드에서 자동으로 시작됩니다. 대부분의 Linux 시스템에서는 항상 실행 중입니다.

2. **Crontab 파일 읽기**: Cron Daemon은 매 분마다 `/var/spool/cron/crontabs/` 디렉터리의 모든 Crontab 파일을 읽습니다. 각 사용자마다 별도의 Crontab 파일이 있습니다.

3. **스케줄 파싱**: Crontab의 각 항목을 읽어서 Cron 표현식을 해석합니다. 예를 들어 `0 9 * * 1`은 "분=0, 시=9, 일=모든 일, 월=모든 월, 요일=월요일(1)"로 파싱됩니다.

4. **조건 확인**: 현재 시간의 분, 시, 일, 월, 요일이 모두 Cron 표현식의 조건과 일치하는지 확인합니다. 하나라도 맞지 않으면 다음 분을 대기합니다.

5. **명령어 실행**: 모든 조건이 일치하면 지정된 명령어를 실행합니다. 명령어는 보통 셸 스크립트(.sh 파일)의 형태입니다.

6. **환경 변수 설정**: Cron은 최소한의 환경 변수만 사용하므로, 필요한 환경 변수는 스크립트 내에서 설정하거나 Crontab에서 정의해야 합니다.

7. **로그 기록 및 알림**: 작업 완료 후 결과를 로그 파일에 기록하거나 이메일로 발송합니다. 오류 발생 시 자동으로 알림을 보낼 수 있습니다.

## ✅ 장단점

**장점:**
- **구현이 매우 간단**: 텍스트 표현식만으로 작업 등록 가능
- **리소스 효율적**: 데몬이 매우 경량이므로 시스템 부하 최소
- **신뢰성**: 수십 년 동안 검증된 안정적인 기술
- **정확성**: 분 단위로 정확한 시간에 작업 실행
- **의존성 없음**: 특별한 라이브러리나 프레임워크 불필요
- **이식성**: 거의 모든 Unix/Linux 시스템에서 동일하게 작동
- **비용 효율적**: 추가 소프트웨어 라이선스 불필요
- **로깅 자동화**: 실행 결과를 쉽게 추적할 수 있음

**단점:**
- **표현식 가독성**: Cron 표현식이 처음에 어렵게 느껴질 수 있음
- **초 단위 실행 불가**: 최소 실행 단위가 분(1분)이므로 초 단위 스케줄 불가능
- **오류 처리 어려움**: 작업 실패 시 자동 재시도 기능이 없음
- **복잡한 조건 불가**: "2월과 5월만 제외"와 같은 복잡한 조건 표현 어려움
- **로그 관리**: 작업이 많아지면 로그 파일 관리가 복잡해짐
- **분산 환경 미지원**: 단일 서버 기반이므로 여러 서버에 걸친 작업 관리 어려움
- **테스트 어려움**: Cron 환경에서 직접 테스트하기 번거로움
- **디버깅 복잡**: 백그라운드 실행이므로 실시간 문제 파악 어려움

## 💡 실제 사례

### 사례 1: 일일 데이터베이스 백업
매일 자정에 데이터베이스를 백업하고, 백업 파일을 원격 저장소로 업로드합니다.

```
Crontab 설정:
0 0 * * * /usr/local/bin/backup-db.sh

스크립트 내용 (backup-db.sh):
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
mysqldump -u root -p'password' --all-databases > /backup/db_$DATE.sql
gzip /backup/db_$DATE.sql
aws s3 cp /backup/db_$DATE.sql.gz s3://my-backup-bucket/
```

결과: 매일 자정마다 자동으로 데이터베이스가 백업되고, 클라우드에 업로드됩니다. 관리자는 설정만 해두면 됩니다.

### 사례 2: 주간 리포트 이메일 발송
매주 월요일 오전 9시에 지난주 매출 리포트를 생성하여 경영진에게 이메일로 발송합니다.

```
Crontab 설정:
0 9 * * 1 /usr/local/bin/send-weekly-report.sh

스크립트 내용:
#!/bin/bash
REPORT_DATE=$(date -d "last week" +%Y-%m-%d)
python3 /app/generate_report.py --date $REPORT_DATE --output /tmp/report.pdf
echo "지난주 매출 리포트를 첨부합니다." | \
mail -s "주간 매출 리포트" -a /tmp/report.pdf ceo@company.com
```

결과: 매주 월요일 정확히 9시에 자동으로 리포트가 생성되어 이메일로 발송됩니다.

### 사례 3: 1시간마다 캐시 갱신
1시간마다 자주 사용되는 데이터를 Redis 캐시에 로드하여 성능을 최적화합니다.

```
Crontab 설정:
0 * * * * /usr/local/bin/refresh-cache.sh

스크립트 내용:
#!/bin/bash
curl -X POST http://localhost:8000/api/refresh-cache
echo "[$(date)] Cache refreshed" >> /var/log/cache-refresh.log
```

결과: 매시간 정각에 캐시가 갱신되어 항상 최신 데이터가 메모리에 유지됩니다.

### 사례 4: 로그 파일 정리
30일이 지난 로그 파일을 자동으로 삭제하여 디스크 공간을 절약합니다.

```
Crontab 설정:
0 3 * * * find /var/log/app -name "*.log" -mtime +30 -delete

또는 더 안전한 방식:
0 3 * * * /usr/local/bin/cleanup-old-logs.sh
```

결과: 매일 오전 3시에 30일 이상 된 로그 파일이 자동으로 삭제되어 디스크 공간이 효율적으로 관리됩니다.

### 사례 5: 자동 보안 업데이트 확인
매일 오전 2시에 보안 업데이트를 확인하고 필요하면 자동으로 설치합니다.

```
Crontab 설정 (Ubuntu):
0 2 * * * apt-get update && apt-get upgrade -y
```

결과: 매일 밤 자동으로 보안 업데이트가 적용되어 시스템이 항상 보안이 최신 상태로 유지됩니다.

## 🔗 관련 용어

- **Crontab (Cron Table)**: Cron Job 설정 파일로, 사용자별로 별도 관리됨
- **Cron Daemon**: 백그라운드에서 실행되는 Cron 프로세스
- **스케줄러 (Scheduler)**: Cron Job을 포함한 작업 스케줄링 시스템
- **작업 스케줄링 (Job Scheduling)**: 특정 시간에 자동으로 작업 실행하는 기능
- **At 명령어**: 일회성 작업 예약 (Cron은 반복성 작업)
- **Systemd Timer**: 최신 Linux 시스템의 Cron 대체 기술
- **Quartz Scheduler**: Java 기반 작업 스케줄러 라이브러리
- **APScheduler**: Python 기반 작업 스케줄러 라이브러리
