# Metric (메트릭)

## 📝 정의

Metric은 **일정 기간의 숫자를 합쳐 요약한 값**이다.

OpenTelemetry 문서는 메트릭을 "실행 중에 붙잡은 서비스의 측정값" 이라 적고, 여러 측정값을 시간 창 안에서 하나로 합치는 일을 집계(aggregation)라고 부른다. 낱낱의 사건을 버리고 요약만 남기기 때문에 싸고 빠르다. 대신 버린 것은 나중에 되물을 수 없다.

### 비유
전기 계량기. 몇 시에 무엇을 켰는지는 안 적고, 이번 달에 쓴 양만 숫자 하나로 남는다.

### 예
대시보드에서 "5분 평균 응답 시간 320ms" 한 줄을 볼 때, 그 뒤에는 수만 건이 눌려 담겨 있다.

### 직접
폰 설정의 데이터 사용량 화면을 보라. 어느 순간에 얼마를 썼는지는 없고 이번 달 합계만 숫자로 남아 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 수만 건의 일이 어떻게 점 하나가 되나
계기 :: 일이 벌어질 때마다 값을 잰다
이름표 :: 어느 경로·어느 상태인지 붙인다
집계 :: 정해진 시간 창 안의 값을 합친다
내보내기 :: 창이 닫히면 숫자 한 줄로 나간다
저장소 :: 시간 축 위에 점으로 쌓인다
= 낱낱의 일은 버리고 한 창의 요약만 남는다. 그래서 싸고, 그래서 되물을 수 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 벌어진 일을 낱낱이 다 남기면 무엇이 문제인가
낱낱이 다 남기면 || 메트릭으로 재면
저장량 :: 건수만큼 는다 || 창 수만큼 는다
지금 상태 :: 세어 봐야 안다 || 값이 이미 있다
알림 :: 걸 기준이 없다 || 값에 선을 긋는다
= 낱낱을 버리는 대신, 언제든 바로 볼 수 있는 숫자 하나를 얻는다
```

초당 수천 건이 도는 곳에서 사건을 하나도 안 버리고 남기면, 저장은 요청 수에 비례해 늘고 "지금 괜찮나" 한 번 보려고 매번 수만 줄을 세야 한다. 사람이 그 속도로 볼 수 없으니 알림도 못 건다.

메트릭은 **시간 창 단위로 미리 합쳐 둔다.** 저장이 트래픽이 아니라 시간에 비례해 늘고, 값이 이미 숫자라서 거기에 선을 그어 알림을 걸 수 있다.

## 📊 비교: 메트릭 종류는 무엇이 다른가

| 종류 | 무엇을 재나 | 예 |
|---|---|---|
| **Counter** | 올라가기만 하는 누적값. 재시작하면 0으로 돌아간다 | 누적 요청 수 |
| **Gauge** | 읽는 순간의 값. 오르내린다 | 큐 길이, 메모리 사용량 |
| **Histogram** | 값을 구간(버킷)에 나눠 세고 합계도 같이 남긴다 | 응답 시간 분포 |
| **Summary** | 움직이는 시간 창 위에서 분위수를 계산한다 | p99 응답 시간 |

Prometheus 문서는 줄어들 수 있는 값에는 Counter 를 쓰지 말라고 못 박는다. 지금 도는 작업 수처럼 오르내리는 것은 Gauge 다.

## 💡 실제 사례

- **알림 걸기** — 오류율이나 지연 값에 선을 긋고, 그 선을 넘으면 사람을 부른다.
- **용량 계획** — 요청량과 포화도를 몇 달치 쌓아 두고 지금 쓰는 양이 어디까지 왔는지 본다.
- **배포 확인** — 새 판을 올린 뒤 오류율과 지연이 올린 시각 앞뒤로 달라졌는지 본다.

## 🚫 흔한 오해

- **평균만 보면 된다** — 빨리 실패한 요청이 평균을 끌어내려서 다 잘 도는 것처럼 보인다. SRE 책도 성공한 요청과 실패한 요청의 지연을 갈라 보라고 적는다.
- **이름표는 많이 붙일수록 좋다** — 이름표 조합 하나마다 따로 쌓이는 자리가 하나씩 생긴다. OpenTelemetry 문서는 사용자 아이디처럼 값이 무한한 것을 붙이면 메모리가 끝없이 늘어난다고 적고, 그래서 한 메트릭이 세는 조합 수에 기본 상한을 둔다.
- **메트릭만 잘 쌓으면 원인까지 나온다** — 모아서 요약한 값이라 "몇 시 몇 분의 그 요청이 왜" 는 안 남는다. 그 자리는 자취와 로그가 맡는다.

## 📝 정리

**"한 시간 창의 숫자를 하나로 눌러 담은 값"** 이라고 읽으면 된다. 낱낱의 일을 버리는 대신 언제든 바로 볼 수 있는 값을 얻는다. 그래서 "지금 괜찮나" 에는 강하고 "그때 그 요청은 왜" 에는 답하지 못한다.

## 🧒 열 살에게

집에 전기를 얼마나 썼는지 세는 계기 봤지? 그건 네가 몇 시에 불을 켰는지는 안 적고 이번 달에 쓴 양만 숫자로 알려줘. 그래서 종이 한 장만 봐도 이번 달에 유난히 많이 썼다는 걸 바로 알 수 있어.

## ❓ 이해했는지

- 큐에 쌓인 개수를 Counter 로 재면 왜 안 되나 → 비교
- 수만 건의 일이 어떻게 그래프의 점 하나가 되나 → 그림
- 대시보드는 다 정상인데 어떤 사용자만 느린 일은 왜 생기나 → 흔한 오해
