# OpenTelemetry (오픈텔레메트리)

## 📝 정의

OpenTelemetry는 **재는 법만 정하고 저장은 안 맡는 공통 규격**이다.

CNCF 프로젝트이고, 문서가 스스로를 "자취·숫자·문장 같은 관측 자료를 만들고 내보내고 모으는 일을 돕는 관측 프레임워크이자 도구 모음" 으로 적는다. 바로 다음 줄에 "OpenTelemetry 는 관측 백엔드가 아니다" 라고 못 박는다 — 저장과 화면은 다른 제품의 몫이라는 선언이다. OpenTracing 과 OpenCensus 가 합쳐지면서 계측 방식이 하나로 모였다.

### 이름
Open :: 누구 것도 아닌
Tele :: 멀리서
Metry :: 재기
= 붙여 읽으면 "멀리서 재는 일을 누구 것도 아니게 연 것". 재는 법만 열고 담는 일은 안 맡는다

### 비유
콘센트 규격. 구멍 모양을 하나로 맞춰 두면 어느 회사 제품을 바꿔 꽂아도 벽을 뜯을 일이 없다.

### 예
관측 도구를 바꾸려고 보니 온 코드에 그 회사 라이브러리가 박혀 있어서 못 바꾸겠던 그 순간이다.

## 🖼️ 그림으로 보기

```도해
층: 재서 보내는 길에서 어디까지가 OpenTelemetry 인가
내 코드 :: 무엇을 잴지 부르는 자리. 사람이 정한다
API :: 부르는 말투만 정해 둔 얇은 층
SDK :: 실제로 모으고 골라 내보내는 구현
Collector :: 받아서 다듬고 여러 곳으로 나눠 보내는 중간 다리
백엔드 :: 저장하고 화면에 그린다. 여기는 OpenTelemetry 가 아니다
= 재고 나르는 데까지만 맡는다. 어디에 담아 어떻게 보여줄지는 다른 제품의 몫이다
```

## ⚠️ 해결하는 문제

```도해
대조: 도구마다 계측을 따로 하면 무엇이 문제인가
도구마다 따로 || 공통 규격으로
도구 교체 :: 코드를 다 고친다 || 보낼 곳만 바꾼다
언어가 여럿 :: 이름이 제각각 || 같은 이름으로
두 회사 사이 :: 자취가 끊긴다 || 번호가 이어진다
= 재는 일과 담는 일을 떼어 놓으면, 담는 쪽을 바꿔도 코드는 그대로다
```

관측 도구를 고르면 그 회사의 계측 라이브러리가 온 코드에 박힌다. 도구를 바꾸려면 코드를 다시 훑어야 하니, 값은 내가 만들어 냈는데 바꿀 자유는 없다. 문서가 "당신이 만든 자료는 당신 것이고 특정 업체에 묶이지 않는다" 를 원칙으로 앞세우는 이유가 여기 있다.

규격은 **재는 쪽과 담는 쪽 사이에 경계를 하나 긋는다.** 코드가 부르는 말투(API), 자료의 모양(의미 규약), 나르는 형식(OTLP)까지만 정해 두고 그 뒤는 열어 둔다. 그래서 담는 쪽을 갈아 끼워도 계측한 코드는 그대로 간다.

## ⚙️ 작동 원리

규격이 다루는 신호는 셋이다 — 자취, 숫자, 문장. 코드가 직접 만나는 것은 API 층이고, 실제로 모으고 표본을 뽑고 내보내는 일은 SDK 가 한다. 둘을 갈라 둔 덕에 라이브러리는 API 만 보고 계측을 넣어도 되고, 어떻게 처리할지는 앱을 굴리는 쪽이 SDK 설정으로 정한다. 흔한 프레임워크는 코드를 안 고치고도 붙는 자동 계측이 따로 준비되어 있다.

Collector 는 앱 밖에 따로 도는 중간 다리다. 문서는 이것을 "업체에 매이지 않고 관측 자료를 받고 처리하고 내보내는 방법" 으로 적고, 앱은 자료를 빨리 넘겨 버리고 재시도·묶어 보내기·암호화·민감한 값 거르기는 Collector 가 맡는 그림을 권한다. 받는 부분(receiver)과 내보내는 부분(exporter)이 설정으로 갈려 있어서, 보낼 곳을 바꾸는 일이 앱이 아니라 Collector 설정에서 끝난다.

이미 쓰던 저장소를 버릴 필요도 없다. Prometheus 는 `--web.enable-otlp-receiver` 를 켜면 OTLP 를 HTTP 로 직접 받아 `/api/v1/otlp/v1/metrics` 경로에 열어 둔다.

## 💡 실제 사례

- **도구 갈아타기** — 계측은 그대로 두고 내보낼 주소만 바꾼다. 코드를 다시 훑지 않는다.
- **중간에 Collector 두기** — 앱은 넘기고 끝내고, 재시도와 묶어 보내기와 민감한 값 거르기는 Collector 가 맡는다.
- **쓰던 저장소로 보내기** — Prometheus 처럼 OTLP 를 직접 받는 쪽이면 담는 쪽은 그대로 두고 보내는 쪽만 바꾼다.

## 🚫 흔한 오해

- **깔면 대시보드가 생긴다** — 아니다. 문서가 스스로 "관측 백엔드가 아니다" 라고 적는다. 저장과 화면은 다른 제품을 따로 골라야 한다.
- **표준이니 쓰던 것을 다 걷어내야 한다** — 담는 쪽 중에는 OTLP 를 그대로 받는 것들이 있다. 보내는 쪽부터 바꾸고 저장소는 두는 길이 열려 있다.
- **계측만 붙이면 관측 가능해진다** — 무엇을 잴지는 여전히 사람이 정한다. 규격은 재는 방법과 이름을 통일할 뿐이다.

## 📝 정리

**"재는 법만 정해 둔 공통 규격"** 이라고 읽으면 된다. 자취와 숫자와 문장을 같은 방식으로 만들어 같은 형식으로 내보내는 데까지가 이 프로젝트의 몫이고, 저장과 화면은 그 밖에 있다. 그래서 담는 쪽을 갈아 끼워도 계측한 코드는 그대로 간다.

## 🧒 열 살에게

벽에 있는 구멍 모양이 다 같으니까 새 물건을 사 와도 그냥 꽂아 쓸 수 있지? 미리 구멍 모양만 하나로 맞춰 뒀을 뿐인데, 나중에 물건을 통째로 바꿔도 벽은 한 번도 안 뜯어도 돼.
