# CI/CD (지속적 통합과 배포)

## 📝 정의

CI/CD는 **코드를 올리면 검사와 배포가 자동으로 도는 파이프라인**이다.

CI는 올라온 코드를 합쳐 빌드하고 테스트하는 단계, CD는 통과한 결과물을 실제 서버에 올리는 단계다. 사람이 매번 같은 절차를 손으로 밟지 않게 만드는 것이 목적이다.

### 이름
Continuous :: 끊이지 않고
Integration :: 합쳐 넣기
Delivery :: 내보낼 준비까지
Deployment :: 실제로 올리기
= 붙여 읽으면 "끊이지 않고 합치고, 끊이지 않고 내보내기". 요점은 자동이 아니라 끊이지 않는 것이다

### 비유
공장의 컨베이어 벨트. 부품이 올라오면 검사대를 차례로 지나고, 하나라도 걸리면 그 자리에서 멈춘다. 사람이 검사 항목을 기억할 필요가 없다.

### 예
쓰는 앱이 일주일에도 몇 번씩 업데이트되는 것은 뒤에서 이 파이프라인이 계속 돌고 있다는 뜻이다.

### 직접
깃허브에서 `facebook/react` 저장소를 열고 위쪽 Actions 탭을 눌러 보라. 커밋마다 돌아간 검사가 초록 체크와 빨간 가위표로 남아 있다. 파이프라인이 없는 저장소에서는 이 탭이 비어 있다.

## 🖼️ 그림으로 보기

```도해
흐름: 커밋 하나가 서버에 올라가기까지 무엇을 거치나
개발자 :: 코드를 저장소에 올린다
CI :: 빌드한다. 깨지면 여기서 멈춘다
CI :: 테스트를 돌린다. 실패하면 여기서 멈춘다
CI :: 컨테이너 이미지를 만들어 저장소에 올린다
CD :: 테스트 환경에 먼저 배포한다
CD :: 확인되면 운영에 순차 배포한다
= 어느 단계에서 멈췄는지가 곧 무엇이 잘못됐는지다
```

## ⚠️ 해결하는 문제

```도해
대조: 배포를 손으로 하면 무엇이 달라지나
수동 배포 || CI/CD
빌드 실수 :: 사람마다 다름 || 항상 같은 절차
테스트 :: 잊거나 건너뜀 || 반드시 돈다
배포 시간 :: 수십 분 || 몇 분
되돌리기 :: 절차를 기억해야 || 이전 이미지로
= 절차를 사람 머리에서 꺼내 코드로 옮기는 일이다
```

손으로 배포하면 매번 조금씩 달라진다. 어떤 날은 테스트를 건너뛰고, 어떤 날은 설정 파일 하나를 빼먹는다. 배포가 무서워지면 사람들은 배포를 미루고, 미룬 만큼 한 번에 나가는 변경이 커져서 더 무서워진다.

CI/CD는 그 고리를 끊는다. 절차가 코드로 적혀 있으니 매번 같고, 작은 변경을 자주 내보낼 수 있게 된다. 문제가 생겨도 바뀐 게 적어서 원인을 찾기 쉽다.

## ⚙️ 작동 원리

```도해
층: 파이프라인은 어떤 순서로 좁혀 가나
빌드 :: 컴파일과 의존성 설치. 가장 싸고 빠름
단위 테스트 :: 함수 단위. 수 초에서 수 분
통합 테스트 :: DB 와 API 를 붙여서. 더 느림
배포 :: 여기까지 통과한 것만 올라간다
= 싸고 빠른 검사를 앞에 둔다. 5분짜리 테스트를 먼저 돌릴 이유가 없다
```

CD는 두 가지로 갈린다. 배포 준비까지만 자동으로 하고 마지막 버튼은 사람이 누르는 방식(지속적 전달)과 승인 없이 운영까지 나가는 방식(지속적 배포)이다.

## 💡 실제 사례

- **PR 검사** — 코드를 병합하기 전에 테스트와 린트(코드 스타일 자동 점검)를 돌려 통과해야만 병합되게 한다.
- **자동 배포** — 기본 브랜치에 병합되면 테스트 환경에 자동으로 올라간다.
- **되돌리기** — 문제가 생기면 이전 이미지 태그로 다시 배포한다.

## 🚫 흔한 오해

- **CI/CD는 배포 자동화다** — 배포는 뒷부분이다. 앞의 검사 자동화가 없으면 실패한 코드를 더 빨리 내보내는 도구가 된다.
- **테스트가 없어도 CI/CD를 쓸 수 있다** — 쓸 수는 있지만 값을 못 한다. 걸러낼 게 없으면 컨베이어만 도는 셈이다.
- **파이프라인이 느려도 상관없다** — 30분짜리 파이프라인은 사람들이 결과를 안 기다리게 만든다. 속도가 곧 사용률이다.

## 🚨 주의사항

- **비밀값을 파이프라인에 하드코딩하지 않는다.** 로그에 그대로 찍히고 저장소 이력에 영구히 남는다.
- **불안정한 테스트를 방치하지 않는다.** 가끔 실패하는 테스트가 몇 개 생기면 사람들은 빨간불을 무시하기 시작하고, 그 순간 파이프라인이 무의미해진다.

## 📝 정리

**"올리면 검사대를 차례로 지나 나가는 그 컨베이어"** 라고 읽으면 된다. 절차를 코드로 옮겨 매번 같게 만들고, 작은 변경을 자주 내보낼 수 있게 하는 것이 실질적인 이득이다.

## 🧒 열 살에게

과자 공장에는 긴 벨트가 있어서 과자가 지나가는 동안 모양 검사, 무게 검사를 차례로 받지? 하나라도 이상하면 그 자리에서 벨트가 멈춰서 밖으로 안 나가. 사람이 일일이 살펴보지 않아도 되니까 조금씩 자주 새로 만들어 내보낼 수 있어.
