# Bare Metal (베어 메탈)

## 📝 정의

Bare Metal은 **가상화 없이 물리 서버를 통째로 쓰는 방식**이다.

물리 서버 한 대 위에 가상 서버를 여러 대 올려 나눠 쓰는 것이 요즘의 기본이다. 그 중간 계층을 걷어내고 운영체제를 하드웨어에 바로 올리는 쪽을 베어 메탈이라 부른다.

### 이름
Bare :: 아무것도 안 씌운
Metal :: 장비 그 자체
= 붙여 읽으면 "맨 장비". 하드웨어와 운영체제 사이에 아무 층도 끼우지 않는다는 뜻이다

### 비유
단독 주택. 건물 하나를 혼자 쓰니 옆집 소음이 없고, 대신 고장 나면 관리실 없이 직접 고쳐야 한다.

### 예
집에 있는 컴퓨터에 윈도우를 깔아 쓰는 것이 그대로 베어 메탈이다. 사이에 낀 층이 하나도 없다.

## 🖼️ 그림으로 보기

```도해
층: 프로그램 아래에는 무엇이 깔려 있나
애플리케이션 :: 실제로 일하는 프로그램
운영체제 :: 하드웨어를 직접 잡고 있다
물리 하드웨어 :: CPU, 메모리, 디스크
= 가상화를 쓰면 운영체제와 하드웨어 사이에 한 층이 더 낀다
```

## ⚠️ 해결하는 문제

```도해
대조: 가운데 한 층이 끼면 무엇이 달라지나
가상화 위에서 || 베어 메탈에서
성능 :: 조금 깎인다 || 깎이지 않는다
지연 :: 들쭉날쭉하다 || 일정한 편이다
하드웨어 기능 :: 일부만 보인다 || 그대로 쓴다
= 얇게 깎이는 성능이 사고가 되는 자리가 있다. 거기가 베어 메탈 자리다
```

가상화 계층은 명령을 대신 받아 하드웨어로 넘긴다. 이 과정에서 성능이 조금 깎이는데, 더 성가신 건 얼마나 깎이는지가 순간마다 달라진다는 점이다. 평소에는 문제가 안 되지만 응답 시간이 일정해야 하는 일에서는 그 편차가 곧 사고다.

베어 메탈은 그 계층을 빼서 운영체제가 하드웨어를 직접 잡게 한다. CPU의 특수 명령어나 가속 카드 같은 것도 가려지지 않고 그대로 보인다. 대신 서버 한 대를 한 곳이 통째로 쓰게 되므로 놀고 있는 자원이 그대로 낭비되고, 관리도 전부 직접 해야 한다.

## ⚙️ 작동 원리

빌리는 절차부터 다르다. 물리 서버 한 대가 배정되면, 전원과 부팅만 따로 맡는 관리 카드(BMC, Baseboard Management Controller)가 그 서버를 켠다. 서버는 디스크가 아니라 네트워크에서 부팅해 운영체제 설치본을 받아 깔고, 다 깔린 뒤에야 접속 정보가 넘어온다. 가상 서버가 몇 초 만에 뜨는 것과 달리 이 자리에서 수십 분이 걸린다.

넘겨받은 다음부터는 커널이 하드웨어를 직접 잡는다. 가상화에서는 메모리 배치를 바꾸거나 장치를 직접 건드리는 특권 명령이 나올 때마다 하이퍼바이저가 그것을 가로채 대신 처리하고 결과만 돌려준다. 가로채기 한 번마다 시간이 붙고, 같은 장비에 올라탄 옆 손님이 무엇을 하느냐에 따라 그 시간이 매번 달라진다. 응답 시간이 들쭉날쭉한 까닭이 여기다.

베어 메탈에는 가로챌 층이 없어서 명령이 CPU 로 바로 간다. 대신 그 서버를 다음 사람에게 넘기려면 앞사람의 디스크를 지우고 처음부터 다시 깔아야 한다. 만들었다 지웠다 하는 일이 값싸지 않은 이유가 그것이다.

## 📊 비교

| | Bare Metal | VM | Container |
|---|---|---|---|
| 가상화 계층 | 없다 | 있다 | 있다 |
| 성능 | 깎이지 않는다 | 조금 깎인다 | 거의 안 깎인다 |
| 격리 | 없다 | 강하다 | 중간 |
| 늘릴 때 | 더 큰 서버로 교체 | 대수를 늘린다 | 대수를 늘린다 |
| 준비 시간 | 길다 | 짧다 | 매우 짧다 |

## 💡 실제 사례

- **거래 시스템** — 지연이 아주 짧은 단위로 갈리는 곳에서는 가상화 계층의 편차를 감당하지 못해 물리 서버를 그대로 쓴다.
- **대형 데이터베이스** — 물리 메모리 전체를 버퍼로 쓰고 CPU도 끝까지 쓰기 때문에, 자원을 나눠 쓸 이유 자체가 없다.
- **클라우드의 베어 메탈 상품** — 클라우드에서도 물리 서버 한 대를 통째로 빌려주는 상품이 있어서, 장비를 직접 사지 않고 같은 조건을 쓴다.

## 🚫 흔한 오해

- **베어 메탈은 클라우드의 반대말이다** — 클라우드에서도 물리 서버를 통째로 빌려준다. 가르는 기준은 어디에 있느냐가 아니라 가상화 계층이 끼어 있느냐다.
- **성능이 좋으니 무조건 낫다** — 서버 한 대를 한 곳이 통째로 쓰므로 노는 자원이 그대로 낭비된다. 부하가 몇 시간만 몰리는 서비스에서는 손해가 크다.
- **계층이 없으니 더 안전하다** — 격리가 없어서 반대다. 프로그램 하나가 뚫리거나 죽으면 그 서버 전체가 같이 간다.

## 🚨 주의사항

- **모든 관리가 직접이다.** 운영체제 패치, 보안 설정, 백업, 감시까지 대신해줄 계층이 없다.
- **늘릴 때가 오래 걸린다.** 대수를 늘리는 방식이 아니라 더 큰 장비로 옮겨야 해서, 갑자기 몰리는 부하에는 대응하기 어렵다.

## 📝 정리

**"사이에 낀 층 없이 장비를 통째로 쓰는 그 방식"** 이라고 읽으면 된다. 성능과 일정한 지연을 얻는 대신 노는 자원, 느린 준비, 격리 없음을 받는다. 얇게 깎이는 성능이 사고가 되는 자리에서만 값을 한다.

## 🧒 열 살에게

한 집을 여러 식구가 나눠 쓰면 옆방 소리도 들리고 물도 느리게 나오지? 큰 컴퓨터 한 대를 통째로 혼자 쓰면 그런 일이 없어서 언제 눌러도 똑같이 빨라. 대신 뭔가 고장 나면 대신 고쳐 줄 사람이 없어서 혼자 다 해야 해.
