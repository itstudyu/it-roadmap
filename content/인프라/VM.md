# VM (Virtual Machine, 가상 머신)

## 📝 정의

VM은 **소프트웨어로 만들어진 컴퓨터 한 대**다.

자기 운영체제를 따로 갖고 부팅도 따로 한다. 물리 서버 한 대에 여러 개가 올라가지만 서로의 안을 들여다볼 수 없다.

### 비유
통째로 파일이 된 컴퓨터. 복사해서 남에게 주거나 다른 책상 위로 옮겨 놓을 수 있다.

### 예
재택근무 때 회사가 내준 가상 PC 에 접속해 봤다면 그 화면 하나가 VM 한 대다.

## 🖼️ 그림으로 보기

```도해
흐름: VM 하나는 만들어져서 없어지기까지 무엇을 겪나
생성 :: 가상 디스크를 만들고 CPU 와 메모리를 떼어 준다
부팅 :: 그 안에서 게스트 OS 가 켜진다
실행 :: 앱이 돌고 하이퍼바이저가 자원을 나눠 준다
스냅샷 :: 그 순간의 상태를 통째로 저장해 둔다
이전 :: 돌아가는 채로 다른 물리 서버로 옮긴다
삭제 :: 지우면 떼어 줬던 자원이 되돌아온다
= 컴퓨터 한 대를 켜고 끄고 옮기고 되돌릴 수 있는 물건으로 만든 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 프로그램마다 서버를 따로 사면 어떻게 되나
물리 서버로만 || VM 으로
서버 사용률 :: 10에서 30퍼센트 || 70퍼센트 넘게
새 환경 :: 몇 주 걸린다 || 몇 분이면 뜬다
장비 교체 :: 서비스를 세운다 || 켠 채로 옮긴다
= 하드웨어에 묶여 있던 것을 파일처럼 다루게 바꾼 것이다
```

물리 서버 한 대는 대개 제 용량의 10에서 30퍼센트만 쓰고 나머지는 놀았다. 그런데도 프로그램마다 서버를 따로 둬야 했다. 한 대에 여러 개를 올리면 하나가 메모리를 다 먹었을 때 나머지도 같이 죽었기 때문이다.

VM 은 서버 한 대를 여러 대로 쪼개면서 그 사이에 벽을 세운다. 각자 운영체제를 따로 갖고 있어서 한쪽이 죽어도 옆이 멀쩡하다. 환경이 하나 더 필요하면 장비를 사는 게 아니라 몇 분 만에 띄운다.

## 🧱 구성

```도해
층: VM 하나는 무엇 위에 얹혀 있나
앱 :: VM 안에서 도는 프로그램
게스트 OS :: VM 마다 하나씩. 부팅도 따로 한다
하이퍼바이저 :: 여러 VM 에 자원을 떼어 주는 층
물리 하드웨어 :: 실제 CPU, 메모리, 디스크
= 게스트 OS 를 통째로 얹기 때문에 무겁고, 그래서 잘 갈린다
```

## ⚙️ 작동 원리

게스트 OS 는 자기가 진짜 하드웨어를 쥐고 있다고 믿고 명령을 낸다. 하이퍼바이저가 그 명령을 가로채 실제 장치로 옮겨 준다. 여러 VM 의 가상 CPU 는 물리 CPU 시간을 나눠 받는데, 한 VM 이 디스크 응답을 기다리는 동안 그 시간은 다른 VM 에 돌아간다.

이 구조 덕에 VM 은 파일처럼 다뤄진다. 어느 순간의 메모리와 디스크와 CPU 상태를 통째로 스냅샷으로 남겼다가 그 지점으로 되돌릴 수 있고, 돌아가는 채로 다른 물리 서버에 옮길 수도 있다.

## 📊 비교: VM vs Container

| | VM | Container |
|---|---|---|
| 각자 갖는 것 | 운영체제를 하나씩 | 커널은 같이 쓴다 |
| 부팅 시간 | 수십 초 | 수백 밀리초 |
| 메모리 | 하나당 수백 MB 이상 | 훨씬 적다 |
| 갈라놓는 정도 | 강하다 | 커널을 공유해 약하다 |

## 💡 실제 사례

- **클라우드 인스턴스** — 콘솔에서 유형을 고르고 누르면 몇 초 만에 VM 하나가 떠서 서버처럼 쓰인다.
- **데이터 센터 통합** — 물리 서버 50대로 하던 일을 고성능 10대 위의 VM 들로 옮겨 전기와 공간을 줄인다.
- **개발 환경 맞추기** — 필요한 환경을 VM 으로 만들어 두면 팀원이 같은 상태를 그대로 띄운다.

## 🚫 흔한 오해

- **VM 은 흉내만 내는 거라 많이 느리다** — 명령 대부분은 물리 CPU 에서 그대로 돌고 가로채는 부분에서만 값이 붙는다. 대체로 물리 서버보다 5에서 10퍼센트쯤 느리다.
- **VM 과 Container 는 같은 것이다** — VM 은 운영체제를 하나씩 통째로 얹고 Container 는 커널(운영체제에서 하드웨어를 직접 다루는 핵심부)을 같이 쓴다. 무게와 부팅 시간과 갈라놓는 정도가 그래서 갈린다.
- **VM 을 쓰면 관리할 게 줄어든다** — 대수는 오히려 는다. VM 마다 OS 패치와 보안 설정을 따로 해야 한다.

## 🚨 주의사항

- **물리 자원보다 많이 떼어 주면 나중에 서로 뺏는다.** 다 같이 바빠지는 순간 전부 느려진다.
- **하이퍼바이저에 문제가 생기면 위의 VM 이 전부 영향을 받는다.** 벽을 세우는 일을 그 층이 맡고 있어서다.

## 📝 정리

VM은 하이퍼바이저가 하드웨어를 잘라 만든 소프트웨어 컴퓨터 한 대다. 운영체제를 통째로 얹어서 무겁지만 그만큼 서로 강하게 갈라지고, 스냅샷이나 이전처럼 파일 다루듯 옮길 수 있다. 무게와 뜨는 속도가 더 중요한 자리에는 Container 가 온다.

## ❓ 이해했는지

- VM 하나가 메모리를 다 써버려도 같은 서버의 다른 VM 이 멀쩡한 이유는 → 해결하는 문제
- 서비스를 세우지 않고 물리 장비를 교체할 수 있는 이유는 → 작동 원리
- 같은 서버인데 Container 가 VM 보다 훨씬 빨리 뜨는 이유는 → 비교
