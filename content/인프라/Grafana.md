# Grafana (그라파나)

## 📝 정의

Grafana는 **값이 사는 곳에 물어서 화면에 그려 주는 도구**다.

공식 문서는 스스로를 "지표·로그·트레이스가 어디에 저장돼 있든 그것을 질의하고, 시각화하고, 알림을 내는 오픈소스 소프트웨어" 로 적는다. 값을 자기 쪽으로 퍼다 옮기지 않고, 저장된 그 자리에 접근한다는 말이 정의 안에 들어 있다.

### 비유
학교 곳곳에 걸린 온도계를 교무실 화면 하나에 띄워 놓은 것. 온도계는 제자리에 그대로 있고, 보는 자리만 한군데로 모은다.

### 예
장애 이야기를 할 때 누군가 붙이는 그래프 캡처 — 시간 축이 하나이고 여러 선이 겹쳐 있는 그 화면이 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 대시보드의 그래프 한 칸은 어떻게 그려지나
패널 :: 그래프 한 칸이 질문 하나를 갖는다
데이터 소스 :: 그 질문을 어디에 물을지 정해 둔 연결
원본 저장소 :: 값이 실제로 사는 곳. 거기서 골라 답한다
< 패널 :: 돌아온 값을 정해 둔 모양으로 그린다
= 값을 가져다 두는 게 아니다. 볼 때마다 사는 곳에 물어서 그 자리에서 그린다
```

## ⚠️ 해결하는 문제

```도해
대조: 지표를 도구마다 따로 보면 무엇이 힘든가
따로 보면 || Grafana 로
장애 볼 때 :: 창을 넷 연다 || 한 화면에 겹친다
시간 맞추기 :: 눈으로 맞춘다 || 같은 축에 선다
합쳐 보기 :: 다 퍼다 넣는다 || 있는 자리에 묻는다
= 값을 한군데로 옮기지 않고, 보는 화면만 한군데로 모은다
```

지표는 이쪽, 로그는 저쪽, 트레이스는 또 다른 곳에 쌓인다. 장애가 났을 때 창을 넷 열어 놓고 눈으로 시간을 맞추는 일이 여기서 나온다. 그렇다고 전부 한 저장소로 퍼다 옮기면 옮기는 일 자체가 새 일거리가 된다.

Grafana 는 **저장소를 합치는 대신 화면을 합친다**. 데이터 소스로 각각에 연결해 두고, 볼 때마다 각자에게 물어서 같은 시간 축 위에 겹쳐 그린다. 값은 원래 자리에 그대로 있다.

## ⚙️ 작동 원리

시작은 데이터 소스를 붙이는 일이다. Prometheus 를 쓴다면 그 주소(대개 `http://localhost:9090/`)를 데이터 소스 설정에 적는다. 이 연결이 있어야 패널이 질문을 던질 곳이 생긴다. 플러그인 얼개 덕에 NoSQL·SQL 같은 다른 저장소도 같은 방식으로 붙는다.

패널마다 질의를 적는다. Prometheus 데이터 소스라면 질의 칸에 PromQL 식을 그대로 쓰고, 범례 이름은 `{{method}} - {{status}}` 처럼 라벨을 끼워 만든다. 같은 화면을 여러 대상에 돌려쓸 때는 템플릿 변수를 쓴다. 대상 이름을 질의에 박아 넣는 대신 변수를 한 번 정해 두고 대시보드 곳곳에서 다시 쓰는 방식이다. 똑같이 생긴 대상이나 데이터 소스가 여럿이면 대시보드는 한 장이고 보는 쪽만 바꾼다.

알림도 이 화면에서 건다. 중요한 지표에 알림 규칙을 눈으로 정해 두면, 규칙이 걸릴 때 PagerDuty·SMS·이메일·VictorOps·OpsGenie·Slack 같은 여러 통지 수단으로 나간다.

## 📊 비교: Prometheus 와 무엇이 다른가

```도해
대조: Prometheus 와 Grafana 는 무엇이 다른가
Prometheus |=| Grafana
값 보관 :: 직접 쌓는다 || 쌓지 않는다
질의 :: PromQL 로 답한다 || 물어보고 받는다
붙는 범위 :: 한 종류를 깊게 || 여러 종류를 함께
= 하나는 값이 사는 곳이고, 하나는 사는 곳들에 물어 보여주는 창이다
```

## 💡 실제 사례

- **한 화면에 겹쳐 보기** — 지표·로그·트레이스를 같은 시간 축 위에 세운다. 값 자체는 원래 자리에 그대로 둔 채다.
- **대시보드 한 장 돌려쓰기** — 똑같이 생긴 대상이 여럿이면 템플릿 변수로 보는 쪽만 바꾼다. 대상마다 복제하지 않으니 고칠 자리도 한 곳이다.
- **화면에서 바로 알림 걸기** — 지켜보던 지표에 알림 규칙을 그 자리에서 정하고, 이메일이나 채팅으로 나가게 한다.

## 🚫 흔한 오해

- **Grafana 에 지표가 저장된다** — 아니다. 공식 문서는 "어디에 저장돼 있든" 그 자리에서 질의하고 시각화한다고 적는다. 플러그인으로 연결할 뿐 값을 퍼다 넣지 않는다.
- **Grafana 는 Prometheus 전용 화면이다** — Prometheus 지원이 2.5.0(2015년 10월)부터 기본으로 들어 있는 것은 맞지만, 플러그인 얼개로 NoSQL·SQL 같은 다른 저장소도 붙는다. Prometheus 질의 API 를 따르는 다른 구현도 같은 데이터 소스로 받는다.
- **대시보드만 잘 만들어 두면 장애를 먼저 안다** — 화면은 사람이 볼 때 일한다. 아무도 안 보는 시간을 메우는 것은 화면이 아니라 알림 규칙 쪽이고, 그래서 이 도구도 시각화와 알림을 한 문장에 함께 적어 둔다.

## 📝 정리

**"값이 사는 곳에 물어 그려 주는 창"** 이라고 읽으면 된다. 값을 옮겨 담지 않고 보는 자리만 한군데로 모으는 것이라, 붙일 저장소가 없으면 아무것도 그리지 못한다. 화면은 사람이 볼 때만 일하므로 알림과 짝으로 놓는다.

## 🧒 열 살에게

교실마다 온도계가 걸려 있으면 다 보려고 교실을 하나씩 돌아야 하지? 그래서 교무실 벽에 큰 화면을 걸고 그 숫자들을 한꺼번에 띄워 놔. 온도계는 그대로 교실에 있고, 보는 자리만 한군데로 모은 거야.

## ❓ 이해했는지

- 새로 깔았는데도 지난달 그래프가 그대로 보이는 이유는 무엇인가 → 그림
- 똑같이 생긴 대상이 열 대인데 대시보드를 열 장 만들지 않아도 되는 이유는 무엇인가 → 작동 원리
- 화면을 아무리 잘 만들어도 새벽 장애를 놓치는 이유는 무엇인가 → 흔한 오해
