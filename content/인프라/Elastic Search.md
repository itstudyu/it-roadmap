# Elastic Search (엘라스틱서치)

## 📝 정의

Elastic Search 는 **글을 단어로 쪼개 미리 색인해두는 검색 엔진**이다.

관계형 데이터베이스는 값이 정확히 일치하는 행을 찾는 데 맞춰져 있다. 글 안에서 단어를 찾는 일은 구조가 다르고, 그 쪽만 맡는 도구가 따로 있다.

### 비유
책 뒤의 찾아보기. 본문을 처음부터 넘기는 대신, 단어마다 몇 쪽에 나오는지 미리 적어둔 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 문서를 넣으면 검색되기까지 무슨 일이 일어나나
문서 :: 제목과 본문을 통째로 넣는다
분석기 :: 단어 단위로 쪼개고 형태를 정리한다
색인 :: 단어마다 어느 문서에 있는지 적어둔다
질의 :: 검색어도 같은 방식으로 쪼갠다
매칭 :: 겹치는 문서를 모아 점수를 매긴다
< 결과 :: 점수 높은 순으로 돌려준다
= 찾을 때 훑는 게 아니라 넣을 때 미리 정리해두기 때문에 빠르다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터베이스의 LIKE 검색은 무엇이 아쉬운가
LIKE 검색 || 색인 검색
속도 :: 행을 다 훑는다 || 색인만 본다
어미 변화 :: 못 찾는다 || 같은 말로 본다
정렬 :: 관련도가 없다 || 점수로 매긴다
= 값이 일치하는 행을 찾는 일과 글 속에서 찾는 일은 도구가 다르다
```

`LIKE '%주소%'` 같은 조건은 앞이 열려 있어서 색인을 못 쓴다. 행 수가 늘면 전체를 훑는 시간이 그대로 늘고, "주소 변경"으로 검색했을 때 "변경 주소"가 적힌 문서는 못 찾는다.

Elastic Search 는 문서를 넣는 순간 단어로 쪼개 어느 문서에 들어 있는지 적어둔다. 검색은 그 목록을 보는 일이라 문서 수가 늘어도 크게 느려지지 않고, 겹치는 단어 수와 희소성으로 점수를 매겨 관련도 순으로 돌려준다.

## 💡 실제 사례

- **로그 검색** — 서버 여러 대의 로그를 한 곳에 모아 넣고, 에러 문구로 기간을 좁혀 찾는다.
- **문서 검색** — 사내 규정이나 매뉴얼을 넣어두고 자연어에 가까운 문장으로 조항을 찾는다.
- **메뉴와 상품 검색** — 사용자가 치는 말이 등록된 이름과 정확히 같지 않아도 후보를 올려준다.

## 🚫 흔한 오해

- **데이터베이스 대신 쓰면 된다** — 검색에 맞춰 만든 것이라 트랜잭션과 정합성은 약하다. 원본은 데이터베이스에 두고 검색용 사본을 여기에 둔다.
- **넣으면 바로 검색된다** — 색인이 갱신되기까지 짧은 지연이 있다. 방금 저장한 글이 안 보이는 것은 대개 그 사이다.
- **알아서 오타를 고쳐준다** — 글자 차이를 얼마나 허용할지 설정했을 때만 그렇다. 기본은 쪼갠 단어가 겹치는지를 본다.

## 🚨 주의사항

- **분석기 설정을 넣기 전에 정한다.** 이미 색인된 문서는 새 분석기로 다시 쪼개지지 않아서 전체를 다시 넣어야 한다.
- **원본과 어긋나는 것을 전제로 만든다.** 데이터베이스에서 지운 문서가 여기에 남아 검색 결과에 뜨는 상황을 처리해둬야 한다.

## 📝 정리

Elastic Search 는 문서를 넣을 때 단어로 쪼개 색인해두고, 검색할 때 그 색인만 보는 엔진이다. 글 속에서 찾는 일과 관련도 순 정렬이 필요한 자리에 쓴다. 원본 저장소를 대신하는 물건은 아니다.
