# Hypervisor (하이퍼바이저)

## 📝 정의

Hypervisor는 **한 대의 컴퓨터를 여러 대처럼 나눠 쓰게 하는 소프트웨어**다.

각 VM 은 자기가 컴퓨터 한 대를 통째로 쓴다고 믿는다. 실제로는 하이퍼바이저가 CPU, 메모리, 디스크를 잘라 나눠주고 있고, 서로 남의 몫을 넘보지 못하게 막고 있다.

### 비유
아파트. 건물 하나에 여러 집이 들어가지만 각 집은 자기 현관을 쓰고 옆집 살림에는 손을 못 댄다.

## 🖼️ 그림으로 보기

```도해
흐름: VM 이 하드웨어를 만지려 하면 무슨 일이 벌어지나
게스트 OS :: 디스크에 직접 쓰겠다고 명령을 낸다
CPU :: 그 명령을 가로채 하이퍼바이저에 넘긴다
하이퍼바이저 :: 이 VM 몫의 영역이 맞는지 확인한다
하이퍼바이저 :: 진짜 디스크의 해당 자리에 대신 쓴다
< 게스트 OS :: 성공했다는 답만 받는다
= 게스트는 가로채였다는 사실을 끝내 모른다
```

## ⚠️ 해결하는 문제

```도해
대조: 서버 한 대에 프로그램을 몰아넣으면 어떻게 되나
하이퍼바이저 없이 || 하이퍼바이저로
한쪽이 폭주 :: 전부 같이 죽는다 || 그 VM 만 막힌다
OS 종류 :: 한 대에 하나 || 섞어서 여러 개
서버 늘리기 :: 장비를 사야 한다 || 몇 분이면 뜬다
= 한 대를 나누되 서로 못 건드리게 벽을 세우는 것이다
```

물리 서버 한 대에 여러 프로그램을 올리면 자원을 놓고 서로 다툰다. 하나가 메모리를 다 먹으면 나머지가 같이 죽고, 하나가 뚫리면 같은 서버의 다른 것들도 위험해진다. 그렇다고 프로그램마다 서버를 따로 사면 대부분의 서버가 놀게 된다.

하이퍼바이저는 한 대를 여러 칸으로 자르고 칸마다 몫을 정해준다. 한 칸이 자기 몫을 다 써도 옆 칸의 몫은 그대로 남아 있다. 칸을 새로 만드는 데는 장비를 사는 게 아니라 몇 분이 든다.

## ⚙️ 작동 원리

게스트 OS 는 자기가 진짜 하드웨어를 쥐고 있다고 믿기 때문에 특권 명령어를 그대로 낸다. CPU 가 이 명령어를 붙잡아 하이퍼바이저로 제어를 넘기고, 하이퍼바이저가 대신 처리한 뒤 다시 게스트로 돌려준다. 이 가로채기를 트랩이라고 한다.

Intel VT 나 AMD-V 같은 CPU 기능이 이 가로채기를 하드웨어에서 도와준다. 이 기능이 꺼져 있으면 하이퍼바이저가 전부 소프트웨어로 흉내 내야 해서 눈에 띄게 느려진다.

```도해
층: Type 2 는 왜 Type 1 보다 느린가
게스트 OS :: VM 안에서 도는 운영체제
하이퍼바이저 :: 명령을 가로채 하드웨어 요청으로 옮긴다
호스트 OS :: Type 2 에만 있다. 여기서 한 번 더 거친다
하드웨어 :: CPU, 메모리, 디스크
= Type 1 은 호스트 OS 층이 없어서 거치는 곳이 하나 적다
```

메모리도 같은 방식이다. 게스트가 보는 주소와 실제 물리 주소가 다르므로 하이퍼바이저가 그 사이를 옮겨 적는 표를 들고 있다.

## 📊 비교: Type 1 vs Type 2

| | Type 1 (베어메탈) | Type 2 (호스티드) |
|---|---|---|
| 설치 자리 | 하드웨어 위에 바로 | 쓰던 OS 위에 앱처럼 |
| 거치는 층 | 하나 적다 | 호스트 OS 를 한 번 더 |
| 쓰는 곳 | 데이터 센터 | 노트북, 학습 |
| 예 | ESXi, Hyper-V, KVM, Xen | VirtualBox, VMware Workstation, Parallels |

## 💡 실제 사례

- **데이터 센터** 서버 한 대에 VM 수십 개를 올려 놀고 있는 자원을 줄인다.
- **개발자 노트북** VirtualBox 를 깔고 리눅스 개발 환경과 윈도우 테스트 환경을 동시에 띄운다.
- **클라우드 인스턴스** 우리가 빌리는 서버는 대개 남의 물리 서버 위에 뜬 VM 한 칸이다.

## 🚫 흔한 오해

- **하이퍼바이저가 운영체제다** — 프로그램을 돌리는 물건이 아니다. 하드웨어를 잘라 나눠주는 일만 하고, 프로그램은 그 위에 올린 게스트 OS 가 돌린다.
- **Type 1 이 Type 2 보다 무조건 낫다** — 쓰는 자리가 다르다. Type 2 는 쓰던 OS 위에 앱처럼 깔면 끝이라 노트북에서는 그쪽이 맞다.
- **VM 으로 나눠도 성능은 그대로다** — 가로채고 옮기는 일에 값이 붙는다. 원본 노트 기준으로 3~10% 정도가 하이퍼바이저 몫으로 나간다.

## 🚨 주의사항

- **하이퍼바이저 자체가 뚫리면 위의 VM 이 전부 뚫린다.** 격리를 맡은 층이라 여기가 무너지면 격리도 같이 무너진다.
- **물리 자원보다 많이 나눠주는 것은 가능하지만 공짜가 아니다.** 실제로 다 쓰기 시작하면 전부 느려진다.

## 📝 정리

Hypervisor는 하드웨어 한 대를 여러 VM 에 나눠주고 서로 못 건드리게 막는 층이다. 게스트가 하드웨어를 만지려 할 때마다 가로채서 대신 처리하므로 게스트는 자기가 서버를 통째로 쓴다고 믿는다. 하드웨어에 바로 까는 Type 1 과 쓰던 OS 위에 까는 Type 2 로 나뉜다.
