# ConfigMap vs Secret (컨피그맵과 시크릿)

## 📝 정의

ConfigMap 과 Secret 은 **설정을 이미지 밖으로 빼 두는 두 그릇**이다.

쿠버네티스 문서는 ConfigMap 을 "비밀이 아닌 데이터를 키-값 쌍으로 담는 것" 으로, Secret 을 "비밀번호·토큰·열쇠 같은 소량의 민감한 데이터를 담는 것" 으로 적는다. 담고 꺼내는 방식은 거의 같고, 갈라지는 곳은 다루는 태도다. 그리고 그 태도는 저절로 지켜지지 않는다.

### 이름
Config :: 설정
Map :: 짝 지어 담는 통
Secret :: 감출 것
= 앞은 "설정을 짝지어 담는 통", 뒤는 "감출 것". 담는 법은 같고 다룰 법이 다르다

### 비유
냉장고에 붙인 메모지와 서랍 속 통장 같은 것이다 — 둘 다 종이지만 아무 데나 붙이는 것과 잠가 두는 것이 다르다.

### 예
접속 정보를 이미지 안에 박아 넣었다가, 운영으로 올릴 때 값 하나 때문에 이미지를 다시 굽고 있던 그 순간이다.

## 🖼️ 그림으로 보기

```도해
대조: 같은 값을 담는데 두 그릇은 무엇이 다른가
ConfigMap |=| Secret
담는 값 :: 감출 것 없는 값 || 비밀번호와 열쇠
적히는 꼴 :: 글자 그대로 || base64 로 적힌다
따로 켤 것 :: 없다 || 저장 암호화와 권한
= 그릇 모양은 같다. 뒤쪽은 "조심할 것" 이라는 이름표이지 잠금장치가 아니다
```

## ⚠️ 해결하는 문제

```도해
대조: 설정을 이미지 안에 박아 두면 무엇이 곤란해지나
이미지 안에 박으면 || 이미지 밖으로 빼면
값 하나 바꾸기 :: 이미지를 다시 굽는다 || 값만 고쳐 올린다
환경별 차이 :: 이미지가 환경 수만큼 || 이미지는 하나
비밀번호 :: 이미지에 남는다 || 이미지에 안 남는다
= 같은 이미지를 어디서나 쓰려면 달라지는 부분이 이미지 밖에 있어야 한다
```

설정을 이미지 안에 넣으면 개발용 이미지와 운영용 이미지가 서로 다른 물건이 된다. 개발에서 통과한 그 이미지가 운영으로 그대로 가지 않으니, 테스트가 보증하는 범위도 그만큼 줄어든다. 비밀번호를 넣었다면 그 이미지를 받아 본 사람은 모두 그 비밀번호를 갖게 되고, 레지스트리에 남은 옛 계층까지 따라다닌다.

두 그릇은 **달라지는 부분만 이미지 밖으로 떼어 낸다.** 이미지는 하나로 두고, 칸마다 다른 ConfigMap 과 Secret 을 붙여 같은 이미지를 개발에도 운영에도 올린다. 값을 바꿀 때 다시 굽는 것은 이미지가 아니라 값 하나다.

## ⚙️ 작동 원리

넣는 길은 넷이다. 환경 변수로 넣기, 명령 인자로 넣기, 볼륨으로 마운트해 파일로 읽기, 앱이 직접 API 를 호출해 읽기. 어느 길로 넣었느냐가 뒤에 값을 바꿨을 때의 행동을 가른다 — 볼륨으로 마운트한 것은 kubelet 이 동기화 주기마다 파일을 갱신해 주지만, 환경 변수로 넣은 값은 파드를 다시 띄우기 전에는 영영 옛 값이다. `subPath` 로 마운트한 것도 갱신을 못 받는다.

Secret 이라는 이름이 잠금을 뜻하지 않는다는 것이 이 편의 핵심이다. 쿠버네티스 문서는 첫머리에 "Secret 은 기본적으로 암호화되지 않은 채, base64 로만 인코딩되어 etcd 에 저장된다" 고 적고 세 가지를 경고한다 — API 에 접근할 수 있는 사람은 읽거나 고칠 수 있고, etcd 를 읽을 수 있는 사람도 읽을 수 있으며, 그 칸에 파드를 만들 수 있는 사람은 그 칸의 아무 Secret 이나 읽을 수 있다.

```도해
층: Secret 이 실제로 잠기려면 무엇이 켜져 있어야 하나
값 그 자체 :: base64 다. 되돌리는 데 열쇠가 필요 없다
저장 암호화 :: etcd 에 암호로 적히도록 따로 켠다
권한 좁히기 :: 누가 읽을 수 있는지 RBAC 로 자른다
바깥 금고 :: 클라우드 금고에서 CSI 로 마운트해 온다
= 아래로 갈수록 손이 더 간다. 위쪽만 해 두고 잠갔다고 말하면 안 된다
```

## 💡 실제 사례

- **같은 이미지, 다른 칸** — `dev` 와 `prod` 에 같은 이미지를 올리고 ConfigMap 만 다르게 붙인다. 값이 바뀌어도 이미지는 안 굽는다.
- **설정 파일 통째로 마운트** — `game.properties` 같은 파일형 키를 볼륨으로 걸면 `/config/game.properties` 에 파일로 뜬다. kubelet 이 주기마다 내용을 갱신한다.
- **비공개 레지스트리 로그인** — `kubernetes.io/dockerconfigjson` 형 Secret 을 만들고 `imagePullSecrets` 에 이름을 적으면 이미지를 받아 올 때 그걸 쓴다.

## 🚫 흔한 오해

- **Secret 은 암호화되어 저장된다** — 아니다. 문서가 기본값은 base64 인코딩일 뿐이라고 못 박는다. 저장 암호화는 따로 켜야 하고, 안 켜면 etcd 를 읽을 수 있는 사람은 그대로 읽는다.
- **`kubectl get secret` 권한이 없으면 못 읽는다** — 그 칸에 파드를 만들 수 있는 사람은 그 칸의 아무 Secret 이나 읽을 수 있다. 파드에 마운트해서 꺼내면 되기 때문이고, 문서가 직접 적어 둔 경고다.
- **어차피 안 보이니 ConfigMap 에 비밀번호를 넣어도 된다** — 문서 첫머리가 "ConfigMap 은 비밀성이나 암호화를 제공하지 않는다" 고 경고하고 Secret 을 쓰라고 적는다. ConfigMap 값은 대시보드·이벤트·매니페스트 사본에 그대로 딸려 다닌다.

## 🚨 주의사항

- **한 그릇에 1MiB 를 넘길 수 없다.** 큰 파일은 볼륨이나 바깥 저장소로 보낸다.
- **`subPath` 로 마운트하면 갱신이 안 온다.** Azure 문서도 이걸 쿠버네티스의 제약으로 적어 두었다. 값이 바뀌면 파드를 다시 띄우거나 앱이 파일 변경을 스스로 감시해야 한다.
- **바꾼 값이 안 먹으면 먼저 넣은 길부터 봐라.** 환경 변수로 넣었으면 파드를 다시 띄우기 전에는 안 바뀐다. 이걸 모르면 "값을 고쳤는데 왜 그대로냐" 로 한 시간을 쓴다.

## 📝 정리

**"이미지 밖으로 뺀 설정 통 둘"** 이라고 읽으면 된다. 담고 꺼내는 법은 거의 같고 다른 것은 다루는 태도라, Secret 은 이름이 그럴 뿐 저장 암호화와 권한 좁히기를 따로 켜야 비로소 잠긴다.

## 🧒 열 살에게

냉장고에 붙여 둔 메모지랑 서랍에 넣어 둔 통장은 둘 다 그냥 종이지? 통장이라고 저절로 잠기는 게 아니라 서랍을 잠가야 잠기는 거야. 겉에 "중요" 라고만 써 붙이면 옆에서 다 볼 수 있어.
