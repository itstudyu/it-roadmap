# On-Premises (온프레미스)

## 📝 정의

On-Premises는 **서버를 직접 사서 자기 공간에 두고 운영하는 방식**이다.

클라우드가 나오면서 생긴 말이다. 남의 장비를 빌려 쓰는 쪽과 구분하려고 원래부터 하던 방식에 이름을 붙인 것이다.

### 비유
집을 사서 사는 것. 수리도 세금도 직접 감당하지만 벽을 뚫든 구조를 바꾸든 마음대로다.

### 예
사무실 한쪽 방에서 밤새 팬 소리가 나고 에어컨이 계속 돌아가는 그 서버실이 온프레미스다.

## 🖼️ 그림으로 보기

```도해
층: 온프레미스에서는 어디까지 직접 맡나
서비스 :: 원래 하려던 것. 맨 위 한 겹
운영체제 :: 설치, 보안 갱신, 백업
하드웨어 :: 서버와 저장 장치의 구매, 설치, 교체
건물과 전력 :: 공간, 전기, 냉방. 여기까지 우리 몫
= 하려던 일은 맨 위 한 겹이고 나머지가 전부 딸려 온다
```

## ⚠️ 해결하는 문제

```도해
대조: 데이터를 밖에 둘 수 없을 때는 어떻게 하나
클라우드로 || 온프레미스로
데이터 위치 :: 남의 시설 || 우리 시설
규제 증명 :: 계약서로 || 직접 보여줌
망 분리 :: 어렵다 || 물리적으로
= 데이터가 어디 있어야 하는지 정해져 있으면 선택지가 좁아진다
```

금융이나 공공처럼 데이터를 국내에, 혹은 정해진 시설 안에 둬야 하는 규제가 있는 곳이 있다. 이런 곳은 서비스가 아무리 편해도 데이터를 밖으로 내보낼 수 없다.

온프레미스는 데이터가 항상 자기 시설에 있다. 누가 접근했는지, 백업이 어디 있는지를 직접 보여줄 수 있고 물리적으로 망을 끊어두는 것도 가능하다. 서버가 가까이 있어 지연이 짧다는 점도 실시간 처리가 걸린 곳에서는 이유가 된다.

## ⚙️ 작동 원리

쓰기 전에 먼저 지어야 한다. 공간을 정하고 장비를 사고 전력과 냉방과 보안 설비를 갖춘 다음에야 서비스를 올린다. 이 준비 기간이 클라우드와 가장 크게 갈리는 지점이다.

용량도 미리 정한다. 앞으로 얼마나 쓸지를 예측해 그만큼 사두는데, 적게 사면 모자라고 많이 사면 놀린다. 트래픽이 갑자기 몰려도 장비를 사서 설치하기 전까지는 늘릴 수 없다.

고장과 재해도 직접 맡는다. 장비가 죽으면 부품을 갈아야 하고, 정전이나 화재에 대비한 복구 절차도 조직이 세운다.

## 💡 실제 사례

- **규제 산업** — 거래 기록과 고객 정보는 자체 시설에만 두고, 밖으로 나가도 되는 부분만 따로 클라우드에 올린다.
- **대량 처리** — 데이터가 많고 성능 요구가 높으면 오래 쓸수록 빌리는 값이 사는 값을 넘어서기도 한다.
- **섞어 쓰기** — 민감한 부분은 자체 시설에 두고 앞단 웹 서비스만 클라우드에 올리는 식으로 나눈다.

## 📊 비교

| | 온프레미스 | 클라우드 |
|---|---|---|
| 인프라 | 직접 산다 | 빌려 쓴다 |
| 초기 비용 | 크다 | 거의 없다 |
| 늘리기 | 사서 설치할 때까지 걸린다 | 즉시 |
| 통제 | 전부 우리 몫 | 제공자와 나눠 진다 |
| 유지 인력 | 전담 팀이 필요하다 | 상당 부분 맡긴다 |

## 🚫 흔한 오해

- **온프레미스가 클라우드보다 무조건 안전하다** — 안전은 위치가 아니라 관리 수준이 정한다. 직접 관리한다는 건 보안 갱신과 감시를 직접 해야 한다는 뜻이고, 그 일을 못 하면 더 위험하다.
- **한 번 사두면 그다음은 돈이 안 든다** — 전기, 냉방, 부품 교체, 전담 인력이 계속 든다. 장비 값은 전체 비용의 일부다.
- **옛날 방식이라 이제 안 쓴다** — 규제와 지연 조건 때문에 고르는 곳이 있다. 클라우드가 나오면서 붙은 이름일 뿐 못 쓰게 된 방식이 아니다.

## 🚨 주의사항

- **용량을 예측해서 산다.** 모자라면 늘리는 데 몇 주가 걸리고 남으면 그만큼 돈이 놀아 있다.
- **복구 절차를 미리 적어둔다.** 장비가 죽었을 때 무엇을 어떤 순서로 되살릴지 정해두지 않으면 그날 정하게 된다.

## 📝 정리

On-Premises는 인프라를 직접 사서 자기 공간에 두고 운영하는 방식이다. 데이터 위치와 통제권을 온전히 갖는 대신 구매부터 고장 대응까지가 전부 조직의 몫이 된다. 규제와 지연이 고르는 이유가 되고, 비용과 확장 속도가 그 대가다.
