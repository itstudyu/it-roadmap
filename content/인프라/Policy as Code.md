# Policy as Code (규칙을 코드로)

## 📝 정의

Policy as Code는 **지켜야 할 규칙을 글이 아니라 판정하는 코드로 적는 것**이다.

규칙을 문서에 적어 두면 지키는 것도 어기는 것도 사람 몫이다. 코드로 적으면 규칙이 요청 하나하나에 대고 된다·안 된다를 돌려주는 물건이 된다. Open Policy Agent 문서는 이 구조를 판정과 집행을 갈라 놓는 것으로 설명한다. 규칙은 답만 돌려주고, 실제로 막는 일은 그 답을 받은 쪽이 한다.

### 이름
Policy :: 지켜야 할 규칙
as :: ~의 꼴로
Code :: 기계가 읽는 글
= 붙여 읽으면 "규칙을 기계가 읽는 글로". 사람이 읽고 지키는 게 아니라 기계가 읽고 막는다

### 비유
지하철 개찰구. "표 없이 들어가지 마시오" 라고 써 붙이는 대신, 표가 없으면 문이 안 열리게 만들어 둔 것이다.

### 예
"저장통을 아무나 볼 수 있게 열어 두지 마세요" 라는 사내 문서가 있는데도 다음 주에 똑같이 열린 저장통이 또 만들어져 있던 그 상황이다.

## 🖼️ 그림으로 보기

```도해
흐름: 무언가를 만들어 달라는 부탁 하나가 규칙을 어떻게 지나가나
부탁 :: "기계 한 대 띄워 줘" 가 접수된다
판정기 :: 규칙 코드에 그 내용을 그대로 넣어 본다
답 :: 된다·안 된다·경고만 중 하나가 나온다
집행기 :: 그 답대로 막거나 통과시킨다
= 규칙을 정하는 자리와 막는 자리가 갈라져 있어서, 규칙 하나만 고치면 쓰는 곳이 다 같이 바뀐다
```

## ⚠️ 해결하는 문제

```도해
대조: 규칙이 문서에만 있으면 무엇이 달라지나
문서로만 || 코드로
어길 때 :: 나중에 발견된다 || 그 자리에서 막힌다
사람마다 :: 해석이 갈린다 || 같은 답이 나온다
확인 :: 눈으로 훑는다 || 전부 자동으로 센다
= 지키라고 적어 둔 규칙과 못 어기게 만들어 둔 규칙은 다른 물건이다
```

문서로 적힌 규칙은 세 군데서 샌다. 못 읽은 사람이 있고, 읽고도 다르게 해석하는 사람이 있고, 지켰는지 확인하려면 사람이 하나하나 훑어야 한다. 만드는 자원이 하루에 수백 개면 훑는 일부터 불가능해진다.

규칙을 코드로 적으면 그 셋이 한꺼번에 사라진다. 쿠버네티스는 자원이 접수되는 자리에서 규칙을 재고 어기면 그 자리에서 거절한다. Azure 문서는 만들거나 고칠 때뿐 아니라 24시간마다 한 번씩 이미 있는 것들까지 다시 재서, 어긴 것 목록을 늘 갱신해 둔다고 적는다. **어기는 일이 나중이 아니라 그 자리에서 드러난다**는 것이 이 방식이 파는 것이다.

## 📊 비교: 어긴 것을 어떻게 다룰까

| 다루는 법 | 무슨 일이 일어나나 | 언제 고르나 |
|---|---|---|
| **막기** | 요청 자체가 거절된다 | 절대 있으면 안 되는 것 |
| **경고** | 통과시키되 경고를 함께 돌려준다 | 새 규칙을 들이는 중 |
| **기록** | 통과시키고 남기기만 한다 | 얼마나 어기는지 먼저 세어 볼 때 |
| **채워 넣기** | 빠진 값을 대신 넣어 맞춰 둔다 | 이미 만들어진 것을 나중에 맞출 때 |

## 💡 실제 사례

- **판에 올라가기 전에 막기** — 쿠버네티스는 자원이 접수되는 자리에서 규칙을 재고, 어기면 그 자리에서 거절한다. 판 안으로 들어온 뒤에 찾아다니지 않아도 된다.
- **설계도 단계에서 걸러내기** — 터를 짓는 코드가 실제로 만들어지기 전에 그 계획서를 규칙에 넣어 본다. 만들고 나서 지우는 것보다 싸다.
- **기록부터 켜 보기** — 새 규칙은 먼저 남기기만 하게 켜 두고, 며칠 세어 본 다음에 막기로 올린다. 몇 개가 걸릴지 모른 채 막기부터 켜면 멀쩡히 돌던 자동화가 먼저 멈춘다.

## 🚫 흔한 오해

- **규칙을 코드로 적으면 사람이 판단할 일이 없어진다** — 무엇을 규칙으로 삼을지, 누구에게 예외를 열어 줄지는 그대로 사람이 정한다. 코드가 대신하는 것은 매번 똑같은 판정을 되풀이하는 부분뿐이다.
- **판정하는 쪽이 곧 문지기다** — OPA 문서는 판정과 집행을 갈라 놓는다고 적는다. 판정기는 된다·안 된다만 돌려주고, 실제로 막는 것은 그 답을 받은 쪽이다. 그래서 같은 규칙을 여러 문 앞에 걸 수 있다.
- **효과가 있으려면 처음부터 막기로 켜야 한다** — Azure 문서는 반대로 권한다. 기록만 남기는 쪽으로 시작해 무엇이 걸리는지 본 다음 막기로 올리라는 것이다. 처음부터 막으면 이미 돌던 자동화가 먼저 멈춘다.

## 📝 정리

**"지키라고 적는 대신 못 어기게 짜 두는 것"** 이라고 읽으면 된다. 판정하는 자리와 막는 자리가 갈려 있어서 규칙 하나를 고치면 그 규칙을 쓰는 모든 문이 같이 바뀐다. 켤 때는 막기가 아니라 세어 보기부터 켠다.

## 🧒 열 살에게

지하철에 "표 없이 들어가지 마세요" 라고 써 붙여 놔도 그냥 넘어가는 사람이 있지? 그래서 아예 표를 대야만 문이 열리게 만들어 놨어. 지켜 달라고 부탁하는 대신, 안 지키면 못 들어가게 만들어 두는 거야.

## ❓ 이해했는지

- 새 규칙을 켰더니 멀쩡히 돌던 자동화가 먼저 멈춰 버리는 일은 왜 생기나 → 흔한 오해
- 어긴 것을 막지 않고 남기기만 하는 방식은 언제 고르나 → 비교
- 규칙 하나를 고쳤을 뿐인데 여러 문이 한꺼번에 바뀌는 이유는 무엇인가 → 그림
