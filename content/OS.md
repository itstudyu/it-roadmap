# OS (Operating System, 운영체제)

## 📝 정의

OS는 **프로그램과 하드웨어 사이에서 자원을 나눠주는 소프트웨어**다.

프로그램이 CPU와 메모리와 디스크를 각자 직접 잡아 쓰면 서로 밟는다. 운영체제는 그 사이에 서서 누구에게 얼마나 줄지 정하고, 프로그램에는 그 과정이 안 보이게 감춘다.

### 비유
건물 관리사무소. 입주자는 전기가 어디서 오는지 모른 채 쓰고, 나눠주고 사고를 막는 일은 관리실이 한다.

### 예
컴퓨터를 켜면 로고가 뜨고 한참 뒤에야 바탕화면이 나온다. 그 사이에 올라오고 있는 것이 이것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 파일을 하나 열면 무슨 일이 일어나나
프로그램 :: 이 파일을 열어달라고 요청한다
운영체제 :: 열 권한이 있는지 확인한다
운영체제 :: 디스크에서 읽어오도록 시킨다
운영체제 :: 읽은 내용을 메모리에 올린다
< 프로그램 :: 파일 내용만 건네받는다
= 프로그램은 그 디스크가 어떤 장치인지 끝내 모른다
```

## ⚠️ 해결하는 문제

```도해
대조: 프로그램이 하드웨어를 직접 다루면 어떻게 되나
운영체제 없이 || 운영체제로
메모리 :: 서로 덮어씀 || 나눠서 할당
장치 :: 기종마다 다시 씀 || 같은 방식으로
동시 실행 :: 하나씩만 || 번갈아 돌린다
= 프로그램이 몰라도 되는 것을 대신 맡아주는 자리다
```

프로그램이 메모리 주소를 직접 골라 쓰면 다른 프로그램이 쓰던 자리를 덮어쓴다. 디스크나 그래픽 장치도 제조사마다 다루는 방식이 달라서, 장치가 바뀔 때마다 프로그램을 다시 써야 한다.

운영체제는 그 사이에 서서 자원을 나눠주고 장치의 차이를 흡수한다. 프로그램은 "이만큼의 메모리를 달라", "이 파일을 열어달라"고 부탁하면 되고, 실제로 어디에서 어떻게 가져오는지는 알 필요가 없어진다.

## 🧱 구성

```도해
층: 프로그램에서 하드웨어까지 무엇이 겹쳐 있나
응용 프로그램 :: 브라우저, 편집기. 사용자가 여는 것
시스템 호출 :: 프로그램이 운영체제에 부탁하는 창구
커널 :: 프로세스, 메모리, 파일 시스템을 관리한다
드라이버 :: 장치마다 다른 말을 커널의 말로 옮긴다
하드웨어 :: CPU, 메모리, 디스크, 입출력 장치
= 위에서 부탁하고 아래에서 실행한다. 경계가 시스템 호출이다
```

## ⚙️ 작동 원리

프로세스 관리는 어느 프로그램이 지금 CPU를 쓸지 정하는 일이다. 아주 짧은 시간마다 돌아가며 바꿔주기 때문에 여러 프로그램이 동시에 도는 것처럼 보인다.

메모리 관리는 각 프로그램에 쓸 구역을 떼어주고, 남의 구역을 건드리면 막는 일이다. 파일 시스템은 디스크에 흩어져 있는 조각을 이름과 폴더라는 그림으로 보여주는 일이고, 입출력 관리는 키보드나 프린터 같은 장치를 프로그램이 같은 방식으로 다루게 하는 일이다.

## 💡 실제 사례

- **여러 앱 동시 실행** — 브라우저와 편집기가 같이 도는 건 CPU를 아주 짧게 번갈아 쓰기 때문이다.
- **다른 컴퓨터에서 같은 프로그램** — 디스크나 그래픽 장치가 달라도 같은 프로그램이 도는 건 그 차이를 운영체제가 흡수해서다.
- **강제 종료** — 응답 없는 프로그램을 밖에서 끝낼 수 있는 건 그 프로그램의 자원을 운영체제가 쥐고 있어서다.

## 🚫 흔한 오해

- **운영체제는 바탕화면과 창을 말한다** — 눈에 보이는 부분은 위에 얹힌 껍데기다. 본체는 안 보이는 자원 관리 쪽이고, 화면 없이 도는 서버 운영체제도 있다.
- **프로그램이 CPU 를 붙잡고 계속 돈다** — 아주 짧게 번갈아 쓴다. 동시에 도는 것처럼 보이는 건 전환이 빠르기 때문이다.
- **파일은 폴더 안에 그대로 들어 있다** — 폴더는 운영체제가 보여주는 그림이다. 디스크에는 조각으로 흩어져 있고 어디에 무엇이 있는지는 파일 시스템이 따로 적어둔다.

## 📝 정리

OS는 프로그램과 하드웨어 사이에 서서 CPU, 메모리, 디스크, 장치를 나눠주는 소프트웨어다. 프로그램은 시스템 호출로 부탁만 하고, 어떻게 가져오는지는 커널과 드라이버가 처리한다. 눈에 보이는 화면은 그 위에 얹힌 부분이다.
