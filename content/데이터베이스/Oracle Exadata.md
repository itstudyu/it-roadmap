# Oracle Exadata (엑사데이타)

## 📝 정의

Oracle Exadata는 **오라클 DB 만 돌리려고 만든 전용 장비**다.

DB 서버와 저장 장치를 따로 사서 붙이는 대신, 둘을 한 덩어리로 묶어 파는 제품이다. 저장 쪽에도 계산 능력을 넣어 데이터를 옮기기 전에 미리 거른다.

### 비유
한 가지 작업만 하는 전용 기계. 다른 일에는 못 쓰지만 그 일 하나는 범용 장비보다 빠르다.

## 🖼️ 그림으로 보기

```도해
흐름: 큰 표에서 몇 건만 뽑을 때 무엇이 다른가
질의 :: 억 단위 행 중 조건에 맞는 것만 찾는다
저장 서버 :: 조건을 저장 장치 쪽에서 먼저 건다
저장 서버 :: 걸러낸 결과만 DB 서버로 보낸다
DB 서버 :: 받은 것만 모아 결과를 만든다
< 사용자 :: 오간 데이터가 줄어든 만큼 빨리 받는다
= 데이터를 옮겨와 거르지 않고 있는 자리에서 거른다
```

## ⚠️ 해결하는 문제

```도해
대조: DB 서버와 저장 장치를 따로 두면 어떻게 되나
따로 둘 때 || 통합 장비
거르는 곳 :: DB 서버에서 || 저장 쪽에서 먼저
오가는 양 :: 표 전체가 이동 || 결과만 이동
병목 :: 사이 구간에 생김 || 옮길 게 적다
= 서버를 키우는 대신 옮기는 양을 줄이는 쪽을 택했다
```

큰 표를 훑는 질의는 대개 DB 서버가 느려서 느린 게 아니다. 조건에 맞는 행이 백만 건이어도, 거르는 일이 DB 서버에서 일어나면 억 단위 행이 저장 장치에서 서버까지 전부 옮겨와야 한다. 그 구간이 막히면 서버를 아무리 키워도 그대로다.

Exadata 는 거르는 자리를 옮긴다. 저장 서버가 조건을 먼저 걸고 결과만 올려 보내니 사이 구간을 지나는 데이터가 줄어든다.

## ⚙️ 작동 원리

저장 쪽에서 미리 거르는 기능을 스마트 스캔이라고 부른다. 질의에 붙은 조건과 필요한 열 정보를 저장 서버가 받아서, 해당하지 않는 행과 열은 보내지 않는다.

압축도 같은 목적을 갖는다. 열 단위로 묶어 압축하면 같은 데이터가 차지하는 자리가 줄고, 읽어 올릴 양도 함께 줄어든다.

자주 읽히는 데이터는 플래시 저장 장치에 따로 담아둔다. 디스크까지 내려가지 않고 그 층에서 끝나는 요청이 늘어난다.

## 💡 실제 사례

- **대용량 집계** — 수억 건을 훑어 합계를 내는 보고서 질의에서 차이가 크게 난다.
- **야간 배치** — 정해진 시간 안에 끝나야 하는 정산 작업의 여유를 만든다.
- **분석용 데이터베이스** — 운영 DB 와 분리해 조회 위주로 쓰는 곳에 놓는다.

## 🚫 흔한 오해

- **비싼 장비니까 모든 쿼리가 빨라진다** — 훑는 양이 많은 질의에서 효과가 크다. 인덱스로 몇 건만 집는 질의는 원래 옮길 게 적어서 차이가 거의 없다.
- **장비를 바꿨으니 튜닝은 안 해도 된다** — 잘못 짠 질의는 그대로 느리다. 줄여주는 것은 옮기는 양이지 질의의 잘못이 아니다.
- **좋은 하드웨어니 다른 DB 도 올려 쓰면 된다** — 오라클 DB 와 맞물려 돌도록 만든 장비다. 다른 DB 를 올리면 저장 쪽에서 거르는 기능이 그냥 안 쓰인다.

## 🚨 주의사항

- **한 회사의 하드웨어와 소프트웨어에 함께 묶인다.** 나중에 다른 DB 로 옮기려 하면 장비도 같이 쓸모가 없어진다.
- **효과를 볼 질의가 있는지 먼저 본다.** 짧은 조회가 대부분인 시스템은 이 장비로 바꿔도 체감이 없다.

## 📝 정리

Oracle Exadata 는 저장 쪽에서 데이터를 먼저 걸러 옮기는 양을 줄이는 오라클 DB 전용 장비다. 큰 표를 훑는 작업에서 효과가 나오고, 짧은 조회가 대부분이면 살 이유가 적다.
