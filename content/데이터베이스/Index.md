# 인덱스 (Database Index)

## 📝 정의

인덱스는 **찾을 값을 미리 정렬해 따로 만들어둔 목록**이다.

인덱스가 없으면 데이터베이스는 조건에 맞는 행을 찾으려고 테이블을 처음부터 끝까지 훑는다. 정렬된 목록이 따로 있으면 그 목록에서 위치를 알아낸 뒤 해당 행으로 바로 간다.

### 비유
책 뒤의 찾아보기. 단어가 몇 쪽에 있는지 적힌 목록을 먼저 보고 그 쪽만 편다. 책 전체를 읽지 않는다.

### 예
회원이 몇백만 명인 사이트에서도 로그인 단추를 누르면 곧바로 다음 화면으로 넘어간다.

## 🖼️ 그림으로 보기

```도해
흐름: 이메일로 회원 한 명을 찾을 때 무슨 순서로 가나
쿼리 :: email 이 이 값인 행을 달라고 한다
옵티마이저 :: 어떻게 찾을지 고르는 쪽. 인덱스가 있나 본다
인덱스 :: 정렬된 목록에서 값의 자리를 좁혀 간다
행 위치 :: 그 값이 어느 행인지 알아낸다
< 테이블 :: 그 행 하나만 읽어서 돌려준다
= 전부 훑는 대신 정렬된 목록에서 자리를 먼저 알아낸다
```

## ⚠️ 해결하는 문제

```도해
대조: 500 만 행에서 한 명을 찾으면 어떻게 되나
인덱스 없이 || 인덱스로
찾는 방법 :: 처음부터 훑는다 || 자리를 좁힌다
비교 횟수 :: 최대 500 만 번 || 스무 번쯤
행이 늘면 :: 같이 느려진다 || 거의 그대로
= 데이터가 커질수록 차이가 벌어진다
```

로그인처럼 초당 여러 번 도는 조회가 전체 테이블을 훑으면, 요청이 늘어날수록 데이터베이스가 같은 일을 반복하며 부하를 다 가져간다. 사용자가 늘면 느려지는 것이 아니라 어느 지점에서 갑자기 못 버틴다.

인덱스는 그 조회를 정렬된 목록 탐색으로 바꾼다. 행이 열 배가 되어도 확인해야 할 단계는 몇 개 늘어날 뿐이다.

## ⚙️ 작동 원리

대부분의 인덱스는 균형 잡힌 트리 구조로 저장된다. 값이 정렬된 채로 갈라져 있어서, 한 단계 내려갈 때마다 볼 범위가 크게 줄어든다.

정렬되어 있다는 성질에서 두 가지가 따라 나온다. 같은지 보는 조건뿐 아니라 범위 조건도 빠르고, 정렬해서 보여주는 쿼리는 정렬 작업 자체를 건너뛴다.

여러 컬럼을 묶은 인덱스는 순서가 뜻을 갖는다. `(user_id, order_date)`로 만들면 `user_id`만으로 찾는 쿼리에도 쓰이지만, `order_date`만으로 찾는 쿼리에는 쓰이지 않는다. 앞쪽 컬럼부터 정렬되어 있기 때문이다.

## 💡 실제 사례

- **로그인 조회** — 이메일 컬럼에 인덱스를 걸면 전체 훑기가 사라지고 응답 시간이 크게 떨어진다.
- **목록 정렬** — 상태와 작성 시각을 묶어 인덱스를 만들면 최신순 목록에서 정렬 단계가 없어진다.
- **조인** — 참조하는 쪽 컬럼에 인덱스가 없으면 조인할 때마다 상대 테이블을 통째로 훑는다.

## 🚫 흔한 오해

- **인덱스를 많이 걸수록 빨라진다** — 조회만 빨라지고 쓰기는 느려진다. 행을 하나 넣을 때마다 걸어둔 인덱스를 전부 함께 고쳐야 하기 때문이다.
- **인덱스를 만들면 항상 그걸 쓴다** — 안 쓸 때가 있다. 조건에 맞는 행이 테이블 대부분이면 옵티마이저는 훑는 편이 싸다고 판단한다.
- **인덱스는 컬럼에 붙는 표시다** — 표시가 아니라 따로 저장되는 자료구조다. 그래서 테이블 크기의 일부만큼 디스크를 더 쓴다.

## 🚨 주의사항

- **값의 종류가 적은 컬럼에는 효과가 없다.** 두 가지 값만 있는 컬럼은 인덱스를 타도 절반이 걸려서 훑는 것과 비슷해진다.
- **앞이 열린 검색에는 안 걸린다.** `LIKE '%검색어%'`처럼 앞부분이 정해지지 않으면 정렬 순서를 쓸 수 없어서 전체를 훑는다.

## 📝 정리

인덱스는 찾을 값을 미리 정렬해 따로 저장한 자료구조다. 조회와 정렬을 크게 줄여주는 대신 쓰기 비용과 저장 공간을 가져가므로, 자주 찾는 컬럼에 골라서 건다.

## ❓ 이해했는지

- 인덱스를 컬럼마다 다 걸었더니 데이터 입력이 느려졌다면 무엇 때문인가 → 흔한 오해
- 인덱스를 걸어뒀는데도 전체 훑기가 그대로 일어나는 컬럼은 어떤 것인가 → 주의사항
- `(user_id, order_date)` 인덱스가 `order_date` 조건만으로 검색할 때 안 쓰이는 이유는 → 작동 원리
