# ORM (Object-Relational Mapping)

## 📝 정의

ORM은 **DB 테이블을 프로그램의 객체처럼 다루게 해주는 계층**이다.

객체지향 코드는 클래스와 속성으로 짜여 있고 관계형 DB는 테이블과 컬럼으로 되어 있다. ORM은 클래스 하나를 테이블 하나에, 속성을 컬럼에 붙여두고 그 사이의 번역을 맡는다.

### 비유
자동 변속기. 기어를 직접 넣지 않아도 굴러가지만, 언제 몇 단을 쓸지는 차가 정한다.

## 🖼️ 그림으로 보기

```도해
흐름: 코드 한 줄이 어떻게 SQL 이 되어 돌아오나
코드 :: `User.filter(name="김")` 을 부른다
ORM :: 매핑 정보를 보고 SQL 로 옮긴다
드라이버 :: `SELECT ... WHERE name='김'` 을 보낸다
DB :: 조건에 맞는 행을 찾아 돌려준다
< ORM :: 행의 컬럼 값을 객체의 속성에 채운다
< 코드 :: `user.name` 으로 꺼내 쓴다
= 개발자는 객체만 보고, SQL 은 가운데서 만들어졌다 사라진다
```

## ⚠️ 해결하는 문제

```도해
대조: SQL 을 직접 쓰면 무엇을 떠안게 되나
직접 SQL || ORM 으로
DB 를 바꾸면 :: 쿼리를 다 고친다 || 설정만 바꾼다
조인 :: 매번 손으로 쓴다 || 관계로 걸어둔다
문자열 조립 :: 인젝션 위험 || 값이 분리된다
= 반복되는 조회와 저장을 대신 써주는 대가로 쿼리 통제권을 내준다
```

목록 조회, 한 건 조회, 저장, 삭제는 테이블마다 거의 같은 모양의 쿼리다. 테이블이 서른 개면 이 뻔한 쿼리를 서른 벌 쓰고 컬럼이 바뀔 때마다 다시 손본다. 문자열로 조립하다 보면 값이 그대로 쿼리에 섞여 인젝션이 열린다.

ORM은 그 부분을 대신 만든다. 매핑 정보를 한 번 적어두면 조회와 저장은 메서드 호출이 되고, 값은 쿼리와 분리되어 전달된다. 스키마 변경도 마이그레이션 파일로 남아 순서대로 반영된다.

## ⚙️ 작동 원리

```도해
층: ORM 은 어느 자리에 끼어 있나
내 코드 :: 객체와 메서드만 다룬다
ORM :: 매핑 정보를 보고 SQL 을 만든다
드라이버 :: 그 SQL 을 DB 로 실어 보낸다
DB :: 테이블에서 행을 찾는다
= 한 층을 끼워 넣고 편함을 얻었고, 그 층이 만든 SQL 은 안 보인다
```

관계를 언제 읽어올지도 ORM이 정한다. 필요할 때 따로 읽어오는 지연 로딩과 처음부터 같이 읽어오는 즉시 로딩이 있고, 무엇을 고르느냐에 따라 나가는 쿼리 개수가 달라진다.

기본값은 대개 지연 로딩이다. 그래서 목록을 돌며 관계를 하나씩 꺼내면 쿼리가 건수만큼 늘어난다.

## 💡 실제 사례

- **반복되는 조회와 저장** — 테이블마다 똑같이 생긴 목록 조회와 한 건 저장을 메서드 한 줄로 대신한다.
- **스키마 변경** — 컬럼을 추가하면 마이그레이션 파일이 남고, 팀원과 배포 서버가 같은 순서로 반영한다.
- **관계 조회** — 사용자와 그 사용자의 글을 외래키 대신 객체 관계로 걸어두고 `user.posts`로 꺼낸다.

## 🚫 흔한 오해

- **ORM을 쓰면 SQL을 몰라도 된다** — 쓰는 일을 대신할 뿐 만들어진 쿼리는 그대로 DB로 간다. 화면이 느려졌을 때 무엇이 나갔는지 읽지 못하면 고칠 수도 없다.
- **ORM이 직접 쓴 SQL보다 빠르다** — 사람이 쓴 것보다 나은 쿼리를 만들지는 않는다. 목록 100건을 돌며 관계를 하나씩 꺼내면 쿼리가 101번 나가는 N+1 문제가 대표적이다.
- **ORM을 쓰면 DB를 언제든 갈아탈 수 있다** — 표준 문법 범위 안에서만 그렇다. 특정 DB에만 있는 기능이나 손으로 쓴 쿼리를 섞기 시작하면 그만큼 묶인다.

## 📊 비교

| | ORM | 직접 SQL |
|---|---|---|
| 반복 쿼리 | 메서드로 대신한다 | 매번 쓴다 |
| 복잡한 집계 | 표현하기 어렵다 | 그대로 쓴다 |
| 성능 조정 | 만들어진 쿼리에 달렸다 | 손으로 잡는다 |
| DB 교체 | 설정 수준으로 끝난다 | 쿼리를 다시 본다 |

## 🚨 주의사항

- **생성된 SQL 로그를 켜두고 개발한다.** 무엇이 나가는지 안 보면 N+1은 데이터가 쌓인 뒤에야 드러난다.
- **복잡한 집계는 ORM으로 억지로 짜지 않는다.** 읽기 힘든 메서드 사슬보다 손으로 쓴 쿼리 한 벌이 낫다.

## 📝 정리

ORM은 클래스와 테이블을 붙여두고 그 사이를 번역하는 계층이다. 반복되는 조회와 저장을 대신 만들어주는 대신 쿼리를 직접 정하는 권한을 가져가므로, 무엇이 만들어져 나가는지는 계속 봐야 한다.
