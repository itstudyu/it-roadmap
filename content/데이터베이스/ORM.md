# ORM

## 📝 정의

ORM(Object-Relational Mapping)은 객체지향 프로그래밍의 객체와 관계형 데이터베이스의 테이블을 자동으로 매핑하여, 개발자가 SQL 쿼리를 직접 작성하지 않고도 데이터베이스를 조작할 수 있게 하는 프레임워크입니다. 프로그래밍 언어의 클래스를 데이터베이스 테이블과 연결하고, 객체의 속성을 테이블의 컬럼과 대응시킵니다.

ORM은 데이터베이스 추상화 계층 역할을 하여, 개발자가 데이터를 객체처럼 다룰 수 있도록 하고, 데이터베이스 종류를 바꾸더라도 애플리케이션 코드 변경을 최소화할 수 있습니다. 또한 데이터베이스 마이그레이션, 관계 설정, 트랜잭션 관리 등을 자동화하여 개발 생산성을 크게 향상시킵니다.

> **한 줄 요약**: ORM은 데이터베이스를 프로그래밍 언어의 객체처럼 다루기 위한 중간 계층

**비유 1**: ORM은 번역기와 같습니다. 프로그래밍 언어와 데이터베이스라는 두 개의 "언어"를 ORM이 중간에서 번역해주어 둘이 이해할 수 있도록 합니다.

**비유 2**: ORM은 자동 변속기와 같습니다. 순수 SQL은 수동 변속기처럼 세밀한 제어가 가능하지만 복잡하고, ORM은 자동 변속기처럼 편하지만 세부 조정이 어렵습니다.

## 🎯 핵심 개념

### 1. 클래스-테이블 매핑
프로그래밍 언어의 클래스 하나가 데이터베이스의 테이블 하나와 대응되며, 클래스의 속성(프로퍼티)은 테이블의 컬럼과 매핑됩니다. 클래스의 인스턴스는 테이블의 행(레코드)을 나타냅니다.

### 2. 쿼리 추상화
ORM은 SQL 쿼리를 메서드나 객체 기반의 쿼리 언어로 추상화하여, 개발자가 데이터베이스 문법을 몰라도 프로그래밍 언어의 논리로 데이터를 조회, 생성, 수정, 삭제할 수 있도록 합니다.

### 3. 연관 관계 관리
데이터베이스의 외래키(Foreign Key)를 객체 간의 관계로 표현하여, 1:N, N:M 등 다양한 관계를 객체지향적으로 모델링하고 자동으로 조인(Join)을 처리합니다.

### 4. 마이그레이션(Migration)
데이터베이스 스키마 변경을 코드로 관리할 수 있으며, 버전 관리를 통해 스키마의 변화 이력을 추적하고 이전/이후 상태를 쉽게 관리할 수 있습니다.

### 5. 캐싱 및 트랜잭션
ORM은 쿼리 결과를 캐시하여 중복된 데이터베이스 접근을 줄이고, 트랜잭션 관리를 자동화하여 데이터 무결성을 보장합니다.

## ⚠️ 해결하는 문제

### 문제 1: SQL 쿼리의 복잡성
개발자가 복잡한 SQL 문법을 모두 학습해야 하고, 데이터베이스마다 문법이 다르며, 쿼리 오류로 인한 버그가 발생할 수 있습니다. ORM은 프로그래밍 언어의 메서드를 통해 이를 간단하게 만듭니다.

### 문제 2: 데이터베이스 의존성
애플리케이션이 특정 데이터베이스(MySQL, PostgreSQL 등)에 강하게 의존되어 있으면, 데이터베이스를 변경할 때 전체 애플리케이션 코드를 수정해야 합니다. ORM은 이러한 의존성을 낮춥니다.

### 문제 3: 객체-관계 임피던스 불일치
객체지향 프로그래밍은 상속, 캡슐화 등을 기반으로 하지만, 관계형 데이터베이스는 테이블 중심으로 설계되어 패러다임이 맞지 않습니다. ORM은 이 간극을 메워줍니다.

### 문제 4: 관계 관리의 복잡성
여러 테이블 간의 조인, 외래키 관계 설정, 데이터 정합성 유지 등이 SQL에서 복잡하고 오류가 많습니다. ORM은 이를 객체 관계로 직관적으로 처리합니다.

## ⚙️ 작동 원리

ORM은 다음과 같은 단계로 작동합니다:

1. **메타데이터 정의**: 개발자가 클래스에 데이터베이스 매핑 정보(테이블명, 컬럼명, 데이터 타입)를 명시합니다.

2. **쿼리 빌드**: 개발자가 ORM의 메서드나 쿼리 언어를 사용하면, ORM은 이를 SQL 쿼리로 변환합니다.

3. **SQL 실행**: ORM은 생성된 SQL을 데이터베이스 드라이버를 통해 데이터베이스에 전송합니다.

4. **결과 처리**: 데이터베이스에서 반환된 행(Row)을 읽고, 각 컬럼 값을 ORM의 메타데이터에 따라 객체의 속성으로 매핑합니다.

5. **객체 반환**: 생성된 객체(또는 객체 컬렉션)를 애플리케이션에 반환합니다.

이 과정에서 ORM은 캐싱, 연관 관계 로딩(Lazy/Eager Loading), 트랜잭션 관리 등을 자동으로 처리합니다.

## ✅ 장단점

### 장점
- **개발 생산성 향상**: SQL을 몰라도 데이터베이스 조작 가능, 보일러플레이트 코드 감소
- **데이터베이스 독립성**: 특정 데이터베이스에 종속되지 않음, 마이그레이션 용이
- **코드 유지보수성**: 객체지향적 설계로 가독성과 유지보수성 향상
- **자동 마이그레이션**: 스키마 변경을 버전 관리와 함께 처리
- **보안 강화**: 파라미터 바인딩으로 SQL Injection 공격 방어
- **관계 관리 자동화**: 외래키 관계 자동 처리, 조인 복잡성 감소

### 단점
- **성능 저하**: 자동 생성된 쿼리가 최적화되지 않을 수 있음, N+1 문제 발생 가능
- **복잡한 쿼리 어려움**: 복잡한 비즈니스 로직 쿼리는 ORM으로 표현하기 어려움
- **학습 곡선**: ORM 프레임워크 자체를 학습해야 함
- **디버깅 어려움**: 자동 생성된 SQL을 직접 보기 어려워 문제 파악 어려움
- **메모리 오버헤드**: 객체 매핑으로 인한 메모리 사용 증가
- **세밀한 제어 불가**: 특정 데이터베이스 기능 사용에 제약이 있을 수 있음

## 💡 실제 사례

### Django ORM (Python)
Django 프레임워크의 ORM을 사용하여 User 테이블의 데이터를 조회합니다:
- `User.objects.all()`: 모든 사용자 조회
- `User.objects.filter(name='John')`: 특정 조건으로 필터링
- `user.save()`: 객체를 데이터베이스에 저장
- `user.delete()`: 객체를 데이터베이스에서 삭제

### Sequelize (Node.js)
Node.js의 Sequelize ORM을 사용하여 데이터 조회:
- `User.findAll()`: 모든 사용자 조회
- `User.findByPk(id)`: 특정 ID의 사용자 조회
- `await user.save()`: 변경사항 저장
- Post와 User의 1:N 관계를 `User.hasMany(Post)` 등으로 정의

### Prisma (TypeScript)
현대적인 TypeScript ORM인 Prisma:
- `await prisma.user.findMany()`: 모든 사용자 조회
- `await prisma.user.create({ data: {...} })`: 새 사용자 생성
- 타입 안정성을 제공하여 컴파일 시점에 오류 감지

### SQLAlchemy (Python)
Python의 강력한 ORM으로 복잡한 쿼리도 표현 가능:
- `session.query(User).all()`: 모든 사용자 조회
- `session.query(User).filter(User.age > 20)`: 조건 필터링

## 🔗 관련 용어

- **데이터베이스(Database)**: ORM이 조작하는 대상인 데이터 저장소
- **SQL(Structured Query Language)**: ORM이 내부적으로 변환하는 데이터베이스 쿼리 언어
- **마이그레이션(Migration)**: ORM을 통한 데이터베이스 스키마 관리
- **Query Builder**: ORM과 순수 SQL의 중간 형태
- **N+1 Problem**: ORM 사용 시 자주 발생하는 성능 문제
- **Eager Loading / Lazy Loading**: ORM의 관계 데이터 로딩 전략
- **Prepared Statement**: ORM이 기반하는 SQL 파라미터 바인딩 기술
- **ACID 트랜잭션**: ORM이 관리하는 데이터 일관성 보장 메커니즘
