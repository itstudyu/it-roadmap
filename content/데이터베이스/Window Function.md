# Window Function (윈도 함수)

## 📝 정의

Window Function은 **줄을 남겨 둔 채로 이웃 줄까지 보고 계산하는 함수**다.

PostgreSQL 문서는 이 함수를 "지금 줄과 관련된 여러 줄에 걸쳐 계산하는 것" 으로 적고, 곧바로 보통의 집계와 갈라 놓는다 — 집계는 여러 줄을 한 줄로 묶어 버리지만 창 함수는 "줄이 각자의 정체를 그대로 유지한다". MySQL 문서의 예가 그 차이를 숫자로 보여준다. 같은 합계를 묶어서 내면 나라별로 3줄이 나오고, 창을 열어서 내면 원래의 13줄이 그대로 나오면서 옆에 나라별 합계 칸 하나가 붙는다.

### 이름
Window :: 지금 줄이 내다보는 범위
Function :: 계산해서 값을 내는 것
= 붙여 읽으면 "정해진 창 안을 내다보고 내는 값". 창은 줄마다 따로 열린다

### 비유
성적표에서 내 점수 옆에 반 평균이 같이 찍혀 있는 것. 평균을 내느라 반 전체를 봤지만 내 줄은 지워지지 않았다.

### 예
은행 앱 거래 내역에서 금액 옆에 그때그때의 잔액이 같이 찍히는 그 화면이 이 계산의 결과다.

## 🖼️ 그림으로 보기

```도해
대조: 묶어서 세는 것과 창을 열고 세는 것은 무엇이 다른가
GROUP BY 방식 |=| OVER 방식
나온 줄 수 :: 묶음 수만큼 || 원래 줄 그대로
원래 값 :: 사라진다 || 옆 칸에 남는다
걸러내기 :: WHERE 에서 된다 || 한 겹 감싸야
= 둘 다 여러 줄을 보지만, 합쳐 없애느냐 옆 칸에 붙이느냐가 다르다
```

## ⚠️ 해결하는 문제

```도해
대조: 순위와 누적을 창 없이 구하면 무엇이 달라지나
창 없이 || 창을 열면
같은 표 :: 두 번 훑는다 || 한 번 훑는다
중복 지우기 :: 밖에 들고 나간다 || 질의 안에서 끝난다
기준이 바뀌면 :: 질의를 다시 짠다 || 정렬만 바꾼다
= 이웃 줄을 보려고 같은 표를 또 읽던 일이 한 번 읽기로 접힌다
```

"이 주문은 그 사람의 몇 번째 주문인가", "어제보다 얼마나 늘었나", "지금까지 얼마가 쌓였나" 는 한 줄만 봐서는 답이 안 나온다. 이웃 줄을 봐야 하는데, 창이 없으면 같은 표를 한 번 더 붙이거나 결과를 밖으로 들고 나가 프로그램에서 다시 훑는 수밖에 없다. 표가 커질수록 이 왕복이 그대로 비용이 된다.

창 함수는 **줄을 없애지 않으면서 이웃을 볼 권한만 주는 방식**으로 이 왕복을 없앤다. 자료 엔지니어가 하루 종일 만나는 두 가지 일 — 늦게 도착해 두 번 들어온 줄을 골라내는 일과, 어제 값과 오늘 값을 나란히 놓는 일 — 이 둘 다 이 자리에서 질의 하나로 끝난다.

## 🧱 구성

```도해
층: OVER 괄호 안은 무엇을 차례로 좁히나
PARTITION BY :: 어느 무리 안에서 볼지 가른다. 없으면 전체가 한 무리다
ORDER BY :: 그 무리 안의 줄 순서를 정한다. 순위와 누적의 기준이 된다
프레임 :: 정해진 순서 위에서 어디부터 어디까지 볼지 자른다
= 무리를 가르고, 줄을 세우고, 그중 몇 줄을 볼지 자른다. 안쪽일수록 좁다
```

## ⚙️ 작동 원리

괄호 안이 비어 있으면 창은 질의가 뽑은 모든 줄이다. `PARTITION BY` 를 넣으면 그 값이 같은 줄끼리 무리로 갈리고, 계산은 그 줄이 속한 무리 안에서만 일어난다. `ORDER BY` 를 넣으면 무리 안에 순서가 생기고, 여기서 성격이 한 번 바뀐다 — 순서가 없을 때의 기본 창은 무리 전체지만, 순서를 넣는 순간 기본 창이 "무리의 첫 줄부터 지금 줄까지, 거기에 정렬 기준으로 지금 줄과 값이 같은 줄까지" 로 좁아진다. 그래서 같은 `sum()` 이 정렬 기준 하나를 넣었다고 총합에서 누적합으로 바뀌고, 정렬 값이 같은 줄끼리는 누적값도 같게 나온다.

계산 시점이 두 번째 함정이다. 창 계산은 `WHERE` · `GROUP BY` · `HAVING` 이 다 끝난 뒤에 논리적으로 실행된다. 그래서 창 함수는 `SELECT` 목록과 맨 바깥 `ORDER BY` 에만 쓸 수 있고, `WHERE` 에는 못 쓴다. "순위 3위 안만 남겨라" 를 하려면 창으로 순위를 매긴 결과를 한 겹 감싸고 바깥에서 걸러야 한다.

중복 제거는 이 둘을 붙여 쓰는 자리다. 같은 열쇠로 무리를 가르고 갱신 시각 내림차순으로 줄을 세운 뒤 번호를 매기면, 열쇠마다 가장 최근 줄에만 1번이 붙는다. 바깥에서 1번만 남기면 두 번 들어온 줄이 사라진다. 적재를 다시 돌려 같은 줄이 겹쳐 들어왔을 때 흔히 쓰는 방법이다.

## 💡 실제 사례

- **두 번 들어온 줄 걸러내기** — 같은 열쇠로 무리를 가르고 최근 것에 1번을 매긴 뒤 1번만 남긴다. 재적재로 겹쳐 들어온 줄이 여기서 걸린다.
- **직전 값과 나란히 놓기** — 어제 값을 한 칸 당겨 와 오늘 줄 옆에 붙인다. 증감 계산이 표 하나 안에서 끝난다.
- **누적 잔액 칸** — 첫 줄부터 지금 줄까지 더한 값을 옆 칸에 붙인다. 거래 내역 화면의 잔액 칸이 이 계산이다.

## 🚫 흔한 오해

- **순위 조건은 WHERE 에 걸면 된다** — 못 건다. 창 계산은 `WHERE` 와 `GROUP BY` 가 끝난 뒤에 돌기 때문에, 순위로 걸러내려면 결과를 한 겹 감싸고 바깥에서 걸러야 한다.
- **줄이 안 사라지니 집계는 이제 다 이걸로 쓰면 된다** — 줄 수를 실제로 줄여야 하는 집계는 묶는 쪽이 맞다. 창은 원래 줄을 그대로 두는 것이 목적이라, 나라별 합계 3줄이 필요한 자리에서 13줄을 돌려준다.
- **괄호 안 정렬은 보기 좋으라고 넣는 것이다** — 그 정렬은 창의 기준이다. 넣는 순간 기본 창이 "첫 줄부터 지금 줄까지, 값이 같은 줄까지 함께" 로 바뀌어 총합이 누적합이 되고, 정렬 값이 같은 줄끼리는 한 덩어리로 묶여 같은 누적값을 받는다.

## 📝 정리

**"줄을 그대로 두고 옆 칸에 이웃을 요약해 붙이는 계산"** 이라고 읽으면 된다. 괄호 안에는 무리를 가르는 기준, 줄을 세우는 기준, 몇 줄까지 볼지가 차례로 들어간다. 거르기가 다 끝난 뒤에 도는 계산이라, 순위로 걸러내려면 반드시 한 겹 감싸야 한다.

## 🧒 열 살에게

시험 점수표에서 내 점수 옆에 반 평균이 같이 적혀 있으면 잘한 건지 못한 건지 그 자리에서 알 수 있지? 평균을 내려고 반 전체를 봤는데도 내 이름 줄은 지워지지 않고 그대로 남아 있어서 그래. 평균만 따로 적힌 종이를 받으면 두 장을 번갈아 보면서 맞춰 봐야 하잖아.

## ❓ 이해했는지

- 순위가 3위 안인 줄만 남기려는데 그 조건을 거르는 자리에 못 쓰는 이유는 무엇인가 → 흔한 오해
- 괄호 안에 정렬 기준을 넣었더니 총합이 누적합으로 바뀌었다. 무엇이 달라진 것인가 → 구성
- 같은 열쇠로 두 번 들어온 줄을 질의 하나로 걸러내려면 무엇을 쓰나 → 실제 사례
