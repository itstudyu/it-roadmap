# Redis

## 📝 정의

Redis는 **데이터를 디스크가 아니라 메모리에 두는 저장소**다.

열쇠 하나에 값 하나를 넣고 빼는 구조라 질의문이 필요 없다. 디스크를 거치지 않으니 읽고 쓰는 데 마이크로초 단위가 걸린다.

### 비유
책상 위. 서랍에서 꺼내오는 것보다 손 닿는 데 올려둔 것이 빠르지만, 올려둘 자리는 좁고 자리를 비우면 사라진다.

## 🖼️ 그림으로 보기

```도해
흐름: 같은 값을 두 번 읽으면 Redis 는 무엇을 하나
앱 :: 사용자 정보를 달라는 요청을 받는다
Redis :: 그 열쇠가 있는지 먼저 본다. 없다
DB :: 앱이 DB 까지 가서 원본을 읽어온다
Redis :: 읽어온 값을 열쇠에 담고 살 시간을 건다
< 앱 :: 두 번째 요청은 Redis 에서 끝난다
= 느린 곳에 가기 전에 빠른 곳을 먼저 들르게 하는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 같은 값을 자주 읽으면 어떻게 되나
DB 만 쓰면 || Redis 를 두면
읽는 시간 :: 디스크까지 간다 || 메모리에서 끝
DB 부하 :: 요청마다 쌓인다 || 처음 한 번만
세션 보관 :: 서버마다 따로 || 한 곳에 모인다
= 자주 읽고 덜 바뀌는 것을 앞에 두는 거래다
```

로그인한 사용자 정보처럼 잘 안 바뀌는 값을 요청마다 DB 에서 읽으면 매번 디스크까지 갔다 온다. 사용자가 늘면 앱보다 DB 가 먼저 버거워진다.

세션도 같은 문제를 만든다. 서버를 여러 대로 늘렸는데 각 서버가 세션을 자기 메모리에 들고 있으면, 다음 요청이 다른 서버로 갈 때 로그인이 풀린다. Redis 한 곳에 모아두면 어느 서버가 받아도 같은 세션을 본다.

## ⚙️ 작동 원리

```도해
층: 값 하나를 읽을 때 어디까지 가게 되나
앱 메모리 :: 그 프로세스 안. 서버를 늘리면 제각각이다
Redis :: 여러 서버가 같이 보는 메모리. 마이크로초
DB :: 디스크에 있는 원본. 여기까지 오면 가장 느리다
= 위에서 끝날수록 빠르고 아래로 갈수록 믿을 수 있다
```

열쇠마다 살아 있을 시간을 걸 수 있다. `setex('session', 3600, 'user123')` 처럼 초를 같이 주면 그 시간이 지난 뒤 알아서 사라진다. 지우는 코드를 따로 쓰지 않아도 되고 오래된 값이 눌러앉는 일도 막는다.

담는 모양은 문자열 하나만이 아니다. 순서가 있는 List, 중복이 없는 Set, 필드를 나눠 담는 Hash 가 있어서 사용자 한 명의 여러 값을 열쇠 하나에 담을 수 있다. Pub/Sub 을 쓰면 저장하지 않고 구독한 쪽에 흘려보낼 수도 있다. 메모리에만 두면 껐을 때 사라지므로 디스크에 내려 적는 기능도 따로 있다.

## 💡 실제 사례

- **세션 저장** 로그인 정보를 만료 시간과 함께 넣어 서버를 몇 대로 늘려도 같은 곳을 보게 한다.
- **조회 캐시** 자주 읽고 덜 바뀌는 목록을 담아 DB 로 가는 요청을 줄인다.
- **작업 목록** List 에 할 일을 밀어 넣고 처리하는 쪽이 앞에서 꺼내 간다.

## 🚫 흔한 오해

- **Redis 는 캐시라서 껐다 켜면 다 날아간다** — 디스크에 내려 적는 기능이 있다. 다만 기본이 메모리라 어디까지 지킬지는 설정하기 나름이다.
- **Redis 가 데이터베이스를 대체한다** — 메모리 크기만큼만 담을 수 있고 값을 열쇠로만 찾는다. 조건을 걸어 여러 행을 뒤지는 일은 DB 쪽이다.
- **메모리에 있으니 얼마든지 넣어도 된다** — 메모리가 차면 넣어둔 것이 밀려 나가거나 쓰기가 막힌다. 만료 시간을 거는 이유가 여기 있다.

## 🚨 주의사항

- **넣을 때 만료 시간을 같이 정한다.** 시간을 안 걸면 아무도 지우지 않은 값이 계속 쌓여 메모리를 채운다.
- **원본은 DB 에 둔다.** Redis 에만 있는 값이 생기면 재시작 한 번에 잃을 수 있다.

## 📝 정리

Redis는 값을 디스크가 아니라 메모리에 두고 열쇠로 바로 꺼내는 저장소다. 느린 DB 앞에 세워 자주 읽는 값을 받아치거나, 여러 서버가 같이 볼 세션을 한 곳에 모으는 데 쓴다. 메모리가 유한하므로 무엇을 얼마 동안 둘지 정하는 일이 늘 따라붙는다.

## ❓ 이해했는지

- 서버를 세 대로 늘렸더니 로그인이 자꾸 풀린다면 세션을 어디에 둔 것인가?
- 캐시에 값을 넣을 때 만료 시간을 같이 거는 이유는?
- 조건을 걸어 여러 행을 뒤지는 일에 Redis 가 맞지 않는 이유는?
