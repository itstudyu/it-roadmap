# Connection Pool (커넥션 풀)

## 📝 정의

커넥션 풀은 **연결을 열어 두고 돌려쓰는 통**이다.

요청마다 DB 에 새로 연결했다가 끊는 대신, 열어 둔 연결 몇 개를 통에 담아 두고 빌려주고 돌려받는다. 라이브러리가 대개 이 통을 기본으로 들고 있다 — Go 의 `sql.DB` 가 그렇고, Node.js 의 HTTP `Agent` 도 소켓을 같은 방식으로 다룬다.

### 비유
공용 우산 보관대. 쓸 때 하나 빼 가고 다 쓰면 꽂아 두며, 없으면 기다린다.

## 🖼️ 그림으로 보기

```도해
흐름: 쿼리 하나가 커넥션 풀을 어떻게 지나가나
앱 :: 풀에 커넥션 하나를 달라고 청한다
풀 :: 놀고 있는 게 있으면 그것을 건넨다
없으면 :: 상한까지는 새로 열고, 상한이면 줄을 선다
쿼리 :: 빌린 커넥션으로 DB 에 묻고 답을 받는다
< 반납 :: 끊지 않고 풀에 돌려준다. 다음 요청이 쓴다
= 연결을 새로 만드는 대신 빌려 쓰고 돌려주는 통이다
```

## ⚠️ 해결하는 문제

```도해
대조: 요청마다 연결을 새로 열면 무엇이 나빠지나
풀 없이 || 풀로
연결 :: 요청마다 새로 || 열어둔 걸 빌린다
동시 연결 :: 무한정 늘어난다 || 상한이 정해진다
다 쓰면 :: 끊고 다시 연다 || 돌려주고 재사용
= 연결을 만드는 일을 요청 수만큼 되풀이하지 않게 한다
```

연결을 요청마다 새로 만들면 두 가지가 한꺼번에 나빠진다. 같은 상대에게 붙었다 떼는 일을 끝없이 되풀이하고, 동시에 열린 연결 수에 아무 뚜껑이 없다. 쓰지 않는 소켓도 운영체제 자원을 잡아먹기 때문에 이건 그냥 놀고 있는 게 아니다.

풀은 **연결의 수명을 요청의 수명에서 떼어낸다.** 요청이 끝나도 연결은 끊지 않고 통으로 돌아가 다음 요청을 기다린다. 대신 몇 개까지 열지, 몇 개를 놀려 둘지에 상한을 걸어 둔다.

## ⚙️ 작동 원리

```도해
층: 풀의 크기를 정하는 값들은 무엇을 붙드나
최대 연결 수 :: 동시에 열어 둘 수 있는 커넥션의 상한
유휴 보관 수 :: 놀고 있어도 남겨 둘 커넥션의 수
최대 수명 :: 한 커넥션을 얼마나 오래 재사용할지
= 얼마나 열고, 얼마나 남기고, 얼마나 오래 쓸지를 이 셋이 정한다
```

Go 의 `sql.DB` 는 이름과 달리 연결 하나가 아니라 **연결 0개 이상을 담은 풀**을 가리키는 손잡이다. 여러 고루틴이 동시에 써도 안전하고, 연결을 만들고 없애는 일과 유휴 연결을 모아 두는 일을 패키지가 알아서 한다. 사람이 조절하는 건 위 도해의 세 값이다.

Node.js 의 HTTP `Agent` 도 같은 얼개다. 한 호스트·포트로 가는 요청을 줄 세워 두고 소켓 하나를 돌려쓰다가, 줄이 비면 그 소켓을 버리거나 풀에 넣어 둔다. 버릴지 넣어 둘지는 `keepAlive` 가 가르고, 한 origin 에 동시에 열 소켓 수는 `maxSockets` 가 정한다.

## 🚨 주의사항

- **풀에 있다고 살아 있는 건 아니다.** 서버 쪽에서 유휴 연결을 닫아 버릴 수 있다. 그러면 그 연결은 풀에서 빠지고 다음 요청 때 새로 열린다.
- **재사용 수명을 정해 둘 수 있다.** Go 의 `SetConnMaxLifetime` 은 한 연결을 얼마나 오래 돌려쓸지를 정하고, 수명이 지난 연결은 다시 쓰기 전에 닫힐 수 있다.
- **다 쓴 풀은 정리한다.** 놀고 있는 소켓도 운영체제 자원을 잡으므로, 더 쓰지 않는 `Agent` 는 `destroy()` 하는 편이 낫다.

## 💡 실제 사례

- **웹 서버와 DB 사이** — 요청이 초당 수백 개 들어와도 DB 로 나가는 연결은 풀에 정해 둔 개수를 넘지 않는다.
- **외부 API 를 자주 부르는 서버** — HTTP 클라이언트가 소켓을 풀에 두고 돌려쓰면 같은 상대에게 매번 새로 붙지 않는다.
- **오래 묵은 연결 갈아 끼우기** — 한 연결의 재사용 수명에 상한을 두면 오래된 연결이 스스로 물러나고 그 자리를 새 연결이 채운다.

## 🚫 흔한 오해

- **연결 객체를 만들면 그때 DB 에 붙는다** — 아니다. Go 의 `sql.Open` 은 인자만 확인하고 연결은 안 맺을 수 있다. 진짜 붙는지 보려면 `Ping` 을 따로 불러야 한다.
- **풀은 크게 잡을수록 빠르다** — 열어 둔 연결은 놀고 있어도 자원을 잡는다. 최대 연결 수와 유휴 보관 수에 상한을 두는 값이 따로 있는 게 그 때문이다.
- **풀에 들어간 연결은 계속 살아 있다** — 서버가 유휴 연결을 끊을 수도 있고, 재사용 수명이 지나 스스로 닫힐 수도 있다. 풀은 그때 조용히 새 연결로 채운다.

## 📝 정리

커넥션 풀은 연결의 수명을 요청의 수명에서 떼어내는 장치다. 요청이 끝나도 연결은 끊지 않고 통으로 돌아가 다음 요청이 빌려 쓴다. 최대 연결 수·유휴 보관 수·최대 수명 세 값이 이 통의 성격을 정한다.
