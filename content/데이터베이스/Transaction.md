# Transaction (트랜잭션)

## 📝 정의

Transaction은 **다 되거나 아예 안 되게 묶는 작업 단위**다.

여러 개의 명령을 하나로 묶어두면 도중에 무엇이 잘못돼도 반만 반영된 상태가 남지 않는다. 은행 이체처럼 두 가지가 함께 일어나야 뜻이 있는 일에 쓴다.

### 비유
물물교환. 내가 돈을 건네고 상대가 물건을 건네는 두 동작은 동시에 끝나야 한다. 하나만 일어나면 거래가 아니라 사고다.

## 🖼️ 그림으로 보기

```도해
흐름: 이체 도중에 서버가 죽으면 돈은 어떻게 되나
시작 :: BEGIN 으로 묶음을 연다
A 계좌 :: 잔액에서 100 을 뺀다. 아직 확정은 아니다
B 계좌 :: 100 을 더하려는데 오류가 난다
되돌림 :: ROLLBACK 으로 뺀 것까지 없던 일로 만든다
< 결과 :: 두 계좌 모두 시작 전 잔액 그대로다
= 반쯤 진행된 상태가 남지 않는 것이 트랜잭션이 파는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 출금은 됐는데 입금 전에 서버가 죽으면 어떻게 되나
트랜잭션 없이 || 트랜잭션으로
중간 실패 :: 돈이 사라진다 || 없던 일이 된다
남의 중간 상태 :: 그대로 읽힌다 || 안 보인다
복구 :: 손으로 맞춘다 || 자동으로 돌린다
= 반쯤 진행된 상태가 밖에 남지 않게 하는 것이 목적이다
```

명령을 하나씩 따로 실행하면 그 사이에 끊길 수 있다. 출금은 반영됐는데 입금 전에 시스템이 멈추면 100원이 어디에도 없는 상태가 되고, 이걸 나중에 찾아 손으로 맞추는 일은 건수가 늘수록 불가능해진다.

동시에 도는 다른 작업도 문제가 된다. 한쪽이 값을 고치는 중인데 아직 확정하지 않았을 때 다른 쪽이 그 값을 읽어가면, 나중에 앞쪽이 되돌려졌을 때 읽어간 쪽은 존재한 적 없는 값을 들고 있게 된다. 트랜잭션은 이 두 가지를 함께 다룬다.

## ⚙️ 작동 원리

`BEGIN`으로 묶음을 열면 그 뒤의 변경은 곧바로 반영되지 않고 아직 확정되지 않은 상태로 들고 있는다. 모두 성공했을 때 `COMMIT`을 부르면 그 변경들이 한꺼번에 디스크에 확정된다. 도중에 실패하면 `ROLLBACK`으로 지금까지의 변경을 전부 버리고 시작 전 상태로 돌아간다.

이 성질을 네 글자로 묶어 ACID라고 부른다. 전부 되거나 전부 안 되는 원자성, 끝난 뒤에도 데이터 규칙이 깨지지 않는 일관성, 동시에 도는 것들이 서로의 중간 상태를 보지 않는 격리성, 한번 확정되면 장애가 나도 남아 있는 지속성이다.

```도해
층: 격리 수준을 올리면 무엇을 더 막아주나
READ UNCOMMITTED :: 확정 안 된 값도 그대로 보인다
READ COMMITTED :: 확정된 것만 보인다
REPEATABLE READ :: 같은 줄을 다시 읽어도 값이 그대로다
SERIALIZABLE :: 새로 끼어든 줄까지 안 보인다
= 아래로 갈수록 안전해지고 동시에 처리할 수 있는 양은 줄어든다
```

격리를 지키는 수단은 잠금이다. 한 트랜잭션이 어떤 줄을 고치는 동안 다른 트랜잭션이 그 줄에 손대지 못하게 막고, 끝나면 푼다. 그래서 격리 수준을 높일수록 잠기는 범위와 시간이 늘고 처리량이 떨어진다. 서로가 쥔 것을 기다리다 둘 다 멈추는 데드락도 잠금 때문에 생긴다.

## 💡 실제 사례

- **계좌 이체** — 출금과 입금을 한 묶음으로 걸어 둘 다 되거나 둘 다 안 되게 한다.
- **주문 처리** — 재고 차감, 결제 승인, 주문 기록을 묶는다. 결제가 실패하면 재고가 원래대로 돌아온다.
- **좌석 예약** — 좌석을 잡아두고 결제까지 끝나야 확정한다. 실패하면 좌석이 다시 풀린다.

## 🚫 흔한 오해

- **트랜잭션을 걸면 데이터가 안 깨진다** — 묶음 단위로 전부 되거나 전부 안 되게 해줄 뿐이다. 잘못된 값을 넣는 로직이 있으면 그 잘못된 값이 그대로 확정된다.
- **커밋하기 전에는 아무도 그 값을 못 본다** — 격리 수준에 달렸다. 가장 낮은 수준에서는 아직 확정되지 않은 값이 다른 트랜잭션에 그대로 보인다.
- **격리 수준은 높일수록 좋다** — 안전한 만큼 잠금이 늘어 동시에 처리할 수 있는 양이 줄어든다. 그래서 보통은 중간 수준을 기본으로 쓴다.

## 🚨 주의사항

- **트랜잭션을 길게 열어두지 않는다.** 잠금이 오래 걸려 있으면 다른 요청이 줄줄이 기다린다. 외부 API 호출 같은 것을 묶음 안에 넣지 않는다.
- **잠그는 순서를 맞춘다.** 두 트랜잭션이 서로가 쥔 것을 기다리면 데드락이 되어 둘 다 멈춘다.

## 📝 정리

Transaction은 여러 명령을 한 묶음으로 만들어 전부 반영되거나 전부 취소되게 하는 장치다. 커밋 전까지는 확정되지 않고, 실패하면 되돌리며, 동시에 도는 다른 작업에는 격리 수준이 정한 만큼만 보인다. 안전을 높일수록 잠금이 늘어 처리량은 줄어드는 거래가 따라온다.
