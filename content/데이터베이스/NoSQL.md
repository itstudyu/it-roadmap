# NoSQL

## 📝 정의

NoSQL은 **표 모양을 고집하지 않는 데이터베이스**다.

관계형 DB는 행과 열이 정해진 표에 값을 나눠 담고 필요할 때 JOIN으로 합친다. NoSQL은 그 규칙을 내려놓고 문서, 키와 값, 열 묶음, 그래프처럼 담을 것에 맞는 모양을 골라 쓴다.

### 비유
서류철과 상자. 서류철은 칸이 정해져 있어 양식에 맞춰야 넣을 수 있고, 상자는 아무거나 넣을 수 있는 대신 안에 무엇이 있는지는 넣은 사람이 안다.

## 🖼️ 그림으로 보기

```도해
흐름: 회원 한 명을 담고 다시 꺼낼 때 어떻게 되나
프로그램 :: 이름, 주소, 주문 목록을 한 덩어리로 넘긴다
NoSQL :: 그 덩어리를 문서 하나로 그대로 담는다
NoSQL :: 표를 미리 정해두지 않아 필드가 달라도 받는다
프로그램 :: 회원 번호로 그 문서를 찾는다
< NoSQL :: 합치는 과정 없이 덩어리를 통째로 돌려준다
= 쪼개지 않고 담았기 때문에 꺼낼 때도 합칠 일이 없다
```

## ⚠️ 해결하는 문제

```도해
대조: 담을 것이 늘어날 때 표 구조는 무엇에 막히나
관계형 DB || NoSQL
스키마 :: 미리 정해둔다 || 문서마다 다름
확장 :: 서버를 키운다 || 서버를 더 붙임
필드 추가 :: 표 전체를 고침 || 그냥 넣는다
= 정해진 모양을 지켜서 얻던 것을 내주고 유연함과 확장을 산다
```

관계형 DB는 열을 미리 정해둔다. 상품마다 속성이 다른 카탈로그를 담으려면 안 쓰는 열이 잔뜩 생기거나 열을 계속 추가해야 하고, 이미 쌓인 데이터가 많으면 그 변경 자체가 부담이다.

늘어나는 방식도 다르다. 관계형 DB는 서버 한 대를 더 좋은 것으로 바꾸는 수직 확장이 기본이라 언젠가 한 대의 한계에 닿는다. NoSQL은 처음부터 여러 대에 나눠 담는 것을 전제로 설계된 제품이 많아서 서버를 더 붙이는 쪽으로 늘린다.

## ⚙️ 작동 원리

관계를 다루는 방법이 다르다. 관계형 DB는 회원과 주문을 각각 다른 표에 두고 JOIN으로 이어 붙인다. 문서형 NoSQL은 주문 목록을 회원 문서 안에 넣어두는 임베딩을 쓴다. 그래서 읽을 때는 한 번에 꺼내지만, 같은 값이 여러 문서에 복사되어 있으면 고칠 때 전부 찾아 고쳐야 한다.

스키마도 사라지는 게 아니라 자리를 옮긴다. DB가 모양을 검사해주지 않으므로 어떤 필드가 있어야 하는지는 애플리케이션 코드가 책임진다.

## 📊 비교: NoSQL 네 갈래

| 갈래 | 담는 모양 | 대표 | 주로 쓰는 곳 |
|---|---|---|---|
| Document | JSON 같은 문서 | MongoDB, CouchDB | 모양이 제각각인 데이터 |
| Key-Value | 열쇠와 값 한 쌍 | Redis, DynamoDB | 캐시, 세션 |
| Column-Family | 열 묶음 | Cassandra, HBase | 대용량 기록 |
| Graph | 점과 이어진 선 | Neo4j | 관계를 따라가는 질문 |

## 💡 실제 사례

- **세션과 캐시** — 로그인 상태를 Key-Value 저장소에 두고 열쇠 하나로 바로 꺼낸다.
- **속성이 제각각인 카탈로그** — 상품마다 들어가는 항목이 달라서 문서 하나에 있는 것만 담는다.
- **친구의 친구 찾기** — 관계를 따라 몇 단계씩 건너가는 질문은 그래프 DB가 선을 따라간다.

## 🚫 흔한 오해

- **NoSQL은 SQL을 못 쓴다는 뜻이다** — 질의 언어를 금지한다는 말이 아니다. 표와 JOIN이라는 관계형 모델을 따르지 않는다는 뜻이고, SQL을 닮은 질의를 제공하는 제품도 있다.
- **스키마가 없으니 설계를 안 해도 된다** — DB가 검사해주지 않을 뿐 모양은 여전히 필요하다. 그 책임이 DB에서 애플리케이션 코드로 옮겨간 것이다.
- **NoSQL이 SQL보다 빠르다** — 쓰임이 맞을 때만 빠르다. 열쇠로 하나 꺼내는 일은 빠르지만 여러 표를 이어 붙여 집계하는 질문은 관계형 DB가 낫다.

## 📝 정리

NoSQL은 관계형 표 대신 담을 것에 맞는 모양을 골라 쓰는 데이터베이스다. 미리 정한 스키마와 JOIN을 내려놓는 대신 유연한 모양과 서버를 붙여 늘리는 확장을 얻는다. 대신 검사와 정합성 관리가 애플리케이션 쪽 일이 된다.
