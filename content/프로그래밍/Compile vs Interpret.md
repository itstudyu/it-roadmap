# Compile vs Interpret (컴파일 vs 인터프리트)

## 📝 정의

컴파일과 인터프리트는 **코드를 기계가 실행하게 만드는 두 방식**이다.

컴파일은 실행하기 전에 코드 전체를 한 번 옮겨 실행 파일을 만들어둔다. 인터프리트는 옮겨두지 않고, 실행하는 동안 한 줄씩 읽어 그 자리에서 처리한다.

### 이름
Compile :: 모아서 엮어 둠
Interpret :: 그 자리에서 풀이
= 미리 다 엮어 두느냐, 닿을 때마다 풀어 주느냐. 이름이 곧 그 차이다

### 비유
책 번역과 통역. 번역은 미리 다 옮겨두고 나중에 읽고, 통역은 말이 나올 때마다 그 자리에서 옮긴다.

### 예
잘 돌아가던 프로그램이 어떤 화면에서만 갑자기 멈추는 일은 돌리면서 옮기는 쪽에서 더 자주 겪는다.

## 🖼️ 그림으로 보기

```도해
대조: 번역을 미리 해두는 것과 돌리면서 하는 것은 무엇이 다른가
컴파일 |=| 인터프리트
번역 시점 :: 실행 전에 한 번 || 한 줄씩 그때그때
남는 것 :: 실행 파일 || 없다
오류가 나는 때 :: 빌드할 때 || 그 줄에 닿을 때
다른 OS 로 :: 다시 빌드한다 || 그대로 쓴다
= 미리 옮기면 실행이 빠르고, 돌리면서 옮기면 고쳐서 바로 본다
```

## ⚠️ 해결하는 문제

```도해
대조: 사람이 쓴 코드를 기계가 그대로 읽을 수 있나
번역 없이 || 번역을 거쳐
CPU :: 글자를 못 읽음 || 기계어를 받는다
사람 :: 0과 1을 씀 || 읽는 글로 쓴다
고칠 때 :: 매번 다시 씀 || 코드만 고친다
= 두 방식은 이 번역을 언제 하느냐만 다르다. 하기는 둘 다 한다
```

CPU가 아는 것은 기계어뿐이다. `print("hi")` 같은 글자는 그대로 넣어도 아무 일도 일어나지 않는다. 사람이 읽을 수 있는 형태와 기계가 실행할 수 있는 형태 사이에는 반드시 번역이 들어간다.

컴파일과 인터프리트는 그 번역을 언제 하느냐가 다르다. 미리 해두면 실행할 때 빠르고, 돌리면서 하면 고친 것을 바로 볼 수 있다. 어느 쪽을 택하든 번역을 건너뛰지는 못한다.

## ⚙️ 작동 원리

컴파일러는 코드 전체를 훑기 때문에 실행하기 전에 문법이나 타입이 어긋난 곳을 찾아낼 수 있다. 대신 고칠 때마다 다시 빌드해야 하고, 나온 실행 파일은 그 환경에 맞춰져 있어서 다른 운영체제로 옮기면 그대로 돌지 않는다.

인터프리터는 앞의 줄만 보고 실행한다. 그래서 아래쪽 줄에 있는 오류는 거기까지 실행이 닿아야 드러난다. 대신 옮겨둔 파일이 없으니 코드를 고치고 바로 돌려볼 수 있고, 인터프리터만 깔려 있으면 어느 운영체제에서든 같은 코드를 쓴다.

둘을 섞기도 한다. 자바는 소스를 미리 중간 형태로 컴파일해두고, 실행할 때 JVM이 그걸 읽어 돌린다.

## 📊 비교

| | 컴파일 | 인터프리트 |
|---|---|---|
| 번역 시점 | 실행 전에 한 번 | 실행하면서 한 줄씩 |
| 남는 것 | 실행 파일 | 없다 |
| 실행 속도 | 빠르다 | 느린 편이다 |
| 오류가 드러나는 때 | 빌드할 때 | 그 줄에 닿았을 때 |
| 다른 OS로 옮기기 | 다시 빌드해야 한다 | 인터프리터만 있으면 된다 |
| 예 | C, C++ | Python, JavaScript |

## 💡 실제 사례

- **빌드 기다리기** — C로 쓴 프로그램은 한 줄을 고쳐도 `gcc`를 다시 돌려야 바뀐 게 반영된다.
- **바로 고쳐 보기** — 파이썬 스크립트는 저장하고 `python script.py`를 다시 치면 끝이라 시험 삼아 돌려보기에 좋다.
- **배포 형태의 차이** — 컴파일한 프로그램은 실행 파일 하나를 옮기면 되고, 인터프리트 언어는 받는 쪽에도 인터프리터가 깔려 있어야 한다.

## 🚫 흔한 오해

- **파이썬은 번역을 안 해서 느린 것이다** — 번역을 안 하는 게 아니라 돌리면서 한다. 느린 이유는 그 작업이 실행 중에 계속 끼어들기 때문이다.
- **언어마다 컴파일 언어인지 인터프리트 언어인지 정해져 있다** — 언어가 아니라 그 언어를 돌리는 도구의 문제다. 같은 언어를 미리 옮겨 돌리는 도구도, 한 줄씩 읽어 돌리는 도구도 있다.
- **컴파일이 통과하면 오류 없는 프로그램이다** — 문법과 타입이 맞다는 뜻일 뿐이다. 없는 파일을 열거나 0으로 나누는 일은 돌려봐야 안다.

## 📝 정리

**"미리 다 옮겨 두느냐, 닿을 때마다 옮기느냐"** 라고 읽으면 된다. 미리 옮기면 실행이 빠르고 오류를 먼저 보지만 옮기는 시간이 든다. 돌리면서 옮기면 고쳐서 바로 확인할 수 있는 대신 실행이 느리고 오류가 늦게 나온다.

## 🧒 열 살에게

외국 책을 읽는 방법은 두 가지야. 하나는 미리 우리말로 다 옮겨 놓고 그 책을 읽는 거고, 하나는 옆에 통역하는 사람을 두고 한 줄씩 읽어 달라고 하는 거야. 미리 옮겨 두면 읽기가 빠른 대신 책을 고칠 때마다 다시 옮겨야 하고, 통역을 두면 고친 자리를 그 자리에서 바로 읽어 줘.

## ❓ 이해했는지

- 프로그램이 한참 잘 돌다가 갑자기 멈추며 오류를 내는 건 어느 쪽 방식에서 더 잘 일어나나 → 비교
- 컴파일한 실행 파일을 다른 운영체제로 복사하면 왜 그대로 돌지 않나 → 작동 원리
- 컴파일이 성공했는데도 실행 중에 오류가 나는 경우는 왜 생기나 → 흔한 오해
