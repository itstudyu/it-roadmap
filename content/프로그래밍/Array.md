# Array / List (배열 / 리스트)

## 📝 정의

Array는 **여러 값을 번호 순서대로 담아두는 그릇**이다.

값마다 변수를 따로 만들면 개수가 늘어날수록 손을 댈 곳이 늘어난다. 배열은 값을 한 덩어리로 묶고 번호를 붙여서, 몇 개가 들어 있든 같은 코드로 다루게 한다.

### 비유
사물함. 칸마다 번호가 붙어 있어서 번호만 알면 앞칸부터 세지 않고 바로 그 칸을 연다.

## 🖼️ 그림으로 보기

```도해
흐름: 번호만으로 값을 바로 꺼낼 수 있는 이유는 무엇인가
만들기 :: 같은 크기 칸을 붙여 한 줄로 잡는다
시작 :: 첫 칸의 위치를 기억해둔다
요청 :: `numbers[3]` 을 달라고 한다
계산 :: 시작 위치 + 칸 크기 × 3
< 읽기 :: 그 자리를 한 번 읽고 끝난다
= 몇 번째든 걸리는 시간이 같다. 세어 나가는 게 아니라 계산해서 간다
```

## ⚠️ 해결하는 문제

```도해
대조: 값 100개를 변수 100개로 두면 어떻게 되나
따로 둔 변수 || 배열로
값 추가 :: 이름을 또 짓는다 || 뒤에 붙인다
전체 처리 :: 한 줄씩 쓴다 || 반복문 한 번
개수 세기 :: 직접 센다 || 길이를 물어본다
= 값을 하나로 묶으면 개수와 상관없이 같은 코드로 다룰 수 있다
```

점수 다섯 개를 `score1`부터 `score5`까지 변수로 두면 평균을 내려고 다섯 개를 전부 적어야 한다. 한 명이 늘면 변수를 하나 더 만들고 평균 식도 다시 고친다.

배열로 두면 값이 몇 개든 코드는 그대로다. 평균은 `sum(scores) / len(scores)` 한 줄이고, 전체 출력은 반복문 하나다. 값의 개수가 코드에 박히지 않는다.

## ⚙️ 작동 원리

번호는 0부터 센다. 첫 칸의 번호가 0인 건 규칙을 이상하게 만든 게 아니라, 번호가 "시작 위치에서 몇 칸 떨어졌나"를 뜻하기 때문이다. 첫 칸은 0칸 떨어져 있다.

```python
numbers = [10, 20, 30, 40, 50]

numbers[0]      # 10   첫 칸
numbers[-1]     # 50   뒤에서 첫 칸
numbers[1:4]    # [20, 30, 40]   1번부터 4번 앞까지
```

끝에 붙이는 것과 가운데에 끼우는 것은 값이 다르다. 끝에 붙이면 빈 자리에 놓고 끝나지만, 가운데에 끼우면 뒤쪽 값이 전부 한 칸씩 밀린다.

## 📊 비교

| Python | List | 늘었다 줄었다 한다 | 타입이 섞여도 된다 |
| JavaScript | Array | 늘었다 줄었다 한다 | 타입이 섞여도 된다 |
| Java | Array | 만들 때 정해진다 | 같은 타입만 |

## 💡 실제 사례

- **점수 통계** — 점수를 배열에 모아두면 평균, 최고점, 상위 세 명이 전부 한 줄짜리 계산이 된다.
- **조건에 맞는 것만 고르기** — 짝수만, 또는 5보다 큰 수만 골라 새 배열로 만든다. 원본은 그대로 둔다.
- **게임판** — 배열 안에 배열을 넣어 가로세로를 표현하고, `board[1][2]`처럼 두 번 번호를 매겨 한 칸을 가리킨다.

## 🚫 흔한 오해

- **번호는 1번부터 시작한다** — 대부분의 언어에서 0부터다. 번호가 순번이 아니라 시작 위치에서 떨어진 칸 수를 뜻하기 때문이다.
- **가운데에 넣는 것도 뒤에 붙이는 것만큼 빠르다** — 뒤에 붙이면 빈 자리에 놓고 끝나지만, 가운데에 끼우면 뒤쪽 값이 전부 밀린다.
- **배열을 다른 변수에 넣으면 복사된다** — 대개 같은 배열을 둘이 함께 보게 될 뿐이다. 한쪽에서 값을 더하면 다른 쪽에서도 늘어나 있다.

## 🚨 주의사항

- **없는 번호를 부르면 멈춘다.** 칸이 세 개인데 `numbers[5]`를 부르면 오류다. 길이를 먼저 확인하거나 반복문으로 도는 편이 안전하다.
- **복사가 필요하면 복사라고 써야 한다.** `list2 = list1`은 이름표를 하나 더 붙인 것이고, 따로 두려면 `list1.copy()`처럼 새로 만들어야 한다.

## 📝 정리

배열은 값을 한 줄로 붙여 담고 번호로 꺼내 쓰는 자료구조다. 번호로 위치를 계산해서 가기 때문에 몇 번째를 꺼내든 걸리는 시간이 같다. 대신 가운데를 건드리면 뒤쪽이 밀린다는 대가가 따른다.

## ❓ 이해했는지

- 100만 개짜리 배열에서 마지막 값을 꺼내는 게 첫 값을 꺼내는 것과 시간이 같은 이유는 → 그림
- `list2 = list1` 로 넘긴 뒤 list2에 값을 더했더니 list1도 늘어났다. 왜 그런가 → 흔한 오해
- 값이 몇 개 들어올지 모르는 상황에서 자바 배열을 쓰면 무엇이 걸리나 → 비교
