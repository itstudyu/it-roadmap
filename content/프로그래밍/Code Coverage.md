# Code Coverage (코드 커버리지)

## 📝 정의

코드 커버리지는 **테스트가 실제로 지나간 코드의 비율**이다.

재는 방법은 언어마다 다르다. Go 는 시험 전에 원본에 세는 장치를 심어 두고, 파이썬의 coverage.py 는 표준 라이브러리의 추적 고리를 써서 실행될 수 있는 줄과 실제로 실행된 줄을 가른다. Go 는 그렇게 얻은 값을 0 과 1 사이의 분수로 돌려준다.

### 이름
Code :: 실행되는 문장들
Coverage :: 덮인 정도
= 붙여 읽으면 "문장이 얼마나 덮였나". 이름이 곧 재는 값이다

### 비유
교과서에 그은 형광펜. 펼쳐 읽은 쪽에만 줄이 남고, 안 펼친 쪽은 하얗게 그대로 있다.

### 예
테스트를 다 돌린 끝에 "몇 퍼센트" 라는 숫자 하나를 보고 안심하거나 뜨끔했던 적이 있다면, 그 숫자가 이것이다.

## 🖼️ 그림으로 보기

```도해
대조: 테스트를 돌리고 나면 코드는 어떻게 나뉘나
안 지나간 줄 || 지나간 줄
보고서 :: 안 밟힘으로 남는다 || 밟힘으로 적힌다
셈 :: 분모에만 들어간다 || 분자에도 들어간다
알 수 있는 것 :: 시험한 적 없다 || 한 번은 지나갔다
= 커버리지는 지나간 줄이 전체의 몇 할인가를 적은 그 숫자다
```

## ⚠️ 해결하는 문제

```도해
대조: 무엇을 시험했는지 안 재면 어떻게 되나
재지 않으면 || 재면
빠진 자리 :: 아무도 모른다 || 목록으로 나온다
새로 쓴 코드 :: 시험 없이 섞인다 || 안 밟힌 줄이 뜬다
믿음 :: 통과했으니 됐다 || 어디까지인지 안다
= 테스트가 늘 초록인 것과 코드를 다 시험한 것은 다른 말이다
```

테스트가 다 통과했다는 말은 "쓴 테스트가 다 맞았다" 는 뜻일 뿐, 안 쓴 테스트에 대해서는 아무 말도 하지 않는다. 그래서 시험대에 한 번도 오르지 않은 자리는 통과 표시 뒤에 조용히 숨는다.

커버리지는 그 자리를 이름으로 불러 준다. 파일과 줄 번호로 "여기는 아무도 안 지나갔다" 고 적어 주므로, 다음에 무엇을 시험할지 고르는 일이 감이 아니라 목록이 된다.

## ⚙️ 작동 원리

Go 는 시험을 돌리기 전에 원본을 고쳐 쓴다. 함수 안을 갈래 없이 이어지는 덩어리(기본 블록)로 나누고 덩어리마다 세는 장치를 심는 것인데, 문서는 이것을 계측(instrumentation)이라 부르고 그 덩어리 나누기가 원본을 훑어 얻은 **어림값**이라고 못 박아 둔다. 세는 방식은 셋이다 — 이 문장이 도는지만 참·거짓으로 보는 `set`, 몇 번 도는지 세는 `count`, 그리고 여러 줄기가 함께 도는 시험에서도 값이 어긋나지 않는 대신 훨씬 비싼 `atomic`.

파이썬의 coverage.py 는 원본을 고치지 않는다. 표준 라이브러리가 주는 코드 분석 도구와 추적 고리를 써서, 애초에 실행될 수 있는 줄이 어디인지 먼저 가려낸 다음 그중 실제로 실행된 줄을 표시한다.

## 💡 실제 사례

- **어떤 테스트가 새 길을 여는지 본다** — 테스트를 하나씩 돌리며 값이 오르는지 보면, 그 테스트가 안 밟히던 자리를 밟았는지 알 수 있다.
- **고친 자리만 본다** — 전체 비율보다 이번에 손댄 줄이 밟혔는지를 먼저 본다. 오래된 코드의 낮은 값에 가려지지 않는다.
- **지워도 되는 코드 찾기** — 어떤 테스트도, 어떤 실행도 지나가지 않는 자리가 계속 남으면 정말 쓰이는 코드인지 의심해 볼 수 있다.

## 🚫 흔한 오해

- **커버리지가 100%면 버그가 없다** — 모든 줄을 지나갔다는 뜻일 뿐이다. 그 줄이 옳게 동작했는지는 재지 않는다.
- **줄을 다 밟았으면 모든 경우를 시험한 것이다** — 아니다. Go 의 계측기는 `&&` 와 `||` 안까지는 들여다보지 않는다고 스스로 적어 둔다. 조건 한쪽만 타고 지나가도 그 줄은 밟힌 것으로 적힌다.
- **숫자가 높을수록 좋은 테스트다** — 값은 지나갔는지만 센다. 아무것도 확인하지 않는 테스트를 늘려도 숫자는 똑같이 올라간다.

## 📝 정리

**"테스트가 밟고 지나간 자리의 비율"** 이라고 읽으면 된다. 밟았는지만 세고 옳았는지는 안 세므로, 높은 값은 좋은 테스트의 증거가 아니라 **안 밟은 자리를 찾는 지도**로 쓸 때 값어치가 있다.

## 🧒 열 살에게

시험공부 하면서 읽은 쪽마다 형광펜을 그어 둔다고 해 봐. 다 하고 나서 촤르륵 넘겨 보면 하얗게 남은 쪽이 보이지. 그게 네가 한 번도 안 본 쪽이야.

## ❓ 이해했는지

- 테스트가 전부 통과했는데도 안심할 수 없는 이유는 무엇인가 → 해결하는 문제
- 조건 두 개를 `&&` 로 묶은 줄이 밟혔다고 나올 때 무엇을 아직 모르는가 → 흔한 오해
- 아무것도 확인하지 않는 테스트를 잔뜩 넣으면 이 값은 어떻게 되나 → 정리

## 🔗 관련 용어

- [[Unit Test]] — 이 값을 실제로 만들어 내는 쪽. 밟는 일은 테스트가 한다
- [[Integration Test]] — 단위 테스트가 못 닿는 자리를 대신 지나가며 값을 채운다
- [[TDD]] — 테스트를 먼저 쓰는 방식. 커버리지는 목표가 아니라 결과로 따라온다
- [[CI/CD]] — 변경마다 이 값을 자동으로 재고 떨어지면 세우는 자리
