# Compile (컴파일)

## 📝 정의

컴파일은 **사람이 쓴 코드를 기계어로 미리 번역하는 일**이다.

CPU는 0과 1로 된 명령어만 알아듣는다. C나 Go로 쓴 글자를 그대로 넘기면 아무 일도 일어나지 않으므로, 실행하기 전에 한 번 바꿔둔다.

### 비유
번역서. 원서를 읽을 때마다 사전을 찾는 대신 미리 번역해 인쇄해두면, 읽을 때는 바로 읽힌다.

## 🖼️ 그림으로 보기

```도해
흐름: `hello.c` 한 파일이 실행 파일이 되기까지 무엇을 거치나
전처리 :: `#include` 같은 자리를 실제 내용으로 채운다
컴파일 :: 문법과 타입을 검사한 뒤 어셈블리로 바꾼다
어셈블 :: 어셈블리를 기계어 조각 파일로 바꾼다
링킹 :: 조각들과 라이브러리를 하나로 붙인다
< 실행 파일 :: 이제 CPU 가 바로 읽을 수 있다
= 오류는 대개 둘째와 넷째에서 난다. 문법이 틀렸거나 붙일 게 없거나다
```

## ⚠️ 해결하는 문제

```도해
대조: 실행할 때마다 코드를 해석하면 무엇이 달라지나
번역 없이 || 미리 번역해두면
반복문 :: 매번 다시 해석 || 한 번만 번역
오류 발견 :: 그 줄에 닿아야 || 실행 전에 안다
실행 속도 :: 해석 시간이 붙음 || 바로 실행된다
= 실행 전에 한 번 고생하고, 실행할 때마다 그만큼 덜 고생한다
```

인터프리터는 줄을 만날 때마다 그게 무슨 뜻인지 해석한다. 백만 번 도는 반복문이면 같은 해석을 백만 번 되풀이한다.

컴파일은 그 해석을 실행 전에 한 번만 한다. 덤으로 얻는 것이 있는데, 코드 전체를 훑기 때문에 타입이 안 맞는 자리 같은 것을 실행하기 전에 잡아낸다. 대신 고칠 때마다 다시 번역해야 하고, 번역 결과는 그 CPU와 운영체제에 맞춰 나오므로 다른 환경으로 옮기면 거기서 다시 해야 한다.

## 📊 비교

| | 컴파일 (AOT) | 인터프리터 | JIT |
|---|---|---|---|
| 번역 시점 | 실행 전에 전부 | 실행하면서 한 줄씩 | 실행 중 자주 도는 부분만 |
| 시작 | 컴파일을 기다린다 | 바로 시작 | 바로 시작 |
| 오류 발견 | 실행 전 | 그 줄에 닿을 때 | 대부분 실행 중 |
| 다른 환경으로 | 다시 컴파일 | 그대로 | 실행기만 있으면 그대로 |
| 예 | C, Rust, Go | Python | Java, JavaScript |

## 💡 실제 사례

- **느린 부분만 바꾸기** 파이썬에서 계산이 몰리는 함수만 C로 써서 컴파일해두고 불러 쓴다.
- **자바의 두 단계** 소스를 바이트코드로 컴파일해두고, 실행할 때 자주 도는 부분만 기계어로 다시 바꾼다.
- **최적화 옵션** 같은 코드도 `-O2` 같은 옵션을 주고 컴파일하면 더 빠른 실행 파일이 나온다.

## 🚫 흔한 오해

- **컴파일하면 프로그램이 빨라진다** — 번역해두는 것뿐이라 절차가 나쁘면 그대로 느리다. 사라지는 건 실행할 때마다 하던 해석 시간이다.
- **파이썬은 컴파일을 안 한다** — 바이트코드로 컴파일한다. 그게 기계어가 아니라 실행기가 읽는 중간 코드라서 실행 중에 한 번 더 거칠 뿐이다.
- **컴파일이 되면 코드가 맞다는 뜻이다** — 문법과 타입만 맞다는 뜻이다. 계산이 틀린 코드에는 컴파일러가 아무 말도 하지 않는다.

## 📝 정리

컴파일은 사람이 쓴 코드를 실행 전에 기계어로 바꿔두는 과정이다. 실행할 때마다 하던 해석을 한 번으로 줄이고, 그 김에 문법과 타입 오류를 실행 전에 잡는다. 대신 고칠 때마다 다시 번역해야 하고 환경이 바뀌면 그 자리에서 다시 해야 한다.
