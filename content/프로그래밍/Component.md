# Component (컴포넌트)

## 📝 정의

Component는 **화면의 한 조각을 떼어내 재사용하는 단위**다.

버튼, 카드, 모달처럼 여러 화면에 되풀이해서 나오는 것을 한 번만 정의해두고 필요한 곳에서 불러 쓴다. 화면은 조각을 조립한 결과가 된다.

### 이름
= component 는 "전체를 이루는 한 부품". 화면이 부품을 조립한 결과라는 말이 이름에 들어 있다

### 비유
레고 블록. 같은 블록을 여기저기 꽂아 쓰고, 블록 하나를 바꾸면 그 블록을 쓴 곳이 전부 따라 바뀐다.

### 예
쇼핑 앱에서 상품마다 똑같이 생긴 카드가 사진과 이름만 바꿔 가며 늘어서는 것이 컴포넌트다.

### 직접
쇼핑 앱에서 상품 목록을 죽 내려 보라. 사진과 이름만 바뀌고 카드 테두리와 단추 자리는 전부 똑같다.

## 🖼️ 그림으로 보기

```도해
흐름: 버튼을 컴포넌트로 만들면 무슨 일이 벌어지나
정의 :: 버튼을 그리는 코드를 한 번만 쓴다
사용 :: 필요한 화면마다 이름으로 불러 쓴다
Props :: 부를 때 글자와 동작을 넘겨준다
화면 :: 넘겨받은 값대로 각자 다르게 그려진다
@ 다시 정의로 :: 한 곳을 고치면 쓴 곳이 다 바뀐다
= 같은 코드를 여러 벌 두지 않고 한 벌만 두는 것이 요점이다
```

## ⚠️ 해결하는 문제

```도해
대조: 같은 버튼을 화면마다 새로 쓰면 어떻게 되나
컴포넌트 없이 || 컴포넌트로
디자인 변경 :: 전부 찾아 고침 || 한 곳만 고침
코드 위치 :: 한 파일에 몰림 || 조각마다 나뉨
테스트 :: 전체를 띄워야 함 || 조각만 띄운다
= 고칠 곳이 하나면 빠뜨릴 곳도 없다
```

같은 모양의 버튼을 화면 스무 곳에 직접 써두면, 색을 바꾸라는 요청 하나에 스무 곳을 찾아야 한다. 한 곳을 빠뜨리면 그 화면만 옛 색으로 남는다.

컴포넌트로 묶으면 정의가 한 곳이라 고칠 곳도 한 곳이다. 파일이 나뉘니 여러 사람이 각자 다른 조각을 동시에 손봐도 부딪히지 않고, 버튼 하나를 확인하려고 애플리케이션 전체를 띄울 필요도 없다.

## ⚙️ 작동 원리

컴포넌트에 값을 넣는 통로가 둘이다. 밖에서 받는 값이 Props고, 안에서 바뀌는 값이 State다.

```jsx
function Button({ text, onClick }) {     // Props: 부모가 넘겨준다
  return <button onClick={onClick}>{text}</button>;
}

function Counter() {
  const [count, setCount] = useState(0); // State: 안에서 바뀐다
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

Props는 받은 쪽에서 바꾸지 않는다. 부모가 준 값이라 부모가 바꿔야 한다. State는 컴포넌트가 자기 것으로 들고 있는 값이고, 이 값이 바뀌면 그 컴포넌트가 다시 그려진다.

조립은 트리 모양이 된다. App 아래에 Header와 Main과 Footer가 있고, Header 아래에 Logo와 Navigation이 있는 식이다. 위쪽 컴포넌트는 배치를 맡고 아래로 갈수록 실제로 그리는 일을 한다.

## 💡 실제 사례

- **화면 쪼개기** — 2000줄짜리 대시보드 파일을 헤더, 사이드바, 차트, 표로 나누면 각 파일이 수십 줄에서 200줄 사이가 된다.
- **입력 칸 통일** — 라벨, 필수 표시, 오류 메시지를 담은 입력 컴포넌트를 하나 만들어 모든 폼에서 쓰면 생김새가 저절로 같아진다.
- **로딩 표시** — 로딩 컴포넌트를 하나 두고 데이터를 기다리는 모든 화면에서 불러 쓰면 기다리는 모습이 화면마다 달라지지 않는다.

## 🚫 흔한 오해

- **컴포넌트는 화면 조각이니 겉모습만 담는다** — 자기 상태와 동작도 같이 품는다. 카운터 컴포넌트는 숫자를 자기 안에 들고 있고, 그 숫자가 바뀌면 스스로 다시 그린다.
- **Props도 컴포넌트 안에서 바꾸면 된다** — 부모가 내려준 값이라 받은 쪽에서 바꾸지 않는다. 안에서 바뀌어야 하는 값은 State로 둔다.
- **잘게 쪼갤수록 좋다** — 한 번밖에 안 쓰는 것까지 쪼개면 파일만 늘고 무엇이 어디 있는지 찾기 어려워진다. 되풀이되는 것부터 떼어낸다.

## 📊 비교

| 구분 | 일반 함수 | 컴포넌트 |
|---|---|---|
| 돌려주는 것 | 값 | 화면 조각 |
| 상태 | 없다 | State를 가질 수 있다 |
| 다시 실행 | 부를 때만 | 상태가 바뀌면 스스로 |

## 📝 정리

**"한 번 만들어 여기저기 꽂아 쓰는 그 조각"** 이라고 읽으면 된다. 정의가 한 곳이라 고칠 곳도 한 곳이고, 파일이 나뉘어 있어 따로 만들고 따로 확인할 수 있다. 밖에서 받는 값은 Props로, 안에서 바뀌는 값은 State로 나눠 둔다.

## 🧒 열 살에게

레고로 집을 지을 때 창문 블록 하나를 여기저기 꽂아 쓰지? 창문 모양을 바꾸고 싶으면 그 블록만 바꾸면 꽂아 둔 자리가 전부 따라 바뀌어. 대신 꽂을 때 색은 따로 정해 줄 수 있어서, 같은 블록인데 하나는 파랑 하나는 빨강이야.

## ❓ 이해했는지

- 버튼 색을 전부 바꿔야 하는데 컴포넌트를 안 썼다면 무엇을 해야 하나 → 해결하는 문제
- 같은 카드 컴포넌트가 화면마다 다른 이름을 보여주는 건 무엇 덕분인가 → 그림
- 카운터 숫자처럼 컴포넌트 안에서 바뀌는 값은 Props와 State 중 어디에 두나 → 작동 원리
