# Integration Test (통합 테스트)

## 📝 정의

Integration Test 는 **조각을 이어 붙여 함께 도는지 보는** 테스트다.

단위 테스트가 가짜로 대신하던 것을 여기서는 진짜로 쓴다. 저장소, 파일, 망에 걸린 부분까지 함께 세워 두고, 요청 하나를 온전히 처리하는 데 필요한 것을 전부 붙여 돌려 보기도 한다. 그래서 조각 안의 판단이 아니라 조각과 조각 사이의 약속이 시험 대상이 된다.

### 이름
Integration :: 따로 놀던 걸 합침
Test :: 맞는지 확인
= 붙여 읽으면 "합쳐 놓고 맞는지 확인". 합친 자리에서만 나는 탈을 잡는 시험이다

### 비유
부품 검사를 하나하나 다 통과한 자전거라도, 조립해서 한 바퀴 굴려 봐야 체인이 튀는지 알 수 있다.

### 예
로그인은 되는데 그다음 화면에서만 목록이 비어 나오는 그 상황이다. 두 조각이 각자는 멀쩡하고 사이가 안 맞을 때 이렇게 된다.

## 🖼️ 그림으로 보기

```도해
층: 무엇까지 붙여 놓고 보는 시험인가
단위 :: 조각 하나. 밖의 것은 전부 가짜로 대신한다
통합 :: 조각 여럿에 진짜 저장소와 파일까지. 사이가 맞는지 본다
전체 :: 다 띄우고 사람이 쓰듯 눌러 본다. 가장 느리고 잘 깨진다
= 통합은 가운데다. 조각 안이 아니라 조각과 조각 사이를 본다
```

## ⚠️ 해결하는 문제

```도해
대조: 조각마다 다 통과했는데 왜 안 도나
붙여 안 보면 || 붙여 보면
가짜로 대신한 것 :: 진짜와 달라도 모름 || 진짜를 그대로 쓴다
조각 사이 약속 :: 아무도 안 본다 || 어긋나면 걸린다
설정과 배선 :: 켜 봐야 안다 || 미리 걸러진다
= 조각이 다 맞아도 사이가 틀리면 안 돈다. 그 사이는 붙여야만 보인다
```

가짜는 편한 대신 거짓말을 할 수 있다. 시험에서 세워 둔 가짜 저장소는 언제나 얌전히 답하지만, 진짜 저장소는 컬럼 이름이 다르거나 권한이 없거나 연결이 끊긴다. 이 차이는 붙여 보기 전까지 아무 시험에도 안 걸린다.

무엇이 무엇에 꽂혀 있는지도 마찬가지다. 조각 하나하나는 다 맞는데 설정에서 엉뚱한 것을 꽂아 두면, 앱은 켜지고 나서야 틀린 것을 알려준다. 통합 테스트는 그 켜는 일을 미리 한 번 해 보는 자리다.

## ⚙️ 작동 원리

진짜 부품을 쓴다는 말이 곧 운영 환경에 올려서 돌린다는 뜻은 아니다. 앱을 시험하는 그 자리에서 띄우고, 요청이 들어와 응답이 나가기까지의 길을 그대로 한 바퀴 돌린다. 서버에 올리거나 바깥 설비에 붙이지 않고도 배선이 맞는지, 손으로 적은 질의문과 테이블 짝이 맞는지, 묶음의 경계가 제대로 잡혔는지를 본다.

대신 값을 치른다. 붙는 것이 늘어난 만큼 준비할 것이 많고 도는 데 오래 걸린다. 단위 테스트가 천분의 몇 초로 끝나는 자리에서 통합 테스트는 훨씬 느리다. 그래서 같은 것을 두 시험 어느 쪽으로도 확인할 수 있으면 단위 쪽을 고른다.

## 💡 실제 사례

- **읽고 쓰고 고치고 지우기** — 저장소가 걸린 곳은 이 네 갈래만 한 벌 덮어 두면 대개 충분하다. 나머지 판단은 단위 테스트가 맡는다.
- **요청 한 바퀴** — 요청이 들어와 응답이 나가기까지를 통째로 한 번 돌려, 중간에 낀 것들이 다 꽂혀 있는지 본다.
- **질의문 점검** — 손으로 적은 질의문과 테이블 짝이 맞는지는 진짜 저장소에 물어봐야 안다.

## 🚫 흔한 오해

- **통합 테스트는 그냥 느린 단위 테스트다** — 보는 것이 다르다. 단위는 조각 안의 판단을, 통합은 조각 사이의 약속을 본다.
- **통합 테스트로 다 덮으면 제일 안전하다** — 경우의 수마다 통합으로 덮으면 한 벌이 몇 시간짜리가 된다. 같은 것을 단위로 확인할 수 있으면 단위로 하는 편이 낫다.
- **통합 테스트는 서버에 올려야 돌릴 수 있다** — 올리지 않고 돌리는 것이 이 시험의 요점이다. 앱을 그 자리에서 띄우고 진짜 부품만 붙인다.

## 🚨 주의사항

- **테스트끼리 자리를 나눠 쓰면 순서가 결과를 바꾼다.** 앞 테스트가 남긴 값이 뒤 테스트를 깨뜨린다. 시작할 때의 상태를 정해 두고 끝나면 되돌린다.
- **느린 만큼 결국 안 돌리게 된다.** 한 벌이 몇 시간으로 늘면 마지막에 몰아서 돌리게 되고, 그러면 고칠 시간이 없을 때 알게 된다.

## 📝 정리

**"조각 사이가 맞는지 붙여 보는 그 시험"** 이라고 읽으면 된다. 가짜를 걷어내고 진짜를 붙이는 만큼 느려지고 준비할 것도 늘어난다. 그래서 다 덮는 것이 아니라, 붙여야만 드러나는 자리만 골라 덮는다.

## 🧒 열 살에게

자전거 부품을 하나씩 다 살펴봐도, 조립해서 타 보기 전에는 체인이 튀는지 몰라. 그래서 다 끼운 다음에 마당을 한 바퀴 돌아 보는 거야. 부품 탓이 아니라 서로 안 맞아서 나는 탈은 그때만 보이거든.

## ❓ 이해했는지

- 조각마다 다 통과했는데 이어 붙이면 안 도는 일이 왜 생기나 → 해결하는 문제
- 같은 것을 두 시험 어느 쪽으로도 확인할 수 있으면 어느 쪽을 고르나 → 흔한 오해
- 앞 테스트를 돌린 뒤에만 뒤 테스트가 깨지는 이유는 → 주의사항
