# 정규표현식 (Regex / Regular Expression)

## 📝 정의

정규표현식은 **글자의 모양을 규칙으로 적어 찾아내는 문법**이다.

전화번호나 이메일처럼 "이런 모양이면 전부 해당"인 것을 하나하나 적는 대신 규칙 한 줄로 적는다. 거의 모든 프로그래밍 언어와 편집기가 같은 문법을 쓴다.

### 비유
파일 탐색기의 `*.txt` 검색. 파일 이름을 다 적지 않아도 모양만 알려주면 해당하는 것을 골라준다.

## 🖼️ 그림으로 보기

```도해
흐름: user@example.com 이 이메일 형식인지 어떻게 가려내나
패턴 :: `^[\w.-]+@[\w.-]+\.[a-z]{2,}$` 를 준다
엔진 :: 문법을 검사하고 내부 형태로 바꾼다
앞부분 :: `[\w.-]+` 가 "user" 를 잡는다
가운데 :: `@` 가 "@" 와 맞는다
뒷부분 :: `[a-z]{2,}` 가 "com" 을 잡는다
< 결과 :: `$` 까지 맞았으니 통과로 돌려준다
= 왼쪽부터 한 조각씩 맞춰보고 끝까지 맞으면 그때 통과다
```

## ⚠️ 해결하는 문제

```도해
대조: 입력이 이메일 형식인지 확인하려면 무엇이 달라지나
직접 코드로 || 정규식으로
검증 코드 :: 수십 줄 || 한 줄
규칙 변경 :: 코드를 고침 || 패턴만 고침
재사용 :: 복사해 붙임 || 패턴을 공유
= 조건을 코드로 풀어 쓰는 대신 모양 자체를 적는 것이다
```

이메일에 `@` 가 있는지, 그 앞뒤에 글자가 있는지, 마지막 점 뒤에 두 글자 이상이 오는지를 코드로 확인하려면 조건문이 줄줄이 이어진다. 규칙이 하나 바뀌면 그 뭉치를 다시 읽고 고쳐야 한다.

정규표현식은 그 조건들을 모양 하나로 적는다. `^[\w.-]+@[\w.-]+\.[a-z]{2,}$` 한 줄이 위의 조건을 전부 담는다. 로그에서 에러 줄만 뽑거나 전화번호 형식을 바꾸는 일도 같은 문법으로 한다.

## ⚙️ 작동 원리

문법은 몇 갈래로 나뉜다.

```도해
층: 패턴은 무엇으로 이루어져 있나
문자 클래스 :: `[a-z]`, `\d`, `\w`. 어떤 글자인지
수량자 :: `*`, `+`, `?`, `{n,m}`. 몇 번 나오는지
경계 :: `^`, `$`, `\b`. 어디에 붙는지
그룹 :: `( )`, `|`. 묶는 것과 고르는 것
= 어떤 글자가 몇 번 어디에 나오는지를 조합해 모양을 만든다
```

수량자는 기본이 욕심쟁이다. 가능한 한 많이 잡아두고 보다가 뒤가 안 맞으면 한 글자씩 물러나며 다시 맞춰본다. 이렇게 되돌아가는 것을 백트래킹이라고 한다. `*?` 나 `+?` 로 적으면 반대로 가능한 한 적게 잡는다.

성능 문제는 대개 이 백트래킹에서 나온다. 되돌아갈 경우의 수가 많은 패턴에 긴 문자열을 넣으면 확인해야 할 조합이 크게 늘어난다.

## 📊 비교: 자주 쓰는 패턴

| 패턴 | 무엇을 잡나 | 맞는 예 | 안 맞는 예 |
|---|---|---|---|
| `^\d{3}-\d{3,4}-\d{4}$` | 전화번호 | 010-1234-5678 | 01-123-456 |
| `^\d{4}-\d{2}-\d{2}$` | 날짜 | 2024-02-19 | 2024/02/19 |
| `^[A-Z][a-z]+$` | 첫 글자만 대문자 | Hello | hello, HELLO |
| `<[^>]+>` | HTML 태그 | `<div class="x">` | 그냥 글자 |

## 💡 실제 사례

- **가입 폼 검증** 이메일 형식이 맞는지 서버로 보내기 전에 브라우저에서 먼저 거른다.
- **로그에서 뽑기** 에러가 난 줄만 골라내고, 그 줄에서 날짜 부분만 다시 뽑는다.
- **형식 바꾸기** `01012345678` 을 세 덩어리로 묶어 `010-1234-5678` 로 바꾼다. 묶은 자리를 `$1`, `$2` 로 가져다 쓴다.

## 🚫 흔한 오해

- **정규식이 통과시켰으면 실제로 있는 값이다** — 모양만 본다. `abc@abc.com` 은 형식은 맞지만 그런 주소가 있는지는 정규식이 알 수 없다.
- **패턴은 정교할수록 좋다** — 길어질수록 쓴 사람도 못 읽는다. 한 달 뒤에 자기가 쓴 패턴을 해석하지 못하는 일이 흔하다.
- **HTML도 정규식으로 파싱하면 된다** — 태그가 안으로 겹쳐 들어가는 구조는 모양 규칙으로 표현되지 않는다. 파서를 쓰는 자리다.

## 🚨 주의사항

- **긴 입력에 복잡한 패턴을 물리지 않는다.** 짧은 문자열에서 멀쩡하던 패턴이 긴 입력에서는 멈춘 것처럼 느려질 수 있다.
- **메타문자를 글자 그대로 찾을 때는 백슬래시를 붙인다.** 점은 아무 글자 하나를 뜻하므로 진짜 점을 찾으려면 `\.` 로 적는다.

## 📝 정리

정규표현식은 글자의 모양을 규칙으로 적어 찾고 확인하고 바꾸는 문법이다. 어떤 글자가 몇 번 어디에 나오는지를 조합해 패턴을 만들면, 엔진이 왼쪽부터 맞춰보다가 안 맞으면 되돌아가며 다시 시도한다. 짧게 유지하지 않으면 읽기도 어렵고 느려지기도 한다.
