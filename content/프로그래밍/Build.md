# Build (빌드)

## 📝 정의

Build는 **소스 코드를 실행할 수 있는 형태로 만드는 과정**이다.

컴파일 하나를 가리키는 말이 아니다. 필요한 라이브러리를 받는 일부터 검사, 테스트, 압축, 포장까지 배포할 물건이 나올 때까지의 공정 전체를 말한다.

### 비유
자동차 조립 라인. 부품을 들여오고 조립하고 검사하고 포장해서 내보내기까지가 한 줄로 이어져 있다.

### 예
앱 업데이트를 누를 때 내려받는 그 파일 하나가 빌드가 끝나고 나온 결과물이다.

## 🖼️ 그림으로 보기

```도해
흐름: 소스 코드가 배포할 물건이 되기까지 무엇을 거치나
의존성 :: 필요한 라이브러리를 정해진 버전으로 받는다
검사 :: 형식과 문법을 먼저 본다
컴파일 :: 소스를 실행 가능한 형태로 바꾼다
테스트 :: 통과하지 못하면 여기서 멈춘다
포장 :: 실행 파일이나 이미지 하나로 묶는다
산출물 :: 배포할 수 있는 덩어리가 남는다
= 어느 단계에서든 실패하면 그 뒤로 넘어가지 않는다
```

## ⚠️ 해결하는 문제

```도해
대조: 손으로 명령을 하나씩 치면 어떻게 되나
손으로 || 빌드 도구로
파일 백 개 :: 명령 수십 줄 || 한 줄
하나만 고쳤을 때 :: 전부 다시 || 바뀐 것만
사람마다 결과 :: 제각각 || 같아진다
= 같은 소스에서 같은 결과가 나오게 만드는 것이 빌드 도구의 일이다
```

파일이 백 개인 프로젝트를 손으로 컴파일하면 명령을 수십 줄 친다. 하나를 고쳤을 때 어떤 파일들이 영향을 받는지도 사람이 따져야 한다.

더 곤란한 것은 "제 컴퓨터에서는 됩니다"다. 개발자마다 언어 버전과 라이브러리 버전이 다르면 같은 소스에서 다른 결과가 나온다. 빌드 도구와 버전을 고정한 파일이 그 차이를 없애서, 어디서 돌려도 같은 산출물이 나오게 한다.

## ⚙️ 작동 원리

빌드 도구는 무엇이 무엇에 의존하는지 알고 있다. 그래서 바뀐 파일과 그것에 딸린 것만 다시 만들고 나머지는 지난번 결과를 그대로 쓴다. 이 재사용이 빌드 시간을 좌우한다.

컨테이너 이미지를 만들 때도 같은 원리가 걸린다. 자주 바뀌지 않는 의존성 설치를 앞에 두고 소스 복사를 뒤에 두면, 코드를 고쳐도 의존성 단계는 지난 결과를 다시 쓴다. 순서를 뒤집으면 매번 처음부터 설치한다.

## 💡 실제 사례

- **코드를 올릴 때마다 자동 실행** — 저장소에 변경이 올라오면 검사와 테스트와 포장이 자동으로 돈다. 하나라도 실패하면 배포로 넘어가지 않는다.
- **개발 중 즉시 반영** — 개발용 도구는 바뀐 부분만 다시 만들어 화면에 바로 반영한다. 전체를 새로 만들지 않는다.
- **컨테이너 이미지 생성** — 실행에 필요한 것을 이미지 하나에 담아두면 어느 서버에서든 같은 환경으로 뜬다.

## 📊 비교

| | 개발용 빌드 | 배포용 빌드 |
|---|---|---|
| 목적 | 고치면서 확인 | 실제 서비스 |
| 최적화 | 하지 않는다 | 압축하고 줄인다 |
| 디버그 정보 | 넣는다 | 뺀다 |
| 걸리는 시간 | 짧다 | 길다 |

## 🚫 흔한 오해

- **빌드는 컴파일을 부르는 다른 말이다** — 컴파일은 여러 단계 중 하나다. 의존성 설치, 검사, 테스트, 포장까지가 빌드 안에 들어간다.
- **컴파일하지 않는 언어에는 빌드가 없다** — 자바스크립트나 파이썬도 의존성 설치와 번들링과 패키징을 거친다. 기계어로 바꾸는 단계만 없을 뿐이다.
- **빌드에 성공했으면 제대로 도는 것이다** — 만들어졌다는 뜻이지 맞게 동작한다는 뜻이 아니다. 그 확인은 테스트 단계가 한다.

## 🚨 주의사항

- **의존성 버전을 고정한다.** 버전을 박아두지 않으면 코드를 안 고쳐도 어제 되던 빌드가 오늘 깨진다.
- **테스트를 빌드 안에 넣는다.** 테스트가 빌드 밖에 있으면 실패해도 배포가 그대로 진행된다.

## 📝 정리

Build는 소스 코드에서 배포할 산출물이 나오기까지의 공정 전체다. 컴파일 한 단계가 아니라 의존성부터 포장까지가 다 들어간다. 자동화와 버전 고정이 있어야 어느 컴퓨터에서든 같은 결과가 나온다.

## ❓ 이해했는지

- 파이썬처럼 컴파일하지 않는 언어에도 빌드가 있는 이유는 → 흔한 오해
- 코드를 안 고쳤는데 어제 되던 빌드가 오늘 깨졌다면 무엇을 의심해야 하나 → 주의사항
- 컨테이너 이미지를 만들 때 의존성 설치를 소스 복사보다 앞에 두는 이유는 → 작동 원리
