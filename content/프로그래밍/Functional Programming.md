# Functional Programming (함수형 프로그래밍)

## 📝 정의

함수형 프로그래밍은 **바깥을 건드리지 않는 함수로 프로그램을 짜는 방식**이다.

문제를 쪼개는 방식은 하나가 아니다. 파이썬 공식 문서는 함수형을 "문제를 함수의 집합으로 쪼개는 것" 이라고 적고, 이상적인 함수는 입력을 받아 출력을 낼 뿐 같은 입력의 결과를 바꿔 놓을 내부 상태를 갖지 않는다고 덧붙인다. 특정 언어의 문법이 아니라 어느 언어에서나 고를 수 있는 짜기 방식이다.

### 이름
Functional :: 함수로 이루어진
Programming :: 프로그램 짜기
= 붙여 읽으면 "함수로 프로그램 짜기". 시킬 일을 순서대로 늘어놓는 대신 함수를 겹쳐 쓴다

### 비유
주스 믹서기. 같은 과일을 넣으면 늘 같은 주스가 나오고, 옆에 놓인 냄비 속은 건드리지 않는다.

### 예
엑셀 수식이 그렇다. 합계 칸에 값이 새로 생길 뿐, 위에 있던 숫자 칸은 하나도 안 바뀐다.

## 🖼️ 그림으로 보기

```도해
흐름: 함수형으로 짠 프로그램에서 값은 어떻게 흘러가나
입력 :: 주문 목록 하나가 들어온다
거르기 :: 취소된 줄을 뺀 새 목록을 낸다
바꾸기 :: 각 줄에서 금액만 남긴 새 목록을 낸다
모으기 :: 금액들을 더해 합계 하나를 낸다
원본 :: 처음 들어온 주문 목록은 그대로다
= 값이 함수를 지날 때마다 새 값이 생긴다. 지나온 값은 하나도 안 바뀐다
```

## ⚠️ 해결하는 문제

```도해
대조: 함수가 바깥 값을 고치면 무슨 일이 생기나
바깥을 고치면 || 값만 돌려주면
같은 입력 :: 결과가 달라진다 || 결과가 같다
고장 찾기 :: 온 데를 뒤진다 || 그 함수만 본다
동시에 돌리기 :: 서로 덮어쓴다 || 따로 돌아간다
= 바깥을 안 건드리면 함수 하나만 보고도 결과를 말할 수 있다
```

값을 여기저기서 고치는 프로그램은 어디서 무엇이 바뀌었는지 아무도 모르는 채로 자란다. 어제 잘 돌던 계산이 오늘 다른 답을 내면, 그 답을 낸 자리가 아니라 그 값을 만졌을지 모르는 모든 자리를 뒤져야 한다.

함수형은 뒤질 자리를 없앤다. 함수가 제 입력만 보고 값을 돌려주면 결과가 이상할 때 볼 곳은 그 함수 하나다. 파이썬 문서는 같은 이유로 테스트(만든 것을 실제로 돌려 보고 맞는지 확인하는 일)가 쉬워진다고 적는다 — 미리 만들어 둘 바깥 상태가 없으니, 입력을 넣고 나온 값만 견주면 된다.

## ⚙️ 작동 원리

순수 함수는 두 가지를 지킨다. 같은 입력에는 언제나 같은 값을 돌려주고, 부작용이 없다. 마이크로소프트의 F# 문서가 순수성을 그 두 문장으로 정의한다.

부작용은 나쁜 짓이라는 뜻이 아니라 "돌려준 값에 안 담긴 변화" 라는 뜻이다. 화면에 글자를 찍는 것, 파일에 쓰는 것, 바깥에 둔 값을 고치는 것이 전부 부작용이다. 파이썬 문서는 화면 출력이나 파일 쓰기처럼 모든 부작용을 피하기는 어렵다고 못 박는다.

둘째 규칙은 값을 고치지 않는 것이다. 고칠 일이 생기면 그 자리를 손보는 대신 새 값을 만든다. [[Immutability]](불변) 이 이 방식의 짝인 이유다.

셋째는 문 대신 식이다. 식은 값을 내놓는 조각이고, 문은 무엇을 하라고 시키는 조각이다. 값을 내놓는 조각으로만 짜면 그 조각을 결과 값으로 바꿔 놓아도 프로그램이 똑같이 돈다. F# 문서는 그 성질을 참조 투명성이라 부른다.

## 💡 실제 사례

- **목록 다루기** — 거르고 바꾸고 모으는 함수를 차례로 겹쳐 쓰면 원본 목록을 건드리지 않고 원하는 값 하나를 얻는다.
- **화면 그리기** — React 문서는 컴포넌트를 순수 함수로 보고, 같은 입력이면 언제나 같은 화면을 내놓아야 한다고 적는다.
- **테스트 짜기** — 바깥 상태를 미리 차려 둘 필요가 없어서, 입력을 넣고 나온 값만 견주면 그 함수를 다 확인한 것이 된다.

## 🚫 흔한 오해

- **함수를 많이 쓰면 함수형이다** — 함수를 쓰느냐가 아니라 그 함수가 바깥을 건드리느냐가 갈림길이다. 바깥 값을 고치는 함수는 백 개를 만들어도 결과가 그때그때 달라진다.
- **함수형이면 부작용이 아예 없다** — 파이썬 문서는 화면에 찍고 파일에 쓰는 일까지 전부 피하기는 어렵다고 적는다. 부작용을 없애는 게 아니라 한쪽으로 몰아 두는 것이다.
- **함수형이 명령형보다 항상 낫다** — 방식은 골라 쓰는 것이다. 값을 그 자리에서 고쳐야 하는 일, 화면·파일·기계 상태를 다루는 일은 결국 누군가 맡아야 한다.

## 📝 정리

**"바깥을 안 건드리고 값만 돌려주는 짜기"** 라고 읽으면 된다. 순수 함수의 조건은 둘뿐이다 — 같은 입력에 같은 출력, 그리고 함수 밖에 남는 변화가 없을 것. 그 둘을 지키면 결과가 이상할 때 볼 곳이 그 함수 하나로 줄어든다.

## 🧒 열 살에게

과일을 믹서기에 넣으면 주스가 나오지? 같은 과일을 넣으면 언제나 같은 주스가 나오고, 옆에 있던 냄비는 하나도 안 건드려. 그래서 맛이 이상하면 부엌 전체를 뒤질 필요 없이 그 믹서기만 열어 보면 돼.

## ❓ 이해했는지

- 취소된 줄을 걸러 냈는데도 원래 주문 목록이 그대로인 이유는 무엇인가 → 그림
- 어제와 같은 값을 넣었는데 오늘 다른 답이 나온다면 무엇을 의심해야 하나 → 해결하는 문제
- 화면에 글자를 찍는 일은 이 방식에서 어떻게 다뤄지나 → 흔한 오해
