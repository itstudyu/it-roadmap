# Framework vs Library (프레임워크와 라이브러리)

## 📝 정의

둘의 차이는 **누가 누구를 부르느냐** 하나로 갈린다.

크기나 완성도의 차이가 아니다. 내 코드가 가져다 부르면 라이브러리고, 반대로 그쪽이 정해진 시점에 내 코드를 불러 쓰면 프레임워크다.

### 비유
망치와 현장 관리자. 망치는 내가 필요할 때 꺼내 들고, 관리자는 나를 불러 일을 시킨다.

## 🖼️ 그림으로 보기

```도해
대조: 내 코드와 그쪽 코드 중 누가 누구를 부르나
Library |=| Framework
먼저 시작 :: 내 코드가 || 그쪽이
부르는 쪽 :: 내가 부른다 || 내가 불린다
구조 :: 내가 정한다 || 이미 정해져 있다
갈아끼우기 :: 쉽다 || 대부분 다시 짠다
= 부르는 방향이 어디냐가 둘을 가르는 유일한 기준이다
```

## ⚠️ 해결하는 문제

```도해
대조: 둘을 구분 못 하면 어떤 선택을 그르치나
구분 못 하면 || 구분하면
정해진 규칙 :: 무시하고 짠다 || 맞춰서 짠다
기능 하나 :: 큰 틀부터 깐다 || 필요한 것만
큰 화면 :: 직접 다 만든다 || 틀에 얹는다
= 무엇이 나를 부르는지 알아야 어디까지가 내 몫인지 정해진다
```

기능 하나만 붙이면 될 자리에 프레임워크를 깔면 쓰지도 않을 구조와 규칙이 통째로 따라온다. 반대로 화면이 여러 개이고 상태가 얽히는 앱을 라이브러리만으로 짜면, 화면 전환과 상태 관리와 갱신 시점을 전부 직접 만들게 된다. 결국 프레임워크를 하나 새로 쓰는 셈이 되는데 그 품질은 검증되지 않은 것이다.

부르는 방향을 알면 이 선택이 쉬워진다. 구조를 내가 정하고 싶으면 라이브러리, 검증된 구조 위에 내 코드만 얹고 싶으면 프레임워크다.

## ⚙️ 작동 원리

프레임워크가 내 코드를 부르는 구조를 제어의 역전이라고 부른다. 원래 프로그램의 흐름은 내가 쓴 코드가 쥐고 있었는데, 그 주도권이 반대쪽으로 넘어갔다는 뜻이다.

같은 말을 더 짧게 하면 "우리한테 전화하지 마, 우리가 전화할게"가 된다. 프레임워크가 요구하는 규칙들은 대부분 이 통화가 가능하게 만드는 조건이다. 함수 이름과 위치를 정해두는 것도, 반환 형식을 정해두는 것도 그쪽이 내 코드를 찾아 부를 수 있어야 하기 때문이다.

그래서 규칙을 어기면 오류 메시지가 아니라 그냥 안 불리는 결과가 나온다.

## 📊 비교

| | Library | Framework |
|---|---|---|
| 부르는 쪽 | 내 코드 | 프레임워크 |
| 구조 | 내가 정한다 | 이미 정해져 있다 |
| 바꾸기 | 다른 것으로 갈아끼우기 쉽다 | 옮기려면 대부분 다시 짠다 |
| 예 | requests, lodash, pandas | Django, Spring, Angular |

## 💡 실제 사례

- **함께 쓰기** — 프레임워크로 구조를 잡고 그 안에서 HTTP 나 날짜 처리 라이브러리를 불러 쓴다.
- **작은 스크립트** — 데이터를 한 번 받아 가공만 하면 되는 코드에는 라이브러리만 쓴다.
- **여럿이 만드는 앱** — 구조가 정해져 있으면 사람마다 다른 방식으로 짜는 일이 줄어든다.

## 🚫 흔한 오해

- **프레임워크가 라이브러리보다 좋은 것이다** — 등급이 아니라 방향의 차이다. 기능 하나만 필요한 자리에 프레임워크를 깔면 안 쓸 규칙까지 전부 따라온다.
- **불러다 쓰면 전부 라이브러리다** — 내가 부르는 코드가 있다고 라이브러리가 되지는 않는다. 정해진 시점에 내 함수를 대신 불러주는 쪽이 있으면 그건 프레임워크다.
- **프레임워크를 써도 내 방식대로 짜면 된다** — 규칙을 벗어난 코드는 프레임워크가 부를 시점을 못 잡는다. 자유도를 내주고 구조를 받는 거래다.

## 📝 정리

Framework 와 Library 는 부르는 방향으로 갈린다. 라이브러리는 내가 부르고 프레임워크는 나를 부르며, 이 방향이 곧 어디까지가 내가 정할 몫인지를 정한다.

## ❓ 이해했는지

- 프레임워크의 규칙을 어기면 대개 오류 대신 어떤 일이 일어나나 → 작동 원리
- 차트 기능 하나만 붙이려는데 프레임워크를 깔면 무엇이 문제인가 → 해결하는 문제
- 프레임워크를 쓰기로 했으면 라이브러리는 안 쓰는 것인가 → 실제 사례
