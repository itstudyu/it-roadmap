# LLM (Large Language Model)

## 📝 정의

LLM은 **다음에 올 단어를 확률로 고르는 모델**이다.

엄청난 양의 글로 학습해서, 주어진 문장 뒤에 무엇이 올 법한지를 안다. 그 예측을 한 단어씩 이어 붙인 것이 우리가 보는 답변이다.

### 비유
문장 완성 게임을 수천만 번 해본 사람. 사실을 외운 게 아니라 "이런 말 뒤에는 보통 이런 말이 온다"를 몸으로 익힌 상태다. 그래서 그럴듯한 말은 아는 것과 상관없이 잘 만든다.

## 🖼️ 그림으로 보기

```도해
흐름: 질문을 넣으면 답이 어떻게 만들어지나
사용자 :: "한국의 수도는" 이라고 입력한다
토크나이저 :: 글자를 토큰이라는 조각으로 쪼갠다
모델 :: 다음 토큰 후보마다 확률을 매긴다
모델 :: "서울" 이 가장 높다. 하나 고른다
모델 :: 고른 것을 뒤에 붙이고 다시 처음부터 예측
< 사용자 :: 끝 신호가 나올 때까지 반복한 결과를 본다
= 문장 전체를 한 번에 만드는 게 아니라 한 조각씩 이어 붙인다
```

## ⚠️ 해결하는 문제

```도해
대조: 규칙을 사람이 짜던 방식과 무엇이 다른가
규칙 기반 || LLM
새 표현 :: 규칙을 추가해야 || 대체로 처리된다
분야 확장 :: 처음부터 다시 || 같은 모델로
답의 근거 :: 규칙을 짚을 수 있다 || 짚기 어렵다
= 사람이 규칙을 다 못 적는 문제를 풀었고, 대신 왜 그렇게 답했는지를 잃었다
```

말은 규칙으로 다 적을 수 없다. 예외가 너무 많고, 새 표현이 계속 생기고, 문맥에 따라 뜻이 달라진다. 규칙을 짜서 자연어를 다루려던 시도가 오래 막혀 있던 이유다.

LLM은 규칙을 사람이 적는 대신 데이터에서 통계를 뽑는 방식으로 이 문제를 우회했다. 대신 답의 근거를 짚을 수 없게 됐고, 그래서 [[Hallucination]] 같은 문제가 따라온다.

## ⚙️ 작동 원리

핵심은 **문맥 창**이다. 모델이 한 번에 볼 수 있는 토큰 수가 정해져 있고, 그 밖의 내용은 존재하지 않는 것과 같다.

```도해
층: 답변 하나가 어떤 재료로 만들어지나
시스템 지시 :: 어떤 역할로 답하라는 사전 지시
대화 기록 :: 이번 대화에서 오간 말
이번 질문 :: 방금 넣은 내용
문맥 창 밖 :: 여기 있던 것은 모델에게 없는 것과 같다
= 대화가 길어지면 앞부분이 창 밖으로 밀려나면서 "기억"이 사라진다
```

같은 질문에 매번 다른 답이 나오는 것도 이 구조 때문이다. 가장 확률 높은 토큰만 고르면 답이 딱딱해져서, 보통은 상위 후보 중에서 무작위로 하나를 고른다.

## 💡 실제 사례

- **문서 요약** 긴 글을 넣고 짧게 다시 쓰게 한다. 원문이 문맥 창에 들어가야 한다.
- **분류** 문의 내용을 보고 어느 부서로 보낼지 정한다. 규칙으로 짜기 어려운 일이 잘 맞는다.
- **코드 작성** 자연어 설명을 코드로 옮긴다. 코드도 결국 토큰의 나열이라 같은 방식으로 예측된다.

## 🚫 흔한 오해

- **LLM이 답을 검색해서 가져온다** — 검색하지 않는다. 학습한 통계로 그럴듯한 말을 만들어낼 뿐이라, 없는 논문 제목도 자신 있게 만들어낸다.
- **모델이 대화를 기억한다** — 기억하지 않는다. 매번 대화 기록 전체를 다시 넣어주기 때문에 기억하는 것처럼 보인다. 창을 넘으면 앞이 사라진다.
- **모델이 계산을 한다** — 계산하지 않고 계산 결과처럼 보이는 토큰을 예측한다. 자릿수가 큰 곱셈에서 틀리는 이유다.

## 🚨 주의사항

- **틀린 답을 자신 있게 말한다.** 확률이 높은 문장은 맞는 문장과 다르다. 사실 확인이 필요한 곳에는 [[RAG]] 같은 근거 제공 장치를 붙인다.
- **문맥 창은 비용이다.** 넣는 토큰만큼 돈과 시간이 든다. 대화 기록을 통째로 넣는 습관은 비싸진다.

## 📝 정리

LLM은 다음 토큰을 확률로 예측하는 모델이다. 규칙을 사람이 적지 않아도 되는 대신 근거를 짚을 수 없고, 그래서 확신에 찬 오답이 나온다.
