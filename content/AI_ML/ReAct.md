# ReAct (Reasoning + Acting)

## 📝 정의

ReAct는 **생각과 행동을 번갈아 하는 AI 에이전트 방식**이다.

한 번에 답을 내놓는 대신, 무엇이 필요한지 생각하고, 도구를 하나 쓰고, 그 결과를 보고 다시 생각한다. 이름은 Reasoning과 Acting을 붙인 것이다.

### 비유
요리하면서 냉장고를 열어보는 것. 재료를 다 외운 채로 순서를 짜지 않고, 한 번 열어보고 있는 것에 맞춰 다음 손을 정한다.

## 🖼️ 그림으로 보기

```도해
흐름: "내일 서울 날씨 어때?" 를 받으면 어떻게 답하나
생각 :: 실시간 정보가 필요하다고 판단한다
행동 :: 날씨 API 를 부른다
관찰 :: "맑음, 15도" 라는 결과를 받는다
생각 :: 필요한 게 다 모였다고 판단한다
행동 :: 도구 대신 답을 내놓기로 정한다
< 답변 :: "내일 서울은 맑고 15도입니다"
= 생각과 행동과 관찰이 한 바퀴고, 필요한 만큼 돈다
```

## ⚠️ 해결하는 문제

```도해
대조: 실시간 정보를 물으면 무엇이 달라지나
그냥 LLM || ReAct 로
모르는 값 :: 못 한다고 답 || 도구로 찾는다
여러 단계 :: 한 번에 추측 || 나눠서 진행
중간 오류 :: 그대로 나감 || 보고 고친다
= 모르는 것을 지어내는 대신 알아보러 가게 만드는 구조다
```

학습해둔 것만으로 답하는 모델은 지금 이 순간의 값을 모른다. 내일 날씨나 방금 바뀐 재고 수량을 물으면 확인할 수 없다고 답하거나, 더 나쁘면 그럴듯한 숫자를 지어낸다.

ReAct는 답하기 전에 한 단계를 끼워 넣는다. 무엇이 필요한지 먼저 말로 적게 하고, 그다음에 도구를 부르게 한다. 도구가 돌려준 값을 보고 다시 판단하므로 한 번에 맞힐 필요가 없고, 중간에 어긋난 것을 알아채면 방향을 바꿀 수 있다.

## ⚙️ 작동 원리

한 바퀴는 세 마디로 되어 있다.

```도해
층: 한 바퀴는 무엇으로 이루어져 있나
Thought :: 지금 무엇이 필요한지 말로 적는다
Action :: 도구 하나를 고르고 부른다
Observation :: 도구가 돌려준 결과를 읽는다
= 판단을 글로 남기므로 어디서 어긋났는지 되짚을 수 있다
```

이 세 마디가 목표에 닿을 때까지 반복된다. 필요한 게 다 모였다고 판단하면 도구를 부르는 대신 답을 내놓고 끝낸다.

생각을 겉으로 적게 한다는 점이 이 방식의 특징이다. 나중에 기록을 열어보면 어느 판단에서 틀어졌는지 보이고, 도구를 잘못 고른 것인지 결과를 잘못 읽은 것인지도 구분할 수 있다.

## 💡 실제 사례

- **사내 챗봇** 남은 휴가 일수를 물으면 인사 시스템을 조회하고 그 값으로 답한다. 모델이 기억하던 값을 쓰지 않는다.
- **자료 검색** 한 번 검색해서 부족하면 검색어를 바꿔 다시 찾는다. 관찰한 결과가 다음 검색어를 정한다.
- **여러 단계 계산** 환율을 받아온 다음 그 값으로 금액을 계산한다. 앞 단계 결과가 없으면 뒤 단계를 시작하지 않는다.

## 🚫 흔한 오해

- **ReAct는 모델 이름이다** — 모델이 아니라 모델을 부리는 방식이다. 같은 모델을 한 번에 답하게 할 수도 있고 ReAct로 돌게 할 수도 있다.
- **ReAct를 쓰면 지어내기가 없어진다** — 줄어들 뿐이다. 도구를 안 부르고 넘어가거나 결과를 잘못 읽으면 틀린 답이 그대로 나간다.
- **바퀴를 많이 돌수록 답이 좋아진다** — 한 바퀴마다 모델 호출 비용이 붙고, 방향을 잘못 잡으면 잘못된 채로 계속 돈다. 몇 바퀴까지 돌지 정해두는 편이 낫다.

## 📝 정리

ReAct는 생각, 행동, 관찰을 한 바퀴로 삼아 반복하는 에이전트 방식이다. 모르는 값을 지어내는 대신 도구로 알아보게 만들고, 판단을 글로 남기게 해서 어디서 어긋났는지 되짚을 수 있게 한다.
