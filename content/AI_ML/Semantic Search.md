# Semantic Search (의미 검색)

## 📝 정의

Semantic Search는 **낱말이 달라도 뜻이 비슷하면 찾아주는 검색**이다.

"급여일"로 물어도 "임금 지급일"이라고 적힌 문서가 걸린다. 글자를 맞춰보는 게 아니라 뜻을 숫자로 바꿔 거리를 재기 때문이다.

### 이름
Semantic :: 뜻에 관한
Search :: 찾기
= 붙여 읽으면 "뜻으로 찾기". 맞춰 보는 대상이 글자에서 뜻으로 옮겨 갔다는 말이다

### 비유
사서에게 묻는 것. "아이 키우는 데 필요한 책"이라고만 해도 제목에 그 말이 없는 책을 꺼내 온다.

### 예
아기 태우는 자전거 의자라고 쳤는데 유아 안장이라고만 적힌 글이 걸려 나오는 그 일이다.

### 직접
검색창에 "아이 키우려고 쉬는 제도" 라고 풀어서 쳐 보라. 치지도 않은 "육아휴직" 이 결과 맨 위에 뜬다.

## 🖼️ 그림으로 보기

```도해
흐름: 급여일을 물으면 무슨 계산으로 문서를 고르나
질문 :: 급여일이 언제냐는 문장이 들어온다
임베딩 :: 그 문장을 숫자 배열로 바꾼다
문서 벡터 :: 문서들도 미리 같은 방식으로 바꿔 두었다
거리 재기 :: 질문과 각 문서 사이의 거리를 잰다
< 결과 :: 가까운 순으로 위에서 몇 개만 돌려준다
= 글자를 맞춰본 적이 없다. 거리만 쟀다
```

## ⚠️ 해결하는 문제

```도해
대조: 질문에 없는 낱말로 적힌 문서는 어떻게 되나
낱말 검색 || 의미 검색
동의어 :: 임금은 못 찾음 || 같이 걸린다
말 바꿔 묻기 :: 0건 || 뜻으로 찾는다
오타 :: 0건 || 어느 정도 견딘다
= 찾는 기준을 글자에서 뜻으로 옮긴 것이다
```

"급여일이 언제죠?"라고 물었는데 문서에는 "임금 지급일은 25일입니다"라고 적혀 있으면, 글자를 맞춰보는 검색은 이 문서를 놓친다. "아이 키우려고 쉬고 싶은데요"라고 물으면 "육아휴직"이라는 낱말이 질문에 없어서 역시 못 찾는다. "육아휴지"처럼 한 글자만 틀려도 결과가 0건이 된다.

의미 검색은 글자 대신 뜻을 비교한다. 질문과 문서를 같은 방식으로 숫자 배열로 바꾸면 뜻이 가까운 것끼리 배열도 가까워진다. 그래서 "급여"와 "임금"과 "월급"이 한자리에 모인다.

## ⚙️ 작동 원리

```도해
층: 유사도 점수는 어디에서 갈리나
0.7 위 :: 관련 있다고 보고 그대로 쓴다
0.5 에서 0.7 :: 애매하다. 참고로만 두거나 버린다
0.5 아래 :: 관련 없다고 보고 버린다
= 문턱을 낮추면 엉뚱한 문서가 답의 근거로 섞여 들어온다
```

거리가 가까운 순서는 언제나 매겨진다. 전혀 관련 없는 문서라도 1등은 나온다는 뜻이다. 그래서 점수 문턱을 정해두고 그 아래는 아예 버린다.

의미 검색만으로 안 되는 자리도 있다. "제32조"처럼 그 글자가 정확히 필요한 질문은 낱말 검색이 낫다. 그래서 의미 검색을 주로 두고 낱말이 정확히 들어맞은 문서에 점수를 얹는 방식을 함께 쓴다.

## 📊 비교: 낱말 검색 vs 의미 검색

| | 낱말 검색 | 의미 검색 |
|---|---|---|
| 맞춰보는 것 | 글자 | 뜻 |
| 동의어 | 못 찾는다 | 찾는다 |
| 오타 | 못 찾는다 | 어느 정도 견딘다 |
| 속도 | 매우 빠르다 | 빠르다 |
| 드는 것 | 거의 없다 | 벡터 DB 가 필요하다 |

## 💡 실제 사례

- **사내 규정 검색** — "아이 키우기 위한 휴가"라고 물어도 육아휴직 조항이 걸린다.
- **말 바꿔 묻기** — "돈 받는 날은?"이라고 물어도 급여일 조항으로 이어진다.
- **오타 섞인 질문** — "육아휴지"라고 쳐도 육아휴직 문서가 위에 올라온다.

## 🚫 흔한 오해

- **의미 검색은 AI 가 질문을 이해하는 것이다** — 이해가 아니라 거리 계산이다. 질문과 문서를 숫자 배열로 바꿔 가까운 것을 고를 뿐이다.
- **의미 검색이 낱말 검색보다 항상 낫다** — "제32조"처럼 그 글자가 정확히 필요한 질문에는 낱말 검색이 낫다. 그래서 둘을 같이 쓴다.
- **유사도 1등이면 답이 거기 있다** — 가장 가까운 문서를 골랐다는 뜻일 뿐이다. 문턱을 두지 않으면 0.3짜리 문서도 1등이 된다.

## 🚨 주의사항

- **문턱값을 정해두지 않으면 항상 무언가가 걸린다.** 순위는 언제나 매겨지므로 몇 점 아래는 버린다고 정해야 한다.
- **아주 짧은 말은 잘 안 잡힌다.** 조사나 한 글자짜리 낱말에는 담긴 뜻이 적어서 거리 계산이 흔들린다.

## 📝 정리

**"글자 말고 뜻을 맞춰 보는 그 찾기"** 라고 읽으면 된다. 그래서 낱말이 다르거나 오타가 섞여도 찾아낸다. 다만 가까운 것을 고를 뿐이라 문턱을 두지 않으면 관련 없는 문서도 1등이 된다.

## 🧒 열 살에게

도서관에서 "아이 키울 때 보는 책 있어요?" 하고 물으면 제목에 그 말이 하나도 없는 책을 꺼내다 주지? 네가 쓴 낱말이 아니라 무슨 얘기를 찾는지를 보고 골라 주니까 그래. 그래서 글자를 좀 틀리게 써도 대충 알아듣고 꺼내 줘.

## ❓ 이해했는지

- "임금 지급일"이라고만 적힌 문서를 "급여일"로 검색해 찾을 수 있는 이유는 → 해결하는 문제
- "제32조"를 찾을 때 낱말 검색을 같이 돌리는 이유는 → 작동 원리
- 유사도 0.3짜리 문서가 결과 1등으로 올라오는 일이 왜 생기나 → 흔한 오해
