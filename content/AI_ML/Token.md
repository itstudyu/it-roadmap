# Token (토큰)

## 📝 정의

Token은 **모델이 글을 다루는 최소 조각**이다.

글자 단위도 아니고 단어 단위도 아니다. 자주 쓰이는 덩어리를 하나로 묶은 중간 크기라서, 영어는 대략 단어 하나가 토큰 하나에 가깝고 한글은 글자 하나가 여러 토큰이 되기도 한다.

### 비유
택배 요금의 부피 단위. 물건 개수도 무게도 아닌 별도 기준으로 값이 매겨진다. 같은 물건이라도 어떻게 포장했느냐에 따라 단위 수가 달라진다.

## 🖼️ 그림으로 보기

```도해
흐름: 입력한 글이 어떻게 요금이 되나
사용자 :: "안녕하세요" 를 입력한다
토크나이저 :: 자주 쓰이는 덩어리로 쪼갠다
토크나이저 :: 조각마다 번호를 붙인다
모델 :: 번호 목록을 받아 다음 번호를 예측한다
< 요금 :: 넣은 토큰 수 + 나온 토큰 수로 계산된다
= 글자 수가 아니라 토큰 수가 비용이자 한계다
```

## ⚠️ 해결하는 문제

```도해
대조: 쪼개는 단위를 무엇으로 하나
글자 단위 || 토큰 단위
목록 크기 :: 작다 || 적당하다
문맥 길이 :: 금방 찬다 || 여유가 있다
처음 보는 말 :: 처리된다 || 조각으로 처리된다
= 글자는 너무 잘고 단어는 너무 많아서 그 사이를 고른 것이다
```

단어 단위로 쪼개면 사전에 없는 말을 만났을 때 처리할 수 없다. 신조어, 오타, 고유명사가 전부 미지의 단어가 된다.

글자 단위로 쪼개면 그 문제는 없지만 목록이 너무 길어진다. 문장 하나가 수십 조각이 되어 문맥 창을 금방 채운다.

토큰은 그 사이다. 자주 나오는 덩어리는 하나로 묶고, 드문 말은 조각으로 나눠서 둘 다 처리한다.

## ⚙️ 작동 원리

한국어는 영어보다 토큰을 훨씬 많이 쓴다. 학습 데이터에 영어가 압도적으로 많아서 영어 덩어리가 더 잘 묶여 있기 때문이다.

```도해
층: 같은 뜻을 쓰는 데 토큰이 얼마나 드나
영어 문장 :: 단어 하나가 대체로 토큰 하나
한글 문장 :: 글자 하나가 토큰 하나에서 셋
코드 :: 들여쓰기와 기호가 각각 토큰
= 같은 내용도 한국어로 쓰면 비용이 몇 배가 된다
```

문맥 창도 토큰으로 센다. 창이 8,000토큰이면 대화 기록과 질문과 답을 다 합쳐 8,000을 넘을 수 없다.

## 💡 실제 사례

- **요금 계산** API 값은 입력 토큰과 출력 토큰을 따로 센다. 출력이 대체로 더 비싸다.
- **문맥 창 관리** 대화가 길어지면 앞부분을 요약해 넣어 토큰을 줄인다.
- **프롬프트 다듬기** 같은 지시를 짧게 쓰면 매 요청마다 그만큼 아낀다.

## 🚫 흔한 오해

- **토큰이 단어와 같다** — 다르다. `unbelievable`은 세 토큰으로 쪼개지고, 한글 `안녕하세요`도 여러 토큰이다.
- **글자 수로 비용을 계산할 수 있다** — 언어마다 비율이 달라서 한국어를 영어 기준으로 계산하면 크게 어긋난다.
- **입력만 돈이 든다** — 모델이 만들어낸 출력도 토큰으로 센다. 긴 답변을 요구하면 그만큼 비싸진다.

## 🚨 주의사항

- **긴 대화 기록을 통째로 넣지 않는다.** 매 요청마다 전체가 다시 계산되어 비용이 대화 길이의 제곱처럼 늘어난다.
- **한국어 비용을 따로 잰다.** 영어 기준 견적으로 계획하면 실제 청구가 몇 배로 나온다.

## 📝 정리

Token은 모델이 글을 다루는 최소 조각이자 비용과 한계의 단위다. 글자도 단어도 아닌 중간 크기이고, 한국어는 같은 내용에 영어보다 훨씬 많은 토큰을 쓴다.
