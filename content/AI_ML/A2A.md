# A2A (Agent2Agent Protocol)

## 📝 정의

A2A는 **에이전트가 다른 에이전트에게 일을 맡기는 규약**이다.

맡기려면 상대가 무엇을 할 수 있는지부터 알아야 한다. 그래서 A2A 는 에이전트마다 명함 한 장(Agent Card)을 내걸게 하고, 부르는 쪽이 그 명함을 읽어 통하는 방식 하나를 골라 말을 건다. 규격 1.0 이 나와 있고 파이썬과 자바스크립트 공식 SDK 가 그것을 구현한다.

### 이름
Agent :: 스스로 일하는 쪽
2 :: to 를 숫자로 쓴 것
Agent :: 일을 맡길 상대
Protocol :: 약속
= 붙여 읽으면 "에이전트가 에이전트에게 거는 약속". 사람이 가운데 끼지 않는 자리다

### 비유
옷을 맡기면 번호표를 주고, 그 번호로 다 됐는지 물어보고 찾아가는 세탁소 접수증.

### 예
일정을 잡아 주는 비서에게 부탁했더니 그쪽이 항공권 찾는 다른 비서에게 다시 물어보고 답을 가져오는 장면이다.

## 🖼️ 그림으로 보기

```도해
흐름: 에이전트가 다른 에이전트에게 일을 맡기면 어떻게 되나
부르는 쪽 :: 상대의 명함(Agent Card)을 먼저 받아 온다
전송 고르기 :: 명함에 적힌 방식 중 통하는 것 하나를 고른다
맡기기 :: 할 일을 메시지로 적어 보낸다
받는 쪽 :: 작업(Task)을 열고 진행 상태를 흘려보낸다
< 부르는 쪽 :: 다 되면 결과물(Artifact)을 받는다
= 사람이 화면을 거치지 않고 에이전트끼리 일을 주고받는다
```

## ⚠️ 해결하는 문제

```도해
대조: 에이전트마다 부르는 법이 다르면 무엇이 힘든가
공용 규약 없이 || A2A 로
붙이는 비용 :: 상대마다 새로 짠다 || 명함 한 장이면 된다
긴 작업 :: 끝났는지 계속 묻는다 || 진행 상태가 흘러온다
상대 교체 :: 코드를 다시 짠다 || 명함만 바꿔 끼운다
= 붙이는 법이 하나면, 에이전트를 늘려도 붙이는 일은 안 늘어난다
```

에이전트가 하나뿐이면 규약이 필요 없다. 문제는 여럿을 잇기 시작할 때 생긴다. 상대마다 부르는 법이 다르면 잇는 곳이 늘어날 때마다 새로 짜야 하고, 상대를 바꾸면 그 코드를 또 버려야 한다.

A2A 는 **부르는 법을 상대에게서 읽어 오게** 해서 이 자리를 없앤다. 상대가 무엇을 할 수 있고 어떤 방식으로 받는지가 명함에 적혀 있으므로, 부르는 쪽은 명함을 읽는 법 하나만 알면 된다.

## ⚙️ 작동 원리

규격 1.0 은 오가는 방식을 셋 정해 뒀다 — JSON-RPC, HTTP+JSON/REST, 그리고 [[gRPC]]. 셋 다 같은 처리기에 물릴 수 있어서 에이전트 하나를 세 방식으로 동시에 열어 둘 수도 있고, 부르는 쪽은 명함에 적힌 목록과 자기가 선호하는 순서를 맞춰 하나를 고른다.

오래 걸리는 일은 한 번에 답이 오지 않는다. 작업이 열렸다는 소식, 상태가 바뀌었다는 소식, 결과물이 나왔다는 소식이 스트림으로 차례차례 흘러온다. 스트림을 계속 열어 둘 수 없는 쪽을 위해 [[Webhook]] 방식도 있다 — 명함에 푸시 알림을 켜 두고 받을 주소를 넘기면 그 주소로 같은 소식들이 날아온다.

## 💡 실제 사례

- **몇 시간 걸리는 일** — 연결을 계속 붙들고 있을 수 없으면 받을 주소를 넘겨 두고 끊는다. 진행과 결과가 그 주소로 날아온다.
- **여러 방식 동시 공개** — 같은 에이전트 하나를 JSON-RPC · REST · gRPC 로 한꺼번에 열어 두고, 부르는 쪽이 되는 것을 고르게 한다.
- **가짜 명함 막기** — 명함에 서명을 붙여 두면 부르는 쪽이 공개된 열쇠로 그 명함이 진짜인지 확인하고 나서 말을 건다.

## 🚫 흔한 오해

- **에이전트를 붙일 일이면 무엇이든 A2A 다** — 한 프로그램 안에서 함수로 부르면 될 일까지 규약에 태우면 느려지기만 한다. 서로 다른 곳에서 따로 도는 에이전트끼리 쓰라고 있는 것이다.
- **명함만 받아 오면 바로 부를 수 있다** — 명함은 무엇을 할 수 있는지를 적어둔 것이지 들어가도 좋다는 허락이 아니다. 인증은 따로 붙여 보내야 하고, 안 붙으면 거절이 돌아온다.
- **일을 맡기면 답이 곧바로 온다** — 오래 걸리는 일은 작업 하나가 열리고 상태가 여러 번 바뀐 뒤에야 결과물이 나온다.

## 📝 정리

**"에이전트끼리 일을 맡기는 그 공용 접수증"** 이라고 읽으면 된다. 상대의 명함을 먼저 읽고 통하는 방식 하나를 골라 넘기기 때문에, 상대를 갈아 끼워도 부르는 쪽은 읽는 법을 그대로 쓴다. 오래 걸리는 일은 작업이 하나 열려 상태가 흘러오고, 다 되면 결과물이 돌아온다.

## 🧒 열 살에게

세탁소에 옷을 맡기면 번호표를 주지? 어느 가게든 번호표 모양이 똑같으면 아무 가게에나 맡기고 아무 가게에서나 찾아올 수 있어. 그러면 가게끼리도 서로 일을 넘기기가 쉬워져.

## ❓ 이해했는지

- 상대 에이전트를 부르기 전에 무엇을 먼저 받아 오나 → 그림
- 몇 시간 걸리는 일을 맡겼는데 연결을 계속 열어 둘 수 없다면 → 작동 원리
- 명함을 제대로 받아 왔는데도 거절당하는 이유는 무엇인가 → 흔한 오해
