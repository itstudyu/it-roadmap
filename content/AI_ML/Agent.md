# Agent (AI 에이전트)

## 📝 정의

Agent는 **목표를 받아 스스로 도구를 쓰며 일을 끝내는 AI**다.

LLM은 물으면 답만 한다. 여기에 검색이나 실행 같은 도구를 쥐여주고, 한 번에 끝내지 않고 결과를 보며 다음 행동을 다시 정하게 만든 것이 Agent다.

### 비유
심부름. 재료를 사 오라고만 말하면 알아서 가게를 고르고, 물건이 없으면 다른 가게로 간다. 한 걸음마다 지시하는 것과 다르다.

## 🖼️ 그림으로 보기

```도해
흐름: 목표 한 줄을 주면 Agent 는 무엇을 하나
사용자 :: "경쟁사 분석 보고서 써줘" 한 줄만 준다
Agent :: 무엇부터 할지 정한다. 검색이 먼저다
도구 :: 검색을 실행하고 결과를 돌려준다
Agent :: 결과를 보고 다음 할 일을 다시 정한다
Agent :: 충분하다고 판단하면 멈춘다
< 사용자 :: 완성된 보고서를 받는다
= 지시가 아니라 목표를 주고, 중간 판단을 넘기는 것이 차이다
```

## ⚠️ 해결하는 문제

```도해
대조: LLM 에게만 물으면 어디서 막히나
Agent 없이 || Agent 로
바깥 정보 :: 모른다고 답함 || 검색해서 가져옴
여러 단계 :: 사람이 이어붙임 || 스스로 이어감
중간 실패 :: 거기서 멈춤 || 다른 길을 시도
= 답을 만드는 것과 일을 끝내는 것은 다르다
```

"이메일 확인하고 중요한 것만 요약해줘"라고 하면 LLM은 이메일에 닿을 수가 없어서 못 한다고 답한다. 자료를 모으고 정리하고 문서로 쓰는 일도 마찬가지다. 각 단계는 할 수 있지만 그걸 이어붙이는 건 사람 몫으로 남는다.

Agent는 그 이어붙이는 자리를 가져간다. 도구를 호출해 결과를 받고, 그 결과를 보고 다음에 무엇을 할지 다시 정한다. 도중에 오류가 나도 사람을 부르지 않고 다른 방법을 먼저 시도한다.

## ⚙️ 작동 원리

Agent 를 이루는 것은 넷이다.

- **LLM** — 다음에 무엇을 할지 정하는 자리
- **도구** — 검색, 계산, 파일 읽기. 밖에 닿는 손
- **기억** — 지금까지 무엇을 했는지 들고 있다
- **멈춤 조건** — 횟수나 비용의 한도. 없으면 안 끝난다

도구가 없으면 말만 하고, 기억이 없으면 같은 일을 반복한다.

행동을 정하는 방식에는 몇 가지 틀이 있다. 생각하고 도구를 쓰고 결과를 본 뒤 다시 생각하는 것을 반복하는 ReAct, 전체 계획을 먼저 세워두고 단계별로 실행하는 Plan-and-Execute가 대표적이다.

멈춤 조건은 설계에 포함해야 한다. 최대 반복 횟수를 정해두지 않으면 답을 못 찾는 상황에서 같은 자리를 맴돈다.

## 💡 실제 사례

- **메일 정리** — 메일을 읽어오는 도구를 붙여주면 목록을 훑고 중요한 것만 골라 요약해 돌려준다.
- **자료 조사** — 검색, 정리, 문서 작성을 지시 한 번으로 이어서 한다.
- **코드 수정** — 코드를 쓰고 실행해본 뒤 오류가 나면 고쳐서 다시 실행하는 것을 반복한다.

## 🚫 흔한 오해

- **Agent는 LLM보다 똑똑한 모델이다** — 모델은 같은 것을 쓴다. 도구를 쥐여주고 여러 번 돌리는 껍데기가 붙었을 뿐이다.
- **한 번 시키면 알아서 끝까지 간다** — 멈출 조건을 정해두지 않으면 끝을 못 찾고 횟수만 채운 뒤 중간 상태로 돌아온다.
- **Agent를 쓰면 답이 더 정확해진다** — 틀리게 답하던 모델은 여전히 틀린다. 달라지는 건 정확도가 아니라 할 수 있는 일의 범위다.

## 🚨 주의사항

- **호출 횟수가 곧 비용이다.** 한 번의 대화가 열 번 넘는 모델 호출로 늘어난다. 반복 한도를 정해두지 않으면 비용이 예측되지 않는다.
- **위험한 도구는 처음부터 빼둔다.** 삭제나 결제처럼 되돌릴 수 없는 도구는 목록에서 제외하거나 사람 확인을 거치게 한다.

## 📝 정리

Agent는 LLM에 도구와 반복 판단을 붙여 목표를 끝까지 밀고 가게 만든 구조다. 모델이 똑똑해진 것이 아니라 손발이 생긴 것이고, 그만큼 반복 한도와 권한을 정해두는 일이 따라온다.

## ❓ 이해했는지

- 같은 모델을 쓰는데 Agent로 감쌌을 때만 할 수 있게 되는 일은 어떤 것인가 → 실제 사례
- 반복 한도를 정해두지 않으면 무슨 일이 벌어지나 → 주의사항
- 메일을 요약해달라는 요청에서 LLM 혼자로는 어디서 막히나 → 해결하는 문제
