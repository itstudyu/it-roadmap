# Intent 분류 (Intent Classification)

## 📝 정의

Intent 분류는 **사용자 말에서 무엇을 원하는지 골라내는 일**이다.

같은 요청도 사람마다 다르게 말한다. 그 표현들을 미리 정해둔 몇 개의 갈래로 묶어서 어디로 보낼지 정한다.

### 비유
전화 자동 안내. 무슨 말을 하든 결국 인사팀과 재무팀 중 한 곳으로 연결된다.

## 🖼️ 그림으로 보기

```도해
흐름: "주소 변경하고 싶어" 는 어디로 가나
사용자 :: 자기 말로 요청을 적는다
분류기 :: 미리 정해둔 갈래에 대응시킨다
분류기 :: 갈래마다 얼마나 확실한지 점수를 낸다
판단 :: 점수가 기준을 넘으면 그 갈래로 정한다
< 담당 :: 정해진 쪽이 실제 답을 만든다
= 무엇을 원하는지 먼저 정해야 어디로 보낼지가 나온다
```

## ⚠️ 해결하는 문제

```도해
대조: 들어온 말을 갈래로 나누지 않으면 어떻게 되나
분류 없이 || Intent 분류로
처리 방식 :: 사람이 나눈다 || 즉시 나뉜다
잘못 보냄 :: 전부 헛돈다 || 한 곳만 실행
같은 뜻 다른 말 :: 따로 처리 || 한 갈래로
= 무엇을 원하는지 정하는 자리가 있어야 뒤가 단순해진다
```

문의가 하루에 수백 건 들어오면 사람이 하나씩 읽어 어느 쪽으로 보낼지 정하는 방식은 느리고 자주 틀린다. 자동으로 넘긴다 해도 갈래를 안 정하면 담당을 전부 돌려보고 그중 맞는 답을 고르게 되어, 시간과 비용이 갈래 수만큼 늘어난다.

Intent 분류는 맨 앞에서 한 번만 판단한다. "주소 변경하고 싶어"와 "주소 어디서 바꿔요"를 같은 갈래로 묶어 한 곳으로 보내면, 뒤에 있는 담당은 자기 일만 하면 된다.

## ⚙️ 작동 원리

분류기는 갈래를 고르면서 얼마나 확실한지도 함께 내놓는다. 이 점수에 기준선을 두고 넘으면 바로 보내고, 못 넘으면 사용자에게 되묻는다. 애매한 것을 억지로 밀어 넣는 것보다 한 번 확인하는 편이 낫기 때문이다.

앞선 대화도 함께 본다. "얼마나 남았어?"만 보면 연차인지 급여일인지 계약 기간인지 알 수 없지만, 바로 앞에서 연차 이야기가 오갔다면 정해진다.

## 💡 실제 사례

- **고객 문의 분류** — 들어온 문의를 갈래로 나눠 담당 창구로 바로 보낸다.
- **사내 챗봇** — 신청 방법, 규정 확인, 급여 같은 갈래로 나눠 각각 다른 자료를 찾게 한다.
- **애매한 질문 되묻기** — 점수가 기준에 못 미치면 답을 지어내지 않고 선택지를 보여준다.

## 📊 비교

| 방법 | 잘하는 것 | 못하는 것 |
|---|---|---|
| 규칙 기반 | 즉시 답하고 결과가 뻔하다 | 표현이 조금만 달라도 못 잡는다 |
| 학습 모델 기반 | 빠르고 대량 처리에 싸다 | 학습 데이터를 모아야 한다 |
| LLM 기반 | 맥락과 뉘앙스를 읽는다 | 호출 비용과 지연이 붙는다 |

## 🚫 흔한 오해

- **의도를 알아냈으면 답도 나온 것이다** — 어디로 보낼지가 정해졌을 뿐이다. 실제 답은 그 갈래를 맡은 쪽이 따로 만든다.
- **갈래를 많이 만들수록 정확해진다** — 갈래끼리 겹치기 시작하면 분류기가 헷갈린다. 서로 안 겹치게 적게 두는 편이 정확도가 높다.
- **한 문장만 보면 된다** — 앞선 대화를 안 보면 "얼마나 남았어?" 같은 말은 무엇을 묻는지 정할 수 없다.

## 🚨 주의사항

- **기준선을 정해둔다.** 점수가 낮은데도 억지로 보내면 엉뚱한 담당이 자신 있게 틀린 답을 낸다.
- **어디에도 안 맞는 갈래를 하나 둔다.** 모든 말을 정해진 갈래에 밀어 넣으면 처리할 수 없는 요청이 조용히 잘못 처리된다.

## 📝 정리

Intent 분류는 사용자 말을 미리 정해둔 갈래 중 하나로 대응시켜 어디로 보낼지 정하는 일이다. 확실한 정도를 함께 내놓기 때문에, 애매하면 되묻고 확실하면 바로 넘길 수 있다.

## ❓ 이해했는지

- "얼마나 남았어?" 한 문장만으로 갈래를 정할 수 없는 이유는?
- 분류 점수가 기준에 못 미치는데 그대로 보내면 무슨 일이 생기나?
- 갈래를 늘렸는데 오히려 분류가 부정확해졌다면 무엇을 의심해야 하나?
