# Multimodal (멀티모달)

## 📝 정의

Multimodal은 **글과 함께 그림 같은 다른 입력도 받는 것**이다.

Hugging Face 용어집은 이 말을 "글에 다른 종류의 입력(예: 이미지)을 합친 일" 로 적는다. 받는 갈래가 늘었다는 뜻이지 모델이 둘로 나뉜다는 뜻이 아니다 — 그림도 조각으로 잘려 글 조각과 같은 줄에 이어 붙는다.

### 이름
Multi :: 여럿
Modal :: 들어오는 갈래
= 붙여 읽으면 "여러 갈래". 글만 받던 입구에 갈래가 더 붙은 것이다

### 비유
숙제 제출함. 글로 쓴 것만 받던 자리에 사진과 녹음도 같이 받게 넓힌 것이다.

### 예
사진을 찍어 올리고 "이게 무슨 뜻이야" 라고 물어본 적이 있다면 그 순간이 이것이다.

### 직접
표나 손글씨가 든 사진을 올려 그 안의 글자를 그대로 옮겨 달라고 해 보라. 글씨가 작으면 틀린다는 것도 같이 보인다.

## 🖼️ 그림으로 보기

```도해
흐름: 올린 사진은 모델 안에서 어떻게 되나
사진 :: 요청에 글과 나란히 실려 들어간다
자르기 :: 가로세로 몇십 픽셀짜리 네모로 나뉜다
세기 :: 네모 하나가 토큰 한 개로 셈된다
잇기 :: 글 토큰과 같은 줄에 이어 붙는다
< 답 :: 모델은 둘을 한 줄로 읽고 답을 돌려준다
= 그림도 글과 같은 조각으로 바꿔 한 입구로 넣는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 그림을 글로 옮겨 적어 넣으면 무엇이 아쉬운가
글로 옮겨 넣으면 || 그림째 넣으면
옮기는 품 :: 사람이 먼저 본다 || 들지 않는다
빠지는 것 :: 표의 배치가 없다 || 그대로 남는다
물어볼 것 :: 옮긴 만큼만 || 안 옮긴 것도
= 그림을 글로 바꿔 놓는 단계를 없애고 그림째 읽히는 것이다
```

예전에는 그림에 대해 물으려면 사람이 먼저 보고 글로 옮겨 적어야 했다. 옮기는 사람이 중요하다고 판단한 것만 넘어가므로, 나중에 다른 것을 묻고 싶어도 원본이 없으면 물을 수가 없다. 표의 칸 배치나 손으로 그은 화살표처럼 글로 옮기기 어려운 것은 그 자리에서 사라진다.

그림을 그대로 넣으면 그 단계가 없어진다. 대신 값은 공짜가 아니다 — OpenAI 문서는 이미지 입력도 글과 비슷하게 토큰 단위로 계량되고 청구된다고 적는다.

## ⚙️ 작동 원리

토큰 수는 픽셀이 아니라 네모 조각의 개수로 정해진다. Anthropic 문서는 이미지를 28×28 픽셀 블록으로 보고, 한 장의 비용을 `⌈가로/28⌉ × ⌈세로/28⌉` 로 적는다. 1000×1000 짜리 한 장이면 36×36, 즉 1296 토큰이다. 가로세로를 각각 두 배로 키우면 네모 수는 네 배가 된다.

무한정 오르지는 않는다. 모델마다 긴 변과 시각 토큰 수에 상한이 있고, 그보다 큰 그림은 비율을 지킨 채 줄여서 넣는다. 그래서 상한을 넘긴 뒤로는 크게 올려도 토큰이 더 늘지 않고, 대신 줄어든 만큼 작은 글씨는 더 안 보인다.

손잡이는 두 군데다. 하나는 보내기 전에 내가 줄이는 것이고, 다른 하나는 정밀도를 고르는 값이다. OpenAI 문서의 `detail` 은 `low`(세밀함이 중요하지 않을 때 빠르고 싸게) · `high` · `original` · `auto` 중에서 고르게 되어 있다.

## 💡 실제 사례

- **서식과 영수증 읽기** — 종이를 찍어 올리면 칸에 적힌 값을 그대로 뽑는다. 사람이 먼저 옮겨 적는 단계가 없어진다.
- **여러 장을 나란히 놓고 묻기** — 한 요청에 그림을 여러 장 넣어 무엇이 다른지 묻는다. 장마다 앞에 짧은 이름표를 달아 두면 뒤에 그 이름으로 가리킬 수 있다.
- **크기로 값 조절하기** — 세밀함이 필요 없는 그림은 보내기 전에 줄인다. 네모 수가 줄어 토큰도 그만큼 준다.

## 🚫 흔한 오해

- **그림은 토큰과 상관없다** — 그림도 네모 조각마다 토큰으로 센다. 1000×1000 한 장이 1296 토큰이라 웬만한 질문 글보다 무겁다.
- **그림을 읽으니 그림도 그려 준다** — 읽는 일과 만드는 일은 다르다. Anthropic 문서는 이미지 이해 전용이라 그림을 생성하거나 편집하지는 못한다고 못 박는다.
- **크게 올릴수록 잘 본다** — 상한을 넘으면 알아서 줄여 넣으므로 더 잘 보이지 않는다. 오히려 줄어든 만큼 작은 글씨가 안 읽히고, 상한 아래라면 값만 네 배로 오른다.

## 🚨 주의사항

- **사람을 알아보게 시키지 않는다.** Anthropic 문서는 사진 속 인물의 이름을 대는 일을 거부한다고 적는다.
- **세기와 위치를 그대로 믿지 않는다.** 물건 개수와 좌표는 어림값이고, 작거나 돌아간 그림에서는 틀리기 쉽다고 문서가 못 박는다.
- **한 요청에 그림을 많이 넣으면 장당 크기 제한이 더 빡빡해진다.** 지난 대화에 실려 다시 오는 그림까지 함께 세어지므로, 대화가 길어지면 모르는 사이에 넘어간다.

## 📝 정리

**"글 말고 다른 갈래도 같은 입구로 받는 것"** 이라고 읽으면 된다. 그림은 작은 네모로 잘려 글과 같은 줄에 이어 붙고 네모 수만큼 토큰으로 셈된다. 그래서 크게 올릴수록 값이 오르고, 상한을 넘으면 알아서 줄여 넣는다.

## 🧒 열 살에게

숙제를 글로 써서 내는 상자가 있다고 해 봐. 그 상자를 넓혀서 그림이랑 사진도 같이 받게 하면, 이제 "이 그림에 뭐가 있어?" 하고 물어볼 수 있지. 대신 큰 사진은 작은 네모로 잘게 잘라서 세니까 자리를 훨씬 많이 차지해.

## ❓ 이해했는지

- 사진의 가로세로를 두 배로 키우면 토큰이 왜 네 배가 되나 → 작동 원리
- 표가 든 종이를 찍어 올리는 편이 옮겨 적는 것보다 나은 까닭은 → 해결하는 문제
- 작은 글씨가 든 사진을 크게 올렸는데 더 안 읽히는 일은 왜 생기나 → 흔한 오해
