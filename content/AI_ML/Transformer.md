# Transformer (트랜스포머)

## 📝 정의

Transformer는 **문장을 한꺼번에 펼쳐 놓고 서로의 관계를 재는 구조**다.

앞에서부터 한 낱말씩 읽던 RNN 을 대신했다. GPT 와 BERT 를 비롯한 요즘 언어 모델이 전부 이 구조 위에 서 있다.

### 비유
책 한 쪽을 통째로 펼쳐 놓고 보는 것. 3번째 줄과 20번째 줄이 이어진다는 걸 한눈에 알아챈다.

## 🖼️ 그림으로 보기

```도해
흐름: 문장 하나가 Transformer 를 지나며 무엇을 겪나
토큰 :: 문장을 조각내 각각 숫자 배열로 바꾼다
위치 표시 :: 몇 번째 조각인지를 그 배열에 더한다
어텐션 :: 모든 조각이 서로를 얼마나 볼지 잰다
섞기 :: 많이 본 쪽 값을 더 얹어 새 배열을 만든다
@ 다시 어텐션으로 :: 같은 일을 여러 겹 쌓아 결과를 낸다
= 순서대로 읽지 않고 전부 펼쳐 놓은 채 관계만 잰다
```

## ⚠️ 해결하는 문제

```도해
대조: 문장을 앞에서부터 한 낱말씩 읽으면 어떻게 되나
한 낱말씩 || 한꺼번에
처리 순서 :: 앞이 끝나야 뒤 || 동시에 본다
GPU :: 나눠 쓸 수 없다 || 병렬로 돌린다
먼 관계 :: 갈수록 흐려진다 || 거리와 무관
= 순서를 버리고 관계를 직접 재는 쪽으로 바꾼 것이다
```

RNN 은 첫 낱말을 처리해야 두 번째를 처리할 수 있다. 순서를 지켜야 하니 GPU 를 여러 장 붙여도 나눠 돌릴 수 없어서, 백만 문장을 학습하는 데 며칠에서 몇 주가 걸렸다. 멀리 떨어진 관계도 약했다. "어제 시장에서 산 사과를 오늘 먹었다"에서 "사과"와 "먹었다"는 여러 낱말 건너에 있어 앞의 정보가 뒤로 오는 동안 흐려진다.

Transformer 는 문장 전체를 펼쳐 놓고 모든 조각 쌍의 관계를 한 번에 잰다. 순서에 묶이지 않으니 나눠 돌릴 수 있어 같은 학습이 몇 시간에서 하루 규모로 줄었다. 거리와 상관없이 "사과"와 "먹었다"가 곧바로 이어진다.

## ⚙️ 작동 원리

한 겹은 네 부품으로 되어 있다.

| 부품 | 하는 일 |
|---|---|
| **위치 인코딩** | 몇 번째 조각인지를 값에 실어 준다 |
| **셀프 어텐션** | 조각끼리 서로 얼마나 볼지 정한다 |
| **멀티 헤드** | 같은 일을 여러 갈래로 나눠 따로 본다 |
| **피드포워드** | 섞인 값을 한 번 더 변환한다 |

이 한 겹을 여러 번 쌓아 올린 것이 모델의 깊이다.

어텐션은 조각마다 다른 조각을 얼마나 볼지 점수로 매기고, 그 점수를 가중치 삼아 값을 섞는다. "나는 학교에 갔다"에서 "갔다"는 "학교에"를 많이 보고 "나는"은 조금만 보는 식이다.

멀티 헤드는 그 보기를 여러 갈래로 나눈다. 한 갈래는 문법 쪽 관계를, 다른 갈래는 의미 쪽 관계를 보게 갈라 두면 한 갈래만 쓸 때보다 잡히는 게 많다.

순서를 안 보고 관계만 재면 "나는 학교에 갔다"와 "학교에 나는 갔다"가 같아진다. 그래서 몇 번째 조각인지를 값에 실어 주는데, 이것을 위치 인코딩이라고 한다.

## 📊 비교: GPT vs BERT vs T5

| | GPT | BERT | T5 |
|---|---|---|---|
| 쓰는 부분 | 디코더만 | 인코더만 | 둘 다 |
| 하는 일 | 다음 낱말 예측 | 가려진 낱말 맞히기 | 입력을 다른 글로 |
| 맞는 자리 | 글 생성 | 분류, 질의응답 | 번역, 요약 |

## 💡 실제 사례

- **글 생성** — "안녕하세요, 저는" 다음에 올 조각을 하나씩 이어 붙여 문장을 만든다.
- **빈칸 맞히기** — "나는 [MASK]에 갔다"에서 가려진 자리를 앞뒤를 다 보고 채운다.
- **번역과 요약** — 입력을 통째로 읽고 다른 글로 바꿔 내놓는다.

## 🚫 흔한 오해

- **Transformer 는 문장을 순서대로 읽는다** — 전부 펼쳐 놓고 동시에 본다. 순서는 위치 인코딩으로 따로 실어 주는 것이라 그걸 빼면 낱말 순서를 아예 구별하지 못한다.
- **Attention 이 곧 이해다** — 어느 조각을 얼마나 볼지 정한 가중치일 뿐이다. 값을 섞는 비율이지 뜻을 읽어낸 결과가 아니다.
- **입력이 길어져도 계산은 비슷하다** — 모든 조각 쌍을 재므로 조각 수가 두 배면 계산은 네 배가 된다. 긴 입력이 부담스러운 이유가 여기 있다.

## 🚨 주의사항

- **입력이 길수록 메모리가 제곱으로 는다.** 긴 문서를 그대로 넣기 전에 자르거나 다른 어텐션 방식을 찾아본다.
- **작은 데이터로는 잘 되지 않는다.** 학습에 아주 많은 양이 필요해서 대개 이미 학습된 모델을 가져다 쓴다.

## 📝 정리

Transformer는 문장의 조각들을 한꺼번에 펼쳐 놓고 서로를 얼마나 볼지 재는 구조다. 순서에 묶이지 않아 나눠 돌릴 수 있고 멀리 떨어진 낱말 사이의 관계도 흐려지지 않는다. 대신 모든 쌍을 재느라 입력이 길어질수록 계산이 제곱으로 늘어난다.

## ❓ 이해했는지

- "나는 학교에 갔다"와 "학교에 나는 갔다"를 구별하려면 무엇이 필요한가 → 작동 원리
- RNN 은 GPU 를 여러 장 붙여도 학습이 빨라지지 않는데 그 이유는 → 해결하는 문제
- 입력 조각 수를 두 배로 늘리면 계산량은 몇 배가 되나 → 흔한 오해
