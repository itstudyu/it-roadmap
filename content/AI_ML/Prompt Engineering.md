# Prompt Engineering (프롬프트 엔지니어링)

## 📝 정의

Prompt Engineering은 **원하는 답이 나오도록 질문을 설계하는 기술**이다.

같은 모델도 무엇을 어떻게 물었느냐에 따라 다른 답을 내놓는다. 모델을 고치는 대신 입력을 고쳐서 답의 범위를 좁히는 것이 이 일이다.

### 이름
Prompt :: 시켜 보내는 글
Engineering :: 되게끔 설계하는 일
= 붙여 읽으면 "시키는 글을 설계하는 일". 한 방에 맞히는 재주가 아니라 고쳐 가며 맞추는 작업이다

### 비유
택배 기사에게 주소를 적어주는 것. "우리 집"이라고 쓰면 못 찾고, 동과 호수까지 쓰면 한 번에 온다.

### 예
검색이 엉뚱하게 나올 때 낱말을 바꿔 다시 쳐서 원하던 결과를 얻어본 적이 있다. 그 고쳐 치는 일이 여기서 하는 일이다.

### 직접
검색에 원하던 게 안 나오면 낱말을 하나 더 붙여 다시 쳐 보라. 같은 곳에 물었는데 결과가 달라진다.

## 🖼️ 그림으로 보기

```도해
흐름: 프롬프트를 고쳐 쓰면 답이 어떻게 달라지나
막연한 요청 :: "코드 짜줘". 언어도 조건도 없다
할 일 적기 :: 무엇을 만들지 한 문장으로 못 박는다
조건 적기 :: 쓸 라이브러리와 입력, 출력을 적는다
예시 넣기 :: 원하는 답의 모양을 한 벌 보여준다
< 모델 :: 좁아진 범위 안에서 골라 답을 돌려준다
= 모델은 마음을 읽지 않는다. 안 적은 것은 알아서 정한다
```

## ⚠️ 해결하는 문제

```도해
대조: 요청을 대충 적으면 무엇이 달라지나
막연한 요청 || 조건을 적은 요청
결과 :: 매번 다르다 || 모양이 고정된다
다시 시키기 :: 계속 고쳐 말한다 || 한 번에 끝난다
쓸 수 있나 :: 손보고 써야 한다 || 그대로 붙인다
= 안 적은 조건은 모델이 대신 정해버린다
```

"코드 작성해줘"라고만 하면 언어도, 쓸 라이브러리도, 예외 처리 여부도 모델이 정한다. 그때그때 다른 선택을 하니 같은 요청에 다른 답이 오고, 받을 때마다 고쳐 써야 한다.

프롬프트에 그 선택지들을 미리 적어두면 모델이 정할 몫이 줄어든다. 답이 매번 비슷한 모양으로 나오고, 그래야 다음 단계에 그대로 넘길 수 있다.

## ⚙️ 작동 원리

```도해
층: 프롬프트에 무엇부터 얹나
할 일 :: 무엇을 만들지 한 문장으로 적는다
조건 :: 형식, 길이, 쓰지 말 것을 적는다
예시 :: 원하는 답을 한두 벌 보여준다
생각 순서 :: "단계별로 생각해보자" 처럼 절차를 준다
= 위쪽만으로 되면 아래를 붙일 이유가 없다. 안 될 때 하나씩 얹는다
```

예시 없이 지시만 주는 것을 Zero-shot이라고 한다. 답의 형식이 흔들리면 예시를 한두 개 붙이는데, 이게 Few-shot이다. "긍정/부정"처럼 라벨을 정해 보여주면 그 표기를 따라온다.

계산이나 추론이 섞이면 "단계별로 생각해보자"를 덧붙인다. 피자 세 판을 여덟 명이 나누는 문제에서 답만 던지는 대신 전체 조각을 먼저 세고 나누는 식으로 과정을 적게 하는 것을 Chain-of-Thought라고 한다.

## 💡 실제 사례

- **분류 작업** — 예시 두 개를 붙여주면 라벨 표기가 예시와 같은 모양으로 나온다.
- **계산 문제** — 과정을 적게 하면 답만 던질 때보다 덜 틀리고, 틀렸을 때 어디서 어긋났는지 보인다.
- **코드 요청** — 쓸 라이브러리, 입력과 출력, 예외 처리 여부를 적어주면 받아서 고칠 일이 줄어든다.

## 🚫 흔한 오해

- **프롬프트는 길게 쓸수록 좋다** — 길이가 아니라 무엇이 적혀 있느냐다. 상관없는 말을 늘리면 정작 지켜야 할 조건이 그 안에 묻힌다.
- **성능을 올려주는 마법의 문장이 있다** — "당신은 전문가입니다" 한 줄이 없던 지식을 만들어주지는 않는다. 역할을 주는 것은 말투와 관점의 범위를 좁히는 일이다.
- **잘 물으면 모르는 것도 답해준다** — 프롬프트는 무엇을 어떤 모양으로 답할지를 정할 뿐이다. 모델이 갖고 있지 않은 사실이 필요하면 그 자료를 프롬프트에 같이 넣어야 한다.

## 📝 정리

**"모델이 알아서 정할 몫을 줄여 가는 그 고쳐 쓰기"** 라고 읽으면 된다. 지시, 조건, 예시, 생각 순서를 필요한 만큼만 얹고, 안 될 때 하나씩 더한다.

## 🧒 열 살에게

택배 아저씨한테 "우리 집" 이라고만 적어 주면 못 찾지? 동이랑 호수까지 적어 주면 한 번에 와. 어떻게 적었느냐로 오는 게 달라지니까, 엉뚱한 게 오면 화내지 말고 적는 말을 고쳐서 다시 보내는 거야.

## ❓ 이해했는지

- "코드 짜줘"라고만 했을 때 같은 요청에 매번 다른 답이 오는 이유는 → 해결하는 문제
- 예시를 한두 개 붙였을 때 답의 무엇이 고정되나 → 실제 사례
- 계산 문제에서 답만 던지고 틀릴 때 프롬프트에 무엇을 덧붙이나 → 작동 원리
