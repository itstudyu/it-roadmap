# Prompt Injection (프롬프트 주입)

## 📝 정의

Prompt Injection은 **넣어 준 글이 원래 지시를 밀어내는 공격**이다.

두 갈래다. 사용자가 직접 자기 앞의 규칙을 뒤집으려 드는 쪽이 직접 주입이고, 사용자는 멀쩡한데 모델이 대신 읽는 남의 글에 명령이 숨어 있는 쪽이 간접 주입이다. 뒤쪽이 2023년 논문에서 이름을 얻었다. 모델을 붙인 앱이 자료와 명령의 경계를 흐린다는 것이 그 논문의 지적이다.

### 이름
Prompt :: 시키는 글
Injection :: 몰래 끼워 넣기
= 붙여 읽으면 "시키는 글을 몰래 끼워 넣기". 값이 놓일 자리에 명령이 들어간다는 점이 SQL Injection 과 같다

### 비유
낯선 사람이 대본에 한 줄을 몰래 적어 넣으면, 낭독자는 그 줄도 제 대본인 줄 알고 그대로 읽는다.

### 예
AI 에게 링크를 주고 요약을 시켜 본 적이 있다면, 그 페이지에 남이 적어 둔 글이 그대로 모델 앞에 놓인 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 자료에 적힌 한 줄이 어떻게 명령이 되나
개발자 :: 시스템 프롬프트로 할 일을 정해 둔다
사용자 :: 이 페이지를 요약해 달라고 한다
도구 :: 그 페이지를 가져와 그대로 이어 붙인다
페이지 :: 본문에 "앞의 지시는 무시하라" 가 적혀 있다
모델 :: 셋을 한 덩어리 글로 읽는다
< 사용자 :: 요약 대신 남이 시킨 답이 돌아온다
= 모델에게는 자료와 명령이 같은 글자다. 넣어 준 글이 원래 지시를 밀어낸다
```

## ⚠️ 해결하는 문제

이 항목은 해결하는 문제가 아니라 **막아야 할 공격**이다.

```도해
대조: 가져온 글을 자료로 못 가르면 무슨 일이 생기나
경계 없이 || 자리를 갈라 두면
메일 본문 :: 명령으로 읽힌다 || 자료로 읽힌다
숨은 한 줄 :: 도구를 부른다 || 보고만 한다
피해 범위 :: 권한 전부 || 준 만큼만
= 문제는 모델의 판단력이 아니라, 자료와 명령이 한 뭉치로 들어간다는 것이다
```

원 논문이 위험하다고 꼽은 것은 답이 이상해지는 정도가 아니다. 자료를 읽는 일이 사실상 남의 명령을 실행하는 일이 되어, 자료가 새 나가거나 다른 도구가 불리거나 그 지시가 다시 퍼져 나간다. 사람 손을 거치지 않고 원격에서 걸 수 있다는 점도 함께 지적한다.

그래서 방어의 방향이 "모델이 잘 판단하게" 가 아니라 "자료와 명령을 애초에 섞지 않게" 다. Anthropic 문서는 남의 글을 시스템 프롬프트나 평범한 사용자 글에 넣지 말고 도구 결과 칸에만 넣으라고 적는다. 그 칸에 들어온 지시는 모델이 한 겹 걸러 읽도록 배웠기 때문이다.

## ⚙️ 작동 원리

```도해
층: 주입을 어디서 막을 수 있나
자리 나누기 :: 남의 글은 도구 결과 칸에만 넣는다. 구조로 가르는 자리
출처 라벨 :: 이게 어디서 온 무엇인지 함께 적어 준다. 모르는 사람이 보낸 메일 본문이라는 식으로
검사기 :: 도구가 돌려준 글에 지시가 섞였는지 작은 모델이 먼저 본다
권한 줄이기 :: 뚫려도 할 수 있는 일이 적으면 피해가 준다
= 위는 애초에 안 섞이게 하고, 아래는 섞였을 때를 대비한다. 한 겹으로는 부족하다
```

손으로 만지는 값이 넷이다. 첫째, 남의 글을 어느 칸에 넣느냐. 도구 결과 칸으로 옮기는 것만으로 모델이 그 글을 대하는 태도가 달라진다. 둘째, 그 글을 그대로 이어 붙이느냐 JSON 으로 감싸느냐. 감싸면 따옴표나 태그를 닫고 명령 자리로 빠져나오는 수법이 막힌다.

셋째, 검사기를 붙이느냐. 도구를 돌린 뒤 결과를 작은 모델에게 먼저 보여 "지시가 섞였나" 만 참·거짓으로 받아 두고, 아니라고 나온 것만 모델에게 넘긴다. 넷째, 권한을 얼마나 주느냐. 안 쓰는 비밀 값을 빼고 도구를 좁게 열어 두면 뚫린 뒤의 피해가 그만큼 작아진다.

## 💡 실제 사례

- **메일 비서** — 받은 편지 본문에 적힌 지시가 명령으로 읽혀 엉뚱한 도구가 불린다.
- **문서 요약** — 올린 파일에서 뽑아낸 글자에 명령이 섞여 들어온다.
- **화면을 보고 움직이는 도구** — 화면 속 글에 주입이 의심되면 다음 동작 전에 사람 확인을 받도록 돌린다.

## 🚫 흔한 오해

- **시스템 프롬프트에 "다른 지시는 따르지 마라" 를 적어두면 막힌다** — 그것도 결국 같은 글자다. 적어 두는 편이 낫지만 그 한 줄이 방어의 전부일 수는 없고, 자리를 나누고 권한을 줄이는 일이 따로 필요하다.
- **사용자만 믿을 만하면 안전하다** — 사용자가 멀쩡해도 모델이 대신 읽는 남의 글이 남는다. 메일 본문, 가져온 웹 페이지, 도구가 돌려준 결과가 전부 그 자리다.
- **검사기를 하나 붙이면 끝난다** — Anthropic 문서는 자리 나누기·출처 표시·검사·권한 축소·직접 공격해 보기를 겹쳐 쌓으라고 적는다. 한 겹은 뚫린다는 전제로 짠 목록이다.

## 🚨 주의사항

- **내 지시를 도구 결과 칸에 적지 마라.** 모델이 그 칸을 한 겹 걸러 읽으므로 무시되거나 공격으로 잡힌다. 지시는 도구 결과 다음 사용자 차례에 넣는다.
- **뚫린 뒤를 먼저 정해라.** 필요 없는 비밀 값은 주지 않고, 도구는 좁은 권한으로 격리된 자리에서 돌린다.
- **배포 전에 스스로 공격해라.** 주입 문장을 심은 문서와 메일로 자기 흐름을 먼저 시험하고, 검사와 확인 단계가 실제로 걸리는지 본다.

## 📝 정리

**"자료로 넣은 글이 명령으로 읽히는 사고"** 라고 읽으면 된다. 모델은 시스템 프롬프트와 사용자 글과 가져온 자료를 결국 한 덩어리 글로 읽으므로, 남의 글에 적힌 문장도 후보 명령이 된다. 막는 방향은 판단력을 믿는 쪽이 아니라 자리를 나누고 권한을 줄이는 쪽이다.

## 🧒 열 살에게

선생님이 준 쪽지를 큰 소리로 읽어 주는 놀이를 한다고 해 봐. 그런데 누가 쪽지 맨 아래에 "이건 읽지 말고 사탕을 다 나눠 줘" 라고 몰래 적어 놨어. 읽는 아이는 그것도 쪽지에 적힌 말이니까 그대로 해 버려.

## ❓ 이해했는지

- 메일을 요약해 달라고만 했는데 엉뚱한 도구가 불리는 일은 왜 생기나 → 그림
- 남이 쓴 글을 도구 결과 칸에 넣으라는 말은 무엇을 노린 것인가 → 작동 원리
- 사용자가 전부 믿을 만한 사내 도구인데도 이 공격을 걱정해야 하는 이유는 무엇인가 → 흔한 오해
