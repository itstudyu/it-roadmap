# LLM (Large Language Model)

## 📝 정의

LLM은 **다음에 올 말을 예측하도록 학습된 언어 모델**이다.

방대한 텍스트로 학습해서, 번역이든 요약이든 코드 작성이든 모델 하나로 처리한다. 예전에는 작업마다 별도의 모델을 따로 학습시켜야 했다.

### 비유
말 이어가기 놀이를 수없이 해본 사람. "나는 사과를" 다음에 무엇이 올지 감으로 안다.

## 🖼️ 그림으로 보기

```도해
흐름: "오늘 날씨가" 를 넣으면 답이 어떻게 만들어지나
토큰화 :: 문장을 작은 조각으로 나눈다
임베딩 :: 조각마다 숫자 벡터를 붙인다
어텐션 :: 각 조각이 어디를 봐야 하는지 계산한다
예측 :: 다음에 올 조각마다 확률을 매긴다
반복 :: 고른 조각을 붙이고 다시 예측한다
< 출력 :: 멈춤 신호가 나올 때까지 이어진 문장
= 문장을 통째로 떠올리는 게 아니라 한 조각씩 이어 붙인다
```

## ⚠️ 해결하는 문제

```도해
대조: 작업마다 모델을 따로 만들면 어떻게 되나
LLM 이전 || LLM 으로
새 작업 :: 데이터 모아 학습 || 예시 몇 개면 됨
문맥 :: 단어만 보고 판단 || 앞뒤를 같이 봄
관리 :: 작업 수만큼 모델 || 하나로 처리
= 모델을 새로 만들던 일을 지시를 바꾸는 일로 옮겼다
```

번역기, 요약기, 질의응답기를 각각 만들던 시절에는 새 작업이 생길 때마다 데이터를 모으고 몇 달을 다시 학습시켜야 했다. 모델이 늘수록 관리할 것도 같이 늘었다.

문맥을 못 보는 것도 문제였다. "사과"라는 단어만 떼어놓고 보면 과일인지 사과문인지 알 수 없다. LLM은 문장 안의 다른 단어들과의 관계를 함께 계산해서 이걸 가른다.

## ⚙️ 작동 원리

모델은 글자가 아니라 토큰이라는 조각 단위로 문장을 다룬다. 대략 영어는 한 단어가 1토큰을 조금 넘고 한국어는 한 단어가 여러 토큰으로 쪼개진다.

어텐션은 각 조각이 문장 안의 어느 조각을 참고해야 하는지를 정한다. "사과를 들고"에서는 앞의 "들고"가, "그녀에게 사과를"에서는 "그녀에게"가 뜻을 가른다.

다음 조각을 고를 때는 확률이 가장 높은 하나만 쓰는 게 아니다. Temperature 값을 0에 가깝게 두면 거의 같은 답이 나오고, 값을 올리면 덜 뻔한 조각도 골라서 답이 매번 달라진다.

## 💡 실제 사례

- **요약과 번역** 같은 모델에 지시만 바꿔서 문서를 줄이거나 다른 언어로 옮긴다.
- **코드 작성** 요구사항을 문장으로 적으면 함수 뼈대를 만들어준다.
- **분류** 예시 두세 개만 보여주면 새 문장을 그 기준으로 나눈다.

## 🚫 흔한 오해

- **LLM이 어딘가에서 답을 찾아온다** — 검색이 아니라 생성이다. 학습한 것을 바탕으로 다음 말을 이어 붙일 뿐이라 원래 출처라는 게 없다.
- **모르는 건 모른다고 한다** — 그럴듯한 문장을 만들도록 학습돼서, 지어낸 답도 아는 답과 똑같은 말투로 나온다.
- **컴퓨터니까 같은 질문엔 같은 답이 나온다** — 다음 조각을 확률로 고르기 때문에 답이 매번 조금씩 달라진다. 고정하려면 Temperature를 0에 가깝게 둬야 한다.

## 🚨 주의사항

- **한 번에 넣을 수 있는 양에 한계가 있다.** 그 길이를 넘기면 문서를 잘라 나눠 넣고 결과를 합치는 식으로 돌아가야 한다.
- **학습이 끝난 뒤의 일은 모른다.** 최신 정보가 필요하면 검색이나 문서를 붙여서 넣어줘야 한다.

## 📝 정리

LLM은 다음에 올 조각을 확률로 골라 문장을 이어 붙이는 모델이다. 하나로 번역과 요약과 코드 작성을 모두 하지만 사실을 확인하는 기능은 없어서, 그럴듯한 오답이 맞는 답과 같은 말투로 나온다.
