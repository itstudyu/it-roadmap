# RAG (Retrieval-Augmented Generation)

## 📝 정의

RAG는 **답하기 전에 문서를 먼저 찾아보게 만드는 방식**이다.

모델이 기억으로만 답하면 사내 규정이나 지난달에 바뀐 값은 알 수 없다. 그래서 관련 문서를 검색해 프롬프트에 붙이고 그 안에서 답하게 한다.

### 비유
시험 중에 교과서를 펴놓고 답을 쓰는 것. 외운 기억이 아니라 펼친 쪽에서 옮겨 적는다.

## 🖼️ 그림으로 보기

```도해
흐름: 육아휴직 기간을 물으면 무슨 순서로 답이 나오나
사용자 :: 육아휴직 기간이 얼마냐고 묻는다
임베딩 :: 그 질문을 숫자 배열로 바꾼다
벡터 DB :: 가까운 문서 조각 서너 개를 돌려준다
프롬프트 :: 찾은 조각과 질문을 한 장에 붙인다
LLM :: 붙여준 조각 안에서 답을 쓴다
< 사용자 :: 답과 함께 어느 조항에서 왔는지 받는다
= 기억을 꺼낸 게 아니라 방금 받은 문서를 읽고 답한 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 회사 내부 규정을 물으면 어떻게 되나
RAG 없이 || RAG 로
모르는 것 :: 그럴듯하게 지음 || 문서에서 찾는다
최신 정보 :: 학습 시점까지만 || 문서 고치면 끝
출처 :: 댈 수 없다 || 조항까지 댄다
= 기억으로 답하던 것을 찾아 읽고 답하는 것으로 바꾼다
```

일반 LLM 에 "우리 회사 육아휴직 기간은?"이라고 물으면 "보통 1년입니다" 같은 답이 돌아온다. 학습할 때 본 적 없는 사내 문서인데도 모른다고 말하는 대신 그럴듯한 값을 지어낸다. 지난달에 바뀐 가격을 물어도 사정은 같다.

RAG 는 답을 만들기 전에 검색을 한 번 끼워 넣는다. 취업규칙에서 육아휴직 대목을 먼저 찾아 프롬프트에 붙이고, 그 안에서만 답하라고 시킨다. 규정이 바뀌면 문서만 갈아 끼우고 모델은 그대로 둔다.

## ⚙️ 작동 원리

```도해
층: RAG 를 세우는 일은 언제 하는 것끼리 나뉘나
문서 넣기 :: 한 번만. 문서를 조각내 벡터로 저장한다
질문 처리 :: 매번. 질문을 벡터로 바꿔 가까운 조각을 찾는다
답 만들기 :: 매번. 찾은 조각을 붙여 LLM 에 넘긴다
= 앞의 한 번이 제대로 되어 있어야 매번 도는 뒤의 둘이 산다
```

문서는 통째로 넣지 않고 조각으로 자른다. 조각이 크면 관계없는 내용까지 딸려 오고, 작으면 문맥이 끊긴다. 원본 노트는 500자쯤으로 자르고 50자쯤 겹치게 두는 예를 든다. 겹치는 부분이 있어야 경계에서 잘린 문장을 덜 잃는다.

가깝다는 판단은 임베딩이 한다. 질문과 조각을 같은 방식으로 숫자 배열로 바꾸면 뜻이 비슷한 것끼리 배열도 가까워진다. 그 거리를 재서 위에서 서너 개만 고른다.

## 📊 비교: 일반 LLM vs RAG vs Fine-tuning

| | 일반 LLM | RAG | Fine-tuning |
|---|---|---|---|
| 지식 출처 | 학습 데이터 | 바깥 문서 | 재학습 데이터 |
| 최신 정보 | 안 된다 | 문서만 고치면 된다 | 다시 학습해야 한다 |
| 출처 표시 | 못 한다 | 조각까지 댄다 | 못 한다 |
| 바꾸는 비용 | 바꿀 수 없다 | 낮다 | 높다 |

## 💡 실제 사례

- **사내 규정 문의** 취업규칙을 넣어두고 조항 번호까지 붙여 답하게 한다.
- **고객 지원** 제품 매뉴얼과 FAQ 를 넣어두고 내용이 바뀌면 문서만 갈아 끼운다.
- **검색 실패 대비** 벡터 검색과 낱말 검색을 같이 돌려 한쪽이 놓친 것을 다른 쪽이 잡게 한다.

## 🚫 흔한 오해

- **RAG 를 붙이면 환각이 사라진다** — 줄어들 뿐이다. 검색이 엉뚱한 조각을 물어오면 모델은 그 조각을 근거로 그럴듯하게 틀린 답을 쓴다.
- **RAG 는 모델을 학습시키는 것이다** — 모델은 손대지 않는다. 찾은 문서를 프롬프트에 붙일 뿐이라 다음 질문에는 아무것도 남지 않는다.
- **문서를 많이 넣을수록 답이 좋아진다** — 넣은 양이 아니라 골라오는 정확도가 답을 정한다. 문서가 늘면 엉뚱한 조각이 섞일 확률도 같이 는다.

## 🚨 주의사항

- **문서가 틀려 있으면 답도 틀린다.** RAG 는 문서를 근거로 옮겨 쓰는 장치라 문서 관리가 곧 답변 품질이다.
- **조각 크기를 정하지 않고 넘어가지 않는다.** 크면 잡음이 섞이고 작으면 문맥이 끊겨서, 검색이 아무리 좋아도 답이 흔들린다.

## 📝 정리

RAG는 답을 만들기 전에 검색을 끼워 넣어 기억이 아니라 찾아온 문서를 근거로 답하게 만드는 방식이다. 모델은 그대로 두고 문서만 갈아 끼우면 되므로 자주 바뀌는 정보와 사내 문서에 맞는다. 다만 골라온 조각이 엉뚱하면 답도 같이 엉뚱해진다.
