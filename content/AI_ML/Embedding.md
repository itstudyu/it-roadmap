# Embedding (임베딩)

## 📝 정의

Embedding은 **텍스트를 숫자로 번역하는 기술**입니다. 마치 GPS가 "강남역"을 좌표(위도, 경도)로 바꾸듯, Embedding은 "육아휴직"을 숫자 벡터로 바꿉니다.

### 핵심 개념

- **무엇인가?**: 텍스트 → 수백 개의 숫자 배열 (벡터)
- **왜 필요한가?**: 컴퓨터가 단어의 "의미"를 이해하고 비교하기 위해
- **어떻게 작동하나?**: 비슷한 의미 = 비슷한 숫자

## 🤔 왜 Embedding이 필요한가?

### 텍스트 그대로는 비교 불가능

**문제 상황**:
```
"육아휴직"과 "양육휴가"는 얼마나 비슷한가?

컴퓨터가 텍스트만 보면:
"육아휴직" = [육, 아, 휴, 직]
"양육휴가" = [양, 육, 휴, 가]
→ 글자가 다르네? 전혀 다른 것 같은데? ❌

사람은 안다:
→ 거의 같은 뜻! ✅
```

**키워드 검색의 한계**:
```
사용자: "아이 키우려고 쉬고 싶어요"
시스템: ["육아휴직" 단어 찾기]
→ 못 찾음! ❌

문제: 같은 의미를 다르게 표현하면 찾지 못함
```

### Embedding의 해결

```
텍스트 → 숫자 벡터로 변환:

"육아휴직" → [0.8, 0.2, 0.9, 0.1, ...]
"양육휴가" → [0.7, 0.3, 0.8, 0.2, ...]
"연차휴가" → [0.3, 0.6, 0.4, 0.8, ...]

거리 계산:
육아휴직 ↔ 양육휴가: 거리 0.1 (매우 가까움!) ✅
육아휴직 ↔ 연차휴가: 거리 0.9 (멀음)
```

## 📊 Embedding 작동 원리

### 의미가 비슷하면 벡터도 비슷


### 2D로 시각화하면

```
       육아휴직 ● ● 양육휴가
                   (가까움!)

    연차휴가 ●


              ● 자동차
           (완전 다름)
```

실제로는 768차원이지만 개념은 같습니다!

## 💡 일상적 비유로 이해하기

### Embedding = GPS 좌표

**주소 (텍스트)**:
```
"강남역" vs "홍대입구"는 얼마나 가까운가?
→ 글자만 보면 알 수 없음
```

**GPS 좌표 (Embedding)**:
```
강남역: (37.498, 127.028)
홍대입구: (37.557, 126.924)

거리 계산: 약 9km ✅
→ 숫자로 변환하니 비교 가능!
```

**Embedding도 마찬가지**:
```
"육아휴직" → [0.8, 0.2, 0.9, ...]
"양육휴가" → [0.7, 0.3, 0.8, ...]

유사도 계산: 0.95 (매우 비슷함!) ✅
```

   "양육휴가" = "육아휴직" 인식 ✅

## 📝 정리

**Embedding 핵심 3줄 요약**:
```
1. 텍스트를 숫자 벡터로 변환
2. 의미가 비슷하면 벡터도 비슷
3. 컴퓨터가 의미를 "계산"할 수 있게 함

→ RAG의 핵심 기술!
```

**비유로 기억하기**:
```
텍스트 = 주소 ("강남역")
Embedding = GPS 좌표 (37.498, 127.028)

주소만으로는 거리 계산 불가
GPS 좌표로 변환하면 거리 계산 가능!

텍스트만으로는 유사도 계산 불가
Embedding으로 변환하면 유사도 계산 가능!
```

**Embedding 공식**:
```
비슷한 의미 = 가까운 벡터
다른 의미 = 먼 벡터

거리 계산 = Cosine Similarity
→ 0.9 이상: 거의 같음
→ 0.5~0.7: 관련 있음
→ 0.3 이하: 관련 없음
```

**P3 시스템 흐름**:
```
1. 문서들 Embedding → Vector DB 저장 (준비)
2. 질문 Embedding → 유사 벡터 검색 (검색)
3. 가까운 문서 찾음 → LLM에 전달 (답변)

핵심: Embedding이 없으면 의미 검색 불가능!
```
