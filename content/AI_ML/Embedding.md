# Embedding (임베딩)

## 📝 정의

Embedding은 **글이나 이미지를 뜻이 담긴 숫자 목록으로 바꾸는 것**이다.

컴퓨터는 "강아지"와 "개"가 비슷한 말인지 모른다. 두 단어를 각각 수백 개의 숫자로 바꾸되, 뜻이 가까우면 숫자도 가깝게 만든다. 그러면 뜻을 계산으로 비교할 수 있다.

### 비유
지도 위의 좌표. 도시 이름만으로는 어디가 가까운지 모르지만 위도와 경도로 바꾸면 거리를 뺄셈으로 구할 수 있다. 임베딩은 뜻에 좌표를 붙이는 일이다.

## 🖼️ 그림으로 보기

```도해
흐름: 비슷한 문서를 찾을 때 무슨 계산을 하나
문장 :: "환불하고 싶어요" 가 들어온다
임베딩 모델 :: 숫자 1536개짜리 목록으로 바꾼다
저장된 문서 :: 이미 같은 방식으로 바뀌어 있다
거리 계산 :: 두 목록이 이루는 각도를 잰다
< 결과 :: 각도가 가장 작은 문서가 뜻이 가장 가깝다
= 단어가 하나도 안 겹쳐도 뜻이 가까우면 찾아낸다
```

## ⚠️ 해결하는 문제

```도해
대조: "환불" 로 검색하면 무엇이 나오나
키워드 검색 || 임베딩 검색
"반품 절차" 문서 :: 못 찾는다 || 찾는다
"환불 불가" 문서 :: 찾는다 || 찾는다
오타 "환뷸" :: 못 찾는다 || 대체로 찾는다
= 글자가 겹치는지가 아니라 뜻이 가까운지로 찾게 만든다
```

키워드 검색은 글자가 겹쳐야 찾는다. "환불"로 검색하면 "반품 절차"라는 제목의 문서는 나오지 않는다. 같은 말을 다르게 쓰는 경우가 워낙 많아서 사용자는 원하는 문서를 찾지 못한다.

임베딩은 뜻을 좌표로 만들어 이 문제를 우회한다. 글자가 하나도 겹치지 않아도 뜻이 가까우면 좌표가 가깝다.

## ⚙️ 작동 원리

벡터 사이의 거리는 보통 각도로 잰다. 이걸 코사인 유사도라고 하고, 1에 가까울수록 뜻이 가깝다.

```도해
층: 무엇을 임베딩할 수 있나
단어 :: "강아지" 하나
문장 :: "강아지가 공을 물었다"
문단 :: 문서 조각 하나
이미지 :: 사진도 같은 공간에 넣을 수 있다
= 같은 공간에 넣으면 글로 이미지를 검색하는 일도 가능해진다
```

중요한 제약이 있다. **같은 모델로 만든 벡터끼리만 비교할 수 있다.** 문서를 A 모델로 임베딩했다면 질문도 A 모델로 해야 한다. 모델을 바꾸면 저장된 벡터를 전부 다시 만들어야 한다.

## 💡 실제 사례

- **의미 검색** — 사용자가 쓴 표현과 문서의 표현이 달라도 찾아준다.
- **추천** — 사용자가 좋아한 항목의 벡터와 가까운 것을 고른다.
- **중복 탐지** — 표현만 바꾼 문서나 문의를 찾아낸다.

## 🚫 흔한 오해

- **임베딩이 문장의 뜻을 이해한다** — 이해하지 않는다. 같이 등장하는 패턴에서 뽑은 통계라 반대말이 서로 가깝게 나오는 일도 흔하다.
- **숫자가 많을수록 좋다** — 차원이 크면 정확도가 조금 오르지만 저장 공간과 검색 비용이 같이 오른다.
- **모델을 바꿔도 기존 벡터를 쓸 수 있다** — 좌표계 자체가 달라진다. 전부 다시 만들어야 한다.

## 🚨 주의사항

- **반대말이 가깝게 나온다.** "좋다"와 "나쁘다"는 같은 문맥에 등장해서 벡터가 가깝다. 감정 판단에 임베딩 거리만 쓰면 틀린다.
- **모델 교체 비용을 미리 계산한다.** 문서 백만 건이면 백만 번 다시 임베딩해야 한다.

## 📝 정리

Embedding은 뜻을 좌표로 바꿔 계산으로 비교할 수 있게 만드는 방법이다. 글자가 안 겹쳐도 찾아주지만, 같은 모델로 만든 벡터끼리만 비교할 수 있다.

## ❓ 이해했는지

- "환불"로 검색했는데 "반품 절차" 문서가 나오는 것이 어떻게 가능한가?
- 임베딩 모델을 바꾸면 무슨 작업이 따라오나?
- 리뷰의 좋고 나쁨을 임베딩 거리로만 판단하면 왜 위험한가?
