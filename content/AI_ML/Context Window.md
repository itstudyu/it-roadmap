# Context Window (컨텍스트 윈도우)

## 📝 정의

Context Window는 **모델이 한 번에 볼 수 있는 글의 길이**다.

길이는 글자가 아니라 토큰으로 센다. 질문과 지난 대화와 붙여 보낸 문서가 전부 이 한도를 나눠 쓰고, 모델이 내놓을 답도 같은 한도 안에 들어가야 한다.

### 이름
Context :: 앞뒤 사정
Window :: 뚫린 만큼만 보는 창
= 붙여 읽으면 "앞뒤 사정이 보이는 창". 창 밖으로 밀려난 것은 없는 것과 같다

### 비유
책상. 아무리 넓어도 올려둔 것만 보면서 일한다. 책장에 꽂힌 책은 올려놓기 전까지 없는 것과 같다.

### 예
긴 문서를 통째로 붙여넣었더니 길이가 넘친다며 거절당하는 그 순간이 창의 끝이다.

### 직접
챗봇과 대화를 아주 길게 이어간 뒤, 맨 처음에 알려 준 이름을 다시 물어보라. 모른다고 하면 그 대목이 창 밖으로 밀려난 것이다.

## 🖼️ 그림으로 보기

```도해
흐름: 대화가 길어지면 앞부분은 어디로 가나
사용자 :: 새 질문 한 줄을 보낸다
프로그램 :: 지난 대화 전체를 앞에 붙여 보낸다
모델 :: 붙어 온 글을 토큰으로 센다
모델 :: 창을 넘으면 거절하거나 앞부분이 잘린다
< 사용자 :: 창 안에 남은 것만 보고 만든 답을 받는다
@ 다음 질문 :: 지난 대화가 또 통째로 붙어 온다
= 모델이 기억하는 게 아니라 매번 통째로 다시 읽는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 창 크기를 모르고 쓰면 어떤 일이 생기나
모르고 쓰면 || 알고 쓰면
긴 문서 :: 통째로 넣는다 || 나눠서 넣는다
결과 :: 길이 초과로 실패 || 필요한 데만 답
비용 :: 안 쓸 글까지 낸다 || 넣은 만큼만
= 창은 늘릴 수 없으니 무엇을 넣을지 고르는 문제가 된다
```

모델에게 자료를 주는 방법은 창 안에 넣는 것 하나뿐이다. 사내 문서 전체를 읽히고 싶어도 창보다 길면 들어가지 않고, 대화를 길게 이어가면 앞부분부터 밀려 나간다.

그래서 창 크기를 아는 일은 곧 무엇을 넣고 무엇을 뺄지 정하는 일이 된다. 질문과 관련된 조각만 찾아 넣거나, 지난 대화를 요약해 압축하거나, 문서를 나눠 여러 번 묻는 방식이 여기서 나온다.

## ⚙️ 작동 원리

토큰은 글을 자른 조각이다. 영어는 단어 하나가 대체로 한두 토큰이고 한국어는 같은 글자 수라도 토큰이 더 많이 나온다. 그래서 창 크기를 글자 수로 환산해 외우면 잘 맞지 않는다.

입력과 출력이 같은 창을 나눠 쓴다는 점도 놓치기 쉽다. 창을 입력으로 거의 채우면 답이 들어설 자리가 남지 않아 중간에서 끊긴다.

## 💡 실제 사례

- **긴 보고서 요약** — 창보다 긴 문서는 조각으로 나눠 각각 요약하고 그 요약을 다시 합친다.
- **오래 이어지는 상담** — 앞부분 대화를 요약본으로 바꿔 넣어 창 안에 남긴다.
- **문서 검색을 붙이는 이유** — 전체를 넣는 대신 질문과 관련된 조각만 찾아 넣는다.

## 🚫 흔한 오해

- **모델이 앞에서 한 말을 기억하고 있다** — 기억하지 않는다. 프로그램이 매번 지난 대화를 통째로 다시 붙여 보내는 것이고, 그래서 대화가 길수록 같은 질문에도 비용이 오른다.
- **창이 크면 채울수록 좋다** — 넣은 만큼 돈과 시간이 든다. 관련 없는 글까지 채우면 느려지고 답도 흐려진다.
- **창은 입력 길이를 뜻한다** — 답변도 같은 창을 나눠 쓴다. 입력으로 창을 거의 채우면 답이 짧아지거나 잘린다.

## 📝 정리

**"책상에 올려둔 만큼만 보는 그 한 뼘"** 이라고 읽으면 된다. 붙여 보낸 지난 대화와 문서, 그리고 모델이 내놓을 답까지 그 한 뼘을 나눠 쓴다. 늘릴 수 없는 값이라 무엇을 올려둘지 고르는 일이 실제 작업이 된다.

## 🧒 열 살에게

책상 위에 올려놓은 종이만 보면서 숙제한다고 해 봐. 책장에 아무리 책이 많아도 꺼내서 올려놓기 전에는 없는 거나 마찬가지지? 새 종이를 자꾸 올리면 먼저 놓았던 게 책상 밖으로 밀려 떨어지고, 떨어진 건 못 봐.

## ❓ 이해했는지

- 대화가 길어질수록 같은 질문에 비용이 더 드는 이유는 → 흔한 오해
- 창보다 긴 문서를 요약해야 할 때 무엇을 하나 → 실제 사례
- 입력을 창 끝까지 채웠더니 답이 중간에 끊긴다면 왜인가 → 작동 원리
