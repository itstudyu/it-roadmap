# Orchestrator (오케스트레이터)

## 📝 정의

Orchestrator 는 **요청을 보고 어느 Agent 에게 맡길지 정하는 층**이다.

Agent 를 여러 개 만들어두는 것만으로는 쓸 수 없다. 들어온 질문이 어느 갈래인지 판단하고, 맡을 곳을 고르고, 여러 곳에서 온 답을 하나로 정리하는 자리가 따로 있어야 한다.

### 비유
병원 접수 창구. 증상을 듣고 어느 과로 보낼지 정하고, 여러 과를 봐야 하면 결과를 모아 한 장으로 준다.

## 🖼️ 그림으로 보기

```도해
흐름: 질문 하나가 들어오면 어느 Agent 가 답하게 되나
사용자 :: 주소를 바꾸고 싶다고 쓴다
분류 :: 이 질문이 어느 갈래인지 판단한다
라우팅 :: 그 갈래를 맡은 Agent 를 고른다
Agent :: 자기 영역에서 답을 찾아온다
통합 :: 여러 답이면 하나로 정리한다
< 사용자 :: 어느 Agent 가 답했는지는 모른 채 받는다
= Agent 를 여러 개 두는 값은 어느 것을 부를지 정하는 자리에서 나온다
```

## ⚠️ 해결하는 문제

```도해
대조: Agent 를 여러 개 두기만 하면 어떻게 되나
조율 없이 || Orchestrator 로
질문 하나 :: 전부 응답한다 || 맡은 곳만 답
답을 못 찾음 :: 거기서 끝난다 || 다음 곳에 물음
요청이 둘 :: 사용자가 정리 || 하나로 묶어 줌
= Agent 를 늘릴수록 어느 것을 부를지 정하는 일이 더 필요해진다
```

문서 검색, 메뉴 안내, 급여 조회를 각각 맡은 Agent 가 있다고 하자. "주소 변경하고 싶어"라는 한 문장에 셋이 전부 답하면 화면에는 서로 다른 세 개의 답이 뜬다. 사용자는 어느 것이 맞는지 알 수 없다.

Orchestrator 는 그 앞에 판단을 하나 넣는다. 질문의 갈래를 정하고 맡을 곳 하나만 부른다. 실패하면 다음 후보에게 넘기고, 한 문장에 두 가지를 물었으면 둘로 쪼개 각각 보낸 뒤 결과를 합쳐 돌려준다.

## ⚙️ 작동 원리

Orchestrator 안은 네 자리로 나뉜다.

| 자리 | 하는 일 |
|---|---|
| **의도 분류** | 질문이 어느 갈래인지 정한다 |
| **라우터** | 갈래에 맞는 Agent 를 고른다 |
| **Agent 풀** | 각자 한 영역만 맡은 실행기들 |
| **응답 통합** | 여러 답을 하나의 문장으로 만든다 |

앞에 선 것이 뒤를 정한다. **분류가 틀리면 뒤가 아무리 좋아도 엉뚱한 답이 나온다.**

의도 분류는 대개 LLM 에게 갈래 목록을 주고 문장 전체를 보고 고르게 한다. 키워드만으로 나누면 같은 단어가 여러 갈래에 걸리는 순간 어긋난다.

맡은 Agent 가 "찾을 수 없다"고 답했을 때 그대로 끝내지 않으려면 다음 후보 순서를 정해둬야 한다. 이것을 폴백이라고 하고, 응답이 충분한지 판단하는 기준을 같이 정해두어야 동작한다.

## 📊 비교

| | Router | Orchestrator |
|---|---|---|
| 하는 일 | 어디로 보낼지만 | 조율 전체 |
| Agent 수 | 하나를 고른다 | 여럿을 부를 수 있다 |
| 결과 통합 | 없다 | 있다 |
| 실패 처리 | 거기서 끝 | 다음 후보로 넘김 |

## 💡 실제 사례

- **사내 문의 챗봇** — 규정 검색, 메뉴 안내, 급여 조회를 각각 맡은 Agent 를 두고 질문마다 하나만 부른다.
- **복합 요청 분해** — 한 문장에 두 가지를 물으면 둘로 쪼개 각각 보내고 답을 번호로 묶어 돌려준다.
- **폴백 사슬** — 맡은 Agent 가 못 찾으면 다음 후보에게 같은 질문을 넘겨 답이 나올 때까지 시도한다.

## 🚫 흔한 오해

- **Orchestrator 는 라우터를 부르는 다른 말이다** — 라우터는 어디로 보낼지만 정한다. 여러 Agent 를 부르고 결과를 합치고 실패를 되받는 것까지가 조율이다.
- **Agent 를 많이 붙일수록 답이 좋아진다** — 갈래가 늘수록 분류가 어려워진다. 잘못 고르면 좋은 Agent 가 있어도 엉뚱한 곳으로 간다.
- **분류는 키워드만 잘 잡으면 된다** — 같은 단어가 여러 갈래에 걸친다. 그래서 대개 문장 전체를 보고 고르게 한다.

## 🚨 주의사항

- **판단 못 한 경우를 정해둔다.** 갈래를 못 고른 질문을 아무 Agent 에게나 보내면 틀린 답이 그럴듯하게 나온다.
- **분류 결과를 로그로 남긴다.** 답이 이상할 때 Agent 가 문제인지 분류가 문제인지 구분할 수 있어야 고칠 수 있다.

## 📝 정리

Orchestrator 는 요청을 보고 어느 Agent 에게 맡길지 정하고, 결과를 모아 한 답으로 만드는 층이다. 의도 분류, 라우팅, 실행, 통합으로 나뉘며 앞의 분류가 전체 품질을 좌우한다. 단순히 갈래를 나누기만 하는 라우터와는 다르다.

## ❓ 이해했는지

- 질문을 던졌는데 엉뚱한 Agent 가 답했다. 어느 자리를 먼저 의심하나 → 작동 원리
- Agent 한 곳이 못 찾았다고 답했을 때 그대로 끝나지 않게 하려면 무엇이 필요한가 → 실제 사례
- 한 문장에 두 가지를 물으면 Orchestrator 는 무엇부터 해야 하나 → 해결하는 문제
