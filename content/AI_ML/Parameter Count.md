# Parameter Count (파라미터 수)

## 📝 정의

Parameter Count는 **모델이 학습으로 정한 숫자의 개수**다.

모델 안에는 학습이 값을 정해 주는 숫자가 들어 있다. 맞히고 틀린 만큼 이 숫자들을 고치는 것이 학습이고, 다 고친 뒤 얼려 둔 그 숫자가 몇 개인지를 센 값이 파라미터 수다. 모델 이름 끝의 `7B`, `70B` 가 이 값을 십억 단위로 적은 것이다.

### 이름
Parameter :: 학습이 정하는 값
Count :: 세어 본 개수
= 붙여 읽으면 "학습이 정한 값이 몇 개인가". 이름이 곧 세는 방법이다

### 비유
라디오 맞추는 손잡이. 손잡이가 많을수록 더 정확히 맞출 수 있지만, 다 돌려 맞춰 두는 데 그만큼 오래 걸린다.

### 예
모델 이름 끝에 붙은 `7B` 의 `B` 가 십억이고 앞의 숫자가 파라미터 수다. 같은 계열이면 이 숫자만으로 무게가 짐작된다.

### 직접
받아 둘 수 있는 모델 파일의 용량을 파라미터 수로 나눠 보라. 값 하나에 몇 바이트를 쓰고 있는지가 그대로 나온다.

## 🖼️ 그림으로 보기

```도해
흐름: 이 숫자들은 어디서 와서 어디에 남나
빈 모델 :: 값이 전부 아무렇게나 채워져 있다
학습 :: 맞혀 보고 틀린 만큼 값을 고친다
되풀이 :: 수많은 글로 이 고치기를 거듭한다
굳히기 :: 다 고친 값을 그대로 얼려 파일에 담는다
쓰기 :: 물어보면 그 값들로 계산해 답을 낸다
= 얼려 둔 그 값이 몇 개인가를 센 수가 파라미터 수다
```

## ⚠️ 해결하는 문제

```도해
대조: 모델의 덩치를 무엇으로 재나
안 세면 || 세어 두면
실력 어림 :: 짐작만 한다 || 규칙이 보인다
필요한 장비 :: 돌려봐야 안다 || 미리 계산된다
모델끼리 견주기 :: 기준이 없다 || 한 줄로 선다
= 층수나 폭 대신 값의 개수 하나로 덩치를 재기로 한 것이다
```

모델을 견줄 잣대는 여럿일 수 있다. 층을 몇 겹 쌓았는지, 한 층이 얼마나 넓은지, 어떤 구조를 골랐는지. 그런데 스케일링 법칙 논문은 그 구조 세부가 넓은 범위 안에서는 거의 영향이 없다고 적는다. 대신 손실은 모델 크기 · 데이터 크기 · 계산량 세 가지에 대해 거듭제곱 꼴로 움직이고, 그 추세가 자릿수로 일곱 개가 넘는 범위에서 이어진다.

그래서 값의 개수 하나가 나머지를 대신하는 잣대가 되었다. 이 수를 알면 학습에 몇 장이 필요한지가 곱셈으로 나오고, 다른 모델과 한 줄에 세울 수도 있다.

## ⚙️ 작동 원리

파라미터 수는 곧바로 메모리로 환산된다. Hugging Face 문서는 혼합 정밀도 학습에서 값 하나에 드는 바이트를 이렇게 나눈다 — 계산용 사본과 안정용 사본에 6바이트, 옵티마이저가 값마다 들고 있는 관성과 분산에 8바이트, 기울기에 4바이트. 합해서 값 하나에 18바이트이고, 여기에 중간 결과가 더 얹힌다. 같은 문서는 40억짜리 모델을 16개씩 묶어 학습하면 GPU 메모리가 85GB쯤 든다고 적는다.

그렇다고 이 수만 올리는 것은 낭비다. 2022년의 한 연구는 계산 예산이 정해져 있을 때 모델 크기와 학습 토큰 수를 같은 비율로 늘려야 한다고 정리했다 — 크기를 두 배로 하면 학습에 먹이는 토큰도 두 배여야 한다. 같은 예산에서 크기를 4분의 1로 줄이고 데이터를 4배로 늘린 모델이, 4배 큰 모델보다 여러 시험에서 더 나은 점수를 냈다.

## 💡 실제 사례

- **장비 미리 잡기** — 학습에 드는 메모리는 값 하나당 18바이트 언저리에서 시작한다. 파라미터 수를 알면 몇 장이 필요한지가 먼저 계산된다.
- **작은 모델로 갈아타기** — 공식 문서는 큰 모델이 값에 안 맞는 자리에서 작고 싸고 빠른 모델을 그 일에 맞게 다듬어 쓰라고 적는다. 이 수를 줄이는 것이 곧 응답 시간과 값을 줄이는 일이다.
- **데이터와 함께 늘리기** — 크기를 두 배로 할 참이면 학습 토큰도 두 배로 잡는다. 한쪽만 늘리면 같은 예산으로 더 나쁜 모델이 나온다.

## 🚫 흔한 오해

- **파라미터가 많을수록 무조건 낫다** — 계산 예산이 정해져 있으면 아니다. 크기를 줄이고 학습 토큰을 늘린 쪽이 4배 큰 모델을 여러 시험에서 앞선 결과가 있다.
- **파라미터 수가 아는 지식의 양이다** — 세어 둔 것은 조절값의 개수지 담아 둔 문서의 개수가 아니다. 학습에 먹인 양은 토큰 수로 따로 센다.
- **층을 깊게 쌓으면 그만큼 좋아진다** — 스케일링 법칙 논문은 폭이나 깊이 같은 구조 세부가 넓은 범위 안에서 거의 영향이 없다고 적었다. 잡히는 것은 전체 값의 개수 쪽이다.

## 📝 정리

**"학습이 정해 놓은 조절값이 몇 개인가"** 라고 읽으면 된다. 이 수 하나로 필요한 장비가 곱셈으로 나오고 다른 모델과 한 줄에 설 수도 있다. 다만 계산 예산이 정해져 있으면 크기만 키우는 것은 손해라, 학습에 먹이는 양과 같은 비율로 올려야 한다.

## 🧒 열 살에게

라디오 맞추는 손잡이 알지? 손잡이가 하나뿐이면 대충만 맞고, 손잡이가 아주 많으면 훨씬 정확히 맞출 수 있어. 대신 손잡이가 많아질수록 그걸 다 돌려 맞춰 두는 데 시간도 자리도 훨씬 많이 들어.

## ❓ 이해했는지

- 파라미터 수를 알면 필요한 장비를 왜 미리 계산할 수 있나 → 해결하는 문제
- 계산 예산이 정해져 있는데 크기만 두 배로 키우면 왜 손해인가 → 작동 원리
- 모델 이름 끝에 붙은 숫자는 무엇을 센 것인가 → 그림
