# Cosine Similarity (코사인 유사도)

## 📝 정의

Cosine Similarity는 **두 벡터가 가리키는 방향이 얼마나 비슷한지** 측정하는 방법입니다. 마치 나침반으로 방향을 비교하듯, 벡터의 "방향"만 보고 유사도를 판단합니다.

### 핵심 개념

- **무엇인가?**: 두 벡터 사이의 각도를 측정 (-1 ~ 1 사이 값)
- **왜 필요한가?**: 문서 길이에 관계없이 "의미"만 비교하기 위해
- **어떻게 작동하나?**: 각도가 작을수록 유사 (0° = 완전 같음, 90° = 무관함)

## 🤔 왜 Cosine Similarity가 필요한가?

### 일반 거리 측정의 문제

**문제 상황: 같은 의미인데 다르다고 판단**
```
짧은 문서: "육아휴직" → 벡터 [1, 2]
긴 문서: "육아휴직 신청 방법 절차 안내..." → 벡터 [10, 20]

유클리드 거리: 매우 멀다! ❌
→ 의미는 같은데 거리가 멀다고 판단

문제: 문서 길이가 다르면 벡터 크기도 달라짐
→ 같은 의미여도 다르다고 오판
```

**문제 상황 2: 방향은 같은데 크기만 다름**
```
벡터 A: [1, 2, 3]
벡터 B: [100, 200, 300] (A의 100배)

유클리드 거리: 엄청 멀다! ❌
실제로는: 방향이 완전 같음 (비율이 1:2:3으로 동일)
```

### Cosine Similarity의 해결

```
핵심 아이디어: 크기는 무시하고 "방향"만 본다!

벡터 A: [1, 2, 3] (북동쪽으로 10km)
벡터 B: [100, 200, 300] (북동쪽으로 1000km)

→ 거리는 다르지만 방향은 같음!
→ Cosine Similarity: 1.0 (완전 유사) ✅

짧은 문서든 긴 문서든, 의미만 비슷하면 찾음!
```

## 📊 작동 원리

### 각도로 유사도 측정


### 기하학적 의미

```
       ↗ B [6, 8]
      /
     / θ=0°
    /
   ↗ A [3, 4]

각도 0°   → Cosine = 1.0  (완전 같음) ✅
각도 45°  → Cosine = 0.7  (비슷함)
각도 90°  → Cosine = 0.0  (관련 없음)
각도 180° → Cosine = -1.0 (정반대)
```

## 💡 일상적 비유로 이해하기

### Cosine Similarity = 나침반 방향 비교

**유클리드 거리 (일반 거리)**:
```
A: "강남역에서 북동쪽으로 1km"
B: "강남역에서 북동쪽으로 10km"

거리로 비교: 9km나 차이! 전혀 다름 ❌
→ 하지만 방향은 같은데?
```

**Cosine Similarity (방향 비교)**:
```
A: 북동쪽 방향 (45°)
B: 북동쪽 방향 (45°)

방향으로 비교: 똑같은 방향! ✅
→ 거리는 달라도 방향은 같음!

유사도: 1.0 (완전 유사)
```

### RAG 검색에서의 활용

```
질문: "육아휴직은?" (짧은 질문)
→ 벡터: [0.1, 0.2, 0.3]

문서 1: "육아휴직" (짧은 문서)
→ 벡터: [0.1, 0.2, 0.3]

문서 2: "육아휴직 신청 방법 절차 안내 규정..." (긴 문서)
→ 벡터: [1.0, 2.0, 3.0]

Cosine Similarity:
문서 1: 1.0 (방향 같음) ✅
문서 2: 1.0 (방향 같음) ✅

→ 길이 무관하게 의미만 비교!
```

```
P3 시스템의 기준:

→ 보여주지만 주의 표시

→ "관련 정보를 찾지 못했습니다" (Hallucination 방지)
```

```

   → 참고용으로 포함 (낮은 신뢰도)

3. 제35조 (회의 규정) → 유사도 0.15 ❌
   → 제외 (무관함)

LLM 답변: "제32조에 따르면, 육아휴직은..."
→ 0.87 이상만 사용하여 정확도 보장
```

## 🔍 Cosine Similarity vs 유클리드 거리

### 비교

```
상황: 같은 의미, 다른 길이

짧은 문서: [1, 2, 3]
긴 문서: [100, 200, 300]

유클리드 거리:
→ 거리 = 약 299 (매우 멀다) ❌
→ 문제: 길이가 다르면 멀다고 판단

Cosine Similarity:
→ 유사도 = 1.0 (완전 같음) ✅
→ 해결: 방향만 보므로 길이 무관
```

### 언제 뭘 쓸까?

```
Cosine Similarity 적합:
- 텍스트 유사도 (RAG, 검색) ✅
- 문서 길이가 다양할 때
- 의미만 비교하고 싶을 때

유클리드 거리 적합:
- 물리적 거리 측정
- 절대적 차이가 중요할 때
- 이미지 픽셀 비교

RAG에서는 Cosine Similarity!
→ 문서 길이 무관, 의미만 중요
```

## 🚀 Cosine Similarity 최적화

### P3의 빠른 검색

```
문제: 10,000개 문서와 각각 비교?
→ 너무 느림!

해결: Vector DB (Pinecone, Milvus)
→ 미리 인덱싱하여 빠르게 검색
→ 0.5초 안에 Top-10 찾기

추가 최적화:
1. 정규화된 벡터 사용 (내적만으로 계산)
2. Approximate 검색 (정확도 95%로 10배 빠르게)
3. 캐싱 (같은 질문 반복 시)
```

### 임계값 조정

```
너무 높게 설정 (0.9):
→ 찾는 문서가 너무 적음
→ "관련 정보가 없습니다" 자주 나옴

너무 낮게 설정 (0.3):
→ 관련 없는 문서도 포함
→ LLM이 엉뚱한 답변 생성

P3 권장: 0.7
→ 정확도와 재현율 균형
→ 필요시 사용자가 조정 가능
```

## 🚨 주의사항

### 1. 음수 값의 의미

```
Cosine = 1.0: 완전 같은 방향 (의미 같음)
Cosine = 0.0: 직각 (관련 없음)
Cosine = -1.0: 정반대 방향 (의미 반대)

예시:
"좋아요" vs "싫어요"
→ 유사도 -0.8 (반대 의미)

RAG에서는:
→ 음수도 관련 없음으로 처리
→ 반대 의미보다는 "다른 주제"가 대부분
```

### 2. 정규화의 중요성

```
이미 정규화된 벡터:
→ 내적만 계산해도 Cosine Similarity
→ 계산 속도 2배 향상

Vector DB는 자동으로 정규화
→ 걱정 안 해도 됨
```

### 3. 차원의 저주

```
768차원 벡터:
→ 대부분의 벡터가 직각에 가까움
→ 유사도가 0.1~0.3 사이에 몰림

해결:
→ 임계값을 낮게 설정 (0.7 → 0.5)
→ Reranking으로 정확도 향상
```

## 📝 정리

**Cosine Similarity 핵심 3줄**:
```
1. 벡터의 "방향" 유사도 측정 (크기 무시)
2. 짧은 문서 vs 긴 문서 문제 해결
3. RAG 검색의 핵심 = 의미만 비교

→ Embedding + Cosine Similarity = 똑똑한 검색
```

**비유로 기억하기**:
```
유클리드 거리 = 직선 거리 측정
→ "강남역에서 10km" vs "강남역에서 1km"
→ 거리가 다르다고 판단 ❌

Cosine Similarity = 나침반 방향 측정
→ "북동쪽" vs "북동쪽"
→ 방향이 같다고 판단 ✅

RAG 검색:
→ 문서 길이 무관하게 의미만 비교
→ 짧은 질문 vs 긴 문서도 매칭!
```

**Cosine Similarity 공식**:
```
유사도 = 두 벡터 사이 각도의 코사인 값

각도 0°   (같은 방향) → 1.0 ✅
각도 45°  (비슷한 방향) → 0.7
각도 90°  (직각) → 0.0 ❌
각도 180° (반대 방향) → -1.0

P3에서:
→ 0.7 이상만 사용
→ Hallucination 방지
→ 출처 명확한 답변
```

**P3 검색 흐름**:
```
1. 질문 Embedding → 벡터로 변환
2. 모든 문서와 Cosine Similarity 계산
3. 유사도 0.7 이상만 선택
4. Top-3를 LLM에 전달
5. 정확한 답변 생성

핵심 = 방향(의미)만 비교하여 정확도 향상!
```
