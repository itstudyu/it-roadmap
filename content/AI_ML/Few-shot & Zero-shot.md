# Few-shot & Zero-shot Learning

## 📝 정의

Zero-shot과 Few-shot은 **프롬프트에 예시를 몇 개 넣느냐**로 갈리는 지시 방식이다.

모델을 다시 학습시키지 않고 프롬프트만으로 새 작업을 시킨다. 예시가 없으면 Zero-shot, 두어 개면 Few-shot, 수십 개를 넘어가면 Many-shot이라 부른다.

### 비유
새로 온 사람에게 일을 넘길 때, 말로만 설명하는 것과 처리해둔 서류 두어 장을 같이 건네는 것의 차이다.

## 🖼️ 그림으로 보기

```도해
흐름: 예시를 붙이면 답이 왜 달라지나
프롬프트 :: "이 문장의 감정을 분류해줘"
예시 :: "최고예요 → 긍정" 을 두어 개 붙인다
모델 :: 예시에서 답의 형태와 기준을 읽는다
답 :: 예시와 같은 모양으로 돌려준다
@ 다음 요청 :: 예시를 또 붙여야 한다. 토큰도 매번
= 예시는 새로 배우게 하는 게 아니라 답의 틀을 정해주는 것이다
```

## ⚠️ 해결하는 문제

```도해
대조: 새 작업을 시키려면 무엇이 필요한가
따로 학습시켜서 || 예시를 붙여서
준비물 :: 데이터 수천 건 || 예시 두세 개
착수 :: 학습을 돌린다 || 바로 쓴다
바꾸려면 :: 다시 학습 || 예시만 고침
= 모델을 건드리지 않고 프롬프트 안에서 끝내는 것이 요점이다
```

전통적인 기계학습은 새 작업마다 수천에서 수만 건의 학습 데이터를 모아야 했다. Fine-tuning으로 줄여도 최소 50~100개 예시가 들고, 기준이 바뀌면 다시 학습을 돌려야 한다.

프롬프트에 예시를 붙이는 방식은 그 준비를 건너뛴다. 기준이 바뀌면 예시 문장을 고치면 되고, 반영은 다음 요청부터 곧바로 된다.

## 📊 비교

| | 예시 개수 | 토큰 | 잘 맞는 곳 |
|---|---|---|---|
| Zero-shot | 0개 | 적다 | 감정 분류, 요약, 번역처럼 흔한 작업 |
| Few-shot | 2~10개 | 많다 | 정해진 형식이나 특정 분야의 답 |
| Many-shot | 수십~수백 개 | 아주 많다 | 규칙이 복잡해 말로 설명하기 어려운 것 |

## ⚙️ 작동 원리

예시는 모델 안에 남지 않는다. 그 요청에 붙어 간 글일 뿐이고, 다음 요청에는 다시 붙여야 한다. 모델은 예시에서 두 가지를 읽는다. 답을 어떤 형식으로 쓸지, 그리고 경계에 걸치는 입력을 어느 쪽으로 볼지.

```
다음 예시처럼 분류하세요.

문장: "정말 최고예요!"   감정: 긍정
문장: "실망스럽네요"     감정: 부정
문장: "보통이에요"       감정: 중립

이제 분류하세요.
문장: {입력}
감정:
```

개수를 늘릴수록 정확해지지만 토큰과 비용도 같이 늘어난다. 보통 서너 개 근처에서 더 넣어도 나아지는 폭이 크게 줄어든다.

## 💡 실제 사례

- **답변 형식 맞추기** — 근거 조항을 앞에 붙인 답변을 예시로 두면 이후 답도 같은 모양으로 나온다.
- **애매한 경계 정하기** — 어중간한 문장을 예시에 넣어 어디까지가 긍정이고 어디부터 중립인지 정해준다.
- **풀이 과정 보이기** — 단계별로 계산한 예시를 넣으면 답만 던지지 않고 과정을 따라 쓴다.

## 🚫 흔한 오해

- **Few-shot은 모델을 학습시키는 것이다** — 모델은 그대로다. 예시는 그 요청 한 번에만 붙어 있는 글이라 다음 요청에는 다시 붙여야 한다.
- **예시가 많을수록 좋다** — 토큰과 비용이 따라 늘고 컨텍스트 창을 밀어낸다. 서너 개를 넘어가면 늘린 만큼 나아지지 않는다.
- **Zero-shot은 예시를 못 넣어서 쓰는 것이다** — 흔한 작업에서는 예시 없이도 답이 나오고 그만큼 싸고 빠르다. 예시는 형식이나 기준이 특이할 때 붙인다.

## 🚨 주의사항

- **예시가 서로 비슷하면 낭비다.** 같은 유형을 세 번 보여주는 대신 수량을 묻는 것, 절차를 묻는 것, 자격을 묻는 것처럼 다른 유형을 섞는다.
- **예시끼리 형식이 어긋나면 답도 어긋난다.** 어떤 예시는 근거를 쓰고 어떤 예시는 안 쓰면 모델은 둘 중 아무거나 고른다.
- **예시도 컨텍스트 창을 먹는다.** 예시를 백 개까지 늘리면 정작 넣어야 할 문서가 들어갈 자리가 없어진다.

## 📝 정리

Zero-shot은 지시만 주는 것이고 Few-shot은 예시를 몇 개 붙여주는 것이다. 예시는 모델을 가르치는 장치가 아니라 그 요청 안에서 답의 형식과 기준을 정해주는 장치다. 형식이 특이하거나 경계가 애매할 때만 붙이고, 개수는 서너 개에서 멈추는 편이 낫다.

## ❓ 이해했는지

- Few-shot으로 잘 나오던 형식이 다음 요청에서 흐트러졌다. 예시를 다시 안 붙였다면 왜 그런가 → 작동 원리
- 예시를 3개에서 30개로 늘렸는데 비용만 늘고 답은 그대로다. 무엇을 잘못 본 건가 → 흔한 오해
- 감정 분류처럼 흔한 작업에 굳이 예시를 안 붙여도 되는 이유는 → 비교
